# Инструкции для агентов

## Что это за репозиторий

Исходный каталог chezmoi (`~/.local/share/chezmoi`) с dotfiles для CachyOS с сессией Hyprland (Wayland). Файлы здесь — **источник**, реальные конфиги живут в `$HOME`. Правки в `$HOME` напрямую не сохраняются в git, пока их не забрать обратно через chezmoi.

## Язык

- Общение с пользователем — ответы, вопросы, пояснения, планы, отчёты — вести
  ТОЛЬКО на русском языке.
- Коммит-сообщения — на русском.
- Документация проекта (`AGENTS.md`, README в конфигах) и артефакты OpenSpec
  (proposal, design, tasks, спецификации) — на русском. Для OpenSpec то же задано
  полем `context` в `openspec/config.yaml`.
- Структурные заголовки OpenSpec и ключевые слова SHALL/MUST/MAY — на английском.
- Код и идентификаторы — на английском: имена компонентов и свойств QML,
  функции и переменные в shell- и Lua-скриптах, ключи конфигурации, имена
  файлов.
- Комментарии в QML, TOML, shell- и Lua-файлах — на русском языке во всех
  каталогах проекта. Технические термины (chezmoi, Hyprland, Quickshell,
  workspace, LazyVim и т. п.) остаются в оригинальном написании.

## Качество русского языка

- Русский текст должен быть написан по-русски, а не переведён калькой
  с английского. Требование распространяется на ответы пользователю,
  документацию, артефакты OpenSpec, комментарии в конфигах и скриптах
  и коммит-сообщения.
- Не переносить английские идиомы дословно: не «сетевая неприятность», а
  «обрыв связи»; не «молча не находит», а «не находит и не сообщает об
  ошибке»; не «остаться молчаливым», а «остаться незамеченным»; не «плитки
  двух природ», а «плитки двух видов».
- Не заимствовать слово, у которого есть русский эквивалент: «спека» →
  «спецификация»; «фикс» → «исправление»; «дефолтный» → «по умолчанию»;
  «ребилд» → «пересборка»; «аддитивные изменения» → «изменения только
  добавляют, ничего не меняя».
- В спецификациях и проектных документах не употреблять разговорные обороты
  («плитки разъезжаются», «упрёмся в производительность», «демон не остаётся
  висеть») — нужна нейтральная формулировка.
- Исключение — технические термины и идентификаторы, перечисленные в разделе
  «Язык»: они сохраняют оригинальное написание (panel, tile, workspace,
  daemon как имена сущностей Quickshell и workspaced).
- После написания длинного документа делать отдельный проход по
  формулировкам, а не ограничиваться проверкой фактов.

## Работа с chezmoi

Соглашения имён: `dot_foo` → `~/.foo`, `executable_bar` → файл `bar` с битом исполнения. В рантайме префикс `executable_` отсутствует, поэтому пути внутри конфигов пишутся без него (`scripts/vpn-up`, не `executable_vpn-up`).

```bash
chezmoi status          # расхождения источник ↔ $HOME (первая колонка — apply, вторая — re-add)
chezmoi diff            # что изменит apply; --reverse показывает, что изменилось в $HOME
chezmoi apply [цель]    # источник → $HOME
chezmoi re-add [цель]   # $HOME → источник (для уже управляемых файлов)
chezmoi forget --force ~/путь   # убрать файл из источника (файл в $HOME не трогается)
chezmoi add ~/путь      # взять под управление новый файл
```

Типичный цикл: править файл в источнике → `chezmoi apply` → проверить в живой системе. Если правка сделана прямо в `$HOME` (например, nvim обновил `lazy-lock.json`), забрать её через `chezmoi re-add`.

Если файл в `$HOME` изменился после последнего применения (например, демон workspaced записал конфиг по `save-workspace`, а изменение нужно отбросить), обычный `chezmoi apply` спрашивает подтверждение, а терминала у агента нет, и команда завершается ошибкой «could not open a new TTY». В этом случае применять конкретный файл принудительно: `chezmoi apply --force ~/путь`; если изменение нужно сохранить, вместо этого `chezmoi re-add ~/путь`.

`.chezmoiignore` исключает `openspec/` и `docs/` — это документация проекта, а не dotfile, и в `$HOME` попадать она не должна. Там же исключены `AGENTS.md`, `CLAUDE.md` и `todo.md` по той же причине.
Каталог `system/` тоже исключён: в нём лежат файлы для `/etc` (например, конфиг greetd) и сценарии их установки; в систему они копируются вручную с правами root, chezmoi их не применяет.

## Самописные скрипты

Все скрипты, написанные вручную (обёртка `sudo-askpass`, скрипты громкости и яркости и подобные), лежат в одном каталоге `~/.local/bin/handmade-scripts`, источник `dot_local/bin/handmade-scripts/executable_<имя>`. Каталог добавлен в PATH (`dot_profile`, `dot_bash_profile`, `hyprland.lua`), поэтому из оболочки скрипты вызываются по имени; в конфигах программ, которые запускаются вне оболочки пользователя (например, `[[binds]]` демона workspaced), указывать полный путь `~/.local/bin/handmade-scripts/<имя>`. Смысл отдельного каталога — видеть все самописные скрипты в одном месте и удалять их, когда для задачи появляется системная замена. Новый вспомогательный скрипт создавать сразу там; каталоги `~/.scripts` и `~/.config/hypr/scripts` больше не используются, скрипты сессии Hyprland (снимки экрана, меню буфера обмена, `vpn-up`) тоже лежат здесь.

## Команды с правами root

У инструментов агента нет терминала, поэтому обычный `sudo` завершается ошибкой «для ввода пароля требуется терминал», а подсказка выполнить команду через `!` не помогает. Любую команду с повышенными привилегиями (pacman, systemctl, запись в `/etc`, смена владельца файлов и т. п.) агент запускает сам и только через обёртку `sudo-askpass`:

```bash
SUDO_ASKPASS=~/.local/bin/handmade-scripts/sudo-askpass sudo -A команда
```

Обёртка `~/.local/bin/handmade-scripts/sudo-askpass` (источник `dot_local/bin/handmade-scripts/executable_sudo-askpass`) показывает окно pinentry-gtk, где кнопкой у поля ввода можно посмотреть набранный пароль; готовой программы askpass в системе нет (`gcr4-ssh-askpass` работает только с gcr-ssh-agent, `git-gui--askpass` требует tk, у `zenity --password` нет показа пароля). Другие способы получить права root (`pkexec`, `su`, rofi, отдельное окно терминала) не использовать. Пароль спрашивается один раз, дальше действует кэш sudo. Терминала у команды нет, значит интерактивные подтверждения не работают: pacman вызывать с `--noconfirm`, а спорные действия (удаление осиротевших пакетов и т. п.) печатать списком и выполнять только по явному решению пользователя. Не просить пользователя выполнить команду вручную.

Базу пакетов синхронизировать только полным обновлением `pacman -Syu`; отдельный `pacman -Sy` (в том числе ради проверки версии) оставляет базу новее установленных пакетов, и следующая установка пакета даёт частичное обновление. Обновление драйвера NVIDIA (`nvidia-utils`) требует перезагрузки: до неё модуль ядра старой версии не совпадает с библиотеками, и `nvidia-smi` не работает. Описание CDI `/etc/cdi/nvidia.yaml` для контейнеров podman обновляет pacman-хук `nvidia-ctk-cdi` (при смене версии подменой строк); если после перезагрузки `podman start fedora-box` жалуется на устройства CDI, перегенерировать его: `nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml` с правами root.

## Git

- Законченную и проверенную работу коммитить самостоятельно, не спрашивая
  разрешения у пользователя.
- После каждого коммита сразу выполнять `git push` в `origin`, не спрашивая
  подтверждения. Коммит без push считается незавершённой работой.
- Логически разные изменения (например, синхронизация dotfiles и
  переработка плиток панели Quickshell) оформлять отдельными коммитами.

## Документация

Долговременные сведения о системе лежат в `docs/`, указатель — [`docs/README.md`](docs/README.md). Там же подкаталоги `decisions/` (принятые решения: выбор инструмента, размещение компонента, отвергнутые варианты и условия пересмотра) и `open-questions/` (вопросы, ответ на которые сейчас получить нельзя). Отдельные документы: `agent-session-tips.md` — приёмы работы агента в живой сессии Hyprland, `host-state.md` — что в системе и в `$HOME` не лежит под chezmoi, `media-and-portals.md` — проверки мультимедиа, аппаратного декодирования и порталов, `window-model.md` — целевая модель окон демона workspaced и серия изменений, которой она вводится.

Сведения разделены так: спецификация OpenSpec описывает поведение, запись в `docs/decisions/` — причины выбора, остальные документы `docs/` — устройство системы и способы проверки, `todo.md` — снимок текущей работы со ссылками. Одно сведение хранится в одном файле; в `AGENTS.md` остаётся только то, что нужно в каждой сессии. Журнал сделанного не ведётся: его хранят история git и `openspec/changes/archive/`.

## OpenSpec

Изменения ведутся по схеме spec-driven: `openspec/specs/<capability>/spec.md` — актуальные требования, `openspec/changes/<name>/` — активное изменение (proposal, design, tasks, изменения спецификаций), `openspec/changes/archive/<дата>-<name>/` — завершённые. Команды рабочего процесса лежат в `.opencode/commands/opsx-*.md` (new, apply, verify, archive, sync и т.д.) и опираются на CLI `openspec` (`openspec list --json`, `openspec list --specs`, `openspec show <имя>`, `openspec status --change <name> --json`, `openspec validate <имя> --strict`, `openspec archive <имя> -y`; без `-y` архивация ждёт подтверждения, а терминала у агента нет).

- Перед изменением поведения панели, демона или сессии Hyprland сверяйтесь со спецификацией соответствующей capability и правьте её тем же изменением, что и код.
- Изменение OpenSpec нужно, когда меняется или добавляется наблюдаемое поведение. Исправление, возвращающее поведение к спецификации, правка документации, переименование, обновление пакетов и разовая настройка системы обходятся коммитом и при необходимости строкой в `todo.md`.
- Решение, принятое по ходу изменения, живёт в его `design.md`; если оно шире одного изменения (выбор инструмента, отказ от подхода), оно уходит в `docs/decisions/`, а в `design.md` остаётся ссылка.
- Ход работы — только в `tasks.md` изменения, в `todo.md` на него ставится ссылка. К моменту архивации незавершённых задач не остаётся: они либо выполняются, либо переносятся в `todo.md` или `docs/open-questions/`.
- Язык артефактов задаёт поле `context` в `openspec/config.yaml`.

## Neovim (`dot_config/nvim`)

LazyVim-конфиг: `lua/config/*` — options/keymaps/autocmds, `lua/plugins/*.lua` — по одному файлу на плагин или тему, `lazyvim.json` — включённые extras. `lazy-lock.json` меняет сам nvim в `$HOME`, после обновления плагинов его нужно забрать через `chezmoi re-add ~/.config/nvim/lazy-lock.json`. Форматирование Lua — `stylua` по `stylua.toml`. Настройки под Neovide (`vim.g.neovide`) лежат в `options.lua`, параллельно с `dot_config/neovide/config.toml`.

## Сессия Hyprland (`dot_config/hypr`, `dot_config/workspaced`, `dot_config/quickshell`)

Единственная сессия — Hyprland с Lua-конфигом `dot_config/hypr/hyprland.lua`. Вход — greetd с tuigreet на виртуальной консоли 1 (конфиг `system/greetd/config.toml`, сценарий переезда `system/greetd/migrate.sh`, изменение OpenSpec greetd-login): при загрузке сессия поднимается без пароля по разделу `[initial_session]`, после выхода tuigreet спрашивает пароль. greetd запускает сессию без login-оболочки и читает только `~/.profile`, поэтому `PATH` сессии (в том числе shims mise) задают `~/.profile` и `hl.env` в `hyprland.lua`, а `.bashrc` на сессию не влияет; `XDG_SESSION_TYPE=wayland` тоже выставляет `hyprland.lua`, greetd этой переменной не задаёт. Все переменные `hl.env` при старте передаются в окружение пользовательского systemd, поэтому их видят демон workspaced, rofi и всё, что запущено из лаунчера; с 17.09.2026 это касается и `ELECTRON_OZONE_PLATFORM_HINT=auto`, из-за которой приложения на Electron запускаются нативно под Wayland. Приложению во flatpak для этого нужен доступ к сокету Wayland: манифест Postman даёт только `--socket=x11`, и с подсказкой `auto` процесс жил около минуты без окна и падал с SIGSEGV; без подсказки Electron выбирает X11, а под Xwayland voxtype печатает цифры. Поэтому Postman задано переопределение `flatpak override --user --socket=wayland --env=ELECTRON_OZONE_PLATFORM_HINT=wayland com.getpostman.Postman`; файлы переопределений `~/.local/share/flatpak/overrides/<id>` лежат под chezmoi (`dot_local/share/flatpak/overrides/`). Масштаб интерфейса Electron под Wayland берётся только у монитора (в Hyprland он равен 1), поэтому Postman запускается с `--force-device-scale-factor=1.5` из собственного ярлыка `~/.local/share/applications/com.getpostman.Postman.desktop` (под chezmoi), который перекрывает ярлык, экспортированный flatpak. LightDM, slick-greeter и xorg-server удалены из системы 17.09.2026; из пакетов xorg остались Xwayland и зависимости Steam. Openbox, дашборд eww и демон eww-daemon удалены из системы 16.09.2026; их история хранится только в `openspec/changes/archive`, резервные копии кода лежат в `~/work/archive`. Панель — Quickshell (`dot_config/quickshell/panel`), состояние workspace и сессий — демон `workspaced` (Rust, проект `~/work/pets/workspaced`, репозиторий `git@github.com:quiet-lab/workspaced.git`, ссылка `~/.local/bin/workspaced`, сборка `cargo build --release`, юнит `workspaced.service`).

- Все привязки и цепочки клавиш сессии живут в одном файле `dot_config/workspaced/config.toml`, раздел `[[binds]]` (спецификации hyprland-binds и ws-config). Workspace `work` (шаблон `thirds`: herdr в wezterm по центру, Chromium слева, neovide справа) поднимается при старте демона по разделу `[startup]` и по `Super+Tab w`; workspace `surf` (шаблон `overlay`: три окна по 1920 px поверх друг друга, левое от панели, правое до края экрана, главное по центру поверх обоих; Яндекс.Браузер по центру и главный, Google Chrome профиля Default слева, профиля AI.dev2026 справа, все из контейнера distrobox `fedora-box`) поднимается по `Super+Tab s` и живёт на столе 2. Приложения вызываются одиночными сочетаниями Super+T (herdr), Super+C (Chromium), Super+E (neovide), Super+B (Chrome, профиль Default), Super+V (Chrome, профиль AI.dev2026), Super+Y (Яндекс.Браузер), закрытие окна — Super+Delete, меню буфера обмена — Super+Insert. Браузеры работают нативно под Wayland: Chrome и Яндекс.Браузер из контейнера distrobox `fedora-box` (Fedora, создан с флагом `--nvidia`; переезд с `ubuntu-box` 17.09.2026, старый контейнер удалён: в Fedora драйвер VA-API NVIDIA с хоста ложится в `/usr/lib64/dri`, куда его ищет libva, а в Ubuntu нет, и там аппаратного декодирования не было) через `--ozone-platform=wayland` и `--enable-features=AcceleratedVideoDecodeLinuxGL,VaapiOnNvidiaGPUs,VaapiIgnoreDriverChecks` в ярлыках `~/.local/share/applications/fedora-box-*.desktop` (экспорт distrobox, не под chezmoi) и в аргументах приложений демона, Chromium через `dot_config/chromium-flags.conf`. Контейнер прогревает юнит `distrobox@fedora-box.service` (`dot_config/systemd/user/distrobox@.service`), дожидаясь устройства `/dev/nvidia-modeset`, иначе первый запуск браузеров затягивается настолько, что окна приходится ждать минуту и больше (сроком ожидание демона не ограничено, но пользоваться сессией в это время неудобно). Под Xwayland voxtype печатает в поля браузера цифры вместо текста, так как `wtype` подаёт символы виртуальной клавиатурой с собственной раскладкой; если под Wayland не воспроизводится видео, это решается иначе, не возвратом на X11. Профили Chrome — два отдельных экземпляра браузера: профиль Default работает с каталогом данных по умолчанию `~/.config/google-chrome` и даёт окна класса `google-chrome`, профиль AI.dev2026 — с каталогом `~/.config/google-chrome-ai` (ключ `--user-data-dir`, путь пишется через `$HOME`: тильду демон подставляет только в начале строки) и собственным классом окна `google-chrome-ai` (ключ `--class`), который получают и окна, открытые по Ctrl+N, поэтому окна профилей различаются по классу. Приложение с полями `class` и `title` (регулярные выражения) захватывает все подходящие открытые окна вместо того, чтобы открывать новое: у приложения может быть несколько окон — экземпляров. Окно помечается тегом `app:<имя>#<номер>`, номер — наименьший свободный среди живых окон приложения; по нему идёт порядок экземпляров, а тег `app:<имя>` без номера остался от прежней версии демона и читается как экземпляр. Окна одного приложения переносятся вместе с workspace и встают в одно место стопкой, фокус получает первый экземпляр. Поле `family` делает приложение вариантом семейства: окно варианта считается и окном семейства, а окно, подходящее обоим, достаётся варианту; уровней ровно два. Так herdr — вариант семейства `wezterm`: его окно опознаётся собственным классом `wezterm-herdr` (`wezterm start --class`), а обычное окно wezterm остаётся за семейством, которое ни в один workspace не входит и клавиши не имеет. У семейства, которое только собирает окна, поле `cmd` можно не задавать; поле `rect` у приложения задаёт место его окна, когда активный workspace об этом приложении ничего не говорит. Окно, открытое по ходу работы (без тега `app:`), остаётся свободным: за workspace не следует и в его составе не значится, пока пользователь не сохранит его явной командой. Команд сохранения две, и обе начинаются с префикса Ctrl+Super+S: `Ctrl+Super+S` принимает посторонние окна текущего стола в активный workspace этого стола как дополнительные приложения сессии (конфиг не меняется, запись живёт в снимке сессии и переживает перезапуск демона и перезагрузку), `Ctrl+Super+W` записывает workspace в `config.toml` вместе с его дополнительными приложениями сессии. Окно, подходящее описанному в конфиге приложению по `class` и `title`, обе команды относят к этому приложению, а не заводят новое. Префикс действий с workspace — Super+Tab (после него Super отпускается): `w` поднять work, `s` поднять surf, `Tab` — следующий workspace стола. Цепочка workspace и цепочка приложения не переносят workspace, уже активный на другом столе: демон переходит на тот стол и отдаёт фокус главному окну; перенос только по явному столу (`--desktop`, запись `[[binds]]` со столом). В `hyprland.lua` собственных `hl.bind` нет: он выполняет код, который печатает `workspaced keys --lua`, а при ошибке загружает копию `~/.local/state/workspaced/keys.lua` и показывает уведомление. Новую привязку добавлять в конфиг демона, проверять `workspaced check` и смотреть `workspaced keys --list`; демон сам вызывает `hyprctl reload config-only` после удачного перечитывания. Демон работает только по событиям: таймеров в нём нет. Снимок сессии `default` пишет обработчик события композитора или команды, изменивших состояние, до ответа клиенту; выход запущенного процесса приходит событием от потока ожидания; конфиг перечитывается по событиям завершённой записи файла (закрытие файла на записи, появление файла после переименования). Предельных сроков ожидания окна нет: ожидание живёт до окна, а клавиша приложения после неудачного запуска запускает его заново. Таймеры в демоне, панели и скриптах сессии запрещены, любое исключение обсуждается с пользователем до написания кода, а оставленный таймер несёт в комментарии метку `FIXME` (событие есть, таймер подлежит замене) или `WARNING` (источника событий нет, опрос неизбежен) с объяснением — запись [`0007`](docs/decisions/0007-no-timers.md). В панели Quickshell после перехода на события остались только три опроса с `WARNING`: датчики, заполнение дисков и погода.
- Сочетания из списка `reserved` в `[keys]` (карта XKB Super+Пробел, Super+Alt+E, Super+Alt+R и намеренно свободное Alt+Super+Пробел) занимать нельзя, проверка конфига их отклоняет. Раскладку переключает сама карта XKB: Super+Пробел по кругу, Super+Alt+E фиксирует US, Super+Alt+R фиксирует RU; одиночное Alt+буква достаётся приложению, поэтому Alt+E в браузерах на Chromium открывает меню браузера.
- Правило геометрии: расстояние от края экрана и панели до окна, между окнами и между плитками панели — одно число, 10 px. Рамка окна — 1 px, как рамка плиток панели (`border_size` в `hyprland.lua` и `border.width` в `Tile.qml`). У панели это `Theme.margin` и `Theme.gap`; у демона ячейки шаблонов и `rect` приложений — это положение и размер окна на экране как есть, демон ничего к ним не прибавляет и не вычитает, а отступ 10 px заложен в числа ячеек (x от 340, y от 10); `gap = 5` нужен только расчётным командам: команды `workspaced half` (Alt+Super+стрелки), `workspaced place` (Alt+Super+Home/PageDown/End — верхний ряд, Ctrl+Alt+Super+Z/X/V — нижний, Ctrl+Alt+Super+C — центр во всю высоту) и `workspaced maximize` (Alt+Super+PageUp, переключатель с возвратом прежней геометрии) считают половины, позиции и развёрнутую область по тому же правилу; режим maximized композитора для плавающих окон отступы не учитывает. Alt+Super+Enter задаёт окну фиксированный размер 1920×1080 и центрирует его диспетчерами композитора, без отступов демона.
- Скрипты громкости и яркости, унаследованные от X11-сессии, лежат в `dot_local/bin/handmade-scripts/` и вызываются из `[[binds]]`; скриншоты и меню буфера обмена — там же. Лаунчер по Super+R — `rofi -show drun` с конфигом `dot_config/rofi/config.rasi`, уведомления — dunst (`dunst.service`).
- Настройка `misc.focus_on_activate` в `hyprland.lua` включена и остаётся общей: запрос активации по действию пользователя (клик по уведомлению, ссылка из другой программы) должен переводить фокус на окно и его стол. Правил окон с `focus_on_activate` и `suppress_event` нет намеренно — композитор проверяет токен активации только на существование и не отличает запрос по входящему сообщению от запроса по клику. Поэтому самопроизвольное поднятие окна Telegram при сообщении убрано в самом Telegram: переключатель «Подсветка окна» в разделе «Уведомления и звуки» выключен (изменение OpenSpec telegram-no-focus-steal, запись в `docs/host-state.md`).
- `hyprctl keyword` и `hyprctl dispatch` с Lua-конфигом не работают: диспетчеры вызываются через `hyprctl eval 'hl.dispatch(hl.dsp.…)'`; форма `hyprctl eval 'return hl.dsp.…'` ничего не выполняет. У `hl.timer` `timeout` в миллисекундах. Браузеры на Chromium при выходе из полноэкранного видео сразу запрашивают maximized, и плавающее окно оставалось на всю рабочую область (ошибка Hyprland, обсуждение #13322, воспроизводится на 0.56.2); обработчик `window.fullscreen` в `hyprland.lua` отменяет maximized в первые 50 мс после выхода из fullscreen. Виртуальная клавиатура `wtype` привязки композитора не запускает, проверки нажатиями делает пользователь. В браузерах включено расширение Surfingkeys, поэтому одиночные клавиши, поданные через `wtype` в страницу (например, `f` в плеере YouTube), перехватывает оно; действия внутри страницы тоже делает пользователь, а агент записывает события композитора из `.socket2.sock` экземпляра Hyprland и состояние окон `hyprctl clients -j`.
- Оболочка агента наследует `HYPRLAND_INSTANCE_SIGNATURE` от той сессии, в которой был запущен Claude Code: после перезахода переменная указывает на прежний экземпляр, и `hyprctl` сообщает, что сокета нет. Действующую подпись даёт `ls -t $XDG_RUNTIME_DIR/hypr | head -1` — каталог живого экземпляра там самый свежий; `hyprctl instances` переменной не требует и печатает подпись вместе с pid, поэтому ею же проверяется, совпадает ли унаследованное значение с живым. Дальше подпись передаётся явно: `HYPRLAND_INSTANCE_SIGNATURE=<подпись> hyprctl …`.
