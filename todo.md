### Цель

Перевести демон workspaced на новую модель окон по [`docs/window-model.md`](docs/window-model.md). ### Открытые вопросы к пользователю

- Как отличать диалоги на шаге 3. Hyprland 0.56.2 наружу не отдаёт ни родителя окна, ни модальности (итоги пробы — `docs/window-model.md`, раздел «Пробные задачи»), а шаг 3 принимает в workspace любое окно, появившееся при активном workspace, и без признака ставил бы в ячейку и диалоги приложений с тем же классом («Сохранить как» через портал приходит своим классом и не задевается). Варианты: эвристика по размеру окна при появлении; отложить «принятие любого окна» до появления признака у Hyprland (запрос в upstream) и оставить нынешнее правило «захватываются только окна приложений конфига, остальные — по Ctrl+Super+S»; свой признак через патч или плагин композитора.

### Где остановились

### Как проверить

```bash
openspec list                              # активных изменений нет
systemctl --user is-active workspaced.service quickshell-panel.service
ss -xp | rg workspaced/sock                # ESTAB — панель подключена к демону
workspaced status --json | jq -c '.pending, (.desktops | to_entries | map({(.key): [.value.workspaces[].name]}) | add)'   # каждый workspace ровно на одном столе
workspaced keys --list | rg 'move-desktop|arrange|save-'
system/modprobe.d/nvidia-vrr.sh status    # после перезагрузки ожидается conceal_vrr_caps = Y, vrr_capable у DP-2 = 0
chezmoi status && git status -sb          # расхождений и незакоммиченного быть не должно
```

### Что пробовали и отвергли

- Относить окно браузера, открытое по Ctrl+N, к приложению активного окна: окно другого профиля из меню аккаунтов совпадает по pid, классу и предыдущему активному окну, ошибка остаётся незамеченной. Подробности — в `docs/window-model.md`.
- Правило окна `focus_on_activate = false` для Telegram: отключило бы и переход к топику по клику на уведомление; всплытие убрано настройкой Telegram «Подсветка окна».
- Помечать таймеры панели `FIXME` и исправлять потом: пользователь велел заменять событием сразу (`docs/decisions/0007-no-timers.md`).
- Переподключение панели к демону таймером: объект `Socket` Quickshell 0.3.1 после неудачной попытки не оживает, нужно пересоздавать его по событию.
- Судить о загрузке новой карты XKB по `hyprctl devices` или по работе нового сочетания: список раскладок берётся из той же старой карты, а старый тип клавиши срабатывал и с лишним модификатором.
- Хранить `~/.claude/settings.json` сценарием `modify_`: пользователь решил держать файл целиком.
- Брать текущий стол для команд демона из кэша событий композитора: отставшее событие возвращает прежний стол; `move-desktop` и `arrange` спрашивают стол у композитора в момент команды.

### Демон workspaced

- [ ] Новая модель окон: семейства и варианты, цикл по клавише, принятие окон в активный workspace, общие окна. Замысел целиком и серия из семи изменений OpenSpec описаны в [`docs/window-model.md`](docs/window-model.md); там же принятые предложения и две пробные задачи, которые нужны до шагов 1 и 3.
- [ ] Демон не переживает сессию, в которой у активного workspace нет монитора (экран выключен, Hyprland на выходе FALLBACK): восстановление сессии падает на `hl.dsp.focus({ workspace = … })` с ошибкой «Workspace has no monitor», и юнит после пяти попыток встаёт в `failed`. Обнаружено 22.09.2026 при перезапуске юнита с выключенным экраном; то же случится при перезаходе в сессию без монитора. Нужно либо откладывать восстановление до появления монитора, либо не считать эту ошибку смертельной.
- [ ] Запускать приложения в отдельный transient scope (`systemd-run --user --scope` или эквивалент через D-Bus), чтобы при `KillMode=process` они не оставались в cgroup демона: systemd при следующем старте пишет «Found left-over process», а память приложений учитывается демону.
- [ ] `Alt+Tab` обходит окна стола по порядку создания (`stable_id`). Если захочется порядок «по последнему использованию», нужен обработчик с удержанием Alt (флаг `release`) либо команда демона с собственной историей фокуса.
- [ ] Обход окон стола стрелками вместо `Alt+Tab`: вверх и влево — к предыдущему окну, вниз и вправо — к следующему. Отложено на отдельное обсуждение 2026-09-16.
- [ ] Парковать вытесненные окна за краем экрана, а не на `special:pool`: Hyprland сохраняет положение окна, вынесенного за пределы экрана (проверено 2026-09-16). Отложено на отдельное обсуждение.
