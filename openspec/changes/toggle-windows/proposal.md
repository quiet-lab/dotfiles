## Why

Некоторые окна нужны на любом столе, но ни к одному workspace не относятся.
Пользователь 17.10.2026 сформулировал требование: «несколько окон не входили
ни в один workspace ни при каких условиях. При этом всегда открывались
на любом workspace в чётко заданной позиции и размере по горячим клавишам,
которые всегда работают как переключатель. Нажал горячую клавишу — окно
показалось. Повторно нажал ту же — окно скрылось. Например, Telegram:
в центре, размером 1000×1000, горячая клавиша Super+T. Поскольку она занята
wezterm (herdr), назначить wezterm другую — Super+W».

Сейчас окно Telegram входит в `work` записью `telegram = { rect = … }`:
поднятие `work` забирает его, парковка `work` уводит его на `special:pool`,
а на другом столе оно не появляется. Отдельной клавиши у Telegram нет.

## What Changes

- Новый вид приложения — окно-переключатель: поле `toggle = true`
  у `[apps.<имя>]`. Его окна получают тег экземпляра `app:<имя>#N`, но
  никогда не получают тегов состава `ws:<имя>`: не захватываются при
  поднятии workspace и при появлении, не становятся дополнительным
  приложением сессии, не попадают в `config.toml` по Ctrl+Super+W и в снимок
  сессии, не паркуются при смене workspace и столов, не участвуют в циклах
  приложений, расстановке и отделении окна.
- Место переключателя — поле `rect`; `rect` без `x` и `y` означает окно
  этого размера по центру рабочей области. Проверка конфига отклоняет
  переключатель в разделе workspace, с `family`, с вариантами, без `class`
  или места, с клавишей, которую делит другое приложение, а действие
  `[[binds]]` с `workspace` или `pull` для него.
- Клавиша переключателя (привязка `workspaced key '<цепочка>'`, как у всех
  клавиш приложений): окно с фокусом на столе композитора прячется
  на `special:pool`, и фокус возвращается окну, с которым пользователь
  работал до показа; видимое без фокуса получает фокус; спрятанное или
  стоящее на другом столе приезжает на текущий стол в своё место,
  поднимается наверх и получает фокус; без окна приложение запускается.
- Окно, появившееся не по клавише, встаёт в своё место на своём столе, стол
  и фокус демон не трогает.
- Активация спрятанного окна (клик по уведомлению, `misc.focus_on_activate`)
  открывает в Hyprland 0.56.2 весь `special:pool` поверх стола; демон
  по событию `activewindowv2` показывает окно на текущем столе и закрывает
  специальный стол.
- При чтении конфига окно приложения, ставшего переключателем, теряет теги
  состава, его записи сессии и места в раскладках снимаются.
- Цепочка с выходом `apps` наследует клавишу переключателя в обоих
  состояниях; «Новое окно» для него — то же переключение.
- Конфиг: herdr получает Super+W, Telegram становится переключателем
  на Super+T с местом 1000×1000 по центру и уходит из `work`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-config`: новое требование «Окно-переключатель в конфиге» (поле
  `toggle`, место по центру, запреты, проверка конфига).
- `ws-daemon`: новое требование «Окно-переключатель» (показ, скрытие,
  запуск, появление не по клавише, активация, смена конфига, сохранения).
- `hyprland-binds`: «Раскладка клавиш сессии» (Super+T — Telegram, Super+W —
  herdr), «Цепочка приложений с выходом» (клавиши W и T).
- `hyprland-config`: «Фокус кликом и рамка активного окна» (активация
  спрятанного окна-переключателя).
- `qs-notifications`: «Действия и клики по уведомлению» (клик по уведомлению
  Telegram при спрятанном окне).

## Порядок архивации

«Раскладка клавиш сессии» взята из дельты `chains-sticky`, «Цепочка
приложений с выходом» — из дельты `sticky-chains`. Дельты написаны против
редакции, которая действует после архивации всех активных изменений,
поэтому это изменение архивируется последним — после
`session-windows-transient`.

## Impact

- Демон `~/work/pets/workspaced` (коммит `3cc271d`): `config.rs` (поле
  `toggle`, тип `AppRect`, проверки), `daemon.rs` (переключение, появление,

  `session.rs`, `keys_help.rs`, `main.rs`.
- Конфиг `dot_config/workspaced/config.toml`.
- Документация: `AGENTS.md`, `docs/window-model.md`.
- Автозапуск Telegram при входе пропадает (он запускался только потому, что
  входил в `work`); по решению пользователя автозапуска нет (`design.md`, D10).
