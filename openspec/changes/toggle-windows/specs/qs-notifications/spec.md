## MODIFIED Requirements

### Requirement: Действия и клики по уведомлению
Действия, присланные клиентом, MUST быть кнопками в карточке; клик по кнопке
MUST сообщать клиенту о выборе действия, после чего уведомление MUST
помечаться просмотренным и уходить с экрана.

Клики по карточке на экране MUST работать так: левый — выполнить действие
по умолчанию (`default`, а при его отсутствии — первое из списка), пометить
уведомление просмотренным и убрать с экрана, оставив запись в истории;
правый — выполнить то же действие и удалить запись из истории; средний —
пометить просмотренными все уведомления сразу, не выполняя никаких действий.
Если действия по умолчанию у уведомления нет — его не было изначально,
приложение его закрыло или запись восстановлена после перезапуска панели, —
левый клик MUST всё равно открывать приложение-отправитель: панель MUST
искать его окно среди окон композитора по подсказке `desktop-entry`
и по имени приложения (сопоставление с классом окна без учёта регистра),
переводить на него фокус вместе с переходом на его стол (спрятанное
окно-переключатель демон при этом показывает на текущем столе), а при
нескольких окнах выбирать то, в котором были последним. Если окна нет, панель MUST
запускать приложение по его `desktop-entry`; если и его нет — только
помечать уведомление просмотренным. Правый клик при отсутствии действия
MUST только удалять запись.

Клик — основной способ убрать уведомление с экрана: сроков показа нет.

Уходящее с экрана уведомление MUST растворяться: карточка плавно становится
прозрачной и только после этого исчезает, а состояние записи MUST меняться,
когда растворение закончилось. Растворение MUST быть анимацией, а не
отсчётом в логике: действие выполняет сигнал окончания анимации. Что при
этом происходит с соседними карточками, описывает требование «Движение
столбика».

#### Scenario: Кнопки действий
- **WHEN** выполнено `notify-send -A ok=Ок -A no=Нет "Вопрос" "Текст"`
- **THEN** в карточке под текстом появляются кнопки «Ок» и «Нет»

#### Scenario: Левый клик по карточке Telegram
- **WHEN** пришло сообщение в Telegram и пользователь кликает по карточке левой кнопкой
- **THEN** Telegram получает своё действие по умолчанию и открывает топик сообщения, карточка растворяется и исчезает, а запись остаётся в истории с отметкой «просмотрено»

#### Scenario: Левый клик по уведомлению без действия
- **WHEN** пользователь кликает левой кнопкой по карточке уведомления Telegram, у которого действия по умолчанию нет, а окно Telegram открыто на другом столе
- **THEN** композитор переходит на стол окна Telegram и отдаёт ему фокус, карточка растворяется, запись остаётся в истории с отметкой «просмотрено»

#### Scenario: Левый клик по уведомлению при спрятанном окне
- **WHEN** пользователь на столе 1 кликает левой кнопкой по карточке уведомления Telegram, у которого действия по умолчанию нет, а окно Telegram спрятано на `special:pool` клавишей окна-переключателя
- **THEN** панель отдаёт фокус окну Telegram, демон показывает его на столе 1 в месте переключателя и закрывает `special:pool` (спецификация ws-daemon, «Окно-переключатель»), карточка растворяется, запись остаётся в истории с отметкой «просмотрено»

#### Scenario: Правый клик по уведомлению Telegram
- **WHEN** пришло сообщение в Telegram и пользователь кликает по карточке правой кнопкой
- **THEN** Telegram получает своё действие по умолчанию, окно приложения показывается, карточка растворяется, а записи об этом уведомлении в истории не остаётся

#### Scenario: Средний клик
- **WHEN** на экране три карточки и пользователь кликает по любой из них средней кнопкой
- **THEN** все три растворяются и уходят с экрана, их записи остаются в истории с отметкой «просмотрено», и ни одно действие не выполняется
