# Design: Фокус на панели ввода

## Решение

Пользователь 6 ноября 2026 решил: после открытия панели ввода фокус
у неё. Прежняя формулировка («без передачи фокуса») правится тем же
изменением. 7 ноября уточнено: клиент на другой workspace не
переключается; форк herdr получает команду `herdr pane activate <панель>`,
до выпуска форка хук работает запасным путём.

## Что проверялось

Хук срабатывает и у исполнителей duty в workspace, которые пользователь
не смотрит. `herdr pane split --focus` и `herdr pane focus` в таком
workspace переключают клиент на него; `--no-focus` клиент не трогает.
Команды сфокусировать панель без переключения клиента в herdr нет.

## Два пути

- Основной: панель делится с `--no-focus`, поправляется высота, запускается
  neovim, затем `herdr pane activate "$new"`: панель становится
  сфокусированной в своей вкладке, активный workspace клиента не меняется.
  Наличие команды проверяется `herdr pane activate --help` до деления.
- Запасной (команды нет): `split --focus`, если `HERDR_WORKSPACE_ID` — workspace
  с `focused: true` в `herdr workspace list`; иначе `--no-focus`, фокус
  остаётся у Claude Code.

## Условие снятия запасного пути

Выпуск форка herdr с `pane activate` на станции. Запасной путь убирается
отдельным изменением.
