## Context

Мотивация — в `proposal.md`. Все привязки сессии задаёт конфиг демона
workspaced, а `hyprland.lua` выполняет код, который печатает
`workspaced keys --lua` (спецификации hyprland-binds и ws-config).
Цепочка из нескольких звеньев сейчас превращается в дерево подкарт
Hyprland (`src/keys.rs`, функции `to_lua` и `emit`): первое сочетание
открывает подкарту `ws:<сочетания>`, последнее звено выполняет действие
и закрывает подкарту (`hl.dsp.submap("reset")`), Escape закрывает её без
действия. Нажатие, которого в подкарте нет, уходит приложению, а подкарта
остаётся открытой.

Клавиша приложения (`workspaced key '<цепочка>'`, спецификация ws-daemon,
«Цепочка приложения») выбирает приложение и workspace по активному
workspace текущего стола и ведёт цикл по экземплярам; приложение
запускается, только когда окон нет. Пока запуск не дал окна, повторная
клавиша второго экземпляра не заводит (`Daemon::spawn`, список `pending`).

Что умеет Hyprland 0.56.2 (проверено по заглушкам
`/usr/share/hypr/stubs/hl.meta.lua`, по исходнику
`src/managers/KeybindManager.cpp` тега v0.56.2 и пробой через `hyprctl eval`):

- `hl.define_submap(имя, fn)` объявляет подкарту, привязки внутри `fn`
  принадлежат ей; форма `hl.define_submap(имя, "reset", fn)` закрывает
  подкарту после любого действия, если действие само её не сменило.
- `hl.bind("catchall", …)` внутри подкарты — привязка на любую клавишу;
  вне подкарты композитор её отклоняет («catchall keybinds are only allowed
  in submaps»). Проба: `hyprctl binds -j` показывает её с `catch_all: true`
  и пустым `key`.
- Условие модификаторов действует и на `catchall`: без `ignore_mods`
  привязка с пустой маской ловит только нажатия без модификаторов.
  С `ignore_mods = true` — любые.
- Признак «нажатие уже обработано», который проверяет `catchall`,
  выставляется только после выполнения найденных привязок. Поэтому
  `catchall` срабатывает вместе с совпавшей привязкой, а не вместо неё,
  и порядок объявления этого не меняет.
- Клавиша привязки сравнивается с keysym первой раскладки карты XKB
  (`m_xkbTranslationState`), без учёта регистра: при русской раскладке
  клавиша `v` остаётся `v`, Shift+V совпадает с `v`.
- Смена подкарты шлёт в `.socket2.sock` событие `submap>>имя`, закрытие —
  `submap>>` с пустым именем (проверено: `hl.dsp.submap` через
  `hyprctl eval`). `hyprctl submap` печатает текущую подкарту
  (`default`, если её нет), Lua — `hl.get_current_submap()`.
- `hl.dsp.no_op()` — пустое действие.

## Goals / Non-Goals

**Goals:**

- Цепочка с выходом: сочетание входа открывает режим, который остаётся
  открытым до клавиши выхода; все нажатия внутри режима обрабатывает он.
- Состояния режима образуют дерево: клавиша ведёт в дочернее состояние,
  Backspace — к родителю, Escape — из режима с любого уровня, клавиша
  с признаком выхода выполняет действие и закрывает режим.
- Клавиши приложений (Super+буква) доступны в состоянии одной буквой без
  повторного описания в конфиге: «поднять или открыть» и «открыть новый
  экземпляр».
- Пользователь видит, что режим открыт и какие клавиши в нём действуют.
- Ни одного таймера: режим закрывается только клавишей.

**Non-Goals:**

- Переход между соседними состояниями одной клавишей (только через
  родителя по Backspace).
- Вход в режим звеном многозвенной цепочки.
- Клавиши мультимедиа и громкости внутри режима (они поглощаются, как
  прочие нажатия).
- Изменение нынешних одноразовых цепочек.

## Decisions

### D1. Отдельный раздел `[sticky.<имя>]`

Цепочка с выходом описывается в новом разделе конфига:

```toml
[sticky.apps]
enter = "SUPER+A"
title = "Приложения"
[sticky.apps.keys]
r = { state = "raise" }
s = { state = "spawn" }

[sticky.apps.states.raise]
title = "Поднять"
apps = "raise"
[sticky.apps.states.raise.keys]
e = { exit = true }

[sticky.apps.states.spawn]
title = "Новое окно"
apps = "spawn"
[sticky.apps.states.spawn.keys]
e = { exit = true }
```

Сама запись `[sticky.<имя>]` — корневое состояние; `states` — дочерние
состояния, у каждого те же поля (`title`, `apps`, `keys`, `states`),
вложенность произвольная. Клавиша состояния — таблица с ровно одним из
полей `state` (перейти в дочернее состояние), `action`, `exec`, `dispatch`,
`lua` (те же действия, что у `[[binds]]`) либо без действия, если клавиша
унаследована от приложений (D5); необязательные `exit` (после действия
закрыть цепочку) и `desc`. `title` — подпись состояния для индикатора
и подсказки, по умолчанию имя состояния.

Рассмотренные варианты:

- Поле `sticky = true` у нынешних строковых цепочек (`chain = "SUPER+A r v"`)
  с общей моделью «дерево подкарт». Отвергнуто: строка цепочки описывает
  один путь до одного действия, а у режима несколько путей с общими
  узлами, подписи состояний, наследование клавиш приложений и Backspace
  к родителю. Для этого строки пришлось бы собирать в дерево по общим
  префиксам и отдельно задавать свойства узлов — это тот же раздел,
  только разбросанный по записям. Общим у двух видов остаётся генератор
  подкарт (D4).
- Раздел `[[modes]]` или `[modes.<имя>]`. Отвергнуто из-за имени: поле
  `mode` у workspace уже означает режим клавиши (`swap`/`stack`).
- Плоский список состояний с полем `parent`. Отвергнуто: вложенные таблицы
  TOML сами задают дерево, а проверка на циклы не нужна.

### D2. Дерево состояний; Backspace — к месту объявления

Родитель состояния — состояние, в `states` которого оно записано. Клавиша
`state` может вести только в дочернее состояние того же узла, и в каждое
дочернее состояние должна вести хотя бы одна клавиша. Backspace
возвращает к родителю, в корне — закрывает цепочку. Поэтому «предыдущий
шаг» из задачи — это всегда родитель, и подкарта Backspace известна при
генерации кода: история переходов не нужна.

Рассмотренные варианты:

- Граф состояний с переходами в любое состояние и Backspace «на шаг
  назад по истории». Отвергнуто: историю пришлось бы хранить в Lua-коде
  композитора или в демоне, а при переходе из соседнего состояния
  Backspace вёл бы в разные места — это труднее запомнить. Пользователь
  описал путь «Backspace, затем S», дерево его покрывает.

### D3. Клавиши состояний — одно имя keysym, привязка с `ignore_mods`

Ключ таблицы `keys` — имя клавиши Hyprland без модификаторов (`v`, `Tab`,
`1`, `F5`). Привязка получает `ignore_mods = true`: клавиша срабатывает
и при удержанном Super, поэтому после Super+A можно не отпускать Super
и нажимать R, V, V, Y. Shift+V совпадает с `v`: композитор сравнивает keysym
без учёта регистра. `Escape` и `BackSpace` заняты во всех состояниях,
и в `keys` они отклоняются; сочетания с `+` и кнопки мыши тоже.

Рассмотренные варианты:

- Клавиши с модификаторами внутри состояния (`SHIFT+v` отдельно от `v`).
  Отвергнуто: с `ignore_mods` их не различить, а без него Super пришлось
  бы отпускать после входа, и нажатие с удержанным Super уходило бы
  в `catchall` без действия.

### D4. Поглощение: `catchall` с пустым действием

В каждой подкарте цепочки с выходом последней объявляется
`hl.bind("catchall", hl.dsp.no_op(), { ignore_mods = true })`: нажатие,
которому нет привязки в состоянии, не доходит до приложения и ничего
не делает, режим остаётся в том же состоянии. Действие `catchall` должно
быть пустым: он срабатывает и вместе с совпавшей привязкой (см. Context),
поэтому `reset` или переход в нём отменял бы и верные нажатия.

Одноразовые цепочки остаются как есть, без `catchall`. Рассматривалось
дать им `catchall` с закрытием подкарты, чтобы случайная клавиша не
оставляла подкарту открытой. Отвергнуто: по той же особенности `catchall`
закрывал бы подкарту и после верного звена, а без `ignore_mods` —
от нажатия одного Ctrl между звеньями цепочки сохранения. Изменение
одноразовых цепочек пользователь не просил.

Отвергнуто также `submap_universal` для клавиш громкости и мультимедиа,
чтобы они действовали внутри режима: задача требует, чтобы все нажатия
обрабатывала цепочка.

### D5. Наследование клавиш приложений (`apps`)

Поле состояния `apps = "raise"` добавляет в состояние по клавише на каждую
цепочку приложения из одного сочетания с единственным модификатором Super
(собственная клавиша приложения или ключ приложения в workspace — те же
цепочки, что дают привязки `workspaced key`). Клавиша — буква сочетания
в нижнем регистре, действие — `workspaced key '<цепочка>'`. Поле
`apps = "spawn"` даёт те же клавиши с действием
`workspaced key --new '<цепочка>'` (D6). В конфиге сессии это T, C, E
(собственные клавиши herdr, Chromium, neovide) и B, V, Y (ключи браузеров
в `surf`). Цепочки Shift+Super+буква не наследуются: с `ignore_mods`
их буква совпала бы с буквой Super+буква.

Запись в `keys` с тем же именем без поля действия дополняет унаследованную
клавишу: задаёт `exit` и `desc`. Запись с действием заменяет унаследованную
клавишу. Запись без действия для клавиши, которой нет среди унаследованных,
отклоняется.

Рассмотренные варианты:

- Перечислять клавиши приложений в каждом состоянии явно. Отвергнуто:
  при новой клавише приложения пришлось бы править и режим, а расхождение
  проверка не заметила бы.
- Отдельный признак `exit_keys = ["e"]` у состояния. Отвергнуто: второе
  место для того же признака; запись `e = { exit = true }` читается так же
  и позволяет добавить описание.

### D6. «Поднять» — та же клавиша приложения; «новое окно» — `key --new`

Действие клавиши в состоянии `raise` — ровно то, что делает Super+буква:
`workspaced key 'SUPER+V'`. Поэтому V в режиме подчиняется тем же правилам
workspace и столов: в `surf` ведёт цикл по окнам Chrome, на другом столе
поднимает `surf`, без окон — открывает Chrome на его месте; повторное V
выбирает следующий экземпляр, а за последним цикл возвращает прежнее окно
(спецификация ws-daemon, «Цепочка приложения»).

Демон получает ключ `--new` у команд `key` и `app` (запрос сокета —
поле `"new": true`). Приложение и workspace выбираются так же, как без
ключа, а вместо цикла демон запускает новый экземпляр:

| Путь клавиши | Без `--new` | С `--new` |
|---|---|---|
| приложение в активном workspace текущего стола | цикл | новый экземпляр на месте приложения в этом workspace |
| workspace приложения активен на другом столе или в списке стола | поднять его и начать цикл | поднять его и открыть новый экземпляр там |
| на столе другой активный workspace (`pull` или открытие) | перетащить окна или открыть приложение в нём | открыть новый экземпляр в активном workspace стола |
| на столе нет активного workspace | цикл по окнам вне workspace | новый экземпляр на месте по умолчанию |

В режиме обмена мест новый экземпляр — тоже выбор экземпляра: приложение
сначала занимает главное место, как при запуске из цикла. Окно получает
тег экземпляра с наименьшим свободным номером и фокус при появлении.

Рассмотренные варианты:

- `workspaced app <имя>` в состоянии режима. Отвергнуто для наследования:
  команда действует как собственная клавиша приложения и не учитывает
  ключи приложений в workspace (Super+V — ключ `chrome-ai` в `surf`,
  собственная клавиша `chrome-ai` — Shift+Super+V). Для явных клавиш
  состояния она остаётся доступна действием `{ app = "<имя>" }`, а новый
  экземпляр — `{ app = "<имя>", new = true }`.
- Открывать новый экземпляр диспетчером композитора (`exec`) без демона.
  Отвергнуто: окно не получило бы места и тега экземпляра.

### D7. Несколько ожиданий запуска одного приложения

Без `--new` правило прежнее: пока запуск приложения не дал окна, повторная
клавиша ждёт. С `--new` демон заводит новую запись ожидания, даже если для
приложения уже есть незавершённая: V, V, V в состоянии «Новое окно» дают
три запуска. Появившееся окно достаётся самой ранней подходящей записи
(порядок `pending`). Браузер, который уже работает, отдаёт новое окно
прежнему процессу, а запущенная команда завершается сразу; такая запись
ждёт окно по классу — как сейчас после выхода процесса. Срока ожидания
по-прежнему нет.

### D8. Вход — одиночное сочетание Super+A

`enter` — одно сочетание (звено). Оно участвует в общих проверках цепочек:
не совпадает с другой цепочкой, не является началом цепочки и не входит
в `reserved`. В конфиге сессии вход — Super+A: Super+S, названное
пользователем для примера, занято окном выбора сессии (`[keys] sessions`,
`workspaced keys --list` 23.09.2026), а Super+A свободно и запоминается
как «applications».

Рассмотренные варианты:

- Перенести окно выбора сессии на другое сочетание и отдать Super+S
  режиму. Отвергнуто без решения пользователя: окно сессий — привычная
  клавиша, а пример в задаче описывает механизм, а не выбор сочетания.
  Если пользователь захочет Super+S, достаточно поменять два поля конфига.
- Вход звеном многозвенной цепочки (`SUPER+TAB a`). Отвергнуто: последнее
  звено одноразовой цепочки закрывает подкарту, и для входа в режим его
  пришлось бы делать исключением.

### D9. Имена подкарт и сброс устаревшей подкарты

Подкарта состояния называется `ws-sticky:<имя цепочки>` для корня
и `ws-sticky:<имя>/<состояние>/<состояние>…` для вложенных. Имена цепочек
и состояний — латинские строчные буквы, цифры и дефис: они входят в имя
подкарты. Префикс `ws-sticky:` отличает режим от одноразовых подкарт `ws:…`
и нужен индикатору панели.

Если конфиг перечитан, пока открыт режим, а состояния в новом конфиге нет,
подкарта осталась бы без привязок, в том числе без Escape, и все сочетания
сессии перестали бы работать. Поэтому код `keys --lua` заканчивается
проверкой: если `hl.get_current_submap()` начинается с `ws-sticky:` или
`ws:` и такой подкарты в этом коде нет, подкарта закрывается. Режим,
состояние которого осталось, после перечитывания не закрывается.

### D10. Строки `keys --list` и `keys --json`

`keys --list` показывает цепочку с выходом путями: `SUPER+A` — действие
`sticky apps`, `SUPER+A r` — `state raise`, `SUPER+A r v` — `key SUPER+V`,
`SUPER+A s v` — `key --new SUPER+V`; у клавиши с выходом в колонке флагов
стоит `exit`, источник — `sticky.apps` либо `sticky.apps.raise`. Пути
в проверке совпадения и начала цепочек не участвуют: цепочкой
сессии является только сочетание входа.

`keys --json` выводит те же строки группой «Цепочки с выходом» (после
«Приложения»): подпись «Super+A r v», описание «Поднять · chrome-ai
в workspace surf» — подпись состояния и описание унаследованной клавиши.
Кроме групп, JSON получает раздел `sticky` — плоский список состояний
для индикатора: имя подкарты, путь подписей и клавиши состояния
с подписью, описанием и признаком выхода. Отдельный раздел нужен, чтобы
индикатор находил состояние по имени подкарты из события без разбора строк.

### D11. Индикатор — карточка вверху рабочей области, по событию `submap`

Панель слушает событие Hyprland `submap` (как плитка раскладки —
`activelayout`). Имя с префиксом `ws-sticky:` показывает карточку,
любое другое или пустое имя — скрывает её. Карточка стоит вверху по центру
рабочей области (отступ 10 px от верхнего края, центр по горизонтали
2085 px — как у окна подсказки клавиш), на слое Overlay, не берёт
клавиатуру и не принимает ввод мыши. В ней путь подписей
(«Приложения ▸ Поднять»), клавиши текущего состояния с описаниями,
клавиши выхода отмечены, внизу строка «Backspace — назад · Escape — выход».

Перечень клавиш панель получает командой `workspaced keys --json`
при входе в режим (событие с `ws-sticky:` после имени без этого префикса):
переходы внутри режима обходятся без процесса. Пока команда выполняется
или если она завершилась ошибкой, карточка показывает путь из имени
подкарты (имена состояний) и, при ошибке, текст ошибки. При старте панель
один раз читает `hyprctl submap`, чтобы после перезапуска панели внутри
режима карточка была на месте. Опроса нет.

Рассмотренные варианты:

- Надпись в плитке раскладки 36×36. Отвергнуто: путь и клавиши не
  помещаются, а без перечня клавиш режим трудно освоить.
- Новая плитка колонки. Отвергнуто: меняет выверенную геометрию колонки
  (спецификация qs-shell) ради состояния, которое видно лишь несколько
  секунд.
- Уведомление. Отвергнуто: уведомления уходят только кликом или клавишей,
  а клавиатура в режиме занята цепочкой.
- Карточка у нижнего края рядом с плиткой раскладки. Отвергнуто: там
  растёт столбик уведомлений.

### D12. Демон не хранит состояние режима

Весь режим живёт в подкартах композитора; демон узнаёт о нём только
через команды клавиш. Если демон остановлен, Escape и Backspace
по-прежнему работают, и выйти из режима можно всегда.

Рассмотренные варианты:

- Автомат состояний в демоне, каждое нажатие — команда сокету.
  Отвергнуто: поглощать нажатия всё равно должен композитор, а при
  недоступном демоне режим нельзя было бы закрыть.

## Risks / Trade-offs

- Пользователь может забыть, что режим открыт, и нажимать клавиши, которые поглощаются →
  карточка индикатора видна всё время, пока режим открыт; Escape
  закрывает его с любого уровня.
- Экран заблокирован при открытом режиме: привязки без `locked` при
  блокировке не действуют, и ввод получает hyprlock; после разблокировки
  режим остаётся открытым → индикатор напоминает о нём.
- Приложение, запрещающее сочетания композитора (shortcuts inhibitor),
  отключает и привязки подкарты → такого приложения в сессии нет; если
  появится, Escape в нём не закроет режим, и это записывается в
  `docs/host-state.md` при появлении.
- Нажатия с удержанием клавиши (повтор) внутри режима не повторяются:
  флага `repeating` у клавиш состояний нет.
- Поведение `ignore_mods` и `catchall` выведено из исходника и проверено
  регистрацией привязок, но не нажатиями: `wtype` привязки композитора
  не запускает. Нажатия проверяет пользователь (задачи 6.x).

## Migration Plan

Изменение только добавляет раздел конфига, ключи команд и окно панели.
Порядок: демон с тестами и пересборкой, затем конфиг сессии (демон сам
вызывает `hyprctl reload config-only`), затем панель. Откат — удалить
раздел `[sticky.apps]` из конфига: подкарты исчезнут при перечитывании.
