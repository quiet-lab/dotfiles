## ADDED Requirements

### Requirement: Новый экземпляр приложения
Команда `workspaced key --new '<цепочка>'` MUST выбирать приложение и workspace так же, как клавиша приложения без ключа (требование «Цепочка приложения»), а вместо цикла по экземплярам MUST запускать новый экземпляр приложения: если приложение описано в активном workspace текущего стола — на месте приложения в этом workspace; если клавиша поднимает workspace приложения (он активен на другом столе или ждёт в списке стола) — поднять его по тем же правилам и запустить новый экземпляр там; если на текущем столе активен другой workspace (путь перетаскивания или открытия приложения) — запустить новый экземпляр в активном workspace текущего стола, и приложение входит в него по правилам открытия; если на текущем столе нет активного workspace — запустить новый экземпляр на месте приложения по умолчанию (`rect` приложения, а без него — центр рабочей области). В workspace режима обмена мест приложение MUST сначала занимать главное место, как при запуске из цикла, и новое окно MUST появляться уже на нём. Команда `workspaced app <имя> --new` MUST делать то же для названного приложения по правилам команды `workspaced app <имя>`. Новое окно MUST получать тег экземпляра с наименьшим свободным номером и фокус при появлении. Цепочка, на которую не отзывается ни одно приложение, MUST давать строку в журнале без действия; приложение без `cmd` MUST NOT запускаться, и это MUST записываться в журнал.

Запуск с `--new` MUST выполняться и тогда, когда предыдущий запуск того же приложения ещё не дал окна: демон MUST заводить для него отдельную запись ожидания, а появившееся окно приложения MUST доставаться самой ранней подходящей записи. Если запущенная команда завершилась, не открыв окна (браузер отдал новое окно уже работающему процессу), запись MUST ждать окно по классу и заголовку приложения, как ожидание после выхода процесса без `--new`; срока ожидания MUST NOT быть. Клавиша приложения без `--new` MUST по-прежнему не заводить второго запуска, пока идёт незавершённый.

#### Scenario: Три новых окна подряд
- **WHEN** `surf` активен на столе 2 в режиме `stack`, у `chrome-ai` одно окно, и трижды подряд выполнена `workspaced key --new 'SUPER+V'`
- **THEN** появляются три новых окна Chrome профиля AI.dev2026 с тегами `app:chrome-ai#2`, `#3`, `#4`, каждое на месте `chrome-ai` в `surf` поверх прежних, последнее появившееся — в фокусе; прежнее окно осталось на месте

#### Scenario: Новый экземпляр с другого стола
- **WHEN** на столе 1 активен `work`, `surf` активен на столе 2, и выполнена `workspaced key --new 'SUPER+Y'`
- **THEN** демон переходит на стол 2 и открывает там новое окно Яндекс.Браузера на месте `yandex-browser`; окна `work` не меняются

#### Scenario: Новый экземпляр в режиме обмена мест
- **WHEN** на столе 1 активен `work` с главным `herdr`, и выполнена `workspaced key --new 'SUPER+E'`
- **THEN** neovide занимает главное место, `herdr` уходит на место neovide, новое окно neovide появляется в центральной ячейке поверх прежнего и получает фокус; оба окна neovide входят в `work` экземплярами `#1` и `#2`

#### Scenario: Новый экземпляр по имени
- **WHEN** выполнена `workspaced app neovide --new` на столе без активного workspace
- **THEN** новое окно neovide открывается в центре рабочей области и получает фокус; прежние окна neovide не двигаются
