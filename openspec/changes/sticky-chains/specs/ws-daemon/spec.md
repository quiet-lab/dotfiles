## ADDED Requirements

### Requirement: Новый экземпляр приложения
Команда `workspaced key --new '<цепочка>'` MUST выбирать приложение и workspace так же, как клавиша приложения без ключа (требование «Цепочка приложения»), а вместо цикла по экземплярам MUST запускать новый экземпляр приложения. Команда `workspaced app <имя> --new` MUST делать то же для названного приложения по правилам команды `workspaced app <имя>`. Новое окно MUST получать тег экземпляра с наименьшим свободным номером и фокус при появлении.

#### Scenario: Новый экземпляр по имени
- **WHEN** выполнена `workspaced app neovide --new` на столе без активного workspace
- **THEN** новое окно neovide открывается в центре рабочей области и получает фокус; прежние окна neovide не двигаются

### Requirement: Место нового экземпляра в workspace
Если приложение описано в активном workspace текущего стола, новый экземпляр MUST запускаться на месте приложения в этом workspace. Если клавиша поднимает workspace приложения (он активен на другом столе или ждёт в списке стола), демон MUST поднять его по тем же правилам и запустить новый экземпляр там. В workspace режима обмена мест приложение MUST сначала занимать главное место, как при запуске из цикла, и новое окно MUST появляться уже на нём.

#### Scenario: Три новых окна подряд
- **WHEN** `surf` активен на столе 2 в режиме `stack`, у `chrome-ai` одно окно, и трижды подряд выполнена `workspaced key --new 'SUPER+V'`
- **THEN** появляются три новых окна Chrome профиля AI.dev2026 с тегами `app:chrome-ai#2`, `#3`, `#4`, каждое на месте `chrome-ai` в `surf` поверх прежних, последнее появившееся — в фокусе; прежнее окно осталось на месте

#### Scenario: Новый экземпляр с другого стола
- **WHEN** на столе 1 активен `work`, `surf` активен на столе 2, и выполнена `workspaced key --new 'SUPER+Y'`
- **THEN** демон переходит на стол 2 и открывает там новое окно Яндекс.Браузера на месте `yandex-browser`; окна `work` не меняются

#### Scenario: Новый экземпляр в режиме обмена мест
- **WHEN** на столе 1 активен `work` с главным `herdr`, и выполнена `workspaced key --new 'SUPER+E'`
- **THEN** neovide занимает главное место, `herdr` уходит на место neovide, новое окно neovide появляется в центральной ячейке поверх прежнего и получает фокус; оба окна neovide входят в `work` экземплярами `#1` и `#2`

### Requirement: Место нового экземпляра вне workspace приложения
Если на текущем столе активен другой workspace (путь перетаскивания или открытия приложения), новый экземпляр MUST запускаться в активном workspace текущего стола, и приложение входит в него по правилам открытия. Если на текущем столе нет активного workspace, новый экземпляр MUST запускаться на месте приложения по умолчанию (`rect` приложения, а без него — центр рабочей области).

#### Scenario: Новый экземпляр в чужом workspace
- **WHEN** на столе 1 активен `work`, `surf` не запущен ни на одном столе, и выполнена `workspaced key --new 'SUPER+SHIFT+Y'`
- **THEN** новое окно Яндекс.Браузера открывается на столе 1 и входит в `work` по правилам открытия приложения; другие столы не меняются

### Requirement: Новый экземпляр без запуска
Цепочка, на которую не отзывается ни одно приложение, MUST давать строку в журнале без действия; приложение без `cmd` MUST NOT запускаться, и это MUST записываться в журнал.

#### Scenario: Цепочка без приложения
- **WHEN** выполнена `workspaced key --new 'SUPER+F12'`, а на `SUPER+F12` не отзывается ни одно приложение
- **THEN** ничего не запускается, окна не меняются, в журнале демона строка о том, что на клавишу не отзывается ни одно приложение

### Requirement: Новый экземпляр до появления окна
Запуск с `--new` MUST выполняться и тогда, когда предыдущий запуск того же приложения ещё не дал окна: демон MUST заводить для него отдельную запись ожидания, а появившееся окно приложения MUST доставаться самой ранней подходящей записи. Клавиша приложения без `--new` MUST по-прежнему не заводить второго запуска, пока идёт незавершённый.

#### Scenario: Два запуска до появления окна
- **WHEN** у `neovide` нет ни одного окна, и `workspaced key --new 'SUPER+E'` выполнена дважды подряд, до появления первого окна
- **THEN** запускаются два процесса neovide, появившиеся окна получают по записи ожидания в порядке запуска и два соседних номера экземпляров; та же пара вызовов `workspaced key 'SUPER+E'` без `--new` запускает neovide один раз

### Requirement: Ожидание окна нового экземпляра
Если запущенная команда завершилась, не открыв окна (браузер отдал новое окно уже работающему процессу), запись MUST ждать окно по классу и заголовку приложения, как ожидание после выхода процесса без `--new`; срока ожидания MUST NOT быть.

#### Scenario: Браузер отдаёт окно работающему процессу
- **WHEN** Chrome профиля AI.dev2026 уже работает и выполнена `workspaced key --new 'SUPER+V'` в `surf`
- **THEN** запущенная команда завершается, не открыв окна, а новое окно, открытое работающим процессом, получает следующий номер экземпляра и место `chrome-ai` в `surf`
