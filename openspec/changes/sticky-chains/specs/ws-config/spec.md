## ADDED Requirements

### Requirement: Цепочки с выходом
Конфиг MUST принимать необязательный раздел `[sticky.<имя>]` — цепочку с выходом: режим, который открывается сочетанием входа и остаётся открытым, пока не нажата клавиша выхода. Запись `[sticky.<имя>]` — корневое состояние цепочки с обязательным полем `enter` (сочетание входа из одного звена в синтаксисе цепочек) и полями состояния: `title` (подпись состояния для индикатора и подсказки, по умолчанию имя), `apps` (`"raise"` или `"spawn"`), `keys` (таблица клавиш) и `states` (таблица дочерних состояний с теми же полями, кроме `enter`, вложенность произвольная). Родитель состояния MUST быть состоянием, в `states` которого оно записано. Имена цепочек и состояний MUST состоять из латинских строчных букв, цифр и дефиса.

Ключ таблицы `keys` MUST быть именем одной клавиши Hyprland без модификаторов (`v`, `Tab`, `F5`); ключ с `+`, кнопка мыши, `Escape` и `BackSpace` MUST отклоняться с указанием цепочки, состояния и клавиши. Значение — таблица с не более чем одним из полей `state` (имя дочернего состояния этого же узла: перейти в него), `action`, `exec`, `dispatch`, `lua` (действия с тем же смыслом и теми же проверками, что у записи `[[binds]]`) и необязательными полями `exit` (логическое: после действия закрыть цепочку; с `state` не допускается) и `desc` (описание для индикатора и подсказки). С указанием цепочки и состояния MUST отклоняться: клавиша, ведущая в несуществующее состояние; дочернее состояние, в которое не ведёт ни одна клавиша; состояние без единой клавиши.

Поле `apps = "raise"` MUST добавлять в состояние по клавише на каждую цепочку клавиши приложения (собственная клавиша приложения или ключ приложения в workspace, требование «Цепочки клавиш и привязки»), состоящую из одного сочетания с единственным модификатором Super: клавиша — клавиша этого сочетания в нижнем регистре, действие — команда `workspaced key '<цепочка>'`, то есть ровно действие самого сочетания Super+клавиша. Поле `apps = "spawn"` MUST добавлять те же клавиши с действием `workspaced key --new '<цепочка>'` (спецификация ws-daemon, «Новый экземпляр приложения»). Иное значение `apps` MUST отклоняться с указанием допустимых. Запись в `keys` без поля действия MUST дополнять одноимённую унаследованную клавишу полями `exit` и `desc`, а для клавиши, которой нет среди унаследованных, MUST отклоняться как клавиша без действия; запись с действием MUST заменять одноимённую унаследованную клавишу.

Сочетание `enter` MUST проходить те же проверки, что и остальные цепочки: не совпадать с другой цепочкой, не быть началом цепочки и не входить в список `reserved`; ошибка MUST называть обе записи (`sticky.<имя>` и вторую) либо запись и зарезервированное сочетание. Вход звеном многозвенной цепочки MUST отклоняться. Клавиши состояний сочетаниями сессии не являются и в проверке совпадения и начала цепочек MUST NOT участвовать.

Действие `action = { app = "<имя>", new = true }` записи `[[binds]]` и клавиши состояния MUST вызывать команду `workspaced app <имя> --new`; ключ `new` допустим только вместе с `app` и без `workspace` и `pull`, иначе запись MUST отклоняться с указанием цепочки и ключа `new`.

#### Scenario: Цепочка приложений сессии
- **WHEN** в конфиге есть `[sticky.apps]` с `enter = "SUPER+S"`, клавишами `r = { state = "raise" }` и `s = { state = "spawn" }`, состояния `raise` с `apps = "raise"` и `spawn` с `apps = "spawn"`, в обоих `e = { exit = true }`, а у приложений цепочки Super+T, Super+C, Super+E и ключи `surf` Super+B, Super+V, Super+Y
- **THEN** `workspaced check` завершается успешно; `workspaced keys --list` содержит строки `SUPER+S` — `sticky apps`, `SUPER+S r` — `state raise`, `SUPER+S r v` — `key SUPER+V`, `SUPER+S s v` — `key --new SUPER+V`, `SUPER+S s e` — `key --new SUPER+E` с флагом `exit`; клавиш от цепочек Shift+Super+B, Shift+Super+V и Shift+Super+Y в состояниях нет

#### Scenario: Вход совпадает с привязкой
- **WHEN** у `[sticky.apps]` задано `enter = "SHIFT+SUPER+S"`, а в `[keys]` — `sessions = "SHIFT+SUPER+S"`
- **THEN** `workspaced check` завершается с ошибкой, называющей `sticky.apps` и `keys.sessions`

#### Scenario: Вход занимает зарезервированное сочетание
- **WHEN** у `[sticky.apps]` задано `enter = "SUPER+space"`, а `SUPER+space` есть в `reserved`
- **THEN** `workspaced check` завершается с ошибкой, называющей `sticky.apps` и зарезервированное сочетание

#### Scenario: Недопустимая клавиша состояния
- **WHEN** в `[sticky.apps.keys]` записана клавиша `Escape` либо `"SHIFT+v"`
- **THEN** `workspaced check` завершается с ошибкой, называющей `sticky.apps`, корневое состояние и клавишу

#### Scenario: Переход в чужое состояние
- **WHEN** в состоянии `raise` записано `s = { state = "spawn" }`, а `spawn` — дочернее состояние корня, а не `raise`
- **THEN** `workspaced check` завершается с ошибкой, называющей `sticky.apps`, состояние `raise` и `spawn`

#### Scenario: Недостижимое состояние
- **WHEN** у `[sticky.apps]` есть состояние `states.move`, но ни одна клавиша корня не ведёт в него
- **THEN** `workspaced check` завершается с ошибкой, называющей `sticky.apps` и `move`

#### Scenario: Дополнение и замена унаследованной клавиши
- **WHEN** в состоянии `raise` с `apps = "raise"` записаны `e = { exit = true }`, `c = { exec = "chromium --incognito" }` и `q = { exit = true }`
- **THEN** `workspaced check` завершается с ошибкой, называющей клавишу `q` как клавишу без действия; без записи `q` проверка проходит, `SUPER+S r e` — `key SUPER+E` с флагом `exit`, `SUPER+S r c` — `exec chromium --incognito`

#### Scenario: Новый экземпляр в записи привязки
- **WHEN** в `[[binds]]` есть `chain = "SUPER+SHIFT+E"` и `action = { app = "neovide", new = true }`
- **THEN** `workspaced check` завершается успешно, `workspaced keys --list` показывает для `SUPER+SHIFT+E` команду `app neovide --new`, а запись с `action = { workspace = "work", new = true }` отклоняется с указанием цепочки и ключа `new`

## MODIFIED Requirements

### Requirement: Генерация привязок для Hyprland
Команда `workspaced keys --lua` MUST печатать код Lua для конфига Hyprland, который объявляет все привязки конфига: одиночные сочетания — прямыми привязками с их флагами, цепочки — подкартами для каждого префикса, где последнее сочетание выполняет действие и закрывает подкарту, а `Escape` в любой подкарте закрывает её без действия. Цепочка с выходом (требование «Цепочки с выходом») MUST давать прямую привязку сочетания входа, открывающую подкарту корневого состояния `ws-sticky:<имя>`, и по подкарте на каждое состояние (`ws-sticky:<имя>/<состояние>/…` по пути от корня). В подкарте состояния MUST быть: привязки клавиш состояния с `ignore_mods = true` — переход открывает подкарту дочернего состояния, действие выполняется без закрытия подкарты, действие клавиши с `exit` выполняется и закрывает подкарту; `BackSpace` с `ignore_mods = true`, открывающий подкарту родителя, а в корне закрывающий подкарту; `Escape` с `ignore_mods = true`, закрывающий подкарту на любом уровне; последней — привязка `catchall` с пустым действием (`hl.dsp.no_op()`) и `ignore_mods = true`, которая поглощает прочие нажатия. Действие `catchall` MUST оставаться пустым: композитор выполняет его и вместе с совпавшей привязкой. Подкарты одноразовых цепочек привязки `catchall` MUST NOT получать. Код MUST заканчиваться проверкой текущей подкарты композитора: если её имя начинается с `ws:` или `ws-sticky:` и такой подкарты в этом коде нет, подкарта MUST закрываться. Действия демона MUST вызывать соответствующую подкоманду; `exec`, `dispatch` и `lua` MUST выполняться композитором без участия демона. Код MUST зависеть только от конфига и быть одинаковым при повторных вызовах с тем же файлом. При успешной генерации команда MUST записать копию кода в `~/.local/state/workspaced/keys.lua`. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr, не печатать частичный код и не трогать копию. Команда `workspaced keys --list` MUST печатать таблицу всех привязок: цепочка, действие и источник (раздел конфига), в порядке следования в файле. Цепочка с выходом MUST выводиться в ней строками путей: сочетание входа с действием `sticky <имя>`, путь до каждого состояния (`SUPER+S r`) с действием `state <состояние>` и путь до каждой клавиши состояния (`SUPER+S r v`) с её действием; у клавиши с `exit` в колонке флагов MUST стоять `exit`, источник — `sticky.<имя>` для корня и `sticky.<имя>.<состояние>…` для вложенных состояний.

#### Scenario: Цепочка из трёх сочетаний
- **WHEN** в конфиге есть `[[binds]]` с `chain = "SUPER+W 3 f"` и `action = { desktop = 3, workspace = "dev-front" }`
- **THEN** после `hyprctl reload` нажатие Super+W, затем 3, затем f поднимает `dev-front` на столе 3, а нажатие Super+W, затем Escape ничего не делает

#### Scenario: Подкарты цепочки с выходом
- **WHEN** в конфиге есть цепочка `[sticky.apps]` из требования «Цепочки с выходом» и выполнена `hyprctl reload`
- **THEN** `hyprctl binds -j` содержит подкарты `ws-sticky:apps`, `ws-sticky:apps/raise` и `ws-sticky:apps/spawn`, в каждой — привязки `BackSpace` и `Escape` и одну привязку с `catch_all: true`; в `ws-sticky:apps/raise` есть привязка `v`; подкарта `ws:SUPER + TAB` привязки `catch_all` не содержит

#### Scenario: Устаревшая подкарта закрывается при перезагрузке
- **WHEN** командой `hyprctl eval 'hl.dispatch(hl.dsp.submap("ws-sticky:apps/raise"))'` открыта подкарта состояния, затем состояние `raise` удалено из конфига и конфиг перечитан
- **THEN** `hyprctl submap` печатает `default`; если бы состояние осталось в конфиге, подкарта осталась бы открытой

#### Scenario: Перезагрузка при ошибке конфига
- **WHEN** конфиг содержит ошибку и выполнена `hyprctl reload`
- **THEN** `workspaced keys --lua` завершается с ошибкой, `keys.lua` не изменяется, конфиг Hyprland загружает привязки из копии, а в журнале Hyprland есть сообщение об ошибке от `workspaced keys`

#### Scenario: Копия после успешной генерации
- **WHEN** конфиг корректен и выполнена `workspaced keys --lua`
- **THEN** содержимое `~/.local/state/workspaced/keys.lua` совпадает с напечатанным кодом

#### Scenario: Список привязок
- **WHEN** выполнена `workspaced keys --list`
- **THEN** в выводе есть строка с `SUPER+Return`, действием `exec wezterm-gui` и источником `binds`, и строка с `SUPER+W d`, действием `raise dots` и источником `workspaces.dots`

### Requirement: Перечень клавиш для подсказки
Команда `workspaced keys --json` MUST печатать перечень всех привязок конфига в JSON вида `{ "groups": [ { "name": <группа>, "keys": [ { "chain", "label", "desc", "action", "source" } ] } ], "sticky": [ { "submap", "path", "keys": [ { "key", "label", "desc", "exit" } ] } ] }`. `chain` и `action` MUST совпадать с цепочкой и действием в выводе `keys --list`, `source` — раздел конфига (`keys.next_workspace`, `apps.herdr`, `workspaces.surf.apps.chrome`, `workspaces.work`, `binds[N]`, `keys.reserved`, `sticky.apps`, `sticky.apps.raise`). `label` MUST быть подписью для человека: модификаторы в порядке Ctrl, Alt, Shift, Super, звенья через пробел, `slash` — «/», `space` — «Пробел», `Return` — «Enter», стрелки — символами, кнопки мыши — «ЛКМ» и «ПКМ», без префикса `XF86`; буква с модификаторами заглавная. Команда MUST читать конфиг сама и MUST NOT требовать работающего демона. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr и MUST NOT печатать частичный перечень.

Группы MUST идти в порядке: Workspace, Столы, Приложения, Цепочки с выходом, Окна, Уведомления, Звук и яркость, Снимки экрана, Раскладка, Сессия и прочее; группа из поля `group`, которой нет в этом списке, MUST идти после них в порядке первого появления; пустая группа MUST NOT выводиться. Строки внутри группы MUST идти в порядке `keys --list`, зарезервированные сочетания — последними в группе «Раскладка». Запись `[[binds]]` с `range` MUST выводиться одной строкой, где `$n` в цепочке, описании и действии заменено подписью «от…до» («Super+1…8»). Каждое сочетание списка `reserved` MUST выводиться в группе «Раскладка» с описанием из `reserved_desc`, а без него — «Зарезервировано».

Без поля `group` группа MUST выводиться из источника и действия: цепочки workspace и служебные цепочки `[keys]`, действия `next-workspace`, `save-session`, `save-workspace`, `sessions`, `arrange` и `{ workspace = … }` — Workspace; `{ move = … }` и `dispatch` с переходом или переносом окна на стол (`workspace = ` без `special:`) — Столы; клавиши приложений и `{ app = … }` — Приложения; строки цепочек с выходом (`sticky.*`) — Цепочки с выходом; `half`, `place`, `maximize`, `detach` и прочие `dispatch` — Окна; `exec` с `ipc call notifications` — Уведомления; `exec` громкости, яркости и `playerctl`, цепочки `XF86Audio*` и `XF86MonBrightness*` — Звук и яркость; `exec` со `screenshot` — Снимки экрана; `dispatch` с `exit()`, прочие `exec` и `lua` — Сессия и прочее. Без поля `desc` описание MUST выводиться из действия: у действий демона — фразой по-русски («Окно в левую половину»), у клавиш приложений — по источнику («Приложение herdr», «chrome в workspace surf»), у цепочек workspace — «Поднять workspace <имя>», у `exec`, `dispatch` и `lua` — действием, как в `keys --list`. У сочетания входа цепочки с выходом описание — `title` корня, у пути до состояния — `title` состояния, у клавиши состояния — `title` её состояния и через « · » описание клавиши (`desc`, а без него — описание унаследованной клавиши приложения или описание действия); у клавиши с `exit` к описанию MUST добавляться « (выход)».

Раздел `sticky` MUST перечислять все состояния всех цепочек с выходом: `submap` — имя подкарты состояния (требование «Генерация привязок для Hyprland»), `path` — подписи (`title`) состояний от корня до этого состояния, `keys` — клавиши состояния в порядке файла, а унаследованные — после явных в порядке цепочек приложений: `key` — имя клавиши, `label` — её подпись по правилам `label`, `desc` — описание клавиши (для перехода — `title` дочернего состояния), `exit` — признак выхода.

#### Scenario: Группы и подписи
- **WHEN** выполнена `workspaced keys --json` с конфигом сессии
- **THEN** первая группа — «Workspace» со строкой `label` «Super+Tab w» и описанием «Поднять workspace work», в группе «Приложения» есть строка «Super+B — chrome в workspace surf», в группе «Окна» — «Alt+Super+← — Окно в левую половину»

#### Scenario: Цепочка с выходом в перечне
- **WHEN** выполнена `workspaced keys --json` с конфигом сессии, где есть `[sticky.apps]` с подписями «Приложения», «Поднять» и «Новое окно»
- **THEN** группа «Цепочки с выходом» идёт после «Приложения» и содержит строки «Super+S — Приложения», «Super+S r — Поднять», «Super+S r v — Поднять · chrome-ai в workspace surf» и «Super+S s e — Новое окно · Приложение neovide (выход)»; раздел `sticky` содержит запись с `submap` `ws-sticky:apps/raise`, `path` `["Приложения", "Поднять"]` и клавишей `e` с `exit: true`

#### Scenario: Серия одной строкой
- **WHEN** в `[[binds]]` есть `chain = "CTRL+SUPER+$n"`, `range = [1, 8]`, `action = { move = "$n" }` без `desc`
- **THEN** в группе «Столы» ровно одна строка этой записи: «Ctrl+Super+1…8 — Перенести workspace на стол 1…8 и перейти туда»

#### Scenario: Зарезервированные сочетания
- **WHEN** в `[keys]` заданы `reserved = ["SUPER+space", "ALT+SUPER+space"]` и `reserved_desc = { "SUPER+space" = "Следующая раскладка" }`
- **THEN** в группе «Раскладка» есть строки «Super+Пробел — Следующая раскладка» и «Alt+Super+Пробел — Зарезервировано»

#### Scenario: Ошибка конфига
- **WHEN** привязка занимает зарезервированное сочетание и выполнена `workspaced keys --json`
- **THEN** команда завершается ненулевым кодом, в stderr названы запись и сочетание, stdout пуст
