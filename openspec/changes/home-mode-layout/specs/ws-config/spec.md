## MODIFIED Requirements

### Requirement: Файл конфига и его разделы
Демон MUST читать конфиг из `~/.config/workspaced/config.toml` (файл под chezmoi). Файл MUST состоять из разделов: `[env]` — общие переменные окружения; `[keys]` — цепочки служебных действий `save_session`, `save_workspace`, `sessions`, `next_workspace` и список `reserved` зарезервированных сочетаний; `[templates.<имя>]` — шаблон геометрии с полем `main` (имя главной ячейки) и таблицей `cells`, где каждая ячейка — прямоугольник `{ x, y, w, h }`, а порядок ячеек MUST сохраняться таким, как в файле (по нему вытесненное приложение режима `home` ищет свободную ячейку); `[apps.<имя>]` — приложение с полями `cmd` (команда запуска), `args` (массив), `cwd`, `env` (таблица), `chain`, `class` и `title` (регулярные выражения для захвата открытого окна по классу и заголовку; `title` без `class` не допускается), `dialog_title` (регулярное выражение по заголовку собственного диалога приложения; без `class` не допускается), `family` (имя приложения-семейства, если это приложение — его вариант) и `rect` (прямоугольник `{ x, y, w, h }` — положение и размер окна по умолчанию, когда workspace об этом приложении ничего не говорит); `[startup]` — `workspace` (имя существующего workspace, который поднимается при старте демона) и `desktop` (стол 1…8, по умолчанию 1); `[workspaces.<имя>]` — workspace с полями `template` (обязательно), `main` (главное приложение по умолчанию — чьё место в раскладке главное, спецификация ws-daemon, «Расстановка окон»; без поля главным считается приложение, записанное в главную ячейку шаблона), `icon`, `chain`, `env`, `mode` и таблицей `apps`, где значение — запись приложения в этом workspace: имя ячейки шаблона строкой, таблица `{ rect = { x, y, w, h } }` для окна вне ячеек либо таблица с полем места `cell` (имя ячейки шаблона) или `rect` (прямоугольник) — ровно одним из двух — и необязательными полями `chain` (клавиша приложения в этом workspace, требование «Цепочки клавиш и привязки») и `mode` (режим клавиши этого приложения в этом workspace); `[[binds]]` — записи с полем `chain`, ровно одним из полей действия `action`, `exec`, `dispatch`, `lua` и необязательными `range`, `locked`, `repeating`, `mouse`, `release`. В корне файла MUST быть допустим необязательный список `ignore_classes` — регулярные выражения, которые сопоставляются с классом окна целиком; окно с подходящим классом демон MUST NOT принимать в workspace ни при каких условиях (спецификация ws-daemon, «Посторонние окна» и «Захват открытых окон приложения»). По умолчанию список пуст. Оба поля, `dialog_title` и `ignore_classes`, нужны потому, что признака диалога композитор не сообщает; выражения с ошибкой MUST приводить к отказу с указанием приложения или списка. Поле `mode` MUST задавать поведение клавиши приложения в этом workspace (спецификация ws-daemon, «Цепочка приложения») и принимать значения `swap` — обмен мест с главным приложением, `stack` — подъём окна без переноса — и `home` — раскладка по домам: вызванное приложение в главной ячейке шаблона, остальные на своих местах из раздела, вытесненные из главной ячейки — в свободных ячейках; по умолчанию MUST действовать `swap`, а иное значение MUST приводить к отказу с указанием workspace, полученного значения и допустимых. Поле `mode` записи приложения в таблице `apps` workspace MUST принимать те же значения и задавать режим клавиши этого приложения в этом workspace; иное значение MUST приводить к отказу с указанием workspace, приложения, полученного значения и допустимых. Без поля `mode` режим приложения в workspace MUST быть режимом workspace, в том числе у приложения, место которого задано `rect` (записью файла или записью дополнительного приложения сессии). Режимы `swap` и `stack` MUST задавать только поведение клавиши: раскладка workspace в памяти, её снятие с экрана и память о геометрии окон в них одинаковы (спецификация ws-daemon, «Расстановка окон»); режим `home` дополнительно задаёт раскладку по домам, принадлежность изменённого прямоугольника домашнему месту и запись домашних мест командой записи workspace (там же). Запись-таблица без `cell` и `rect` или с обоими полями сразу MUST отклоняться с указанием workspace и приложения. Порядок записей в таблице `apps` workspace MUST сохраняться таким, как в файле: по нему конец цикла клавиши выбирает следующее приложение workspace, а приложения, добавленные сессией, MUST идти после описанных в файле. У приложения MUST быть задано хотя бы одно из полей `cmd` и `class`: без `cmd` приложение не открывает новых окон и только собирает подходящие по `class`, без `class` окно узнаётся лишь по запуску. Поле `family` MUST называть другое приложение того же файла, у которого самого нет `family`: уровней ровно два — семейство и его варианты. Имя приложения MUST NOT содержать двоеточие и знак `#`: этими знаками демон отделяет части тега экземпляра. Прямоугольники ячеек, `rect` приложения и `rect` в таблице `apps` workspace — это положение и размер окна на экране как есть: демон MUST передавать их композитору без прибавления или вычитания отступов. Координаты прямоугольников MUST отсчитываться от левого верхнего угла экрана: целое число — пиксели, строка с процентом — доля ширины или высоты монитора; смешивать формы в одном прямоугольнике MUST быть можно. Координаты MUST допускать отрицательные значения, а размеры — значения больше экрана: окно может выходить за его края частично с любой стороны, демон MUST передавать такие значения композитору без обрезания и без сдвига внутрь экрана. Необязательный ключ `gap` в корне файла задаёт зазор в пикселях только для команд `half`, `place` и `maximize`, которые строят геометрию от рабочей области; по умолчанию 0. Неизвестные ключи MUST приводить к предупреждению в журнале, но не к отказу.

#### Scenario: Минимальный конфиг
- **WHEN** файл содержит один шаблон `halves` с ячейками `left` и `right`, одно приложение `terminal` с `cmd = "wezterm-gui"` и один workspace `work` с `template = "halves"`, `main = "terminal"` и `apps = { terminal = "right" }`
- **THEN** `workspaced check` завершается успешно и выводит один workspace, одно приложение и один шаблон

#### Scenario: Заголовок диалога у приложения
- **WHEN** у приложения `chrome` заданы `class = "(?i)^google-chrome$"` и `dialog_title = "^(Диспетчер задач|Task Manager)$"`
- **THEN** `workspaced check` завершается успешно, окно Chrome с заголовком «Диспетчер задач» остаётся свободным, а обычное окно Chrome принимается в workspace; конфиг с `dialog_title` без `class` или с ошибкой в выражении отклоняется с указанием приложения и поля

#### Scenario: Список исключённых классов
- **WHEN** в корне файла задано `ignore_classes = ["termfilechooser", "pinentry.*"]`
- **THEN** `workspaced check` завершается успешно, окна классов `termfilechooser` и `pinentry-gtk` не принимаются ни в один workspace, а окно класса `termfilechooser-2` под выражение не подходит: класс сопоставляется целиком; конфиг с ошибкой в выражении отклоняется с указанием `ignore_classes`

#### Scenario: Режим workspace
- **WHEN** у workspace `surf` задано `mode = "stack"`, а у `work` поля `mode` нет
- **THEN** `workspaced check` завершается успешно, `surf` работает подъёмом окон, `work` — обменом мест; конфиг с `mode = "stak"` отклоняется с указанием workspace, значения `stak` и допустимых `swap`, `stack` и `home`

#### Scenario: Порядок приложений в разделе workspace
- **WHEN** в разделе `surf` приложения записаны в порядке `chrome`, `yandex-browser`, `chrome-ai`
- **THEN** демон держит их в этом порядке, и конец цикла клавиши переходит от `chrome` к `yandex-browser`, а не к `chrome-ai` по алфавиту

#### Scenario: Цепочки сохранения сессии и записи в конфиг
- **WHEN** в `[keys]` заданы `save_session = "CTRL+SUPER+s CTRL+SUPER+s"` и `save_workspace = "CTRL+SUPER+s CTRL+SUPER+w"`
- **THEN** `workspaced check` завершается успешно, а `workspaced keys --list` показывает для первой цепочки команду `save-session`, для второй — `save-workspace`

#### Scenario: Класс, заголовок и стартовый workspace
- **WHEN** у приложения `herdr` заданы `class = "^wezterm-herdr$"` и `title = "^herdr · "`, а в `[startup]` — `workspace = "work"`
- **THEN** `workspaced check` завершается успешно; конфиг с `title` без `class`, с некорректным регулярным выражением или с `startup.workspace`, которого нет среди workspace, отклоняется с указанием поля

#### Scenario: Семейство и его вариант
- **WHEN** в файле есть `[apps.wezterm]` с `cmd = "wezterm-gui"` и `class = "^org\\.wezfurlong\\.wezterm$"`, а `[apps.herdr]` содержит `family = "wezterm"`, свою команду запуска и `class = "^wezterm-herdr$"`
- **THEN** `workspaced check` завершается успешно и показывает `herdr` как вариант семейства `wezterm`; конфиг, где `family` называет приложение, которого нет, где вариант указан вариантом другого варианта или где приложение названо своим же семейством, отклоняется с указанием приложения и поля

#### Scenario: Приложение без команды запуска
- **WHEN** у приложения `wezterm` задан только `class`, без `cmd`
- **THEN** `workspaced check` завершается успешно: приложение собирает окна, но само их не открывает; конфиг с приложением без `cmd` и без `class` отклоняется с указанием приложения

#### Scenario: Положение окна по умолчанию у приложения
- **WHEN** у приложения `neovide` задано `rect = { x = 1125, y = 10, w = 1920, h = 2140 }`, и ни один workspace его не описывает
- **THEN** `workspaced check` завершается успешно, а окно `neovide`, открытое по его цепочке, встаёт в этот прямоугольник

#### Scenario: Проценты и пиксели в одной ячейке
- **WHEN** ячейка задана как `{ x = 330, y = 0, w = "50%", h = "100%" }` на мониторе 3840×2160
- **THEN** демон считает прямоугольник 330,0 размером 1920×2160

#### Scenario: Окно шире экрана со сдвигом за левый край
- **WHEN** ячейка задана как `{ x = -400, y = -150, w = 5000, h = 2600 }` и в неё поставлено окно при `gap = 5`
- **THEN** `hyprctl clients -j` показывает у окна положение −400,−150 и размер 5000×2600

#### Scenario: Ссылка на несуществующую ячейку
- **WHEN** workspace ссылается на ячейку `top`, которой нет в его шаблоне
- **THEN** `workspaced check` завершается с ошибкой, называющей workspace, приложение и ячейку; демон продолжает работать с прежним конфигом

#### Scenario: Запись привязки с двумя действиями
- **WHEN** запись `[[binds]]` содержит и `exec`, и `dispatch`
- **THEN** `workspaced check` завершается с ошибкой, называющей цепочку записи и оба поля

#### Scenario: Переопределение клавиши и режима в workspace
- **WHEN** у приложения `chrome-ai` задано `chain = "SUPER+SHIFT+V"`, в разделе `surf` записано `chrome-ai = { cell = "right", chain = "SUPER+V" }`, а в разделе `work` — `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 }, mode = "swap" }`
- **THEN** `workspaced check` завершается успешно; ключ `chrome-ai` в `surf` — Super+V, место — ячейка `right`; `calc` в `work` выбирается обменом мест, хотя ячейки у него нет

#### Scenario: Запись приложения без места
- **WHEN** в разделе `surf` записано `chrome-ai = { chain = "SUPER+V" }` либо `chrome-ai = { cell = "right", rect = { x = 0, y = 0, w = 10, h = 10 } }`
- **THEN** `workspaced check` завершается с ошибкой, называющей `surf` и `chrome-ai`

#### Scenario: Недопустимый режим приложения в workspace
- **WHEN** в разделе `work` записано `chromium = { cell = "left", mode = "stak" }`
- **THEN** `workspaced check` завершается с ошибкой, называющей `work`, `chromium`, значение `stak` и допустимые `swap`, `stack` и `home`

#### Scenario: Приложение без ячейки берёт режим workspace
- **WHEN** в разделе `work` (без поля `mode`) записано `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 } }`
- **THEN** `workspaced check` завершается успешно, и клавиша `calc` в `work` меняет калькулятор местами с главным приложением, как у приложений с ячейкой; запись `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 }, mode = "stack" }` оставляет главное приложение на месте и только поднимает окно калькулятора

#### Scenario: Режим home и шаблон с разделённой колонкой
- **WHEN** в файле шаблон `thirds-split` с ячейками в порядке `left_top = { x = -805, y = 10, w = 1920, h = 1065 }`, `left_bottom = { x = -805, y = 1085, w = 1920, h = 1065 }`, `center` (главная) и `right`, а у `work` заданы `template = "thirds-split"`, `mode = "home"` и записи `herdr = "center"`, `chromium = "left_top"`, `chrome = "left_bottom"`, `neovide = "right"`
- **THEN** `workspaced check` завершается успешно; клавиша приложения в `work` ставит его в `center`, остальные — по домам, а ячейки шаблона для вытесненного перебираются в порядке `left_top`, `left_bottom`, `center`, `right`
