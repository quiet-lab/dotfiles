## MODIFIED Requirements

### Requirement: Цепочка приложения
По клавише приложения — команде `workspaced key <цепочка>`, которую вызывает привязка (спецификация ws-config, «Цепочки клавиш и привязки»), — демон MUST выбрать приложение и workspace и вести цикл по экземплярам этого приложения. Приложение MUST считаться описанным в workspace, если в разделе workspace эффективного конфига есть запись самого приложения или его семейства. Ключ приложения в workspace и отклик workspace на цепочку MUST определяться по спецификации ws-config: ключ — `chain` записи приложения в этом workspace, а без него — собственная клавиша приложения; workspace откликается на цепочку, если в нём есть запись приложения с таким ключом. Запущенным MUST считаться workspace, который числится в списке какого-либо стола, в том числе ожидающий ленивого поднятия; запущенный workspace MUST искаться сначала в списке текущего стола по порядку, затем в списках столов по возрастанию номера. Workspace, не числящийся ни в одном списке столов, клавиша приложения MUST NOT поднимать.

Пусть нажата цепочка `K`, на текущем столе активен workspace `W` (или активного нет), `Own(K)` — приложения с собственной клавишей `K`, по именам, а кандидаты `K` — приложения из `Own(K)` и приложения, которым `K` назначена ключом записи в каком-либо workspace конфига, в том числе разные приложения в разных workspace. Кандидат MUST считаться входящим в `W`, если он описан в `W` (в том числе через семейство или записью дополнительного приложения сессии) либо его окно входит в `W` по тегу состава (требование «Состав workspace»); окно варианта при этом считается и окном его семейства. Путь MUST выбираться по порядку: (1) клавиша ведёт к окну там, где оно сейчас есть: `W` откликается на `K` — цикл отозвавшегося приложения в `W`; иначе в `W` входит кандидат `K` — цикл этого кандидата в `W`, а из нескольких таких — того, чья запись стоит в разделе `W` раньше, причём кандидаты, входящие в `W` только окнами, идут после описанных, по порядку: сначала `Own(K)`, затем остальные, внутри по именам; (2) в `W` не входит ни один кандидат, а запущенный workspace `V` откликается на `K` либо описывает приложение из `Own(K)` через его семейство, не имея записи самого приложения (у такого приложения в `V` переопределения нет), — `V` MUST быть поднят, а если он в списке другого стола, демон MUST перейти на стол с наименьшим номером, в списке которого он есть, и поднять его там; цикл идёт по отозвавшемуся или описанному приложению в `V`; (3) приложение `X` из `Own(K)` описано в запущенных workspace, и каждый из них переопределил его клавишу — при активном `W` окна `X` MUST быть перетащены в `W`, и цикл идёт в `W`; без активного `W` MUST быть поднят первый такой workspace по правилу шага (2), и цикл идёт в нём; (4) иначе берётся первое приложение из `Own(K)`, а если собственной клавиши `K` нет ни у одного приложения, — первое по имени приложение, которому `K` назначена ключом в каком-либо workspace: при активном `W` оно MUST быть открыто в `W`, без него цикл MUST идти по окнам приложения вне workspace. Если на `K` не отзывается ни одно приложение, демон MUST записать это в журнал и не делать ничего.

Если в workspace на цепочку `K` откликаются несколько записей (ключ `K` у каждой — `chain` записи или собственная клавиша приложения), они образуют группу общей клавиши, и путь, ведущий к циклу в этом workspace (шаг (1) или поднятие на шаге (2)), MUST вести один общий цикл по окнам всех приложений группы. Ряд цикла MUST составляться из окон приложений группы по порядку записей в разделе workspace, а внутри приложения — по порядку экземпляров; шаг цикла, prev и конец цикла MUST определяться по этому ряду так же, как по экземплярам одного приложения: окна приложений группы prev не бывают, а следующим приложением при конце цикла без prev MUST считаться первое приложение после последней записи группы, не входящее в неё. Приложение группы без окон в workspace цикл MUST пропускать и MUST NOT запускать; если окон нет ни у одного приложения группы, MUST быть запущено первое по порядку записей. Цикл MUST идти в режиме клавиши записей группы (у записей с общей цепочкой он один, спецификация ws-config, «Цепочки клавиш и привязки»). В режимах обмена мест и `home` главное место, занятое любым приложением группы, MUST считаться занятым группой: нажатие продолжает цикл, а не начинает его заново, а выбор окна другого приложения группы MUST ставить на главное место его приложение. Собственная клавиша приложения группы, отличная от общей цепочки, MUST вести цикл только по окнам этого приложения, а перетаскивание и открытие приложения в `W` (шаги (3) и (4)) MUST действовать на одно приложение, как раньше. Новый экземпляр по общей цепочке (`workspaced key --new`) MUST запускаться у приложения активного окна, если оно входит в группу, иначе у первого приложения группы. Поднятие workspace MUST по-прежнему запускать каждое приложение раздела, у которого нет окон.

Команда `workspaced app <app> [--pull]` и действие `{ app = … }` записи `[[binds]]` MUST действовать как собственная клавиша приложения: по тем же шагам, где `Own(K)` — это приложение, а workspace откликается, если описывает приложение и не переопределяет его клавишу. Признак перетаскивания (`--pull`, ключ `pull` у действия записи `[[binds]]`) при активном `W` MUST перетаскивать окна приложения в `W` сразу после шага (1). Несколько имён в команде MUST считаться кандидатами: действует тот, для которого путь найдётся на более раннем шаге, а при равенстве — первый по порядку.

Если workspace поднят этой же клавишей или приложение открыто либо перетащено в него этой клавишей, цикл MUST начинаться заново — с первого экземпляра: поднятие уже отдало фокус первому экземпляру главного приложения. Открытие приложения в `W` MUST идти по правилам захвата при поднятии (требование «Захват открытых окон приложения»): свободные окна приложения MUST быть захвачены, а если их нет — окна приложения из других workspace MUST быть отданы ему в общее пользование; без окон приложение MUST быть запущено; окна MUST войти в `W` с записью о месте (требование «Посторонние окна»). Открытое или перетащенное приложение MUST выбираться без обмена мест в любом режиме: первый экземпляр получает фокус и поднимается наверх на своём месте, места остальных приложений MUST NOT меняться.

Перетаскивание MUST добавлять в активный workspace текущего стола все нескрытые окна приложения — по семейству окна семейства, по варианту окна варианта — из любых workspace и свободные; из прежних workspace окна MUST NOT уходить (требование «Состав workspace»). Workspace MUST получить запись о месте приложения: для приложения файла конфига — запись только о месте, для дополнительного приложения сессии другого workspace — полную запись с классом, командной строкой и каталогом (требование «Дополнительные приложения сессии» спецификации ws-sessions). Окна MUST встать на текущий стол на место приложения по правилу мест требования «Расстановка окон», а без места — в центр рабочей области с нынешним размером окна. Если окон у приложения нет, перетаскивание MUST действовать как открытие приложения. Если приложение в активном workspace уже описано, признак перетаскивания MUST NOT менять действия: цикл идёт в `W`.

Шаг цикла MUST определяться активным окном и порядком экземпляров (требование «Идентификация окон»), а не счётчиком нажатий: если активное окно — экземпляр приложения и за ним есть следующий, MUST быть выбран следующий; если активное окно — последний экземпляр, цикл MUST быть закончен; во всех остальных случаях MUST быть выбран первый экземпляр. Выбор экземпляра мышью MUST NOT менять учёта: демон MUST NOT помнить, какие экземпляры уже показаны. Исключение — режимы обмена мест и `home`: если вызванное приложение не главное (требование «Расстановка окон»), нажатие MUST начинать цикл заново, даже когда активно окно этого приложения: выбранным MUST стать активное окно, если оно экземпляр вызванного приложения, иначе первый экземпляр, а prev — первое окно главного приложения. Так окно, которое пользователь только что двигал мышью и которое поэтому активно, клавиша ставит на главное место, а не возвращает фокус prev. Нажатия, которое открыло или перетащило приложение, исключение не касается. В цикл MUST входить окна приложения, входящие в этот workspace (требование «Состав workspace»), кроме окон на `special:hidden`; окна варианта, у которого в workspace есть собственная запись, в цикл его семейства MUST NOT входить. Если окон нет, приложение MUST быть запущено с окружением workspace, а приложение без `cmd` MUST остаться без окна с записью в журнал; пока у приложения есть хотя бы одно окно в этом workspace, клавиша MUST NOT запускать ещё один экземпляр.

Что значит «выбрать экземпляр», MUST задавать режим вызванного приложения в workspace (спецификация ws-config, «Файл конфига и его разделы»): поле `mode` его записи, а без него — режим workspace, в том числе у приложения, место которого задано прямоугольником, а не ячейкой; приложение, описанное в workspace только через семейство, берёт режим записи семейства. Весь цикл — выбор экземпляра, запоминание prev, конец цикла и запуск без окон — MUST идти в режиме вызванного приложения. В режиме обмена мест (`swap`) демон MUST перед выбором снять раскладку workspace с экрана (требование «Расстановка окон»); если приложение выбранного окна не главное, оно и главное приложение MUST обменяться местами в раскладке — каждое место целиком, с изменённым прямоугольником, если он есть, — и вызванное приложение MUST стать главным; окна вызванного приложения MUST встать в прямоугольник главного места, а окна прежнего главного — в прямоугольник прежнего места вызванного, стопка на стопку: окно, сдвинутое или растянутое пользователем, отдаёт свой прямоугольник прежнему главному приложению. Затем выбранное окно MUST получить фокус и подняться наверх; запуск без окон MUST сначала перевести приложение на главное место. Обмен MUST NOT менять положение остальных окон. В режиме `stack`: выбранное окно MUST получить фокус и подняться наверх, а положение и размер окон демон MUST NOT менять.

В режиме раскладки по домам (`home`) демон MUST перед выбором снять раскладку workspace с экрана, как в режиме обмена мест, и расставить приложения workspace заново по правилу: (1) вызванное приложение `A` MUST встать в главную ячейку шаблона и стать главным, все его окна — стопкой там же; (2) каждое другое приложение с записью в разделе workspace MUST встать на своё домашнее место — место из его записи в разделе эффективного конфига (ячейку или `rect`; у дополнительного приложения сессии — прямоугольник записи), если это место не главная ячейка; приложение, стоявшее не на своём месте, уступает его хозяину; (3) приложение, чей дом — главная ячейка, вытеснено и MUST взять свободную ячейку: сначала дом `A`, если `A` его освободило и он не дом другого приложения, затем остальные свободные ячейки шаблона в порядке их записи в шаблоне; свободной MUST считаться ячейка, которая не главная, не дом приложения, стоящего дома, и не занята другим вытесненным приложением; без свободной ячейки вытесненное приложение MUST встать стопкой в дом `A`; (4) вытесненные приложения MUST разбираться в порядке записей раздела workspace, а приложение с несколькими окнами занимает место стопкой. Окна приложений, чьё место изменилось, MUST встать в прямоугольники новых мест; окна приложений, чьё место не изменилось, демон MUST NOT двигать. Прямоугольник места в режиме `home` MUST определяться по требованию «Расстановка окон»: изменённый прямоугольник действует только на домашнем месте приложения. Затем выбранное окно MUST получить фокус и подняться наверх; запуск без окон MUST сначала поставить приложение в главную ячейку по тому же правилу.

Конец цикла MUST возвращать пользователя к прежнему окну (prev), выбирая его тем же действием. В режиме обмена мест prev — первое окно приложения, бывшего главным в начале цикла, поэтому конец цикла MUST давать обратный обмен мест и фокус прежнему главному окну. В режиме `home` prev — тоже первое окно приложения, бывшего главным в начале цикла: конец цикла MUST ставить это приложение в главную ячейку по правилу режима `home`, а остальные — по домам, и отдавать фокус его окну. В режиме `stack` prev — активное окно workspace в начале цикла, не принадлежащее вызванному приложению, а если активным было чужое окно — последнее окно этого workspace, получавшее фокус. Если prev нет или его окно закрыто либо скрыто, конец цикла MUST выбрать первый экземпляр следующего приложения workspace: следующим MUST считаться первое приложение после вызванного по порядку записи в разделе workspace (циклически), у которого есть нескрытое окно в этом workspace; приложения без окон MUST быть пропущены, и запускать их конец цикла MUST NOT. Если такого приложения нет, конец цикла MUST снова выбрать первый экземпляр вызванного приложения. У приложения вне workspace prev нет: за последним его экземпляром MUST идти первый.

#### Scenario: Обмен с главной ячейкой
- **WHEN** в `dev-front` (шаблон `cross`, режим обмена) редактор в ячейке `center`, терминал в `left`, и нажата цепочка терминала
- **THEN** терминал занимает `center`, редактор занимает `left`, браузер в `right` не сдвигается, фокус у терминала

#### Scenario: Приложение уже главное
- **WHEN** редактор с единственным окном стоит в главной ячейке с фокусом, цикл по нему не начинался, и нажата его цепочка
- **THEN** цикл заканчивается: выбирается первый экземпляр следующего приложения workspace по порядку записи в его разделе, у которого есть окно, и в режиме обмена мест оно занимает главное место

#### Scenario: Обмен ячеек у приложения с двумя окнами
- **WHEN** в `work` (шаблон `thirds`, режим обмена мест) herdr в главной ячейке `center`, у `chromium` в ячейке `left` два окна, и нажата цепочка `chromium`
- **THEN** оба окна `chromium` встают в ячейку `center` одно поверх другого, окно herdr уходит в ячейку `left`, фокус и верхнее место получает первый экземпляр `chromium`

#### Scenario: Повторное нажатие при двух окнах
- **WHEN** оба окна `chromium` стоят в главной ячейке, фокус у первого экземпляра, и его цепочка нажата ещё раз
- **THEN** ячейки не меняются, фокус и верхнее место получает второй экземпляр `chromium`

#### Scenario: Конец цикла возвращает расстановку
- **WHEN** оба окна `chromium` стоят в главной ячейке, фокус у второго экземпляра, и цепочка `chromium` нажата ещё раз
- **THEN** окна `chromium` возвращаются в ячейку `left`, окно herdr — в ячейку `center`, фокус у herdr

#### Scenario: Единственный экземпляр — переключатель
- **WHEN** у `neovide` одно окно в ячейке `right`, фокус у herdr, и цепочка `neovide` нажата дважды
- **THEN** первое нажатие выбирает окно `neovide`, второе возвращает фокус окну herdr, и расстановка та же, что была до нажатий

#### Scenario: Режим stack поднимает окно, не двигая его
- **WHEN** у workspace `surf` задано `mode = "stack"`, окна трёх браузеров стоят по ячейкам `overlay`, фокус у Яндекс.Браузера, и нажата цепочка `chrome`
- **THEN** окно `chrome` поднимается наверх и получает фокус, ячейки и положения всех окон не меняются

#### Scenario: Конец цикла в режиме stack
- **WHEN** в `surf` у `chrome` два окна, цепочка `chrome` нажата трижды подряд от окна Яндекс.Браузера
- **THEN** первое нажатие поднимает первый экземпляр `chrome`, второе — второй, третье возвращает наверх окно Яндекс.Браузера с фокусом; положения окон не меняются

#### Scenario: Клик мышью по экземпляру
- **WHEN** у `chromium` три окна, `chromium` — главное приложение `work` (или приложение workspace режима `stack`), пользователь кликнул по второму экземпляру и нажал цепочку `chromium`
- **THEN** выбирается третий экземпляр, следующее нажатие заканчивает цикл и возвращает к prev, а первый экземпляр повторно не показывается

#### Scenario: Клик мышью по окну неглавного приложения
- **WHEN** в `work` (режим обмена мест) у `neovide` одно окно в ячейке `right`, главное приложение — herdr, пользователь кликнул по окну `neovide` и нажал Super+E
- **THEN** `neovide` встаёт на главное место с фокусом, herdr — в ячейку `right`; следующее нажатие Super+E возвращает обоих обратным обменом и отдаёт фокус herdr

#### Scenario: Окно prev закрыто
- **WHEN** цикл `chromium` в `work` начат от окна herdr, пользователь закрыл окно herdr, и цикл дошёл до конца
- **THEN** выбирается первый экземпляр следующего приложения `work` по порядку записи в его разделе, у которого есть окно; если такого нет, снова выбирается первый экземпляр `chromium`

#### Scenario: Закрытое окно приложения
- **WHEN** окно терминала `dev-front` закрыто пользователем и нажата цепочка терминала
- **THEN** терминал запускается заново с окружением `dev-front`, после появления окна занимает главную ячейку, редактор уходит в ячейку терминала

#### Scenario: Приложение в другом workspace того же стола
- **WHEN** на столе 1 активен `chat`, в списке стола 1 есть `dev-front` с `editor-front`, у которого два окна, и нажата цепочка `editor-front`
- **THEN** на столе 1 поднимается `dev-front`, фокус у первого экземпляра редактора, `chat` припаркован; второй экземпляр выбирается следующим нажатием

#### Scenario: Приложение на другом столе

### Requirement: Расстановка окон
Место окна приложения MUST определяться по первому подходящему правилу: место этого приложения в раскладке workspace, в котором окно ставится (для общего окна — в том workspace, на стол которого оно пришло); место его семейства в той же раскладке; `rect` самого приложения; центр рабочей области. Центр рабочей области — центр монитора за вычетом зон, зарезервированных слоями (поле `reserved` у `hyprctl monitors -j`; панель Quickshell резервирует 330 px слева): окно ставится с нынешним размером так, что его центр совпадает с центром этой области. Так же центрирует окна сам композитор (новое плавающее окно, правило `center`, диспетчер центрирования), поэтому окно без места стоит там же, где его поставил бы композитор; на мониторе 3840×2160 с панелью окно 1920×1080 встаёт в 1125,540, как ячейка `center` шаблонов по ширине. Рабочая область MUST читаться у композитора в момент расстановки, а если прочитать её не удалось, центром MUST считаться центр монитора. Демон MUST задавать плавающему окну положение и размер этого места ровно так, как они записаны: демон MUST NOT прибавлять или вычитать зазор `gap` или иные отступы ни к координатам, ни к размерам. Если у приложения несколько окон, MUST быть расставлены все: они получают одно и то же место и стоят стопкой одно поверх другого. Порядок окон по глубине демон MUST NOT менять, кроме окна, которому передаётся фокус: оно MUST подниматься наверх. Ручные перемещения и изменения размера демон MUST NOT отменять: они становятся раскладкой workspace. Закрытие окна MUST NOT менять места остальных окон. Перекрытие окон ячейками с пересекающимися прямоугольниками MUST быть допустимо.

Раскладка workspace в памяти демона MUST назначать каждому приложению, описанному в разделе workspace эффективного конфига (файл конфига вместе с дополнительными приложениями сессии), место: исходное — ячейку шаблона или `rect` записи — и, если окно приложения сдвигали или меняли его размер, изменённый прямоугольник. Прямоугольником места MUST считаться изменённый, а без него — исходный. При первом обращении раскладка MUST собираться из описания: исходные места — записи раздела, изменённых прямоугольников нет. Главным приложением workspace MUST считаться приложение, названное полем `main` его раздела, а без него — приложение, записанное в главную ячейку шаблона; главное место — место главного приложения в раскладке. Где требования говорят о главной ячейке и о приложении главной ячейки, имеются в виду главное место и главное приложение. Обмен мест (требование «Цепочка приложения») MUST передавать места целиком — исходное вместе с изменённым прямоугольником — и делать главным вызванное приложение.

В режиме `home` назначение мест MUST быть раскладкой по домам (требование «Цепочка приложения»): после клавиши приложения режима `home` — с вызванным приложением в главной ячейке шаблона, а при первом обращении к раскладке workspace, у которого поле `mode` раздела — `home`, — с главным приложением по конфигу (поле `main` раздела, без него — приложение, чей дом — главная ячейка) в главной ячейке и остальными по домам. Домашнее место приложения — его место в разделе эффективного конфига. Изменённый прямоугольник приложения режима `home` MUST принадлежать его домашнему месту: прямоугольником места MUST считаться изменённый, только пока приложение стоит дома, а в главной ячейке и в чужой свободной ячейке — прямоугольник этой ячейки; уход из дома изменённый прямоугольник MUST NOT снимать. Команда записи workspace (спецификация ws-config, «Запись по команде сохранения») MUST писать у приложения режима `home` его домашнее место — именем ячейки или `rect`, с изменённым прямоугольником, если он есть, — а не нынешнее место, и полем `main` — главное приложение. Раскладку демон MUST NOT записывать в файл конфига без команды записи workspace (спецификация ws-config, «Запись по команде сохранения»); в снимок сессии она попадает по команде сохранения сессии (спецификация ws-sessions, «Файлы сессий»).

Событий о перемещении и изменении размера окна композитор не сообщает, поэтому раскладку MUST снимать с экрана сам демон в тот момент, когда собирается по ней действовать, из того же списка окон композитора, который он читает для действия; опроса и таймеров для этого MUST NOT быть. Снятие раскладки workspace `W` MUST выполняться только на столе, где `W` активен: для каждой записи приложения `W`, у которой на этом столе есть окно `W`, не скрытое и не находящееся в полноэкранном режиме композитора (fullscreen или maximized), изменённым прямоугольником места MUST стать прямоугольник первого такого окна в порядке экземпляров, а если он совпадает с исходным, изменённого прямоугольника MUST NOT оставаться; у записи режима `home`, стоящей не на домашнем месте, изменённый прямоугольник при снятии MUST NOT меняться; места записей без таких окон MUST NOT меняться. Там же для каждого такого окна MUST запоминаться его прямоугольник для `W`. Раскладка MUST сниматься: перед циклом клавиши приложения в `W`; перед поднятием workspace — у workspace, активного на целевом столе (вытесняемого или того же), и у workspace, переносимого с другого стола; перед уходом окна `W` со стола `W` — к другому своему workspace, за пользователем, на `special:pool`, в другой workspace перетаскиванием или командой отделения; перед удалением `W` из списка стола; перед командами сохранения сессии и записи workspace.

Демон MUST помнить для каждого окна и каждого его workspace прямоугольник, в котором окно оставлено на столе этого workspace, одинаково во всех режимах: прямоугольник MUST запоминаться при снятии раскладки и при каждой постановке окна на место в этом workspace. Окно, приходящее на стол workspace — при поднятии, при следовании за пользователем, при уходе к другому своему workspace, — MUST вставать в запомненный прямоугольник, а без него — на место своего приложения в раскладке. Окно, которое уже стоит на столе workspace как его окно, поднятие MUST NOT двигать ни в одном режиме. У общего окна запомненные прямоугольники и места в раскладках разных workspace MUST быть независимы: раскладка `W` снимается только на столе `W`. Перенос workspace на другой стол (требование «Перенос workspace на стол») расстановкой MUST NOT считаться: окна, переносимые вместе с workspace, MUST встать на новом столе в те прямоугольники, в которых стояли на прежнем. Место из раскладки демон MUST задавать окну при появлении окна запущенного демоном приложения, при захвате появившегося или открытого окна, при приходе окна на стол workspace без запомненного прямоугольника, при обмене мест, при загрузке сессии и восстановлении из снимка и при применении раскладки, собранной заново после правки конфига (спецификация ws-config, «Слежение за конфигом»). Режимы `swap` и `stack` (поле `mode` workspace и записи приложения) на раскладку, её снятие и память окон MUST NOT влиять: они задают только поведение клавиши приложения; режим `home` влияет на них только так, как сказано выше. Раскладка и память окон MUST жить до остановки демона; в снимок сессии они попадают только по команде сохранения сессии.

Когда в `W` не остаётся ни одного окна приложения — окно закрыто, отделено командой отделения окна или снято сверкой состава, — изменённый прямоугольник места этого приложения в `W` MUST быть снят: следующее окно приложения встанет на исходное место. Если окна приложения в `W` остаются, место MUST сохраняться. Изменённый прямоугольник MUST сниматься и тогда, когда обмен мест передаёт место приложению, у которого в `W` нет окон. Команда расстановки (требование «Возврат раскладки к конфигу по команде») MUST снимать изменённые прямоугольники всех мест `W`.

### Requirement: Возврат раскладки к конфигу по команде
По записи `[[binds]]` с `action = "arrange"` или команде `workspaced arrange` демон MUST расставить окна текущего стола по описанию workspace, активного на этом столе. Окно приложения, описанного в эффективном конфиге (файл конфига вместе с дополнительными приложениями сессии), MUST встать на место своего приложения по правилу мест требования «Расстановка окон»: ячейка или `rect`, записанные для приложения в этом workspace; то же, записанное там для его семейства; `rect` самого приложения. Если активного workspace на столе нет, MUST действовать оставшаяся часть правила: `rect` приложения, а без него — положение по умолчанию. Окно, для которого места не нашлось, и окно, которому не подходит ни одно приложение конфига, MUST вставать в положение по умолчанию — центр рабочей области с нынешним размером окна; окна одного класса MUST при этом вставать стопкой на место первого из них по порядку появления. Окна всех экземпляров приложения MUST, как и при всякой расстановке, вставать стопкой на одно место.

Команда MUST возвращать раскладку активного workspace к эффективному конфигу целиком — так же, как её собирает перечитывание конфига после правки раздела этого workspace (требование «Слежение за конфигом» спецификации ws-config): назначение мест MUST быть собрано заново из раздела workspace в файле конфига и записей дополнительных приложений сессии, у которых место — прямоугольник записи; главным приложением MUST стать приложение из поля `main` раздела, а без него — приложение главной ячейки шаблона. В workspace режима `home` назначение мест MUST собираться раскладкой по домам (требование «Расстановка окон»): главное приложение — в главной ячейке шаблона, остальные — по домам, вытесненные — в свободные ячейки. Обмены мест, сделанные клавишами приложений, MUST быть отменены, изменённые прямоугольники всех мест MUST быть сняты, а запомненные прямоугольники окон этого workspace MUST быть заменены местами, на которые команда их поставила, у окон этого стола и забыты у окон, стоящих на других столах и на `special:pool`. Помимо раскладки по домам в режиме `home`, режим workspace на действие MUST NOT влиять. Фокус MUST остаться у активного окна, а само окно MUST подняться наверх своей стопки; порядок остальных окон по глубине демон MUST NOT менять. Окно-переключатель команда MUST NOT трогать. Столом расстановки MUST быть тот, на котором композитор находится в момент команды, — он MUST спрашиваться у композитора по тому же правилу, что и у переноса workspace. Окна других столов, окна на `special:pool` и `special:hidden` команда MUST NOT трогать, состав workspace MUST NOT менять: свободное окно остаётся свободным.
