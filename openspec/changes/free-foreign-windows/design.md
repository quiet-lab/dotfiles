# Design: Окна, открытые во время работы, не входят в workspace до сохранения

## Context

Посторонние окна демон хранит в `state.foreign` (адрес → `Foreign { workspace, rect, cmd, cwd }`). Поле `workspace` заполняется в трёх местах: при событии `openwindow` (`on_open`), при сопоставлении живых окон со снимком на старте (`adopt_live_foreign`, окно не из снимка) и при запуске приложения вне workspace (`adopt`, цель `Center`). Поднятие (`raise`), удаление (`remove`) и состояние для панели (`state_json`) считают окно частью workspace по этому полю; команда сохранения (`save_workspace`) записывает только окна с совпадающим полем и не ставит им тег, поэтому после записи окно оставалось посторонним, а назначения ячеек (`state.cells`) для уже поднятого workspace не обновлялись.

## Goals / Non-Goals

**Goals:**
- Окно, открытое по ходу работы, никуда не следует за workspace, пока пользователь не сохранил workspace.
- После сохранения окно ведёт себя как окно приложения: тег, ячейка, перенос вместе с workspace.

**Non-Goals:**
- Изменение формата сессии и конфига.
- Захват окон по `class` и `title` (изменение work-workspace) не меняется.

## Decisions

**D1. Привязка убирается из состояния, а не обнуляется.** Поле `workspace` исчезает из `Foreign` и `ExpectedForeign`; `raise` паркует только окна живых приложений других workspace, `remove` — только окна приложений workspace, `state_json` перечисляет в составе workspace только окна с тегом, `status` показывает признак «постороннее» вместо привязки. Вариант «оставить поле и всегда писать `None`» отвергнут: код парковки и возврата посторонних окон стал бы мёртвым, а старые снимки продолжали бы привязывать окна. В `SessionWindow` поле `workspace` остаётся необязательным ради чтения прежних снимков, при записи опускается.

**D2. Сохранение отбирает окна по столу, а не по привязке.** Кандидаты — окна текущего стола из `state.foreign`, кроме окон приложений, уже назначенных в ячейки workspace. Окно приложения конфига (тег есть, приложение описано) записывается под своим именем с `rect`; остальные — новой записью `[apps.<имя>]` по команде и каталогу процесса с именем от класса окна. Окна на `special:hidden` не имеют номера стола и не попадают в выборку.

**D3. Записанное окно становится окном приложения сразу.** Новому приложению ставится тег `app:<имя>` диспетчером `window.tag`, адрес убирается из `state.foreign`, назначения ячеек workspace (`state.cells[ws]`) сбрасываются перед перечитыванием конфига, чтобы собраться заново из записанного файла. Без сброса `reload_config` сохраняет прежние назначения, и новое приложение не попало бы в ячейки до перезапуска демона.

## Risks / Trade-offs

- [Снимок `default.toml` от прежней версии содержит привязанные окна] → поле разбирается и отбрасывается, окна восстанавливаются на своих столах свободными; после следующей записи снимка поля нет.
- [Панель показывает свободное окно в плитке стола, а не workspace] → так уже задано сценарием «Свободное окно» спецификации ws-daemon.

## Migration Plan

1. `cargo test`, `cargo build --release`, перезапуск `workspaced.service`.
2. Проверка вживую: терминал из лаунчера не уходит с поднятием другого workspace; после `Super+Tab Super+S` он записан в конфиг и переносится вместе с workspace.
3. Откат: предыдущая сборка демона; конфиг и сессия совместимы.
