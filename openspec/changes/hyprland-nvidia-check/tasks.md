## 1. Подготовка

- [x] 1.1 Убедиться, что вычистка joyful-desktop закоммичена и запушена: `git status --short` не показывает изменений в `dot_config/openbox/` и `dot_scripts/` (коммит делается по просьбе пользователя, задача только проверяет). Результат: чисто, коммиты 6c7952f…3193fb4 запушены, `main` совпадает с `origin/main`.
- [x] 1.2 Зафиксировать исходное состояние драйвера по спецификации «Условия драйвера NVIDIA»: `modinfo nvidia_drm | rg parm` показывает modeset и fbdev включёнными по умолчанию, `pacman -Q nvidia-utils egl-wayland xorg-xwayland wayland-protocols` даёт 610.x, любую версию, ≥ 24.1 и ≥ 1.34. Результат: modeset и fbdev включены по умолчанию (modinfo); nvidia-utils 610.57.04, egl-wayland 1.1.22, xorg-xwayland 24.1.13, wayland-protocols 1.49; условия драйвера выполнены.
- [x] 1.3 Установить `hyprland xdg-desktop-portal-hyprland hyprpolkitagent quickshell` и проверить: `Hyprland --version` печатает 0.56.x, `qs --version` печатает 0.3.x, `chezmoi status` пуст, lightdm на tty7 работает как прежде. Результат: hyprland 0.56.2-2.1, xdg-desktop-portal-hyprland 1.4.1, hyprpolkitagent 0.1.3, quickshell 0.3.1-1.1; `Hyprland --version` и `qs --version` отвечают; chezmoi status пуст; lightdm active.
- [x] 1.4 Создать пробный конфиг `~/.config/hypr/hyprland.lua` по design D2, D3, D7: монитор `DP-2` в режиме 3840x2160 с родной частотой, четыре `hl.env` для NVIDIA, `kb_file` на `~/.config/X11/xkb_custom`, привязки только для терминала (`wezterm`) и выхода, без Win+Пробел, Alt+E и Alt+R, включённые размытие, скругления и анимации. Проверка: файл существует, в нём нет ни одной привязки на перечисленные сочетания. Результат: файл создан, `luac -p` без ошибок, привязки только Super+Return/F/Q/V/M, стрелки, 1–4, мышь и Super+Shift+C (переключение курсора); режим монитора `3840x2160@120`.
- [x] 1.5 Создать пробную панель `~/.config/quickshell/nvcheck/shell.qml` по design D6: `PanelWindow` слева с зарезервированной зоной 330px, часы и элемент с бесконечной анимацией, кнопка, меняющая цвет по клику. ## 2. Проверка сессии Hyprland (сценарии «Условия драйвера», «Окружение клиентов», «Критерии совместимости»)

- [x] 2.1 Запустить из tty2 `Hyprland` и проверить сценарий «Драйвер соответствует условиям»: `hyprctl monitors` показывает DP-2 в 3840x2160 с родной частотой, ошибок NVIDIA в выводе консоли нет. Результат: DP-2 3840x2160@119.994 at 0x0, scale 1, hardwareCursorsInUse true (вывод `hyprctl monitors` в ~/com.txt); две пробы по 17 и 20 минут без ошибок NVIDIA в журнале. Побочная находка: при выходе через Super+M Hyprland падает с SIGSEGV в деструкторе DRM-бэкенда aquamarine (`CDRMBackend::flushAsyncCommitEvents` из `exit()`), coredump 16:45:22 и 17:04:57; сессия к этому моменту уже завершена, на проверку не влияет, класс ошибки известен (Hyprland discussion #12467).
- [x] 2.2 Проверить курсор по design D4: движение по всему экрану, наведение на края, быстрые перемещения. При артефактах включить `cursor:no_hardware_cursors`, перезагрузить конфиг и повторить. Результат (аппаратный или программный): аппаратный (`hardwareCursorsInUse: true`), артефактов нет по ответу пользователя в скрипте ~/nvcheck/run.sh (отчёт ~/nvcheck/report-20260908-171814).
- [x] 2.3 Сценарий «Клиент видит переменные»: в терминале из сессии `env | rg 'LIBVA_DRIVER_NAME|__GLX_VENDOR_LIBRARY_NAME|NVD_BACKEND|ELECTRON_OZONE_PLATFORM_HINT'` показывает четыре строки с ожидаемыми значениями. Результат: все четыре переменные с ожидаемыми значениями в терминале из сессии (~/com.txt).
- [x] 2.4 Нативные Wayland-клиенты: wezterm и firefox запускаются из сессии, `hyprctl clients` показывает `xwayland: 0` для обоих, окна отрисовываются без мерцания при перемещении и изменении размера. Результат: neovide и firefox нативные (`xwayland=false`), Firefox с отдельным профилем открыл страницу, мерцаний и чёрных областей при перемещении нет.
- [x] 2.5 Клиенты Xwayland: `Handy.AppImage` и второе X11-приложение из системы (например, `xclock` или `geany` с `GDK_BACKEND=x11`) запускаются, `hyprctl clients` показывает `xwayland: 1`, мерцания и чёрных областей нет. Результат: GIMP через `GDK_BACKEND=x11` запустился и работал нормально (со слов пользователя); wezterm тоже оказался клиентом Xwayland (`xwayland: 1`), так как у wezterm Wayland выключен по умолчанию; Xwayland поднят на DISPLAY=:1 по журналу. Первая жалоба GIMP «не найден дисплей» была при запуске из первой пробы и не повторилась.
- [x] 2.6 Сценарий «Видео декодируется аппаратно»: в firefox воспроизвести видео H.264 или AV1, в это время `nvidia-smi --query-gpu=utilization.decoder --format=csv -l 1` даёт ненулевые значения. Результат: декодер работает в Firefox 155 из сессии после настроек VA-API в user.js (media.hardware-video-decoding.force-enabled, media.rdd-ffmpeg.enabled, gfx.x11-egl.force-enabled, widget.dmabuf.force-enabled, media.av1.enabled=false) и MOZ_DISABLE_RDD_SANDBOX=1: локальный H.264 max 11%, YouTube VP9 max 2% (отчёт ~/nvcheck/report-20260908-173535). Без этих настроек декодер 0%: Firefox не включает VA-API на NVIDIA сам, а YouTube отдаёт AV1, который Turing не декодирует. Драйвер отдельно подтверждён mpv --hwdec=vaapi (до 14%).
- [x] 2.7 Эффекты на 4K: открыть четыре окна с включёнными размытием, скруглениями и анимациями, перемещать и переключать рабочие столы; рывков нет, `nvidia-smi` показывает нагрузку GPU без насыщения. Результат: 15 проходов перемещения плавающего окна и переключения столов при включённых размытии (size 6, passes 2), скруглениях и анимациях: рывков нет; GPU по nvidia-smi среднее 21%, максимум 31% на 3840x2160@120.
- [x] 2.8 Карта XKB (design D7): в терминале Alt+E фиксирует US, Alt+R фиксирует RU, Win+Пробел переключает по кругу, буквы e и r печатаются в обеих раскладках; `hyprctl devices -j` показывает активную раскладку. Результат: `hyprctl getoption input:kb_file` показывает путь; карта, снятая с композитора через `xkbcli dump-keymap-wayland`, содержит ALT_GROUP_SELECT и LockGroup; `switchxkblayout 1` даёт «Russian»; набор после Alt+R «rуке», после Alt+E «eert», Win+Пробел переключает в обе стороны («уке», «ert»). Побочное наблюдение: символ клавиши Alt+R и Alt+E попадает в строку (третий уровень типа повторяет базовый символ, так задумано в карте).

## 3. Проверка Quickshell (сценарий «Панель Quickshell замирает»)

- [x] 3.1 Запустить `qs -c nvcheck` из сессии: панель появляется у левого края, окна не заходят под зону 330px (`hyprctl monitors` показывает reserved слева), часы идут, анимация непрерывна не менее пяти минут при одновременном перемещении окон. Результат: слой `nvcheck` на уровне top, xywh 10 10 320 2140, reserved [340,0,0,0] (зона 330 плюс отступ 10); минута с перемещением окон: часы, вращение и бегущая полоса без остановок.
- [x] 3.2 Отклик: клик по кнопке меняет цвет без задержки; при замираниях повторить запуск с `QSG_RENDER_LOOP=basic` и с `QSG_RENDER_LOOP=threaded`, записать, в каком режиме замираний нет. Результат: клик меняет цвет сразу; замираний не было, сравнение QSG_RENDER_LOOP не потребовалось.
- [ ] 3.3 Размытие слоя: добавить в конфиг правило слоя с размытием для пространства имён панели, перезагрузить конфиг, убедиться, что фон панели размыт, а анимация не деградировала. Результат: (в работе) второй заход с плавающим окном под панелью: панель осталась непрозрачной, размытие не видно. Причина по FAQ Quickshell: окно с непрозрачным фоном получает непрозрачную поверхность; в shell.qml фон переведён в transparent с surfaceFormat.opaque=false и прямоугольником #b31a1b26 внутри. Шейдеры размытия в Hyprland компилируются (blur FB создан), ошибок нет. Нужен третий заход `~/nvcheck/run.sh 3.3`.
