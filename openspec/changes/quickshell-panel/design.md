# Design: Боковая панель на Quickshell

## Context

Мотивация — в proposal.md (раздел Why). Исходное состояние:

- Сессия Hyprland 0.56.2 с конфигом на Lua (`dot_config/hypr/hyprland.lua`), автозапуск через собственную цель `hyprland-session.target` (design D3 архива `2026-09-10-hyprland-config`). Панели нет, `nm-applet --indicator` уже запускается ради будущего трея.
- Quickshell 0.3.1 из репозитория extra. В сборке есть модули `Quickshell.Hyprland`, `Quickshell.Wayland`, `Quickshell.Networking`, `Quickshell.Services.SystemTray`, `Quickshell.Services.Pipewire`, `Quickshell.Io`, `Quickshell.Widgets`. Пробная конфигурация `~/.config/quickshell/nvcheck/shell.qml` подтвердила: `PanelWindow` с `exclusiveZone: 330` резервирует зону, а прозрачность слоя требует `color: "transparent"` и `surfaceFormat.opaque: false`.
- Дашборд eww описан спецификациями `eww-*`; его геометрия, цвета и поведение плиток — эталон для переноса. Демон `eww-daemon` (Rust) даёт столы, окна, лаунчер, календарь, меню трея и подсказки, но целиком построен на X11.
- С Lua-конфигом Hyprland текст, переданный в `hyprctl dispatch` и в сокет IPC как `dispatch …`, оборачивается в `hl.dispatch(<текст>)` и трактуется как выражение Lua: строка вида `workspace 3` не работает, работает `hl.dsp.focus({ workspace = 3 })`. Это установлено в изменении `hyprland-config` и определяет, как панель отдаёт команды композитору.
- Правила слоёв задаются в Lua функцией `hl.layer_rule` с полями `match.namespace`, `blur`, `ignore_alpha`; в конфиге сейчас нет ни одного правила слоя.

## Goals / Non-Goals

**Goals:**
- Одна конфигурация Quickshell, воспроизводящая колонку eww по геометрии, стилю и поведению, без зависимостей от X11 и от `eww-daemon`.
- Реактивные источники данных там, где Quickshell даёт их из коробки; скрипты только для метрик, дисков и погоды.
- Панель как штатная часть автозапуска сессии с перезапуском при падении.
- Поэтапная сборка: каждая плитка — отдельный модуль QML, который можно включать и отлаживать независимо.

**Non-Goals:**
- Изменение внешнего вида относительно eww (новая раскладка колонки, новые плитки) — вне объёма, панель повторяет прототип.
- Lua-раскладка зон окон и overlay для неё — отдельное изменение; панель лишь резервирует зону.
- Удаление сессии Openbox, конфигурации eww и проекта `eww-daemon`.
- Поддержка нескольких мониторов и других разрешений: панель, как и eww, рассчитана на DP-2 3840×2160.

## Decisions

**D1. Одна конфигурация `dot_config/quickshell/panel/`: `shell.qml`, `Theme.qml`, каталог `tiles/`, каталог `scripts/`.**
`shell.qml` содержит `ShellRoot` с единственным `PanelWindow` и колонкой плиток; каждая плитка — файл `tiles/<Name>.qml` (`Power`, `Clock`, `Weather`, `Gauges`, `Network`, `Disks`, `Favorites`, `Workspaces`, `Tray`, `Lang`, `Launcher`), всплывающие окна — `popups/<Name>.qml`. Цвета Tokyo Night, шрифты и размеры собраны в синглтон `Theme.qml` (объявлен через `qmldir`), чтобы плитки не дублировали значения. Импорт по относительным путям, без устаревших `root:/`, которые ломают LSP и синглтоны. Скрипты копируются из `dot_config/eww/widgets/*/scripts/` с переводом вывода на JSON; скрипты eww не трогаются, так как сессия Openbox остаётся рабочей. Альтернатива «положить QML прямо в `~/.config/quickshell/shell.qml`» отвергнута: документация Quickshell советует именованные конфигурации, и `nvcheck` до удаления сосуществует с `panel`.

**D2. Одно окно layer-shell вместо двадцати одного окна eww.**
Плитки eww были отдельными окнами, потому что picom размывал промежутки между ними. В Hyprland размытие слоя настраивается правилом с порогом прозрачности: `hl.layer_rule({ name = "panel-blur", match = { namespace = "^panel$" }, blur = true, ignore_alpha = 0.2 })` — пиксели с альфой ниже порога не размываются и не затемняются. Поэтому панель — один `PanelWindow` с `anchors.left/top/bottom`, `implicitWidth: 330`, `exclusiveZone: 330`, `WlrLayershell.namespace: "panel"`, `WlrLayershell.layer: Top`, `color: "transparent"`, `surfaceFormat.opaque: false`; плитки — `Rectangle` с чёрной заливкой непрозрачностью 0.9, рамкой 1 px и скруглением 12 px на абсолютных координатах из `eww.yuck`. Правила слоя Hyprland (`HL.LayerRuleSpec`) не задают непрозрачность слоя, поэтому, в отличие от eww под picom, альфу несёт заливка плитки; порог `ignore_alpha = 0.2` ниже неё, и промежутки с альфой 0 не размываются. Это единственное отступление от правила «прозрачность задаёт композитор», оно записано в спецификации qs-shell. Альтернатива «окно на плитку, как в eww» отвергнута: двадцать layer-surface с одной зоной усложняют фокус и порядок слоёв без выгоды. Окно создаётся через `Variants` по списку `Quickshell.screens` с фильтром по имени DP-2, а не как одиночный `PanelWindow`: при реализации 2026-09-11 монитор ночью отключился и вернулся (Hyprland создал и убрал выход FALLBACK), одиночное окно потеряло экран и не пересоздалось, панель исчезла при живом процессе; `Variants` уничтожает окно ушедшего экрана и создаёт новое для вернувшегося.

**D3. Панель не просит клавиатуру; режим по требованию только у поля фильтра.**
`WlrLayershell.keyboardFocus: None` по умолчанию: клик по любой плитке не забирает ввод у окон. Первый вариант с `OnDemand` на всём окне отвергнут при проверке 2026-09-11: любой клик по панели (например, по иконке окна в плитке стола) отдавал клавиатуру слою, а диспетчер фокуса окна у слоя её не забирал — терминал не принимал ввод до Alt+Tab. Поле фильтра лаунчера включает `OnDemand` заранее, при наведении указателя (композитор отдаёт клавиатуру слою только по клику, и к моменту клика запрос уже стоит), а отпускает по Escape, после запуска приложения, по событию `activewindowv2` от Hyprland (клик по окну, Alt+Tab) и когда указатель уходит с плитки при поле в фокусе. Полагаться на композитор нельзя: даже с `misc.layers_hog_keyboard_focus = false` клик по окну не забирал клавиатуру у слоя по требованию, поэтому панель отпускает её сама. Альтернатива `Exclusive` отвергнута: панель перехватила бы весь ввод.

**D4. Команды композитору — выражения Lua через `Hyprland.dispatch`.**
`Hyprland.dispatch(text)` из `Quickshell.Hyprland` шлёт в сокет `dispatch <text>`, а Hyprland с Lua-конфигом оборачивает текст в `hl.dispatch(...)`. Панель передаёт готовые выражения: `hl.dsp.focus({ workspace = 3 })`, `hl.dsp.focus({ window = "address:0x…" })`, `hl.dsp.window.move({ workspace = "special:hidden", follow = false, window = "address:0x…" })`, `hl.dsp.window.close({ window = "address:0x…" })`. Методы `HyprlandWorkspace.activate()` и подобные, которые шлют строку `workspace <имя>`, не используются, поскольку с Lua-конфигом они не работают; это проверяется первой задачей реализации. Запасной путь, если `dispatch` через сокет окажется недоступен: `Process` с `hyprctl eval '<lua>'`. Переключение раскладки — `Process` с `hyprctl switchxkblayout <клавиатура> next`, имя клавиатуры берётся из `hyprctl devices -j` при старте.

**D5. Столы и окна — из `Quickshell.Hyprland`, иконки — по классу окна через записи .desktop.**
`Hyprland.workspaces` и `Hyprland.toplevels` обновляются по сокету событий; у `HyprlandToplevel` есть `title`, `workspace`, `activated`, `urgent`, `address`, класс окна — в `lastIpcObject.class` (обновляется при `Hyprland.refreshToplevels()`, который панель вызывает по событиям `openwindow`, `movewindow`, `closewindow` из `Hyprland.rawEvent`). Иконка: `DesktopEntries.heuristicLookup(class)` → `Quickshell.iconPath(entry.icon, "application-x-executable")`; для консольных программ в wezterm класс один и тот же, поэтому, как и в eww, имя программы берётся из заголовка `<программа> · …`, который формирует `format-window-title` в `wezterm.lua`, и ищется как запись .desktop, иначе иконка терминала. Скрытые окна: при перемещении окна на `special:hidden` панель запоминает в своей модели пару «адрес → прежний стол» из события `movewindowv2`, и окно показывается свёрнутым на прежнем столе; если пары нет (окно скрыто до старта панели), иконка закрепляется за столом, активным в момент, когда панель впервые увидела окно, и не переезжает при переключении столов, как записано в qs-workspaces. Альтернатива `ToplevelManager` (протокол foreign-toplevel) отвергнута: в нём нет столов Hyprland и адресов для диспетчеров.

**D6. Трей — `SystemTray.items`, меню — собственная отрисовка через `QsMenuOpener`.**
Значки берутся из `SystemTrayItem.icon`, клики — `activate()`, `secondaryActivate()`, `scroll()`. Меню DBusMenu отрисовывается панелью: `QsMenuOpener` отдаёт дерево пунктов, всплывающее окно `popups/TrayMenu.qml` показывает их списком в стиле Tokyo Night на прозрачном фоне рядом с панелью (x = 340, на уровне значка), поддерживает подменю, флажки и разделители. Альтернатива `QsMenuAnchor` (нативное меню платформы) отвергнута: его внешний вид не подчиняется теме панели, и именно этот класс проблем (чёрные меню, прижатые к колонке) пришлось чинить в локальной сборке eww. Мост `xembedsniproxy` не нужен: nm-applet работает как StatusNotifierItem, приложений XEmbed в сессии нет.

**D7. Громкость — `Quickshell.Services.Pipewire`.**
`Pipewire.defaultAudioSink` под `PwObjectTracker`; `audio.volume` и `audio.muted` дают уровень и признак выключения, запись в них меняет громкость без `pactl`. Шаг колеса 5 %, потолок 100 %, ползунок 0…100 в раскрывающейся области с задержкой скрытия 300 мс после ухода указателя. Левый клик открывает `pavucontrol`, правый переключает `muted`. Скрипты `volume`, `vol-step`, `vol-watch` из eww не переносятся: их работа встроена в модуль.

**D8. Сеть — `nmcli` по событиям потока `nmcli monitor`.**
Модуль `Quickshell.Networking` 0.3.1 даёт устройства и их состояние, но не сообщает адреса IPv4 и не выражает VPN-соединения (проверено по документации при реализации), поэтому строки плитки строит скрипт `scripts/netstate` (`nmcli device status`, `nmcli dev show`, `nmcli con show --active` → один объект JSON), а запускается он только в ответ на события NetworkManager: панель держит открытым `nmcli monitor` как поток и после каждой строки перечитывает состояние с задержкой 300 мс, чтобы пачка событий дала один запуск. Опросов по таймеру нет. Меню строит `scripts/netmenu` при каждом открытии (`nmcli radio wifi`, список соединений типа vpn, подключённое проводное устройство); действия — команды из веток `scripts/popup` eww: `nmcli device wifi rescan`, `nmcli radio wifi on|off`, `nmcli con up|down id <имя>`, `nmcli device disconnect <iface>`; редактор — `nm-connection-editor`. Альтернатива «модуль Networking для eth и wifi плюс nmcli для остального» отвергнута: два источника для одной плитки без выгоды, раз адреса всё равно из nmcli.

**D9. Лаунчер — `DesktopEntries.applications` и файл статистики в формате eww-daemon.**
Список приложений обновляется модулем при изменении каталогов .desktop, фильтр — по подстроке названия без учёта регистра по модели QML, без демона и сокета. Запуск — `DesktopEntry.execute()`; для записей с `runInTerminal` — `wezterm start --class <id> -- <команда>`. Статистика запусков — `~/.local/share/quickshell-panel/usage.json` через `FileView` с `JsonAdapter`; формат тот же, что у `eww-daemon` (`{ "<id>": <число> }`), но файл новый, чтобы обе сессии не спорили за одну запись. Иконки — `Quickshell.iconPath(entry.icon, "application-x-executable")`, кэш файлов не нужен.

**D10. Календарь, часы и дата — средствами QML.**
Сетка месяца строится функцией JavaScript по `Date`: понедельник первым, шесть строк по семь дней, дни соседних месяцев серым, сегодняшний и выбранный день выделены. Названия месяцев и дней — русские массивы в модуле, дата — `Qt.locale("ru_RU")`. Таймер раз в секунду обновляет часы и при смене даты пересобирает сетку. Демон и файл `calendar.json` не используются.

**D11. Метрики, диски и погода — скрипты через `Process` и `Timer`.**
Скрипты `scripts/cpu`, `scripts/ram`, `scripts/gpu`, `scripts/cputemp`, `scripts/gputemp`, `scripts/disks`, `scripts/weather` — POSIX sh, копии скриптов eww с выводом одной строки JSON (`{"value": 37, "class": "t-low"}` для шкал, массив дисков, объект погоды). Интервалы как в eww: 3 с загрузка, 5 с температуры, 30 с диски, 30 мин погода, раз в час объём RAM. Скрипт cpu хранит прошлое значение `/proc/stat` в `$XDG_RUNTIME_DIR/quickshell-panel/`, как хранил в `/tmp` скрипт eww. Погода кэшируется в `$XDG_CACHE_HOME/quickshell-weather.json`. Альтернатива «читать `/proc` из QML через `FileView`» отвергнута: дельты `/proc/stat` и разбор `nvidia-smi` проще держать в sh, а скрипты уже отлажены.

**D12. Всплывающие окна — `PopupWindow` панели.**
Меню сети, меню окна, меню трея и подсказка при наведении — `PopupWindow` с `anchor.window` = окно панели и `anchor.rect` у плитки или значка, `anchor.gravity` вправо, так что окно появляется при x = 340 на уровне элемента и не следует за указателем. Закрытие: по действию, по клику вне окна и по уходу указателя с задержкой 300 мс (`HoverHandler` окна плюс таймер), подсказка — сразу при уходе. Альтернатива `PanelWindow` с отступами отвергнута: всплывающее окно не должно резервировать зону и должно позиционироваться относительно элемента.

**D13. Юнит `dot_config/systemd/user/quickshell-panel.service`.**
`ExecStart=/usr/bin/qs -c panel`, `Restart=on-failure`, `RestartSec=1`, `PartOf=hyprland-session.target`, `After=hyprland-session.target`, `[Install] WantedBy=hyprland-session.target`. Переменные `WAYLAND_DISPLAY` и `HYPRLAND_INSTANCE_SIGNATURE` юнит получает из окружения пользовательского systemd, куда их импортирует Hyprland (проверено в hyprland-config, задача 5.2). Включение — `systemctl --user enable quickshell-panel.service`; в сессии Openbox цель не поднимается, юнит не стартует. Альтернатива `hl.exec_cmd("qs -c panel")` отвергнута: нет перезапуска при падении и остановки при выходе.

**D14. Правило слоя и последствия для конфига Hyprland.**
В `hyprland.lua` добавляется правило из D2. Функция половин рабочей области (D5 архива hyprland-config) уже берёт `reserved` монитора, поэтому с панелью половины считаются от 3510 px, что и зафиксировано в proposal как изменение сценария hyprland-binds; сам конфиг привязок не меняется. Автозапуск в `hyprland.lua` не меняется: панель стартует юнитом.

**D16. Фокус кликом, без переноса курсора, рамка активного окна цвета плиток.**
По замечаниям пользователя при проверке столов 2026-09-11: `input.follow_mouse = 2` и `input.float_switch_override_focus = 0` (фокус только кликом, колесо идёт окну под курсором, наведение между плавающими окнами фокус не переводит), `cursor.no_warps = true` (активация окна из панели и Alt+Tab не переносят курсор), `general.col.active_border = rgba(e0af68ee)` (yellow Tokyo Night, как рамки плиток). Это изменение конфига Hyprland внесено в дельту спецификации hyprland-config этого изменения, поскольку впервые проявилось из-за панели: активация из плитки при `follow_mouse = 1` теряла фокус при первом движении курсора. Альтернатива `follow_mouse = 0` отвергнута: прокрутка окна под курсором без фокуса удобнее.

**D15. Отладка и проверка.**
Во время разработки панель запускается из терминала `qs -c panel` (журнал в stdout); юнит включается после прохождения чек-листа. Для проверки диспетчеров и событий используются `hyprctl eval`, `hyprctl clients -j`, `socat` на сокет событий `$XDG_RUNTIME_DIR/hypr/<сигнатура>/.socket2.sock`. Снимки для сравнения с eww — `grim`.

## Risks / Trade-offs

- [`Hyprland.dispatch` из Quickshell может не пройти через обёртку Lua так же, как `hyprctl dispatch`] → первая задача реализации проверяет `Hyprland.dispatch("hl.dsp.focus({ workspace = 2 })")`; при отказе все команды идут через `Process` с `hyprctl eval`, решение D4 меняется в одном месте (обёртка `Hypr.qml`).
- [В `Quickshell.Networking` 0.3.1 нет отдельного представления VPN] → строка VPN и меню работают через `nmcli` (D8); задача реализации проверяет, отражается ли VPN в модуле, и фиксирует результат.
- [Размытие с `ignore_alpha` может оставлять ореол на скруглённых углах плиток, где альфа сглаживания попадает между 0 и 0.9] → порог 0.2 подбирается по снимку `grim` при первом запуске; при ореоле снижается до 0.05.
- [Класс окна доступен только через `lastIpcObject` после `refreshToplevels()`] → обновление по событиям окон; при задержке иконка появляется с опозданием до одного цикла обновления, что не хуже eww.
- [Панель на слое `Top` перекрывает полноэкранные окна] → окна в полноэкранном режиме Hyprland рисует над слоем `Top` по умолчанию (`fullscreen` игнорирует зону), проверка в задачах; при необходимости слой `Bottom` для панели с потерей отрисовки над окнами, как у eww с `stacking fg` этого не было.
- [Меню DBusMenu у nm-applet с вложенными подменю и динамическими пунктами] → отрисовка через `QsMenuOpener` поддерживает подменю; сравнение с меню в eww входит в чек-лист.
- [Quickshell 0.3 и Hyprland 0.56 обновляются часто] → версии зафиксированы здесь, при обновлении сначала проверяется панель из терминала; конфиг eww остаётся в репозитории как эталон поведения.

## Migration Plan

1. Создать каркас: `Theme.qml`, `shell.qml` с окном, зоной и пустыми плитками нужной геометрии; запустить `qs -c panel` из терминала, добавить правило слоя, сверить размытие и прозрачность.
2. Наполнять плитки по одной в порядке: питание, часы с календарём, столы, трей с громкостью, раскладка, лаунчер, сеть, шкалы, диски, погода, избранное; каждую проверять по сценариям её спецификации.
3. Создать и включить юнит, перезайти в сессию, пройти сценарии hyprland-autostart.
4. Удалить `~/.config/quickshell/nvcheck/`.
5. Откат: `systemctl --user disable --now quickshell-panel.service`; сессия работает без панели, как до изменения. Файлы под chezmoi никому не мешают.
