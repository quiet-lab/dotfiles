# Proposal: Единственный workspace Work с захватом открытых окон и стартом при входе

## Why

Пользователь работает в одном наборе окон: терминал wezterm с запущенным herdr по центру, Chromium слева и neovide справа, на шаблоне `thirds` с окнами по 1920 px. Остальные workspace и приложения конфига (dots, workspaced, chat, firefox, telegram, thunar и пары редактор/терминал) больше не нужны, а цепочки `Super+A` для самых частых приложений слишком длинны: нужны одиночные Super+T, Super+C и Super+E. Два свойства демона мешают этому: окна он опознаёт только по своему тегу, поэтому уже открытые Chromium, wezterm с herdr и neovide (в том числе с тегами удалённых приложений) при поднятии workspace остаются где были, а при старте он поднимает только то, что записано в сессии, и после смены конфига стартовать было бы нечему. Терминал и Firefox из автозапуска композитора при этом становятся лишними.

## What Changes

- В конфиге остаётся один workspace `work` на шаблоне `thirds`: `herdr` (wezterm с `herdr`) в центре и главный, `chromium` слева, `neovide` справа. Остальные workspace, приложения и записи со столом удаляются; шаблоны остаются.
- Приложение получает необязательные поля `class` и `title` (регулярные выражения): при поднятии workspace или вызове приложения демон, не найдя окна с тегом, MUST захватить открытое окно с подходящими классом и заголовком, где бы оно ни было (любой стол, `special:pool`), в том числе окно с тегом приложения, которого больше нет в конфиге; окно получает тег приложения и дальше ведёт себя как запущенное демоном.
- Новый раздел `[startup]` конфига: `workspace` и `desktop` (по умолчанию 1). При старте после восстановления сессии демон поднимает этот workspace на указанном столе.
- Привязки: `Super+T` — herdr (сочетание уходит из `reserved`; оттуда же уходят Alt+Пробел и Super+D, память о меню окна и показе рабочего стола Openbox), `Super+C` — Chromium, `Super+E` — neovide, `Super+Delete` — закрыть окно (вместо Super+C), `Super+Tab w` — поднять `work`. Запись `Super+E` для thunar и цепочки `Super+A` исчезают.
- Из автозапуска `hyprland.lua` убираются `wezterm-gui` и `firefox`: окна сессии открывает демон, поднимая стартовый workspace.
- Второй workspace `surf` на шаблоне `halves` для двух окон Google Chrome из контейнера ubuntu-box (профили Default и AI.dev2026, приложения `chrome` и `chrome-ai`, `Super+B` и `Super+V`), цепочка `Super+Tab s`; сохранение workspace переезжает на `Super+Tab Super+S`, меню буфера обмена — на `Super+Insert`. Окна двух профилей одного процесса Chrome несут один класс и неотличимы по заголовку, поэтому захват по классу различает их только пока живут теги демона.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `ws-config`: у приложения поля `class` и `title`; раздел `[startup]`.
- `ws-daemon`: новое требование «Захват открытых окон приложения».
- `ws-sessions`: восстановление при старте дополняется поднятием стартового workspace из конфига.
- `hyprland-autostart`: из состава автозапуска уходят терминал и браузер, их место занимает стартовый workspace демона.
- `hyprland-binds`: строки таблицы для приложений, закрытия окна и workspace; `Super+T`, Alt+Пробел и Super+D больше не зарезервированы.

## Impact

- Проект `~/work/pets/workspaced`: поля приложения и раздел `[startup]` в `config.rs` (новая зависимость `regex`), захват окон в `daemon.rs` при поднятии и вызове приложения, поднятие стартового workspace в `startup`, тесты.
- `dot_config/workspaced/config.toml`: приложения, workspace, привязки, `reserved`, `[startup]`.
- `dot_config/hypr/hyprland.lua`: две строки автозапуска.
- Спецификации ws-config, ws-daemon, ws-sessions, hyprland-autostart, hyprland-binds; AGENTS.md.
- Файл сессии `default.toml` очистится сам: записи об удалённых workspace демон отбрасывает при чтении.
