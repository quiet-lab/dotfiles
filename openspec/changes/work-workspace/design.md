# Design: Единственный workspace Work с захватом открытых окон и стартом при входе

## Context

Мотивация — в proposal.md. Что есть сейчас:

- Демон находит окно приложения только по тегу `app:<имя>` (`find_app_window`), который ставит сам после запуска (`adopt`, диспетчер `window.tag`). Окна, открытые не им, остаются посторонними; окна с тегами удалённых из конфига приложений тоже никому не принадлежат.
- При старте `restore_default` восстанавливает списки столов из `default.toml`, отбрасывая workspace, которых нет в конфиге, и поднимает только активный workspace активного стола из снимка. Раздела о стартовом workspace в конфиге нет.
- Автозапуск `hyprland.lua` запускает `wezterm-gui` и `firefox` напрямую.
- Текущий herdr запущен как клиент `herdr` внутри wezterm с каталогом `~`; заголовок окна wezterm начинается с `herdr · ` (обработчик `format-window-title`). Chromium сейчас под Xwayland с классом `Chromium-browser`, нативно класс `chromium`.
- Одиночное сочетание в `chain` приложения допустимо: цепочка из одного звена.

## Goals / Non-Goals

**Goals:**
- Один workspace, который сам собирает свои окна, откуда бы они ни были, и поднимается при входе в сессию.
- Три самых частых приложения по одному сочетанию.

**Non-Goals:**
- Захват окон для посторонних (не описанных в конфиге) программ.
- Изменение правил парковки и обхода окон.

## Decisions

**D1. Захват по регулярным выражениям `class` и `title`, а не по исполняемому файлу.** Класс есть у любого окна, а заголовок отличает wezterm с herdr от другого wezterm; исполняемый файл не отличил бы. Выражения совпадают с окном целиком по классу (`^…$`) и по заголовку так, как написано (`^herdr · ` — префикс). Зависимость `regex`; выражения компилируются при проверке конфига, ошибка называет приложение и поле.

**D2. Кандидаты захвата — окна без тега и с тегом отсутствующего приложения.** Окно с тегом живого приложения принадлежит ему и не отбирается. Окно на `special:hidden` пропускается, как и при поднятии. Из нескольких кандидатов берётся первое по порядку `j/clients` не на `special:pool`, затем с пула. Прежний тег снимается диспетчером `window.tag` с префиксом `-`, новый ставится обычным вызовом.

**D3. Захват выполняется перед каждым поиском окон: в `raise`, в `make_main` (цепочка приложения внутри workspace) и в пути приложения без workspace.** Отдельный проход `adopt_untagged`: для каждого приложения без окна с тегом ищет кандидата, переставляет теги в композиторе и в локальном списке клиентов и убирает окно из списка посторонних, после чего обычный `find_app_window` находит окно. Первая версия пропускала `make_main`, и Super+E запускал второй neovide вместо захвата открытого из терминала.

**D4. Стартовый workspace — раздел `[startup]` конфига, а не сессия.** Сессия описывает «как было», конфиг — «как должно быть при входе». Поднятие выполняется в `startup` после `restore_default`: если сессия уже подняла этот workspace, повторное `raise` лишь расставит окна. Проверка конфига требует существующего workspace и стола 1…8.

**D5. Приложение herdr описано как `wezterm-gui start --always-new-process -- herdr` с каталогом `~`.** Так запущен текущий экземпляр; `--always-new-process` нужен, чтобы окно не открылось внутри уже работающего wezterm (в том числе терминала агента).

**D6. Автозапуск композитора не запускает приложения.** Строки `wezterm-gui` и `firefox` удаляются из `hyprland.lua`; окна даёт стартовый workspace. Firefox при необходимости открывается лаунчером.

**D7. Super+T, Alt+Пробел и Super+D снимаются с резерва, Super+C переходит приложению, закрытие — Super+Delete.** Резерв этих трёх сочетаний был памятью Openbox (рамки окна, меню окна, показ рабочего стола); пользователь отдал Super+T терминалу, а Alt+Пробел и Super+D просто освободил. В резерве остаются сочетания карты XKB и Alt+Super+Пробел. Закрытие окна на Super+Delete читается как «удалить окно».

## Risks / Trade-offs

- [Chromium под Xwayland и нативно имеют разные классы] → выражение `(?i)^chromium(-browser)?$` покрывает оба.
- [Два окна Chromium] → захватывается одно, второе остаётся посторонним и может быть привязано к workspace как постороннее окно по обычным правилам.
- [Запуск neovide и chromium при старте до готовности среды] → как и раньше для приложений workspace: демон ждёт окно до 30 секунд и ставит его в ячейку по появлении.
- [Прежняя сессия `default.toml` со старыми workspace] → записи отбрасываются при чтении, файл перезаписывается при первом изменении.

## Migration Plan

1. Собрать демон (`cargo test`, `cargo build --release`), применить новый конфиг, перезапустить `workspaced.service`, выполнить `hyprctl reload config-only`.
2. Поднять `work` командой `workspaced raise work`: открытые Chromium, wezterm с herdr и neovide будут захвачены и расставлены.
3. Применить `hyprland.lua`; результат автозапуска виден при следующем входе.
4. Откат: вернуть прежний конфиг из git; демон совместим с обоими.
