# Design: Сторож внимания

## Источник событий

Сервер herdr подписывает на статус агента только по `pane_id`; события
статуса для всех панелей сразу нет, а `pane.updated` при смене статуса
не приходит. Поэтому одно соединение `events.subscribe` несёт подписки
`pane.created`, `pane.closed`, `pane.moved`, `tab.closed`, `workspace.closed`
и `pane.agent_status_changed` на каждую панель из `pane.list`. Событие
изменения состава закрывает соединение и открывает новое с новым списком.
После подтверждения подписки снимается второй `pane.list`: изменения позже
снимка приходят событиями, и статусы применяются по порядку. Панель,
появившаяся между двумя снимками, сразу даёт новую подписку.

Сервер недоступен — поток ждёт события inotify в каталоге сокета
(`~/.config/herdr/herdr.sock` или `HERDR_SOCKET_PATH`): создание сокета
или запись журнала сервера. Только созданием сокета не обойтись: сокет
появляется при `bind()`, соединения принимаются после `listen()`, и попытка
между ними получает отказ, после которого нового создания уже не будет.
Подмена сервера `live-handoff` создаёт сокет заново по тому же пути.

Имена событий состава сервер пишет через подчёркивание (`pane_created`,
`tab_closed`), хотя подписка называет их через точку; при закрытии вкладки
приходит `tab_closed` без `pane_closed`.

## Сигнал и отбой

- Первый снимок после подключения задаёт состояние и сигнала не даёт:
  вопрос, висевший до старта демона или до подмены сервера, фокус не
  забирает. Снимок переподписки сравнивается с известным состоянием.
- Сигнал — панель вошла в `blocked`, а сигнал ещё не действует. Отбой —
  вышли из `blocked` все панели, вошедшие в него после сигнала. Панель,
  давно оставленная в `blocked` до сигнала, отбой не задерживает: иначе
  остановленная игра ждала бы без срока.
- Обрыв связи с сервером отбоя не даёт (подмена `live-handoff` не должна
  отпускать игру посреди ответа): первый снимок нового соединения оставляет
  в сигнале ждущие панели, а без них даёт отбой. Пока сервера нет,
  остановленное окно отпускает возврат пользователя в него.
- Снимок переподписки сначала принимает новые панели в `blocked`, затем
  убирает ушедшие: панель, сменившая идентификатор (`pane.moved`), не даёт
  отбоя с немедленным новым сигналом.
- Пользователь сам вернулся в остановленное окно (событие фокуса
  композитора) — `SIGCONT` сразу.
- Окно herdr уже в фокусе — ничего не делается.

## Порядок действий

Запрос паузы уходит до `SIGSTOP`, а при отбое `SIGCONT` — до `play`:
плеер в остановленном процессе не отвечает по D-Bus. `playerctl` ждёт ответа
плеера по D-Bus, поэтому пауза и возобновление идут в отдельных потоках,
а список поставленных на паузу плееров приходит демону сообщением; пауза,
закончившаяся после отбоя, сразу возобновляет плееры. Возобновляются только
плееры, бывшие в состоянии `Playing`. Фокус на herdr — путь клавиши
приложения (`app`), как по Super+W: переход на стол, поднятие workspace.

## Безопасность остановки

Останавливаются процесс полноэкранного окна (режим `fullscreen`, не
maximized) и его потомки, принадлежащие пользователю, кроме pid 1, самого
демона и процессов herdr, wezterm, Hyprland, Quickshell, systemd, D-Bus,
PipeWire, Xwayland. Список pid пишется в
`~/.local/state/workspaced/attention-frozen` до первого `SIGSTOP`;
не записался — не останавливается никто. `SIGCONT` по файлу получают
процессы при старте демона, при SIGTERM и SIGINT (обработчик пишет в канал,
поток возвращает процессы и повторяет сигнал с действием по умолчанию)
и при панике. Обработчик, а не маска сигналов: маску наследовали бы
запускаемые приложения; канал создаётся с `O_CLOEXEC`. Снимок сессии
при завершении по-прежнему не пишется.

Фокус на herdr идёт путём клавиши приложения, поэтому в режиме `home`
он, как Super+W, ставит herdr в главную ячейку; отбой раскладку
не возвращает (записка задачи: «как по Super+W»).

## Машина состояний

Решения принимает `Watch` без Hyprland и herdr, действия выполняет трейт
`Effects`; тесты подставляют свою реализацию.
