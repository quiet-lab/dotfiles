## Context

Решения пользователя — записка задачи keys-help, решения 1–9, и раздел
«Переданные» её правил (универсальный извлекатель, файл неизвестных
программ, хук разбора). Они обязательны; ниже они не пересматриваются,
а доводятся до устройства. Развилки решены по приоритетам записки:
(1) решения дословно; (2) без таймеров и опроса; (3) просмотрщик на Rust;
(4) всё под chezmoi; (5) таблицы из живой конфигурации; (6) ядро не знает
имён программ.

Исходные факты, проверенные по живой системе и документации форка herdr
(`~/work/pets/duty-herdr`, ветвь `duty`, документы
`docs/preview/website/src/content/docs/{plugins,socket-api,cli-reference,configuration}.mdx`):

- Плагин herdr — каталог с `herdr-plugin.toml`; `[[actions]]`, `[[panes]]`,
  `[[build]]`, `[[events]]`; `plugin link` сборку не запускает,
  `plugin install` запускает. Действие получает `HERDR_PANE_ID`,
  `HERDR_TAB_ID`, `HERDR_WORKSPACE_ID`, `HERDR_BIN_PATH`,
  `HERDR_SOCKET_PATH`. Клавиша — `[[keys.command]] type = "plugin_action"`.
- `plugin.pane.open` с `placement = "split"` принимает `target_pane_id`,
  `direction` и `focus`, но не `ratio`; `layout.set_split_ratio` и
  `pane.resize` меняют доли; `ratio` в herdr — доля **первого** (верхнего)
  потомка: `pane split --direction down --ratio 0.333` даёт верхней панели
  треть. Решено (координатор, приоритет 1 записки): нижняя панель
  занимает треть высоты, доля верхнего потомка 0.667 задаётся
  `layout.set_split_ratio` (D4).
- `PaneInfo` не сообщает плагин-владельца панели, но несёт `tokens`
  (`pane.report_metadata`), `foreground_process`, `terminal_title`;
  `pane.process_info` — процессы переднего плана с pid и argv.
- `events.subscribe`: `pane.focused`, `pane.updated` (заголовок),
  `pane.closed`, `pane.moved` (при переносе в другой workspace у панели
  новый `pane_id`), `layout.updated`, `tab.focused`, `workspace.focused`,
  `pane.output_matched` (по `pane_id`, регулярному выражению, срабатывает
  на переходе «нет совпадения → есть»). При отставании подписчика —
  `events_lost`, восстановление — новая подписка и чтение состояния.
- ble.sh: `ble-bind -m <keymap> -P` печатает строки вида
  `ble-bind -m 'vi_imap' -f C-a beginning-of-line`, `-x M-f fzf-file-widget`
  (пользовательские виджеты оболочки), `-c M-d '…'` (команды), `-s`
  (макросы). Все смены keymap проходят через `ble/decode/keymap/push`
  и `ble/decode/keymap/pop`, режимы vi завершаются вызовом
  `ble/keymap:vi/update-mode-indicator` — его же результат выводит
  `contrib/prompt-vim-mode` (индикатор пересчитывается при каждом его
  вызове). Привязки `-x` выполняет `ble/widget/.EDIT_COMMAND`, `-c` —
  `ble/widget/.SHELL_COMMAND`. Хуки `blehook PREEXEC`/`PRECMD` есть.
- yazi 26.9.1: `~/.config/yazi/init.lua` и прочие файлы yazi берутся под
  chezmoi (D9), `keymap.toml` в `~/.config/yazi` нет (действуют встроенные умолчания,
  файла умолчаний на диске нет). `ya sub <kinds>` отдаёт сообщения DDS
  всех экземпляров; встроенные виды (`hey`, `bye`, `cd`, `hover`, `tab`,
  …) слоя (manager, input, confirm, …) не сообщают.
- atuin: `~/.config/atuin/config.toml`, `keymap_mode` закомментирован
  (умолчание `emacs`), есть раздел `[keys]`. television:
  `~/.config/television/config.toml`, раздел `[keybindings]`. fzf:
  `man fzf` перечисляет действия и клавиши по умолчанию, `--bind`
  приходит из `FZF_DEFAULT_OPTS` процесса fzf.

## Goals / Non-Goals

**Goals:**

- Клавиша Ctrl+Alt+Shift+/ открывает и закрывает нижнюю панель с таблицей
  клавиш контекста верхней панели; таблица меняется по событиям смены
  режима, запуска и выхода программ, смены фокуса.
- Добавление программы — один манифест без правок ядра; любая программа
  без манифеста проходит универсальный извлекатель, не найденная —
  попадает в файл неизвестных программ.
- Конфигурация представления по решению 6, правится и вручную,
  и клавишами просмотрщика.

**Non-Goals:**

- Замена панели `qs-keys-help` (клавиши композитора).
- Правка содержимого конфигов yazi, atuin, television (под chezmoi без изменений; поставщик
  yazi дописан в `init.lua` — D9).
- Редактирование привязок программ из просмотрщика.

## Decisions

### D1. Состав плагина и размещение

Каталог источника `dot_config/herdr/plugins/keys-help/` →
`~/.config/herdr/plugins/keys-help/`:

```text
herdr-plugin.toml        манифест herdr: действие toggle, панель viewer, build
Cargo.toml, Cargo.lock   один пакет, бинарник keys-help
src/                     ядро (main.rs, herdr.rs, channel.rs, context.rs,
                         manifest.rs, extract/, view.rs, ui.rs, unknown.rs)
manifests/               манифесты программ: ble.toml, fzf.toml, atuin.toml,
                         tv.toml, yazi.toml, nvim.toml, generic.toml
manifests/data/          данные манифестов, которых нет в живой системе
                         (умолчания keymap yazi 26.9.1, базовые клавиши vim)
tests/fixtures/          снимки ble-bind -P, keymap.toml, man-страницы
```

Манифест herdr:

```toml
id = "quiet-lab.keys-help"
name = "Keys help"
version = "0.1.0"
min_herdr_version = "0.9.5"
platforms = ["linux"]

[[build]]
command = ["cargo", "build", "--release", "--locked"]

[[actions]]
id = "toggle"
title = "Подсказка клавиш"
contexts = ["workspace"]
command = ["target/release/keys-help", "toggle"]

[[panes]]
id = "viewer"
title = "keys"
placement = "split"
command = ["target/release/keys-help", "viewer"]
```

`plugin link` сборку не запускает, поэтому сборку при `chezmoi apply`
делает сценарий `run_onchange_after_build-herdr-keys-help.sh.tmpl`:
в шаблоне — хеш исходников (`include` файлов `src/**`, `Cargo.*`), тело —
`cargo build --release --locked` в `~/.config/herdr/plugins/keys-help`.
Регистрацию делает отдельный сценарий `run_after_link-herdr-keys-help.sh`
при каждом `apply`: плагин уже есть в `~/.config/herdr/plugins.json` — выход
без вызовов herdr; иначе `herdr plugin link`, которому нужен запущенный сервер.
Сервер не запущен — сообщение и успешное завершение: сценарий сборки
по `run_onchange` повторно не выполнится, а регистрирующий выполнится при
следующем `apply` (или вручную `herdr plugin link
~/.config/herdr/plugins/keys-help`). Каталог `target/`
лежит в `$HOME` рядом с исходниками, chezmoi им не управляет. Ядро,
извлекатели и просмотрщик — один бинарник с подкомандами `toggle`,
`viewer`, `table <контекст> --pane <id>` (печать таблицы для проверок
и тестов), `unknown list`.

Отвергнуто: просмотрщик на Python (приоритет 3); отдельный бинарник
извлекателей (лишняя сборка — извлекатели декларативные и программ
не знают, D6).

### D2. Канал «верхняя панель → просмотрщик»

Каталог `$XDG_RUNTIME_DIR/herdr-keys-help/panes/<HERDR_PANE_ID>/`
(`:` в имени допустим). Каждый поставщик пишет свою запись — файл
`<программа>-<pid>.json`, один JSON-объект:

```json
{"v":1,"program":"ble","mode":"vi_nmap","pid":12345,
 "state":"active","command":null,"table":"/run/user/1000/herdr-keys-help/ble/12345/vi_nmap.bind",
 "server":null,"env":{}}
```

- `program` — имя программы, по нему манифест объявляет себя поставщику
  (`[detect] provider = "ble"`); `mode` — режим (`null` — без режима);
  `pid` — процесс поставщика (оболочка, nvim, yazi).
- `state`: `active` — программа на переднем плане в режиме `mode`;
  `exec` — оболочка запустила команду `command` (`PREEXEC`);
  `widget` — оболочка выполняет виджет или команду привязки `command`
  (`-x`/`-c`), программа запускается внутри него.
- Необязательные поля — подстановки для источников таблиц манифеста
  (`table`, `server`, `env`): `{record.table}`, `{record.server}`,
  `{env.FZF_DEFAULT_OPTS}`. Поставщик может добавить любое другое поле
  (например, `base_table` модуля ble.sh): манифест ссылается на него
  `{record.<поле>}`, ядро имён полей не знает. Подставляются строковые,
  числовые и логические значения; `null`, массивы и объекты — нет.

Запись — целиком одним `write` (bash: `printf … >file`; Lua:
`io.open(…,"w")`), просмотрщик читает по `IN_CLOSE_WRITE` и `IN_MOVED_TO`,
неразобранный JSON пропускает до следующего события. Запись удаляется
поставщиком при выходе (`VimLeavePre`, `EXIT` оболочки); запись
упавшего процесса снимает просмотрщик по событию pidfd (D3).

Каталог панели создаёт просмотрщик при выборе цели, до наблюдения
inotify, и поставщик (`mkdir -p` перед первой записью). Каталог
наблюдается вместе с родительским `panes/`: если каталог цели удалён
и создан заново, событие `IN_CREATE` в `panes/` возобновляет наблюдение
и перечитывает записи. Удаляет каталог просмотрщик: по `pane.closed`
любой панели — каталог закрытой панели вместе с символическими ссылками
прежних id на него (D3, п. 4); при старте — каталоги панелей, которых нет
в `pane.list`. Имена каталогов при старте читаются до запроса списка
панелей, поэтому каталог панели, созданной после этого чтения, уборка
не трогает. Ссылка прежнего id удаляется вместе с каталогом,
на который указывает, — по ней пишет оболочка перенесённой панели.

Порядок записей — порядок изменения: при старте по `mtime`
(наносекунды), дальше — по порядку событий inotify. Активна последняя
изменённая запись живого процесса; если среди записей есть запись
в состоянии `active` процесса переднего плана цели (`pane.process_info`),
активна самая свежая из таких. Так запись оболочки о запуске `fg` после
Ctrl-Z не заслоняет запись nvim, вернувшегося на передний план,
и `{record.server}` остаётся доступным. Так стек bash → yazi → nvim
разрешается без счётчиков: nvim пишет позже yazi, при выходе nvim его
запись удаляется, и активной снова становится запись yazi; после выхода
yazi оболочка пишет `PRECMD`-запись.

Переменные окружения для подстановок (`env`) оболочка берёт из файла
`$XDG_RUNTIME_DIR/herdr-keys-help/env-vars` (по строке на имя); файл
пишет просмотрщик при старте объединением полей `env` всех манифестов.
Модуль ble.sh перечитывает его в `PRECMD`, только если файл новее
прочитанного (`[[ -nt ]]`, встроенная проверка).

Отвергнуто: сокет на панель (поставщику bash пришлось бы держать
соединение или запускать внешний процесс на каждую смену режима); один
файл на панель (вложенные программы затирали бы друг друга, стек
пришлось бы восстанавливать).

### D3. Цель просмотрщика: следование за фокусом

Просмотрщик — один поток, цикл `poll` по дескрипторам: подписка herdr
(сокет `HERDR_SOCKET_PATH`), inotify каталога записей и каталога
`view.toml`, signalfd (`SIGWINCH`, `SIGTERM`, `SIGHUP`), pidfd процессов
записей и извлекателей, ввод терминала. Таймеров нет.

1. Старт: `pane.current` по своему `HERDR_PANE_ID` даёт workspace и tab;
   цель — панель, на которую указывал `--target-pane` при открытии
   (передаётся окружением `KEYS_HELP_TARGET`).
2. Подписка `events.subscribe`: `pane.focused`, `pane.updated`,
   `pane.closed`, `pane.moved`, `layout.updated`.
3. `pane.focused` в своём workspace на панель, которая не является
   просмотрщиком (нет токена `keys_help`), меняет цель; фокус на самом
   просмотрщике и в чужих workspace цель не меняет. herdr сообщает
   `pane.focused` только для workspace, открытого в клиенте: смена фокуса
   в фоновом workspace (`herdr pane activate`) не порождает ни
   `pane.focused`, ни `layout.updated`, и цель меняется, когда workspace
   открывают в клиенте (herdr тогда сообщает фокус его панели).
4. `pane.moved` с `previous_pane_id` цели переносит цель и каталог записей
   (`rename` каталога на новый `pane_id`), а на месте старого каталога
   оставляет символическую ссылку на новый: поставщики панели сохраняют
   прежний `HERDR_PANE_ID`, и их записи (и `mkdir -p`) по старому пути
   попадают в новый каталог; `pane.closed` цели — цель переходит к панели
   в фокусе своего tab.
5. Смена цели, событие inotify в каталоге цели, `pane.updated` цели,
   срабатывание `pane.output_matched` цели, выход pidfd — пересчёт
   контекста (D5) и, если контекст или таблица изменились, перерисовка.
6. `events_lost`: новая подписка, `pane.current`/`pane.list` и пересчёт.

Сервер herdr отвечает на один запрос в соединении и закрывает его, поэтому
каждый запрос просмотрщика идёт новым соединением; подписки — долгие
соединения.

Подписки `pane.output_matched` строятся из манифестов (`[detect] screen`)
для текущей цели и пересоздаются при смене цели (отдельное соединение
на набор подписок цели).

### D4. Открытие, размер и закрытие (toggle)

Действие `toggle` (`keys-help toggle`):

1. `pane list` по `HERDR_TAB_ID`; панель с токеном `keys_help` = `viewer`
   источника `plugin:quiet-lab.keys-help` — просмотрщик этого tab.
2. Есть — `plugin pane close <pane_id>`; конец. Повторное нажатие
   закрывает панель независимо от того, где фокус в этом tab.
3. Нет — `plugin pane open --plugin quiet-lab.keys-help --entrypoint viewer
   --placement split --target-pane $HERDR_PANE_ID --direction down
   --no-focus --env KEYS_HELP_TARGET=$HERDR_PANE_ID`.

Просмотрщик при старте ставит себе токен (`pane.report_metadata`, без
TTL; токен снимается вместе с панелью) и задаёт размер: по `pane.layout`
находит split, вторым потомком которого он является, и
`layout.set_split_ratio` даёт верхнему потомку долю 0.667 — нижней панели
треть. Затем и по каждому `SIGWINCH` и `layout.updated` своего tab:
если строк содержимого (`TIOCGWINSZ`) меньше 5, — `pane.resize`
своей панели вверх на недостающую долю высоты split; если высоты split
не хватает на 5 строк и минимальную верхнюю панель, увеличения нет.
Уменьшение, сделанное пользователем выше минимума, не отменяется.

Выход просмотрщика — по `SIGHUP`/`SIGTERM` (закрытие панели действием
`toggle`): удаляет свои файлы, закрывает подписки и pidfd дочерних
извлекателей. Клавиша `q` в просмотрщике панель не закрывает, а
возвращает фокус верхней панели (D13).

Отвергнуто: `pane split` + `pane run` (панель без владельца-плагина);
реестр просмотрщиков в файлах (токен herdr исчезает вместе с панелью,
файл — нет).

### D5. Разрешение контекста

Для цели просмотрщик собирает признаки:

- активная запись (D2) живого процесса;
- процессы переднего плана — `pane.process_info` цели, запрашивается
  при каждом пересчёте (это ответ на событие, не опрос);
- заголовок `terminal_title_stripped`;
- текущие совпадения `pane.output_matched` цели.

Порядок:

1. Запись `state = active` → манифест с `provider = <program>`,
   режим — `mode` записи (через `[modes]` манифеста).
2. Запись `exec`/`widget` или запись отсутствует → кандидаты манифестов
   по `command` записи (`shell_commands`, шаблоны), по имени процесса
   переднего плана (`process`), по заголовку (`title`), по экрану
   (`screen`); при нескольких — наибольший `priority`. Режим — по экрану
   (`[[modes.screen]]`), по конфигурации программы (`[modes.from_config]`)
   или `default`.
3. Манифеста нет → универсальный извлекатель (D7) для команды переднего
   плана: контекст `<команда>.generic`.
4. Извлекатель ничего не нашёл → запись в файл неизвестных программ (D8),
   просмотрщик показывает «клавиши <команда> не найдены».

Команда — имя исполняемого файла (`basename` argv0 процесса или первого
слова `command` записи без присваиваний и `sudo`/`env`). Оболочка
с ble.sh без записи (ble.sh не загружен) идёт по шагу 3 как `bash.generic`.

### D6. Формат манифеста программы

```toml
program = "ble"               # имя, первая часть контекста
priority = 100                # выбор среди кандидатов; generic — 0
origins = ["readline", "ble", "fzf", "atuin", "tv", "user"]

[detect]
provider = "ble"              # записи этого program
process = []                  # имена процессов переднего плана (glob)
shell_commands = []           # command записей exec/widget (glob)
title = ""                    # регулярное выражение по заголовку
screen = []                   # [{ source = "visible", lines = 30, regex = "…" }]

[modes]
default = "vi_imap"
names = { mgr = "manager" }   # родное имя режима → имя в контексте
# from_config = { file = "~/.config/atuin/config.toml", key = "keymap_mode",
#                 map = { emacs = "search", vim-insert = "search", vim-normal = "normal" } }
# [[modes.screen]] mode = "input", regex = "…"

[[source]]                    # источники таблицы, по порядку
modes = ["*"]                 # к каким режимам относится
kind = "regex"                # regex | toml | json | static
file = "{record.table}"       # или command = [...] / env = "NAME"
regex = '''^ble-bind -m \S+ -(?P<type>[fxcs]) (?P<key>'[^']*'|\S+) (?P<action>.+)$'''
unquote = ["key", "action"]   # снять кавычки shell
skip = { key = "^__.*__$", action = "^(bell|nop)$" }
on_conflict = "override"      # override | keep
# kind = "toml": path, tables = ["{mode}"], arrays = ["prepend_keymap",
#   "keymap", "append_keymap"], key_field = "on", action_field = "run",
#   desc_field = "desc", replace_if = "keymap"

[key]                         # нормализация записи клавиши
map = { "ctrl-" = "C-", "alt-" = "M-", "<Esc>" = "ESC" }

[[describe]]                  # описание по действию
action = "^history-isearch-backward$"
desc = "поиск по истории назад"
[[group]]                     # группа по действию
action = "^(history|.*-history)"
group = "history"
[[origin]]                    # происхождение по полям совпадения
type = "^[xc]$"
origin = "user"
```

Поля источников по видам:

- общие: `modes`, `on_conflict`, `skip` (поле → регулярное выражение;
  проверяется по исходному значению и по нормализованной клавише), `group`
  и `origin` — значения по умолчанию для записей источника; вход — `command`,
  `file` (или `path`), `env` или `text` (строка с подстановками);
- `regex`: `regex` (именованные захваты `key`, `action`, `desc`, `group`,
  `origin` и любые другие — для условий правил), `sections`, `unquote`,
  `split` — регулярное выражение-разделитель захвата `key`: каждая часть
  становится отдельной записью (строка `ctrl-k up` из `man fzf` при
  `split = ' +'`); `sections` без `regex` — разбор строк «клавиша —
  описание» универсального извлекателя (D7);
- `toml`: `tables` (пути с подстановками), `layout` — `arrays` (массивы
  таблиц `arrays`, по умолчанию при непустом `arrays`), `key_value`
  (`клавиша = действие`, по умолчанию) или `value_key` (`действие =
  клавиша` или список клавиш), `key_field`, `action_field`, `desc_field`,
  `group_field`, `origin_field`, `replace_if`; внутри источника первое
  вхождение клавиши побеждает;
- `json`: массив объектов по `pointer` (JSON Pointer, по умолчанию корень),
  те же `*_field`, `raw_fields` — поля, из которых собирается `raw`
  (без них — объект целиком);
- `static`: `entries = [{ key, action, desc, desc_full, group, origin, raw }]`
  или `file` — TOML с массивом `entries` (`entry`) либо JSON-массив тех же
  объектов; в статической записи `desc` — короткое описание, `desc_full` —
  полное.

Верхний уровень: `first_nonempty` — источники по порядку, первый непустой
результат побеждает (по умолчанию — при `[detect] fallback = true`); `env` —
дополнительные имена переменных для файла `env-vars`. Неизвестные поля
манифеста не мешают разбору, но перечисляются в журнале плагина
(`$HERDR_PLUGIN_STATE_DIR/keys-help.log`) как возможные опечатки.

Клавиша нормализуется к записи ble.sh: модификаторы `C-` (Ctrl), `M-`
(Alt, Meta), `S-` (Shift), `s-` (Super, Cmd, Win) в порядке `C-M-S-s-`,
именованные клавиши (`ESC`, `RET`, `TAB`, `SP`, `up`,
`f1`), последовательности — через пробел. По нормализованной записи
работают `hide`, `pin` и `[entry]`.

Запись таблицы:

| Поле | Смысл |
|---|---|
| `key` | нормализованная клавиша |
| `desc` | короткое описание: что делает, в нескольких словах, без имён виджетов и функций |
| `desc_full` | полный текст описания из источника (`desc` из `keymap.toml`, текст `man`, `desc` Neovim) |
| `group`, `origin` | группа и происхождение |
| `action` | имя виджета, функции или действия |
| `source` | откуда взята запись: `manifest:<файл>`, `generic`, `user` (`[entry]` в `view.toml`) |
| `raw` | исходный фрагмент: строка `ble-bind -P` для ble.sh, `rhs` и `файл:строка` определения для Neovim, фрагмент `man`/`--help` для `generic` |

Короткое описание берётся из `[[describe]]` манифеста (поле `desc`;
описания составляют авторы манифестов, переформулируя длинные тексты
источников и имена виджетов); полный — из поля описания источника
(`desc_field`) или `desc_full` у `[[describe]]`. Если короткого описания
нет, ядро сокращает полный текст правилом D7а; если нет и полного —
показывается действие.

Подстановки в `file`, `command`, `env`, `path`: `{mode}`, `{record.<поле>}`,
`{env.<ИМЯ>}`, `{command}`, `{pid}`; тильда в начале пути. `{mode}` — родное
имя режима (ключ `[modes] names`), `{mode_name}` — имя в контексте;
`{env.<ИМЯ>}` берётся из поля `env` записи, затем из окружения процесса
программы (`/proc/<pid>/environ`), затем из окружения просмотрщика.
`{record.<поле>}` — любое строковое, числовое или логическое поле записи
поставщика (D2). Подстановка без значения пропускает источник; причина
пишется в журнал плагина строкой отладки, если задана переменная
окружения `KEYS_HELP_DEBUG`. Источник
`command` запускается без оболочки, stdin `/dev/null`, без терминала
(`setsid`), окружение `TERM=dumb MANPAGER=cat PAGER=cat MANWIDTH=200`.
Его ожидание — по pidfd; процесс живёт не дольше контекста, ради которого
запущен: смена контекста или выход просмотрщика завершает его по pid.
Сроков ожидания нет. Готовность задания цикл просмотрщика сверяет
по номеру задания в теге ожидания: если обработчик события в той же
итерации заменил задание, готовность прежнего pidfd пропускается и цикл
не ждёт новый процесс. Таблица кешируется в памяти по ключу «манифест,
режим, значения подстановок, `mtime` прочитанных файлов»; если командный
источник манифеста подставляет поля записи (`{record.…}`), в ключ входит
и ревизия записи — номер её последней перезаписи. Поэтому перезапись
записи поставщиком (смена режима Neovim) строит таблицу заново,
и привязки, появившиеся позже (LSP), попадают в неё. Выводы команд живут
только пока строится одна таблица. Кеш ограничен: новая таблица того же
манифеста, команды и процесса заменяет прежнюю, таблицы процесса
снимаются по его завершению (pidfd), а сверх 64 записей снимается самая
старая.

Ядро знает только виды источников и формат записи; имена программ,
пути их конфигов, регулярные выражения и описания — в манифестах
(приоритет 6). Описания пишутся по-русски.

Манифесты первой очереди:

| Манифест | Распознавание | Режимы | Таблица |
|---|---|---|---|
| `ble.toml` | `provider = "ble"` | keymap ble.sh (`vi_imap`, `vi_nmap`, `vi_xmap`, `vi_smap`, `vi_omap`, `vi_cmap`, `isearch`, `nsearch`, `menu_complete`, `auto_complete`, `emacs`) | `regex` по `{record.table}` — дамп `ble-bind -m <keymap> -P`; `-x`/`-c` → `user` или по имени функции (`fzf`, `atuin`, `tv`), `vi-rlfunc/` → `readline`, прочие `-f` → `ble` |
| `fzf.toml` | `process = ["fzf"]`, `shell_commands = ["fzf-*", "__fzf_*"]` | без режима (`fzf`) | `regex` по `man fzf` (раздел действий с клавишами по умолчанию) + `regex` по `{env.FZF_DEFAULT_OPTS}` (`--bind`), `override` |
| `atuin.toml` | `process = ["atuin"]`, `shell_commands = ["__atuin_*"]` | `search` (`emacs`, `auto`), `insert` (`vim-insert`), `normal` (`vim-normal`) из `keymap_mode` | `static` по `keymap_mode` + `toml` раздела `[keys]` конфига |

| `nvim.toml` | `provider = "nvim"`, `process = ["nvim"]` | `normal`, `insert`, `visual`, `select`, `cmdline`, `replace`, `terminal`, `operator` | `json` из `nvim --server {record.server} --remote-expr` (дамп `nvim_get_keymap` и `nvim_buf_get_keymap` с `desc`), затем `static` базовых клавиш vim, `keep` |

### D7. Универсальный извлекатель

`manifests/generic.toml` — обычный манифест с `program = "*"`,
`priority = 0`, `[detect] fallback = true`; контекст — `<команда>.generic`,
происхождение всех записей — `generic`. Источники по порядку, первый
непустой результат побеждает:

1. `man`: `command = ["man", "-P", "cat", "{command}"]`, вид `regex`
   с `sections` — регулярное выражение заголовков разделов о клавишах
   (`^(KEY ?BINDINGS|KEYS|KEYBOARD( SHORTCUTS| COMMANDS)?|COMMANDS|INTERACTIVE( COMMANDS| MODE)?|SHORTCUTS|NAVIGATION)\b`);
   внутри раздела запись — строка с отступом, где термин похож
   на клавишу (`C-x`, `Ctrl+X`, `^X`, `<Esc>`, `Alt-x`, одиночный символ,
   `F1`), а описание отделено двумя пробелами или следует строкой ниже
   с большим отступом; группа — ближайший подзаголовок.
2. `--help`: `command = ["{command}", "--help"]` с тем же разбором
   по заголовкам и строкам-клавишам; программа запускается без терминала
   (D6), поэтому полноэкранные программы завершаются с ошибкой, не
   заняв экран; зависший процесс завершается при смене контекста.

**Проба справки.** Любая команда источника с аргументом `--help`
(источник `{command} --help` и параметры первого слова строки ввода, D17)
— проба справки, и ядро запускает её с ограничениями без знания имён
программ: исполняемый файл (путь из `argv[0]` или первый по `PATH`, по
ссылкам) должен начинаться с заголовка ELF `\x7fELF` — сценарий с `#!`,
который `--help` не разбирает, выполнил бы своё действие (окно пароля,
снимок экрана), поэтому сценарии не запускаются, а вывод считается
пустым; окружение пробы — без `DISPLAY`, `WAYLAND_DISPLAY`,
`WAYLAND_SOCKET`, `HYPRLAND_INSTANCE_SIGNATURE`, `DBUS_SESSION_BUS_ADDRESS`,
`SUDO_ASKPASS`, `SWAYSOCK`, `XAUTHORITY`, чтобы программа не нашла
графическую сессию, композитор и шину; stdin `/dev/null`, без терминала
(`setsid`) — как у всех команд D6.
3. Известные файлы конфигурации клавиш:
   `~/.config/{command}/config.toml` — таблицы `keybindings`, `keys`,
   `keymap` (`клавиша = действие`), и `~/.config/{command}/keybindings.conf`
   — строки `bind <клавиша> <действие>` и `<клавиша> = <действие>`.

Флаг `sections` и признаки «похож на клавишу» — общие возможности вида
`regex`, а не знание о программах. Результат кешируется на диске
`$XDG_CACHE_HOME/herdr-keys-help/generic/<команда>.json` с ключом
«путь исполняемого файла, его `mtime` и размер, `mtime` man-страницы»:
при тех же входах извлечение не повторяется.

### D7а. Правило сокращения описаний

Применяется к записям `generic` и к любой записи без короткого описания
в манифесте; полный текст остаётся в `desc_full`:

1. Пробельные символы схлопываются, разметка man (`\fB`, подчёркивания
   с возвратом) снимается.
2. Берётся первое предложение: текст до первого `. `, `; `, `: ` или
   конца строки.
3. Отбрасываются скобочные пояснения и начальные служебные слова:
   артикли (`the`, `a`, `an`), `this`, `will`, `used to`, `allows (you)
   to`, `lets you`, «позволяет», «используется для», «служит для».
4. Регистр букв исходника сохраняется, точка в конце снимается.
5. Предел — 32 символа: длиннее режется по границе слова с `…`.

Константы (предел, перечень служебных слов) — в ядре, а не в манифестах:
правило одно для всех программ и не зависит от их имён.

Конфигурация представления действует для `<команда>.generic` так же,
как для остальных контекстов (`[context."htop.generic"]`,
`[context."*.generic"]`).

### D8. Файл неизвестных программ и порядок разбора

`$XDG_STATE_HOME/herdr-keys-help/unknown-programs.toml`:

```toml
[program.htop]
count = 3
last = "2026-11-08"
```

Пишет просмотрщик, когда для команды не нашлось ни манифеста, ни таблицы
универсального извлекателя, — один раз на появление процесса (новый pid
команды на переднем плане цели); одна таблица на команду, повторов нет.
Обновление — чтение, изменение, запись во временный файл и `rename`
под `flock` файла-замка рядом: файл один на пользователя по решению
пользователя, размножить его нельзя, а писать могут несколько
просмотрщиков (по одному на tab); ожидание замка — на время одной
записи (`flock` блокирующий, без срока); комментарий с этим объяснением —
над кодом замка (правило изоляции `~/.claude/CLAUDE.md`). Команда,
получившая манифест или таблицу, из файла удаляется тем же механизмом
при следующем появлении.

Разбор идёт по событию: хук Claude Code `SessionStart` проекта dotfiles
(`.claude/settings.json` → `.claude/hooks/keys-help-unknown.sh`) печатает
список из файла (команда, счётчик, дата, по убыванию счётчика) или
ничего, если файла нет или он пуст. Главная сессия по этому списку
ставит задачу на манифесты; порядок разбора — в `docs/keys-help.md`:
манифест программы (раздел «Добавление программы»), пополнение
`view.toml`, удаление строки из файла.

### D9. yazi: слой и выход

Решение пользователя (ответ о слое yazi, `rules.md` задачи, раздел «Переданные»):
всё, чего нет, и всё, с чем работает плагин, берётся под chezmoi. Поэтому
`~/.config/yazi/init.lua`, `yazi.toml`, `theme.toml`, `package.toml`,
локальная тема `flavors/modus-vivendi.yazi` (без `.git`), `~/.config/atuin/config.toml`
и `~/.config/television/config.toml` лежат в источнике без изменения содержимого
(`chezmoi add`); плагины и темы из `package.toml` (`full-border`, `catppuccin-frappe`)
в источник не входят: их ставит `ya pkg install` скрипт
`run_onchange_after_ya-pkg-install.sh.tmpl` после правки `package.toml`.

Поставщик yazi — код в `init.lua` после `full-border`, без отдельного плагина:

- Запуск: при выполнении `init.lua` (при запуске yazi) создаётся каталог панели
  (единственный внешний процесс — `mkdir -p`) и пишется запись
  `yazi-<pid>.json` со слоем `mgr`; pid — первое поле `/proc/self/stat`.
- Слой: `ya.sub` слой не сообщает, но любая смена слоя перерисовывает
  интерфейс, а во время перерисовки в Lua доступен `cx.layer`. Поэтому
  поставщик оборачивает `Root:redraw` и по значению `tostring(cx.layer)`
  пишет запись, только если слой изменился (`mgr`, `tasks`, `spot`, `pick`,
  `input`, `confirm`, `cmp`, `help`; слои `which`, `notify`, `app` контекст
  не меняют). Таймеров и опроса нет: проверка идёт по событию перерисовки.
- Выход: Lua выхода yazi не видит (завершение процесса не даёт события),
  поэтому запись снимает просмотрщик по pidfd процесса из записи (D2, D3);
  отдельное сообщение о выходе не отправляется.
- Запись пишется одним `write`, формат — D2; режим в записи — родное имя слоя,
  имя в контексте даёт `[modes] names = { mgr = "manager" }` манифеста.

Запуск yazi из оболочки видно и по записи `exec` (`y`, `yazi`), запуск не из
оболочки — по процессу переднего плана; поставщик нужен для слоя и для
порядка записей стека bash → yazi → nvim.

### D10. Модуль ble.sh

`dot_config/blesh/keys-help.bash`, подключается строкой в `dot_blerc`
(`ble-import -d ~/.config/blesh/keys-help.bash` или `source`), действует
только при `HERDR_PANE_ID` и `XDG_RUNTIME_DIR`:

- `ble/function#advice after` на `ble/decode/keymap/push`,
  `ble/decode/keymap/pop` и `ble/keymap:vi/update-mode-indicator`
  (последний — тот же вызов, по которому `contrib/prompt-vim-mode`
  обновляет индикатор): функция `keys_help/notify` берёт
  `_ble_decode_keymap` и пишет запись `active`, только если keymap
  изменился с прошлой записи (сравнение в переменной, без внешних
  процессов).
- Дамп таблицы: при первой записи каждого keymap в этой оболочке —
  `ble-bind -m <keymap> -P > $XDG_RUNTIME_DIR/herdr-keys-help/ble/$$/<keymap>.bind`;
  функция `keys-help-refresh` сбрасывает дампы после ручного `ble-bind`.
- `blehook PREEXEC`: запись `exec` с `command` — командной строкой;
  `blehook PRECMD`: снова `active` с текущим keymap.
- `ble/function#advice around` на `ble/widget/.EDIT_COMMAND` и
  `ble/widget/.SHELL_COMMAND`: до вызова — запись `widget` с `command`
  (так fzf, atuin и tv, запущенные клавишами M-f, M-r, M-t, распознаются
  по `shell_commands` манифестов), после — `active`.
- `blehook EXIT`: удаление своей записи и каталога дампов.
- Строка ввода, курсор, слова оболочки и кандидаты дополнения при
  открытой панели — файлы `ble-<pid>.line`, `.words`, `.cands` (D17).

Запись делает встроенный `printf` в файл, внешних процессов на смену
режима нет.

### D11. Модуль Neovim

`dot_config/nvim/lua/keys_help.lua`, `require("keys_help").setup()`
из `lua/config/autocmds.lua`, действует только при `vim.env.HERDR_PANE_ID`:

- `VimEnter` и `ModeChanged`: запись `active` с `mode` (первая буква
  `mode()` → `normal`, `insert`, `visual`, `select`, `cmdline`,
  `replace`, `terminal`, `operator`), `server = vim.v.servername`;
  записывается только при смене имени режима.
- `VimLeavePre`: удаление записи.
- `dump(mode)`: JSON-массив записей `nvim_get_keymap(mode)` и
  `nvim_buf_get_keymap(0, mode)` с `desc`; `origin` — по файлу
  `callback` (`debug.getinfo`) или `sid`: каталог конфига → `user`,
  `lazy/LazyVim` → `lazyvim`, `lazy/<плагин>` → имя плагина, иначе
  `nvim`; группа записи равна её происхождению: у which-key нет
  публичного API групп. Клавиши в записи `<C-x>` нормализуются манифестом.

### D12. Конфигурация представления

Файл `~/.config/herdr/keys-help/view.toml` — символическая ссылка
(chezmoi `symlink_view.toml.tmpl`) на `{{ .chezmoi.sourceDir }}/herdr-keys-help/view.toml`;
каталог `herdr-keys-help/` источника исключён в `.chezmoiignore`. Так
правки из просмотрщика сразу попадают в репозиторий, без `re-add`.
Запись — через `toml_edit` (комментарии и порядок сохраняются),
во временный файл в каталоге настоящего файла и `rename` поверх
настоящего пути (ссылка не заменяется).

Поля — ровно решение 6:

| Поле | Тип | Наследование |
|---|---|---|
| `order` | список групп | заменяется более частным уровнем |
| `hide` | список клавиш | объединяется |
| `hide_groups` | список групп | объединяется |
| `pin` | список клавиш | заменяется |
| `only_modifiers` | bool | заменяется |
| `show_origin` | bool или список происхождений | заменяется |
| `[entry."<контекст>"."<клавиша>"]` `desc`, `group` | | частное поверх общего |

Уровни: `[defaults]` → раздел `[view]` манифеста программы (D15) →
`[context."<программа>.*"]` и `[context."<программа>"]`
→ `[context."<программа>.<режим>"]`; среди шаблонов более частный
(больше символов до `*`) применяется позже. Шаблон `x.*` подходит
и к `x`, и к `x.<режим>`; `*.generic` — ко всем контекстам
универсального извлекателя. Ключи `[entry]` принимают те же шаблоны.

Смысл полей при показе: записи из `hide` и групп из `hide_groups`
не показываются; `pin` — первыми, в заданном порядке, отдельным блоком;
затем группы по `order`, остальные группы — по алфавиту; внутри группы —
по клавише. `only_modifiers = true` оставляет записи, первая клавиша
которых содержит `C-` или `M-`. `show_origin = true` — показывать
происхождение у каждой записи; список — подпись только у записей
перечисленных происхождений (остальные записи показываются без подписи);
`false` — без подписей. На состав записей `show_origin` не влияет.
`[entry]` переопределяет `desc` и `group` найденной записи или добавляет
запись с происхождением `user`, если клавиши в таблице нет.

Изменение файла (inotify каталога настоящего файла, `IN_CLOSE_WRITE`,
`IN_MOVED_TO`) перечитывается и перерисовывает таблицу; ошибка разбора
показывается строкой в панели, действует прежняя конфигурация.

### D13. Просмотрщик: вид, навигация и подробности

**Вид.** Шапка — контекст и цель (`ble.vi_nmap · w1:p1`) и строка поиска,
когда он активен. Ниже — таблица ячеек «клавиша → действие» (короткое
описание `desc`, подпись происхождения по `show_origin`), записи идут
по порядку D12 сверху вниз по колонкам; заголовок группы — отдельная
строка колонки перед первой записью группы. Число колонок — сколько
ячеек шириной не меньше `C = 33` символов помещается в ширину панели
`W`, но не больше 5 и не меньше 1: `n = min(5, max(1, ⌊W / 33⌋))`
(решение пользователя на проверке 9.2). Ширина колонки — `W / n`;
клавиша выравнивается по самой длинной клавише колонки, но не шире
половины колонки, описание, не помещающееся в ячейку, режется с `…`.
Под описание остаётся `W / n − 2 −` ширина клавиши колонки: при ширине
колонки 33 и клавишах до 7 символов (`C-right`) — 24 символа, поэтому
короткие описания D7а длиной 25–32 символа на самой узкой ячейке
обрезаются с `…` на 24-м символе, а при более широкой колонке
помещаются целиком. Высота колонки
не больше числа строк таблицы на экране: записи, которые не помещаются
в `n` колонок такой высоты, уходят в следующие колонки, а колонки сдвигаются
по горизонтали вслед за выбором так, чтобы колонка выбора была видна.
Поэтому на низкой панели (треть высоты экрана) первые разделы — курсор,
дополнение, источники — видны сразу, без прокрутки (проверка 12.12).

**Навигация.** Панель создаётся без фокуса; клавиши действуют, когда
пользователь перевёл в неё фокус (`prefix+j` herdr или мышь). Буквы
не пересекаются: навигация — `h j k l g G / n N q K` и Esc, скрытие —
`d D u`.

| Клавиша | Действие |
|---|---|
| `j`/`k` | следующая/предыдущая ячейка в колонке (с переходом на соседнюю колонку на краю) |
| `h`/`l` | ячейка той же строки в колонке левее/правее |
| `g`/`G` | первая/последняя запись |
| `/` | поиск: ввод образца в строке шапки, Enter — применить; таблица заменяется списком совпадений, отсортированным по релевантности (D16), совпавшие части подсвечиваются, выбор — на первое (самое релевантное) |
| `n`/`N` | следующее/предыдущее совпадение в порядке релевантности по кругу |
| Esc | сброс поиска: прежний порядок таблицы (в окне подробностей — закрыть его) |
| `K` (Shift+K) | подробности выбранной записи |
| `d` | скрыть запись: дописать клавишу в `hide` текущего контекста; кандидат раздела «дополнение» не клавиша — строка состояния сообщает, что его скрыть нельзя |
| `D` | скрыть группу: дописать группу в `hide_groups` текущего контекста; только из раздела группы — в разделах закреплённых записей, по позиции курсора, дополнения и по происхождению своего поля скрытия в `view.toml` нет, и строка состояния сообщает «группу скрыть нельзя: <раздел>» |
| `u` | отменить последнее скрытие этой сессии просмотрщика |
| `q` | вернуть фокус верхней панели — цели (`pane.focus`); панель остаётся открытой |

**Подробности (`K`).** Окно поверх таблицы внутри панели просмотрщика
показывает поля записи: клавишу, полное описание `desc_full`, действие
`action` (виджет, функция), источник `source` (манифест, `generic`,
`user`), контекст и `raw` (для ble.sh — строка `ble-bind -P` этой
клавиши, для Neovim — `rhs` и файл определения, для `generic` — фрагмент
`man` или `--help`). Длинный текст прокручивается `j`/`k`; `q` и Esc
закрывают окно, остальные клавиши в нём не действуют.

Фокус на просмотрщике цель не меняет (D3), поэтому скрытие, поиск
и подробности относятся к контексту панели, с которой пришёл
пользователь. При смене таблицы (новый контекст) выбор ставится
на первую запись, поиск сбрасывается.

### D15. Порядок по происхождению

Решение пользователя на живой проверке 9.1: в контексте оболочки сначала
идут клавиши atuin, television и fzf, доступные из оболочки, затем
клавиши ble.sh и readline. Ядро имён программ не знает, поэтому порядок
задаёт манифест: раздел `[view]` манифеста — умолчания представления
программы, уровень между `[defaults]` файла `view.toml` и разделами
`[context."<программа>…"]`. Его поле `origin_order` — список
происхождений:

```toml
# manifests/ble.toml
[view]
origin_order = ["atuin", "tv", "fzf", "user"]
```

Порядок показа: `pin` → раздел «по позиции курсора» (D17) → раздел
«дополнение» (D17) → по разделу на каждое происхождение из `origin_order`
в заданном порядке (заголовок — имя происхождения, записи по клавише) →
остальные записи по группам и `order` (D12). Происхождения, не
перечисленные в `origin_order`, попадают в группы как раньше. Поля
`view.toml` (решение 6) не меняются; переопределять `origin_order`
из `view.toml` нельзя (открытый вопрос).

Отвергнуто: порядок групп в `order` по умолчанию (клавиши atuin, tv и fzf
лежат в группах `history` и `tools` вместе с клавишами ble.sh и
не поднимаются целиком); список происхождений в ядре (имена программ).

### D16. Ранжирование поиска

Совпадение образца `p` (без учёта регистра, кроме ступени 1) с записью
оценивается по лучшей ступени:

| Ступень | Условие | Очки |
|---|---|---|
| 1 | клавиша равна `p` с учётом регистра | 1000 |
| 2 | клавиша равна `p` без учёта регистра | 900 |
| 3 | клавиша начинается с `p` | 800 |
| 4 | слово короткого описания начинается с `p` | 700 − 10 × номер слова |
| 5 | `p` — подстрока клавиши или короткого описания | 500 − позиция / 4 |
| 6 | `p` — подстрока `desc_full` или `action` | 300 |
| 7 | символы `p` идут по порядку в клавише или коротком описании (нечёткое совпадение) | 200 − число пропущенных символов, не ниже 1 |

Записи без совпадения в список поиска не попадают. Сортировка — по очкам
по убыванию, при равенстве — по порядку таблицы без поиска. Подсветка —
совпавшие символы ступени. Ступени и веса — в ядре: они не зависят
от программ.

### D17. Строка ввода оболочки: курсор и дополнение

Решение пользователя на живой проверке 9.1: пока панель открыта
и в оболочке набирается команда, наверх поднимаются команды
редактирования, применимые при текущей позиции курсора, и предлагаются
команды, аргументы и аббревиатуры ble.sh для текущего слова.

**Событие.** ble.sh вызывает `ble/textarea#render` после обработки каждой
порции ввода (каждого нажатия или пачки вставленных символов); в его
состоянии `caret_state` — `_ble_edit_ind` (курсор) и версия текста
`_ble_edit_str`. Модуль ставит `ble/function#advice after` на
`ble/textarea#render`: это событие самого ble.sh, таймера и опроса нет.

**Дёшево и только при открытой панели.** Просмотрщик, выбрав цель,
создаёт в её каталоге собственную файл-отметку `viewer.<pid просмотрщика>`
(пустой файл) и удаляет при смене цели и выходе только её: на одну цель
могут смотреть несколько просмотрщиков (в разных вкладках), и уход одного
не выключает запись для остальных. Обработчик модуля:

1. Есть ли в каталоге хоть одна отметка `viewer.*` — проверка встроенным
   glob без внешних процессов, например
   `local m=("$dir"/viewer.*); [[ -e ${m[0]} ]]` (при `nullglob` —
   `(( ${#m[@]} ))`); нет отметки — выход.
2. Строка и курсор не изменились с прошлой записи (сравнение
   переменных) — выход.
3. `printf '%s
%s' "$_ble_edit_ind" "$_ble_edit_str" > $dir/ble-$$.line`
   — встроенный `printf`, без внешних процессов и без экранирования:
   первая строка — позиция курсора в символах, остальное — текст как есть.

Отдельный файл не трогает запись `ble-<pid>.json`: смена курсора
не вызывает пересчёта контекста и таблицы, только пересчёт двух верхних
разделов (D15).

**Слова оболочки.** В `PRECMD` при отметке модуль пишет
`ble-<pid>.words` (TSV `вид	имя	значение`): аббревиатуры
(`ble-sabbrev`, только если изменился `_ble_complete_sabbrev_version`),
псевдонимы (`compgen -a`) и функции (`compgen -A function` без имён
с `/` и с ведущим `_`). Кандидаты дополнения самого ble.sh (он строит их
при наборе — автодополнение `complete_auto_complete` включено — и по TAB)
модуль получает обёрткой `ble/function#advice after
ble/complete/candidates/generate` (ставится по `blehook complete_load`):
при отметке и `cand_count > 0` — `ble-<pid>.cands` (`COMPV` первой
строкой, затем по строке на `cand_word`). Это тоже событие ble.sh.

**Формат файлов.** Все три файла — UTF-8, перезаписываются целиком
(`printf … >file`); просмотрщик читает их по `IN_CLOSE_WRITE`
и `IN_MOVED_TO`, отсутствие файла — нет данных.

- `ble-<pid>.line`: первая строка — `_ble_edit_ind` (номер символа,
  с нуля), со второй строки до конца файла — `_ble_edit_str` как есть
  (перевод строки после текста не добавляется).
- `ble-<pid>.words`: по строке на слово, поля через табуляцию —
  вид, имя, значение. Виды: `sabbrev` (значение — раскрытие),
  `alias` (значение — подстановка), `function` (значение пустое).
  Табуляция и перевод строки в значении заменяются пробелом. Файл
  содержит все виды каждый раз; аббревиатуры модуль перечитывает только
  при изменении `_ble_complete_sabbrev_version`, а пишет сохранённые.
- `ble-<pid>.cands`: первая строка — `COMPV`, дальше по строке
  на `cand_word` в порядке ble.sh.

Модуль пишет файлы только при хотя бы одной отметке `viewer.*`: при
изменении, а также заново, если файл исчез, пуст или старше самой свежей
отметки; изменение строки или выполнение команды без наблюдения один раз
обнуляет файл встроенным перенаправлением; при выходе оболочки модуль
удаляет файлы вместе с записью. Просмотрщик, сняв свою отметку (смена
цели, выход), удаляет только её, а `.line`, `.words` и `.cands` оставляет:
при возврате фокуса без ввода оболочка о новой отметке не узнаёт,
и разделы строятся по оставленным файлам сразу. Просмотрщик читает файлы
без сравнения со временем отметки, пустой файл — данных нет; устаревшие
данные не показываются, потому что модуль обнуляет файлы при изменениях
без наблюдения. Удаляются файлы только уборкой каталога закрытой панели
(D2); отметки завершившихся просмотрщиков (pid не жив) просмотрщик удаляет,
создавая и снимая свою.

**Переменные позиции.** Просмотрщик вычисляет из `point` и текста
числовые переменные, доступные в `when`: `point`, `len`, `row`, `rows`,
`rows_below` (строк ниже текущей: `rows − 1 − row`; арифметики в `when`
нет), `col` (символов от начала текущей строки до курсора), `line_len`
(длина текущей строки), `word_len` (число непробельных символов слева
от курсора), `word_index` (номер слова: 0 — позиция команды), `blank`
(1, если строка пуста или из пробелов). Само слово слева от курсора
(`word`, непробельные символы) в `when` недоступно: ядро использует его
только как образец раздела «дополнение». Ядро знает только эти
переменные, имён программ в них нет.

**Применимость в манифесте.** Раздел `[[applies]]` манифеста:

```toml
[[applies]]
modes = ["vi_imap", "emacs"]
action = "^(backward-char|backward-cword|beginning-of-line|delete-backward-char|kill-backward-line|vi_imap/kill-backward-word)"
when = "col > 0"

[[applies]]
modes = ["vi_imap", "emacs"]
action = "^(forward-char|forward-cword|end-of-line|delete-forward-char|kill-forward-line)"
when = "col < line_len"

[[applies]]
modes = ["vi_imap", "emacs"]
action = "^(beginning-of-text|history-prev)"
when = "row > 0"
```

`when` — сравнения `<переменная> <оп> <число или переменная>`
(`<`, `<=`, `>`, `>=`, `==`, `!=`), соединённые `&&`; неизвестная
переменная — ошибка манифеста. Запись, подходящая правилу по `action`
(и `modes`), при истинном `when` применима, при ложном — остаётся в группе
и показывается приглушённой.

Раздел «по позиции курсора» — не больше 8 ячеек (решение пользователя
на проверке 12.11): по одной на правило с истинным `when` в порядке
правил манифеста. Из записей правила берётся самая короткая клавиша,
при равенстве — первая по таблице (`C-a`, а не `home`), поэтому одно
действие на разных клавишах и синонимы из разных keymap занимают одну
ячейку. Остальные применимые записи остаются в своих группах
обычными, без приглушения. Частоту команд ядро не знает: её задаёт
порядок правил манифеста — правило на одну команду, от частых к редким
(в `ble.toml`: в начало и в конец строки, символ влево и вправо, слово
влево и вправо, удалить символ слева и справа, вырезать слово назад
и вперёд, вырезать до начала и до конца строки, затем прочие). Поле
приоритета у правила не вводится: порядок правил уже его задаёт. Раздел есть, пока существует
`ble-<pid>.line` активной записи и строка не пуста (`blank = 0`).

**Раздел «дополнение».** При непустом `word` — до 20 ячеек «кандидат →
вид»: аббревиатуры, ключ которых начинается с `word` (значение — их
раскрытие), затем кандидаты ble.sh из `.cands`, если их `COMPV` равен
`word`, затем при `word_index = 0` — псевдонимы, функции и команды
`PATH`, начинающиеся с `word`, при `word_index > 0` — параметры первого
слова (`-x`, `--long` с описанием), извлечённые разбором `--help` и `man`
по правилам D7 и кешем D7. Список команд `PATH` просмотрщик строит сам
по каталогам `PATH` из окружения процесса оболочки: полностью — при смене
набора каталогов, дальше по событиям inotify (`IN_CREATE`, `IN_MOVED_TO`,
`IN_DELETE`, `IN_MOVED_FROM`, `IN_ATTRIB`) по имени из события: команда
добавляется или снимается по наличию исполняемого файла с этим именем
в любом из каталогов `PATH`, без пересканирования каталогов (обновление
пакетов даёт тысячи событий). Описание кандидата — сокращение D7а. Подробности `K`
по кандидату показывают вид, полное значение и источник.

Отвергнуто: `ble-bind -f __after_widget__` (слот keymap, его уже
занимает keymap emacs; обёртка над отрисовкой срабатывает на каждую
порцию ввода во всех keymap); `compgen -c` в оболочке на каждое нажатие
(просмотр каталогов `PATH` задерживает ввод); JSON в файле строки
(экранирование на каждое нажатие).

## Risks / Trade-offs

- [Сокращение описаний `generic` теряет смысл] → полный текст
  в `desc_full` виден по `K`; программа с плохим результатом получает
  манифест с переформулированными описаниями.
- [`--help` неизвестной программы может не завершиться] → запуск без
  терминала, процесс живёт не дольше контекста, сроков нет; результат
  кешируется, повторного запуска при тех же входах нет.
- [Разбор man по эвристике даёт ложные записи] → происхождение `generic`
  видно в таблице, записи скрываются `hide`; программа с плохим
  результатом получает манифест.
- [ble.sh меняет внутренние имена функций] → модуль проверяет наличие
  функций при подключении и пишет предупреждение в `ble/util/print`
  вместо записи контекста; тест модуля на живом ble.sh.
- [Записи упавших процессов] → pidfd сообщает выход, запись удаляется.
- [Файл неизвестных программ видит только запуски при открытом
  просмотрщике] → так решено (пишет просмотрщик); описано в документации.
- [`view.toml` — ссылка в источник chezmoi] → при отсутствии источника
  (другая машина без `chezmoi init`) ссылка висит, просмотрщик работает
  с умолчаниями и показывает строку об ошибке записи.

- [Обёртки над внутренними функциями ble.sh (`ble/textarea#render`,
  `ble/complete/candidates/generate`) меняются с версиями ble.sh] →
  модуль проверяет наличие функций при подключении и без них не пишет
  строку и кандидатов; тест под псевдотерминалом ловит изменение.
- [Запись файла на каждое нажатие] → только при отметке `viewer.*`
  и при изменении строки или курсора, встроенным `printf`.
