## ADDED Requirements

### Requirement: Плагин лежит в источнике chezmoi
Плагин `quiet-lab.keys-help` MUST лежать в каталоге источника `dot_config/herdr/plugins/keys-help` с манифестом `herdr-plugin.toml` (действие `toggle`, панель `viewer`, `[[build]]` с `cargo build --release --locked`) и проектом Rust, собирающим бинарник `target/release/keys-help`.

#### Scenario: Состав каталога
- **WHEN** выполнен `chezmoi apply`
- **THEN** `~/.config/herdr/plugins/keys-help/herdr-plugin.toml` объявляет действие `toggle` и панель `viewer`, рядом лежат `Cargo.toml` и `manifests/`

### Requirement: Сборка и регистрация при apply
`chezmoi apply` после изменения исходников плагина MUST собирать бинарник и регистрировать плагин командой `herdr plugin link`; без изменения исходников сборка MUST NOT запускаться.

#### Scenario: Плагин виден herdr
- **WHEN** выполнен `chezmoi apply` с изменёнными исходниками плагина
- **THEN** бинарник `target/release/keys-help` существует, а `herdr plugin list` показывает `quiet-lab.keys-help` включённым и без `warnings`

#### Scenario: Повторный apply
- **WHEN** `chezmoi apply` выполняется повторно без изменения исходников плагина
- **THEN** сборка не запускается

### Requirement: Без таймеров
Плагин и модули-поставщики MUST работать только по событиям (подписка herdr, inotify, pidfd, сигналы, ввод, хуки программ); таймеров, тактов и опроса по расписанию MUST NOT быть.

#### Scenario: Проверка кода
- **WHEN** исходники плагина и модулей просматриваются на `sleep`, `timeout`, `interval`, `Instant`-циклы и `hl.timer`
- **THEN** вызовов ожидания по времени нет

### Requirement: Клавиша переключения
Конфиг herdr MUST связывать `ctrl+alt+shift+slash` с действием `quiet-lab.keys-help.toggle` (`[[keys.command]]`, `type = "plugin_action"`). Действие MUST открывать панель просмотрщика, если в текущем tab её нет, и MUST закрывать её, если она есть; в одном tab MUST NOT быть больше одной панели просмотрщика.

#### Scenario: Открытие
- **WHEN** в tab без просмотрщика вызывается `herdr plugin action invoke quiet-lab.keys-help.toggle`
- **THEN** `herdr pane list` показывает новую панель с токеном `keys_help`

#### Scenario: Повторное нажатие закрывает
- **WHEN** действие вызывается в tab, где панель просмотрщика открыта, при любой панели tab в фокусе
- **THEN** панель просмотрщика закрыта, остальные панели tab на месте

### Requirement: Размер и место панели просмотрщика
Панель просмотрщика MUST появляться делением панели в фокусе вниз без перевода фокуса и MUST занимать треть высоты разделённой панели (доля верхней части 0.667), но не меньше 5 строк содержимого. При нехватке строк просмотрщик MUST увеличивать свою панель (`pane.resize`) при открытии и по каждому событию изменения размера.

#### Scenario: Треть высоты
- **WHEN** действие вызывается при фокусе на панели высотой 45 строк
- **THEN** новая панель под ней высотой 15 ± 1 строка, фокус у прежней панели

#### Scenario: Низкая панель
- **WHEN** действие вызывается на панели высотой 12 строк
- **THEN** `viewport_rows` панели просмотрщика не меньше 5

#### Scenario: Окно уменьшилось
- **WHEN** после открытия окно терминала уменьшается так, что у просмотрщика меньше 5 строк, а высоты разделённой панели хватает
- **THEN** просмотрщик по событию изменения размера увеличивает свою панель до 5 строк содержимого

### Requirement: Цель просмотрщика следует за фокусом
Целью просмотрщика MUST быть последняя панель в фокусе его workspace, кроме самой панели просмотрщика. Фокус на просмотрщике и фокус в другом workspace MUST NOT менять цель. Шапка MUST показывать контекст и `pane_id` цели.

#### Scenario: Другая панель
- **WHEN** просмотрщик открыт под панелью A, а фокус переходит на панель B того же workspace
- **THEN** шапка показывает `pane_id` панели B и контекст B

#### Scenario: Фокус на самом просмотрщике
- **WHEN** фокус переходит на панель просмотрщика
- **THEN** цель и таблица не меняются

#### Scenario: Другой workspace
- **WHEN** фокус переходит на панель другого workspace
- **THEN** цель не меняется

### Requirement: Контекст и запись таблицы
Контекст MUST быть строкой `<программа>` или `<программа>.<режим>`. Таблица MUST состоять из записей с полями `key`, `desc` (короткое описание), `desc_full` (полный текст источника), `group`, `origin`, `action`, `source`, `raw`; клавиши MUST записываться в виде ble.sh: модификаторы `C-M-S-` в этом порядке, имена `ESC`, `RET`, `TAB`, `SP`, `up`, последовательности через пробел.

#### Scenario: Нормализация
- **WHEN** источник таблицы даёт клавиши `<C-x>`, `ctrl-alt-t` и `<Esc>`
- **THEN** в таблице они записаны как `C-x`, `C-M-t` и `ESC`

### Requirement: Подкоманда печати таблицы
`keys-help table <контекст> --pane <pane_id>` MUST печатать ту же таблицу с учётом конфигурации представления, что показывает просмотрщик для этого контекста.

#### Scenario: Печать
- **WHEN** выполняется `keys-help table ble.vi_nmap --pane <pane_id оболочки>`
- **THEN** вывод совпадает со списком записей просмотрщика в контексте `ble.vi_nmap`

### Requirement: Канал записей поставщиков
Поставщик MUST писать запись — JSON с полями `v`, `program`, `mode`, `pid`, `state` (`active`, `exec`, `widget`) и необязательными `command`, `table`, `server`, `env` — одной записью файла в `$XDG_RUNTIME_DIR/herdr-keys-help/panes/<HERDR_PANE_ID>/<program>-<pid>.json` и MUST удалять свой файл при выходе.

#### Scenario: Запись оболочки
- **WHEN** в панели с ble.sh выводится приглашение
- **THEN** в каталоге панели есть `ble-<pid оболочки>.json` с `"state":"active"`

### Requirement: Выбор активной записи
Просмотрщик MUST ждать изменений каталога записей через inotify и MUST считать активной последнюю изменённую запись живого процесса. Запись процесса, завершившегося без удаления, MUST удаляться по событию выхода процесса (pidfd).

#### Scenario: Вложенные программы
- **WHEN** из оболочки запущен yazi, из yazi — Neovim, затем Neovim завершён
- **THEN** таблица последовательно показывает контекст yazi, Neovim и снова yazi

#### Scenario: Процесс убит
- **WHEN** Neovim завершён сигналом `SIGKILL`
- **THEN** его запись удалена, после `PRECMD` оболочки контекст — оболочка

### Requirement: Поставщик ble.sh — режимы
Модуль `~/.config/blesh/keys-help.bash`, подключённый из `~/.blerc`, при заданных `HERDR_PANE_ID` и `XDG_RUNTIME_DIR` MUST писать запись `program = "ble"`, `state = "active"` с текущим keymap в `mode` при каждой смене keymap и только при смене; на смену keymap MUST NOT запускаться внешние процессы.

#### Scenario: Смена режима vi
- **WHEN** в режиме вставки нажимается Esc, затем `i`
- **THEN** контекст `ble.vi_nmap`, затем `ble.vi_imap`

#### Scenario: Поиск по истории
- **WHEN** в `ble.vi_imap` нажимается C-r, затем поиск закрывается
- **THEN** контекст `ble.isearch`, затем снова `ble.vi_imap`

### Requirement: Поставщик ble.sh — таблица
Для каждого keymap оболочка MUST один раз писать дамп `ble-bind -m <keymap> -P` и указывать его в поле `table` записи. Записи `-x`/`-c` MUST получать происхождение по имени функции (`fzf`, `atuin`, `tv`) или `user`, `vi-rlfunc/…` — `readline`, остальные `-f` — `ble`; служебные `__…__` MUST NOT показываться.

#### Scenario: Пользовательские привязки
- **WHEN** контекст `ble.vi_imap`
- **THEN** таблица содержит M-h, M-f, M-d, M-r, M-up, M-t и C-M-t с происхождением `fzf`, `atuin` или `tv`, а записей `__default__` нет

### Requirement: Поставщик ble.sh — запуск программ
`PREEXEC` MUST писать запись `state = "exec"` с командной строкой в `command`; привязка `-x` или `-c` MUST писать до выполнения запись `state = "widget"` с командой привязки; после неё и в `PRECMD` MUST писаться `state = "active"`.

#### Scenario: Привязка запускает fzf
- **WHEN** нажимается M-f, затем fzf закрывается
- **THEN** пока открыт fzf, контекст `fzf`, после — `ble.vi_imap`

#### Scenario: Команда из строки
- **WHEN** в оболочке выполняется `tv`, затем он закрывается
- **THEN** пока открыт tv, контекст `tv`, после — контекст оболочки

### Requirement: Поставщик Neovim
Модуль `keys_help` конфига Neovim при заданном `HERDR_PANE_ID` MUST писать запись `program = "nvim"` с `mode` (`normal`, `insert`, `visual`, `select`, `cmdline`, `replace`, `terminal`, `operator`) и `server` по `VimEnter` и `ModeChanged` при смене имени режима и MUST удалять её по `VimLeavePre`.

#### Scenario: Режимы Neovim
- **WHEN** в панели запущен `nvim`, нажимаются `i`, Esc, `v`
- **THEN** контекст последовательно `nvim.normal`, `nvim.insert`, `nvim.normal`, `nvim.visual`

### Requirement: Таблица Neovim
Функция `dump(mode)` модуля `keys_help` MUST возвращать JSON-массив глобальных и буферных привязок режима с `desc`, происхождением (`user`, `lazyvim`, имя плагина, `nvim`) и группой.

#### Scenario: Привязки LazyVim
- **WHEN** контекст `nvim.normal`
- **THEN** таблица содержит `SP f f` (привязка `<leader>ff` при лидере-пробеле: Neovim отдаёт `lhs` с подставленным пробелом, а клавиша записывается в виде ble.sh) с описанием из `desc`

### Requirement: Манифест программы
Распознавание программы и режима и источник таблицы MUST задаваться одним TOML-файлом в `manifests/` плагина с разделами `[detect]`, `[modes]`, `[[source]]` (виды `regex`, `toml`, `json`, `static`), `[key]`, `[[describe]]`, `[[group]]`, `[[origin]]`. Добавление программы MUST требовать только манифеста; код ядра MUST NOT содержать имён программ.

#### Scenario: Новая программа одним манифестом
- **WHEN** в `manifests/` добавлен манифест с `process = ["kh-fake"]` и источником `static`, а в панели запущен `kh-fake`
- **THEN** просмотрщик показывает контекст и таблицу этого манифеста без пересборки плагина

#### Scenario: Ошибочный манифест
- **WHEN** в `manifests/` лежит манифест с синтаксической ошибкой
- **THEN** он пропущен с сообщением в журнале плагина, остальные манифесты действуют

### Requirement: Таблицы из живой конфигурации
Манифесты первой очереди MUST покрывать ble.sh, fzf, atuin, television, yazi и Neovim и MUST строить таблицы из живой конфигурации программ; статическая таблица допускается только там, где конфигурации клавиш нет. Таблица fzf, atuin и television внутри открытой программы MUST строиться один раз при входе в контекст.

#### Scenario: fzf с FZF_DEFAULT_OPTS
- **WHEN** fzf запущен с `FZF_DEFAULT_OPTS='--bind ctrl-y:accept'`
- **THEN** таблица `fzf` содержит `C-y` с действием `accept` поверх клавиш по умолчанию из `man fzf`

#### Scenario: television
- **WHEN** открыт tv
- **THEN** таблица `tv` совпадает с разделом `[keybindings]` файла `~/.config/television/config.toml`

#### Scenario: atuin
- **WHEN** открыт поиск atuin, `keymap_mode` не задан
- **THEN** контекст `atuin.search`, таблица — клавиши режима emacs

#### Scenario: yazi
- **WHEN** запущен yazi, а `~/.config/yazi/keymap.toml` нет
- **THEN** контекст `yazi.manager`, таблица — умолчания yazi 26.9.1 слоя `mgr` с их `desc`

### Requirement: Универсальный извлекатель
Для команды без своего манифеста MUST применяться манифест `generic.toml`: разделы о клавишах в `man` (KEY BINDINGS, KEYS, COMMANDS, INTERACTIVE и подобные), затем `--help`, затем известные файлы конфигурации клавиш. Первый непустой результат MUST показываться в контексте `<команда>.generic` с происхождением `generic`.

#### Scenario: Раздел клавиш в man
- **WHEN** запущена программа без манифеста, man-страница которой содержит раздел `KEY BINDINGS` (фикстура)
- **THEN** контекст `<команда>.generic`, таблица — записи раздела с происхождением `generic`

### Requirement: Порядок извлечения
Для одной программы порядок MUST быть: манифест программы → универсальный извлекатель → запись в файл неизвестных программ.

#### Scenario: Манифест важнее извлекателя
- **WHEN** запущен fzf, у которого есть манифест и man-страница
- **THEN** контекст `fzf`, а не `fzf.generic`

### Requirement: Команды извлечения без сроков и с кешем
Команды источников MUST запускаться без терминала, со stdin `/dev/null`, и MUST завершаться при смене контекста, ради которого запущены; сроков ожидания MUST NOT быть. Результат универсального извлекателя MUST кешироваться по входам (путь, `mtime` и размер исполняемого файла, `mtime` man-страницы) и MUST NOT извлекаться заново при тех же входах.

#### Scenario: Повторный запуск программы
- **WHEN** программа без манифеста запускается второй раз без изменения её файлов
- **THEN** `man` и `--help` не запускаются, таблица берётся из кеша

#### Scenario: Зависшая команда
- **WHEN** `--help` программы не завершается, а пользователь переходит на другую панель
- **THEN** процесс извлечения завершён

### Requirement: Файл неизвестных программ
Если для команды нет ни манифеста, ни таблицы универсального извлекателя, просмотрщик MUST записывать в `$XDG_STATE_HOME/herdr-keys-help/unknown-programs.toml` таблицу `[program."<команда>"]` с `count` (число новых процессов команды на переднем плане цели) и `last` (`ГГГГ-ММ-ДД`), одну на команду, и MUST показывать строку «клавиши <команда> не найдены». Команда, получившая таблицу, MUST удаляться из файла при следующем появлении.

#### Scenario: Неизвестная программа
- **WHEN** дважды запускается программа без манифеста, man-страницы и `--help` (фикстура `kh-unknown`)
- **THEN** в файле одна таблица `[program.kh-unknown]` с `count = 2` и сегодняшней датой `last`

### Requirement: Хук разбора неизвестных программ
Хук Claude Code `SessionStart` проекта dotfiles MUST печатать список неизвестных программ (команда, счётчик, дата, по убыванию счётчика), а при пустом или отсутствующем файле MUST NOT печатать ничего.

#### Scenario: Старт сессии
- **WHEN** в проекте dotfiles стартует сессия Claude Code, а в файле есть `kh-unknown`
- **THEN** вывод хука содержит строку с `kh-unknown`, счётчиком и датой

#### Scenario: Пустой файл
- **WHEN** файла неизвестных программ нет
- **THEN** хук ничего не печатает и завершается с кодом 0

### Requirement: Поля и наследование конфигурации представления
Файл `~/.config/herdr/keys-help/view.toml` MUST принимать `[defaults]` и `[context."<шаблон>"]` с полями `order`, `hide`, `hide_groups`, `pin`, `only_modifiers`, `show_origin` и `[entry."<контекст>"."<клавиша>"]` с `desc` и `group`. Уровни MUST применяться «умолчания → программа → режим»; шаблон `x.*` MUST подходить к `x` и `x.<режим>`; `hide` и `hide_groups` MUST объединяться, прочие поля MUST заменяться более частным уровнем.

#### Scenario: Шаблон программы
- **WHEN** `[context."yazi.*"]` задаёт `hide_groups = ["tabs"]`, а `[context."yazi.input"]` — `hide = ["C-a"]`
- **THEN** в `yazi.input` нет ни группы `tabs`, ни `C-a`, в `yazi.manager` нет только группы `tabs`

#### Scenario: Контексты извлекателя
- **WHEN** `[context."*.generic"]` задаёт `only_modifiers = true`
- **THEN** в контексте `htop.generic` показываются только записи с `C-` или `M-`

### Requirement: Показ по конфигурации представления
Записи из `hide` и групп из `hide_groups` MUST NOT показываться; записи `pin` MUST идти первыми в заданном порядке; группы MUST идти по `order`, остальные — по алфавиту; `only_modifiers = true` MUST оставлять записи, первая клавиша которых содержит `C-` или `M-`; `show_origin = true` MUST подписывать происхождение у всех записей, список — только у записей этих происхождений. `[entry]` MUST переопределять описание и группу или добавлять запись с происхождением `user`.

#### Scenario: Пример решения 6
- **WHEN** `view.toml` содержит пример из решения 6, контекст `ble.vi_nmap`
- **THEN** записей `h`, `j`, `k`, `l`, `w`, `b`, `e`, `0`, `$` и группы `motion` нет, первыми идут `C-r`, `M-r`, `M-h`, затем группы `history`, `completion`, `edit`

#### Scenario: Добавленная запись
- **WHEN** задано `[entry."ble.vi_imap"."C-x C-k"] desc = "проверка", group = "edit"`
- **THEN** в `ble.vi_imap` в группе `edit` есть запись `C-x C-k` «проверка» с происхождением `user`

### Requirement: Перечитывание конфигурации
Изменение `view.toml` MUST применяться без перезапуска просмотрщика; ошибка разбора MUST показываться строкой в панели, и MUST действовать прежняя конфигурация.

#### Scenario: Правка на лету
- **WHEN** в `view.toml` дописывается клавиша в `hide` текущего контекста
- **THEN** просмотрщик перестаёт показывать запись без перезапуска

#### Scenario: Ошибка разбора
- **WHEN** в `view.toml` вносится синтаксическая ошибка
- **THEN** панель показывает строку об ошибке, таблица по прежней конфигурации

### Requirement: Таблица в 3–5 колонок
Просмотрщик MUST выводить записи ячейками «клавиша → короткое описание» в колонках, число которых зависит от ширины панели `W` при наименьшей ширине ячейки 28 символов: 5 при `W ≥ 140`, 4 при `112 ≤ W < 140`, иначе 3. Описание, не помещающееся в ячейку, MUST обрезаться с `…`; число колонок MUST пересчитываться по событию изменения размера.

#### Scenario: Ширина 140
- **WHEN** ширина панели просмотрщика 140 символов
- **THEN** таблица в 5 колонок

#### Scenario: Ширина 120
- **WHEN** ширина панели 120 символов
- **THEN** таблица в 4 колонки

#### Scenario: Ширина 90
- **WHEN** ширина панели 90 символов
- **THEN** таблица в 3 колонки

### Requirement: Короткие описания
В ячейке MUST показываться короткое описание `desc` — что делает действие, в нескольких словах, без имён виджетов и функций; полный текст источника MUST сохраняться в `desc_full`. Короткие описания записей манифестов первой очереди MUST задаваться в манифестах (`[[describe]]`).

#### Scenario: Манифест ble.sh без имён виджетов
- **WHEN** контекст `ble.vi_imap`
- **THEN** у записи `C-r` короткое описание из манифеста, а не имя виджета `history-isearch-backward`; имя виджета — в поле `action`

### Requirement: Правило сокращения описаний
Для записей `generic` и записей без короткого описания ядро MUST сокращать полный текст: первое предложение, без скобочных пояснений и начальных служебных слов, без точки в конце, не длиннее 32 символов с обрезкой по границе слова и `…`.

#### Scenario: Сокращение generic
- **WHEN** разбор man даёт для клавиши `q` текст «This will quit the program immediately. Unsaved changes are lost.»
- **THEN** `desc` записи — «quit the program immediately», `desc_full` — исходный текст целиком

#### Scenario: Длинный текст
- **WHEN** первое предложение длиннее 32 символов
- **THEN** `desc` не длиннее 32 символов и оканчивается на `…` после целого слова

### Requirement: Навигация в стиле vi
При фокусе в панели просмотрщика `j`/`k` MUST переводить выбор на следующую/предыдущую ячейку колонки, `h`/`l` — на ячейку той же строки в соседней колонке, `g`/`G` — на первую/последнюю запись; `q` MUST возвращать фокус панели-цели, оставляя просмотрщик открытым. Клавиши навигации (`h j k l g G / n N q K`, Esc) и скрытия (`d D u`) MUST NOT пересекаться.

#### Scenario: Переход по колонкам
- **WHEN** выбрана первая запись второй колонки и нажата `h`
- **THEN** выбрана первая запись первой колонки

#### Scenario: Конец таблицы
- **WHEN** нажата `G`, затем `g`
- **THEN** выбрана последняя запись, затем первая

#### Scenario: Возврат фокуса
- **WHEN** фокус в просмотрщике и нажата `q`
- **THEN** `herdr pane list` показывает фокус на панели-цели, панель просмотрщика открыта

### Requirement: Поиск в таблице
`/` MUST открывать ввод образца в шапке; после Enter совпадения образца с клавишей или коротким описанием без учёта регистра MUST подсвечиваться, а выбор MUST переходить на первое совпадение; `n`/`N` MUST переходить к следующему/предыдущему совпадению по кругу; Esc MUST сбрасывать поиск и подсветку. Смена контекста MUST сбрасывать поиск.

#### Scenario: Поиск по описанию
- **WHEN** в `ble.vi_imap` вводится `/истор` и Enter
- **THEN** подсвечены записи, в коротком описании которых есть «истор», выбрана первая из них

#### Scenario: Переход и сброс
- **WHEN** после поиска нажаты `n`, `N`, затем Esc
- **THEN** выбор переходит на второе совпадение и обратно, затем подсветка снята

### Requirement: Подробности записи
`K` (Shift+K) MUST открывать в панели просмотрщика окно подробностей выбранной записи: клавиша, `desc_full`, `action`, `source` (манифест, `generic`, `user`), контекст и `raw` — для ble.sh строка `ble-bind -P` этой клавиши, для Neovim `rhs` и файл определения, для `generic` фрагмент `man` или `--help`. `q` и Esc MUST закрывать окно подробностей, не меняя фокус.

#### Scenario: Подробности ble.sh
- **WHEN** в `ble.vi_imap` выбрана `M-f` и нажата `K`
- **THEN** окно показывает `fzf-file-widget`, источник `manifest:ble.toml` и строку `ble-bind -m 'vi_imap' -x M-f fzf-file-widget`

#### Scenario: Подробности Neovim
- **WHEN** в `nvim.normal` выбрана привязка из конфига и нажата `K`
- **THEN** окно показывает `rhs` или описание обратного вызова и файл определения

#### Scenario: Закрытие
- **WHEN** окно подробностей открыто и нажата Esc
- **THEN** окно закрыто, видна таблица, фокус в просмотрщике

### Requirement: Скрытие записей из просмотрщика
В режиме навигации `d` MUST дописывать клавишу выбранной записи в `hide`, `D` — её группу в `hide_groups` раздела `[context."<контекст>"]` текущего контекста, создавая раздел при отсутствии; `u` MUST отменять последнее скрытие сессии просмотрщика.

#### Scenario: Скрыть запись
- **WHEN** в `ble.vi_nmap` выбрана запись `x` и нажата `d`
- **THEN** `hide` раздела `[context."ble.vi_nmap"]` содержит `"x"`, запись не показывается

#### Scenario: Скрыть группу
- **WHEN** выбрана запись группы `completion` и нажата `D`
- **THEN** `hide_groups` текущего контекста содержит `"completion"`, записи группы не показываются

#### Scenario: Отмена
- **WHEN** после `d` нажата `u`
- **THEN** клавиша убрана из `hide`, запись снова показывается

### Requirement: Запись конфигурации сохраняет файл
Запись `view.toml` из просмотрщика MUST сохранять комментарии и порядок существующих строк и MUST заменять файл целиком через временный файл и `rename` в каталоге настоящего файла; символическая ссылка MUST оставаться ссылкой.

#### Scenario: Комментарии и ссылка
- **WHEN** `view.toml` — символическая ссылка на файл с комментариями, и нажата `d`
- **THEN** комментарии на месте, путь в `$HOME` по-прежнему символическая ссылка, изменён файл, на который она указывает

### Requirement: Рамки панелей herdr
Конфиг herdr MUST задавать в `[ui]` `pane_outer_borders = false` и `pane_gaps = false`; `pane_borders` MUST оставаться `auto`.

#### Scenario: Конфиг перечитан
- **WHEN** выполнены `chezmoi apply` и `herdr server reload-config`
- **THEN** перезагрузка без диагностик, у панелей нет внешних рамок и промежутков, между панелями — разделители
