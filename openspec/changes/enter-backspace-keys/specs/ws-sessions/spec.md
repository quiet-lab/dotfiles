## MODIFIED Requirements

### Requirement: Дополнительные приложения сессии
Окно, принятое в workspace по событию (спецификация ws-daemon, «Посторонние окна») или по команде сохранения сессии, а также окно, перетащенное в workspace цепочкой приложения с признаком перетаскивания (спецификация ws-daemon, «Цепочка приложения»), MUST становиться дополнительным приложением сессии этого workspace, если приложения с таким местом в workspace ещё нет. Запись MUST жить только в сессии: файл конфига демон MUST NOT изменять. Если окно подходит приложению конфига, дополнительным приложением MUST становиться само это приложение с прямоугольником окна — и только тогда, когда в этом workspace его ещё нет. Если подходящего приложения нет, демон MUST завести дополнительное приложение сессии с именем, построенным из класса окна и не совпадающим ни с одним именем приложения конфига или другого дополнительного приложения, и записать у него класс окна, командную строку и каталог процесса окна (по правилу требования «Файлы сессий») и его прямоугольник. Если приложение окна известно только записи сессии другого workspace, в этом workspace MUST заводиться полная запись под тем же именем — с классом, командной строкой, каталогом и прямоугольником: запись только о месте без приложения в файле конфига не выживает. Окно MUST получить тег экземпляра этого приложения и тег состава этого workspace (спецификация ws-daemon, «Состав workspace»). Имя дополнительного приложения MUST быть единственным в сессии: одно имя MUST называть одну программу, и окно другой программы MUST NOT приписываться чужой записи, даже если класс окна тот же (спецификация ws-daemon, «Посторонние окна»). Окно без класса и окно, для процесса которого не найден исполняемый файл, дополнительным приложением MUST NOT становиться: первое не отличить от служебного окна приложения, второе нечем запустить заново.

По цепочке `save_session` или команде `workspaced save-session` демон MUST записать снимок сессии целиком. Команда MUST пройти по всем столам, на которых активен workspace, и принять в него окна без тега по тем же правилам, что действуют при появлении окна; местом принятого окна MUST становиться прямоугольник, который окно занимает сейчас, — окно, уже поставленное пользователем куда нужно, команда MUST NOT двигать. Затем команда MUST снять раскладку каждого такого workspace с экрана (спецификация ws-daemon, «Расстановка окон») и записать снимок вместе с раскладками (требование «Файлы сессий»): сдвинутое окно — дополнительного приложения или приложения конфига — даёт изменённый прямоугольник места своего приложения, у приложения с несколькими окнами — по первому экземпляру. Прямоугольник записи дополнительного приложения — место, с которым приложение принято, — команда MUST NOT менять. Общее окно, которое стоит не на столе этого workspace (ушло за пользователем к другому своему workspace), раскладку этого workspace MUST NOT менять: его нынешнее положение описывает место в другом workspace. Места приложений в файле конфига команда MUST NOT менять. В снимок MUST попадать записи дополнительных приложений, у которых в workspace есть окна, и записи из прежнего снимка, ещё ждущие окна. Команда MUST записать в журнал строку с числом workspace, числом их окон и числом принятых окон. Файл конфига команда MUST NOT изменять.

Дополнительное приложение сессии демон MUST во всём остальном вести как приложение workspace: его окна MUST переноситься вместе с workspace на другой стол, MUST парковаться при вытеснении workspace и возвращаться с ним, MUST вставать на своё место в раскладке, когда приходит на стол workspace и MUST входить в состав окон workspace для панели. Если в конфиге появляется приложение с именем дополнительного приложения сессии, MUST действовать запись конфига, а дополнительное приложение MUST быть снято с записью предупреждения в журнал. Запись, которая называет приложение конфига и задаёт ему только место, MUST быть снята, когда приложения с таким именем в конфиге не стало; запись workspace, которого в конфиге не стало, MUST быть снята так же. Запись MUST жить, пока в её workspace есть окно приложения: окно, открытое по ходу работы, входит в workspace, пока открыто, а в файл конфига без команды записи workspace не попадает. Когда из workspace уходит последнее окно приложения — окно закрыто или убрано командой отделения окна (спецификация ws-daemon, «Отделение окна»), — запись MUST сниматься в этом workspace вместе с местом в раскладке. Окнами приложения при этом MUST считаться его окна, входящие в workspace по тегу состава, в том числе скрытые, и окна его вариантов, которых workspace отдельно не описывает. Если других окон у приложения при этом нет нигде, запись с командной строкой MUST сниматься во всех workspace, где она есть; если окна приложения остаются в других workspace, их записи MUST оставаться. Без окон MUST жить только запись, взятая из снимка сессии при старте или загрузке (требования «Восстановление при старте», «Загрузка сессии»), пока в её workspace не появилось окно приложения: закрытие окон других приложений её MUST NOT снимать, а команды сохранения MUST переносить её в новый снимок как есть. С появлением окна такая запись MUST подчиняться общему правилу, а закрытие последнего окна её приложения во всех workspace MUST снимать и её. Запись сессии, как и приложение раздела файла конфига, MUST получать при поднятии workspace общее окно своего приложения из других workspace: общее окно остаётся общим независимо от того, как оно запущено. Окон варианта по семейству запись сессии MUST NOT получать (спецификация ws-daemon, «Захват открытых окон приложения»). Перечитывание конфига MUST сохранять дополнительные приложения сессии, кроме снятых по этим правилам.

#### Scenario: Окно из лаунчера становится частью workspace
- **WHEN** на столе 1 активен `work` и из лаунчера открыт калькулятор, не описанный в конфиге
- **THEN** `config.toml` не изменился, `chezmoi status` пуст, окно калькулятора несёт тег `app:<имя>#1`, плитка стола 1 показывает его значок, а поднятие `work` на столе 3 переносит калькулятор туда вместе с окнами `work`

#### Scenario: Окно подходит приложению конфига
- **WHEN** на столе 2 активен `surf`, в котором описаны `chrome` и `yandex-browser`, и открыто окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai`
- **THEN** окно получает тег `app:chrome-ai#1`, дополнительным приложением `surf` становится `chrome-ai` с прямоугольником окна, нового приложения с именем по классу окна не появляется, `config.toml` не изменился

#### Scenario: Команда сохранения проходит по всем столам
- **WHEN** на столе 1 активен `work`, на столе 2 активен `surf`, на столе 2 открыто окно, появившееся до поднятия `surf` и потому оставшееся свободным, и нажата цепочка `save_session`
- **THEN** окно входит в `surf` дополнительным приложением с нынешним прямоугольником, снимок записан, в журнале строка с числом workspace, их окон и принятых окон

#### Scenario: Места дополнительных приложений обновляются
- **WHEN** принятое окно калькулятора передвинуто пользователем и нажата цепочка `save_session`
- **THEN** в снимке у `work` записан изменённый прямоугольник места калькулятора — его новое положение, а запись дополнительного приложения хранит прежний прямоугольник, с которым калькулятор принят; после перезагрузки калькулятор встаёт в новое положение, а Ctrl+Super+Пробел возвращает его на место приёма

#### Scenario: Посторонних окон нет
- **WHEN** на столах все окна уже входят в свои workspace и нажата цепочка `save_session`
- **THEN** снимок всё равно записан, в журнале демона строка с числом workspace, их окон и нулём принятых окон

#### Scenario: Места описанных приложений не трогаются
- **WHEN** в `work` пользователь сдвинул окно Chromium из ячейки `left` и нажал цепочку `save_session`
- **THEN** `config.toml` не изменился; в снимке исходное место `chromium` — ячейка `left`, изменённый прямоугольник — нынешнее положение окна, главное приложение прежнее; следующее поднятие `work` оставляет Chromium там, куда его сдвинули, а Ctrl+Super+Пробел возвращает в `left`

#### Scenario: Приложение появилось в конфиге
- **WHEN** дополнительное приложение сессии `galculator` живёт в `work`, и пользователь дописал в конфиг `[apps.galculator]`
- **THEN** после перечитывания конфига действует описание из файла, дополнительное приложение снято, в журнале демона предупреждение об этом

#### Scenario: Окна без класса не становятся приложением
- **WHEN** на столе 1 активен `work`, на столе 2 — `surf`, в Chromium и в Яндекс.Браузере открыты диспетчеры задач, окна которых пришли с пустым классом, и нажата цепочка `save_session`
- **THEN** оба окна остаются свободными, ни в `work`, ни в `surf` нет дополнительного приложения `app`, в снимке они записаны свободными окнами со своими командами, и поднятие `surf` запускать нечего

#### Scenario: Перетаскивание заводит запись о месте
- **WHEN** окно `chrome-ai` из `surf` перетащено в `work` командой `workspaced app chrome-ai --pull`
- **THEN** у `work` появляется дополнительное приложение сессии `chrome-ai` — запись только о месте с прямоугольником окна, `config.toml` не изменился, а после `save_session` запись есть в `default.toml`

#### Scenario: Место общего окна при сохранении сессии
- **WHEN** окно `chrome-ai` входит в `work` (стол 1, запись о месте) и `surf` (стол 2), пользователь на столе 2, окно стоит там, и нажата цепочка `save_session`
- **THEN** запись `chrome-ai` у `work` и место `chrome-ai` в раскладке `work` сохраняют прежние прямоугольники, а не получают положение окна на столе 2

#### Scenario: Отделение общего окна снимает запись только в своём workspace
- **WHEN** дополнительное приложение сессии `alacritty` принято в `work`, его единственное окно перетащено в `dev-front` (там заведена полная запись под тем же именем), и в `work` нажато Shift+Super+Delete
- **THEN** запись `alacritty` у `work` снята, у `dev-front` осталась, окно не закрыто и входит в `dev-front`

#### Scenario: Закрытое окно уходит из workspace
- **WHEN** на столе 1 активен `work`, из лаунчера открыт калькулятор, не описанный в конфиге, и окно калькулятора закрыто
- **THEN** дополнительного приложения калькулятора у `work` больше нет, в журнале демона строка о снятой записи, следующая запись снимка его не содержит, а поднятие `work` калькулятор не запускает

#### Scenario: Запись закрытого окна не забирает окно варианта
- **WHEN** в `surf` по ходу работы открыт терминал wezterm, окно закрыто, а herdr (вариант семейства `wezterm`) работает в `work`, и `surf` поднят заново
- **THEN** записи `wezterm` у `surf` нет, окно herdr не получает тега `ws:surf` и остаётся только в `work`

#### Scenario: Окно закрыто в одном из двух workspace
- **WHEN** дополнительное приложение сессии `alacritty` записано в `work` и `dev-front`, у него два окна — одно в `work`, другое в `dev-front`, — и окно в `work` закрыто
- **THEN** запись `alacritty` у `work` снята, у `dev-front` осталась

#### Scenario: Запись из снимка ждёт окна
- **WHEN** после перезагрузки у `surf`, ждущего ленивого поднятия на столе 2, в снимке запись Telegram, на столе 1 закрыто окно Chromium, и нажата цепочка `save_session`
- **THEN** запись Telegram у `surf` остаётся и записана в новый снимок; при переходе на стол 2 Telegram запускается
