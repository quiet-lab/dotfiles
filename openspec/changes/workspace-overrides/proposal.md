## Why

Клавиша приложения и поведение окна по клавише задаются сейчас на двух уровнях:
у приложения (`[apps.<имя>].chain`) и у workspace (`mode` действует на все его
приложения). Workspace может переопределить для приложения только место —
ячейку шаблона или `rect`. Замысел модели окон
([`docs/window-model.md`](../../../docs/window-model.md), раздел 2.1) требует,
чтобы в workspace переопределялись для приложения ещё клавиша и режим: «на
одном workspace все окна Chromium отзываются на общую клавишу семейства, на
другом у каждого профиля своя клавиша». Без переопределения клавиши
не наступает и случай «в» таблицы клавиши приложения (раздел 2.5): собственная
клавиша приложения, нажатая в workspace, который его не описывает,
перетаскивает туда окно, только если workspace, где приложение живёт, назначил
ему другую клавишу. Шаг 4 (`shared-windows`) ввёл перетаскивание как операцию
(`workspaced app <имя> --pull`) и отдельной клавиши для него не заводил:
её роль с этого шага берёт собственная клавиша приложения (решение D8
изменения `shared-windows`).

Есть и второе основание. Приложение, принятое в workspace режима обмена
ячеек записью сессии (калькулятор из лаунчера, перетащенное окно `chrome-ai`),
ячейки не имеет, а клавиша всё равно меняет его с главной ячейкой: главное
приложение уходит на место калькулятора. Это отмечено в рисках шага 4, и
исправить это можно только режимом на уровне приложения.

Это шаг 5 серии изменений модели окон (`docs/window-model.md`, раздел 5).
После шага на одном workspace профили браузера отзываются на общую клавишу
семейства, на другом — каждый на свою, а собственная клавиша приложения
перетаскивает его окно в текущий workspace.

## What Changes

- **Запись приложения в workspace становится таблицей.** Кроме прежних форм
  (имя ячейки строкой и `{ rect = … }`) допустима таблица
  `{ cell = "<ячейка>" | rect = { … }, chain = "<цепочка>", mode = "swap" | "stack" }`:
  место (ровно одно из `cell` и `rect`), клавиша приложения в этом workspace
  и режим клавиши для этого приложения. Поля `chain` и `mode` необязательны.
- **Клавиша приложения в workspace.** Ключ приложения в workspace — `chain`
  его записи там, а без него — собственный `chain` приложения. Проверка
  «две записи с одной клавишей в одном workspace» идёт по этим ключам.
  Все приложения, отзывающиеся на одну цепочку (собственной клавишей или
  переопределением), дают одну привязку `workspaced key '<цепочка>'`, а какое
  приложение и в каком workspace она вызывает, демон решает при нажатии
  по активному workspace текущего стола.
- **Таблица клавиши приложения выполняется целиком.** Нажатая клавиша `K`:
  активный workspace откликается на `K` — цикл в нём; `K` — собственная
  клавиша приложения, описанного в активном workspace, — цикл в нём;
  запущенный workspace откликается на `K` — поднять его (случай «б» и клавиша
  `K'` переопределения); приложение с собственной клавишей `K` есть только
  в запущенных workspace, переопределивших её, — перетащить его окна
  в активный workspace (случай «в»); иначе открыть приложение в активном
  workspace (случай «а»). Команда `workspaced app <имя>` действует как
  собственная клавиша приложения.
- **Приложение, описанное через семейство.** Приложение считается описанным
  в workspace, если там есть запись его или его семейства; собственная
  клавиша варианта в workspace, описывающем только семейство, ведёт цикл
  по окнам варианта, а не поднимает другой workspace.
- **Режим на уровне приложения.** Цикл клавиши идёт в режиме приложения
  в этом workspace: `mode` его записи, а без него — режим workspace, за одним
  исключением: приложение без ячейки (место задано `rect`, в том числе
  записью сессии) в workspace режима `swap` выбирается в режиме `stack`.
  Память о геометрии окон (ячейка или запомненный прямоугольник) по-прежнему
  определяется режимом workspace.
- **Запись workspace в конфиг сохраняет переопределения.** Команда
  `save-workspace` правит записи раздела на месте: меняет только место,
  сохраняет `chain`, `mode`, порядок записей и комментарии, новые записи
  добавляет в конец.
- **Конфиг сессии.** У браузеров `surf` собственные клавиши переходят на
  Shift+Super+B/V/Y, а `surf` переопределяет их на прежние Super+B/V/Y. В
  `surf` клавиши работают как раньше, в другом месте Super+B/V/Y поднимают
  `surf`, а Shift+Super+B/V/Y перетаскивают окно браузера в активный workspace
  текущего стола.

## Что не входит

- Положение по умолчанию у workspace для неописанных окон (уровень 3
  раздела 2.1 документа): его имя и форма в обсуждении не выбирались, и
  таблица шагов раздела 5 к шагу 5 его не относит.
- Память о геометрии по режиму приложения: в режиме `stack` приложения внутри
  workspace режима `swap` окно при поднятии по-прежнему встаёт в ячейку или
  на место из конфига, а не в запомненный прямоугольник.
- Показ общего окна в плитках обоих столов (шаг 6).
- Состав workspace и переопределения в снимке сессии (шаг 7). Записи
  дополнительных приложений сессии переопределений не несут.
- Семейство Chrome в конфиге сессии не заводится (решение D11 изменения
  `app-families` остаётся в силе): ни один workspace сессии не описывает все
  окна Chrome одной записью, и общая клавиша семейства проверяется на
  временном конфиге.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-config`: «Файл конфига и его разделы» (таблица записи приложения
  в workspace, `chain` и `mode` в ней), «Цепочки клавиш и привязки» (ключ
  приложения в workspace, проверка по нему, привязка `workspaced key`),
  «Запись по команде сохранения» (переопределения, порядок и комментарии
  записей сохраняются).
- `ws-daemon`: «Цепочка приложения» (выбор приложения и workspace по нажатой
  цепочке, случай «в» от собственной клавиши, описание через семейство, режим
  приложения).
- `hyprland-binds`: «Раскладка клавиш сессии» (Super+B/V/Y — клавиши `surf`,
  Shift+Super+B/V/Y — собственные клавиши браузеров).

## Impact

- Демон `~/work/pets/workspaced`: `config.rs` (запись приложения
  в workspace, проверки, режим и ключ приложения в workspace), `keys.rs`
  (сбор привязок по ключам, проверка внутри workspace, команда `key`),
  `main.rs` и разбор запроса в `daemon.rs` (подкоманда `key`), `daemon.rs`
  (выбор пути `key_route`, `app_route`, режим цикла по приложению), `state.rs`
  (назначения ячеек из новой записи), `save.rs` (правка записей на месте).
- Конфиг `dot_config/workspaced/config.toml`: клавиши браузеров и записи
  раздела `surf`.
- Документация: `AGENTS.md`, `docs/window-model.md` (разделы 2.1, 2.5, 3, 5),
  `docs/host-state.md` (упоминание Super+B/V/Y), комментарий о Super+Shift+V
  в `dot_config/hypr/hyprland.lua`.
- Панель Quickshell не меняется.

## Порядок архивации

Изменение опирается на текст требований, изменённых шагом 4
(`openspec/changes/shared-windows/`), который ещё не заархивирован: дельты
«Цепочки клавиш и привязки», «Запись по команде сохранения» и «Цепочка
приложения» взяты из его дельт. Архивировать строго после `shared-windows`;
если текст этих требований в `shared-windows` изменится до архивации, дельты
этого изменения нужно сверить заново.
