## MODIFIED Requirements

### Requirement: Цепочка приложения
По клавише приложения — команде `workspaced key <цепочка>`, которую вызывает привязка (спецификация ws-config, «Цепочки клавиш и привязки»), — демон MUST выбрать приложение и workspace и вести цикл по экземплярам этого приложения. Приложение MUST считаться описанным в workspace, если в разделе workspace эффективного конфига есть запись самого приложения или его семейства. Ключ приложения в workspace и отклик workspace на цепочку MUST определяться по спецификации ws-config: ключ — `chain` записи приложения в этом workspace, а без него — собственная клавиша приложения; workspace откликается на цепочку, если в нём есть запись приложения с таким ключом. Запущенным MUST считаться workspace, который числится в списке какого-либо стола, в том числе ожидающий ленивого поднятия; запущенный workspace MUST искаться сначала в списке текущего стола по порядку, затем в списках столов по возрастанию номера. Workspace, не числящийся ни в одном списке столов, клавиша приложения MUST NOT поднимать.

Пусть нажата цепочка `K`, на текущем столе активен workspace `W` (или активного нет), а `Own(K)` — приложения с собственной клавишей `K`, по именам. Путь MUST выбираться по порядку: (1) `W` откликается на `K` — цикл отозвавшегося приложения в `W`; (2) приложение из `Own(K)` описано в `W` — цикл этого приложения в `W`; (3) запущенный workspace `V` откликается на `K` либо описывает приложение из `Own(K)` через его семейство, не имея записи самого приложения (у такого приложения в `V` переопределения нет), — `V` MUST быть поднят, а если он в списке другого стола, демон MUST перейти на стол с наименьшим номером, в списке которого он есть, и поднять его там; цикл идёт по отозвавшемуся или описанному приложению в `V`; (4) приложение `X` из `Own(K)` описано в запущенных workspace, и каждый из них переопределил его клавишу — при активном `W` окна `X` MUST быть перетащены в `W`, и цикл идёт в `W`; без активного `W` MUST быть поднят первый такой workspace по правилу шага (3), и цикл идёт в нём; (5) иначе берётся первое приложение из `Own(K)`, а если собственной клавиши `K` нет ни у одного приложения, — первое по имени приложение, которому `K` назначена ключом в каком-либо workspace: при активном `W` оно MUST быть открыто в `W`, без него цикл MUST идти по окнам приложения вне workspace. Если на `K` не отзывается ни одно приложение, демон MUST записать это в журнал и не делать ничего.

Команда `workspaced app <app> [--pull]` и действие `{ app = … }` записи `[[binds]]` MUST действовать как собственная клавиша приложения: по тем же шагам, где `Own(K)` — это приложение, а workspace откликается, если описывает приложение и не переопределяет его клавишу. Признак перетаскивания (`--pull`, ключ `pull` у действия записи `[[binds]]`) при активном `W` MUST перетаскивать окна приложения в `W` сразу после шага (2). Несколько имён в команде MUST считаться кандидатами: действует тот, для которого путь найдётся на более раннем шаге, а при равенстве — первый по порядку.

Если workspace поднят этой же клавишей или приложение открыто либо перетащено в него этой клавишей, цикл MUST начинаться заново — с первого экземпляра: поднятие уже отдало фокус первому экземпляру главного приложения. Открытие приложения в `W` MUST идти по правилам захвата при поднятии (требование «Захват открытых окон приложения»): свободные окна приложения MUST быть захвачены, а если их нет — окна приложения из других workspace MUST быть отданы ему в общее пользование; без окон приложение MUST быть запущено; окна MUST войти в `W` с записью о месте (требование «Посторонние окна»). Открытое или перетащенное приложение MUST выбираться без обмена ячеек в любом режиме: первый экземпляр получает фокус и поднимается наверх на своём месте, ячейки остальных приложений MUST NOT меняться.

Перетаскивание MUST добавлять в активный workspace текущего стола все нескрытые окна приложения — по семейству окна семейства, по варианту окна варианта — из любых workspace и свободные; из прежних workspace окна MUST NOT уходить (требование «Состав workspace»). Workspace MUST получить запись о месте приложения: для приложения файла конфига — запись только о месте, для дополнительного приложения сессии другого workspace — полную запись с классом, командной строкой и каталогом (требование «Дополнительные приложения сессии» спецификации ws-sessions). Окна MUST встать на текущий стол на место приложения по правилу мест требования «Расстановка окон», а без места — в центр экрана с нынешним размером окна. Если окон у приложения нет, перетаскивание MUST действовать как открытие приложения. Если приложение в активном workspace уже описано, признак перетаскивания MUST NOT менять действия: цикл идёт в `W`.

Шаг цикла MUST определяться активным окном и порядком экземпляров (требование «Идентификация окон»), а не счётчиком нажатий: если активное окно — экземпляр приложения и за ним есть следующий, MUST быть выбран следующий; если активное окно — последний экземпляр, цикл MUST быть закончен; во всех остальных случаях MUST быть выбран первый экземпляр. Выбор экземпляра мышью MUST NOT менять учёта: демон MUST NOT помнить, какие экземпляры уже показаны. В цикл MUST входить окна приложения, входящие в этот workspace (требование «Состав workspace»), кроме окон на `special:hidden`; окна варианта, у которого в workspace есть собственная запись, в цикл его семейства MUST NOT входить. Если окон нет, приложение MUST быть запущено с окружением workspace, а приложение без `cmd` MUST остаться без окна с записью в журнал; пока у приложения есть хотя бы одно окно в этом workspace, клавиша MUST NOT запускать ещё один экземпляр.

Что значит «выбрать экземпляр», MUST задавать режим вызванного приложения в workspace (спецификация ws-config, «Файл конфига и его разделы»): поле `mode` его записи, а без него — режим workspace, кроме приложения без ячейки в workspace режима `swap`, которое выбирается в режиме `stack`; приложение, описанное в workspace только через семейство, берёт режим записи семейства. Весь цикл — выбор экземпляра, запоминание prev, конец цикла и запуск без окон — MUST идти в режиме вызванного приложения. В режиме обмена ячеек (`swap`): если приложение выбранного окна не стоит в главной ячейке, окна приложения MUST занять главную ячейку, а окна прежнего главного приложения — ячейку вызванного, стопка на стопку; затем выбранное окно MUST получить фокус и подняться наверх; запуск без окон MUST сначала перевести приложение в главную ячейку. Обмен ячеек MUST NOT менять положение остальных окон. В режиме `stack`: выбранное окно MUST получить фокус и подняться наверх, а положение и размер окон демон MUST NOT менять.

Конец цикла MUST возвращать пользователя к прежнему окну (prev), выбирая его тем же действием. В режиме обмена ячеек prev — первое окно приложения, стоявшего в главной ячейке в начале цикла, поэтому конец цикла MUST давать обратный обмен ячеек и фокус прежнему главному окну. В режиме `stack` prev — активное окно workspace в начале цикла, не принадлежащее вызванному приложению, а если активным было чужое окно — последнее окно этого workspace, получавшее фокус. Если prev нет или его окно закрыто либо скрыто, конец цикла MUST выбрать первый экземпляр следующего приложения workspace: следующим MUST считаться первое приложение после вызванного по порядку записи в разделе workspace (циклически), у которого есть нескрытое окно в этом workspace; приложения без окон MUST быть пропущены, и запускать их конец цикла MUST NOT. Если такого приложения нет, конец цикла MUST снова выбрать первый экземпляр вызванного приложения. У приложения вне workspace prev нет: за последним его экземпляром MUST идти первый.

#### Scenario: Обмен с главной ячейкой
- **WHEN** в `dev-front` (шаблон `cross`, режим обмена) редактор в ячейке `center`, терминал в `left`, и нажата цепочка терминала
- **THEN** терминал занимает `center`, редактор занимает `left`, браузер в `right` не сдвигается, фокус у терминала

#### Scenario: Приложение уже главное
- **WHEN** редактор с единственным окном стоит в главной ячейке с фокусом, цикл по нему не начинался, и нажата его цепочка
- **THEN** цикл заканчивается: выбирается первый экземпляр следующего приложения workspace по порядку записи в его разделе, у которого есть окно, и в режиме обмена ячеек оно занимает главную ячейку

#### Scenario: Обмен ячеек у приложения с двумя окнами
- **WHEN** в `work` (шаблон `thirds`, режим обмена ячеек) herdr в главной ячейке `center`, у `chromium` в ячейке `left` два окна, и нажата цепочка `chromium`
- **THEN** оба окна `chromium` встают в ячейку `center` одно поверх другого, окно herdr уходит в ячейку `left`, фокус и верхнее место получает первый экземпляр `chromium`

#### Scenario: Повторное нажатие при двух окнах
- **WHEN** оба окна `chromium` стоят в главной ячейке, фокус у первого экземпляра, и его цепочка нажата ещё раз
- **THEN** ячейки не меняются, фокус и верхнее место получает второй экземпляр `chromium`

#### Scenario: Конец цикла возвращает расстановку
- **WHEN** оба окна `chromium` стоят в главной ячейке, фокус у второго экземпляра, и цепочка `chromium` нажата ещё раз
- **THEN** окна `chromium` возвращаются в ячейку `left`, окно herdr — в ячейку `center`, фокус у herdr

#### Scenario: Единственный экземпляр — переключатель
- **WHEN** у `neovide` одно окно в ячейке `right`, фокус у herdr, и цепочка `neovide` нажата дважды
- **THEN** первое нажатие выбирает окно `neovide`, второе возвращает фокус окну herdr, и расстановка та же, что была до нажатий

#### Scenario: Режим stack поднимает окно, не двигая его
- **WHEN** у workspace `surf` задано `mode = "stack"`, окна трёх браузеров стоят по ячейкам `overlay`, фокус у Яндекс.Браузера, и нажата цепочка `chrome`
- **THEN** окно `chrome` поднимается наверх и получает фокус, ячейки и положения всех окон не меняются

#### Scenario: Конец цикла в режиме stack
- **WHEN** в `surf` у `chrome` два окна, цепочка `chrome` нажата трижды подряд от окна Яндекс.Браузера
- **THEN** первое нажатие поднимает первый экземпляр `chrome`, второе — второй, третье возвращает наверх окно Яндекс.Браузера с фокусом; положения окон не меняются

#### Scenario: Клик мышью по экземпляру
- **WHEN** у `chromium` три окна, пользователь кликнул по второму экземпляру и нажал цепочку `chromium`
- **THEN** выбирается третий экземпляр, следующее нажатие заканчивает цикл и возвращает к prev, а первый экземпляр повторно не показывается

#### Scenario: Окно prev закрыто
- **WHEN** цикл `chromium` в `work` начат от окна herdr, пользователь закрыл окно herdr, и цикл дошёл до конца
- **THEN** выбирается первый экземпляр следующего приложения `work` по порядку записи в его разделе, у которого есть окно; если такого нет, снова выбирается первый экземпляр `chromium`

#### Scenario: Закрытое окно приложения
- **WHEN** окно терминала `dev-front` закрыто пользователем и нажата цепочка терминала
- **THEN** терминал запускается заново с окружением `dev-front`, после появления окна занимает главную ячейку, редактор уходит в ячейку терминала

#### Scenario: Приложение в другом workspace того же стола
- **WHEN** на столе 1 активен `chat`, в списке стола 1 есть `dev-front` с `editor-front`, у которого два окна, и нажата цепочка `editor-front`
- **THEN** на столе 1 поднимается `dev-front`, фокус у первого экземпляра редактора, `chat` припаркован; второй экземпляр выбирается следующим нажатием

#### Scenario: Приложение на другом столе
- **WHEN** на столе 1 нет workspace с `firefox-chat`, а `chat` есть в списке стола 2, и нажата цепочка `firefox-chat`
- **THEN** активным становится стол 2, `chat` поднят, `firefox-chat` в главной ячейке с фокусом

#### Scenario: Одна цепочка у разных приложений
- **WHEN** `firefox-front` (в `dev-front`) и `firefox-chat` (в `chat`) имеют одну цепочку, на текущем столе активен `chat`
- **THEN** цепочка действует на `firefox-chat` с его профилем и окружением, `firefox-front` не запускается

#### Scenario: Приложение без workspace
- **WHEN** приложение `calc` не входит ни в один workspace, у него задан `rect = { x = 2600, y = 1500, w = 600, h = 400 }`, и нажата его цепочка на столе 1 с активным `dev-front`
- **THEN** калькулятор появляется в этом прямоугольнике поверх окон `dev-front`, получает фокус и входит в `dev-front` записью о месте, ячейки `dev-front` не меняются; второе нажатие заканчивает цикл и возвращает фокус окну, активному до первого нажатия; после переноса окна пользователем и нового нажатия цепочки окно остаётся на новом месте и получает фокус, а ячейки `dev-front` по-прежнему не меняются: у калькулятора нет ячейки, и он выбирается в режиме `stack`

#### Scenario: Приложение без workspace и без места
- **WHEN** у приложения `calc` поля `rect` нет и нажата его цепочка
- **THEN** окно появляется в центре экрана поверх остальных окон, как раньше, и входит в активный workspace стола, если он есть

#### Scenario: Workspace приложения не запущен
- **WHEN** `surf` не числится ни в одном списке столов, на столе 1 активен `work`, и нажата цепочка `chrome-ai`, описанного только в `surf`
- **THEN** `surf` не поднимается; если окон `chrome-ai` нет, он запускается, а если его окно осталось на `special:pool` от `surf`, оно становится общим; окно встаёт в центр экрана со своим размером и входит в `work` записью о месте

#### Scenario: Перетаскивание окна в активный workspace
- **WHEN** `surf` активен на столе 2, у `chrome-ai` там одно окно, пользователь на столе 1 с активным `work` и выполнена `workspaced app chrome-ai --pull`
- **THEN** окно `chrome-ai` входит в `work` и в `surf`, переезжает на стол 1 в центр экрана со своим размером и получает фокус; `surf` остаётся активным на столе 2, `work` получает запись о месте `chrome-ai`, новый Chrome не запускается

#### Scenario: Перетаскивание уже описанного приложения
- **WHEN** на столе 1 активен `work`, и выполнена `workspaced app chromium --pull`
- **THEN** действие то же, что у цепочки `chromium` без признака: цикл по экземплярам в `work`

#### Scenario: Стол без активного workspace
- **WHEN** на столе 4 активного workspace нет, `calc` не описан ни в одном запущенном workspace, и нажата цепочка `calc`
- **THEN** окно `calc` открывается на столе 4 свободным окном приложения, а при нескольких его окнах цепочка перебирает их по кругу

#### Scenario: Клавиша workspace поднимает его
- **WHEN** `surf` активен на столе 2 и записывает `chrome-ai = { cell = "right", chain = "SUPER+V" }`, собственная клавиша `chrome-ai` — Shift+Super+V, пользователь на столе 1 с активным `work` и нажимает Super+V
- **THEN** активным становится стол 2, фокус у первого экземпляра `chrome-ai`, окно `chrome-ai` в `work` не входит

#### Scenario: Собственная клавиша перетаскивает окно
- **WHEN** при тех же условиях на столе 1 нажато Shift+Super+V
- **THEN** окно `chrome-ai` входит в `work` и в `surf`, переезжает на стол 1 в центр экрана со своим размером и получает фокус; `surf` остаётся активным на столе 2, новый Chrome не запускается, ячейки `work` не меняются

#### Scenario: Обе клавиши в workspace с переопределением
- **WHEN** на столе 2 активен `surf` с той же записью `chrome-ai`, и нажато Super+V, затем Shift+Super+V
- **THEN** оба нажатия ведут цикл `chrome-ai` в `surf`: первое поднимает его окно наверх, второе заканчивает цикл и возвращает prev; окна не перетаскиваются и не двигаются

#### Scenario: Клавиша переопределения без запущенного workspace
- **WHEN** `surf` не числится ни в одном списке столов, на столе 1 активен `work`, и нажато Super+V, назначенное `chrome-ai` только записью `surf`
- **THEN** `surf` не поднимается; окно `chrome-ai` открывается в `work`, как по его собственной клавише в случае, когда workspace приложения не запущен

#### Scenario: Приложение в двух workspace, один без переопределения
- **WHEN** `chrome-ai` описан в `surf` с ключом Super+V и в `ai` без переопределения, оба workspace запущены, на столе 1 активен `work`, и нажато Shift+Super+V
- **THEN** поднимается `ai`, окно `chrome-ai` не перетаскивается в `work`

#### Scenario: Общая клавиша семейства
- **WHEN** у `chrome` задано `chain = "SUPER+B"`, у `chrome-ai` — `family = "chrome"` и `chain = "SUPER+V"`, workspace `mix` записывает только `chrome = "center"`, в нём два окна `chrome` и одно окно `chrome-ai`, и Super+B нажато трижды
- **THEN** нажатия по очереди выбирают все три окна, окно `chrome-ai` в том числе; Super+V в `mix` выбирает только окно `chrome-ai` и не поднимает другой workspace

#### Scenario: Клавиша варианта поднимает workspace его семейства
- **WHEN** при тех же приложениях `mix` запущен на столе 2, на столе 1 активен `work`, который `chrome` не описывает, и нажато Super+V
- **THEN** активным становится стол 2, поднят `mix`, фокус у окна `chrome-ai`; окно в `work` не перетаскивается

#### Scenario: Каждый вариант на своей клавише
- **WHEN** при тех же приложениях workspace `surf` записывает `chrome = "left"` и `chrome-ai = "right"`, и нажато Super+B
- **THEN** цикл идёт только по окнам `chrome`, окно `chrome-ai` в него не входит; Super+V ведёт цикл по окну `chrome-ai`

#### Scenario: Приложение без ячейки не меняется с главным
- **WHEN** окно `chrome-ai` перетащено в `work` (режим обмена ячеек) и описано там записью сессии с `rect`, фокус у окна herdr в главной ячейке, и нажата собственная клавиша `chrome-ai`
- **THEN** окно `chrome-ai` поднимается наверх и получает фокус на своём месте, herdr остаётся в ячейке `center`; следующее нажатие возвращает фокус окну herdr, и ячейки не меняются

#### Scenario: Явный обмен у приложения без ячейки
- **WHEN** в разделе `dev-front` (режим обмена ячеек) записано `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 }, mode = "swap" }`, фокус у окна другого приложения, и нажата цепочка `calc`
- **THEN** окно калькулятора занимает главную ячейку, а прежнее главное приложение встаёт в прямоугольник калькулятора

#### Scenario: Режим stack у приложения с ячейкой
- **WHEN** в разделе `work` (режим обмена ячеек) записано `chromium = { cell = "left", mode = "stack" }`, herdr в ячейке `center` с фокусом, и нажато Super+C дважды
- **THEN** первое нажатие поднимает окно `chromium` наверх в ячейке `left` и даёт ему фокус, herdr остаётся в `center`; второе возвращает фокус окну herdr, ячейки не меняются
