## Context

Quickshell 0.3.1 отдаёт каталог конфигурации модулем `qs`, а его
подкаталоги — модулями `qs.<подкаталог>`; модуль подкаталога
загружается целиком, со всеми типами из его `qmldir`. Окно askpass
подключало панель ссылкой `panel -> ../panel` ради двух файлов —
`Theme.qml` и `Tile.qml` (решение D2 архивного изменения
`2026-09-22-qs-askpass`). Пока синглтоны панели не импортировали
ничего из корня, это работало. Коммит `3f7e9e1` (22.09.2026, 21:27)
добавил `import qs` в `NotificationService.qml`, модуль `qs.panel`
в конфигурации askpass перестал загружаться, и обёртка каждый раз
уходила на запасной путь pinentry-gtk.

Зависимости общих файлов проверены: `Theme.qml` и `Tile.qml`
импортируют только `QtQuick`, `Tile` пользуется `Theme` из своего
каталога. Им не нужно ничего из панели.

## Goals / Non-Goals

**Goals:**

- Окно askpass загружается и не зависит от кода панели.
- Сбой окна виден вызвавшей программе, а не подменяется другим диалогом.
- `sudo -A` находит окно без переменной `SUDO_ASKPASS` в командной строке.

**Non-Goals:**

- Агент polkit на Quickshell — отдельное изменение (D5).
- Изменение вида окна или панели.

## Decisions

**D1. Общий модуль `qs.common` через символические ссылки.**
`Theme.qml` и `Tile.qml` перенесены в `dot_config/quickshell/common/`
со своим `qmldir`. В каталогах `panel` и `askpass` лежит ссылка
`common -> ../common` (в источнике chezmoi — файл `symlink_common`),
и обе конфигурации импортируют `qs.common`. Модуль содержит только
оформление, поэтому новые синглтоны панели на окно askpass больше
не влияют. Проверено: панель после перезапуска `quickshell-panel.service`
загружается без ошибок QML, `qs -c askpass` печатает «Configuration
Loaded».

Отвергнуто — относительный импорт каталога (`import "../common"`)
без модуля `qs`: при проверке 22.09.2026 такой импорт не отдавал
singleton `Theme` (имя не определено, а с псевдонимом объект был без
свойств, D2 архивного `qs-askpass`). Отвергнуто — копии `Theme.qml`
и `Tile.qml` в каталоге askpass: оформление жило бы в двух местах.
Отвергнуто — ссылки на отдельные файлы панели (`askpass/Theme.qml ->
../panel/Theme.qml`): тогда их надо помнить при каждом переносе, а
граница «что общее» нигде не записана; отдельный каталог её задаёт.

Файлам панели теперь нужен явный `import qs.common`: раньше `Theme`
и `Tile` лежали в корне панели и были видны без импорта. Импорт
добавлен в 23 файла, которые ими пользуются; `qmldir` панели больше
не регистрирует эти два типа.

**D2. Запасного пути нет, отказ — в stderr и код 1.** Решение
пользователя 23.09.2026 (запись `0008`). Обёртка проверяет `qs`,
конфигурацию и `WAYLAND_DISPLAY`, при ошибке пишет строку
`sudo-askpass: <причина>` в stderr и завершается с кодом 1; то же при
отмене и при завершении окна без ответа. `sudo` тогда отказывает
с сообщением «пароль не предоставлен», и агент видит обе строки в выводе
команды. Stdout при отказе пуст: sudo читает оттуда пароль.

**D3. `Path askpass` в `/etc/sudo.conf`.** Строка с абсолютным путём
`/home/mne/.local/bin/handmade-scripts/sudo-askpass` делает окно
программой askpass по умолчанию для всех, кто вызывает `sudo -A` без
переменной. Файл принадлежит пакету sudo и помечен в нём как файл
настройки: pacman при обновлении не перезаписывает изменённый файл,
а кладёт `.pacnew`. chezmoi `/etc` не применяет, поэтому копия лежит
в `system/sudo/sudo.conf`, установка вручную описана в
`system/sudo/README.md` (как `system/greetd/`). Абсолютный путь
с именем пользователя допустим: машина однопользовательская, а sudo.conf
переменных не раскрывает.

**D4. `SUDO_ASKPASS` в окружении сессии.** Переменная важнее строки
`sudo.conf` и нужна программам, которые смотрят только на неё
(сценарии вида `${SUDO_ASKPASS:-…}`). Она задана в `hyprland.lua`
через `hl.env`, передаётся пользовательскому systemd тем же
`import-environment`, что и остальные переменные сессии, и в
`~/.profile` — для входа без Hyprland. Вызов в правилах агентов остаётся
`sudo -A -p '<зачем>'`: ключ `-A` явно требует программу askpass
и не зависит от того, как sudo ведёт себя без терминала, а `-p` нужен
ради пояснения в окне.

**D5. Polkit — отдельным изменением.** В Quickshell 0.3.1 есть модуль
`Quickshell.Services.Polkit` (`/usr/lib/qt6/qml/Quickshell/Services/Polkit`,
тип `PolkitAgent` и поток `AuthFlow` со свойствами `message`,
`inputPrompt`, `responseVisible`, методами `submit` и
`cancelAuthenticationRequest`). Сейчас
агент polkit в сессии — `hyprpolkitagent` (юнит `hyprpolkitagent.service`
из пакета, запускается целью `hyprland-session.target`). План:
агент живёт в процессе панели (агент polkit должен работать постоянно,
а панель и так работает всю сессию), окно запроса оформлено тем же
модулем `qs.common` и повторяет окно askpass; `hyprpolkitagent.service`
маскируется ссылкой на `/dev/null` в `dot_config/systemd/user/`, как
dunst. Открытые вопросы плана: общий компонент окна для askpass и polkit
(вынести поле ввода в `qs.common`) и порядок регистрации агента
на шине, если панель перезапускается. Задача записана в `todo.md`.

## Risks / Trade-offs

- [Окно сломается снова — пароль не спросить никак] → sudo сообщает
  об отказе сразу, причина в stderr обёртки; починка — в конфигурации
  окна. Права root для починки не нужны: конфигурация лежит в `$HOME`.
- [Обновление пакета sudo принесёт `.pacnew`] → строка `Path askpass`
  остаётся в действующем файле; сверка описана в README.

## Migration Plan

Порядок архивации: после `work-area-center`. Оба изменения правят
спецификацию `qs-shell`, но разные требования (`work-area-center` —
«Окно панели», это изменение — «Модульная структура конфигурации»),
поэтому текст из `work-area-center` переносить не нужно; порядок
задан, чтобы архивы шли в порядке появления правок.
