## MODIFIED Requirements

### Requirement: Оформление как у плиток панели
Окно MUST быть оформлено как плитка панели: чёрная заливка с непрозрачностью 0.9, рамка 1 px цвета yellow `#E0AF68`, скругление 12 px, расстояние от содержимого до внешнего края 10 px, шрифт IosevkaTermSlab NF, палитра Tokyo Night. Цвета, шрифт и размеры MUST браться из `Theme.qml`, а сама плитка — из `Tile.qml` общего модуля оформления `qs.common` (каталог `~/.config/quickshell/common`), из которого их берёт и панель; конфигурация подключает модуль через символическую ссылку `common` на этот каталог и MUST NOT содержать собственных копий этих значений. Конфигурация MUST NOT подключать модуль панели (`qs.panel`): синглтоны панели импортируют модуль `qs` её корня и в конфигурации askpass не загружаются. Содержимое окна сверху вниз: заголовок «SUDO» приглушённым серым, пояснение вызвавшей программы, поле ввода, строка подсказки о клавишах. Расстояние между этими частями — 10 px. Композитор MUST размывать фон под слоем `askpass` тем же правилом, что и под слоем панели.

#### Scenario: Вид совпадает с панелью
- **WHEN** окно открыто рядом с панелью
- **THEN** заливка, жёлтая рамка 1 px, скругление и отступы окна совпадают с плитками панели, текст набран тем же шрифтом, фон под окном размыт

#### Scenario: Стиль правится в одном месте
- **WHEN** в `common/Theme.qml` изменён цвет рамки плиток
- **THEN** и панель, и окно запроса пароля при следующем запуске рисуются новым цветом, правок в конфигурациях `panel` и `askpass` для этого не требуется

#### Scenario: Окно не зависит от кода панели
- **WHEN** в панель добавлен синглтон, который импортирует модуль `qs` её корня
- **THEN** `qs -c askpass` по-прежнему печатает «Configuration Loaded», ошибок загрузки в журнале Quickshell нет

### Requirement: Ввод и отмена
Enter MUST завершать ввод и отдавать пароль обёртке; при пустом поле Enter MUST NOT завершать ввод. Escape MUST отменять запрос: окно закрывается, обёртка завершается с кодом 1, её stdout пуст, а в stderr стоит одна строка о том, что ввод отменён. Снятие окна (завершение процесса Quickshell) MUST давать тот же код выхода и пустой stdout — обёртка не остаётся ждать ответа.

#### Scenario: Пароль введён
- **WHEN** пользователь набрал пароль и нажал Enter
- **THEN** окно исчезает, обёртка печатает пароль одной строкой и завершается с кодом 0

#### Scenario: Отказ от ввода
- **WHEN** пользователь нажал Escape
- **THEN** окно исчезает, обёртка завершается с кодом 1, её stdout пуст, а `sudo` сообщает, что пароль не получен

### Requirement: Конфигурация под chezmoi
Конфигурация окна MUST храниться под chezmoi в каталоге `dot_config/quickshell/askpass/` и попадать в `~/.config/quickshell/askpass/` командой `chezmoi apply`. Связь с общим модулем оформления MUST задаваться символической ссылкой (в источнике — `symlink_common` с целью `../common`), а не копией файлов. Ссылки на каталог панели в конфигурации MUST NOT быть. Пути внутри конфигурации MUST записываться без префиксов chezmoi.

#### Scenario: Конфигурация применена
- **WHEN** выполнена команда `chezmoi apply`
- **THEN** в `~/.config/quickshell/askpass/` лежат `shell.qml` и ссылка `common` на `../common`, ссылки `panel` нет, `chezmoi status` не показывает расхождений

## ADDED Requirements

### Requirement: Отказ без запасного пути
Окно Quickshell MUST быть единственным способом ввести пароль через обёртку: другого диалога (pinentry, zenity, терминала) обёртка MUST NOT вызывать. Если окно нельзя показать (нет команды `qs`, нет конфигурации `askpass`, пуста переменная `WAYLAND_DISPLAY`, не удалось создать канал) или процесс окна завершился, не ответив, обёртка MUST написать причину одной строкой в stderr и завершиться с кодом 1 при пустом stdout.

#### Scenario: Окно не загрузилось
- **WHEN** `~/.config/quickshell/askpass/shell.qml` содержит ошибку и процесс Quickshell завершается сразу
- **THEN** никакого другого диалога не появляется, обёртка пишет в stderr, что окно завершилось, не ответив, и выходит с кодом 1, а `sudo -A` сообщает, что пароль не предоставлен

#### Scenario: Сессия не Wayland
- **WHEN** обёртка запущена без переменной `WAYLAND_DISPLAY`
- **THEN** она сразу завершается с кодом 1 и строкой о пустой `WAYLAND_DISPLAY` в stderr

### Requirement: Программа askpass по умолчанию
Обёртка MUST быть программой askpass по умолчанию для sudo: `/etc/sudo.conf` MUST содержать строку `Path askpass /home/mne/.local/bin/handmade-scripts/sudo-askpass`, а копия этого файла MUST храниться в репозитории в `system/sudo/sudo.conf` вместе с описанием ручной установки (chezmoi каталог `system/` не применяет). Окружение сессии MUST задавать переменную `SUDO_ASKPASS` с тем же путём (спецификация hyprland-session). Команды с правами root без терминала MUST вызываться как `sudo -A -p '<пояснение>'`, пояснение попадает в окно.

#### Scenario: sudo без переменной
- **WHEN** кэш sudo сброшен (`sudo -k`) и выполнена `env -u SUDO_ASKPASS sudo -A -p 'Проверка окна askpass' true`
- **THEN** появляется окно Quickshell askpass с этим пояснением, после ввода пароля команда завершается с кодом 0, а `sudo -n true` сразу после неё тоже завершается с кодом 0

## REMOVED Requirements

### Requirement: Запасной путь pinentry-gtk
**Reason**: Решение пользователя 23.09.2026: пароль для повышения привилегий спрашивает только окно Quickshell. Запасной путь скрыл поломку окна — с 22.09.2026 все запросы показывал pinentry-gtk, и это осталось незамеченным (запись `docs/decisions/0008-askpass-quickshell-only.md`).
**Migration**: Обёртка при сбое окна завершается с кодом 1 и причиной в stderr (требование «Отказ без запасного пути»); окно чинится в конфигурации `~/.config/quickshell/askpass`, права root для этого не нужны.
