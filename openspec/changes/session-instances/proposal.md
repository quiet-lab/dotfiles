## Why

Шаги 1–4 серии изменений модели окон
([`docs/window-model.md`](../../../docs/window-model.md), раздел 5) дали
приложению несколько окон-экземпляров, режим `stack` с памятью
прямоугольников по workspace и состав workspace «многие ко многим» тегами
`ws:<имя>`. Всё это живёт в тегах композитора и в памяти демона, а снимок
сессии по-прежнему описывает модель «одно приложение — одно окно»: у окна
приложения записаны только имя приложения, стол и прямоугольник, а при
восстановлении демон запускает по одному окну на приложение. Поэтому
перезапуск демона экземпляры и состав не теряет, а перезагрузка теряет
(оговорка про сессии в конце раздела 5 документа):

- второе окно браузера после перезагрузки либо не возвращается, либо
  (если браузер восстановил его сам) принимается как новое окно в workspace
  стола, где появилось, а не туда, где было;
- второй экземпляр программы, которая держит по процессу на окно (neovide,
  открытый из yazi, второй терминал), не запускается вовсе;
- общее окно собирается заново только по описаниям в файле конфига
  и записям о месте в сессии (решение D14 изменения `shared-windows`), номер
  экземпляра и порядок экземпляров не сохраняются;
- прямоугольники режима `stack`, запомненные для workspace, пропадают
  и при перезапуске демона, и при перезагрузке (решение D9 изменения
  `key-cycle-stack`).

Это шаг 7 серии. После шага перезагрузка возвращает систему к тому набору
окон, с которым работал пользователь: экземпляры с номерами, их состав
и места в каждом workspace.

## What Changes

- **Окно приложения записывается в снимок экземпляром.** К имени
  приложения, столу и прямоугольнику добавляются номер экземпляра, список
  workspace по тегам состава и прямоугольники, запомненные для каждого его
  workspace режима `stack`. Экземпляр с собственным процессом, кроме первого
  экземпляра приложения, записывается ещё и с командной строкой и каталогом
  процесса — по тем же правилам, что свободное окно. Первый экземпляр
  и окна, чей процесс держит и другие окна (второе окно браузера), командной
  строки не получают.
- **Восстановление при старте ведётся по экземплярам.** Экземпляр
  с командной строкой запускается при поднятии первого из своих workspace;
  первый экземпляр — командой приложения, как сейчас; остальные окна без
  командной строки открывает сам процесс приложения (браузер, восстанавливающий
  свои окна), а демон, запустивший приложение, ждёт их по событиям
  композитора и раскладывает по записям. Появившееся окно получает номер
  из снимка, теги состава из записи и встаёт по правилу размещения шага 4;
  прямоугольники режима `stack` становятся запомненными.
- **Перезапуск демона без перезагрузки не запускает копий.** Запись снимка,
  для которой живое окно с тем же тегом экземпляра уже есть, не запускается;
  теги состава живых окон остаются как есть (решение D14 шага 4), из снимка
  берутся только прямоугольники режима `stack`.
- **Загрузка именованной сессии сверяет окна по экземплярам.** Живые окна
  приложения переиспользуются для записей снимка по порядку номеров
  и получают состав из снимка; окна сверх числа записей закрываются штатно,
  недостающие восстанавливаются, как при старте.
- **Номер экземпляра восстановленного окна** берётся из снимка, если
  свободен: порядок экземпляров в цикле клавиши остаётся прежним.
- **Совместимость.** Снимок прежнего формата читается и восстанавливается
  по прежнему правилу (одно окно на приложение); прежняя версия демона читает
  снимок нового формата, пропуская новые поля.

## Что не входит

- Содержимое окон — вкладки браузера, открытые файлы, история терминала:
  его восстанавливают сами приложения.
- Запуск второго окна браузера демоном (`--new-window` и подобное): окна,
  не являющиеся отдельными процессами, открывает сам браузер (предложение,
  принятое 22.09.2026, `docs/window-model.md`, раздел 4).
- Геометрия окна до развёртывания (Alt+Super+PageUp), незаконченный цикл
  клавиши, prev и история активных workspace стола: это след работы
  пользователя, а не состояние окон, и в снимок они не попадают, как
  и раньше.
- Настройки браузеров: «продолжить с того же места» при запуске — условие,
  без которого браузер своих окон не восстановит, но меняет его
  пользователь (`design.md`, решение D3).
- Панель и конфиг сессии не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-sessions`: «Файлы сессий» (экземпляры, состав, прямоугольники
  по workspace, командная строка экземпляра), «Загрузка сессии» (сверка
  по экземплярам, состав из снимка), «Восстановление при старте» (запуск
  экземпляров, ожидание окон, сопоставление, размещение, перезапуск демона
  без перезагрузки).
- `ws-daemon`: «Состав workspace» (пятое событие входа — восстановление
  из снимка; загрузка сессии приводит состав к снимку), «Идентификация окон»
  (номер из снимка, совпадение по pid раньше совпадения по классу).

Требование «Дополнительные приложения сессии» (ws-sessions) не меняется:
команда сохранения пишет снимок целиком, а что входит в снимок, задаёт
требование «Файлы сессий».

## Порядок архивации

Шаги 4–6 серии не заархивированы. Требования «Состав workspace»
и «Идентификация окон» взяты из дельты ws-daemon изменения `shared-windows`
(первое там добавлено, второе изменено), «Файлы сессий», «Загрузка сессии»
и «Восстановление при старте» — из `openspec/specs/ws-sessions/spec.md`
(шаги 4–6 их не меняли). Поэтому это изменение архивируется последним:
после `shared-windows`, `workspace-overrides` и `panel-shared-windows`.

## Impact

- Демон `~/work/pets/workspaced`: `state.rs` (формат записи окна в снимке,
  план восстановления), `session.rs` (снимок, восстановление при старте,
  загрузка), `daemon.rs` (сопоставление появившегося окна, запуск
  экземпляров, поднятие workspace при ожидаемых экземплярах, снятие ожиданий
  клавишей приложения), `save.rs` (команда сохранения снимает ожидания).
- Снимок `~/.local/state/workspaced/sessions/default.toml` получает новые
  поля при первом же сохранении; старый снимок читается без ошибки.
- Конфиг `dot_config/workspaced/config.toml` и панель Quickshell
  не меняются.
- Документация: `AGENTS.md` (абзац о снимке сессии), `docs/window-model.md`
  (разделы 2.4, 2.7, 3, 5 и оговорка про сессии), `docs/host-state.md`
  (настройка восстановления окон в браузерах), `README.md` демона.
