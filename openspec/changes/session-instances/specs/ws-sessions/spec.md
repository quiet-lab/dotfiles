## MODIFIED Requirements

### Requirement: Файлы сессий
Сессии MUST храниться в `~/.local/state/workspaced/sessions/<имя>.toml`, по файлу на сессию. Файл MUST содержать: время снимка, номер активного стола, для каждого стола список workspace по порядку и активный, для каждого workspace назначение приложений по ячейкам и таблицу дополнительных приложений сессии, и список окон. Запись дополнительного приложения сессии MUST хранить его имя ключом таблицы, прямоугольник и, если запись описывает не приложение конфига, класс окна, командную строку и каталог процесса. Таблица дополнительных приложений MUST быть необязательной: снимок прежнего формата MUST читаться без ошибки.

Окно с тегом экземпляра MUST записываться экземпляром: имя приложения, номер экземпляра из тега (у тега без номера — 1), список workspace, в которые окно входит по тегам состава (спецификация ws-daemon, «Состав workspace»), стол, `pool` или `hidden`, прямоугольник окна и для каждого своего workspace режима `stack` прямоугольник, запомненный для этого workspace; для окна, которое стоит на столе, где такой workspace активен, MUST записываться нынешний прямоугольник. Для workspace режима обмена ячеек прямоугольник MUST NOT записываться: место там задаёт ячейка приложения. Экземпляр, у процесса которого нет других окон и который не является первым экземпляром своего приложения (с наименьшим номером среди живых окон приложения), MUST хранить ещё командную строку и каталог процесса по правилу ниже; первый экземпляр и экземпляр, чей процесс держит и другие окна (второе окно браузера), командную строку MUST NOT хранить: первый запускается командой приложения, остальные открывает сам процесс приложения. Если командная строка экземпляра не найдена, он MUST записываться без неё. Запись снимка, которая ещё ждёт поднятия своего workspace (требование «Восстановление при старте») и окна которой с тем же тегом экземпляра нет, MUST переноситься в новый снимок как есть. Свободное окно без тега MUST записываться со столом, командной строкой, каталогом и прямоугольником. Окно приложения без номера экземпляра (снимок прежнего формата) MUST читаться без ошибки и восстанавливаться по прежнему правилу: одно окно на приложение, без состава и прямоугольников из снимка. Поле `workspace` у свободного окна в снимках прежних версий MUST читаться без ошибки и MUST NOT учитываться и записываться.

Снимок `default` MUST записываться только по команде сохранения сессии — цепочке `save_session` или `workspaced save-session` (требование «Дополнительные приложения сессии»). События композитора и остальные команды демона файл MUST NOT изменять: снимок — это сохранённое состояние, к которому возвращаются, а не след последнего действия. Отложенной записи и записи по таймеру MUST NOT быть. Перед загрузкой именованной сессии демон MUST записать `default` (требование «Загрузка сессии»): это единственный случай, когда файл обновляется не по команде сохранения, и он тоже вызван явной командой пользователя. Именованная сессия MUST записываться только по команде `session save <имя>` или из окна выбора и MUST быть копией текущего состояния на момент команды.

Состояние, изменившееся после последнего снимка — принятые окна, переносы workspace между столами, обмен ячеек, списки столов, записи ожидания запуска и ожидания окон при восстановлении, — MUST жить только в памяти демона: перезапуск демона и перезагрузка системы MUST возвращать систему к последнему записанному снимку. Теги экземпляров и состава живых окон при перезапуске демона без перезагрузки MUST оставаться как есть (требование «Восстановление при старте»): состав живого окна снимок MUST NOT менять, а сверка с эффективным конфигом снимает теги, которым записи сессии больше не соответствуют (спецификация ws-daemon, «Состав workspace»).

Командная строка и каталог, которые демон записывает для окна — в снимке сессии у свободного окна и у экземпляра, в записи дополнительного приложения сессии и в разделе workspace по команде сохранения, — MUST быть пригодны для запуска с хоста. У процесса в песочнице flatpak путь к исполняемому файлу и рабочий каталог существуют только внутри песочницы, поэтому командной строкой такого окна MUST записываться `flatpak run <идентификатор приложения>` и исходные аргументы процесса после пути к исполняемому файлу, а каталог MUST NOT записываться. Идентификатор приложения MUST браться из `/proc/<pid>/cgroup` по юниту вида `app-flatpak-<идентификатор>-<номер>.scope`, причём экранирование `\xNN` в имени юнита MUST раскодироваться. Если юнита такого вида нет, MUST записываться командная строка процесса, приведённая к виду, пригодному для запуска: строка, которую процесс переписал одной строкой с пробелами вместо отдельных аргументов (так делают Chromium и основанные на нём браузеры), MUST делиться по пробелам, если файла с таким именем нет; относительный путь к исполняемому файлу (`./steamwebhelper`) MUST заменяться абсолютным от рабочего каталога процесса; имя без каталога MUST оставаться как есть, если находится в `PATH`; если исполняемый файл так не найден, вместо него MUST браться путь из `/proc/<pid>/exe`. Если не найден и он, у окна нет командной строки: свободное окно в снимок MUST NOT попадать, дополнительным приложением MUST NOT становиться, а демон MUST записать предупреждение в журнал. Команду свободного окна из снимка прежней версии демон MUST приводить к тому же виду перед запуском и сверкой с открытыми окнами; команду, исполняемый файл которой не найден, демон MUST NOT запускать и MUST записать предупреждение в журнал.

#### Scenario: Автосохранение
- **WHEN** выполнена команда `workspaced raise dev-front --desktop 1`, затем открыто новое окно
- **THEN** `default.toml` не изменился: снимок сам по себе не пишется, и время изменения файла прежнее

#### Scenario: Снимок пишет команда сохранения
- **WHEN** после этого нажата цепочка `save_session`
- **THEN** к моменту, когда команда вернула управление, `default.toml` содержит стол 1 с активным `dev-front` и все его окна с прямоугольниками

#### Scenario: Изменения после последнего снимка не переживают перезапуск
- **WHEN** после команды сохранения пользователь перенёс `work` на стол 3, принял там новое окно и перезапустил демон
- **THEN** демон восстанавливает состояние на момент сохранения: `work` снова на прежнем столе, принятого окна в его составе нет

#### Scenario: Именованный снимок
- **WHEN** выполнена `workspaced session save review`
- **THEN** появляется `review.toml` с состоянием на этот момент; дальнейшая работа его не меняет

#### Scenario: Дополнительное приложение в снимке
- **WHEN** в `work` принят калькулятор, не описанный в конфиге, и нажата цепочка `save_session`
- **THEN** к возврату команды в `default.toml` у `work` есть запись дополнительного приложения с классом окна, командной строкой, каталогом и прямоугольником, а само окно записано как экземпляр этого приложения

#### Scenario: Окно программы из flatpak
- **WHEN** в `work` принято окно Postman, запущенного из flatpak с аргументами `--force-device-scale-factor=1.5` и `--no-sandbox`, и нажата цепочка `save_session`
- **THEN** командной строкой записано `flatpak run com.getpostman.Postman --force-device-scale-factor=1.5 --no-sandbox`, каталога у записи нет, и этой командой окно поднимается с хоста; путь `/app/extra/Postman/postman` в снимок не попадает

#### Scenario: Командная строка Chromium
- **WHEN** свободное окно Chromium, процесс которого показывает в `/proc/<pid>/cmdline` одну строку `/usr/lib/chromium/chromium --ozone-platform=wayland`, попадает в снимок
- **THEN** командой записаны два элемента, `/usr/lib/chromium/chromium` и `--ozone-platform=wayland`, и этой командой окно поднимается

#### Scenario: Относительная команда
- **WHEN** свободное окно Steam принадлежит процессу с командой `./steamwebhelper …` и рабочим каталогом `~/.local/share/Steam/ubuntu12_64`, и нажата цепочка `save_session`
- **THEN** командой в снимке записан абсолютный путь `/home/mne/.local/share/Steam/ubuntu12_64/steamwebhelper` с прежними аргументами; снимок прежней версии с `./steamwebhelper` при восстановлении запускается тем же абсолютным путём

#### Scenario: Снимок прежней версии с привязками
- **WHEN** в `default.toml` у свободного окна записано `workspace = "work"`, а таблицы дополнительных приложений в файле нет
- **THEN** демон читает снимок, ставит окно на его место на столе, но к `work` не привязывает; после следующей записи снимка поля `workspace` у окна нет

#### Scenario: Экземпляры и состав в снимке
- **WHEN** у `chromium` два окна одного процесса — `app:chromium#1` с тегом `ws:work` и `app:chromium#2` с тегами `ws:work` и `ws:surf`, у `neovide` окно `app:neovide#1` из запуска демоном и окно `app:neovide#2`, открытое из yazi командой `neovide notes.md` в каталоге `~/notes`, и нажата цепочка `save_session`
- **THEN** в `default.toml` четыре записи окон приложений: `chromium` с номером 1 и `workspaces = ["work"]`, `chromium` с номером 2 и `workspaces = ["surf", "work"]`, `neovide` с номером 1 — все три без командной строки, и `neovide` с номером 2, командой `["neovide", "notes.md"]` и каталогом `/home/mne/notes`

#### Scenario: Прямоугольник режима stack в снимке
- **WHEN** окно `chrome-ai` входит в `surf` (режим `stack`, стол 2) и в `work` (режим обмена ячеек, стол 1), для `surf` запомнен прямоугольник 1700,60 1920×2140, пользователь на столе 1, окно стоит там, и нажата цепочка `save_session`
- **THEN** у записи окна `rects` содержит `surf` с прямоугольником 1700,60 1920×2140 и не содержит `work`; `rect` записи — нынешнее положение окна на столе 1

#### Scenario: Сохранение до ленивого поднятия
- **WHEN** после перезагрузки на столе 1 поднят `work`, на стол 2 с `surf` пользователь ещё не переходил, в снимке у `chrome-ai` запись с `workspaces = ["surf"]` и прямоугольником для `surf`, и нажата цепочка `save_session`
- **THEN** в новом `default.toml` запись `chrome-ai` с тем же номером, составом и прямоугольником сохранена, и при переходе на стол 2 окно восстанавливается по ней

#### Scenario: Снимок прежнего формата с окнами приложений
- **WHEN** в `default.toml` у окон `chromium` и `neovide` нет номеров экземпляров, у `chromium` две записи окна
- **THEN** демон читает снимок без ошибки, поднятие `work` запускает `chromium` и `neovide` по одному разу, второе окно `chromium` не ждётся, а следующая команда сохранения пишет записи с номерами

### Requirement: Загрузка сессии
По `session load <имя>` или выбору в окне сессий демон MUST сначала записать текущее состояние в `default`, затем привести систему к снимку. Окна приложения MUST сверяться с его экземплярами в снимке: живые окна приложения по возрастанию номера MUST переиспользоваться для записей снимка по возрастанию номера и MUST сохранять свои номера. Переиспользованное окно MUST получить состав из записи — теги состава, которых в записи нет, MUST сниматься, недостающие MUST ставиться для тех workspace записи, которые описывают приложение окна в эффективном конфиге после загрузки, — и встать на место из снимка по правилу размещения (спецификация ws-daemon, «Следование общего окна за столом»): в ячейку своего приложения в workspace режима обмена ячеек, в прямоугольник, записанный для workspace режима `stack`, а без него — на место из конфига; прямоугольники записи по workspace MUST стать запомненными. Живые окна приложения сверх числа его записей в снимке и окна приложений, которых в снимке нет, MUST быть закрыты штатно, как по запросу закрытия от композитора. Свободное окно MUST переиспользоваться, если в снимке есть свободное окно с той же командной строкой и каталогом, иначе MUST закрываться штатно. Записи снимка, которым живого окна не хватило, MUST восстанавливаться так же, как при старте (требование «Восстановление при старте»); демон MUST считать приложение запущенным при восстановлении, если запустил его этой загрузкой. Дополнительные приложения сессии MUST браться из загружаемого снимка и заменять прежние целиком: приложения загруженного снимка входят в свои workspace, а дополнительные приложения прежнего состояния MUST быть сняты. Списки workspace по столам и активные MUST стать как в снимке, приведённом к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»); активный стол — как в снимке. Ожидания окон, оставшиеся от прежнего восстановления, загрузка MUST снимать до сверки.

#### Scenario: Загрузка со сверкой
- **WHEN** открыты окна `editor-front`, `terminal-front` и Telegram, и загружена сессия, в которой есть `editor-front`, `firefox-front`, а Telegram нет
- **THEN** окна `editor-front` и `terminal-front` не перезапускаются (`terminal-front` паркуется, если его workspace в снимке не активен), Telegram получает запрос закрытия, `firefox-front` запускается, все окна на местах из снимка

#### Scenario: Дополнительные приложения из снимка
- **WHEN** в текущем состоянии у `work` есть дополнительное приложение `galculator`, а в загружаемой сессии у `work` записано дополнительное приложение `keepassxc`
- **THEN** после загрузки `work` содержит `keepassxc` и не содержит `galculator`, окно `keepassxc` запущено и стоит на месте из снимка

#### Scenario: Несохранённый документ
- **WHEN** загружаемая сессия не содержит окна редактора с несохранённым файлом
- **THEN** редактор получает штатный запрос закрытия и показывает свой диалог, демон не завершает процесс принудительно

#### Scenario: Лишнее окно браузера
- **WHEN** открыты три окна `chromium` с номерами 1, 2 и 3, а в загружаемой сессии у `chromium` две записи
- **THEN** окна с номерами 1 и 2 переиспользуются и получают состав из записей, окно с номером 3 получает запрос закрытия, `chromium` не запускается

- **THEN** после загрузки у окна теги `ws:surf` и `ws:work`, второй `chrome-ai` не запускается

- **THEN** демон запускает `neovide notes.md` в `~/notes`, окно получает тег `app:neovide#2` и `ws:work` и встаёт в стопку `neovide` в ячейке `right`

### Requirement: Восстановление при старте
При старте демон MUST загрузить `default`: списки workspace по столам, активные и дополнительные приложения сессии восстанавливаются целиком; полностью поднимается (с запуском приложений) только workspace, активный на столе, который был активен на момент снимка; посторонние окна снимка MUST быть запущены сразу на своих местах; активный workspace другого стола MUST подниматься при первом переходе на этот стол; workspace, не активные ни на одном столе, MUST подниматься при первом вызове. Дополнительное приложение сессии MUST восстанавливаться так же, как приложение конфига: при поднятии его workspace демон MUST захватить подходящее открытое окно, а при его отсутствии запустить приложение по записанным командной строке и каталогу. Списки столов из снимка демон MUST привести к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»): столом workspace MUST стать тот, где он в снимке активен, а если он не активен ни на одном столе — первый по номеру стол, в списке которого он встретился; из остальных списков он MUST быть убран, и стол, лишившийся своего активного workspace, MUST остаться без активного. Порядок оставшихся workspace в списке стола MUST сохраняться. Если `default` отсутствует или не читается, демон MUST стартовать с пустым состоянием и записать причину в журнал. После восстановления демон MUST поднять workspace из раздела `[startup]` конфига на его столе, если раздел задан: приложения без окон запускаются, открытые подходящие окна захватываются; если этот workspace уже поднят сессией, повторное поднятие только расставляет окна.

Экземпляры снимка (требование «Файлы сессий») MUST восстанавливаться по записям. Запись, для которой уже есть живое окно с тем же тегом `app:<имя>#<номер>` (перезапуск демона без перезагрузки), MUST считаться исполненной: приложение MUST NOT запускаться повторно, теги состава окна MUST оставаться как есть, а прямоугольники записи MUST стать запомненными для тех её workspace режима `stack`, в которые окно входит. Запись с командной строкой, для которой живого окна нет, MUST запускаться этой командой в своём каталоге при поднятии первого из её workspace — раньше, чем поднятие захватывает окна и запускает приложения; запись без workspace — сразу после поднятия workspace активного стола. Первый экземпляр приложения — запись с наименьшим номером среди записей этого приложения в снимке — MUST запускаться командой приложения при поднятии своего workspace, как приложение без окон. Пока окно записи с командной строкой не появилось, поднятие её workspace MUST NOT отдавать приложению окна других workspace и MUST NOT запускать команду приложения, если первого экземпляра, ждущего запуска, среди записей этого workspace нет. Остальные записи без командной строки демон MUST NOT запускать: их окна открывает сам процесс приложения (браузер, восстанавливающий свои окна). Демон MUST ждать такие окна, только если сам запустил приложение при восстановлении; если окна приложения при старте уже открыты, записи без командной строки, которым живого окна не нашлось, MUST сниматься со строкой в журнале.

Появившееся окно MUST сопоставляться с записью: сначала по pid процесса, запущенного для записи с командной строкой, и его потомков, затем по приложению окна — с ожидающей записью этого приложения с наименьшим номером; окну, принятому ожиданием запуска приложения, MUST доставаться запись с наименьшим номером среди тех, у которых в списке есть workspace, для которого приложение запущено, а без таких — с наименьшим номером вообще. Сопоставленное окно MUST получить номер экземпляра из записи (спецификация ws-daemon, «Идентификация окон»), теги состава тех workspace записи, которые описывают его приложение в эффективном конфиге, и встать по правилу размещения (спецификация ws-daemon, «Следование общего окна за столом»): в workspace режима обмена ячеек — в ячейку своего приложения, в workspace режима `stack` — в прямоугольник записи для этого workspace, а без него — на место из конфига; если ни один его workspace не активен — на `special:pool`; запись без workspace — на свой стол в свой прямоугольник. Все прямоугольники записи по workspace MUST стать запомненными. Фокус восстановление MUST NOT менять, кроме фокуса главному окну поднимаемого workspace. Окно на `special:hidden` в момент снимка MUST восстанавливаться видимым по тому же правилу.

Ожидание окон при восстановлении MUST быть событийным и MUST NOT ограничиваться сроком: окно приходит событием композитора, выход процесса — событием от процесса. Ожидание записи с командной строкой MUST сниматься с предупреждением в журнале, если запущенный для неё процесс завершился без окна. Ожидание записей без командной строки MUST сниматься, когда все записи приложения исполнены, клавишей приложения или командой `workspaced app` для него, командой сохранения сессии и загрузкой сессии; команда сохранения MUST NOT снимать записи, которые ждут поднятия своего workspace, — они переходят в новый снимок (требование «Файлы сессий»); после этого новое окно приложения MUST приниматься по общим правилам (спецификация ws-daemon, «Посторонние окна»). Содержимое окон — вкладки, открытые файлы, историю — демон MUST NOT восстанавливать: это дело приложений.

#### Scenario: После перезагрузки
- **WHEN** при выходе был активен стол 1 с `dev-front`, на столе 2 активен `chat`, и сессия запущена заново
- **THEN** через 10 секунд после старта открыты окна `dev-front` на столе 1 и нет окон `chat`; плитка «2» показывает иконку `chat`; при первом переходе на стол 2 `chat` поднимается

#### Scenario: Дополнительное приложение после перезапуска демона
- **WHEN** в `work` принят посторонний калькулятор, и демон перезапущен при открытом окне калькулятора
- **THEN** после старта окно остаётся окном того же дополнительного приложения по своему тегу, второй калькулятор не запускается, и поднятие `work` на другом столе переносит окно туда

#### Scenario: Стартовый workspace из конфига
- **WHEN** в `[startup]` задан `workspace = "work"`, а сессия `default` не содержит активного workspace на столе 1 (например, после удаления прежних workspace из конфига)
- **THEN** через 10 секунд после старта демона `work` поднят на столе 1, его приложения открыты или захвачены, плитка «1» показывает его иконку как активную

#### Scenario: Голая сессия
- **WHEN** загружена именованная сессия, снятая без посторонних окон
- **THEN** посторонние окна, открытые до загрузки, закрыты штатно, восстановлены только workspace снимка

#### Scenario: Посторонние окна в снимке
- **WHEN** в снимке есть калькулятор вне workspace с прямоугольником 1600,900 600×400 на столе 1
- **THEN** после загрузки калькулятор запущен и стоит на столе 1 в прямоугольнике 1600,900 600×400

#### Scenario: Снимок с повторами в списках столов
- **WHEN** в `default.toml` `surf` записан в списках столов 1, 2, 6 и 7 и активен на столе 2, а `work` — в списках столов 1, 2 и 3 и активен на столе 1
- **THEN** после старта `surf` числится только на столе 2, `work` — только на столе 1, списки столов 3, 6 и 7 пусты, и `workspaced status --json` показывает каждый workspace ровно на одном столе

#### Scenario: Второе окно браузера после перезагрузки
- **WHEN** в снимке у `chromium` записи с номером 1 (`workspaces = ["work"]`) и номером 2 (`workspaces = ["surf", "work"]`), `work` активен на столе 1, `surf` — на столе 2, сессия запущена заново, и Chromium при запуске сам открыл оба своих окна
- **THEN** `chromium` запущен один раз; первое окно несёт теги `app:chromium#1` и `ws:work`, второе — `app:chromium#2`, `ws:surf` и `ws:work`; оба стоят на столе 1 в стопке `chromium` в ячейке `left`, и при переходе на стол 2 второе окно приходит туда

#### Scenario: Экземпляр отдельным процессом после перезагрузки
- **WHEN** в снимке у `neovide` запись с номером 1 без командной строки и запись с номером 2, командой `["neovide", "notes.md"]` и каталогом `~/notes`, обе в `work`, и сессия запущена заново
- **THEN** демон запускает `neovide` командой из конфига и `neovide notes.md` в `~/notes`; окна несут теги `app:neovide#1` и `app:neovide#2` независимо от того, какое появилось раньше, оба входят в `work` и стоят в стопке в ячейке `right`

#### Scenario: Общее окно после перезагрузки
- **WHEN** в снимке запись `chrome-ai` с номером 1, `workspaces = ["surf", "work"]` и прямоугольником 1700,60 1920×2140 для `surf`, у `work` запись о месте `chrome-ai`, и сессия запущена заново на столе 1 с `work`
- **THEN** `chrome-ai` запущен один раз, окно несёт теги `ws:surf` и `ws:work` и стоит на столе 1 на месте записи `work`; при переходе на стол 2 окно встаёт в прямоугольник 1700,60 1920×2140

#### Scenario: Перезапуск демона без повторных запусков
- **WHEN** снимок записан при двух окнах `chromium` и двух окнах `neovide` (второе — с командной строкой), окна живы, и демон перезапущен
- **THEN** ни одно приложение не запускается, у окон прежние номера экземпляров и теги состава, `workspaced status --json` показывает те же четыре окна

#### Scenario: Браузер не восстановил второе окно
- **WHEN** в снимке у `chromium` записи с номерами 1 и 2, сессия запущена заново, а Chromium открыл при запуске только одно окно
- **THEN** окно получает номер 1; нажатие Super+C снимает ожидание второго окна, и окно, открытое после этого по Ctrl+N, принимается в активный workspace своего стола по общим правилам

#### Scenario: Окно экземпляра не появилось
- **WHEN** запущенный по записи снимка процесс `neovide notes.md` завершился, не открыв окна
- **THEN** демон записывает предупреждение в журнал, остальные записи восстанавливаются, и запись больше не ждёт окна
