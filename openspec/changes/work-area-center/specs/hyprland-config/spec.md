## MODIFIED Requirements

### Requirement: Поведение окон
Новые окна MUST открываться плавающими с сохранением возможности перевести окно в мозаичный режим привязкой; расположение окон workspace по ячейкам задаёт демон workspaced (спецификация ws-daemon), собственная раскладка зон в конфиге Hyprland MUST NOT создаваться. Центрирование композитора MUST учитывать панель: новое плавающее окно без правила размещения, окно по правилу окна с `center` (окно выбора файла `termfilechooser`, Postman) и окно после диспетчера `window.center` MUST вставать по центру рабочей области — монитора за вычетом зоны, которую резервирует панель (спецификация qs-shell), — а режим maximized MUST разворачивать окно на рабочую область, не заходя под панель; отступы 10 px режим maximized не соблюдает, их даёт команда демона `maximize` (спецификация hyprland-binds). Помимо `special:hidden` для окон, скрытых пользователем, сессия MUST допускать специальный стол `special:pool` для окон, припаркованных демоном; переключение на него привязкой MUST NOT предусматриваться. Приложения Xwayland MUST поддерживаться: Xwayland включён, окна GTK-программ, запущенных с `GDK_BACKEND=x11`, и приложений AppImage отображаются без чёрных областей. Браузеры (Chromium, Google Chrome и Яндекс.Браузер из контейнера fedora-box) MUST работать нативно под Wayland (`--ozone-platform=wayland` в файле флагов Chromium и в ярлыках distrobox): под Xwayland печать через wtype даёт цифры вместо текста. Неполадки воспроизведения видео под Wayland MUST решаться без возврата браузера на X11.

#### Scenario: Новое окно плавающее
- **WHEN** из сессии запущен терминал
- **THEN** `hyprctl activewindow` показывает `floating: 1`

#### Scenario: Центрирование с учётом панели
- **WHEN** на столе без активного workspace открыто окно `wev` (640×480), затем ему заданы размер 1920×1080 и диспетчер `hl.dsp.window.center()`, затем режим maximized
- **THEN** новое окно стоит в 1765,840, после центрирования — в 1125,540 1920×1080, в режиме maximized занимает область правее панели (x не меньше 330), а `hyprctl monitors -j` показывает у DP-2 `reserved` `[330, 0, 0, 0]`

#### Scenario: Окно Xwayland
- **WHEN** из сессии запущена GTK-программа с `GDK_BACKEND=x11`
- **THEN** `hyprctl clients` показывает для неё `xwayland: 1`, окно отрисовано полностью

#### Scenario: Диктовка в браузер
- **WHEN** в поле ввода Google Chrome, Chromium или Яндекс.Браузера пользователь диктует фразу через voxtype
- **THEN** `hyprctl clients` показывает для окна `xwayland: 0`, в поле появляется распознанный текст, а не цифры

#### Scenario: Выход из полноэкранного видео в браузере
- **WHEN** в плавающем окне браузера на Chromium (Google Chrome, Яндекс.Браузер) видео переведено в полноэкранный режим и выведено из него по Esc, при этом браузер вслед за снятием fullscreen сразу запрашивает состояние maximized
- **THEN** `hyprctl clients -j` показывает у окна `fullscreen: 0` и прежние положение и размер (ячейку workspace), а не окно на всю рабочую область; обработчик события `window.fullscreen` в конфиге отменяет maximized, запрошенный в первые 50 мс после выхода из fullscreen

#### Scenario: Припаркованное окно
- **WHEN** демон перенёс окно на `special:pool`
- **THEN** `hyprctl clients -j` показывает у окна стол `special:pool`, окно не видно ни на одном столе, `hyprctl binds` не содержит привязки для показа `special:pool`
