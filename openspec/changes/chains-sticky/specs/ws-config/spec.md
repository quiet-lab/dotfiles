## MODIFIED Requirements

### Requirement: Цепочки клавиш и привязки
Цепочка MUST записываться строкой сочетаний через пробел, где сочетание — модификаторы и клавиша в синтаксисе Hyprland через `+` (`"SUPER+W 3 f"`); одиночное сочетание (`"SUPER+Return"`, `"XF86AudioMute"`, `"SUPER+mouse:272"`) — цепочка из одного звена. Короткая форма `chain` у workspace означает действие «поднять на текущем столе», у приложения и у записи приложения в таблице `apps` workspace — клавишу приложения: цикл по его экземплярам по правилам спецификации ws-daemon, «Цепочка приложения». Ключ приложения в workspace — `chain` его записи в этом workspace, а если его нет, собственный `chain` приложения; workspace откликается на цепочку, если в нём есть запись приложения с таким ключом. Переопределение освобождает собственную клавишу приложения в этом workspace: её может занять ключом другое приложение того же workspace. Переопределение, совпадающее с собственной клавишей приложения, ничего не меняет. Все приложения, отзывающиеся на одну цепочку собственной клавишей или ключом в каком-либо workspace, MUST давать одну привязку, вызывающую команду `workspaced key '<цепочка>'`; какое приложение и в каком workspace она вызывает, MUST решать демон при нажатии по активному workspace текущего стола. В `workspaced keys --list` у такой привязки MUST стоять действие `key <цепочка>`, а в колонке источника — все отозвавшиеся записи (`apps.<имя>` для собственной клавиши, `workspaces.<workspace>.apps.<имя>` для ключа в workspace). Запись `[[binds]]` MUST принимать ровно одно действие: `action` — таблица с любым сочетанием ключей `desktop` (1…8), `workspace` и `app` и необязательным логическим ключом `pull` (перетащить окна приложения в активный workspace текущего стола, спецификация ws-daemon, «Цепочка приложения»; ключ допустим только вместе с `app` и без `workspace`, иначе запись MUST отклоняться с указанием цепочки; действие с `pull = true` MUST вызывать команду `workspaced app <имя> --pull`; действие `{ app = "<имя>" }` без `workspace` MUST вызывать команду `workspaced app <имя>`, которая действует как собственная клавиша приложения), таблица `{ half = "left" | "right" | "up" | "down" }`, таблица `{ place = "top-left" | "top-center" | "top-right" | "bottom-left" | "bottom-center" | "bottom-right" | "center" | "full" }`, таблица `{ move = <стол 1…8> }` (перенести активный workspace текущего стола на этот стол) либо строка `"sessions"`, `"save-session"`, `"save-workspace"`, `"next-workspace"`, `"maximize"`, `"arrange"`, `"detach"` (убрать активное окно из активного workspace текущего стола, спецификация ws-daemon, «Отделение окна»); `exec` — командная строка, запускаемая композитором; `dispatch` — выражение диспетчера Hyprland без префикса `hl.dsp.` (`"window.close()"`) либо массив таких выражений, выполняемых по порядку одним вызовом; `lua` — тело функции на Lua, выполняемое композитором при нажатии. Необязательные строки `desc` (описание) и `group` (группа) записи `[[binds]]` MUST использоваться только перечнем для подсказки (требование «Перечень клавиш для подсказки») и MUST NOT влиять на привязку. Раздел `[keys]` MUST принимать необязательную таблицу `reserved_desc`: сочетание из списка `reserved` → его описание. Флаги `locked` (действует при заблокированном экране), `repeating` (повторяется при удержании), `mouse` (привязка к кнопке мыши с удержанием), `release` (срабатывает при отпускании) MUST передаваться композитору; `mouse` MUST быть допустим только у цепочки из одного звена. Поле `range = [от, до]` MUST разворачивать запись в серию: для каждого целого из диапазона подстрока `$n` в `chain`, `exec`, `dispatch` и в значении действия `move` и в `desc` заменяется числом. Значение `move` MUST читаться числом или строкой и MUST проверяться после разворачивания серии: до него на месте номера стоит `$n`. Стол вне диапазона 1…8 MUST приводить к отказу с указанием цепочки и полученного значения. Цепочки MUST быть произвольными; демон MUST NOT навязывать смысл сегментам. Одна цепочка MUST NOT совпадать с другой или быть её началом, в том числе одиночное сочетание с первым звеном цепочки; две цепочки с общим первым звеном и разными последующими MUST быть допустимы; две записи приложений одного workspace с одинаковым ключом MUST считаться ошибкой, в том числе когда ключ одной из них задан переопределением, а другой — собственной клавишей; одна цепочка у приложений из разных workspace MUST быть допустима. Цепочка переопределения MUST проходить те же проверки совпадения, начала цепочки и зарезервированных сочетаний, что и остальные цепочки. Сочетание из списка `reserved` раздела `[keys]` MUST NOT встречаться ни в одной цепочке. Демон MUST проверять эти условия при чтении и при ошибке называть обе конфликтующие записи либо запись и зарезервированное сочетание; ошибка двух записей одного workspace MUST называть workspace, оба приложения и цепочку.

Многозвенная цепочка MUST задавать режим клавиатуры с выходом на последнем звене (требование «Генерация привязок для Hyprland»): все цепочки с одним первым сочетанием из любых разделов конфига (`[keys]`, `chain` у workspace, у приложения и у записи приложения в workspace, `[[binds]]`) образуют один режим; общее промежуточное звено нескольких цепочек — вложенное состояние режима; последнее звено — клавиша выхода. Сравнение звеньев MUST вестись так же, как сравнение цепочек: модификаторы по порядку, клавиша без учёта регистра. Отдельного признака режима у записи MUST NOT быть: режимом становится каждая цепочка из двух и более звеньев. Звено после первого MUST NOT быть клавишей `Escape` или `BackSpace`, с модификаторами или без: в каждом состоянии режима они возвращают назад и закрывают режим. Два звена одного состояния с одной клавишей, у одного из которых нет модификаторов, MUST отклоняться как неразличимые: звено без модификаторов срабатывает при любых модификаторах. Звенья одной клавиши с разными непустыми наборами модификаторов MUST быть допустимы. Имя подкарты режима, совпадающее с именем подкарты корня цепочки с выходом (требование «Цепочки с выходом»), MUST отклоняться. Ошибки звеньев MUST называть цепочки и их записи.

### Requirement: Генерация привязок для Hyprland
Команда `workspaced keys --lua` MUST печатать код Lua для конфига Hyprland, который объявляет все привязки конфига: одиночные сочетания — прямыми привязками с их флагами, многозвенные цепочки — режимами (требование «Цепочки клавиш и привязки»), цепочки с выходом (требование «Цепочки с выходом») — прямой привязкой сочетания входа, открывающей подкарту корневого состояния `ws-sticky:<имя>`, и подкартой на каждое состояние (`ws-sticky:<имя>/<состояние>/…` по пути от корня). Первое сочетание многозвенных цепочек MUST давать одну прямую привязку, открывающую подкарту корня режима `ws-sticky:<первое сочетание>`, а каждое промежуточное звено — подкарту вложенного состояния `ws-sticky:<первое сочетание>/<второе>/…`; звено в имени подкарты MUST записываться в каноническом виде `keys --list`: модификаторы в порядке SUPER, CTRL, ALT, SHIFT через `+` и клавиша (`ws-sticky:SUPER+TAB`, `ws-sticky:SUPER+CTRL+s`, `ws-sticky:SUPER+W/3`). Одноразовых подкарт, которые закрываются после последнего звена, но не поглощают посторонние нажатия, MUST NOT быть.

В подкарте состояния цепочки с выходом MUST быть привязки клавиш состояния с `ignore_mods = true`: переход открывает подкарту дочернего состояния, действие выполняется без закрытия подкарты, действие клавиши с `exit` выполняется и закрывает подкарту. В подкарте состояния режима MUST быть привязки его звеньев: промежуточное звено открывает подкарту вложенного состояния, последнее звено выполняет действие своей цепочки и закрывает подкарту; звено без модификаторов MUST привязываться с `ignore_mods = true`, звено с модификаторами — с ними и без `ignore_mods`; флаги записи `[[binds]]` (`locked`, `repeating`, `release`) MUST сохраняться у её последнего звена. В каждой подкарте обоих видов MUST быть также: `BackSpace` с `ignore_mods = true`, открывающий подкарту родителя, а в корне закрывающий подкарту; `Escape` с `ignore_mods = true`, закрывающий подкарту на любом уровне; последней — привязка `catchall` с пустым действием (`hl.dsp.no_op()`) и `ignore_mods = true`, которая поглощает прочие нажатия. Действие `catchall` MUST оставаться пустым: композитор выполняет его и вместе с совпавшей привязкой. Код MUST заканчиваться проверкой текущей подкарты композитора: если её имя начинается с `ws:` (подкарты прежних версий) или `ws-sticky:` и такой подкарты в этом коде нет, подкарта MUST закрываться. Действия демона MUST вызывать соответствующую подкоманду; `exec`, `dispatch` и `lua` MUST выполняться композитором без участия демона. Код MUST зависеть только от конфига и быть одинаковым при повторных вызовах с тем же файлом. При успешной генерации команда MUST записать копию кода в `~/.local/state/workspaced/keys.lua`. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr, не печатать частичный код и не трогать копию.

Команда `workspaced keys --list` MUST печатать таблицу всех привязок: цепочка, действие, флаги и источник (раздел конфига), в порядке следования в файле. Многозвенная цепочка MUST выводиться одной строкой, как записана в конфиге, с флагом `exit` в колонке флагов после флагов записи. Цепочка с выходом MUST выводиться строками путей: сочетание входа с действием `sticky <имя>`, путь до каждого состояния (`SUPER+S r`) с действием `state <состояние>` и путь до каждой клавиши состояния (`SUPER+S r v`) с её действием; у клавиши с `exit` в колонке флагов MUST стоять `exit`, источник — `sticky.<имя>` для корня и `sticky.<имя>.<состояние>…` для вложенных состояний.

#### Scenario: Цепочка из трёх сочетаний
- **WHEN** в конфиге есть `[[binds]]` с `chain = "SUPER+W 3 f"` и `action = { desktop = 3, workspace = "dev-front" }`
- **THEN** `hyprctl binds -j` содержит подкарты `ws-sticky:SUPER+W` с переходом по `3` и `ws-sticky:SUPER+W/3` с клавишей `f`; нажатие Super+W, затем 3, затем f поднимает `dev-front` на столе 3 и закрывает режим; Super+W, 3, затем Backspace возвращает в `ws-sticky:SUPER+W`, а Escape ничего не делает и закрывает режим

#### Scenario: Подкарты цепочки с выходом
- **WHEN** в конфиге есть цепочка `[sticky.apps]` из требования «Цепочки с выходом» и выполнена `hyprctl reload`
- **THEN** `hyprctl binds -j` содержит подкарты `ws-sticky:apps`, `ws-sticky:apps/raise` и `ws-sticky:apps/spawn`, в каждой — привязки `BackSpace` и `Escape` и одну привязку с `catch_all: true`; в `ws-sticky:apps/raise` есть привязка `v`

#### Scenario: Режимы цепочек сессии
- **WHEN** в конфиге есть цепочки `SUPER+TAB Tab`, `SUPER+TAB w`, `SUPER+TAB s`, `CTRL+SUPER+s CTRL+SUPER+s` и `CTRL+SUPER+s CTRL+SUPER+w` и выполнена `hyprctl reload config-only`
- **THEN** `hyprctl binds -j` содержит подкарту `ws-sticky:SUPER+TAB` с клавишами `Tab`, `s`, `w` без модификаторов и подкарту `ws-sticky:SUPER+CTRL+s` с клавишами `s` и `w` с модификаторами Super и Ctrl (маска 68), в обеих — `BackSpace`, `Escape` и одна привязка с `catch_all: true`; подкарт с именем на `ws:` нет

#### Scenario: Устаревшая подкарта закрывается при перезагрузке
- **WHEN** командой `hyprctl eval 'hl.dispatch(hl.dsp.submap("ws-sticky:apps/raise"))'` открыта подкарта состояния, затем состояние `raise` удалено из конфига и конфиг перечитан
- **THEN** `hyprctl submap` печатает `default`; если бы состояние осталось в конфиге, подкарта осталась бы открытой

#### Scenario: Перезагрузка при ошибке конфига
- **WHEN** конфиг содержит ошибку и выполнена `hyprctl reload`
- **THEN** `workspaced keys --lua` завершается с ошибкой, `keys.lua` не изменяется, конфиг Hyprland загружает привязки из копии, а в журнале Hyprland есть сообщение об ошибке от `workspaced keys`

#### Scenario: Копия после успешной генерации
- **WHEN** конфиг корректен и выполнена `workspaced keys --lua`
- **THEN** содержимое `~/.local/state/workspaced/keys.lua` совпадает с напечатанным кодом

#### Scenario: Список привязок
- **WHEN** выполнена `workspaced keys --list`
- **THEN** в выводе есть строка с `SUPER+Return`, действием `exec wezterm-gui` и источником `binds`, строка с `SUPER+W d`, действием `raise dots`, флагом `exit` и источником `workspaces.dots`, и строка с `SUPER+CTRL+s SUPER+CTRL+w`, действием `save-workspace`, флагом `exit` и источником `keys.save_workspace`

### Requirement: Перечень клавиш для подсказки
Команда `workspaced keys --json` MUST печатать перечень всех привязок конфига в JSON вида `{ "groups": [ { "name": <группа>, "keys": [ { "chain", "label", "desc", "action", "source" } ] } ], "sticky": [ { "submap", "path", "keys": [ { "key", "label", "desc", "exit" } ] } ] }`. `chain` и `action` MUST совпадать с цепочкой и действием в выводе `keys --list`, `source` — раздел конфига (`keys.next_workspace`, `apps.herdr`, `workspaces.surf.apps.chrome`, `workspaces.work`, `binds[N]`, `keys.reserved`, `sticky.apps`, `sticky.apps.raise`). `label` MUST быть подписью для человека: модификаторы в порядке Ctrl, Alt, Shift, Super, звенья через пробел, `slash` — «/», `space` — «Пробел», `Return` — «Enter», стрелки — символами, кнопки мыши — «ЛКМ» и «ПКМ», без префикса `XF86`; буква с модификаторами заглавная. Команда MUST читать конфиг сама и MUST NOT требовать работающего демона. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr и MUST NOT печатать частичный перечень.

Группы MUST идти в порядке: Workspace, Столы, Приложения, Цепочки с выходом, Окна, Уведомления, Звук и яркость, Снимки экрана, Раскладка, Сессия и прочее; группа из поля `group`, которой нет в этом списке, MUST идти после них в порядке первого появления; пустая группа MUST NOT выводиться. Строки внутри группы MUST идти в порядке `keys --list`, зарезервированные сочетания — последними в группе «Раскладка». Запись `[[binds]]` с `range` MUST выводиться одной строкой, где `$n` в цепочке, описании и действии заменено подписью «от…до» («Super+1…8»). Каждое сочетание списка `reserved` MUST выводиться в группе «Раскладка» с описанием из `reserved_desc`, а без него — «Зарезервировано».

Без поля `group` группа MUST выводиться из источника и действия: цепочки workspace и служебные цепочки `[keys]`, действия `next-workspace`, `save-session`, `save-workspace`, `sessions`, `arrange` и `{ workspace = … }` — Workspace; `{ move = … }` и `dispatch` с переходом или переносом окна на стол (`workspace = ` без `special:`) — Столы; клавиши приложений и `{ app = … }` — Приложения; строки цепочек с выходом (`sticky.*`) — Цепочки с выходом; `half`, `place`, `maximize`, `detach` и прочие `dispatch` — Окна; `exec` с `ipc call notifications` — Уведомления; `exec` громкости, яркости и `playerctl`, цепочки `XF86Audio*` и `XF86MonBrightness*` — Звук и яркость; `exec` со `screenshot` — Снимки экрана; `dispatch` с `exit()`, прочие `exec` и `lua` — Сессия и прочее. Без поля `desc` описание MUST выводиться из действия: у действий демона — фразой по-русски («Окно в левую половину»), у клавиш приложений — по источнику («Приложение herdr», «chrome в workspace surf»), у цепочек workspace — «Поднять workspace <имя>», у `exec`, `dispatch` и `lua` — действием, как в `keys --list`. У сочетания входа цепочки с выходом описание — `title` корня, у пути до состояния — `title` состояния, у клавиши состояния — `title` её состояния и через « · » описание клавиши (`desc`, а без него — описание унаследованной клавиши приложения или описание действия); у клавиши с `exit` к описанию MUST добавляться « (выход)».

Раздел `sticky` MUST перечислять все состояния всех цепочек с выходом: `submap` — имя подкарты состояния (требование «Генерация привязок для Hyprland»), `path` — подписи (`title`) состояний от корня до этого состояния, `keys` — клавиши состояния в порядке файла, а унаследованные — после явных в порядке цепочек приложений: `key` — имя клавиши, `label` — её подпись по правилам `label`, `desc` — описание клавиши (для перехода — `title` дочернего состояния), `exit` — признак выхода. Раздел `sticky` MUST перечислять после них и все состояния режимов многозвенных цепочек: `submap` — имя подкарты состояния, `path` — подписи `label` звеньев от первого сочетания до этого состояния («Super+Tab», «Super+W», «3»), `keys` — звенья состояния в порядке строк `keys --list`: `key` — звено в каноническом виде `keys --list` (`w`, `SUPER+CTRL+w`), `label` — его подпись по правилам `label` («w», «Ctrl+Super+W»), `desc` — для последнего звена описание его цепочки, как у её строки в группах подсказки, для промежуточного — «Далее: » и подписи звеньев вложенного состояния через запятую, `exit` — `true` у последнего звена. Строки многозвенных цепочек в группах подсказки MUST оставаться прежними: одна строка на цепочку в группе по её действию.
