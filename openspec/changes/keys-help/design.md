## Context

Мотивация — в `proposal.md`. Все привязки сессии задаёт конфиг демона
workspaced (`dot_config/workspaced/config.toml`: раздел `[keys]`, цепочки
приложений и workspace, записи `[[binds]]`), `hyprland.lua` выполняет код,
который печатает `workspaced keys --lua` (спецификации hyprland-binds
и ws-config). Команда `workspaced keys --list` печатает таблицу «цепочка —
действие — флаги — источник» в порядке конфига. Описаний у привязок нет:
у записи `exec` действие — командная строка, у `dispatch` — выражение
диспетчера, у `lua` — первая строка тела функции.

Панель Quickshell уже показывает окна двух видов: всплывающие окна
у колонки (`PanelPopup`: история уведомлений, выбор сессии) и отдельные
окна layer-shell (столбик уведомлений на слое Overlay). IPC-цели панели
объявлены в синглтонах (`notifications` в `NotificationService.qml`).

## Goals / Non-Goals

**Goals:**

- Shift+Super+/ показывает все цепочки сессии, сгруппированные по
  назначению, с описанием каждой; повторное нажатие скрывает окно.
- Одно место правды: перечень строится из того же конфига, из которого
  строятся привязки, и не расходится с ними.
- Описания и группы задаются в конфиге там, где их нельзя вывести из
  действия.

**Non-Goals:**

- Поиск и фильтр в окне подсказки.
- Выполнение привязки кликом по строке.
- Описания у приложений и workspace: их строки подписываются именами
  из конфига.

## Decisions

### D1. Источник перечня — `workspaced keys --json`

Демон получает ключ `--json` у подкоманды `keys`. Команда, как и `--list`,
читает конфиг сама, проверяет его теми же проверками цепочек и к сокету
работающего демона не обращается. Поэтому новая подкоманда работает сразу
после пересборки бинарника, а перезапуск демона для окна подсказки
не нужен.

Формат вывода:

```json
{ "groups": [ { "name": "Workspace",
                "keys": [ { "chain": "SUPER+TAB w", "label": "Super+Tab w",
                            "desc": "Поднять workspace work",
                            "action": "raise work", "source": "workspaces.work" } ] } ] }
```

`chain` и `action` совпадают с колонками `keys --list`, `label` — подпись
для человека (D4), `source` — раздел конфига (`binds[N]` без цепочки).
При ошибке конфига команда завершается ненулевым кодом с текстом ошибки
в stderr, как `--list`.

Рассмотренные варианты:

- Разбирать в панели вывод `keys --list`. Отвергнуто: в таблице нет
  описаний и групп, а разбор колонок, выровненных пробелами, ломается
  на действиях с пробелами.
- Запрашивать перечень у работающего демона по сокету. Отвергнуто:
  перечень зависит только от файла конфига, состояние демона ему не нужно,
  а новый запрос потребовал бы перезапуска демона.

### D2. Группы и правило отнесения

Группы в порядке показа: Workspace, Столы, Приложения, Окна, Уведомления,
Звук и яркость, Снимки экрана, Раскладка, Сессия и прочее. Имя группы
из поля `group`, которого нет в этом списке, заводит новую группу после
них в порядке первого появления. Пустые группы не выводятся.

Группа без поля `group` выводится так:

| Источник или действие | Группа |
|---|---|
| `keys.save_session`, `keys.save_workspace`, `keys.sessions`, `keys.next_workspace`; цепочка workspace (`raise`); `action` `next-workspace`, `save-*`, `sessions`, `arrange`, `{ workspace = … }` | Workspace |
| `action = { move = … }` (`move-desktop`); `dispatch` с `workspace = ` без `special:` (переход на стол, перенос окна на стол) | Столы |
| клавиши приложений (`apps.*`, ключи записей workspace); `action = { app = … }` | Приложения |
| `action` `half`, `place`, `maximize`, `detach`; прочие `dispatch` (закрыть, спрятать, фокус, полноэкранный режим, мышь) | Окна |
| `exec` с `ipc call notifications` | Уведомления |
| `exec` с `change-volume`, `change-brightness`, `playerctl`; цепочки `XF86Audio*`, `XF86MonBrightness*` | Звук и яркость |
| `exec` с `screenshot` | Снимки экрана |
| список `reserved` раздела `[keys]` | Раскладка |
| `dispatch` с `exit()`; прочие `exec`; `lua` | Сессия и прочее |

Группа «Столы» добавлена к перечню из постановки задачи: три серии
Super+1…8, Shift+Super+1…8 и Ctrl+Super+1…8 относятся к столам, и в одной
группе они читаются вместе. Поэтому перенос workspace на стол
(`move-desktop`) стоит в «Столах», а не в «Workspace». Тело функции `lua`
демону непрозрачно, поэтому по умолчанию оно попадает в «Сессию и прочее»,
а Alt+Tab и Alt+Shift+Tab получили в конфиге `group = "Окна"`; лаунчер
Super+R — `group = "Приложения"`.

### D3. Поля `desc`, `group` и таблица `reserved_desc`

Запись `[[binds]]` принимает необязательные строки `desc` и `group`.
В серии `range` подстрока `$n` в `desc` заменяется так же, как в цепочке.
Описание без `desc` выводится из действия: у команд демона — готовой
фразой («Окно в левую половину», «Перенести workspace на стол 3 и перейти
туда»), у клавиш приложений — по источнику («Приложение herdr», «chrome
в workspace surf»), у цепочек workspace — «Поднять workspace work»;
у `exec`, `dispatch` и `lua` — действием, как в `keys --list`. Поэтому
всем существующим записям `exec`, `dispatch` и `lua` в конфиге заданы
описания, а записи с командами демона обходятся без них.

Описания зарезервированных сочетаний лежат в отдельной таблице
`[keys].reserved_desc` («сочетание» = «описание»), сравнение сочетаний —
как у проверки `reserved`: порядок модификаторов и регистр клавиши
не важны. Сочетание без описания подписывается «Зарезервировано».

Рассмотренный вариант: разрешить в списке `reserved` таблицы
`{ chain = …, desc = … }`. Отвергнуто: работающий демон со старым
бинарником перечитывает конфиг по событию записи и такой список
не разобрал бы, а незнакомые поля записи `[[binds]]` и раздела `[keys]`
он пропускает с предупреждением в журнале.

### D4. Подпись цепочки

Подпись строится из разобранной цепочки: модификаторы в порядке Ctrl, Alt,
Shift, Super (как пишет документация сессии: «Ctrl+Alt+Super+Z»,
«Shift+Super+B»), звенья через пробел. Клавиши: `slash` → «/», `space` →
«Пробел», `Return` → «Enter», `BackSpace` → «Backspace», `Page_Up` →
«PageUp», стрелки — символами «←→↑↓», `mouse:272`/`273` — «ЛКМ»/«ПКМ»,
префикс `XF86` отбрасывается. Имена сравниваются без учёта регистра, как
в Hyprland (`TAB` → «Tab»). Буква с модификаторами пишется заглавной
(«Super+T»), звено без модификаторов — как в конфиге («Super+Tab w»).
Подпись строит демон, а не панель: правило одно и проверяется тестами.

### D5. Серия `range` — одна строка

Запись с `range = [1, 8]` выводится одной строкой: `$n` в цепочке,
описании и действии заменяется подписью «1…8» («Super+1…8 — Перейти
на стол 1…8»). Восемь одинаковых строк на серию только удлиняли бы окно.

### D6. Окно подсказки — отдельное окно layer-shell, карточка по центру рабочей области

Окно — `PanelWindow` на слое Overlay на весь экран DP-2 (`exclusionMode`
Ignore, пространство имён `keys-help`, чтобы правило размытия слоя `panel`
не размывало весь экран). Экран под карточкой затемнён
(`rgba(0, 0, 0, 0.35)`), карточка по центру в оформлении плиток: заливка
`Theme.tileBg`, жёлтая рамка 1 px, скругление `Theme.tileRadius`, шрифт
`Theme.fontFamily`; строки набраны шрифтом 32 px, заголовок 36 px — вдвое
крупнее плиток панели, по замечанию пользователя 23.09.2026 (первый
вариант с 16 px он счёл слишком мелким). Карточка шириной 1920 px стоит
по центру рабочей области — экрана без полосы панели `Theme.panelWidth`
(330 px), той же зоны, которую панель объявляет композитору: x = 330 +
(3510 − 1920) / 2 = 1125, как ячейка `center` шаблонов демона и окно
1920×1080 после Alt+Super+Enter (изменение work-area-center, требование
пользователя 23.09.2026 «центрирование окон во всех сценариях должно
учитывать панель виджетов, в том числе для окна подсказок»). Сам слой
по-прежнему занимает весь экран: затемнение и закрытие кликом мимо
карточки действуют и над панелью. По высоте карточка занимает экран
от верхнего до нижнего отступа `Theme.margin` (10 px), то есть 2140 px. Сверху
заголовок «ГОРЯЧИЕ КЛАВИШИ» и напоминание «Shift+Super+/ или Escape —
закрыть», под ним жёлтая черта; эта шапка не прокручивается. Под ней
перечень одной колонкой: группы по порядку, заголовок группы — серым
прописными буквами, как заголовок окна истории уведомлений; строка
высотой 52 px — подпись цепочки жёлтым в колонке 580 px слева и описание
цветом текста справа. Строка, у которой подпись или описание не помещаются
в свою колонку, растёт по содержимому (D11). 73 строки с заголовками групп
занимают около 4500 px, поэтому колонка лежит во `Flickable` с обрезкой
по границе и прокручивается колесом мыши, перетаскиванием и клавишами
(D12). Клавиши принимает тот же приёмник, что и Escape: слой и так держит
клавиатуру монопольно. При каждом открытии прокрутка возвращается
в начало. `QtQuick.Controls` панель не использует,
поэтому вместо `ScrollBar` у правого края перечня нарисована полоска
шириной 6 px: её положение и длина следуют `visibleArea` области
прокрутки, а когда перечень помещается целиком, полоски нет. Таймеров
прокрутка не требует: положение меняется по событиям ввода.

Закрытие: повторная команда `toggle` (Shift+Super+/), Escape, клик мимо
карточки. Пока окно показано, слой берёт клавиатуру монопольно
(`WlrKeyboardFocus.Exclusive`), иначе Escape до окна не дойдёт; скрытое
окно не отображается и клавиатуру не держит, фокус возвращается окну,
у которого был. Привязки композитора действуют и при монопольной
клавиатуре слоя, поэтому повторное Shift+Super+/ закрывает окно. Сроков
показа нет.

Рассмотренные варианты:

- Всплывающее окно `PanelPopup` у колонки, как история уведомлений.
  Отвергнуто: окно у колонки нельзя закрыть клавишей (история
  уведомлений закрывается уходом указателя, а при открытии с клавиатуры
  указатель может быть где угодно) и прокручивать клавишами.
- Карточка во весь экран с группами в три колонки по 1180 px без
  прокрутки (первая реализация). Отвергнуто решением пользователя
  23.09.2026: окно должно быть шириной 1920 px, а перечень — одной
  колонкой с прокруткой.
- Слой подсказки только над рабочей областью (привязка к краям
  с учётом занятой зоны панели, `exclusionMode` Normal), карточка
  по центру слоя. Отвергнуто: затемнение не закрывало бы панель, и клик
  по панели при открытой подсказке уходил бы плиткам, а не закрывал окно.
  Смещение карточки на ширину панели внутри полноэкранного слоя даёт тот же
  центр без этих последствий.
- Центр по всему экрану (x = 960), как в первой реализации. Отвергнуто
  требованием пользователя: левая часть карточки уходила под панель
  по восприятию, центр не совпадал с главным окном workspace.

### D11. Перенос подписи и описания

Описание и подпись набраны с `wrapMode: Text.Wrap` без многоточия, каждое
в своей колонке: подпись — 580 px слева, описание — от 604 px до правого
края перечня. Высота строки — наибольшая из высот подписи и описания плюс
поля сверху и снизу, но не меньше 52 px. Поле равно
(52 − высота строки шрифта) / 2 по `FontMetrics` шрифта перечня, поэтому
однострочная строка выглядит как прежде, а у перенесённой первая строка
подписи и описания стоит там же, где стояла бы в строке 52 px. Режим
`Text.Wrap` в Qt переносит по границам слов, а слово длиннее колонки —
в любом месте, так что подпись из одного длинного сочетания тоже
не обрезается.

Проверка без глаз: `state` сообщает `wrapExtra` — на сколько пикселей
перечень выше, чем были бы строки по 52 px и заголовки групп по 80 px.
Ноль — ни одна строка не перенесена. При нынешнем конфиге (23.09.2026)
`wrapExtra=0`: шрифт IosevkaTermSlab NF моноширинный, 16 px на знак при
32 px, в колонку описаний (1244 px) входит 77 знаков, а самое длинное
описание — 53 знака («Развернуть окно; повторно — вернуть прежнюю
геометрию»); в колонку подписей входит 36 знаков, самая длинная подпись —
25 («Ctrl+Super+S Ctrl+Super+W»).

Шаг прокрутки «на строку» (стрелки, j/k) — постоянные 52 px, а не высота
текущей строки. Рассмотренный вариант: сдвигать на высоту строки у верхнего
края области. Отвергнуто: перечень состоит из заголовков групп по 80 px
и строк разной высоты, и шаг «по строке» потребовал бы искать строку под
краем при каждом нажатии, а заметной разницы для читающего не дал бы —
перенесённые строки редки, и 52 px — это одна строка текста.

### D12. Плавная прокрутка и клавиши

Сдвиг клавишами и колесом выполняет `NumberAnimation` по `contentY`
длительностью 150 мс с замедлением `Easing.OutCubic`. Цель нового сдвига
отсчитывается от цели идущей анимации, а не от нынешнего положения,
поэтому пять быстрых нажатий j сдвигают ровно на пять строк. Анимация
запускается событием ввода и кончается сама; таймером в смысле записи
[`0007`](../../../docs/decisions/0007-no-timers.md) она не является: это
отрисовка перехода, а не ожидание события по сроку.

`Behavior on contentY` отвергнут: он анимировал бы и каждый шаг
перетаскивания, и перечень отставал бы от пальца. Колесо перехватывает
`MouseArea` с `acceptedButtons: Qt.NoButton` поверх перечня: щелчок колеса
(`angleDelta` 120) — три строки с анимацией, точная прокрутка тачпада
(`pixelDelta`) — без анимации, она плавная сама. Перетаскивание и инерцию
по-прежнему ведёт `Flickable`; для экрана 4K заданы
`flickDeceleration: 4000` и `maximumFlickVelocity: 8000`, начало
перетаскивания останавливает анимацию.

Клавиши (требование пользователя 23.09.2026, клавиши в духе Vim —
дополнение пользователя в тот же день):

- ↓ и j, ↑ и k — строка, 52 px;
- Пробел и Ctrl+D, Shift+Пробел и Ctrl+U — половина высоты видимой части;
- PageDown и Ctrl+F, PageUp и Ctrl+B — высота видимой части без одной
  строки, чтобы строка у края осталась на экране;
- Home и g g — начало, End и G — конец;
- Escape — закрыть.

g g — два нажатия g подряд. Срока между ними нет: таймеры запрещены,
а Vim без срока (`notimeout`) ведёт себя так же. Первое g сбрасывает любая
другая клавиша, кроме одиночных Shift, Ctrl, Alt и Super: G набирается
с Shift, и нажатие Shift не должно терять пару.

Раскладка. Буква определяется так: если Qt сообщил латинскую клавишу
(`Qt.Key_A`…`Qt.Key_Z`), берётся она; иначе — по коду клавиши
`nativeScanCode`. Под Wayland Qt кладёт туда код XKB (код evdev + 8), он
от раскладки не зависит: j — 44, k — 45, d — 40, u — 30, f — 41, b — 56,
g — 42. При русской раскладке клавиша приходит кириллической (`о`, `л`,
`в`…), и буква находится по коду. Рассмотренные варианты:

- Только код клавиши. Отвергнуто: у виртуальной клавиатуры (wtype) карта
  собственная и коды не совпадают с XKB — проверка агентом показала, что
  при опоре на код Ctrl+D и G из wtype толковались как другие буквы.
  Порядок «клавиша, затем код» верен для обеих клавиатур.
- `nativeVirtualKey` (keysym). Отвергнуто: keysym зависит от раскладки —
  при русской это кириллица, та же проблема, что у `ev.key`.
- Таблица кириллических букв (о → j, л → k…). Отвергнуто: привязана
  к одной раскладке, а код клавиши работает при любой.

Ограничение: при латинской раскладке с другим порядком букв (Dvorak)
действует буква раскладки, а не положение клавиши; у пользователя
раскладки US и RU.

Проверка агентом: `wtype` подаёт клавиши в слой с монопольной
клавиатурой, а `state` сообщает цель прокрутки. Сочетания с Ctrl из wtype
до клиентов не доходят вовсе — ни до окна подсказки, ни до пробного окна
`wev` (с Alt доходят), поэтому Ctrl+D/U/F/B и русская раскладка
проверяются пользователем.

### D7. Загрузка перечня при открытии

Синглтон `KeysHelp.qml` запускает `~/.local/bin/workspaced keys --json`
процессом `Process` при каждом открытии окна: окно показывает конфиг
таким, каким он записан сейчас, без опроса и без слежения за файлом.
Вывод, поток ошибок и код выхода приходят тремя событиями в произвольном
порядке; разбор выполняется, когда пришли все три. Пока команда
выполняется, окно показывает прежний перечень, а при первом открытии —
«Загрузка…». При ненулевом коде выхода или выводе, который не разобрался
как JSON, окно показывает текст ошибки красным (ошибка конфига, бинарник
без ключа `--json`); разбор `keys --list` как запасной путь не делается
(D1).

### D8. Сочетание Shift+Super+/

Привязка записывается `SUPER+SHIFT+slash` — именем keysym, как
`SUPER+BackSpace`, `SUPER+Insert`, `CTRL+Escape` в том же конфиге.
Hyprland сверяет привязки по keysym первой раскладки карты XKB, пока
`input:resolve_binds_by_sym` выключен (проверено: `hyprctl getoption
input:resolve_binds_by_sym` — `false`, в `hyprland.lua` не задан), а первая
группа карты `dot_config/X11/xkb_custom` — `us`. Модификаторы при этом
в keysym не входят (так работает `SUPER+SHIFT+Z`). Поэтому сочетание
срабатывает и при русской раскладке, где на этой клавише точка, и вторая
привязка `SUPER+SHIFT+period` не нужна. Код клавиши (`code:61`) отвергнут:
он не нужен при этой настройке и нечитаем в `keys --list`. `hyprctl binds`
показывает привязку с `modmask` 65 (Super + Shift) и клавишей `slash`.

### D9. IPC-цель `keys`

Функции: `toggle` (привязка), `open`, `close` и `state` — строка
«shown|hidden groups=N rows=M card=x,y WxH scroll=цель/предел wrapExtra=N»
с пометками `loading` и `error=…` для проверки из оболочки. Сведения
о карточке и прокрутке окно пишет в свойство `view` синглтона привязкой
`Binding`: окно создаётся через `Variants`, и синглтон его не видит. Имя `show` не годится: `qs ipc call keys show`
печатает описание цели вместо вызова функции.

### D10. Перезапуск демона не нужен

Окно подсказки работает с пересобранным бинарником сразу: `keys --json`
выполняется отдельным процессом. Работающий демон со старым бинарником
при каждом перечитывании конфига пишет в журнал предупреждения
«неизвестный ключ конфига: binds.N.desc», но конфиг принимает.
Предупреждения уйдут после перезапуска демона, который делается
при удобном случае.

## Risks / Trade-offs

- [Описание, выведенное из `exec`, — командная строка] → новым записям
  `exec`, `dispatch` и `lua` задавать `desc`; без него строка всё равно
  показывается, только менее понятно.
- [Монопольная клавиатура слоя] → пока окно открыто, ввод в окна
  приложений невозможен; окно закрывается тремя способами и не остаётся
  на экране незаметно для пользователя.
