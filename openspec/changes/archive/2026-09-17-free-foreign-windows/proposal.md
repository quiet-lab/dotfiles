# Proposal: Окна, открытые во время работы, не входят в workspace до сохранения

## Why

Сейчас любое окно без тега, появившееся на столе с активным workspace, демон сразу привязывает к этому workspace: оно уходит на `special:pool` при поднятии другого workspace и возвращается вместе со своим, попадает в состав окон workspace для панели и при команде сохранения записывается в конфиг. То же происходит с окнами без тега при старте демона и с окном приложения конфига, вызванного по цепочке вне workspace. Пользователь хочет другого: окно, открытое по ходу работы (терминал из лаунчера, второй браузер, диалог), должно оставаться свободным и не следовать за workspace. Частью workspace оно становится только по явной команде сохранения `Super+Tab Super+S`.

## What Changes

- Постороннее окно (без тега `app:`) при появлении, при старте демона и при вызове приложения вне workspace MUST оставаться свободным: без привязки к активному workspace стола, без парковки и возврата вместе с ним, вне состава окон workspace для панели.
- Команда сохранения записывает в workspace посторонние окна, открытые на столе этого workspace: новое приложение в `[apps]` по команде процесса, либо уже описанное приложение под своим именем. Сохранённое окно получает тег `app:<имя>`, перестаёт быть посторонним, назначение ячеек workspace пересобирается из записанного конфига.
- Свободные окна на других столах и окна на `special:hidden` командой сохранения не записываются.
- Привязка постороннего окна к workspace исчезает из состояния демона и из снимков сессии: в снимке у постороннего окна остаются стол, команда, каталог и прямоугольник; поле `workspace` прежних снимков читается и не учитывается.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `ws-daemon`: требование «Посторонние окна» — окно остаётся свободным до команды сохранения.
- `ws-config`: требование «Запись по команде сохранения» — какие посторонние окна записываются и что с ними происходит после записи.
- `ws-sessions`: требование «Файлы сессий» — постороннее окно в снимке без привязки к workspace.

## Impact

- Проект `~/work/pets/workspaced`: `state.rs` (структура постороннего окна без привязки), `daemon.rs` (появление окна, поднятие и удаление workspace, состояние для панели и `status`), `session.rs` (снимок и восстановление), `save.rs` (отбор окон по столу, тег, сброс назначений ячеек), `main.rs` (вывод `status`).
- Спецификации ws-daemon, ws-config и ws-sessions; AGENTS.md.
- Конфиг и привязки не меняются. Снимки прежних версий читаются: поле `workspace` у постороннего окна разбирается и отбрасывается.
