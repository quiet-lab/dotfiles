## ADDED Requirements

### Requirement: Захват открытых окон приложения
Если у приложения заданы `class` и, при необходимости, `title`, то при поднятии workspace с этим приложением и при вызове приложения по цепочке демон, не найдя окна с тегом `app:<имя>`, MUST найти среди открытых окон на любом столе и на `special:pool` окно, класс которого целиком совпадает с регулярным выражением `class`, а заголовок — с `title` (если задано), и без тега либо с тегом приложения, отсутствующего в конфиге; окно на `special:hidden` MUST NOT захватываться. Найденное окно MUST получить тег `app:<имя>` (прежний тег снимается) и дальше MUST считаться окном приложения: переноситься на стол, ставиться в ячейку, участвовать в цепочке и сессии. Если подходящих окон несколько, захватывается одно; остальные остаются посторонними. Если подходящего окна нет, приложение MUST быть запущено, как раньше. Приложение без `class` MUST NOT захватывать чужие окна. Окно с тегом приложения, которого нет в конфиге, и не захваченное никем, MUST считаться посторонним: при поднятии workspace оно MUST NOT парковаться на `special:pool`.

#### Scenario: Открытый Chromium попадает в workspace
- **WHEN** у приложения `chromium` задано `class = "(?i)^chromium(-browser)?$"`, на столе 3 открыто окно класса `Chromium-browser` без тега, и на столе 1 поднят workspace `work` с `chromium` в ячейке `left`
- **THEN** окно получает тег `app:chromium`, переносится на стол 1 в ячейку `left`, новый Chromium не запускается

#### Scenario: Терминал с herdr отличается заголовком
- **WHEN** у приложения `herdr` заданы `class = "^org\\.wezfurlong\\.wezterm$"` и `title = "^herdr · "`, открыты два окна wezterm: с заголовком «herdr · dev-lab» и «bash · mne@dev-lab», и поднят `work`
- **THEN** захватывается окно с заголовком «herdr · dev-lab», второе окно остаётся посторонним

#### Scenario: Окно с тегом удалённого приложения
- **WHEN** окно neovide несёт тег `app:editor-dots`, приложения `editor-dots` в конфиге больше нет, а у `neovide` задано `class = "^neovide$"`, и поднят `work`
- **THEN** тег `app:editor-dots` снят, окно получает тег `app:neovide` и занимает ячейку `right`

#### Scenario: Подходящего окна нет
- **WHEN** окон класса `neovide` нет и поднят `work`
- **THEN** демон запускает `neovide`, как для любого приложения без окна

#### Scenario: Окно с устаревшим тегом остаётся на столе
- **WHEN** окно firefox несёт тег `app:firefox`, приложения `firefox` в конфиге нет, и на его столе поднят `work`
- **THEN** окно остаётся на столе там же, где было, а не уходит на `special:pool`

## MODIFIED Requirements

### Requirement: Идентификация окон
Демон MUST запускать приложения сам (отдельная сессия процессов, каталог `cwd`, сложенное окружение) и сопоставлять появившееся окно с приложением по pid процесса или его потомков; если у приложения заданы `class` и, при необходимости, `title`, окно, которому эти выражения соответствуют, MUST сопоставляться с ожидающим приложением и без совпадения по pid, так как окно приложения из контейнера (distrobox, podman) не является потомком запущенного процесса. После сопоставления окно MUST получить тег `app:<имя>` в композиторе, по которому оно опознаётся при перезапуске демона. Окно, не появившееся в течение 30 секунд после запуска, MUST считаться не запустившимся с записью в журнал. Если процесс завершился без окна, а в системе уже есть окно того же исполняемого файла без тега (одноэкземплярное приложение вроде Telegram), демон MUST считать это окно окном приложения. Окна без тега MUST считаться посторонними.

#### Scenario: Тег после запуска
- **WHEN** демон запустил `editor-front` и его окно появилось
- **THEN** `hyprctl clients -j` показывает у окна тег `app:editor-front`

#### Scenario: Окно из контейнера
- **WHEN** у приложения `chrome` задано `class = "(?i)^google-chrome$"`, демон запустил его через `distrobox-enter`, и через две секунды появилось окно класса `google-chrome`, чей процесс не потомок `distrobox-enter`
- **THEN** окно сразу получает тег `app:chrome` и занимает свою ячейку, а не остаётся посторонним до следующего поднятия workspace

#### Scenario: Перезапуск демона
- **WHEN** демон перезапущен при открытых окнах трёх приложений с тегами
- **THEN** после старта `workspaced status --json` показывает эти окна у их приложений, ни одно приложение не запускается повторно
