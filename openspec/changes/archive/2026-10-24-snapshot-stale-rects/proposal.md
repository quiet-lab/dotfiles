## Why

После перезагрузки workspace `work` расставил окна по прежнему шаблону
`thirds` (ячейки `left`, `center`, `right`), хотя в конфиге у него шаблон
`thirds-split`. Снимок сессии записан до смены шаблона. Загрузка снимка
отбрасывала его раскладку `work` как называющую ячейку `left`, которой
в шаблоне нет (изменение home-mode-layout, решение D10), но у окон снимка
оставались прямоугольники для `work`, снятые по старым ячейкам, и окна,
восстановленные по записям снимка, вставали в них.

## What Changes

- Раскладка workspace из снимка, снятая не по нынешнему шаблону,
  отбрасывается вместе с прямоугольниками окон снимка для этого workspace:
  окна встают на места раскладки, собранной из конфига. Прямоугольники
  окон для других workspace и записи дополнительных приложений сессии
  остаются.
- Снимок пишет у раскладки workspace геометрию ячеек его шаблона
  (таблица `grid`). Раскладка считается устаревшей не только по имени
  исчезнувшей ячейки, но и когда ячейка из таблицы снимка исчезла или
  стоит теперь в другом прямоугольнике. Снимок без таблицы сверяется
  только по именам ячеек.
- Правило, прежде записанное только в решении D10 изменения
  home-mode-layout, становится требованием.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-sessions`: новое требование «Раскладка снимка по устаревшему
  шаблону».

## Impact

- Демон workspaced: `src/state.rs` (поле `grid` у `SessionWorkspace`),
  `src/session.rs` (`template_grid`, `stale_layout`,
  `forget_stale_layouts` при чтении снимка для загрузки и восстановления,
  геометрия ячеек в `session_workspaces`).
- Документы: `docs/window-model.md` (раздел 2.7), `AGENTS.md` (он же
  `CLAUDE.md`).
