# Design: Буфер ввода Claude Code в neovim

## Context

Требование пользователя — в `proposal.md`. Claude Code работает в панели
herdr; у herdr есть сокет с методами `pane.split`, `pane.get`,
`pane.layout`, `pane.resize`, `pane.send_text`, `pane.send_keys`,
`pane.send_input`, `pane.close` и подпиской `events.subscribe` (документ
`socket-api.mdx` форка herdr, `herdr api schema --json`). Режим ввода
Claude Code у пользователя — vim (`editorMode = "vim"` в `~/.claude.json`).

Сверка с живой системой перед проектированием (herdr 0.9.5, Claude Code
2.1.319):

- `pane.send_text` пишет в терминал панели байты как есть.
  `pane.send_input` оборачивает текст рамкой bracketed paste, если
  программа её включила, и дописывает клавиши после текста;
  `pane.send_keys` кодирует клавиши по текущему режиму клавиатуры
  терминала (протокол kitty или обычные байты).
- Сервер herdr отвечает на один запрос и закрывает соединение;
  соединение остаётся открытым только у подписки `events.subscribe`.
- `pane.split` с `ratio` задаёт долю исходной панели; у панелей
  в разбиении прямоугольник выше области вывода на 2 строки (рамка),
  одиночная панель рамки не имеет. `pane.resize` с `amount` сдвигает
  разделитель на эту долю высоты разбиения. Выход процесса панели
  закрывает панель.
- Новая панель получает `HERDR_ENV`, `HERDR_PANE_ID`,
  `HERDR_SOCKET_PATH` и переменные из `--env`; запуск bash в ней занимает
  1–2 с, ввод до готовности оболочки копится в терминале.

## Пробы

Пробы шли в отдельном workspace herdr на Claude Code 2.1.319
(`claude --model sonnet`). Содержимое строки ввода снималось через
Ctrl+G с `VISUAL`, указывающим на сценарий, который копирует файл
запроса и сразу выходит.

### П1. Очистка строки ввода

- `ctrl+u` стирает только текущую строку многострочного ввода, повтор
  не даёт предсказуемого результата.
- `esc g g d G i` одним вызовом `send-keys` очищает ввод, пока Claude
  Code держит протокол клавиатуры kitty: herdr кодирует Esc как
  `CSI 27 u`. После возврата из внешнего редактора (Ctrl+G) Claude Code
  этот протокол не восстанавливает, herdr шлёт Esc голым байтом `0x1b`,
  и Claude Code читает Esc со следующей `g` как Alt+g: в строку попадает
  `gdGi`, старый текст остаётся. Отдельные запросы для Esc и для
  остальных клавиш не помогают: байты приходят в одном чтении.
- Esc в кодировке kitty (`ESC [ 2 7 u`), отправленный сырыми байтами,
  Claude Code понимает в обоих состояниях.
- Открытое меню подсказок закрывается первым Esc, а режим vim остаётся
  INSERT: меню `/` (`/he`, `/help`, `/`) после такого Esc превращало
  `ggdGi` в текст. Меню `@` закрывает и пробел, меню `/` — нет. `ctrl+u`
  стирает строку с `/`, и меню закрывается само.
- Режим оболочки (`!` в начале) очисткой `ggdG` не снимается;
  Backspace на пустом вводе его снимает.

Итог: очистка — сырые байты `i`, `ctrl+u` (`0x15`), `ESC [ 2 7 u`, `g`,
`g`, `d`, `G`, `i`, Backspace (`0x7f`). Последовательность прошла
в серии случайных многострочных замен (30 из 30), после меню `/` и `@`,
в режиме оболочки, из режима NORMAL и после Ctrl+G.

### П2. Esc при работающем агенте и при диалоге

- Ход агента (`!sleep 15`, статус herdr `working`): первый Esc из INSERT
  только переводит строку в NORMAL (внизу «esc to interrupt»), второй
  Esc из NORMAL прерывает ход.
- Очистка начинается с `i`: из NORMAL она переводит в INSERT, в INSERT
  печатает букву, которую затем стирает `ggdG`. Поэтому Esc очистки
  всегда приходит из INSERT и ход не прерывает.
- Диалог AskUserQuestion даёт статус `blocked`; Esc закрывает диалог.
  Местный диалог `/help` статуса не меняет (`idle`), и Esc очистки
  закрывает его.

Итог: трансляция идёт при статусе `idle` и `working`; при `blocked`
отправка откладывается до смены статуса (D4). Очистка без Esc
не найдена.

### П3. Многострочный текст

- Перевод строки `0x0a` в сыром тексте вставляет новую строку и запрос
  не отправляет; 60 коротких строк сырым текстом показываются целиком.
- Кусок сырого ввода длиннее ~800 знаков (знаков, а не байт: 790
  кириллических знаков — 1580 байт — проходят) Claude Code считает
  вставкой и показывает `[Pasted text #N]`; префикс очистки в том же
  куске попадает внутрь вставки, и старый текст остаётся.
- Рамка bracketed paste сворачивает уже 15 строк в
  `[Pasted text #N +14 lines]`, но содержимое запроса сохраняется
  целиком, а префикс очистки до рамки работает.
- `0x0d` (Enter) в том же куске после текста отправляет запрос.

Итог: текст до 700 знаков без управляющих символов, кроме `0x0a`, идёт
сырыми байтами и виден в строке ввода как есть; более длинный или
с управляющими символами — в рамке bracketed paste после префикса
очистки. Строка ввода показывает его как `[Pasted text #N …]`,
отправляется он целиком.

### П4. Задержка

Замер `probe/p4.py` каталога задачи: запрос `pane.send_text` с полной
заменой — 0,3–1,3 мс, новое содержимое на экране Claude Code — 12–17 мс
для 20–700 знаков (изредка ~100 мс). Перепечатка всего буфера на каждое
изменение незаметна; переход на отправку по `InsertLeave` не нужен.

## Goals / Non-Goals

**Goals:**
- Панель буфера 13 строк под панелью Claude Code, открывается и закрывается
  вместе с сессией.
- Строка ввода Claude Code всегда повторяет буфер; `:w` отправляет запрос.

**Non-Goals:**
- Обратная трансляция (правка в строке Claude Code не попадает в буфер).
- Поддержка Claude Code без режима vim.

## Decisions

### D1. Очистка и замена одним запросом

Каждое изменение буфера — один запрос `pane.send_text` с текстом
`PREFIX .. payload`, где `PREFIX = "i\x15\x1b[27uggdGi\x7f"` (П1, П2),
а `payload` — содержимое буфера (строки через `\n`, без завершающего
перевода строки) сырыми байтами, если в нём не больше 700 знаков
и нет управляющих символов, кроме `\n`; иначе
`"\x1b[200~" .. содержимое .. "\x1b[201~"` (П3). Пустой буфер даёт
только `PREFIX`. Один запрос исключает гонку между очисткой и текстом:
байты одного запроса уходят в терминал одной записью.

Отвергнуто: `send-keys esc g g d G i` (ломается без протокола kitty, П1);
`ctrl+c` (на пустой строке второй подряд закрывает Claude Code, при ходе
прерывает его); подсчёт строк и `ctrl+u` (зависит от положения курсора).

### D2. Отправка запроса по `:w`

`BufWriteCmd` шлёт один запрос `PREFIX .. payload .. "\r"`: строка ввода
заново получает ровно содержимое буфера, и Enter отправляет его (П3).
После ответа сервера буфер очищается и признак изменения снимается.
Пустой буфер `:w` не отправляет. При статусе `blocked` `:w` ничего
не отправляет, буфер не очищается, neovim сообщает, что Claude Code ждёт
ответа в диалоге.

### D3. Транспорт: сокет herdr из `vim.uv`, соединение на запрос

Путь сокета — `HERDR_SOCKET_PATH`, без неё — `~/.config/herdr/herdr.sock`.
Запрос — строка JSON с `\n`, ответ — одна строка JSON; сервер закрывает
соединение после ответа, поэтому на каждый запрос открывается новое
соединение `vim.uv.new_pipe():connect()`. Процессов на клавишу нет.

Цепочка одной отправки: `pane.get` панели Claude → по `agent_status`
решение → `pane.send_text`. В полёте одна цепочка; изменение во время
цепочки ставит признак «грязный», и после ответа уходит последнее
состояние буфера. Таймеров и отложенных повторов нет (запись решения
`docs/decisions/0007-no-timers.md`).

### D4. Статус `blocked` — ожидание по подписке

Если `pane.get` вернул `blocked`, отправка откладывается: открывается
одно соединение `events.subscribe` с подпиской
`{ "type": "pane.agent_status_changed", "pane_id": <панель Claude> }`;
событие со статусом не `blocked` закрывает подписку и запускает отправку
последнего состояния. Обрыв подписки (`events_lost`, закрытие)
снимает ожидание, следующая правка буфера начинает цепочку заново.

### D5. Панель: разбиение на 13 строк и соответствие панелей

`open`: высота H — прямоугольник панели Claude из `pane.layout`;
`ratio = (H - 15) / H` (13 строк вывода и 2 строки рамки), после
`pane.split --direction down --no-focus --env CLAUDE_INPUT_PANE=<панель
Claude>` проверяется `viewport_rows` новой панели и при расхождении
разделитель сдвигается `pane.resize --direction up|down --amount
|13 - rows| / H`. Затем `herdr pane run <новая> 'exec nvim +ClaudeInput'`:
`exec` делает neovim процессом панели, и `:q` закрывает панель.
Соответствие «панель Claude → панель буфера» — файл
`${XDG_STATE_HOME:-~/.local/state}/claude-input/<панель Claude с : → _>`
с идентификатором панели буфера; `open` не создаёт панель, если файл
указывает на живую панель того же workspace, `close` закрывает её
и удаляет файл. Если панель Claude меньше 13 + 2 + 5 строк, `open`
ничего не делает.

### D6. Плагин neovim — локальный каталог

Модуль `lua/claude_input/init.lua` лежит в
`dot_config/nvim/local/claude-input/`, спецификация lazy.nvim —
`lua/plugins/claude-input.lua` с `dir` на этот каталог и `cmd =
"ClaudeInput"`. В `lazy-lock.json` локальные плагины не попадают.

## Risks / Trade-offs

- [Местный диалог Claude Code (`/help`, `/model`) статуса не меняет,
  и правка буфера во время такого диалога закрывает его Esc очистки] →
  принимается: пользователь, работающий в диалоге Claude Code, буфер
  в это время не правит.
- [`?` на пустой строке Claude Code открывает справку и в строку
  не попадает] → строка ввода расходится с буфером, пока он начинается
  с `?`; принимается.
- [Текст длиннее 700 знаков Claude Code показывает как
  `[Pasted text #N]`] → содержимое видно в буфере neovim, отправляется
  целиком.
- [Статус панели Claude Code в herdr определяется по экрану и на экране
  доверия к папке при запуске бывает и `blocked`, и `idle`; текст,
  переданный до окончания запуска Claude Code, теряется или попадает
  в строку ввода позже] → принимается: панель буфера открывает хук
  `SessionStart`, то есть уже после экрана доверия, и пользователь начинает
  набор после запуска. Отложенная отправка при `blocked` проверена
  на поддельном сервере herdr (`tests/deferred_spec.lua` каталога задачи).
- [Изменение вида строки ввода или режима vim в новой версии Claude Code]
  → сверка проб при обновлении; признак — расхождение строки ввода
  с буфером.
