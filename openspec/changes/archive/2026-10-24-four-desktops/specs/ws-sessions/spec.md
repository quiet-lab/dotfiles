## ADDED Requirements

### Requirement: Столы снимка за числом столов
При загрузке снимка сессии — при старте демона и по команде `session load` — демон MUST отбросить записи снимка, относящиеся к столу с номером больше N (число столов из ключа `desktops`, спецификация ws-config, «Число столов»): список workspace такого стола, окно приложения без workspace и постороннее окно, записанные с таким столом. О каждой отброшенной записи демон MUST писать предупреждение в журнал с номером стола и тем, что отброшено; пустой список стола, который снимки прежних версий писали для всех восьми столов, MAY отбрасываться без предупреждения. Окна, уже открытые на экране, отброшенная запись MUST NOT трогать: демон их не закрывает и не переносит. Запись окна, входящего в workspace, MUST оставаться: стол снимка для такого окна при восстановлении не учитывается, и окно встаёт по правилу размещения своего workspace. Активный стол снимка с номером больше N MUST заменяться столом 1. Сам файл снимка при загрузке MUST NOT переписываться: он меняется только командами сохранения.

#### Scenario: Снимок восьми столов при четырёх столах
- **WHEN** в снимке `default` есть пустые списки столов 5…7 и окно Firefox на столе 4, а в конфиге `desktops = 4`, и демон перезапущен
- **THEN** списки столов 5…7 отброшены, окно Firefox восстанавливается на столе 4, `workspaced status --json` показывает столы 1…4

#### Scenario: Окно на столе за числом столов
- **WHEN** в снимке записано постороннее окно на столе 6, на столе 5 — список с workspace `dev`, а в конфиге `desktops = 4`
- **THEN** окно стола 6 не запускается, список стола 5 не восстанавливается, в журнале по предупреждению о каждой записи; окна, открытые на экране, остаются, где стоят
