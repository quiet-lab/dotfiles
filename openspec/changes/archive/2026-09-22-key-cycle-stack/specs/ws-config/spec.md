## MODIFIED Requirements

### Requirement: Файл конфига и его разделы
Демон MUST читать конфиг из `~/.config/workspaced/config.toml` (файл под chezmoi). Файл MUST состоять из разделов: `[env]` — общие переменные окружения; `[keys]` — цепочки служебных действий `save_session`, `save_workspace`, `sessions`, `next_workspace` и список `reserved` зарезервированных сочетаний; `[templates.<имя>]` — шаблон геометрии с полем `main` (имя главной ячейки) и таблицей `cells`, где каждая ячейка — прямоугольник `{ x, y, w, h }`; `[apps.<имя>]` — приложение с полями `cmd` (команда запуска), `args` (массив), `cwd`, `env` (таблица), `chain`, `class` и `title` (регулярные выражения для захвата открытого окна по классу и заголовку; `title` без `class` не допускается), `family` (имя приложения-семейства, если это приложение — его вариант) и `rect` (прямоугольник `{ x, y, w, h }` — положение и размер окна по умолчанию, когда workspace об этом приложении ничего не говорит); `[startup]` — `workspace` (имя существующего workspace, который поднимается при старте демона) и `desktop` (стол 1…8, по умолчанию 1); `[workspaces.<имя>]` — workspace с полями `template` (обязательно), `main` (имя приложения в главной ячейке по умолчанию), `icon`, `chain`, `env`, `mode` и таблицей `apps`, где значение — имя ячейки шаблона либо таблица `{ rect = { x, y, w, h } }` для окна вне ячеек; `[[binds]]` — записи с полем `chain`, ровно одним из полей действия `action`, `exec`, `dispatch`, `lua` и необязательными `range`, `locked`, `repeating`, `mouse`, `release`. Поле `mode` MUST задавать поведение клавиши приложения в этом workspace (спецификация ws-daemon, «Цепочка приложения» и «Расстановка окон») и принимать значения `swap` — обмен ячеек — и `stack` — подъём окна без переноса; по умолчанию MUST действовать `swap`, а иное значение MUST приводить к отказу с указанием workspace, полученного значения и допустимых. Порядок записей в таблице `apps` workspace MUST сохраняться таким, как в файле: по нему конец цикла клавиши выбирает следующее приложение workspace, а приложения, добавленные сессией, MUST идти после описанных в файле. У приложения MUST быть задано хотя бы одно из полей `cmd` и `class`: без `cmd` приложение не открывает новых окон и только собирает подходящие по `class`, без `class` окно узнаётся лишь по запуску. Поле `family` MUST называть другое приложение того же файла, у которого самого нет `family`: уровней ровно два — семейство и его варианты. Имя приложения MUST NOT содержать двоеточие и знак `#`: этими знаками демон отделяет части тега экземпляра. Прямоугольники ячеек, `rect` приложения и `rect` в таблице `apps` workspace — это положение и размер окна на экране как есть: демон MUST передавать их композитору без прибавления или вычитания отступов. Координаты прямоугольников MUST отсчитываться от левого верхнего угла экрана: целое число — пиксели, строка с процентом — доля ширины или высоты монитора; смешивать формы в одном прямоугольнике MUST быть можно. Координаты MUST допускать отрицательные значения, а размеры — значения больше экрана: окно может выходить за его края частично с любой стороны, демон MUST передавать такие значения композитору без обрезания и без сдвига внутрь экрана. Необязательный ключ `gap` в корне файла задаёт зазор в пикселях только для команд `half`, `place` и `maximize`, которые строят геометрию от рабочей области; по умолчанию 0. Неизвестные ключи MUST приводить к предупреждению в журнале, но не к отказу.

#### Scenario: Минимальный конфиг
- **WHEN** файл содержит один шаблон `halves` с ячейками `left` и `right`, одно приложение `terminal` с `cmd = "wezterm-gui"` и один workspace `work` с `template = "halves"`, `main = "terminal"` и `apps = { terminal = "right" }`
- **THEN** `workspaced check` завершается успешно и выводит один workspace, одно приложение и один шаблон

#### Scenario: Режим workspace
- **WHEN** у workspace `surf` задано `mode = "stack"`, а у `work` поля `mode` нет
- **THEN** `workspaced check` завершается успешно, `surf` работает подъёмом окон, `work` — обменом ячеек; конфиг с `mode = "stak"` отклоняется с указанием workspace, значения `stak` и допустимых `swap` и `stack`

#### Scenario: Порядок приложений в разделе workspace
- **WHEN** в разделе `surf` приложения записаны в порядке `chrome`, `yandex-browser`, `chrome-ai`
- **THEN** демон держит их в этом порядке, и конец цикла клавиши переходит от `chrome` к `yandex-browser`, а не к `chrome-ai` по алфавиту

#### Scenario: Цепочки сохранения сессии и записи в конфиг
- **WHEN** в `[keys]` заданы `save_session = "CTRL+SUPER+s CTRL+SUPER+s"` и `save_workspace = "CTRL+SUPER+s CTRL+SUPER+w"`
- **THEN** `workspaced check` завершается успешно, а `workspaced keys --list` показывает для первой цепочки команду `save-session`, для второй — `save-workspace`

#### Scenario: Класс, заголовок и стартовый workspace
- **WHEN** у приложения `herdr` заданы `class = "^wezterm-herdr$"` и `title = "^herdr · "`, а в `[startup]` — `workspace = "work"`
- **THEN** `workspaced check` завершается успешно; конфиг с `title` без `class`, с некорректным регулярным выражением или с `startup.workspace`, которого нет среди workspace, отклоняется с указанием поля

#### Scenario: Семейство и его вариант
- **WHEN** в файле есть `[apps.wezterm]` с `cmd = "wezterm-gui"` и `class = "^org\\.wezfurlong\\.wezterm$"`, а `[apps.herdr]` содержит `family = "wezterm"`, свою команду запуска и `class = "^wezterm-herdr$"`
- **THEN** `workspaced check` завершается успешно и показывает `herdr` как вариант семейства `wezterm`; конфиг, где `family` называет приложение, которого нет, где вариант указан вариантом другого варианта или где приложение названо своим же семейством, отклоняется с указанием приложения и поля

#### Scenario: Приложение без команды запуска
- **WHEN** у приложения `wezterm` задан только `class`, без `cmd`
- **THEN** `workspaced check` завершается успешно: приложение собирает окна, но само их не открывает; конфиг с приложением без `cmd` и без `class` отклоняется с указанием приложения

#### Scenario: Положение окна по умолчанию у приложения
- **WHEN** у приложения `neovide` задано `rect = { x = 1125, y = 10, w = 1920, h = 2140 }`, и ни один workspace его не описывает
- **THEN** `workspaced check` завершается успешно, а окно `neovide`, открытое по его цепочке, встаёт в этот прямоугольник

#### Scenario: Проценты и пиксели в одной ячейке
- **WHEN** ячейка задана как `{ x = 330, y = 0, w = "50%", h = "100%" }` на мониторе 3840×2160
- **THEN** демон считает прямоугольник 330,0 размером 1920×2160

#### Scenario: Окно шире экрана со сдвигом за левый край
- **WHEN** ячейка задана как `{ x = -400, y = -150, w = 5000, h = 2600 }` и в неё поставлено окно при `gap = 5`
- **THEN** `hyprctl clients -j` показывает у окна положение −400,−150 и размер 5000×2600

#### Scenario: Ссылка на несуществующую ячейку
- **WHEN** workspace ссылается на ячейку `top`, которой нет в его шаблоне
- **THEN** `workspaced check` завершается с ошибкой, называющей workspace, приложение и ячейку; демон продолжает работать с прежним конфигом

#### Scenario: Запись привязки с двумя действиями
- **WHEN** запись `[[binds]]` содержит и `exec`, и `dispatch`
- **THEN** `workspaced check` завершается с ошибкой, называющей цепочку записи и оба поля

### Requirement: Цепочки клавиш и привязки
Цепочка MUST записываться строкой сочетаний через пробел, где сочетание — модификаторы и клавиша в синтаксисе Hyprland через `+` (`"SUPER+W 3 f"`); одиночное сочетание (`"SUPER+Return"`, `"XF86AudioMute"`, `"SUPER+mouse:272"`) — цепочка из одного звена. Короткая форма `chain` у workspace означает действие «поднять на текущем столе», у приложения — «вести цикл по его экземплярам в режиме его workspace» по правилам ws-daemon. Запись `[[binds]]` MUST принимать ровно одно действие: `action` — таблица с любым сочетанием ключей `desktop` (1…8), `workspace` и `app`, таблица `{ half = "left" | "right" | "up" | "down" }`, таблица `{ place = "top-left" | "top-center" | "top-right" | "bottom-left" | "bottom-center" | "bottom-right" | "center" | "full" }` либо строка `"sessions"`, `"save-session"`, `"save-workspace"`, `"next-workspace"`, `"maximize"`; `exec` — командная строка, запускаемая композитором; `dispatch` — выражение диспетчера Hyprland без префикса `hl.dsp.` (`"window.close()"`) либо массив таких выражений, выполняемых по порядку одним вызовом; `lua` — тело функции на Lua, выполняемое композитором при нажатии. Флаги `locked` (действует при заблокированном экране), `repeating` (повторяется при удержании), `mouse` (привязка к кнопке мыши с удержанием), `release` (срабатывает при отпускании) MUST передаваться композитору; `mouse` MUST быть допустим только у цепочки из одного звена. Поле `range = [от, до]` MUST разворачивать запись в серию: для каждого целого из диапазона подстрока `$n` в `chain`, `exec` и `dispatch` заменяется числом. Цепочки MUST быть произвольными; демон MUST NOT навязывать смысл сегментам. Одна цепочка MUST NOT совпадать с другой или быть её началом, в том числе одиночное сочетание с первым звеном цепочки; две цепочки с общим первым звеном и разными последующими MUST быть допустимы; два приложения с одной цепочкой внутри одного workspace MUST считаться ошибкой; одна цепочка у приложений из разных workspace MUST быть допустима. Сочетание из списка `reserved` раздела `[keys]` MUST NOT встречаться ни в одной цепочке. Демон MUST проверять эти условия при чтении и при ошибке называть обе конфликтующие записи либо запись и зарезервированное сочетание.

#### Scenario: Цепочка приложения ведёт цикл
- **WHEN** у приложения `chromium` задано `chain = "SUPER+C"`, оно входит в workspace `work` режима обмена ячеек, и у него два окна
- **THEN** Super+C по очереди выбирает экземпляры `chromium` в главной ячейке, а за последним возвращает расстановку и фокус прежнему главному окну

#### Scenario: Одна цепочка у двух приложений в разных workspace
- **WHEN** `firefox-front` и `firefox-chat` имеют `chain = "SUPER+A b"`, первое входит в `dev-front`, второе в `chat`
- **THEN** `workspaced check` завершается успешно

#### Scenario: Одна цепочка у двух приложений одного workspace
- **WHEN** `firefox-front` и `firefox-back` имеют `chain = "SUPER+A b"` и оба входят в `dev-front`
- **THEN** `workspaced check` завершается с ошибкой, называющей `dev-front` и оба приложения

#### Scenario: Общий префикс у двух цепочек
- **WHEN** в `[keys]` заданы `save_session = "CTRL+SUPER+s CTRL+SUPER+s"` и `save_workspace = "CTRL+SUPER+s CTRL+SUPER+w"`
- **THEN** `workspaced check` завершается успешно, а `hyprctl binds` содержит одну подкарту, открываемую Ctrl+Super+S, с двумя действиями внутри

#### Scenario: Цепочка является началом другой
- **WHEN** у workspace `chain = "SUPER+W f"`, а в `[[binds]]` есть `chain = "SUPER+W f 3"`
- **THEN** `workspaced check` завершается с ошибкой, называющей обе цепочки

#### Scenario: Одиночное сочетание совпадает с началом цепочки
- **WHEN** в `[[binds]]` есть `chain = "SUPER+W"` с `exec = "wezterm-gui"`, а у workspace `chain = "SUPER+W d"`
- **THEN** `workspaced check` завершается с ошибкой, называющей обе записи

#### Scenario: Запуск команды с флагами
- **WHEN** в `[[binds]]` есть `chain = "XF86AudioRaiseVolume"`, `exec = "~/.local/bin/handmade-scripts/change-volume.sh +"`, `locked = true`, `repeating = true`
- **THEN** после `hyprctl reload` удержание клавиши повышает громкость несколько раз подряд, в том числе при экране, закрытом hyprlock

#### Scenario: Серия по диапазону
- **WHEN** в `[[binds]]` есть `chain = "SUPER+$n"`, `range = [1, 8]`, `dispatch = "focus({ workspace = $n })"`
- **THEN** `hyprctl binds` содержит восемь привязок Super+1…Super+8, и Super+3 переводит на стол «3»

#### Scenario: Несколько диспетчеров по порядку
- **WHEN** в `[[binds]]` есть `chain = "ALT+Tab"` и `dispatch = ["window.cycle_next({ next = true })", "window.bring_to_top()"]`
- **THEN** нажатие Alt+Tab переводит фокус на следующее окно стола, и оно оказывается поверх остальных

#### Scenario: Зарезервированное сочетание
- **WHEN** в `[keys]` задано `reserved = ["SUPER+space", "ALT+SUPER+E"]`, а в `[[binds]]` есть `chain = "ALT+SUPER+E"`
- **THEN** `workspaced check` завершается с ошибкой, называющей запись и зарезервированное сочетание

#### Scenario: Развёртывание окна в записи привязки
- **WHEN** в `[[binds]]` есть `chain = "SUPER+X"` и `action = "maximize"`
- **THEN** `workspaced check` завершается успешно, `workspaced keys --list` показывает для Super+X команду `workspaced maximize`, а запись с `action = "maximise"` отклоняется как неизвестное действие

#### Scenario: Позиция в записи привязки
- **WHEN** в `[[binds]]` есть `chain = "ALT+SUPER+Home"` и `action = { place = "top-left" }`
- **THEN** `workspaced check` завершается успешно, `workspaced keys --list` показывает команду `workspaced place top-left`, а запись с `action = { place = "left" }` отклоняется с перечнем допустимых позиций

#### Scenario: Мышь в цепочке
- **WHEN** в `[[binds]]` есть `chain = "SUPER+W mouse:272"` с `mouse = true`
- **THEN** `workspaced check` завершается с ошибкой о том, что флаг `mouse` допустим только у одиночного сочетания
