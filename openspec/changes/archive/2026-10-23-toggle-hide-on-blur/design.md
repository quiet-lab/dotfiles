# Design: Окно-переключатель прячется при потере фокуса

## Context

Мотивация — в `proposal.md`. До изменения (коммит демона `41abe4d`):

- Клавиша переключателя решается функцией `toggle_step` (изменение
  `toggle-windows`, решение D5): окно с фокусом на столе композитора
  прячется на `special:pool`, и фокус возвращается окну, с которым работали
  до показа (`toggle_back`); окно на столе без фокуса получает фокус.
- Событие `activewindowv2` обрабатывает `Daemon::on_focus`: окно с фокусом
  спрашивается у композитора (`j/activewindow`), спрятанное окно
  переключателя, получившее фокус, показывается на текущем столе
  (решение D6 `toggle-windows`), окно обычного стола запоминается как
  `last_plain`.
- Список `ignore_classes` в корне конфига перечисляет классы окон, которые
  не принимаются никогда (`termfilechooser`, `xdg-desktop-portal-gtk`,
  `pinentry.*`, `zenity`, `hyprland-dialog`).

## Goals / Non-Goals

**Goals:** окно переключателя, у которого был фокус, уходит на
`special:pool`, как только фокус уходит в обычное окно или ни к одному
окну; выбор файла, ввод пароля и окна того же приложения его не прячут.

**Non-Goals:** новые поля конфига; отдельный режим для отдельных
переключателей; изменение клавиши, активации, запуска и места окна.

## Decisions

### D1. Источник — событие `activewindowv2`

Скрытие делается в обработчике `activewindowv2` (`on_focus`) до прежней
логики обработчика. Решение принимает чистая функция `blur_step`: на входе
приложение-переключатель, окно которого держало фокус
(`Daemon::toggle_focused`), и окно с фокусом сейчас; на выходе —
приложение, окна которого надо спрятать, и новое значение
`toggle_focused`. Таймеров и опроса нет: состояние — след событий фокуса.

Рассмотренные варианты: событие `activewindowv2` (**выбран**: композитор
сообщает каждую смену фокуса, включая пустую); событие `activewindow`
(отвергнут: несёт класс и заголовок без адреса, по нему не отличить два
окна одного класса); проверка при следующем нажатии клавиши (отвергнут:
окно остаётся на экране до нажатия, а задача — убрать его сразу).

Прячутся только окна приложения, которое держало фокус: окно, появившееся
не по клавише и фокуса не получавшее (решение D9 `toggle-windows`), смена
фокуса между другими окнами не трогает. Получив и потеряв фокус, оно
прячется по общему правилу.

### D2. Окна выбора файла, запроса пароля и окна без класса

Фокус, ушедший в окно класса из `ignore_classes` или в окно без класса,
потерей фокуса не считается: иначе Telegram пропадал бы, пока пользователь
выбирает файл для отправки или вводит пароль. `blur_step` в этом случае
ничего не прячет и сохраняет `toggle_focused`: когда фокус вернётся в окно
переключателя, ничего не происходит, а когда уйдёт из окна выбора файла
в другое обычное окно, переключатель прячется по общему правилу. Список
классов берётся из `ignore_classes`, отдельного списка нет: это те же
окна, которые демон ни в один workspace не принимает (решение основной
сессии 23.10.2026).

Рассмотренные варианты: список `ignore_classes` (**выбран**); отдельное
поле у переключателя (отвергнут: новых полей конфига нет, и классы
диалогов пришлось бы перечислять дважды); признак диалога от композитора
(недоступен: Hyprland 0.56.2 не сообщает ни родителя окна, ни
модальности, `docs/open-questions/hyprland-window-parent.md`).

### D3. Окна того же приложения

Фокус, ушедший в другое окно того же приложения-переключателя (просмотр
медиа в Telegram, диалог Telegram того же класса), — не потеря.
Приложение окна определяется по тегу экземпляра, а у окна без тега
(диалог по `dialog_title`, окно, ещё не принятое демоном) — по `class`
и `title` приложений конфига (`toggle_app_of`). Фокус, ушедший в окно
другого переключателя, — потеря для прежнего: его окна прячутся, фокус
держит новый.

### D4. Фокус ни у одного окна и промежуточные события

Событие с пустым адресом (переход на пустой стол, закрытие окна с фокусом)
считается потерей фокуса: окна переключателя на обычных столах прячутся.

Окно с фокусом демон спрашивает у композитора в момент обработки события,
а не берёт адрес из события. Проверено 23.10.2026 записью событий
`.socket2.sock`:

- показ клавишей даёт `movewindowv2`, затем `activewindowv2` окна Telegram,
  пустого адреса между ними нет;
- активация спрятанного окна даёт `activewindowv2` окна Telegram на
  `special:pool`, затем при закрытии `special:pool` — `activewindowv2`
  другого окна стола, затем `movewindowv2` и снова `activewindowv2` окна
  Telegram. Промежуточные события обрабатываются после того, как
  `show_toggle` выполнил диспетчеры, и запрос `j/activewindow` к этому
  моменту возвращает окно Telegram, поэтому окно не прячется;
- открытие лаунчера rofi (слой, а не окно) событий `activewindowv2` не
  даёт: окно Telegram остаётся.

Рассмотренные варианты: запрос окна с фокусом при обработке (**выбран**:
устаревшее событие не прячет окно, которое к этому моменту снова
в фокусе); адрес из события (отвергнут: промежуточное событие активации
спрятало бы только что показанное окно); пустой адрес не считать потерей
(отвергнут решением основной сессии: при переходе на пустой стол окно
должно уходить).

### D5. Общий путь скрытия

Скрытие по потере фокуса и по клавише выполняет один метод `hide_toggle`:
окна уходят на `special:pool` диспетчером `window.move` без следования.
У потери фокуса окна возврата нет — фокус уже ушёл, и запомненное окно
возврата (`toggle_back`) забывается. Прячутся окна приложения на обычных
столах (1…8); окна на `special:pool` и `special:hidden` не трогаются.
В журнал пишется строка «окно-переключатель <имя>: потеря фокуса (фокус
у <адрес> (<класс>)) — спрятано» или «(фокуса нет ни у одного окна)».

## Risks / Trade-offs

- [Диалог другого класса, не перечисленный в `ignore_classes`] → окно
  переключателя спрячется, пока открыт диалог. Класс добавляется в
  `ignore_classes`, демон учитывает его сразу после перечитывания конфига.
- [Переход на другой стол прячет окно] → это и есть решение: на новом
  столе окно показывает клавиша или активация.
