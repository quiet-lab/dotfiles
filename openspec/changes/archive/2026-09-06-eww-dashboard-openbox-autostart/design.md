# Design: Автозапуск EWW-дашборда в Openbox

## Context

Сессия запускается через `openbox-session`: `/usr/lib/openbox/openbox-autostart` исполняет `~/.config/openbox/autostart`, а при его отсутствии — `autostart.sh`. В репозитории есть только `dot_config/openbox/autostart.sh` (цель chezmoi — `~/.config/openbox/autostart.sh`), он уже содержит всю стартовую логику сессии (pulseaudio, picom, joyd_* и т.д.). Скрипт начинается с `exec >/dev/null 2>&1`, интерпретатор — POSIX `sh`. Демон eww сейчас нигде не запускается (см. proposal.md — Why).

## Goals / Non-Goals

**Goals:**

- Автоматический старт демона eww и окна `dashboard` при логине в Openbox-сессию.
- Идемпотентность: повторный запуск скрипта (например, после `openbox --restart`) не создаёт второй демон и дубликат окна.
- Отсутствие `eww` в системе не ломает остальной автостарт.

**Non-Goals:**

- Изменения конфига EWW (`dot_config/eww/*`) — окно `dashboard` уже описано и специфицировано (`eww-shell`).
- Управление жизненным циклом демона (автоперезапуск при падении, systemd-юниты).
- Поддержка Wayland или других WM.

## Decisions

### D1: Точка интеграции — существующий `autostart.sh`

Блок добавляется в конец `dot_config/openbox/autostart.sh` (после строки «Any additions should be added below»).

- *Почему*: это единственный исполняемый хук сессии, который уже используется; правка одного файла минимальна.
- *Альтернативы*: systemd user service (в этой настройке нет пользовательской systemd-сессии с корректным `DISPLAY`); XDG autostart `.desktop` (лишняя прослойка openbox-xdg-autostart, выбивается из стиля репозитория).

### D2: Проверки в POSIX-стиле, как в соседних блоках файла

```sh
{ [ -x "$(command -v eww)" ] && { pidof -s eww -q || eww daemon; } && eww open dashboard; } &
```

- Наличие бинарника — идиома `[ -x "$(command -v …)" ]`, уже применяемая в этом файле для lxpolkit/xss-lock.
- Защита от дублей демона — `pidof -s eww -q || eww daemon`, по образцу проверки pulseaudio в начале скрипта.
- Весь блок — фоновый `{ … } &`, чтобы не тормозить остальной автостарт; вывод уже подавляется глобально.
- *Альтернатива*: `eww ping` как индикатор живого демона — отклонено: команда зависит от версии eww, тогда как `pidof` универсален.

### D3: Открытие окна — после фактического открытия, без гонок

`eww open dashboard` выполняется в том же блоке последовательно за гарантией демона: если демон уже был жив — окно откроется сразу; `eww open` для уже открытого окна безвреден (не создаёт дубликат), что закрывает сценарий `openbox --restart`.

- *Риск гонки* (сокет демона не успел появиться) закрывается тем, что `eww daemon` синхронизирует готовность перед возвратом управления в свежих версиях; если на практике окно не появится — добавляется короткий цикл ретраев с таймаутом (решение фиксируется в tasks.md при реализации, на спеку не влияет).

## Risks / Trade-offs

- [Гонка: окно открывается раньше готовности демона] → последовательный запуск в одном блоке; при необходимости — цикл ретраев с таймаутом ~5 c.
- [`pidof` не найдёт переименованный бинарник] → пакет поставляет бинарник ровно с именем `eww`; риск теоретический.
- [Дашборд появляется позже остальных окон автостарта] → фоновый запуск означает отсутствие блокировки; визуально колонка резервирует страту сразу после открытия окна.
- [Правка не применена к цели chezmoi] → деплой входит в tasks; до `chezmoi apply` поведение системы не меняется.

## Migration Plan

1. Правка `dot_config/openbox/autostart.sh`, проверка синтаксиса (`sh -n`).
2. `chezmoi apply` — цель обновляется.
3. Проверка сценариев спеки: логин в сессию, `openbox --restart` (без дублей), временно скрытый `eww` из `$PATH`.
4. Откат: удалить добавленный блок, повторить `chezmoi apply`.
