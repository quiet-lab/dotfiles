## Context

Замер в цепочке пользователя (wezterm → herdr → nvim, журнал `vim.on_key`)
показал, что `<S-CR>` и `<S-Space>` доходят до nvim. Буфер диалога
не открывался из-за линии рамки «──── имя сессии ─» под подвалом диалога.
Решения пользователя по поведению карточки, подсказке и отмене записаны
в правилах задачи (каталог результатов задачи `claude-input-keys`).

## Decisions

- Д1. Замыкающая строка, начинающаяся с «───», подвалом не считается и
  пропускается вместе с пустыми строками.
- Д2. Строка вкладок карточки (`←  ☒ Q1  ☐ Q2  ✔ Submit  →`) даёт число
  отвеченных вопросов. Пока экран — вопрос карточки, плагин держит
  подписку `pane.output_matched` на строку вкладок с большим числом `☒`;
  её срабатывание — переход к следующему вопросу или к обзору. `:w`
  на вопросе карточки окно к вводу не возвращает; к вводу возвращает
  `:w` на обзоре, отмена или закрытие диалога.
- Д3. Детектор herdr после правки поля свободного ввода держит статус
  `idle` до конца карточки, поэтому экран карточки (строка вкладок или
  обзор) считается диалогом при любом статусе, кроме `working` (тогда
  это прежний кадр отвеченной карточки). Закрытие диалога ловит
  подписка `pane.output_matched` на подвал строки ввода Claude Code:
  режим vim с пометкой режима разрешений, пометки `⏵⏵`, `⏸` или
  `? for shortcuts`. Совпадение на кадре, который остаётся диалогом,
  запоминается по подписи кадра, и подписка до смены кадра не
  повторяется: herdr шлёт совпадение сразу при подписке.
- Д2а. Подпись диалога включает число отвеченных вопросов карточки, иначе
  соседние вопросы с одинаковыми пунктами неразличимы. Правка буфера
  до перехода карточки ждёт того же образца строки вкладок.
- Д2б. Подписки `pane.output_matched` (выделение, строка вкладок, строка
  ввода) ведёт одна функция с ключом подписки.
- Д4. Буфер диалога создаётся при открытии диалога, не входит в список
  буферов (`nvim_create_buf(false, …)`) и удаляется при возврате окна
  к вводу: вручную перейти в него вне диалога нельзя.
- Д5. Подсказка — виртуальные строки (extmark `virt_lines`) под первой
  строкой буфера: заголовок («Вопрос k из n», «Обзор ответов» или
  «Диалог»), пункты экрана с номерами и знаком выделения, строка клавиш.
  Текст буфера не меняется.
- Д6. Ctrl+C (режимы вставки и обычный) отправляет `pane.send_keys`
  `esc` (во время идущей цепочки — после неё) и сразу возвращает окно
  к вводу; подпись последнего экрана
  запоминается как отвеченная, чтобы прежний кадр не открыл диалог снова.
- Д7. Shift+Enter и Shift+Пробел в буфере ввода вызывают ту же отправку,
  что `:w`.

## Risks / Trade-offs

- Ctrl+C в nvim привычно выходит из режима вставки; в буфере диалога он
  отменяет весь диалог без подтверждения (решение пользователя).
- Shift+Пробел в режиме вставки буфера ввода отправляет запрос: Shift,
  задержанный после заглавной буквы перед пробелом, отправит
  недописанный запрос (решение пользователя).
- Возврат к уже отвеченному вопросу карточки стрелкой `←` в панели
  Claude Code и его повторный ответ не меняют числа `☒`: переход к
  следующему экрану плагин узнаёт только при следующей правке буфера.

- Вид экранов Claude Code меняется с версиями: образцы строки вкладок и
  подвала строки ввода сверяются по снимкам после обновления
  (`docs/claude-input.md`).
- Переход фокуса herdr на диалоги других workspace (`[ui.follow_blocked]`)
  посреди карточки — поведение клиента herdr, вне этого изменения.
