# Design: Развёртывание окна командой демона workspaced

## Context

Мотивация — в proposal.md («Why»). Что есть сейчас и что ограничивает подход:

- Демон workspaced (`~/work/pets/workspaced`) уже умеет ставить активное окно в половину рабочей области: `daemon.rs`, функция `half`, берёт активное окно и активный монитор через сокет Hyprland, считает прямоугольник от `Monitor::work_area().inset(gap)` и ставит окно двумя диспетчерами (`window.resize`, `window.move`) после `window.float`. Действие в конфиге — `{ half = "<сторона>" }`, команда сокета `half`, подкоманда CLI `Half`, генератор `keys.rs` печатает `workspaced half <сторона>`.
- Служебные действия без параметров задаются строкой: `"sessions"`, `"save-workspace"`, `"next-workspace"`. Их перечень проверяется в `config.rs` и превращается в команду в `keys.rs`.
- `Client` из `j/activewindow` содержит `address`, `at`, `size`, `floating`, но не содержит поля полноэкранного режима; `j/activewindow` его отдаёт (`fullscreen`, число: 0 — нет, 1 — maximized, 2 — fullscreen).
- Диспетчер `window.fullscreen` в режиме `maximized` для плавающего окна ставит его вплотную к рабочей области (проверено: 332,2 и 3506×2156 при панели 330 px и рамке 2 px); опций вроде `no_gaps_when_only` в Hyprland 0.56.2 нет.
- Адрес окна Hyprland не меняется за время жизни окна и повторно не используется в пределах сессии, поэтому годится как ключ памяти.

## Goals / Non-Goals

**Goals:**
- Super+X даёт те же 10 px от краёв и панели, что половины и ячейки workspace, и остаётся переключателем.
- Правило расстояний живёт в одном месте — в демоне; в конфиге и в Lua композитора расчёта нет.

**Non-Goals:**
- Полноэкранный режим Super+F остаётся диспетчером Hyprland и не меняется.
- Восстановление мозаичного режима: окно, развёрнутое из мозаики, после возврата остаётся плавающим с прежними положением и размером, как после `half`.
- Сохранение памяти развёрнутых окон между перезапусками демона и в файлах сессий.

## Decisions

**D1. Действие — строка `"maximize"`, а не таблица.** У действия нет параметров, поэтому оно встаёт в ряд служебных строк `"sessions"`, `"save-workspace"`, `"next-workspace"`. Альтернатива `{ half = "full" }` смешивала бы два разных действия под одним ключом и ломала бы проверку сторон `half`.

**D2. Геометрия — `work_area().inset(2·gap)`.** У `half` рабочая область сужается на `gap`, затем половина сужается ещё на `gap`; для целой области оба шага складываются в один `inset(2·gap)`, и окно получает те же 10 px от краёв, что и половина. Расчёт выполняется в той же функции размещения, что и у `half`, чтобы изменение зазора меняло оба действия одновременно.

**D3. Переключение по сравнению с целевым прямоугольником, а не по флагу.** Демон хранит `HashMap<адрес окна, PxRect>` с геометрией до развёртывания. При вызове сначала считается целевой прямоугольник; если текущая геометрия окна совпадает с ним и в памяти есть запись, окно возвращается к записи, а запись удаляется; во всех остальных случаях окно разворачивается, а текущая геометрия записывается (перезаписывая старую). Так сдвинутое пользователем окно разворачивается заново, а память не хранит устаревшего флага «развёрнуто». Альтернатива — хранить флаг и проверять его — давала бы ложный возврат после ручного перемещения.

**D4. Совпадение геометрии — точное.** Диспетчеры `resize` и `move` с `relative = false` ставят окно ровно в заданные координаты (проверено на `half`), поэтому допуск не нужен. Если окно не может принять размер (минимальный размер клиента больше целевого), геометрия не совпадёт, и каждое нажатие будет пытаться развернуть заново без возврата; это принимается как известное ограничение.

**D5. Память очищается при вызове.** Перед проверкой демон удаляет из памяти адреса окон, которых больше нет среди клиентов `j/clients`. Отдельной подписки на события закрытия окон для этого не нужно: память мала, а лишние записи безвредны до следующего вызова.

**D6. Полноэкранное окно выводится из режима и остаётся развёрнутым.** В `Client` добавляется поле `fullscreen` (число, по умолчанию 0). При ненулевом значении демон сначала снимает режим диспетчером `window.fullscreen` с `action = "unset"` и тем же `mode`, что у окна (`fullscreen` для 2, `maximized` для 1: `unset` с другим режимом состояние не снимает, проверено), затем заново читает активное окно, потому что в полноэкранном режиме композитор отдаёт геометрию во весь экран, а прежняя известна только после выхода. Дальше команда ведёт себя так, чтобы окно оказалось развёрнутым: уже развёрнутое остаётся на месте без возврата, остальные разворачиваются с запоминанием. Первый вариант, пропуск полноэкранного окна с записью в журнал, пользователь отверг: Super+X после Super+F должен давать видимый результат одним нажатием.

**D7. Проводка команды повторяет `half`.** Конфиг: строка `"maximize"` в списке допустимых служебных действий; генератор: `workspaced maximize`; CLI: подкоманда `Maximize` без аргументов; сокет: команда `maximize`; демон: функция `maximize` рядом с `half`, с тем же `mark_dirty` после перемещения, чтобы сессия `default` сохранила новое положение окна.

## Risks / Trade-offs

- [Окно с минимальным размером больше целевого не встаёт в развёрнутую область] → геометрия не совпадёт, возврата не будет; поведение описано в D4, для обычных окон на 3840×2160 недостижимо.
- [Адрес окна повторно используется композитором после закрытия] → запись стёрта при очистке в D5 при следующем вызове; между закрытием и вызовом новое окно с тем же адресом появиться не успевает, а если появится, получит лишь ложный возврат к чужой геометрии одним нажатием.
- [Пользователь ожидает от Super+X поведение Hyprland maximized с `fullscreen_opacity`] → развёрнутое окно демона остаётся обычным плавающим, прозрачность не меняется; это соответствует Openbox, где ToggleMaximize тоже не менял оформление.

## Migration Plan

1. Реализовать и собрать демон (`cargo build --release`), `cargo test`.
2. Перезапустить `workspaced.service`; демон перечитает конфиг после правки `config.toml` и сам выполнит `hyprctl reload config-only`.
3. Откат: вернуть в `config.toml` прежнюю запись `dispatch = "window.fullscreen({ mode = \"maximized\", action = \"toggle\" })"`; старый двоичный файл демона не нужен, действие `maximize` без привязки не вызывается.
