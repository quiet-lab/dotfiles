## ADDED Requirements

### Requirement: Состав и геометрия плиток
Панель MUST отображать колонку плиток с составом, порядком и координатами из таблицы ниже (левый отступ 10 px, зазор между плитками 10 px, расчёт под экран 3840×2160). Полный ряд имеет ширину 320 px; если не указано иное, x = 10 px и ширина 320 px:

|--------|---|-------------|
| питание: блокировка, выход, перезапуск, перезагрузка, выключение | 10 px | x = 10/76/142/208/274 px, квадраты 56×56 px в один ряд |
| часы с датой и календарём | 76 px | высота 239 px |
| погода | 325 px | высота 215 px |
| шкалы CPU, RAM, GPU | 704 px | x = 10/120/230 px, ширина 100 px |
| сеть | 816 px | |
| диски | 933 px | |
| избранное | 1178 px | |
| рабочие столы 1…8 | 1462 px + 46 px·(n−1) | по плитке на стол, 274×36 px |
| трей | 1462 px | x = 294 px, 36×312 px (вертикальный, справа от столов) |
| раскладка | 1784 px | x = 294 px, 36×36 px (на уровне восьмого стола) |
| лаунчер | 1830 px | 320×320 px (квадрат у нижнего края) |

Колонка MUST занимать монитор по вертикали целиком (10…2150 px) тремя группами: вверху — ряд питания, часы и погода (10…540 px); внизу — лаунчер у нижнего края (1830…2150 px), а над ним через зазор 10 px блок рабочих столов с треем и раскладкой (1462…1820 px); средняя группа (шкалы, сеть, диски, избранное, всего 595 px) MUST стоять по центру свободного промежутка между верхней и нижней группами (отступы 164 px сверху и 163 px снизу). При изменении высоты какой-либо плитки координаты MUST быть пересчитаны: нижняя группа привязана к нижнему краю, средняя центрируется заново.

#### Scenario: Порядок и координаты фиксированы
- **WHEN** панель запущена
- **THEN** плитки следуют в порядке из таблицы без пропусков, каждая занимает указанные координаты и размеры, между соседними плитками зазор 10 px

#### Scenario: Геометрия колонки
- **WHEN** на снимке экрана сессии измерены положения и размеры плиток
- **THEN** границы всех плиток совпадают с точностью до пикселя

### Requirement: Запуск панели при старте сессии
Панель MUST запускаться пользовательским юнитом systemd, привязанным к цели `hyprland-session.target`, без ручных действий пользователя. Юнит MUST обеспечивать единственную копию панели (повторная активация цели или `hyprctl reload` не порождает второй экземпляр) и перезапускать панель при её аварийном завершении. Файл юнита MUST храниться под chezmoi в `dot_config/systemd/user/`.

#### Scenario: Вход в сессию Hyprland
- **WHEN** пользователь входит в сессию Hyprland
- **THEN** `systemctl --user is-active quickshell-panel.service` даёт `active`, колонка плиток видна

#### Scenario: Панель аварийно завершилась
- **WHEN** процесс панели завершён принудительно (например, `systemctl --user kill quickshell-panel.service` или сигнал KILL)
- **THEN** systemd перезапускает панель, и колонка появляется снова без действий пользователя

#### Scenario: Перезагрузка конфига Hyprland не дублирует панель
- **WHEN** выполнена `hyprctl reload` при работающей панели
- **THEN** процесс панели остаётся единственным, окно панели существует в одном экземпляре

## MODIFIED Requirements

### Requirement: Окно панели
Панель MUST быть единственным окном layer-shell на мониторе DP-2, привязанным к левому краю и занимающим полосу шириной 330 px по всей высоте монитора, так что координаты плиток внутри панели совпадают с экранными. Окно MUST резервировать зону 330 px у левого края, чтобы обычные окна не перекрывали колонку и располагались правее неё. Пространство имён слоя MUST быть `panel`; слой MUST лежать выше обычных окон, но ниже полноэкранных слоёв композитора (блокировка экрана).

Панель MUST NOT забирать фокус клавиатуры: единственное исключение — поле фильтра лаунчера, которое получает фокус по клику пользователя (фокус по требованию) и отдаёт его, когда пользователь уходит из поля.

Размытие MUST давать композитор правилом для слоя `panel` с порогом прозрачности, ниже которого пиксели не размываются. Правила слоя Hyprland не задают непрозрачность слоя, поэтому прозрачность несёт сама заливка: каждая плитка MUST заливаться чёрным `#000000` с непрозрачностью 0.9, а промежутки между плитками и вся остальная площадь окна MUST быть полностью прозрачными и лежать ниже порога размытия: только так размытие ложится на плитки и не трогает зазоры. Иных полупрозрачных заливок и наложений в стилях панели MUST NOT быть.

#### Scenario: Окна не залезают под колонку
- **WHEN** пользователь разворачивает любое окно на мониторе DP-2
- **THEN** окно располагается правее полосы 330 px от левого края, а `hyprctl monitors` показывает у DP-2 зарезервированную зону 330 px слева

#### Scenario: Панель не перехватывает клавиатуру
- **WHEN** в фокусе терминал, а пользователь кликает по плитке часов или по плитке рабочего стола
- **THEN** фокус клавиатуры остаётся у терминала, и последующий ввод попадает в него

#### Scenario: Поле фильтра принимает ввод по клику
- **WHEN** пользователь кликает в поле фильтра лаунчера и печатает текст
- **THEN** символы попадают в поле, а после клика по обычному окну ввод снова идёт в это окно

#### Scenario: Монитор пропадал и вернулся
- **WHEN** монитор DP-2 отключался и был подключён снова (пересоединение DisplayPort, временный выход FALLBACK композитора)
- **THEN** панель без перезапуска снова отображается на DP-2 с зарезервированной зоной 330 px

#### Scenario: Размытие только под плитками
- **WHEN** за панелью находятся обои или окно с контрастным содержимым
- **THEN** сквозь плитки видно размытый фон с непрозрачностью 0.9, а в промежутках между плитками фон виден без размытия и без затемнения
