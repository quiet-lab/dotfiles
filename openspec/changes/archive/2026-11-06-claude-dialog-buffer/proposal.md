## Why

Буфер ввода Claude Code в neovim (`claude-input`) не помогает отвечать
на диалоги Claude Code: пока открыт вопрос с вариантами или запрос
разрешения, правка буфера откладывается, а ответ приходится давать
в панели Claude Code. Пользователь 6 ноября 2026 сформулировал требование:
«При открытии диалогов должен открываться отдельный буфер. Ввод цифр
в этом буфере перемещает выбор на соответствующий пункт диалога и очищает
буфер. Сохранение подтверждает выбор. Если выбор в диалоге на пункте,
в котором происходит ввод, текст выводится в соответствующий пункт
диалога. Если на пункте для ввода в пустом буфере вводятся цифры, это
меняет пункт выбора». Уточнения: буфер открывается для всех диалогов
с пунктами выбора (AskUserQuestion, запросы разрешения, доверие каталогу
и подобные); в вопросе с множественным выбором цифра ставит или снимает
отметку; в карточке из нескольких вопросов `:w` подтверждает текущий
вопрос и переходит к следующему.

## What Changes

- Плагин `claude-input` держит подписку на смену статуса панели Claude
  Code и при диалоге с пунктами выбора показывает в своей панели буфер
  `claude://dialog` вместо `claude://input`; после закрытия диалога
  возвращает буфер ввода с прежним содержимым.
- Экран диалога читается через сокет herdr (`pane.read`) и разбирается:
  пункты, выделенный пункт, пункт свободного ввода, множественный выбор,
  вкладка обзора ответов.
- Цифра в буфере диалога переводит выделение стрелками на пункт с этим
  номером (в множественном выборе — переключает отметку) и очищает буфер;
  текст при выделенном пункте свободного ввода повторяется в его поле;
  `:w` подтверждает выбор.

## Impact

- `dot_config/nvim/local/claude-input/` — модуль разбора экрана
  `claude_input/dialog.lua`, правка `claude_input/init.lua`, тесты
  `tests/` (в `$HOME` не ставятся, `.chezmoiignore`).
- Зависимости прежние: herdr с подпиской `pane.agent_status_changed`
  и методом `pane.read`, Claude Code с режимом vim.
