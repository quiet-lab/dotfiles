# Design: Буфер диалога Claude Code в neovim

## Context

Требование — в `proposal.md`. Буфер ввода устроен по решениям D1–D6
изменения `claude-input-buffer` (`openspec/changes/archive/`): замена
строки ввода одним запросом `pane.send_text` с префиксом очистки (D1),
`:w` (D2), сокет herdr из `vim.uv` по соединению на запрос (D3),
ожидание выхода из `blocked` по подписке `pane.agent_status_changed`
(D4), панель 13 строк (D5), локальный плагин (D6). Таймеров нет
(`docs/decisions/0007-no-timers.md`).

Сверка перед проектированием (herdr 0.9.5, Claude Code 2.1.319):

- `pane.read` с `source = "detection"` возвращает тот же видимый экран,
  по которому детектор herdr определяет статус; ответ — около 1 мс.
- Подписка `events.subscribe` принимает `pane.agent_status_changed`
  и `pane.output_matched` (событие при совпадении вывода панели
  с образцом).
- Детектор herdr ставит `blocked`, когда внизу экрана подсказка
  «Esc to cancel» вместе с «Enter to confirm» или «Enter to select»
  (правило `live_blocked_form`), и по отдельным правилам — запросу
  разрешения и MCP elicitation.

## Пробы

Пробы шли в отдельном workspace herdr на Claude Code 2.1.319
(`claude --model sonnet --permission-mode default`, каталог без доверия).
Экраны лежат в `probe/screens/` каталога задачи и в
`dot_config/nvim/local/claude-input/tests/fixtures/`. Запросов модели
в пробах — два: карточка AskUserQuestion из двух вопросов и пара
Bash + Write. Правила `ask` для Bash и Write задавал файл, переданный
`--settings`: у пользователя оба инструмента разрешены.

### Д1. Вид экранов

- Доверие каталогу (`trust`): пункты без номеров — «❯ No, exit»,
  «Yes, I trust this folder»; выделение по умолчанию на «No, exit»;
  подвал «Enter to confirm · Esc to cancel»; статус `blocked`.
- AskUserQuestion, вопрос с одиночным выбором: строка вкладок
  «←  ☐ Цвет  ☐ Фрукты  ✔ Submit  →», заголовок вопроса, пункты
  «❯ 1. Красный» с описанием на следующей строке, «4. Type something.»
  (свободный ввод), горизонтальная черта, «5. Chat about this»; подвал
  «Enter to select · Tab/Arrow keys to navigate · Esc to cancel».
- Множественный выбор: пункты «1. [ ] Яблоко», отмеченные «[✔]»,
  свободный ввод «4. [ ] Type something», под ним строка «Submit» без
  номера — отдельная позиция выделения; затем черта и «5. Chat about this».
- Вкладка обзора: «Review your answers», ответы, «Ready to submit your
  answers?», «❯ 1. Submit answers», «2. Cancel».
- Разрешение Bash: «Bash command», команда между пунктирными чертами,
  «Do you want to proceed?», «❯ 1. Yes», «2. No»; подвал «Esc to cancel ·
  Tab to amend». Разрешение Write (общий вид): «Create file», «Do you want
  to create probe2.txt?», «1. Yes», «2. Yes, and switch to accept edits …»,
  «3. No».
- Местный выбор модели (`/model`): пункты с номерами и подвал
  «… · Esc to cancel», статус `idle`.
- Выделенный пункт помечен знаком `❯` в начале строки; номер выделенного
  пункта на экране совпадает с его порядковым номером.

### Д2. Клавиши выбора

- Цифра в одиночном выборе AskUserQuestion выбирает пункт и сразу
  переходит к следующему вопросу; в запросе разрешения цифра сразу
  подтверждает пункт. На экране доверия цифра ничего не делает.
- В множественном выборе цифра переключает отметку пункта, выделение
  не двигается.
- Стрелки `CSI A`/`CSI B` сырыми байтами переводят выделение на соседнюю
  позицию во всех видах диалогов; несколько стрелок одним запросом
  проходят все. `j` на экране доверия тоже двигает выделение.
- Стрелка вправо `CSI C` со строки пункта переводит на следующую вкладку
  карточки; сырой Tab (`0x09`) вкладку не переключил.
- Сырой `\r` в диалоге — Enter: подтверждает выделенный пункт. В строке
  ввода сырой `\r` запрос не отправляет ни в одном куске с текстом, ни
  отдельно; клавиша `enter` через `pane.send_keys` (herdr кодирует её по
  режиму клавиатуры терминала) отправляет. Так `:w` буфера ввода (D2)
  на 2.1.319 перестал отправлять обычный текст: проверка прежней задачи
  шла с `/help`, где Enter принимает пункт меню команд.

### Д3. Поле свободного ввода

- Выделение на «Type something» открывает поле в режиме vim (в подвале
  «-- INSERT --»), набранный текст сразу заменяет надпись пункта,
  в множественном выборе пункт отмечается сам.
- Префикс очистки D1 (`i`, `ctrl+u`, `CSI 27 u`, `ggdG`, `i`, Backspace)
  с текстом за ним заменяет содержимое поля целиком; один префикс
  очищает поле; на пустом поле диалог не закрывает.
- Перевод строки `0x0a` в поле добавляет строку, `ctrl+u` стирает только
  текущую строку.
- Стрелка вверх из поля — с текстом и без — переводит выделение на
  предыдущий пункт, текст поля остаётся.
- Пока выделено поле, подвал теряет «Esc to cancel», и детектор herdr
  показывает статус `done`, а не `blocked`; со строки «Submit» подвал
  снова полный, статус `blocked`.

### Д4. Живая проверка

Плагин в отдельном workspace herdr на том же Claude Code, журнал —
`live.log` каталога задачи; третий запрос модели — один вопрос, карточка
из двух вопросов и Bash. Проверено: переход на `claude://dialog` при
вопросе и запросе разрешения; цифра переводит выделение и очищает буфер;
текст при выделенном «Type something» — в поле, статус при этом `done`,
буфер диалога остаётся; очистка буфера и цифра снимают текст и переводят
выделение; в множественном выборе цифры ставят и снимают отметки,
в том числе из поля с текстом; `:w` подтверждает одиночный вопрос
и свой ответ, в множественном выборе ведёт на вкладку обзора, на ней
отправляет ответы; в запросе разрешения цифра 2 только выделяет «No»;
после закрытия диалога — `claude://input` с прежним текстом. Экран
доверия — с буфером, открытым вручную для панели нового каталога:
буфер диалога открывается сразу, цифра и `:w` принимают доверие.
Вопрос из одного вопроса выводит вкладку «☐ Шаг» без «Submit».

## Goals / Non-Goals

**Goals:**
- Ответ на диалог Claude Code с пунктами из буфера neovim: цифра, текст
  свободного ввода, `:w`.
- Возврат к буферу ввода с прежним содержимым после закрытия диалога.

**Non-Goals:**
- Дополнение ответа на запрос разрешения (Tab to amend).
- Местные диалоги Claude Code со статусом `idle` (`/model`, `/help`).
- MCP elicitation и другие экраны без пунктов выбора.

## Decisions

### E1. Распознавание диалога по экрану

Экран читается `pane.read` (`source = "detection"`). Диалог — если
последняя непустая строка содержит «Enter to select», «Enter to confirm»
или «Esc to cancel». Пункты ищутся снизу вверх от подвала:

- нумерованный пункт — строка `^%s*❯?%s*(%d+)%.%s+(.*)`, перед номером
  только пробелы и `❯`; номера, найденные снизу вверх, должны идти
  подряд по убыванию до 1, первая строка с номером 1 завершает поиск,
  поэтому нумерованные списки в выводе выше диалога не попадают;
- строка ровно «Submit» среди пунктов множественного выбора — позиция
  выделения без номера;
- если нумерованных пунктов нет, а подвал содержит «Enter to confirm»
  или «Enter to select», пункты — подряд идущие строки с тем же отступом,
  что у строки с `❯`, им присваиваются номера по порядку (экран доверия).
  MCP elicitation подсказки Enter не имеет и диалогом не считается.

Выделенный пункт — строка со знаком `❯`. Множественный выбор — у пунктов
есть отметки `[ ]`/`[✔]`. Пункт свободного ввода есть только у вопроса
AskUserQuestion: это пункт с номером на единицу меньше, чем у «Chat about
this»; его текст — надпись пункта без отметки, надпись «Type something»
означает пустое поле. Вкладка обзора — пункт «Submit answers».

Отвергнуто: запоминать выделение в плагине — пользователь может двигать
его в панели Claude Code (решение записки).

### E2. Переключение буферов по подписке

Плагин при открытии буфера ввода держит одно соединение
`events.subscribe` на `pane.agent_status_changed` панели Claude Code.
Каждое событие, правка буфера диалога и `:w` перечитывают экран:

- статус `blocked` и экран — диалог: окно панели показывает
  `claude://dialog` (`acwrite`, без подкачки, пустой, режим вставки);
- буфер диалога уже открыт и экран остаётся диалогом — буфер остаётся,
  если статус `blocked` или выделено поле свободного ввода: в поле
  детектор даёт `done` (Д3); иной статус при другом выделении — прежний
  кадр закрытого диалога, окно возвращается к буферу ввода;
- экран не диалог — окно возвращается к `claude://input`, его содержимое
  не меняется.

Статус берётся из последнего события подписки, `pane.get` — только
пока статус неизвестен (после открытия подписки и обрыва). Обрыв
подписки открывает её заново один раз; неудачное открытие сообщается
и повторяется при следующей правке буфера ввода или диалога. Таймеров нет.

Отложенная отправка буфера ввода (D4) не меняется: буфер ввода в это
время не виден и не правится.

### E3. Цифра

Содержимое буфера — одно число N, и либо выделен не пункт свободного
ввода, либо буфер был пуст перед числом (поле пусто или пользователь
очистил буфер). Тогда, по свежему экрану:

- пункта N нет — ничего не отправляется;
- одиночный выбор, разрешение, доверие, обзор: стрелки вниз или вверх
  на разность позиций выделенного и N-го пункта (строка «Submit» —
  тоже позиция);
- множественный выбор, пункт N — не свободный ввод: если выделение
  не в поле — клавиша N (переключает отметку, Д2); если в поле —
  стрелки до пункта N и клавиша N одним запросом;
- пункт N — свободный ввод: только стрелки.

Если выделено поле и в нём есть текст, перед стрелками в том же запросе
идёт префикс очистки D1. Затем буфер очищается без отправки.

Признак «буфер был пуст» ставит обработчик `on_lines` (`nvim_buf_attach`)
на каждом изменении буфера: Ctrl+U и цифра, пришедшие одним куском
нажатий, дают одно событие `TextChangedI` уже с цифрой.

### E4. Текст в поле свободного ввода

Иное содержимое при выделенном пункте свободного ввода уходит в поле
одним запросом `PREFIX .. payload` (D1); пустой буфер очищает поле.
Если выделен другой пункт, текст никуда не отправляется и остаётся
в буфере. Запомненный текст поля сбрасывается после `:w`.

### E5. Сохранение

`:w` по свежему экрану: в множественном выборе (кроме вкладки обзора) —
стрелки до строки «Submit» и Enter, иначе — Enter (E5а). Буфер
очищается без отправки. Если экран уже не диалог, ничего не
отправляется, окно возвращается к буферу ввода.

### E5а. Enter — клавишей

Enter и в буфере ввода (`:w`, D2), и в буфере диалога уходит запросом
`pane.send_keys` с клавишей `enter` после запроса `pane.send_text`
с текстом или стрелками (Д2). Запросы идут друг за другом, байты
в терминал панели приходят в том же порядке.

### E6. Безопасность

Каждая отправка идёт после чтения экрана в той же цепочке, в полёте
одна цепочка. Esc уходит только внутри префикса D1 и только при
выделенном пункте свободного ввода: префикс начинается с `i`, поэтому
Esc приходит из режима вставки поля (П2). Подтверждение (Enter или
цифра в одиночном выборе и разрешении) уходит только по `:w`
пользователя: цифра в одиночном выборе и разрешении заменена стрелками.

Экран, прочитанный сразу после отправки стрелок или Enter, может быть
прежним: Claude Code перерисовывает его за 12–17 мс (П4). Решение
по такому экрану отправило бы префикс с Esc в поле, из которого стрелки
уже увели выделение, и Esc закрыл бы диалог. Поэтому перед отправкой
стрелок или Enter плагин запоминает подпись диалога — пункты, отметки
и выделение; пока свежий экран с ней совпадает, правка буфера ничего
не отправляет, а решение принимается при следующей правке или событии
подписки (без опроса). После стрелок плагин знает пункт, который станет
выделенным, и ждёт его строку событием `pane.output_matched`; по событию
отложенная правка или `:w` выполняется заново, поэтому цифра, набранная
в окне перерисовки, не теряется, а стрелки до «Submit» считаются
от нового выделения. Клавиша цифры в множественном выборе выделение
не меняет и подписи не ставит. Текст в поле подписи не ставит:
следующая замена поля безопасна, пока выделение на том же пункте.

## Risks / Trade-offs

- [Детектор herdr показывает `done` при выделенном поле свободного
  ввода] → буфер диалога держится по экрану, а не по статусу (E2);
  закрытие диалога из поля без смены статуса не замечается до следующей
  правки или события.
- [Экран доверия появляется до `SessionStart`, и панель буфера при нём
  ещё не открыта] → разбор поддерживает экран доверия, живая проверка
  — с буфером, открытым вручную для этой панели.
- [Вид экранов меняется с версией Claude Code] → разбор опирается на
  подвал, `❯` и номера; сверка экранов — в `docs/claude-input.md`.
