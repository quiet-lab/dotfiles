## Context

Обновление на пути старта зависит от сети: при недоступных именах
`claude update` и `herdr update` выходят по срокам, демон стартует с задержкой
около 100 с. Исполнитель проверил, что `herdr update` отказывает «outside
herdr» из-за переменных `HERDR_*` в окружении клиента, а не из-за работающего
сервера, — обновление вне пути старта было возможно, но пользователь решил,
что оно не нужно.

## Decisions

### D1. Обновлений при старте сессии нет
herdr — собственная сборка с патчами, обновляется при пересборке; Claude Code
пользователь обновляет сам. Отдельный юнит обновления не заводится (решение
пользователя). Автообновление Claude Code в `~/.claude.json` уже выключено.

### D2. Остаются быстрые шаги
`herdr integration install claude` (под установленную версию herdr) и чистый
старт herdr — без сети, меньше секунды. Требование «Чистый старт herdr» не
меняется.

### D3. Срок юнита
`TimeoutStartSec` юнита подготовки — 30 с вместо 120 с: сети шаги не
используют.
