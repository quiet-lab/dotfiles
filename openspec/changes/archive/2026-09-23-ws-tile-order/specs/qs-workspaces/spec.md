## MODIFIED Requirements

### Requirement: Иконки workspace в плитке стола
Панель MUST получать состояние демона workspaced по его сокету (подписка) и показывать в плитке стола иконки workspace из списка этого стола. Ряд плитки MUST начинаться с иконок всех workspace стола в порядке списка демона, то есть в порядке попадания workspace на стол: иконка активного workspace подсвечена, иконки неактивных затенены. Позиции иконок workspace MUST NOT меняться при переключении workspace на столе. За иконками workspace MUST идти иконки окон активного workspace (по списку адресов окон в состоянии демона), за ними — свободные окна стола. Иконки окон неактивных workspace MUST NOT отображаться, в том числе окна, которое по списку демона принадлежит неактивному workspace, но осталось на столе. Иконка берётся из поля `icon` конфига демона через тему иконок, при отсутствии — иконка-заглушка. Левый клик по иконке workspace MUST поднимать его на этом столе через демон; правый клик MUST открывать меню с пунктами «Поднять» и «Убрать со стола»; наведение MUST показывать подсказку с именем workspace, его состоянием на столе и списком его приложений в общем всплывающем окне подсказок. Ограничение в 10 иконок и метка «+N» MUST считаться по сумме иконок окон и workspace. Без демона (сокет недоступен) плитки MUST показывать только окна, как раньше; панель MUST подключаться заново по разрыву соединения с демоном и по появлению файла его сокета (объект подключения пересоздаётся заново при каждой попытке), а также по появлению каталога `$XDG_RUNTIME_DIR/workspaced`, если панель запустилась раньше демона — периодического опроса при этом MUST NOT быть. Окна на `special:pool` MUST NOT отображаться.

#### Scenario: Активный и неактивный workspace
- **WHEN** на стол 1 первым попал `docs-front`, затем `dev-front`; активен `dev-front` с тремя окнами, на столе открыт свободный терминал
- **THEN** плитка «1» показывает затенённую иконку `docs-front`, подсвеченную иконку `dev-front`, затем три иконки окон `dev-front` и иконку терминала

#### Scenario: Поднятие кликом
- **WHEN** пользователь кликает по затенённой иконке `docs-front` в плитке «1»
- **THEN** демон поднимает `docs-front` на столе 1; иконки `docs-front` и `dev-front` остаются на прежних местах, `docs-front` подсвечена, `dev-front` затенена, за ними идут иконки окон `docs-front` и свободный терминал, иконок окон `dev-front` в плитке нет

#### Scenario: Припаркованные окна не видны
- **WHEN** окна `chat` перенесены демоном на `special:pool`, либо окно из списка неактивного workspace `chat` осталось на столе
- **THEN** ни одна плитка не показывает иконки окон `chat`

#### Scenario: Панель без демона
- **WHEN** демон остановлен, а затем запущен снова
- **THEN** пока демон остановлен, плитки показывают только иконки окон; как только демон завёл сокет заново, панель подключается без задержки и без опроса, и иконки workspace появляются сразу
