# Design: Проверка совместимости Hyprland и Quickshell с NVIDIA

## Context

Мотивация в proposal.md, раздел Why. Состояние машины на момент проектирования:

- RTX 2080 Ti, `nvidia-open` 610.57, модуль `nvidia_drm` загружен; по `modinfo` параметры `modeset` и `fbdev` включены по умолчанию, файлов в sysfs у этой ветки драйвера нет. Ранний KMS не настроен (`MODULES=()` в mkinitcpio), параметры ядра для NVIDIA не заданы, загрузчик systemd-boot.
- Установлены `egl-wayland`, `libva-nvidia-driver`, `qt6-wayland`, Xwayland 24.1.13, wayland-protocols 1.49.
- Сессия: lightdm 1.33 с `user-session=openbox` на tty7. Каталога `/usr/share/wayland-sessions` до установки пакетов не было; пакет `hyprland` кладёт туда `hyprland.desktop` и `hyprland-uwsm.desktop`. В консоли tty1 есть сессия пользователя без seat.
- Пакеты в официальных репозиториях: `hyprland` 0.56.2 (зависит от `lua`, то есть конфиг на Lua), `quickshell` 0.3.1 под Qt 6.11.2, `xdg-desktop-portal-hyprland`, `hyprpolkitagent`, `uwsm`.
- Hyprland с 0.55 объявил hyprlang устаревшим: конфиг `~/.config/hypr/hyprland.lua` загружается вместо `hyprland.conf`, если существует.
- Пользовательская карта XKB `~/.config/X11/xkb_custom` компилируется libxkbcommon 1.13 без предупреждений в обоих форматах.
- Звук: PipeWire с `pipewire-pulse`, строка `pulseaudio --start` в автозапуске Openbox мёртвая.
- Требования, которые устанавливает проверка, в specs/hyprland-session/spec.md.

## Goals / Non-Goals

**Goals:**

- Получить однозначный ответ «да» или «нет» по каждому критерию совместимости из спецификации, с обходной настройкой там, где она известна.
- Не нарушить действующую X11-сессию ни на одном шаге; откат равен выходу из Hyprland.
- Заодно снять два дешёвых риска следующего этапа: загрузку карты XKB файлом и работу Quickshell на layer-shell под NVIDIA.

**Non-Goals:**

- Рабочий конфиг Hyprland: привязки клавиш, правила окон, раскладки на Lua, зоны.
- Перенос плиток eww на Quickshell, автозапуск, блокировка, обои, портал для демонстрации экрана.
- Выбор менеджера входа и способа запуска сессии (uwsm или прямой запуск) для постоянной работы.
- Взятие пробных файлов под управление chezmoi.

## Decisions

**D1. Запуск из tty2 командой `Hyprland`, не через lightdm и не через uwsm.**
Lightdm не видит Wayland-сессий, а любая правка его конфига затрагивает вход в X11-сессию. uwsm заворачивает сессию в юниты systemd, что усложняет откат и диагностику на первой пробе. Прямой запуск из консоли оставляет tty7 с Openbox нетронутым и даёт журнал Hyprland прямо в консоли. Альтернатива «временная запись в `/usr/share/wayland-sessions`» отвергнута до прохождения проверки.

**D2. Конфиг сразу на Lua.**
Пакет 0.56 собран с Lua, hyprlang доживает один-два выпуска. Пробный конфиг на старом синтаксисе пришлось бы переписывать через месяц. Конфиг минимальный: монитор, переменные окружения, `kb_file`, привязки только для нужд чек-листа (терминал, браузер с пробным профилем, приложение под Xwayland, закрытие и плавающий режим окна, столы 1–4, переключение режима курсора, выход), включённые размытие, скругления и анимации по умолчанию.

**D3. Переменные окружения через `hl.env`, без параметров ядра и без раннего KMS.**
Набор из вики Hyprland: `LIBVA_DRIVER_NAME`, `__GLX_VENDOR_LIBRARY_NAME`, `NVD_BACKEND`, `ELECTRON_OZONE_PLATFORM_HINT`. Modeset и fbdev у драйвера 610 включены по умолчанию, поэтому `/etc/modprobe.d` для них не трогаем. Ранний KMS вики отмечает как ломающий возврат из гибернации, а пользы для проверки он не даёт.

**D4. Курсор: сначала аппаратный, программный только по факту артефактов.**
`cursor:no_hardware_cursors` включается лишь если аппаратный курсор мерцает или пропадает. Результат проверки записывается вместе с выбранным режимом, чтобы рабочий конфиг унаследовал его осознанно.

**D5. Пробные файлы только в `$HOME`.**
`~/.config/hypr/hyprland.lua` и `~/.config/quickshell/nvcheck/shell.qml` создаются вручную и не добавляются в chezmoi. Источник chezmoi хранит рабочие конфиги, а пробный за время проверки будет меняться много раз и в истории не нужен. Следующее изменение возьмёт под управление уже рабочий конфиг. Альтернатива «добавить в chezmoi сразу» отвергнута, чтобы `chezmoi status` оставался чистым индикатором изоляции (см. спецификацию).

**D6. Проба Quickshell: одна панель на layer-shell с непрерывной анимацией.**
`PanelWindow` у левого края с зарезервированной зоной 330px, как у будущей колонки плиток, внутри элемент с бесконечной анимацией и часы. Замирания ищутся по остановке анимации и по отклику на клик. При замираниях сравниваются режимы `QSG_RENDER_LOOP=basic` и `threaded`; это единственная известная ручка со стороны Qt. Размытие фона панели включается правилом слоя в Hyprland, чтобы проверить взаимодействие layer-shell и эффектов.

**D7. Карта XKB подключается файлом как есть.**
`kb_file` указывает на `~/.config/X11/xkb_custom`; ни одна привязка в пробном конфиге не занимает Win+Пробел, Alt+E и Alt+R, иначе композитор перехватит их раньше XKB. Успех проверяется вводом в терминале.

**D8. Результаты записываются в tasks.md.**
Каждая проверка это задача с отметкой и короткой записью результата (что наблюдалось, какой обходной режим включён). Отдельного отчёта не заводится; при архивировании спецификация `hyprland-session` отражает подтверждённые условия.

## Risks / Trade-offs

- [NVIDIA для Hyprland не поддерживается официально] → чек-лист из вики выполнен заранее, версии драйвера и протоколов выше порогов; при провале критерия фиксируется причина, а не подбирается бесконечно обходной путь.
- [Задержки основного потока Qt6 под NVIDIA на Wayland, о которых сообщают на форуме CachyOS] → проверка D6 воспроизводит именно этот сценарий; при провале в обоих режимах отрисовки вопрос об оболочке возвращается к обсуждению, а не решается молча.
- [Переключение консолей на NVIDIA может оставить чёрный экран] → перед пробой открыт вход на tty1; при зависании сессию можно завершить через `loginctl terminate-session` с другой консоли.
- [Handy.AppImage под Xwayland может не запуститься по причинам, не связанным с драйвером] → проверяется вторым клиентом Xwayland (любое X11-приложение из системы), чтобы отделить проблему приложения от проблемы Xwayland.
- [Пробные файлы вне chezmoi легко забыть] → задача на их судьбу (перенос или удаление) стоит последней в tasks.md.

## Migration Plan

1. Закоммитить висящую в рабочем дереве вычистку joyful-desktop до начала, чтобы история не смешалась (по просьбе пользователя).
2. Установить пакеты; это не меняет X11-сессию.
3. Создать пробные файлы, пройти чек-лист из tty2, записывать результаты по ходу.
4. Итог: решение о следующем этапе.

Откат: выйти из Hyprland; при желании удалить пакеты `pacman -Rns`, файл в `/etc/modprobe.d` и выключить службы `nvidia-*`; пробные файлы в `$HOME` удалить. Ни один управляемый chezmoi файл не меняется.

## Open Questions

- Постоянный способ запуска сессии: uwsm с юнитами systemd или прямой запуск из менеджера входа. Не влияет на проверку, решается в изменении про автозапуск.
- Менеджер входа для Wayland: остаться на lightdm с записью в `wayland-sessions` (запись `hyprland.desktop` уже установлена пакетом), перейти на sddm или greetd. Решается вместе с предыдущим вопросом.
- Оставлять ли eww поверх Hyprland на переходный период (сборка с layer-shell уже есть) или переносить плитки на Quickshell сразу. Решается после результатов D6.

## Решения для следующего изменения

Приняты пользователем 2026-09-10 по итогам проверки; реализуются в изменении про рабочий конфиг и автозапуск сессии Hyprland.

- **Голосовой ввод.** `Handy.AppImage` в пробной сессии не запускался. В сессии Hyprland он MUST запускаться из автозапуска, либо вместо него используется VoxType (пакет `voxtype` 0.7.5 из AUR уже установлен, ориентирован на Wayland). Выбор между ними делается в следующем изменении после запуска обоих из сессии Hyprland.
- **wezterm.** В пробе wezterm был клиентом Xwayland не из-за настройки `enable_wayland` (в сборке `~/builds/wezterm` по умолчанию `true`), а потому что сборка сделана без возможности `wayland`: отпечаток cargo для `wezterm-gui` содержит только `vendored-fonts`. wezterm пересобирается штатной командой `cargo build --release` с набором возможностей по умолчанию (включает `wayland`); проверка нативного окна wezterm в сессии Hyprland входит в следующее изменение.
