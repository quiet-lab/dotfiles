## Context

VoxType печатает распознанный текст виртуальной клавиатурой `wtype`.
Пока эта виртуальная клавиатура существует, Hyprland временно делает её
клавиатурой сиденья и передаёт окну её карту — карту из одной раскладки,
без группы 1. Когда `wtype` завершается и виртуальная клавиатура пропадает,
Hyprland возвращает клавиатуру сиденья на реальное устройство и присылает
окну полную карту us+ru, но не присылает вместе с ней событие `modifiers`
с номером группы. Клиентские приложения заводят состояние xkb для новой
карты с группой 0 по умолчанию, поэтому окно печатает латиницу, пока
что-нибудь не пришлёт группу явно. Подробный разбор по исходникам Hyprland
и по событиям `wev` — в `docs/media-and-portals.md`.

## Decisions

- **Перехват в самом VoxType (`post_output_command`), а не таймер.**
  Событие «вывод текста закончен» у VoxType уже есть и ровно совпадает
  с моментом, когда виртуальная клавиатура исчезает и карта окна
  устаревает. Опрос состояния клавиатуры по расписанию не нужен: правило
  проекта запрещает таймеры там, где есть источник событий
  (`docs/decisions/0007-no-timers.md`), а здесь он есть.
- **Переключение группы на 0 и обратно одним `hyprctl --batch`, а не
  `switchxkblayout` сразу на нужный номер.** Именно переключение (а не
  установка того же значения) Hyprland проводит как изменение модификаторов
  клавиатуры: она снова становится клавиатурой сиденья, и только тогда
  окно получает `modifiers` с её настоящей группой. Один пакетный запрос —
  чтобы оба шага пришли одним сообщением композитору и не создавали видимого
  промежуточного состояния.
- **Отвергнутые способы** (разобраны при поиске причины 23.09.2026):
  - `switchxkblayout <клавиатура> <та же группа>` без промежуточного
    переключения на 0 — Hyprland не шлёт `modifiers`, когда новое значение
    совпадает с текущим: карта фактического изменения не претерпевает.
  - Смена фокуса окна (увести и вернуть) — событие фокуса присылает группу
    клавиатуры сиденья на момент смены, то есть 0 (последнее устройство
    списка после `wtype` — не физическая клавиатура), а не группу, которую
    показывает плитка раскладки.
  - Ждать первого нажатия модификатора пользователем — оно действительно
    чинит раскладку, но делает это не всегда сразу и не по событию, которое
    можно перехватить: ошибка тем и была незаметной, что чинилась случайным
    следующим нажатием, а не сразу после диктовки.
- **Клавиатуры с группой 0 не трогаются.** Для них новое состояние xkb уже
  верное (группа 0 совпадает), а лишнее переключение только заставило бы
  плитку раскладки дважды мигнуть без надобности.
- **Правило одобрено пользователем 22.09.2026**: серия шагов и мелкие
  доработки в этой части системы не ждут отдельного подтверждения
  на каждом шаге, решения по ходу фиксируются в `design.md` и документации,
  а не выносятся вопросом.
