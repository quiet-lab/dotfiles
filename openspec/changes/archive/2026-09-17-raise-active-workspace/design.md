# Design: Поднятие workspace, уже активного на другом столе

## Context

`raise(ws, desktop)` брал стол из аргумента, а без него — текущий, и дальше переносил на него все окна workspace. Цепочка workspace, `next` и путь цепочки приложения по списку текущего стола вызывают `raise` без стола (последний — со своим столом, равным текущему). Workspace может числиться в списках нескольких столов, но активен не более чем на одном (`Desktop.active`).

## Goals / Non-Goals

**Goals:**
- Цепочка ведёт к уже поднятому workspace, не перетаскивая его.

**Non-Goals:**
- Изменение явной миграции по `--desktop` и по записям `[[binds]]` со столом.

## Decisions

**D1. Стол по умолчанию — тот, где workspace активен.** В `raise` без явного стола ищется стол с `active == ws`; найденный становится целевым, иначе берётся текущий. Дальше работает прежняя последовательность: переход на стол, расстановка окон (они уже на месте), фокус главного окна. Отдельной ветки «только перейти и сфокусировать» нет: повторная расстановка по ячейкам дёшева и заодно возвращает окна, сдвинутые пользователем.

**D2. Путь цепочки приложения по списку текущего стола вызывает `raise` без стола.** Раньше он передавал текущий стол явно, что читалось бы как миграция; смысл этого шага — «поднять workspace из списка стола», и правило D1 к нему применимо.

## Risks / Trade-offs

- [Пользователь хочет перетащить workspace на текущий стол] → запись `[[binds]]` со столом или `workspaced raise <ws> --desktop N`.
