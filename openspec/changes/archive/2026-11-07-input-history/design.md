# Design: История ввода в буфере ввода

## Источник и проект

Файл `~/.claude/history.jsonl` (путь — поле `M.HISTORY_PATH`, тесты подставляют
свой): строка на запрос с полями `display` и `project`. Берутся записи, у которых
`project` равен `cwd` панели Claude Code из ответа `pane.get` для
`CLAUDE_INPUT_PANE`. Строки чужих проектов отсеиваются проверкой подстроки
`"project":"<cwd>"` до разбора JSON (файл около 2 МБ). Подряд одинаковые `display`
схлопываются. Текст записи вставляется как есть, метки вставок — текстом.

## Клавиши

`<Up>` работает на первой экранной строке буфера, `<Down>` — на последней
строке; иначе стрелка двигает курсор как обычно (привязка `expr` возвращает
исходную клавишу). `k` и `j` не меняются, буфер диалога не затрагивается.

## Листание и сброс

Состояние `state.hist`: список, позиция, черновик (текст буфера на момент первого
`<Up>`), текст, показанный листанием. `<Up>` берёт более старую запись, на самой
старой ничего не делает; `<Down>` за самой новой возвращает черновик. Содержимое
заменяется целиком, курсор — в конец; отправку в строку ввода Claude Code ведёт
обычная `schedule_send`, вызываемая сразу (событие `TextChanged` после правки из
обратного вызова приходит не всегда). Правка, чей текст не равен показанному
листанием, а также `:w`, `<S-CR>`, `<S-Space>` и возврат из буфера диалога
сбрасывают позицию. Ответ `pane.get`, пришедший после сброса, отбрасывается
(счётчик `hist_seq`).

## Чтение без наблюдателей

Файл читается при первом `<Up>` после сброса: после `:w` Claude Code дописывает
запись, и следующее листание её видит. Наблюдателей и таймеров нет
(`docs/decisions/0007-no-timers.md`). Нет файла или `cwd` — клавиши ведут себя как
обычно, без сообщений об ошибках.
