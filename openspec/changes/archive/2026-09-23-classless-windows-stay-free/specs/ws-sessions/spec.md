## MODIFIED Requirements

### Requirement: Файлы сессий
Сессии MUST храниться в `~/.local/state/workspaced/sessions/<имя>.toml`, по файлу на сессию. Файл MUST содержать: время снимка, номер активного стола, для каждого стола список workspace по порядку и активный, для каждого workspace назначение приложений по ячейкам и таблицу дополнительных приложений сессии, и список окон: для окна приложения — имя приложения, стол или `pool`, прямоугольник; для свободного окна — стол, командную строку, каталог и прямоугольник. Запись дополнительного приложения сессии MUST хранить его имя ключом таблицы, прямоугольник и, если запись описывает не приложение конфига, класс окна, командную строку и каталог процесса. Таблица дополнительных приложений MUST быть необязательной: снимок прежнего формата MUST читаться без ошибки. Поле `workspace` у свободного окна в снимках прежних версий MUST читаться без ошибки и MUST NOT учитываться и записываться.

Снимок `default` MUST записываться только по команде сохранения сессии — цепочке `save_session` или `workspaced save-session` (требование «Дополнительные приложения сессии»). События композитора и остальные команды демона файл MUST NOT изменять: снимок — это сохранённое состояние, к которому возвращаются, а не след последнего действия. Отложенной записи и записи по таймеру MUST NOT быть. Перед загрузкой именованной сессии демон MUST записать `default` (требование «Загрузка сессии»): это единственный случай, когда файл обновляется не по команде сохранения, и он тоже вызван явной командой пользователя. Именованная сессия MUST записываться только по команде `session save <имя>` или из окна выбора и MUST быть копией текущего состояния на момент команды.

Состояние, изменившееся после последнего снимка — принятые окна, переносы workspace между столами, обмен ячеек, списки столов и записи ожидания запуска, — MUST жить только в памяти демона: перезапуск демона и перезагрузка системы MUST возвращать систему к последнему записанному снимку.

Командная строка и каталог, которые демон записывает для окна — в снимке сессии, в записи дополнительного приложения сессии и в разделе workspace по команде сохранения, — MUST быть пригодны для запуска с хоста. У процесса в песочнице flatpak путь к исполняемому файлу и рабочий каталог существуют только внутри песочницы, поэтому командной строкой такого окна MUST записываться `flatpak run <идентификатор приложения>` и исходные аргументы процесса после пути к исполняемому файлу, а каталог MUST NOT записываться. Идентификатор приложения MUST браться из `/proc/<pid>/cgroup` по юниту вида `app-flatpak-<идентификатор>-<номер>.scope`, причём экранирование `\xNN` в имени юнита MUST раскодироваться. Если юнита такого вида нет, MUST записываться командная строка процесса, приведённая к виду, пригодному для запуска: строка, которую процесс переписал одной строкой с пробелами вместо отдельных аргументов (так делают Chromium и основанные на нём браузеры), MUST делиться по пробелам, если файла с таким именем нет; относительный путь к исполняемому файлу (`./steamwebhelper`) MUST заменяться абсолютным от рабочего каталога процесса; имя без каталога MUST оставаться как есть, если находится в `PATH`; если исполняемый файл так не найден, вместо него MUST браться путь из `/proc/<pid>/exe`. Если не найден и он, у окна нет командной строки: в снимок оно MUST NOT попадать, дополнительным приложением MUST NOT становиться, а демон MUST записать предупреждение в журнал. Команду свободного окна из снимка прежней версии демон MUST приводить к тому же виду перед запуском и сверкой с открытыми окнами; команду, исполняемый файл которой не найден, демон MUST NOT запускать и MUST записать предупреждение в журнал.

#### Scenario: Автосохранение
- **WHEN** выполнена команда `workspaced raise dev-front --desktop 1`, затем открыто новое окно
- **THEN** `default.toml` не изменился: снимок сам по себе не пишется, и время изменения файла прежнее

#### Scenario: Снимок пишет команда сохранения
- **WHEN** после этого нажата цепочка `save_session`
- **THEN** к моменту, когда команда вернула управление, `default.toml` содержит стол 1 с активным `dev-front` и все его окна с прямоугольниками

#### Scenario: Изменения после последнего снимка не переживают перезапуск
- **WHEN** после команды сохранения пользователь перенёс `work` на стол 3, принял там новое окно и перезапустил демон
- **THEN** демон восстанавливает состояние на момент сохранения: `work` снова на прежнем столе, принятого окна в его составе нет

#### Scenario: Именованный снимок
- **WHEN** выполнена `workspaced session save review`
- **THEN** появляется `review.toml` с состоянием на этот момент; дальнейшая работа его не меняет

#### Scenario: Дополнительное приложение в снимке
- **WHEN** в `work` принят калькулятор, не описанный в конфиге, и нажата цепочка `save_session`
- **THEN** к возврату команды в `default.toml` у `work` есть запись дополнительного приложения с классом окна, командной строкой, каталогом и прямоугольником, а само окно записано как окно этого приложения

#### Scenario: Окно программы из flatpak
- **WHEN** в `work` принято окно Postman, запущенного из flatpak с аргументами `--force-device-scale-factor=1.5` и `--no-sandbox`, и нажата цепочка `save_session`
- **THEN** командной строкой записано `flatpak run com.getpostman.Postman --force-device-scale-factor=1.5 --no-sandbox`, каталога у записи нет, и этой командой окно поднимается с хоста; путь `/app/extra/Postman/postman` в снимок не попадает

#### Scenario: Командная строка Chromium
- **WHEN** свободное окно Chromium, процесс которого показывает в `/proc/<pid>/cmdline` одну строку `/usr/lib/chromium/chromium --ozone-platform=wayland`, попадает в снимок
- **THEN** командой записаны два элемента, `/usr/lib/chromium/chromium` и `--ozone-platform=wayland`, и этой командой окно поднимается

#### Scenario: Относительная команда
- **WHEN** свободное окно Steam принадлежит процессу с командой `./steamwebhelper …` и рабочим каталогом `~/.local/share/Steam/ubuntu12_64`, и нажата цепочка `save_session`
- **THEN** командой в снимке записан абсолютный путь `/home/mne/.local/share/Steam/ubuntu12_64/steamwebhelper` с прежними аргументами; снимок прежней версии с `./steamwebhelper` при восстановлении запускается тем же абсолютным путём

#### Scenario: Снимок прежней версии с привязками
- **WHEN** в `default.toml` у свободного окна записано `workspace = "work"`, а таблицы дополнительных приложений в файле нет
- **THEN** демон читает снимок, ставит окно на его место на столе, но к `work` не привязывает; после следующей записи снимка поля `workspace` у окна нет

### Requirement: Дополнительные приложения сессии
Окно, принятое в workspace по событию (спецификация ws-daemon, «Посторонние окна») или по команде сохранения сессии, MUST становиться дополнительным приложением сессии этого workspace, если приложения с таким местом в workspace ещё нет. Запись MUST жить только в сессии: файл конфига демон MUST NOT изменять. Если окно подходит приложению конфига, дополнительным приложением MUST становиться само это приложение с прямоугольником окна — и только тогда, когда в этом workspace его ещё нет. Если подходящего приложения нет, демон MUST завести дополнительное приложение сессии с именем, построенным из класса окна и не совпадающим ни с одним именем приложения конфига или другого дополнительного приложения, и записать у него класс окна, командную строку и каталог процесса окна (по правилу требования «Файлы сессий») и его прямоугольник. Окно MUST получить тег экземпляра этого приложения. Имя дополнительного приложения MUST быть единственным в сессии: одно имя MUST называть одну программу, и окно другой программы MUST NOT приписываться чужой записи, даже если класс окна тот же (спецификация ws-daemon, «Посторонние окна»). Окно без класса и окно, для процесса которого не найден исполняемый файл, дополнительным приложением MUST NOT становиться: первое не отличить от служебного окна приложения, второе нечем запустить заново.

По цепочке `save_session` или команде `workspaced save-session` демон MUST записать снимок сессии целиком. Команда MUST пройти по всем столам, на которых активен workspace, и принять в него окна без тега по тем же правилам, что действуют при появлении окна; местом принятого окна MUST становиться прямоугольник, который окно занимает сейчас, — окно, уже поставленное пользователем куда нужно, команда MUST NOT двигать. Затем команда MUST обновить прямоугольники дополнительных приложений сессии по нынешнему положению их окон (у приложения с несколькими окнами — по первому экземпляру) и записать снимок. Приложения, описанные в конфиге, MUST сохранять своё место и главную ячейку: их ведёт файл. Команда MUST записать в журнал строку с числом workspace, числом их окон и числом принятых окон. Файл конфига команда MUST NOT изменять.

Дополнительное приложение сессии демон MUST во всём остальном вести как приложение workspace: его окна MUST переноситься вместе с workspace на другой стол, MUST парковаться при вытеснении workspace и возвращаться с ним, MUST вставать на свой прямоугольник при поднятии workspace и MUST входить в состав окон workspace для панели. Если в конфиге появляется приложение с именем дополнительного приложения сессии, MUST действовать запись конфига, а дополнительное приложение MUST быть снято с записью предупреждения в журнал. Запись, которая называет приложение конфига и задаёт ему только место, MUST быть снята, когда приложения с таким именем в конфиге не стало; запись workspace, которого в конфиге не стало, MUST быть снята так же. Запись MUST сниматься и тогда, когда закрывается последнее окно приложения по команде отделения окна (спецификация ws-daemon, «Отделение окна»): запись с командной строкой — во всех workspace, где она есть. Перечитывание конфига MUST сохранять дополнительные приложения сессии, кроме снятых по этим правилам.

#### Scenario: Окно из лаунчера становится частью workspace
- **WHEN** на столе 1 активен `work` и из лаунчера открыт калькулятор, не описанный в конфиге
- **THEN** `config.toml` не изменился, `chezmoi status` пуст, окно калькулятора несёт тег `app:<имя>#1`, плитка стола 1 показывает его значок, а поднятие `work` на столе 3 переносит калькулятор туда вместе с окнами `work`

#### Scenario: Окно подходит приложению конфига
- **WHEN** на столе 2 активен `surf`, в котором описаны `chrome` и `yandex-browser`, и открыто окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai`
- **THEN** окно получает тег `app:chrome-ai#1`, дополнительным приложением `surf` становится `chrome-ai` с прямоугольником окна, нового приложения с именем по классу окна не появляется, `config.toml` не изменился

#### Scenario: Команда сохранения проходит по всем столам
- **WHEN** на столе 1 активен `work`, на столе 2 активен `surf`, на столе 2 открыто окно, появившееся до поднятия `surf` и потому оставшееся свободным, и нажата цепочка `save_session`
- **THEN** окно входит в `surf` дополнительным приложением с нынешним прямоугольником, снимок записан, в журнале строка с числом workspace, их окон и принятых окон

#### Scenario: Места дополнительных приложений обновляются
- **WHEN** принятое окно калькулятора передвинуто пользователем и нажата цепочка `save_session`
- **THEN** у дополнительного приложения записан новый прямоугольник, и следующее поднятие `work` ставит калькулятор туда, а не на прежнее место

#### Scenario: Посторонних окон нет
- **WHEN** на столах все окна уже входят в свои workspace и нажата цепочка `save_session`
- **THEN** снимок всё равно записан, в журнале демона строка с числом workspace, их окон и нулём принятых окон

#### Scenario: Места описанных приложений не трогаются
- **WHEN** в `work` пользователь сдвинул окно Chromium из ячейки `left` и нажал цепочку `save_session`
- **THEN** у `chromium` в назначениях workspace остаётся ячейка `left`, главная ячейка прежняя, и следующее поднятие `work` возвращает Chromium в `left`

#### Scenario: Приложение появилось в конфиге
- **WHEN** дополнительное приложение сессии `galculator` живёт в `work`, и пользователь дописал в конфиг `[apps.galculator]`
- **THEN** после перечитывания конфига действует описание из файла, дополнительное приложение снято, в журнале демона предупреждение об этом

#### Scenario: Окна без класса не становятся приложением
- **WHEN** на столе 1 активен `work`, на столе 2 — `surf`, в Chromium и в Яндекс.Браузере открыты диспетчеры задач, окна которых пришли с пустым классом, и нажата цепочка `save_session`
- **THEN** оба окна остаются свободными, ни в `work`, ни в `surf` нет дополнительного приложения `app`, в снимке они записаны свободными окнами со своими командами, и поднятие `surf` запускать нечего
