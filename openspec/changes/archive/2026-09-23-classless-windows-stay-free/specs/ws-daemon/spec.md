## MODIFIED Requirements

### Requirement: Посторонние окна
Окно без тега, появившееся на столе, где активен workspace, MUST входить
в этот workspace. Демон MUST решать по одному правилу, одинаковому для
появления окна и для команды сохранения сессии, в таком порядке: окно без класса (композитор сообщает пустой `class`; так
приходят, например, окна диспетчера задач Chromium и Яндекс.Браузера) MUST
оставаться свободным всегда — при появлении, при поднятии workspace и при
командах сохранения, — и дополнительным приложением оно MUST NOT становиться:
чьё это окно, по нему не определить; окно, класс которого подходит списку
`ignore_classes` конфига, MUST оставаться свободным всегда; окно, подходящее приложению эффективного конфига по `class` и `title`,
MUST становиться окном этого приложения (требование «Захват открытых окон
приложения»), а если его заголовок подходит `dialog_title` этого приложения —
оставаться свободным там, где его поставил композитор; окно на столе без
активного workspace MUST оставаться свободным; окно, у которого не удалось
прочитать командную строку процесса или найти её исполняемый файл
(требование «Файлы сессий» спецификации ws-sessions), MUST оставаться
свободным с записью в журнал. Причину, по которой окно осталось свободным, демон MUST записывать
в журнал вместе с адресом окна, его классом и заголовком.

Принятое окно приложения, которого в файле конфига нет, MUST становиться
дополнительным приложением сессии этого workspace (требование
«Дополнительные приложения сессии» спецификации ws-sessions): имя MUST
строиться из класса окна и не совпадать ни с одним именем приложения конфига
или другого дополнительного приложения, запись MUST хранить класс окна,
командную строку и каталог процесса и прямоугольник окна. Одно имя MUST
называть одну программу: окно, которое по классу подходит дополнительному
приложению сессии другого workspace, MUST получать имя этой записи, только
если его процесс запущен тем же исполняемым файлом; окно другой программы
с тем же классом MUST заводить новое дополнительное приложение со своим
именем, а чужую запись MUST NOT менять. Принятое окно
приложения, которое в конфиге описано, но в этот workspace не входит, MUST
давать запись только о месте — под именем этого приложения. Приложение,
которое в workspace уже есть, MUST получать лишь ещё один экземпляр: ни его
место, ни главная ячейка MUST NOT меняться.

Место принятого окна MUST определяться правилом мест требования «Расстановка
окон»: ячейка или `rect`, записанные для приложения в этом workspace; то же
у его семейства; `rect` самого приложения; центр экрана с нынешним размером
окна. Окна одного приложения MUST вставать стопкой на место первого. Стол
окна демон MUST NOT менять, а фокус MUST NOT трогать: его новому окну уже
отдал композитор.

Свободное окно MUST оставаться вне workspace: поднятие и удаление workspace
MUST NOT переносить его, в состав окон workspace для панели оно MUST NOT
входить, в снимке сессии оно MUST записываться без workspace. То же MUST
относиться к окнам без тега, найденным при старте демона и не совпавшим
со снимком. Перенос свободного окна пользователем на другой стол MUST быть
допустим, демон его не отменяет. Частью workspace свободное окно MUST
становиться по команде сохранения сессии (на время сессии) либо по команде
сохранения workspace (записью в конфиг).

Окно, чей тег `app:<имя>#<номер>` называет приложение, которого в эффективном
конфиге (файл конфига вместе с дополнительными приложениями сессии) нет, MUST
становиться свободным: демон MUST снять с окна теги `app:` диспетчером
композитора, завести его посторонним окном с командной строкой и каталогом
процесса, как любое окно без тега, и записать строку в журнал с адресом окна,
его классом и именем исчезнувшего приложения. Тег `app:<имя>` без номера,
оставшийся от прежней версии демона, MUST проверяться так же. Проверка MUST
выполняться после каждого перечитывания конфига, при первичной сверке окон
на старте демона и при загрузке сессии — то есть всякий раз, когда меняется
состав приложений. Окна дополнительных приложений сессии свободными MUST NOT
становиться: эти приложения входят в эффективный конфиг.

Той же проверкой MUST сниматься записи ожидания окна: если приложения, окно
которого демон ждёт, в эффективном конфиге больше нет, запись ожидания MUST
быть снята со строкой в журнале, и в `workspaced status --json` её MUST
NOT остаться. Запущенный процесс демон MUST NOT завершать, а его окно, если
оно всё-таки появится, MUST быть разобрано по общему правилу.

### Requirement: Захват открытых окон приложения
Если у приложения заданы `class` и, при необходимости, `title`, то при
появлении нового окна, при поднятии workspace с этим приложением и при вызове
приложения по цепочке демон MUST найти среди открытых окон на любом столе
и на `special:pool` все окна, класс которых целиком совпадает с регулярным
выражением `class`, а заголовок — с `title` (если задано), и без тега либо
с тегом приложения, отсутствующего в конфиге; окно на `special:hidden` MUST
NOT захватываться, окно, класс которого подходит списку `ignore_classes`
конфига, MUST NOT захватываться тоже. Окно без класса (пустой `class`)
MUST NOT захватываться ни одним приложением, даже если его выражение `class`
подходит пустой строке; запуск приложения MUST NOT принимать такое окно своим,
даже если его процесс — потомок запущенного процесса (требование
«Посторонние окна»). Каждое найденное окно MUST получить тег
экземпляра приложения (прежний тег снимается) и дальше MUST считаться окном
приложения: переноситься на стол, ставиться на своё место, участвовать
в цепочке и сессии. Окно, подходящее и варианту, и его семейству, MUST
достаться варианту: более точное совпадение побеждает. Если окно подходит
нескольким вариантам одного семейства, демон MUST отдать его первому варианту
в порядке имён и записать предупреждение в журнал. Захват MUST выполняться
и для приложения, у которого окна уже есть: у приложения MUST быть допустимо
несколько окон. Если подходящего окна нет, приложение с `cmd` MUST быть
запущено, как раньше, а приложение без `cmd` MUST остаться без окна с записью
в журнал. Приложение без `class` MUST NOT захватывать чужие окна. Окно с тегом
приложения, которого нет в конфиге, и не захваченное никем, MUST считаться
свободным: при поднятии workspace оно MUST NOT парковаться на `special:pool`.

Окно, появившееся само (пользователь открыл второе окно приложения, приложение
открыло окно в ответ на действие в другом окне), MUST захватываться сразу,
не дожидаясь поднятия workspace или вызова приложения. Такое окно MUST
получить тег экземпляра со следующим свободным номером и MUST встать на место
своего приложения по первому подходящему правилу: ячейка или `rect`,
записанные для приложения в workspace, активном на столе этого окна; то же,
записанное там для его семейства; `rect` самого приложения. Если приложения
нет в активном workspace стола, оно MUST быть принято в этот workspace
записью о месте (требование «Посторонние окна»), и местом MUST стать центр
экрана с нынешним размером окна. Если активного workspace на столе нет
и `rect` у приложения не задан, окно MUST остаться там, где его открыл
композитор: центрировать окно демон MUST NOT. На другой стол демон окно MUST
NOT переносить, а фокус MUST NOT трогать — фокус новому окну уже отдал
композитор. В режиме `stack` прямоугольник такого окна MUST запоминаться сразу
(требование «Расстановка окон»). Окна, которого ждёт запуск приложения или
восстановление постороннего окна из снимка сессии, это правило MUST NOT
касаться: такое окно MUST приниматься ожиданием, как раньше.

Отличить диалог приложения от обычного его окна демон не может: Hyprland
0.56.2 не сообщает ни родителя окна, ни его модальности — ни в `hyprctl
clients -j`, ни в объекте окна Lua, ни в событии `openwindow`. Поэтому
собственный диалог приложения, приходящий с тем же классом, MUST отделяться
полем `dialog_title` этого приложения: окно с подходящим заголовком
не захватывается и остаётся свободным. Диалог, приходящий отдельным классом,
приложению не подходит и MUST отделяться списком `ignore_classes`.

#### Scenario: Новое окно Chrome по Ctrl+N на месте приложения
- **WHEN** на столе 2 активен `surf` (`mode = "stack"`), приложение `chrome` записано в ячейку `left`, у него одно окно, и пользователь нажал Ctrl+N в окне Chrome
- **THEN** новое окно получает тег `app:chrome#2`, встаёт в ячейку `left` поверх первого окна Chrome, остаётся на столе 2 и сохраняет фокус, который дал ему композитор

#### Scenario: Новое окно в workspace режима обмена ячеек
- **WHEN** на столе 1 активен `work`, `chromium` стоит в ячейке `left`, и пользователь нажал Ctrl+N в окне Chromium
- **THEN** новое окно получает тег `app:chromium#2` и встаёт в ячейку `left`; если `chromium` к этому моменту обменом ячеек переведён в `center`, окно встаёт в `center` — туда, где приложение стоит сейчас

#### Scenario: Новое окно приложения вне активного workspace
- **WHEN** на столе 2 активен `surf`, `chromium` в него не входит, своего `rect` у `chromium` нет, и на столе 2 появилось второе окно Chromium
- **THEN** окно получает тег `app:chromium#2`, встаёт в центр экрана со своим размером и входит в `surf` записью о месте; поднятие `surf` на другом столе переносит его туда

#### Scenario: Новое окно приложения со своим местом
- **WHEN** у приложения `calc` задан `rect = { x = 2600, y = 1500, w = 600, h = 400 }`, ни в один активный workspace оно не входит, и его окно появилось на столе без активного workspace
- **THEN** окно получает тег `app:calc#1` и встаёт в этот прямоугольник

#### Scenario: Окно диалога не захватывается
- **WHEN** у приложения `chromium` задано `dialog_title = "^DevTools"`, и пользователь отстыковал окно средств разработки
- **THEN** окно средств разработки тега не получает, остаётся там, где его открыл композитор, и в ячейку `chromium` не встаёт

#### Scenario: Открытый Chromium попадает в workspace
- **WHEN** у приложения `chromium` задано `class = "(?i)^chromium(-browser)?$"`, на столе 3 открыто окно класса `Chromium-browser` без тега, и на столе 1 поднят workspace `work` с `chromium` в ячейке `left`
- **THEN** окно получает тег `app:chromium#1`, переносится на стол 1 в ячейку `left`, новый Chromium не запускается

#### Scenario: Захватываются все подходящие окна
- **WHEN** открыты три окна Chromium без тегов и поднят `work` с `chromium` в ячейке `left`
- **THEN** все три окна получают теги `app:chromium#1`, `app:chromium#2`, `app:chromium#3`, стоят в ячейке `left` одно поверх другого, и ни одно из них не остаётся свободным

#### Scenario: Окно достаётся варианту, а не семейству
- **WHEN** у семейства `chromium` задано `class = "(?i)^chromium(-browser)?$"`, у его варианта `chromium-mail` — тот же `class` и `title = "^Gmail"`, открыты окно с заголовком «Gmail — Входящие» и окно с заголовком «Новости», и поднят workspace с `chromium` и `chromium-mail`
- **THEN** окно «Gmail — Входящие» получает тег `app:chromium-mail#1`, окно «Новости» — тег `app:chromium#1`, и в ячейку варианта встаёт только окно Gmail

#### Scenario: Терминал с herdr отличается заголовком
- **WHEN** у приложения `herdr` заданы `class = "^org\\.wezfurlong\\.wezterm$"` и `title = "^herdr · "`, открыты два окна wezterm: с заголовком «herdr · dev-lab» и «bash · mne@dev-lab», и поднят `work`
- **THEN** захватывается окно с заголовком «herdr · dev-lab» и получает тег `app:herdr#1`, второе окно достаётся семейству `wezterm`, если оно описано, иначе остаётся свободным

#### Scenario: Вариант опознаётся своим классом
- **WHEN** у семейства `wezterm` задано `class = "^org\\.wezfurlong\\.wezterm$"`, у его варианта `herdr` — `class = "^wezterm-herdr$"`, открыты окно класса `wezterm-herdr` и окно класса `org.wezfurlong.wezterm`, и поднят `work` с `herdr` в ячейке `center`
- **THEN** окно класса `wezterm-herdr` получает тег `app:herdr#1` и встаёт в ячейку `center`

#### Scenario: Окно с тегом удалённого приложения
- **WHEN** окно neovide несёт тег `app:editor-dots#1`, приложения `editor-dots` в конфиге больше нет, а у `neovide` задано `class = "^neovide$"`, и поднят `work`
- **THEN** тег `app:editor-dots#1` снят, окно получает тег `app:neovide#1` и занимает ячейку `right`

#### Scenario: Подходящего окна нет
- **WHEN** окон класса `neovide` нет и поднят `work`
- **THEN** демон запускает `neovide`, как для любого приложения без окна

#### Scenario: Семейство без команды запуска
- **WHEN** у семейства `wezterm` задан только `class`, ни одного окна wezterm нет, и поднят workspace с `wezterm` в ячейке
- **THEN** ничего не запускается, ячейка остаётся пустой, в журнале запись о том, что у приложения нет `cmd`

#### Scenario: Окно без класса не захватывается
- **WHEN** открыто окно диспетчера задач Яндекс.Браузера с пустым классом, в конфиге есть приложение, выражение `class` которого подходит любой строке, и поднят workspace с этим приложением
- **THEN** окно диспетчера задач тега не получает и остаётся на своём месте, а приложение захватывает только окна с непустым классом либо запускается

#### Scenario: Окно с устаревшим тегом остаётся на столе
- **WHEN** окно firefox несёт тег `app:firefox#1`, приложения `firefox` в конфиге нет, и на его столе поднят `work`
- **THEN** окно остаётся на столе там же, где было, а не уходит на `special:pool`

### Requirement: Поднятие workspace на столе
По цепочке workspace, записи `[[binds]]` с `workspace` или команде `workspaced raise <workspace> [--desktop N]` демон MUST поднять workspace на указанном столе. Без явного стола демон MUST сначала проверить, активен ли workspace на каком-либо столе: если да, целевым столом MUST стать тот стол, композитор MUST перейти на него, а фокус MUST получить первый экземпляр приложения главной ячейки, без переноса окон; если нет, целевой стол — активный. Явный стол (`--desktop N`, запись `[[binds]]` со столом, команда переноса `workspaced move-desktop N`) MUST переносить workspace и тогда, когда он активен на другом столе. При поднятии на целевом столе: окна всех экземпляров его приложений, где бы они ни находились (другой стол, `special:pool`), MUST быть перенесены на этот стол без перехода за ними; приложения без окна MUST быть запущены с их окружением, а приложение без `cmd` MUST остаться без окна с записью в журнал; сбой запуска одного приложения (исполняемый файл не найден, нет прав на запуск) MUST NOT обрывать поднятие: демон MUST записать в журнал предупреждение с именем приложения, командой, аргументами, рабочим каталогом и текстом ошибки ОС, место приложения MUST остаться пустым, а остальные приложения MUST быть подняты, и workspace MUST стать активным; если рабочего каталога приложения нет, запуск MUST выполняться в домашнем каталоге с предупреждением в журнале; окна других workspace на этом столе MUST быть перенесены на `special:pool`; окна MUST быть расставлены по своим местам, посторонние окна, привязанные к workspace, MUST вернуться на свои места; фокус MUST получить первый экземпляр приложения главной ячейки; workspace MUST стать активным на столе и попасть в его список, если его там не было. Workspace MUST числиться ровно на одном столе: из списков всех остальных столов он MUST быть убран, а стол, на котором он был активным, MUST остаться без активного workspace; исключение — команда переноса `workspaced move-desktop N`: преемника на прежнем столе задаёт требование «Перенос workspace на стол». Сбой запуска MUST NOT обрывать и перенос workspace командой `workspaced move-desktop N` вместе с поднятием преемника, и загрузку сессии (спецификация ws-sessions, «Загрузка сессии»). Ленивое поднятие, назначенное этому workspace на прежнем столе, MUST сниматься: первый переход на тот стол MUST NOT возвращать workspace туда. Окна на `special:hidden` демон MUST NOT переносить при поднятии. Приложение, входящее в два workspace, MUST иметь один набор окон, который следует за последним вызовом. Все переносы и расстановка уже открытых окон MUST выполняться как одна последовательность, чтобы окна не появлялись на промежуточных столах. Порядок окон workspace по глубине демон MUST задавать явно: он MUST прочитать нынешний порядок у композитора до переноса и восстановить его после, окно за окном снизу вверх. При поднятии workspace верхним MUST становиться окно, получающее фокус, — первый экземпляр приложения главной ячейки. При переносе workspace, активного на другом столе (`--desktop N`, запись `[[binds]]` со столом, команда `workspaced move-desktop N`), порядок окон по глубине MUST оставаться прежним, включая верхнее окно: смена стола MUST NOT менять того, что пользователь оставил на виду.

#### Scenario: Первое поднятие запускает приложения
- **WHEN** ни одно окно `dev-front` не открыто и нажата его цепочка на столе 1
- **THEN** запускаются все приложения `dev-front` с их окружением, их окна появляются на столе 1 в своих ячейках, фокус у окна главной ячейки, плитка «1» показывает их иконки

#### Scenario: Все окна приложения переезжают вместе
- **WHEN** у `chromium` в workspace `work` (ячейка `left`) два окна, `work` активен на столе 1 и вызвана его цепочка со столом 3
- **THEN** оба окна `chromium` оказываются на столе 3 в ячейке `left` одно поверх другого, на столе 1 их больше нет

#### Scenario: Цепочка ведёт к уже поднятому workspace
- **WHEN** `surf` активен на столе 2, пользователь на столе 1 нажал цепочку `surf`
- **THEN** активным становится стол 2, окна `surf` остаются на столе 2 в своих ячейках, фокус у окна главной ячейки, стол 1 не меняется

#### Scenario: Миграция на другой стол
- **WHEN** `dev-front` активен на столе 1 и вызван `[[binds]]` со столом 3
- **THEN** активным становится стол 3, окна `dev-front` оказываются на столе 3 в тех же ячейках, стол 1 их больше не показывает, в списке стола 1 `dev-front` больше нет и активного workspace там не остаётся

#### Scenario: Вытеснение другого workspace
- **WHEN** на столе 2 активен `chat`, и на столе 2 поднят `dev-back`
- **THEN** окна `chat` переносятся на `special:pool`, плитка «2» показывает окна `dev-back` и иконку `chat` как неактивного, стол `special:pool` не показывается

#### Scenario: Общее приложение
- **WHEN** `terminal-front` входит в `dev-front` (стол 1) и `docs-front` (стол 3), и `docs-front` поднят на столе 3
- **THEN** окна `terminal-front` переезжают на стол 3, на столе 1 их нет, а следующее поднятие `dev-front` возвращает их на стол 1

#### Scenario: Скрытое окно не трогается
- **WHEN** окно `editor-front` скрыто пользователем на `special:hidden` и поднят `dev-front`
- **THEN** окно остаётся на `special:hidden`, второй экземпляр не запускается, остальные окна расставлены

#### Scenario: Следующий workspace на столе
- **WHEN** в списке стола 1 workspace `dev-front`, `docs-front`, `chat`, активен `docs-front`, и нажата цепочка `next_workspace`
- **THEN** на столе 1 поднимается `chat`; повторное нажатие поднимает `dev-front`

#### Scenario: Перенос сохраняет порядок окон по глубине
- **WHEN** в `surf` (шаблон `overlay`) боковое окно Chrome поднято поверх главного окна Яндекс.Браузера, workspace перенесён на стол 3 и возвращён на стол 2
- **THEN** Chrome остаётся верхним окном, Chrome AI — под ним, как и до переноса, а фокус получает главное окно Яндекс.Браузера

#### Scenario: Поднятие возвращает главное окно наверх
- **WHEN** `surf` активен на столе 2, сверху оставлено окно Chrome, и на столе 2 нажата цепочка `surf`
- **THEN** главное окно Яндекс.Браузера становится верхним и получает фокус, а Chrome и Chrome AI сохраняют порядок между собой

#### Scenario: Сбой запуска не обрывает поднятие
- **WHEN** в `surf` входит дополнительное приложение сессии, записанная команда которого указывает на несуществующий файл, окна этого приложения нет, и нажата цепочка `surf`
- **THEN** окна Яндекс.Браузера и двух Chrome встают на свои места, `surf` активен на столе, в журнале предупреждение с именем приложения, командой, аргументами, каталогом и текстом «No such file or directory (os error 2)»

### Requirement: Отделение окна
По записи `[[binds]]` с `action = "detach"` или команде `workspaced detach`
демон MUST убрать активное окно текущего стола из активного workspace этого
стола. Текущим столом MUST считаться тот, на котором композитор находится
в момент команды: демон MUST спрашивать его у композитора, как это делают
перенос workspace и расстановка. Окно, вышедшее из workspace, ни в один другой
workspace не входит, поэтому демон MUST закрыть его штатным запросом закрытия
через диспетчер композитора — так приложение успевает спросить
о несохранённом. Если закрывается последнее окно дополнительного приложения
сессии, демон MUST снять и запись этого приложения, чтобы загрузка снимка
не запускала программу заново. Запись, которая описывает само приложение
(с командной строкой), MUST сниматься во всех workspace, где она есть, вместе
с назначением его места: с последним окном программа уходит из сессии. Запись, которая задаёт только место приложения конфига, MUST
сниматься лишь в активном workspace стола. Описание приложения в файле
конфига MUST оставаться на месте. Команда MUST завершаться без действия с записью в журнал, если
активного окна нет, если на столе нет активного workspace или если активное
окно в этот workspace не входит: свободное окно и окно чужого workspace
команда MUST NOT трогать.

#### Scenario: Окно приложения workspace
- **WHEN** на столе 1 активен `work`, активно второе окно Chromium, и нажато Super+Backspace
- **THEN** окно получает запрос закрытия и исчезает, первое окно Chromium остаётся в ячейке `left`, запись `chromium` в конфиге не меняется

#### Scenario: Последнее окно дополнительного приложения
- **WHEN** в `work` принят Alacritty с единственным окном, оно активно, и нажато Super+Backspace
- **THEN** окно закрывается, дополнительное приложение сессии `alacritty` снято, в составе `work` его больше нет, и следующая запись снимка его не содержит

#### Scenario: Запись приложения сессии в двух workspace
- **WHEN** дополнительное приложение сессии `wev` записано и в `work`, и в `surf`, его единственное окно активно на столе 2, где активен `surf`, и нажато Super+Backspace
- **THEN** окно закрывается, запись `wev` снята и в `surf`, и в `work`, в журнале строка с перечнем workspace, откуда она снята

#### Scenario: Свободное окно
- **WHEN** активно свободное окно диалога, оставшееся вне workspace, и нажато Super+Backspace
- **THEN** ничего не происходит, окно остаётся открытым, в журнале строка о том, что активное окно не входит в активный workspace стола

#### Scenario: На столе нет активного workspace
- **WHEN** на столе 4 активного workspace нет и нажато Super+Backspace
- **THEN** ничего не происходит, в журнале строка о том, что на столе нет активного workspace
