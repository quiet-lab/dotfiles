## Why

Происшествие 23.09.2026 (журнал `journalctl --user -u workspaced.service
--since '13:20'`). Пользователь открыл диспетчер задач Chromium (Shift+Esc),
затем диспетчер задач Яндекс.Браузера. Окна диспетчеров приходят
от композитора с пустым классом, поэтому `dialog_title` приложений, который
проверяется вместе с `class`, их не отловил, и демон принял оба окна
дополнительным приложением сессии с именем `app` (имя по пустому классу):
первое — в `work`, второе — в `surf`, так что одна запись оказалась в двух
workspace. Командой приложения `app` стала командная строка процесса
Chromium, и каждое поднятие `surf` пыталось её запустить, получало
«No such file or directory (os error 2)» и обрывалось целиком: workspace
стал недоступен. Super+Backspace на окне диспетчера закрыл окно, но запись
`app` не снял. Состояние вернул только перезапуск демона.

Кроме того, при восстановлении сессии демон каждый раз запускал
`./steamwebhelper` — окно Steam попало в снимок с относительной командой.

## What Changes

- **Окно без класса остаётся свободным всегда**: не захватывается
  ни при появлении, ни при поднятии workspace, ни командами сохранения,
  дополнительным приложением не становится; причина пишется в журнал.
- **Сбой запуска одного приложения не обрывает поднятие workspace**,
  перенос на другой стол и загрузку сессии: предупреждение в журнал
  с командой, аргументами, каталогом и ошибкой ОС, остальные приложения
  поднимаются, workspace становится активным. Несуществующий рабочий
  каталог заменяется домашним.
- **Командная строка процесса приводится к запускаемому виду.** Причина
  ENOENT — Chromium переписывает `/proc/<pid>/cmdline` одной строкой
  с пробелами, и вся строка становилась именем программы. Такая строка
  делится по пробелам, относительный путь берётся от рабочего каталога
  процесса, не найденный файл заменяется путём из `/proc/<pid>/exe`; если
  файла нет и там, окно в снимок не попадает, а в журнал идёт предупреждение.
- **Одно имя — одна программа.** Окно другой программы с тем же классом
  получает собственное имя, а не чужую запись; отделение последнего окна
  приложения сессии снимает его запись во всех workspace.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-daemon`: требования «Посторонние окна», «Захват открытых окон
  приложения», «Поднятие workspace на столе», «Отделение окна».
- `ws-sessions`: требования «Файлы сессий» и «Дополнительные приложения
  сессии».

## Impact

- Демон `workspaced` (`~/work/pets/workspaced`): `src/daemon.rs` —
  `classless`, `matcher_fits`, `Pending::matches`, `Daemon::on_open`,
  `join_window` (вместо признака `has_cmd` получает командную строку),
  `same_program`, `Free::NoClass`, `proc_info`, `launchable`, `launch_dir`,
  `start`, `Daemon::spawn`, `Daemon::spawn_foreign`, `Daemon::raise_on`,
  `Daemon::detach`, `drop_extra_app`; `src/save.rs` — `session_plan`,
  `save_workspace`; `src/session.rs` — `load`, `spawn_missing_foreign`,
  `adopt_live_foreign`, `same_window`.
- Документация: `AGENTS.md` (фраза о диалогах).
- Конфиг демона, привязки клавиш и панель не меняются.
