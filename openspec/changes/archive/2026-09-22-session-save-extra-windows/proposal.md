## Why

Сохранение состояния workspace и запись конфига сейчас делает одна команда
`save-workspace` (цепочка `SUPER+TAB SUPER+s`). Из-за этого случайное нажатие
правит файл под chezmoi: 22.09.2026 в `config.toml` попали сдвинутое положение
Chromium вместо ячейки `left` и лишнее приложение `google-chrome-ai` с командой
`/opt/google/chrome/chrome` из `/proc` процесса в контейнере, которой на хосте
нет. Откат правки расстановку не вернул: перечитывание конфига не пересобирает
назначения ячеек уже поднятого workspace, и состояние пришлось чинить правкой
снимка сессии при остановленном демоне.

При этом задача, ради которой команду нажимают чаще всего, — запомнить окно,
открытое по ходу работы, чтобы оно ездило вместе с workspace, — постоянной
записи в конфиг не требует. Сейчас такого способа нет вовсе: окно без тега
`app:` остаётся свободным (решение `free-foreign-windows`), а единственный
способ включить его в workspace — запись в конфиг.

Изменение разделяет два действия: сессия запоминает дополнительные окна
workspace, конфиг правится отдельной комбинацией клавиш. Это предвестник шага 3
серии из [`docs/window-model.md`](../../../docs/window-model.md): состав
workspace впервые живёт на уровне сессии, а не только в конфиге. Автоматическое
принятие окон изменение не вводит — окно входит в workspace только по явной
команде.

## What Changes

- **Команда `save-session`** (цепочка `CTRL+SUPER+s CTRL+SUPER+s`): посторонние
  окна текущего стола входят в активный workspace этого стола как
  дополнительные приложения сессии с текущим положением и размером. Файл
  конфига не меняется.
- **Дополнительное приложение сессии** хранится в снимке сессии при своём
  workspace: имя по классу окна, класс, командная строка и каталог из `/proc`,
  прямоугольник. Живое окно получает тег экземпляра, и дальше демон обращается
  с ним как с окном приложения: оно следует за workspace между столами,
  паркуется и возвращается с ним, встаёт на своё место при поднятии,
  показывается в плитке панели и восстанавливается при старте демона и при
  загрузке именованной сессии.
- **Окно, подходящее приложению конфига, новой записью не становится**: оно
  получает тег этого приложения, а в сессию попадает только место приложения
  в этом workspace, если его там ещё нет.
- **Запись в конфиг переезжает на свою цепочку** `CTRL+SUPER+s CTRL+SUPER+w`
  (`keys.save_workspace`, команда `save-workspace` — имя прежнее). Она пишет
  и приложения конфига, и дополнительные приложения сессии: те переходят из
  сессии в конфиг. Прежняя цепочка `SUPER+TAB SUPER+s` снимается.
- **Запись по команде сохранения сначала ищет подходящее приложение среди всех
  описанных в конфиге** по `class` и `title`: окно `google-chrome-ai`
  записывается как существующее `chrome-ai`, а не как новое приложение
  с командой из контейнера.
- **Перечитывание конфига пересобирает ячейки** тех workspace, чьё описание
  в файле изменилось, поэтому откат конфига возвращает расстановку без
  перезапуска демона.
- **Демон переходит на события, таймеров в нём не остаётся.** Снимок сессии
  пишет сам обработчик события или команды, изменивших состояние, — до ответа
  клиенту, а не отложенная запись через полсекунды. Выход запущенного процесса
  становится событием, предельные сроки ожидания окна (30 с и 2 с) снимаются:
  ожидание живёт до окна, а клавиша приложения после неудачного запуска
  запускает его заново. Перечитывание конфига идёт по событиям завершённой
  записи файла (закрытие файла на записи, появление файла после
  переименования), без задержки и подавления.
- **Не входит в это изменение** (следующие изменения серии): автоматическое
  принятие окна, появившегося по ходу работы; цикл по клавише и режим `stack`;
  общие окна нескольких workspace; переопределения на уровне workspace.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-sessions`: новое требование «Дополнительные приложения сессии» — команда
  `save-session` и обращение демона с такими приложениями; «Файлы сессий» —
  дополнительные приложения в снимке; «Восстановление при старте» и «Загрузка
  сессии» — их восстановление.
- `ws-config`: «Файл конфига и его разделы» — цепочка `save_session`
  в `[keys]`; «Цепочки клавиш и привязки» — действие `"save-session"`
  в `[[binds]]`; «Слежение за конфигом» — пересборка ячеек изменённого
  workspace; «Запись по команде сохранения» — поиск подходящего приложения
  конфига и запись дополнительных приложений сессии.
- `ws-daemon`: «Посторонние окна» — окно становится частью workspace и по
  команде сохранения сессии; «Идентификация окон» — событийное ожидание окна
  без предельного срока; «Состояние для панели» — команда `save-session`
  в перечне.
- `hyprland-binds`: «Раскладка клавиш сессии» — две цепочки `Ctrl+Super+S`
  вместо `Super+Tab Super+S`.

## Impact

- Проект `~/work/pets/workspaced`: `state.rs` (запись дополнительного
  приложения и её место в снимке), `daemon.rs` (эффективный конфиг из файла
  и дополнительных приложений, пересборка ячеек при перечитывании, команда
  в сокете), `save.rs` (команда сохранения сессии, поиск приложения по классу,
  запись дополнительных приложений в конфиг), `session.rs` (снимок и
  восстановление), `config.rs` (`keys.save_session`), `keys.rs` и `main.rs`
  (цепочка и подкоманда), модульные тесты.
- `dot_config/workspaced/config.toml`: две цепочки в `[keys]` вместо одной.
- `AGENTS.md` и `docs/window-model.md`: новое поведение и место изменения
  в серии.
- Снимки сессий прежнего формата читаются без ошибки: раздела дополнительных
  приложений в них просто нет.
