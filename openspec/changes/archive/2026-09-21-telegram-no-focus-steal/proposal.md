# Proposal: Входящее сообщение Telegram не забирает фокус

## Why

При входящем сообщении окно Telegram само поднимается наверх, получает
фокус клавиатуры и уводит композитор на свой стол, хотя пользователь
окна не трогал. Записи событий композитора за 21.09.2026 показывают это
трижды подряд (стол пользователя — 1, окно Telegram — на столе 2):

```
17:41:40 urgent>>55eedcbdc6b0
17:41:40 activewindow>>org.telegram.desktop,‎⁨Тата⁩ – (9)
17:41:40 workspace>>2
17:41:40 openlayer>>notifications
```

В ту же секунду Telegram отправляет уведомление dunst по D-Bus
(`member=Notify`, `string "Telegram Desktop"`, 17:41:40.059) и получает
от композитора токен xdg-activation
(`[CXDGActivationToken] assigned new xdg-activation token`). То есть фокус
забирает не dunst и не привязка сессии, а сам Telegram: при сообщении он
привлекает внимание к окну вызовом `QWindow::alert`, QtWayland превращает
этот вызов в запрос активации, а Hyprland с включённой настройкой
`misc.focus_on_activate` выполняет запрос целиком — поднимает окно, отдаёт
ему фокус и переходит на его стол.

Отличить такой запрос от запроса по клику по уведомлению композитор
не может: токен активации он проверяет только на существование, а кем
и при каком действии пользователя тот выдан, не смотрит. Поэтому
самопроизвольное поднятие окна убирается на стороне Telegram, а поведение
композитора остаётся прежним, и клик по уведомлению по-прежнему ведёт
к окну.

## What Changes

- Настройка Telegram Desktop «Draw attention to the window» («Уведомления
  и звуки») MUST быть выключена: без неё Telegram при сообщении не просит
  активацию, окно не поднимается, фокус и стол не меняются, уведомление
  dunst приходит как раньше.
- Настройка `misc.focus_on_activate` MUST оставаться общей и включённой,
  правило окна `focus_on_activate` для Telegram MUST NOT задаваться: иначе
  вместе с самопроизвольным поднятием окна пропал бы переход к окну по клику
  по уведомлению.
- Факт о выключенной настройке Telegram записывается в `docs/host-state.md`
  (она живёт в `~/.local/share/TelegramDesktop/tdata` и под chezmoi
  не берётся), причина общей настройки — в комментарии `hyprland.lua`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `hyprland-config`: новое требование «Привлечение внимания без действия
  пользователя» — окно не поднимается и не забирает фокус, пока
  пользователь ничего не сделал, при сохранённом переходе по клику
  по уведомлению и по ссылке из другой программы.

## Impact

- `dot_config/hypr/hyprland.lua`: комментарий у `misc.focus_on_activate`
  (значение не меняется, правил окон не добавляется).
- `docs/host-state.md`: настройка Telegram вне chezmoi.
- `AGENTS.md`: раздел «Сессия Hyprland», одна фраза о настройке Telegram.
- Спецификация `hyprland-config`.
- Поведение других программ не меняется: запрос активации по действию
  пользователя (клик по уведомлению, открытие ссылки) работает как раньше.
