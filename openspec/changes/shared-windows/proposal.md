## Why

Сейчас окно принадлежит workspace не само по себе, а через своё приложение:
тег `app:<имя>#<номер>` называет приложение, а в какие workspace окно входит,
демон выводит из того, какие workspace описывают это приложение в конфиге.
Отсюда три неудобства, перечисленные в
[`docs/window-model.md`](../../../docs/window-model.md), раздел 1.

- Приложение, описанное в двух workspace, имеет один набор окон, который
  следует за последним поднятием: окно уходит на стол того workspace, который
  подняли позже, и пропадает со стола, где пользователь с ним работал.
- Одно окно нельзя перенести в другой workspace, не перенеся туда всё
  приложение, и нельзя убрать из одного workspace, оставив в другом.
- Super+Backspace (команда `detach`, шаг 3) всегда закрывает окно: другого
  способа убрать окно из workspace нет, потому что окно не может входить
  в два workspace сразу.

Это шаг 4 серии изменений модели окон (`docs/window-model.md`, раздел 5):
состав «многие ко многим», захват открытых окон при поднятии, перетаскивание
окна общей клавишей, Super+Backspace и следование окна за столом. После шага
одно окно живёт в нескольких workspace, идёт за пользователем между столами
и убирается из workspace по Super+Backspace.

## What Changes

- **Состав workspace хранится у окна.** Окно, входящее в workspace, несёт тег
  `ws:<имя workspace>`, по тегу на каждый workspace. Тег ставится, когда окно
  входит в workspace (запуск для workspace, появление на столе с активным
  workspace, захват при поднятии, перетаскивание), и снимается, когда окно
  из него выходит. Теги живут в композиторе, поэтому состав переживает
  перезапуск демона так же, как номера экземпляров.
- **Общее окно следует за пользователем.** Окно, входящее в несколько
  workspace, стоит на том столе, где находится пользователь, если активный там
  workspace его содержит; иначе остаётся на столе, где активен другой его
  workspace; иначе уходит на `special:pool`. При переходе на стол демон
  по событию композитора переносит туда общие окна активного workspace и ставит
  их в состояние, запомненное для этого workspace: в режиме обмена ячеек —
  в ячейку, в режиме `stack` — в запомненный прямоугольник.
- **Поднятие забирает окна в общее пользование.** Если у приложения
  поднимаемого workspace нет ни одного окна в этом workspace, демон ищет его
  окна в других workspace и добавляет их в поднимаемый, не убирая из прежних:
  по семейству — все окна семейства, по варианту — окна варианта. Запуск —
  только когда подходящих окон нет нигде. Свободные окна приложения
  захватываются, как и раньше.
- **Клавиша приложения различает три случая** из таблицы
  `docs/window-model.md`, раздел 2.5. Приложение не входит ни в один
  запущенный workspace — оно открывается в активном workspace стола (раньше
  демон поднимал на текущем столе первый workspace конфига с этим приложением).
  Приложение есть в запущенном workspace — тот поднимается, как раньше.
  Перетаскивание окна в активный workspace (случай «в») вводится как операция:
  признак `--pull` у команды `workspaced app` и ключ `pull = true` у действия
  `{ app = … }` в `[[binds]]`. Переопределение клавиши в workspace, при котором
  случай «в» наступает от собственной клавиши приложения, — шаг 5.
- **Super+Backspace убирает окно из активного workspace стола.** Окно, которое
  входит ещё в другие workspace, остаётся открытым и уходит на свой стол
  по правилу общего окна; закрывается только окно, для которого этот workspace
  был последним. Запись дополнительного приложения сессии снимается, когда
  из workspace уходит последнее окно приложения.
- **Состояние для панели** показывает общее окно в составе каждого его
  workspace; в `workspaced status --json` у окна появляется список его
  workspace.
- **Запись workspace в конфиг** (`save_workspace`) берёт окна по составу
  workspace, в том числе общие, и место общего окна — то, которое окно
  занимает в этом workspace.

## Что не входит

- Переопределения клавиши, места и режима приложения внутри workspace
  (шаг 5). Без них случай «в» доступен только явной операцией перетаскивания;
  собственная клавиша приложения перетаскивает окно начиная с шага 5.
- Показ общего окна в плитках обоих столов (шаг 6). Панель не меняется
  и до шага 6 показывает общее окно в плитке того стола, где оно стоит.
- Состав workspace и запомненные прямоугольники в снимке сессии (шаг 7).
  Снимок по-прежнему хранит записи дополнительных приложений, и по ним общие
  окна после перезагрузки собираются заново поднятием workspace.
- Новые сочетания клавиш в конфиге сессии: отдельной клавиши перетаскивания
  не заводится, её роль с шага 5 берёт собственная клавиша приложения.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-daemon`: «Поднятие workspace на столе», «Цепочка приложения»,
  «Расстановка окон», «Идентификация окон», «Состояние для панели», «Захват
  открытых окон приложения», «Перенос workspace на стол», «Отделение окна»;
  новые требования «Состав workspace» и «Следование общего окна за столом».
- `ws-config`: «Цепочки клавиш и привязки» (ключ `pull` у действия
  приложения), «Запись по команде сохранения» (окна по составу workspace,
  место общего окна).
- `ws-sessions`: «Дополнительные приложения сессии» (запись о месте при
  перетаскивании, снятие записи по уходу последнего окна, место общего окна
  при сохранении).

## Impact

- Демон `~/work/pets/workspaced`: `hypr.rs` (разбор тега `ws:`), `daemon.rs`
  (состав, поднятие, следование, цепочка приложения, перетаскивание,
  отделение, перенос, состояние для панели, сверка тегов), `config.rs`
  и `keys.rs` (ключ `pull`), `main.rs` (признак `--pull`), `save.rs` (запись
  workspace и места дополнительных приложений), `session.rs` (сверка состава
  после восстановления и загрузки сессии).
- Конфиг `dot_config/workspaced/config.toml` не меняется.
- Документация: `AGENTS.md`, `docs/window-model.md` (разделы 2.5, 3 и 5).
- Панель Quickshell не меняется: состав workspace она берёт у демона,
  и общее окно в двух списках её расчёт не ломает.
