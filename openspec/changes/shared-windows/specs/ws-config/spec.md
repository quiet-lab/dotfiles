## MODIFIED Requirements

### Requirement: Цепочки клавиш и привязки
Цепочка MUST записываться строкой сочетаний через пробел, где сочетание — модификаторы и клавиша в синтаксисе Hyprland через `+` (`"SUPER+W 3 f"`); одиночное сочетание (`"SUPER+Return"`, `"XF86AudioMute"`, `"SUPER+mouse:272"`) — цепочка из одного звена. Короткая форма `chain` у workspace означает действие «поднять на текущем столе», у приложения — «вести цикл по его экземплярам в режиме его workspace» по правилам ws-daemon. Запись `[[binds]]` MUST принимать ровно одно действие: `action` — таблица с любым сочетанием ключей `desktop` (1…8), `workspace` и `app` и необязательным логическим ключом `pull` (перетащить окна приложения в активный workspace текущего стола, спецификация ws-daemon, «Цепочка приложения»; ключ допустим только вместе с `app` и без `workspace`, иначе запись MUST отклоняться с указанием цепочки; действие с `pull = true` MUST вызывать команду `workspaced app <имя> --pull`), таблица `{ half = "left" | "right" | "up" | "down" }`, таблица `{ place = "top-left" | "top-center" | "top-right" | "bottom-left" | "bottom-center" | "bottom-right" | "center" | "full" }`, таблица `{ move = <стол 1…8> }` (перенести активный workspace текущего стола на этот стол) либо строка `"sessions"`, `"save-session"`, `"save-workspace"`, `"next-workspace"`, `"maximize"`, `"arrange"`, `"detach"` (убрать активное окно из активного workspace текущего стола, спецификация ws-daemon, «Отделение окна»); `exec` — командная строка, запускаемая композитором; `dispatch` — выражение диспетчера Hyprland без префикса `hl.dsp.` (`"window.close()"`) либо массив таких выражений, выполняемых по порядку одним вызовом; `lua` — тело функции на Lua, выполняемое композитором при нажатии. Флаги `locked` (действует при заблокированном экране), `repeating` (повторяется при удержании), `mouse` (привязка к кнопке мыши с удержанием), `release` (срабатывает при отпускании) MUST передаваться композитору; `mouse` MUST быть допустим только у цепочки из одного звена. Поле `range = [от, до]` MUST разворачивать запись в серию: для каждого целого из диапазона подстрока `$n` в `chain`, `exec`, `dispatch` и в значении действия `move` заменяется числом. Значение `move` MUST читаться числом или строкой и MUST проверяться после разворачивания серии: до него на месте номера стоит `$n`. Стол вне диапазона 1…8 MUST приводить к отказу с указанием цепочки и полученного значения. Цепочки MUST быть произвольными; демон MUST NOT навязывать смысл сегментам. Одна цепочка MUST NOT совпадать с другой или быть её началом, в том числе одиночное сочетание с первым звеном цепочки; две цепочки с общим первым звеном и разными последующими MUST быть допустимы; два приложения с одной цепочкой внутри одного workspace MUST считаться ошибкой; одна цепочка у приложений из разных workspace MUST быть допустима. Сочетание из списка `reserved` раздела `[keys]` MUST NOT встречаться ни в одной цепочке. Демон MUST проверять эти условия при чтении и при ошибке называть обе конфликтующие записи либо запись и зарезервированное сочетание.

- **THEN** Super+C по очереди выбирает экземпляры `chromium` в главной ячейке, а за последним возвращает расстановку и фокус прежнему главному окну

#### Scenario: Одна цепочка у двух приложений в разных workspace

### Requirement: Запись по команде сохранения
По цепочке `save_workspace` или команде `workspaced save-workspace` демон MUST записать в раздел активного workspace текущего стола: назначение приложений по ячейкам (`apps`), `main` по текущей главной ячейке, `rect` у приложений, окна которых не совпадают со своей ячейкой, дополнительные приложения сессии этого workspace и свободные окна, открытые на текущем столе. Окна workspace MUST определяться по тегам состава (спецификация ws-daemon, «Состав workspace»), а не по описанию приложений: окно, убранное из workspace командой отделения, MUST NOT давать места своему приложению, а общее окно, входящее и в другие workspace, MUST записываться наравне с остальными — приложение под своим именем, с местом, которое окно занимает в этом workspace. Записи того же приложения в разделах других workspace команда MUST NOT менять: после записи приложение описано в нескольких разделах, и окно остаётся общим и после перезапуска демона. Для свободного окна и для дополнительного приложения сессии демон MUST сначала найти среди всех приложений конфига то, которому окно подходит по выражениям `class` и, если оно задано, `title`: поиск MUST идти сначала по приложениям-вариантам, затем по семействам, внутри каждой группы по именам, и найденное приложение MUST быть записано под своим именем с `rect`; новое приложение MUST заводиться только тогда, когда подходящего не нашлось, — с `cmd`, `args`, `cwd` из процесса окна (по правилу требования «Файлы сессий» спецификации ws-sessions, по которому окно из песочницы flatpak записывается командой `flatpak run`) и `rect`. Окно, которое в workspace не принимается (класс из `ignore_classes`, заголовок под `dialog_title` его приложения), демон MUST NOT записывать: в конфиге ему не место, как и в составе workspace. Дополнительные приложения сессии записанного workspace MUST после записи быть сняты: они перешли в конфиг. Если у приложения несколько окон, в `rect` MUST записываться место первого экземпляра, а остальные его окна MUST NOT попадать в файл отдельными записями. Записанное окно MUST получить тег экземпляра этого приложения и тег состава этого workspace и перестать быть свободным, а назначения ячеек workspace MUST быть пересобраны из записанного конфига без перезапуска демона. Свободные окна на других столах и окна на `special:hidden` MUST NOT записываться. Остальные разделы и workspace, комментарии и порядок ключей MUST сохраняться. Запись MUST быть атомарной; перед записью файл MUST быть перечитан, и если он изменился с момента последнего чтения, команда MUST быть отклонена с сообщением, а конфиг перечитан. После удачной записи команда MUST NOT перечитывать конфиг сама: перечитывание приходит событием завершённой записи файла, одно на одно сохранение. Без команды сохранения демон MUST NOT изменять файл.

#### Scenario: Сохранение после обмена ячеек
- **WHEN** в workspace `dev-front` терминал переведён в главную ячейку цепочкой приложения и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` `main = "terminal-front"`, назначения `apps` соответствуют экрану, комментарии в файле на месте, остальные workspace не изменились

#### Scenario: Сохранение приложения с двумя окнами
- **WHEN** в workspace `work` у `chromium` два окна: первый экземпляр сдвинут пользователем, второй стоит в ячейке `left`, и вызвана команда сохранения
- **THEN** у `chromium` записан `rect` первого экземпляра, второй записи о `chromium` в файле нет, и следующее поднятие `work` ставит оба окна в этот прямоугольник

#### Scenario: Сохранение постороннего окна
- **WHEN** на столе с активным `dev-front` из лаунчера открыт калькулятор, не описанный в конфиге, он принят дополнительным приложением сессии, перемещён пользователем, и вызвана команда сохранения workspace
- **THEN** в конфиге у `dev-front` появляется приложение с `cmd` калькулятора и `rect` его текущего положения, окно несёт тег этого приложения, а следующий `raise` `dev-front` ставит калькулятор на это место

#### Scenario: Дополнительные приложения сессии переходят в конфиг
- **WHEN** в `work` приняты калькулятор и окно `chrome-ai`, затем вызвана цепочка `save_workspace`
- **THEN** в конфиге у `work` записаны оба приложения, в `[apps]` появилось описание калькулятора, дополнительных приложений сессии у `work` больше нет, и следующая запись снимка сессии их не содержит

#### Scenario: Диалог в конфиг не попадает
- **WHEN** на столе с активным `surf` открыт диалог выбора файла класса `termfilechooser`, перечисленного в `ignore_classes`, и вызвана команда сохранения workspace
- **THEN** диалог в конфиг не записан, приложения по его классу в `[apps]` не появилось, окно осталось свободным

#### Scenario: Окно подходит приложению другого workspace
- **WHEN** на столе с активным `work` открыто свободное окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai` из workspace `surf`, и вызвана команда сохранения
- **THEN** в таблице `apps` у `work` появляется запись `chrome-ai` с `rect` окна, нового приложения по классу окна в `[apps]` не появляется, окно несёт тег `app:chrome-ai#1`

#### Scenario: Одно перечитывание на одну запись
- **WHEN** вызвана цепочка `save_workspace` и файл конфига записан
- **THEN** в журнале демона одна строка о перечитывании конфига, `hyprctl reload config-only` вызывается один раз

#### Scenario: Свободное окно на другом столе не записывается
- **WHEN** на столе 1 активен `dev-front`, на столе 3 без активного workspace открыт свободный терминал, и на столе 1 вызвана команда сохранения
- **THEN** терминал в конфиг не попадает и остаётся свободным

#### Scenario: Работа без сохранения
- **WHEN** пользователь два часа поднимает workspace, меняет ячейки и двигает окна, не вызывая команду сохранения
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст

#### Scenario: Общее окно записывается в раздел workspace
- **WHEN** окно `chrome-ai` из `surf` перетащено в `work`, сдвинуто пользователем, и на столе 1 вызвана цепочка `save_workspace`
- **THEN** в разделе `work` появляется запись `chrome-ai` с `rect` окна, запись `chrome-ai = "right"` в разделе `surf` не меняется, окно по-прежнему входит в оба workspace, а после перезагрузки поднятие второго из них забирает окно первого, а не запускает второй Chrome AI

#### Scenario: Отделённое окно не записывается
- **WHEN** у `chromium` в `work` два окна, первое убрано из `work` командой отделения и осталось в `dev-front`, второе стоит в ячейке `left`, и вызвана цепочка `save_workspace`
- **THEN** у `chromium` в разделе `work` остаётся ячейка `left`: место считается по второму окну, входящему в `work`
