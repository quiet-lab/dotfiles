## MODIFIED Requirements

### Requirement: Файл конфига и его разделы
Демон MUST читать конфиг из `~/.config/workspaced/config.toml` (файл под chezmoi). Файл MUST состоять из разделов: `[env]` — общие переменные окружения; `[keys]` — цепочки служебных действий `save_session`, `save_workspace`, `sessions`, `next_workspace` и список `reserved` зарезервированных сочетаний; `[templates.<имя>]` — шаблон геометрии с полем `main` (имя главной ячейки) и таблицей `cells`, где каждая ячейка — прямоугольник `{ x, y, w, h }`; `[apps.<имя>]` — приложение с полями `cmd` (команда запуска), `args` (массив), `cwd`, `env` (таблица), `chain`, `class` и `title` (регулярные выражения для захвата открытого окна по классу и заголовку; `title` без `class` не допускается), `family` (имя приложения-семейства, если это приложение — его вариант) и `rect` (прямоугольник `{ x, y, w, h }` — положение и размер окна по умолчанию, когда workspace об этом приложении ничего не говорит); `[startup]` — `workspace` (имя существующего workspace, который поднимается при старте демона) и `desktop` (стол 1…8, по умолчанию 1); `[workspaces.<имя>]` — workspace с полями `template` (обязательно), `main` (имя приложения в главной ячейке по умолчанию), `icon`, `chain`, `env` и таблицей `apps`, где значение — имя ячейки шаблона либо таблица `{ rect = { x, y, w, h } }` для окна вне ячеек; `[[binds]]` — записи с полем `chain`, ровно одним из полей действия `action`, `exec`, `dispatch`, `lua` и необязательными `range`, `locked`, `repeating`, `mouse`, `release`. У приложения MUST быть задано хотя бы одно из полей `cmd` и `class`: без `cmd` приложение не открывает новых окон и только собирает подходящие по `class`, без `class` окно узнаётся лишь по запуску. Поле `family` MUST называть другое приложение того же файла, у которого самого нет `family`: уровней ровно два — семейство и его варианты. Имя приложения MUST NOT содержать двоеточие и знак `#`: этими знаками демон отделяет части тега экземпляра. Прямоугольники ячеек, `rect` приложения и `rect` в таблице `apps` workspace — это положение и размер окна на экране как есть: демон MUST передавать их композитору без прибавления или вычитания отступов. Координаты прямоугольников MUST отсчитываться от левого верхнего угла экрана: целое число — пиксели, строка с процентом — доля ширины или высоты монитора; смешивать формы в одном прямоугольнике MUST быть можно. Координаты MUST допускать отрицательные значения, а размеры — значения больше экрана: окно может выходить за его края частично с любой стороны, демон MUST передавать такие значения композитору без обрезания и без сдвига внутрь экрана. Необязательный ключ `gap` в корне файла задаёт зазор в пикселях только для команд `half`, `place` и `maximize`, которые строят геометрию от рабочей области; по умолчанию 0. Неизвестные ключи MUST приводить к предупреждению в журнале, но не к отказу.

#### Scenario: Приложение без команды запуска
- **WHEN** у приложения `wezterm` задан только `class`, без `cmd`
- **THEN** `workspaced check` завершается успешно: приложение собирает окна, но само их не открывает; конфиг с приложением без `cmd` и без `class` отклоняется с указанием приложения

- **THEN** демон считает прямоугольник 330,0 размером 1920×2160

#### Scenario: Запись привязки с двумя действиями

### Requirement: Цепочки клавиш и привязки
Цепочка MUST записываться строкой сочетаний через пробел, где сочетание — модификаторы и клавиша в синтаксисе Hyprland через `+` (`"SUPER+W 3 f"`); одиночное сочетание (`"SUPER+Return"`, `"XF86AudioMute"`, `"SUPER+mouse:272"`) — цепочка из одного звена. Короткая форма `chain` у workspace означает действие «поднять на текущем столе», у приложения — «сделать главным» по правилам ws-daemon. Запись `[[binds]]` MUST принимать ровно одно действие: `action` — таблица с любым сочетанием ключей `desktop` (1…8), `workspace` и `app`, таблица `{ half = "left" | "right" | "up" | "down" }`, таблица `{ place = "top-left" | "top-center" | "top-right" | "bottom-left" | "bottom-center" | "bottom-right" | "center" | "full" }` либо строка `"sessions"`, `"save-session"`, `"save-workspace"`, `"next-workspace"`, `"maximize"`; `exec` — командная строка, запускаемая композитором; `dispatch` — выражение диспетчера Hyprland без префикса `hl.dsp.` (`"window.close()"`) либо массив таких выражений, выполняемых по порядку одним вызовом; `lua` — тело функции на Lua, выполняемое композитором при нажатии. Флаги `locked` (действует при заблокированном экране), `repeating` (повторяется при удержании), `mouse` (привязка к кнопке мыши с удержанием), `release` (срабатывает при отпускании) MUST передаваться композитору; `mouse` MUST быть допустим только у цепочки из одного звена. Поле `range = [от, до]` MUST разворачивать запись в серию: для каждого целого из диапазона подстрока `$n` в `chain`, `exec` и `dispatch` заменяется числом. Цепочки MUST быть произвольными; демон MUST NOT навязывать смысл сегментам. Одна цепочка MUST NOT совпадать с другой или быть её началом, в том числе одиночное сочетание с первым звеном цепочки; две цепочки с общим первым звеном и разными последующими MUST быть допустимы; два приложения с одной цепочкой внутри одного workspace MUST считаться ошибкой; одна цепочка у приложений из разных workspace MUST быть допустима. Сочетание из списка `reserved` раздела `[keys]` MUST NOT встречаться ни в одной цепочке. Демон MUST проверять эти условия при чтении и при ошибке называть обе конфликтующие записи либо запись и зарезервированное сочетание.

### Requirement: Слежение за конфигом
Демон MUST замечать изменение файла конфига без перезапуска, перечитывать его и, если файл корректен, применять: новые и изменённые workspace и приложения доступны следующей цепочкой, а привязки обновляются вызовом `hyprctl reload`. Перечитывание MUST запускаться по событиям файловой системы, означающим завершённую запись файла: закрытие файла, открытого на запись, и появление файла под своим именем после записи во временный файл с переименованием. События, приходящие посреди записи, демон MUST NOT учитывать, а задержку вместо них применять MUST NOT: одно сохранение файла MUST давать ровно одно перечитывание. При перечитывании демон MUST сравнить раздел каждого workspace в прежнем и новом файле и снять текущие назначения ячеек у тех workspace, чей раздел изменился или исчез: их назначения MUST быть собраны заново из нового файла при следующем обращении, и правка файла MUST возвращать расстановку без перезапуска демона. Назначения workspace, раздел которых не менялся, MUST сохраняться, чтобы правка одного workspace не сбрасывала обмен ячеек в другом. При ошибке демон MUST оставить прежний конфиг и записать ошибку в журнал.

#### Scenario: Новый workspace добавлен вручную
- **WHEN** пользователь дописал в конфиг workspace `notes` с `chain = "SUPER+W n"` и сохранил файл
- **THEN** демон перечитывает конфиг по событию завершения записи, в журнале одна строка о перечитывании, `workspaced status --json` содержит `notes`, а Super+W, n поднимает его

#### Scenario: Запись во временный файл с переименованием
- **WHEN** конфиг применён командой `chezmoi apply`, которая пишет временный файл и переименовывает его на место конфига
- **THEN** демон перечитывает конфиг один раз, неполный файл не читается, `hyprctl reload` вызывается один раз

#### Scenario: Откат правки возвращает расстановку
- **WHEN** в разделе `work` ячейка `chromium` заменена прямоугольником, `work` поднят, затем правка отменена и файл сохранён
- **THEN** назначения `work` снова берутся из файла, и следующее поднятие `work` ставит Chromium в ячейку `left`; назначения соседнего workspace `surf` не сбрасываются

### Requirement: Запись по команде сохранения
По цепочке `save_workspace` или команде `workspaced save-workspace` демон MUST записать в раздел активного workspace текущего стола: назначение приложений по ячейкам (`apps`), `main` по текущей главной ячейке, `rect` у приложений, окна которых не совпадают со своей ячейкой, дополнительные приложения сессии этого workspace и посторонние окна, открытые на текущем столе. Для постороннего окна и для дополнительного приложения сессии демон MUST сначала найти среди всех приложений конфига то, которому окно подходит по выражениям `class` и, если оно задано, `title`: поиск MUST идти сначала по приложениям-вариантам, затем по семействам, внутри каждой группы по именам, и найденное приложение MUST быть записано под своим именем с `rect`; новое приложение MUST заводиться только тогда, когда подходящего не нашлось, — с `cmd`, `args`, `cwd` из процесса окна и `rect`. Дополнительные приложения сессии записанного workspace MUST после записи быть сняты: они перешли в конфиг. Если у приложения несколько окон, в `rect` MUST записываться место первого экземпляра, а остальные его окна MUST NOT попадать в файл отдельными записями. Записанное окно MUST получить тег экземпляра этого приложения и перестать быть посторонним, а назначения ячеек workspace MUST быть пересобраны из записанного конфига без перезапуска демона. Свободные окна на других столах и окна на `special:hidden` MUST NOT записываться. Остальные разделы и workspace, комментарии и порядок ключей MUST сохраняться. Запись MUST быть атомарной; перед записью файл MUST быть перечитан, и если он изменился с момента последнего чтения, команда MUST быть отклонена с сообщением, а конфиг перечитан. Без команды сохранения демон MUST NOT изменять файл.

#### Scenario: Сохранение после обмена ячеек
- **WHEN** в workspace `dev-front` терминал переведён в главную ячейку цепочкой приложения и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` `main = "terminal-front"`, назначения `apps` соответствуют экрану, комментарии в файле на месте, остальные workspace не изменились

#### Scenario: Сохранение приложения с двумя окнами
- **WHEN** в workspace `work` у `chromium` два окна: первый экземпляр сдвинут пользователем, второй стоит в ячейке `left`, и вызвана команда сохранения
- **THEN** у `chromium` записан `rect` первого экземпляра, второй записи о `chromium` в файле нет, и следующее поднятие `work` ставит оба окна в этот прямоугольник

#### Scenario: Сохранение постороннего окна
- **WHEN** на столе с активным `dev-front` из лаунчера открыт калькулятор, не описанный в конфиге, перемещён пользователем и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` появляется приложение с `cmd` калькулятора и `rect` его текущего положения, окно несёт тег этого приложения, а следующий `raise` `dev-front` ставит калькулятор на это место

#### Scenario: Окно подходит приложению другого workspace
- **WHEN** на столе с активным `work` открыто постороннее окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai` из workspace `surf`, и вызвана команда сохранения
- **THEN** в таблице `apps` у `work` появляется запись `chrome-ai` с `rect` окна, нового приложения по классу окна в `[apps]` не появляется, окно несёт тег `app:chrome-ai#1`

#### Scenario: Дополнительные приложения сессии переходят в конфиг
- **WHEN** в `work` приняты по цепочке `save_session` посторонний калькулятор и окно `chrome-ai`, затем вызвана цепочка `save_workspace`
- **THEN** в конфиге у `work` записаны оба приложения, в `[apps]` появилось описание калькулятора, дополнительных приложений сессии у `work` больше нет, и следующая запись снимка сессии их не содержит

#### Scenario: Свободное окно на другом столе не записывается
- **WHEN** на столе 1 активен `dev-front`, на столе 3 открыт свободный терминал, и на столе 1 вызвана команда сохранения
- **THEN** терминал в конфиг не попадает и остаётся свободным
