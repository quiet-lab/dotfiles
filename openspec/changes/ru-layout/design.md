# Design: Neovim в русской раскладке

## Context

Требования пользователя — в `proposal.md`. Критерий: наибольшее покрытие
при наименьшем числе переключений раскладки, ручных и системных; объём кода
значения не имеет. Опыты, сравнение вариантов и таблица остатков — проект
«Neovim в русской раскладке» (задача nvim-layout, каталог результатов).
Устройство и правила для пользователя — `docs/ru-layout.md`.

## Decisions

### D1. Свой модуль привязок вместо langmapper

`langmap` не находит привязки с латинской левой частью. Плагин langmapper
подменяет API привязок, но переводит буквенные привязки в `i` и `c` и искажает
русский текст, добавляет к описаниям пометки и не берёт таблицу из карты XKB.
Выбран свой `keymap.lua`: подмена `nvim_set_keymap`, `nvim_buf_set_keymap`
и функций удаления, дубль с теми же правой частью и опциями; в `n`, `x`, `o`
всегда, в `i`, `c`, `t`, `s` только при модификаторе; проход по `FileType`
для Vim-script плагинов. Таблица создаётся `gen-table.lua` из `xkb_custom`.

### D2. Система не переключается

Автопереключение системной раскладки в `:` и терминале отвергнуто: оно
затрагивает панель Claude Code и браузер в той же сессии и не работает без
Hyprland. Перевод идёт внутри Neovim по физическим клавишам.

### D3. Правило перевода строки `:`

Строка переводится по `<CR>` (и перед `<Tab>`): диапазон, командное слово,
флаги `:s` и имена опций — по клавишам; текстовые аргументы (`:s/…/…/`, `:let`,
`:echo`, пути) остаются как набраны. Строка из одних русских букв переводится
целиком. Расхождение с английской раскладкой — только у русского слова,
набранного по ошибке: оно выполняется как команда тех же клавиш.

### D4. Знаки по раскладке

Клавиши, печатающие в RU `. , " ; : ? /`, в n/x/o выполняют действия клавиш
`/ ? @ $ ^ & |`; прежние действия остаются на парах `ю б Э ж Ж`. Раскладка —
из события Hyprland; без Hyprland знаки не переводятся.

### D5. Метки flash кириллицей

Набор меток переводится по раскладке в момент вызова; поиск идёт по обеим
раскладкам. Обёртка ставится на `flash.commands.*` и внутренности flash
(`Char.mode`, `Labeler.skip`, `Pattern.extend`); при их изменении обёртка не
ставится и выводится предупреждение.

### D6. Обёртки плагинов вместо глобальной подмены `getchar`

Перевод `getchar` включается только на время вызова функции плагина:
глобальная подмена ломает русский поиск flash. Сторожевой тест находит новых
потребителей `getchar`; плагин, сохранивший функцию в локальную переменную
при загрузке, не перехватывается.

### D7. Защита тестами с откатом по lazy-lock

После каждого `:Lazy update` гоняется `tests/run-all.sh`; при падении
плагин откатывается по `lazy-lock.json` (`:Lazy restore <плагин>`), код
плагинов в `~/.local/share/nvim/lazy` не правится.

### D8. Обёртки `r`, `@`, ответов диалогов

`r` — по правилу: кириллица над латиницей даёт парную латинскую клавишу,
иначе буква как набрана. `@` читает имя регистра по физической клавише и
выполняет встроенный `@` с включённой на время выполнения `'langremap'`, поэтому
макрос из RU воспроизводится и в `:normal @a`. Ответы `confirm()` и `:s///c`
переводит `vim.on_key` в режиме ожидания одной буквы.

### D9. Терминал

Привязки режима `t` по паре ставятся буферно для программ из списка
(по умолчанию `lazygit`), по имени буфера и по заголовку терминала (OSC);
shell не затрагивается по решению пользователя.

## Остатки

Латинский текст в insert и shell вне списка — выбор языка за пользователем.
Остальное — в таблицах `docs/ru-layout.md`: `:normal!`, `-- More --`,
цепочки `|`, знаки в `:`, метки flash при макросе в другой раскладке,
плагин с кэшированным `getchar`.
