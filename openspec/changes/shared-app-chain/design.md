# Design: Общая клавиша нескольких приложений workspace

## Context

Мотивация — в `proposal.md`. До изменения (коммит демона `3cc271d`):

- `keys::collect` отклонял две записи одного workspace с одинаковым
  ключом (решение D8 изменения workspace-overrides).
- `Config::responds` возвращал первую запись, откликнувшуюся на цепочку,
  а `Daemon::cycle` вёл цикл по окнам одного приложения
  (`placed_windows`).
- Конец цикла без prev выбирал следующее приложение раздела после
  вызванного (`next_app_window`).
- Привязка одна на цепочку уже была: все отклики собираются в одну
  привязку `workspaced key '<цепочка>'`, источники перечисляются через
  запятую. Цепочка с выходом наследует буквы по привязкам, поэтому
  наследование от изменения не зависит.

## Решения

### D1. Группа общей клавиши и порядок цикла

Группа — все записи workspace, ключ которых (`app_key`: `chain` записи,
а без него собственная клавиша) совпадает с нажатой цепочкой,
по порядку раздела (`Config::responders`). Группа действует только тогда,
когда путь клавиши ведёт к циклу в workspace (`Cycle`, `Raise`), а этот
workspace откликается на цепочку записью приложения пути (`key_group`).
Собственная клавиша приложения, отличная от общей цепочки
(Shift+Super+V у `chrome-ai`), ведёт цикл только по окнам этого
приложения; перетаскивание и открытие в другом workspace действуют
на одно приложение, как раньше. Команда `workspaced app <имя>` тоже
работает с одним приложением: цепочки у неё нет.

Ряд цикла — окна приложений группы подряд по порядку записей, внутри
приложения по порядку экземпляров (`group_windows`, повторы
исключаются). Шаг вычисляет прежняя `cycle_step` по этому ряду; prev
запоминается для группы целиком (`Cycle.app` — имена через запятую),
окна группы prev не бывают. Следующее приложение при конце цикла без prev
ищется после последней записи группы, записи группы пропускаются.

### D2. Приложение группы без окон

Рассмотренные варианты:

1. Цикл идёт по имеющимся окнам; запускается первое приложение группы,
   только если окон нет ни у одного. **Выбран.**
2. Каждое нажатие, дошедшее до приложения без окон, запускает его.
   Отвергнут: при закрытом профиле «AI2» каждый проход цикла открывал бы
   новый Chrome — именно этого конец цикла избегает и для следующего
   приложения workspace.
3. Запускать все приложения группы без окон при первом нажатии.
   Отвергнут по той же причине и потому, что поднятие workspace уже
   запускает каждое приложение без окон.

Открыть недостающее приложение можно поднятием workspace, его
собственной клавишей, командой `workspaced app <имя>` или новым
экземпляром (D4).

### D3. Режим цикла

Цикл идёт в одном режиме, поэтому проверка конфига требует, чтобы
режим клавиши (`Config::app_mode`) у записей с общей цепочкой совпадал,
и отклоняет конфиг с разными режимами, называя workspace, оба
приложения и цепочку. Это проще объяснить, чем правило «режим первой
записи», и исключает непредсказуемый обмен мест у части окон ряда.

В режиме `swap` главное место, занятое любым приложением группы,
считается занятым группой: нажатие продолжает цикл, а не начинает его
заново (`swap_start` получает признак «главное приложение — из группы»),
выбор окна другого приложения группы ставит его приложение на главное
место (`select_window` берёт приложение выбранного окна), а prev —
окно прежнего главного приложения, если оно не из группы. Запуск без
окон в режиме `swap` ставит на главное место первую запись группы.

### D4. Новый экземпляр по общей цепочке

`workspaced key --new` (состояние «Новое окно» цепочки `[sticky.apps]`)
запускает новый экземпляр приложения активного окна, если оно входит
в группу, иначе первого приложения группы. Так из окна `chrome-ai2`
открывается ещё одно окно `chrome-ai2`, а не `chrome-ai`.

### D5. Строка подсказки

Источники-записи одного workspace сводятся в одну часть описания:
«chrome-ai, chrome-ai2 в workspace surf» (`keys_help::app_key_desc`).
Привязка и строка в `keys --list` остаются одной, как и раньше.

### D6. Проверка «одинаковым столом»

В задании упоминалась проверка, что общая цепочка допустима только
у записей с одинаковым столом. Записи раздела `apps` workspace стола
не имеют: стол есть у workspace в списке столов и у действия записи
`[[binds]]`. Поэтому ограничение сводится к «записи одного workspace»;
одна цепочка у записей разных workspace допустима, как и раньше.

## Порядок архивации

Дельты этого изменения построены на последних текстах требований
из незаархивированных изменений: «Цепочка приложения» — из
`work-area-center` (оно основано на `live-layout`), «Цепочки клавиш
и привязки» и «Перечень клавиш для подсказки» — из `chains-sticky`
(оно основано на `sticky-chains`). Архивировать `shared-app-chain`
нужно после `live-layout`, `work-area-center`, `sticky-chains`
и `chains-sticky`, иначе их полные тексты требований затрут это
изменение.

Дельта «Цепочка приложения» перенесена в изменение `home-mode-layout`
вместе с правилами `live-layout` и `work-area-center` и вошла в основную
спецификацию с его архивацией; у этого изменения остались дельты ws-config.

## Проверка вживую

Записи `chrome-ai2` в действующем конфиге нет: профиль «AI2» ещё не
переехал в собственный каталог данных, а запись без каталога создала бы
пустой профиль Chrome. Поэтому общий цикл на живой сессии не проверялся:
поведение покрыто модульными тестами, а проверка конфига, привязка
и строка подсказки — копией конфига во временном `XDG_CONFIG_HOME`.
