## Context

Основной профиль (`docs/amnezia-split-tunnel.md`, запись
`docs/decisions/0009-amneziawg-split-by-destination.md`): трафик
отбирает таблица nftables `inet amn`, внешний трафик идёт в `amn0`,
соединение NetworkManager `axata` (OpenVPN, `tun0`) имеет
`ipv4.never-default yes` и маршрут 10.0.0.0/8 через 10.200.5.254.
При загрузке `awg-quick@amn0.service` и `axata-vpn.service` поднимают
туннели, `tunnels-before-login.service` ждёт их перед `greetd`
(спецификация hyprland-autostart). Панель показывает значки туннелей
по событиям (спецификация qs-tray-lang; запись `docs/decisions/0007-no-timers.md`
запрещает таймеры и опрос).

Живое состояние на 21.11.2026 (запасной режим, поднятый вручную):
`amn0` остановлен; `openvpn --config axata.ovpn` без `never-default`
принял `redirect-gateway`: в `main` стоят `0.0.0.0/1` и `128.0.0.0/1`
через `10.200.5.254 dev tun0`, выход наружу — Белоруссия. DNS: канал
`tun0` — серверы 10.200.115.1 и 10.200.115.2, `Default Route: yes`;
канал `enp43s0` держит зоны `~ru ~by ~su ~xn--p1ai` (серверы
192.168.1.1). Профиль NetworkManager `axata` (проверено `nmcli`):
`ipv4.never-default yes`, `ipv4.routes 10.0.0.0/8 10.200.5.254`,
`ipv4.ignore-auto-dns no`, `connection.autoconnect no`,
`connection.secondaries` пуст.

Расхождения документов с кодом, найденные при чтении (код верен):

- `design.md` архивного изменения `tunnel-tray-autostart` называет
  маршрут `axata` 10.200.0.0/16 и глиф 󰖟 для `amn0`; в коде и
  спецификации — 10.0.0.0/8 и силуэт Amnezia.
- `system/sudo/README.md` описывает правило `amn-switch` как разрешающее
  только `amn-switch` и `systemctl`; в файле правила также `awg show`,
  `amn-zones-update --count|--force` и `amn-apply-config` (README
  правится задачей 7.3).

## Goals / Non-Goals

**Goals:**

- Второй профиль сети «всё через axata» с переходом туда и обратно
  из меню панели и из терминала без пароля.
- Профиль переживает перезагрузку.
- Переход проверяет результат и откатывается при отказе; посторонние
  процессы не завершаются.
- Состояние профиля в панели — по событиям, без таймеров.

**Non-Goals:**

- Автоматический переход (по потере связи `amn0` и т. п.): только
  вручную, решение пользователя 21.11.2026.
- Изменение устройства основного профиля, списков стран, выбора страны.
- Раздельная маршрутизация в запасном профиле: весь трафик, включая
  адреса России и Белоруссии, идёт через `axata`.
- Управление профилем в самом NetworkManager (`connection.secondaries`,
  автоподключение): остаётся как есть по `tunnel-tray-autostart`.

## Decisions

### D1. Профиль NetworkManager `axata-full` вместо переключения `never-default`

`axata-full` — копия `axata` (`nmcli connection clone`), отличается
именем, `uuid`, `ipv4.never-default no` (и наследует маршрут
10.0.0.0/8, безвредный рядом с полным туннелем). `connection.autoconnect no`,
`connection.secondaries` пуст — как у `axata`.

Отвергнуто: менять `never-default` у одного профиля `axata`. Профиль
виден только по свойству, а не по имени активного соединения;
состояние хранится в NetworkManager и расходится с файлом профиля;
сбой на полпути оставляет профиль с половиной настроек, а
`amn-switch` и `install.sh revert` уже меняют это свойство для
других целей (два владельца свойства). С двумя профилями каждый
из них неизменен, а выбор записан в одном месте (D3).

Цена: две копии учётных данных и `vpn.data`. Расхождение после правки
`axata` в `nm-connection-editor` — `install.sh status` его показывает,
`install.sh profile` пересоздаёт `axata-full` из `axata` (отказ, пока
`axata-full` активен).

### D2. Сценарий `/usr/local/sbin/net-profile`

Лежит в `system/tunnels/` (он управляет обоими туннелями и
юнитами загрузки; `system/amnezia/` — только `amn0`), ставится
`install.sh files` в `/usr/local/sbin` (root, 0755), как `amn-switch`.
Вызовы: `net-profile backup`, `net-profile main`; другие аргументы —
отказ. Самодостаточен: на время перехода связи с внешним миром нет,
запускает его пользователь из панели. Журнал — `/var/log/net-profile.log`,
итог построчно, как у `amn-switch`. Второй одновременный вызов
отказывает сразу: замок `flock -n /run/net-profile.lock` стоит на
единственный ресурс (сетевое состояние станции размножить нельзя),
ожидания нет, замок снимается завершением процесса.

Порядок `backup` (прежний профиль — основной):

1. Проверки до изменений: root; профиль `axata-full` существует;
   устройство `tun0` либо отсутствует, либо принадлежит активному
   соединению `axata`/`axata-full` (иначе отказ — D4); запоминается состояние для
   отката: содержимое файла профиля, активность `awg-quick@amn0`, активное соединение.
2. Запись `backup` в `/etc/amnezia/profile` (атомарно: временный файл
   и `mv`); прежнее содержимое запоминается.
3. `systemctl stop awg-quick@amn0` (`PostDown` — `amn-route down`
   снимает правило метки, таблицу 100 и таблицу `inet amn`).
4. Отключение `axata`, подъём `axata-full` (`nmcli --wait 60`).
5. Проверка выхода (требование «Проверка запасного профиля»).
6. При отказе любого шага — откат (D5).

Порядок `main` (прежний — запасной):

1. Проверки до изменений: root; `tun0` — как выше; конфиг
   `/etc/amnezia/amneziawg/amn0.conf` существует.
2. Запись `main` в файл профиля — до запуска `awg-quick@amn0`, иначе
   условие загрузки (D3) пропустит запуск.
3. Отключение `axata-full`, подъём `axata` (с `never-default`).
4. `systemctl start awg-quick@amn0`.
5. Проверка выхода: те же проверки, что шаг 5 `amn-switch`
   (запрос к `api.anthropic.com` идёт через `amn0`, счётчик приёма
   `amn0` растёт, адрес не в `zones` и `bypass`, маршрут с меткой 0x1
   — `amn0`), прямой выход к `ya.ru` при поднятом туннеле, 10.0.0.0/8
   через `tun0`, маршрута по умолчанию через `tun0` нет.
6. При отказе — откат (D5).

Проверки дублируют `amn-switch`; вынос общих функций в отдельный файл
не делается: `amn-switch` — одноразовый сценарий миграции, его
поведение по приоритету 1 остаётся прежним. Повторный вызов
в том же профиле при пройденной проверке ничего не переподключает.

### D3. Профиль между перезагрузками

Файл `/etc/amnezia/profile` (root, 0644), содержимое `main` или
`backup`; запасным профиль считается только при точном `backup`
(`grep -qx`), отсутствие файла и любое другое содержимое — основной.
Каталог `/etc/amnezia/` уже отслеживает `inotifywait` панели
(`country.json`), поэтому новый источник событий не нужен; файл читают
все (панель — от пользователя).

- `awg-quick@amn0.service.d/10-profile.conf`:
  `ExecCondition=/bin/sh -c '! grep -qx backup /etc/amnezia/profile'`.
  При запасном профиле юнит пропускается (состояние `inactive`,
  `Result=exec-condition`, а не `failed`), очередь загрузки не
  задерживается, `tunnels-before-login.service` по порядку `After=`
  не ждёт. Включение в автозапуск (`systemctl enable`) не меняется:
  `amn-switch` и откат продолжают работать как раньше, источник правды
  один — файл. Побочное следствие: ручной `systemctl start
  awg-quick@amn0` при запасном профиле ничего не делает; пункт меню
  «Запустить» панель при запасном профиле не показывает (D6).
- `axata-vpn.service`: `ExecCondition` пропускает запуск, если активно
  любое из двух соединений (`axata` или `axata-full`), `ExecStart`
  выбирает имя по файлу (`axata-full` при `backup`, иначе `axata`).

Отвергнуто: хранить профиль включением юнитов (`enable`/`disable`
`awg-quick@amn0` и второго юнита `axata-full-vpn.service`). Два
источника правды, которые расходятся при сбое на полпути, и панели
пришлось бы читать состояние юнитов вместо файла, который
уже отслеживает `inotifywait`.

### D4. Посторонний процесс на `tun0`

Нынешний ручной режим (`sudo openvpn --config ./axata.ovpn`) держит
`tun0`; подъём соединения NetworkManager рядом занял бы `tun1`, а
маршруты двух клиентов столкнулись бы. Сценарий не завершает чужие
процессы (запрет `pkill` и завершения по образцу): если `tun0`
существует, а ни `axata`, ни `axata-full` не активны, он отказывается
до любых изменений, печатает PID процессов `openvpn` (только для
сведения) и просит завершить процесс самому. Код выхода 3, отличный
от кода неудачной проверки (1).

### D5. Откат

Откат возвращает состояние, зафиксированное до вызова, а не «прямой
выход», как `amn-switch`: пользователь переходил между двумя рабочими
режимами по собственному решению.

- `backup` не прошёл: файл профиля — прежнее содержимое, `axata-full`
  отключён, `axata` поднят, `awg-quick@amn0` запущен, если был активен.
- `main` не прошёл (сервер Amnezia не отвечает — главный повод держать
  запасной профиль): станция остаётся в запасном профиле, то есть
  выполняются шаги `backup` без проверок прямого выхода: файл —
  `backup`, `awg-quick@amn0` остановлен, `axata-full` поднят. Итог
  сообщает о причине и о том, что профиль остался запасным.
- Если откат сам не прошёл — итог называет это строкой «ОШИБКА»,
  код выхода 1, состояние (`ip route`, `nmcli`) печатается в журнал.

### D6. Панель

Профиль читается `scripts/tunnelstate` из файла и добавляется полем
`profile` (`main`/`backup`) в состояние обоих туннелей. Для `axata`
имя соединения берётся по активному из двух (`nmcli -t -f NAME,STATE
connection show --active`, имена `axata`, `axata-full`), а если активного
нет — по файлу; поле `connection` содержит имя. Профиль, как и
`state`, перечитывается по событиям: `nmcli monitor` и журнал
`axata-vpn.service` (уже есть), `inotifywait` на `/etc/amnezia/`
(регулярное выражение дополняется `profile$`; строка запускает чтение
состояния обоих туннелей). Таймеров и новых потоков нет.

Пункты меню: «Запасной профиль: всё через axata» в меню значков `amn0`
и `axata` при основном профиле, «Основной профиль» — при запасном.
Действие — `sudo -n /usr/local/sbin/net-profile backup|main` процессом
панели; пока оно выполняется, оба значка заняты (`amnBusy`,
`axataBusy`), второго действия нет; при ненулевом коде последняя
строка вывода ошибок становится ошибкой обоих значков (до следующего
успешного действия).

Значок `amn0` при запасном профиле серый, не красный: служба
остановлена намеренно (ошибка здесь не состояние службы, а ошибка
действия или `failed`); подсказка — «выключен: запасной профиль».
Меню `amn0` при запасном профиле содержит только «Основной профиль»:
«Запустить», «Остановить», «Страна туннеля…», «Обновить списки стран»
скрыты, так как таблица `inet amn` при запасном профиле не должна
существовать (метка 0x1 без маршрута таблицы 100 сбивала бы
маршрутизацию). Меню `axata` — «Отключить»/«Подключить» (для
соединения активного профиля), «Настройки» (редактор открывает
соединение активного профиля, `uuid` из `tunnelstate`), и пункт смены
профиля. Окно сведений `axata` получает строки «Профиль», «Соединение»,
«Маршрут по умолчанию» и «DNS»; окно `amn0` — строку «Профиль».

Проверка без мыши: `tunnels state` (поле `profile`), `tunnels run axata
'Запасной профиль: всё через axata'`, `tunnels run amn0 'Основной
профиль'`, `tunnels info axata`, как у остальных действий (команды —
`docs/amnezia-split-tunnel.md`, раздел «Значки в трее»).

### D7. DNS запасного профиля

Именами занимается systemd-resolved и NetworkManager, а не сценарий
перехода: у соединения без `never-default` NetworkManager передаёт
resolved серверы, присланные OpenVPN, и маршрут по умолчанию
(`Default Route: yes`) канала `tun0`; зоны `~ru ~by ~su ~xn--p1ai`
остаются на `enp43s0` (профиль «Проводное подключение 2»,
`ipv4.dns-search`), поскольку маршрутный домен точнее. Сценарий проверяет
результат (`resolvectl status tun0`) и при его отсутствии считает
проверку не пройденной; руками `resolvectl` он не вызывает: настройки
канала принадлежат NetworkManager и затёрлись бы при переподключении.
Допущение «NetworkManager выставляет те же значения, что ручной
`openvpn` с сценарием resolved» не проверено на живой станции;
проверка — задача 8.2, при расхождении D7 и требование уточняются.

## Risks / Trade-offs

- Имена зон `ru`, `by`, `su`, `рф` остаются за маршрутизатором при обоих
  профилях; остальные имена в запасном профиле видит администратор
  корпоративной сети, а внешний адрес — адрес выхода в Белоруссии:
  российские сервисы могут отвечать иначе. Так выбрано пользователем
  («всё через axata»).
- Ручной `systemctl start awg-quick@amn0` при запасном профиле без сообщения
  пропускается (D3); панель такой пункт не показывает.
- Две копии учётных данных (D1).
- Откат `main` оставляет запасной профиль: пользователь возвращается
  на основной повторным вызовом, когда Amnezia заработает.
- Первый запуск `net-profile backup` с живой станции возможен, только
  если ручной `openvpn` остановлен (D4); отдельная задача 8 выполняется
  пользователем из панели, потому что на время перехода связи нет.
