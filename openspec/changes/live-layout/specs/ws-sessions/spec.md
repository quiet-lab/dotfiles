## MODIFIED Requirements

### Requirement: Файлы сессий
Сессии MUST храниться в `~/.local/state/workspaced/sessions/<имя>.toml`, по файлу на сессию. Файл MUST содержать: время снимка, номер активного стола, для каждого стола список workspace по порядку и активный, для каждого workspace его раскладку в памяти (спецификация ws-daemon, «Расстановка окон»), снятую с экрана командой сохранения, — исходное место каждого приложения (ячейку или прямоугольник), главное приложение и изменённые прямоугольники мест — и таблицу дополнительных приложений сессии, и список окон. Запись дополнительного приложения сессии MUST хранить его имя ключом таблицы, прямоугольник и, если запись описывает не приложение конфига, класс окна, командную строку и каталог процесса. Таблица дополнительных приложений, главное приложение и изменённые прямоугольники мест MUST быть необязательными: снимок прежнего формата MUST читаться без ошибки, главным тогда считается приложение по полю `main` раздела конфига или главной ячейке, а изменённых прямоугольников нет.

Окно с тегом экземпляра MUST записываться экземпляром: имя приложения, номер экземпляра из тега (у тега без номера — 1), список workspace, в которые окно входит по тегам состава (спецификация ws-daemon, «Состав workspace»), стол, `pool` или `hidden`, прямоугольник окна и для каждого своего workspace прямоугольник, запомненный для окна в этом workspace, в обоих режимах; для окна, которое стоит на столе, где такой workspace активен, MUST записываться нынешний прямоугольник. Экземпляр, у процесса которого нет других окон и который не является первым экземпляром своего приложения (с наименьшим номером среди живых окон приложения), MUST хранить ещё командную строку и каталог процесса по правилу ниже; первый экземпляр и экземпляр, чей процесс держит и другие окна (второе окно браузера), командную строку MUST NOT хранить: первый запускается командой приложения, остальные открывает сам процесс приложения. Если командная строка экземпляра не найдена, он MUST записываться без неё. Запись снимка, которая ещё ждёт поднятия своего workspace (требование «Восстановление при старте») и окна которой с тем же тегом экземпляра нет, MUST переноситься в новый снимок как есть. Свободное окно без тега MUST записываться со столом, командной строкой, каталогом и прямоугольником. Окно приложения без номера экземпляра (снимок прежнего формата) MUST читаться без ошибки и восстанавливаться по прежнему правилу: одно окно на приложение, без состава и прямоугольников из снимка. Поле `workspace` у свободного окна в снимках прежних версий MUST читаться без ошибки и MUST NOT учитываться и записываться.

Снимок `default` MUST записываться только по команде сохранения сессии — цепочке `save_session` или `workspaced save-session` (требование «Дополнительные приложения сессии»). События композитора и остальные команды демона файл MUST NOT изменять: снимок — это сохранённое состояние, к которому возвращаются, а не след последнего действия. Отложенной записи и записи по таймеру MUST NOT быть. Перед загрузкой именованной сессии демон MUST записать `default` (требование «Загрузка сессии»): это единственный случай, когда файл обновляется не по команде сохранения, и он тоже вызван явной командой пользователя. Именованная сессия MUST записываться только по команде `session save <имя>` или из окна выбора и MUST быть копией текущего состояния на момент команды.

Состояние, изменившееся после последнего снимка — принятые окна, переносы workspace между столами, обмен мест, сдвинутые окна, списки столов, записи ожидания запуска и ожидания окон при восстановлении, — MUST жить только в памяти демона: перезапуск демона и перезагрузка системы MUST возвращать систему к последнему записанному снимку. Теги экземпляров и состава живых окон при перезапуске демона без перезагрузки MUST оставаться как есть (требование «Восстановление при старте»): состав живого окна снимок MUST NOT менять, а сверка с эффективным конфигом снимает теги, которым записи сессии больше не соответствуют (спецификация ws-daemon, «Состав workspace»).

Командная строка и каталог, которые демон записывает для окна — в снимке сессии у свободного окна и у экземпляра, в записи дополнительного приложения сессии и в разделе workspace по команде сохранения, — MUST быть пригодны для запуска с хоста. У процесса в песочнице flatpak путь к исполняемому файлу и рабочий каталог существуют только внутри песочницы, поэтому командной строкой такого окна MUST записываться `flatpak run <идентификатор приложения>` и исходные аргументы процесса после пути к исполняемому файлу, а каталог MUST NOT записываться. Идентификатор приложения MUST браться из `/proc/<pid>/cgroup` по юниту вида `app-flatpak-<идентификатор>-<номер>.scope`, причём экранирование `\xNN` в имени юнита MUST раскодироваться. Если юнита такого вида нет, MUST записываться командная строка процесса, приведённая к виду, пригодному для запуска: строка, которую процесс переписал одной строкой с пробелами вместо отдельных аргументов (так делают Chromium и основанные на нём браузеры), MUST делиться по пробелам, если файла с таким именем нет; относительный путь к исполняемому файлу (`./steamwebhelper`) MUST заменяться абсолютным от рабочего каталога процесса; имя без каталога MUST оставаться как есть, если находится в `PATH`; если исполняемый файл так не найден, вместо него MUST браться путь из `/proc/<pid>/exe`. Если не найден и он, у окна нет командной строки: свободное окно в снимок MUST NOT попадать, дополнительным приложением MUST NOT становиться, а демон MUST записать предупреждение в журнал. Команду свободного окна из снимка прежней версии демон MUST приводить к тому же виду перед запуском и сверкой с открытыми окнами; команду, исполняемый файл которой не найден, демон MUST NOT запускать и MUST записать предупреждение в журнал.

#### Scenario: Автосохранение
- **WHEN** выполнена команда `workspaced raise dev-front --desktop 1`, затем открыто новое окно
- **THEN** `default.toml` не изменился: снимок сам по себе не пишется, и время изменения файла прежнее

#### Scenario: Снимок пишет команда сохранения
- **WHEN** после этого нажата цепочка `save_session`
- **THEN** к моменту, когда команда вернула управление, `default.toml` содержит стол 1 с активным `dev-front` и все его окна с прямоугольниками

#### Scenario: Изменения после последнего снимка не переживают перезапуск
- **WHEN** после команды сохранения пользователь перенёс `work` на стол 3, принял там новое окно и перезапустил демон
- **THEN** демон восстанавливает состояние на момент сохранения: `work` снова на прежнем столе, принятого окна в его составе нет

#### Scenario: Именованный снимок
- **WHEN** выполнена `workspaced session save review`
- **THEN** появляется `review.toml` с состоянием на этот момент; дальнейшая работа его не меняет

#### Scenario: Дополнительное приложение в снимке
- **WHEN** в `work` принят калькулятор, не описанный в конфиге, и нажата цепочка `save_session`
- **THEN** к возврату команды в `default.toml` у `work` есть запись дополнительного приложения с классом окна, командной строкой, каталогом и прямоугольником, а само окно записано как экземпляр этого приложения

#### Scenario: Окно программы из flatpak
- **WHEN** в `work` принято окно Postman, запущенного из flatpak с аргументами `--force-device-scale-factor=1.5` и `--no-sandbox`, и нажата цепочка `save_session`
- **THEN** командной строкой записано `flatpak run com.getpostman.Postman --force-device-scale-factor=1.5 --no-sandbox`, каталога у записи нет, и этой командой окно поднимается с хоста; путь `/app/extra/Postman/postman` в снимок не попадает

#### Scenario: Командная строка Chromium
- **WHEN** свободное окно Chromium, процесс которого показывает в `/proc/<pid>/cmdline` одну строку `/usr/lib/chromium/chromium --ozone-platform=wayland`, попадает в снимок
- **THEN** командой записаны два элемента, `/usr/lib/chromium/chromium` и `--ozone-platform=wayland`, и этой командой окно поднимается

#### Scenario: Относительная команда
- **WHEN** свободное окно Steam принадлежит процессу с командой `./steamwebhelper …` и рабочим каталогом `~/.local/share/Steam/ubuntu12_64`, и нажата цепочка `save_session`
- **THEN** командой в снимке записан абсолютный путь `/home/mne/.local/share/Steam/ubuntu12_64/steamwebhelper` с прежними аргументами; снимок прежней версии с `./steamwebhelper` при восстановлении запускается тем же абсолютным путём

#### Scenario: Снимок прежней версии с привязками
- **WHEN** в `default.toml` у свободного окна записано `workspace = "work"`, а таблицы дополнительных приложений в файле нет
- **THEN** демон читает снимок, ставит окно на его место на столе, но к `work` не привязывает; после следующей записи снимка поля `workspace` у окна нет

#### Scenario: Экземпляры и состав в снимке
- **WHEN** у `chromium` два окна одного процесса — `app:chromium#1` с тегом `ws:work` и `app:chromium#2` с тегами `ws:work` и `ws:surf`, у `neovide` окно `app:neovide#1` из запуска демоном и окно `app:neovide#2`, открытое из yazi командой `neovide notes.md` в каталоге `~/notes`, и нажата цепочка `save_session`
- **THEN** в `default.toml` четыре записи окон приложений: `chromium` с номером 1 и `workspaces = ["work"]`, `chromium` с номером 2 и `workspaces = ["surf", "work"]`, `neovide` с номером 1 — все три без командной строки, и `neovide` с номером 2, командой `["neovide", "notes.md"]` и каталогом `/home/mne/notes`

#### Scenario: Прямоугольник режима stack в снимке
- **WHEN** окно `chrome-ai` входит в `surf` (режим `stack`, стол 2) и в `work` (режим обмена мест, стол 1), для `surf` запомнен прямоугольник 1700,60 1920×2140, пользователь на столе 1, окно стоит там в 400,300 1400×1000, и нажата цепочка `save_session`
- **THEN** у записи окна `rects` содержит `surf` с прямоугольником 1700,60 1920×2140 и `work` с прямоугольником 400,300 1400×1000: прямоугольник пишется для workspace обоих режимов; `rect` записи — тот же нынешний прямоугольник

#### Scenario: Раскладка workspace в снимке
- **WHEN** в `work` окно `chrome-ai` (запись сессии с прямоугольником в центре экрана) сдвинуто в 400,300 1400×1000, Super+V поменял его местами с herdr, и нажата цепочка `save_session`
- **THEN** у `work` в `default.toml` исходное место `chrome-ai` — ячейка `center`, исходное место herdr — прямоугольник записи `chrome-ai`, главное приложение — `chrome-ai`, изменённый прямоугольник места herdr — 400,300 1400×1000; `config.toml` не изменился, а после перезапуска демона `workspaced status --json` показывает ту же раскладку

#### Scenario: Сохранение до ленивого поднятия
- **WHEN** после перезагрузки на столе 1 поднят `work`, на стол 2 с `surf` пользователь ещё не переходил, в снимке у `chrome-ai` запись с `workspaces = ["surf"]` и прямоугольником для `surf`, и нажата цепочка `save_session`
- **THEN** в новом `default.toml` запись `chrome-ai` с тем же номером, составом и прямоугольником сохранена, и при переходе на стол 2 окно восстанавливается по ней

#### Scenario: Снимок прежнего формата с окнами приложений
- **WHEN** в `default.toml` у окон `chromium` и `neovide` нет номеров экземпляров, у `chromium` две записи окна
- **THEN** демон читает снимок без ошибки, поднятие `work` запускает `chromium` и `neovide` по одному разу, второе окно `chromium` не ждётся, а следующая команда сохранения пишет записи с номерами

### Requirement: Загрузка сессии
По `session load <имя>` или выбору в окне сессий демон MUST сначала записать текущее состояние в `default`, затем привести систему к снимку. Окна приложения MUST сверяться с его экземплярами в снимке: живые окна приложения по возрастанию номера MUST переиспользоваться для записей снимка по возрастанию номера и MUST сохранять свои номера. Переиспользованное окно MUST получить состав из записи — теги состава, которых в записи нет, MUST сниматься, недостающие MUST ставиться для тех workspace записи, которые описывают приложение окна в эффективном конфиге после загрузки, — и встать на место из снимка по правилу размещения (спецификация ws-daemon, «Следование общего окна за столом»): в прямоугольник, записанный для окна в этом workspace, а без него — на место своего приложения в раскладке workspace из снимка, одинаково в обоих режимах; прямоугольники записи по workspace MUST стать запомненными. Живые окна приложения сверх числа его записей в снимке и окна приложений, которых в снимке нет, MUST быть закрыты штатно, как по запросу закрытия от композитора. Свободное окно MUST переиспользоваться, если в снимке есть свободное окно с той же командной строкой и каталогом, иначе MUST закрываться штатно. Записи снимка, которым живого окна не хватило, MUST восстанавливаться так же, как при старте (требование «Восстановление при старте»); демон MUST считать приложение запущенным при восстановлении, если запустил его этой загрузкой. Дополнительные приложения сессии MUST браться из загружаемого снимка и заменять прежние целиком: приложения загруженного снимка входят в свои workspace, а дополнительные приложения прежнего состояния MUST быть сняты. Раскладка каждого workspace — назначение мест, главное приложение, изменённые прямоугольники — MUST браться из снимка и заменять прежнюю, а у workspace, которого в снимке нет, MUST собираться из описания. Списки workspace по столам и активные MUST стать как в снимке, приведённом к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»); активный стол — как в снимке. Ожидания окон, оставшиеся от прежнего восстановления, загрузка MUST снимать до сверки.

#### Scenario: Загрузка со сверкой
- **WHEN** открыты окна `editor-front`, `terminal-front` и Telegram, и загружена сессия, в которой есть `editor-front`, `firefox-front`, а Telegram нет
- **THEN** окна `editor-front` и `terminal-front` не перезапускаются (`terminal-front` паркуется, если его workspace в снимке не активен), Telegram получает запрос закрытия, `firefox-front` запускается, все окна на местах из снимка

#### Scenario: Дополнительные приложения из снимка
- **WHEN** в текущем состоянии у `work` есть дополнительное приложение `galculator`, а в загружаемой сессии у `work` записано дополнительное приложение `keepassxc`
- **THEN** после загрузки `work` содержит `keepassxc` и не содержит `galculator`, окно `keepassxc` запущено и стоит на месте из снимка

#### Scenario: Несохранённый документ
- **WHEN** загружаемая сессия не содержит окна редактора с несохранённым файлом
- **THEN** редактор получает штатный запрос закрытия и показывает свой диалог, демон не завершает процесс принудительно

#### Scenario: Лишнее окно браузера
- **WHEN** открыты три окна `chromium` с номерами 1, 2 и 3, а в загружаемой сессии у `chromium` две записи
- **THEN** окна с номерами 1 и 2 переиспользуются и получают состав из записей, окно с номером 3 получает запрос закрытия, `chromium` не запускается

#### Scenario: Состав из снимка при загрузке
- **WHEN** окно `chrome-ai` входит только в `surf`, а в загружаемой сессии его запись содержит `workspaces = ["surf", "work"]` и у `work` есть запись о месте `chrome-ai`
- **THEN** после загрузки у окна теги `ws:surf` и `ws:work`, второй `chrome-ai` не запускается

#### Scenario: Недостающий экземпляр при загрузке
- **WHEN** открыто одно окно `neovide` с номером 1, а в загружаемой сессии у `neovide` ещё запись с номером 2, командой `["neovide", "notes.md"]` и каталогом `~/notes` в `work`, активном на столе 1
- **THEN** демон запускает `neovide notes.md` в `~/notes`, окно получает тег `app:neovide#2` и `ws:work` и встаёт в стопку `neovide` в ячейке `right`

### Requirement: Восстановление при старте
При старте демон MUST загрузить `default`: списки workspace по столам, активные, дополнительные приложения сессии и раскладки workspace (назначение мест, главное приложение, изменённые прямоугольники) восстанавливаются целиком; полностью поднимается (с запуском приложений) только workspace, активный на столе, который был активен на момент снимка; посторонние окна снимка MUST быть запущены сразу на своих местах; активный workspace другого стола MUST подниматься при первом переходе на этот стол; workspace, не активные ни на одном столе, MUST подниматься при первом вызове. Дополнительное приложение сессии MUST восстанавливаться так же, как приложение конфига: при поднятии его workspace демон MUST захватить подходящее открытое окно, а при его отсутствии запустить приложение по записанным командной строке и каталогу. Списки столов из снимка демон MUST привести к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»): столом workspace MUST стать тот, где он в снимке активен, а если он не активен ни на одном столе — первый по номеру стол, в списке которого он встретился; из остальных списков он MUST быть убран, и стол, лишившийся своего активного workspace, MUST остаться без активного. Порядок оставшихся workspace в списке стола MUST сохраняться. Если `default` отсутствует или не читается, демон MUST стартовать с пустым состоянием и записать причину в журнал. После восстановления демон MUST поднять workspace из раздела `[startup]` конфига на его столе, если раздел задан: приложения без окон запускаются, открытые подходящие окна захватываются; если этот workspace уже поднят сессией, повторное поднятие только расставляет окна.

Экземпляры снимка (требование «Файлы сессий») MUST восстанавливаться по записям. Запись, для которой уже есть живое окно с тем же тегом `app:<имя>#<номер>` (перезапуск демона без перезагрузки), MUST считаться исполненной: приложение MUST NOT запускаться повторно, теги состава окна MUST оставаться как есть, а прямоугольники записи MUST стать запомненными для тех её workspace, в которые окно входит. Запись с командной строкой, для которой живого окна нет, MUST запускаться этой командой в своём каталоге при поднятии первого из её workspace — раньше, чем поднятие захватывает окна и запускает приложения; запись без workspace — сразу после поднятия workspace активного стола. Первый экземпляр приложения — запись с наименьшим номером среди записей этого приложения в снимке — MUST запускаться командой приложения при поднятии своего workspace, как приложение без окон. Пока окно записи с командной строкой не появилось, поднятие её workspace MUST NOT отдавать приложению окна других workspace и MUST NOT запускать команду приложения, если первого экземпляра, ждущего запуска, среди записей этого workspace нет. Остальные записи без командной строки демон MUST NOT запускать: их окна открывает сам процесс приложения (браузер, восстанавливающий свои окна). Демон MUST ждать такие окна, только если сам запустил приложение при восстановлении; если окна приложения при старте уже открыты, записи без командной строки, которым живого окна не нашлось, MUST сниматься со строкой в журнале.

Появившееся окно MUST сопоставляться с записью: сначала по pid процесса, запущенного для записи с командной строкой, и его потомков, затем по приложению окна — с ожидающей записью этого приложения с наименьшим номером; окну, принятому ожиданием запуска приложения, MUST доставаться запись с наименьшим номером среди тех, у которых в списке есть workspace, для которого приложение запущено, а без таких — с наименьшим номером вообще. Сопоставленное окно MUST получить номер экземпляра из записи (спецификация ws-daemon, «Идентификация окон»), теги состава тех workspace записи, которые описывают его приложение в эффективном конфиге, и встать по правилу размещения (спецификация ws-daemon, «Следование общего окна за столом»): в прямоугольник записи для этого workspace, а без него — на место своего приложения в раскладке workspace, одинаково в обоих режимах; если ни один его workspace не активен — на `special:pool`; запись без workspace — на свой стол в свой прямоугольник. Все прямоугольники записи по workspace MUST стать запомненными. Фокус восстановление MUST NOT менять, кроме фокуса главному окну поднимаемого workspace. Окно на `special:hidden` в момент снимка MUST восстанавливаться видимым по тому же правилу.

Ожидание окон при восстановлении MUST быть событийным и MUST NOT ограничиваться сроком: окно приходит событием композитора, выход процесса — событием от процесса. Ожидание записи с командной строкой MUST сниматься с предупреждением в журнале, если запущенный для неё процесс завершился без окна. Ожидание записей без командной строки MUST сниматься, когда все записи приложения исполнены, клавишей приложения или командой `workspaced app` для него, командой сохранения сессии и загрузкой сессии; команда сохранения MUST NOT снимать записи, которые ждут поднятия своего workspace, — они переходят в новый снимок (требование «Файлы сессий»); после этого новое окно приложения MUST приниматься по общим правилам (спецификация ws-daemon, «Посторонние окна»). Содержимое окон — вкладки, открытые файлы, историю — демон MUST NOT восстанавливать: это дело приложений.

### Requirement: Дополнительные приложения сессии
Окно, принятое в workspace по событию (спецификация ws-daemon, «Посторонние окна») или по команде сохранения сессии, а также окно, перетащенное в workspace цепочкой приложения с признаком перетаскивания (спецификация ws-daemon, «Цепочка приложения»), MUST становиться дополнительным приложением сессии этого workspace, если приложения с таким местом в workspace ещё нет. Запись MUST жить только в сессии: файл конфига демон MUST NOT изменять. Если окно подходит приложению конфига, дополнительным приложением MUST становиться само это приложение с прямоугольником окна — и только тогда, когда в этом workspace его ещё нет. Если подходящего приложения нет, демон MUST завести дополнительное приложение сессии с именем, построенным из класса окна и не совпадающим ни с одним именем приложения конфига или другого дополнительного приложения, и записать у него класс окна, командную строку и каталог процесса окна (по правилу требования «Файлы сессий») и его прямоугольник. Если приложение окна известно только записи сессии другого workspace, в этом workspace MUST заводиться полная запись под тем же именем — с классом, командной строкой, каталогом и прямоугольником: запись только о месте без приложения в файле конфига не выживает. Окно MUST получить тег экземпляра этого приложения и тег состава этого workspace (спецификация ws-daemon, «Состав workspace»). Имя дополнительного приложения MUST быть единственным в сессии: одно имя MUST называть одну программу, и окно другой программы MUST NOT приписываться чужой записи, даже если класс окна тот же (спецификация ws-daemon, «Посторонние окна»). Окно без класса и окно, для процесса которого не найден исполняемый файл, дополнительным приложением MUST NOT становиться: первое не отличить от служебного окна приложения, второе нечем запустить заново.

По цепочке `save_session` или команде `workspaced save-session` демон MUST записать снимок сессии целиком. Команда MUST пройти по всем столам, на которых активен workspace, и принять в него окна без тега по тем же правилам, что действуют при появлении окна; местом принятого окна MUST становиться прямоугольник, который окно занимает сейчас, — окно, уже поставленное пользователем куда нужно, команда MUST NOT двигать. Затем команда MUST снять раскладку каждого такого workspace с экрана (спецификация ws-daemon, «Расстановка окон») и записать снимок вместе с раскладками (требование «Файлы сессий»): сдвинутое окно — дополнительного приложения или приложения конфига — даёт изменённый прямоугольник места своего приложения, у приложения с несколькими окнами — по первому экземпляру. Прямоугольник записи дополнительного приложения — место, с которым приложение принято, — команда MUST NOT менять. Общее окно, которое стоит не на столе этого workspace (ушло за пользователем к другому своему workspace), раскладку этого workspace MUST NOT менять: его нынешнее положение описывает место в другом workspace. Места приложений в файле конфига команда MUST NOT менять. Команда MUST записать в журнал строку с числом workspace, числом их окон и числом принятых окон. Файл конфига команда MUST NOT изменять.

Дополнительное приложение сессии демон MUST во всём остальном вести как приложение workspace: его окна MUST переноситься вместе с workspace на другой стол, MUST парковаться при вытеснении workspace и возвращаться с ним, MUST вставать на своё место в раскладке, когда приходит на стол workspace и MUST входить в состав окон workspace для панели. Если в конфиге появляется приложение с именем дополнительного приложения сессии, MUST действовать запись конфига, а дополнительное приложение MUST быть снято с записью предупреждения в журнал. Запись, которая называет приложение конфига и задаёт ему только место, MUST быть снята, когда приложения с таким именем в конфиге не стало; запись workspace, которого в конфиге не стало, MUST быть снята так же. Запись MUST сниматься и тогда, когда из этого workspace по команде отделения окна (спецификация ws-daemon, «Отделение окна») уходит последнее окно приложения; если окно при этом закрывается и других окон у приложения нет нигде, запись с командной строкой MUST сниматься во всех workspace, где она есть, а если окна приложения остаются в других workspace, их записи MUST оставаться. Перечитывание конфига MUST сохранять дополнительные приложения сессии, кроме снятых по этим правилам.
