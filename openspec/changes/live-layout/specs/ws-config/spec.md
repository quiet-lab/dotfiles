## MODIFIED Requirements

### Requirement: Файл конфига и его разделы
Демон MUST читать конфиг из `~/.config/workspaced/config.toml` (файл под chezmoi). Файл MUST состоять из разделов: `[env]` — общие переменные окружения; `[keys]` — цепочки служебных действий `save_session`, `save_workspace`, `sessions`, `next_workspace` и список `reserved` зарезервированных сочетаний; `[templates.<имя>]` — шаблон геометрии с полем `main` (имя главной ячейки) и таблицей `cells`, где каждая ячейка — прямоугольник `{ x, y, w, h }`; `[apps.<имя>]` — приложение с полями `cmd` (команда запуска), `args` (массив), `cwd`, `env` (таблица), `chain`, `class` и `title` (регулярные выражения для захвата открытого окна по классу и заголовку; `title` без `class` не допускается), `dialog_title` (регулярное выражение по заголовку собственного диалога приложения; без `class` не допускается), `family` (имя приложения-семейства, если это приложение — его вариант) и `rect` (прямоугольник `{ x, y, w, h }` — положение и размер окна по умолчанию, когда workspace об этом приложении ничего не говорит); `[startup]` — `workspace` (имя существующего workspace, который поднимается при старте демона) и `desktop` (стол 1…8, по умолчанию 1); `[workspaces.<имя>]` — workspace с полями `template` (обязательно), `main` (главное приложение по умолчанию — чьё место в раскладке главное, спецификация ws-daemon, «Расстановка окон»; без поля главным считается приложение, записанное в главную ячейку шаблона), `icon`, `chain`, `env`, `mode` и таблицей `apps`, где значение — запись приложения в этом workspace: имя ячейки шаблона строкой, таблица `{ rect = { x, y, w, h } }` для окна вне ячеек либо таблица с полем места `cell` (имя ячейки шаблона) или `rect` (прямоугольник) — ровно одним из двух — и необязательными полями `chain` (клавиша приложения в этом workspace, требование «Цепочки клавиш и привязки») и `mode` (режим клавиши этого приложения в этом workspace); `[[binds]]` — записи с полем `chain`, ровно одним из полей действия `action`, `exec`, `dispatch`, `lua` и необязательными `range`, `locked`, `repeating`, `mouse`, `release`. В корне файла MUST быть допустим необязательный список `ignore_classes` — регулярные выражения, которые сопоставляются с классом окна целиком; окно с подходящим классом демон MUST NOT принимать в workspace ни при каких условиях (спецификация ws-daemon, «Посторонние окна» и «Захват открытых окон приложения»). По умолчанию список пуст. Оба поля, `dialog_title` и `ignore_classes`, нужны потому, что признака диалога композитор не сообщает; выражения с ошибкой MUST приводить к отказу с указанием приложения или списка. Поле `mode` MUST задавать поведение клавиши приложения в этом workspace (спецификация ws-daemon, «Цепочка приложения») и принимать значения `swap` — обмен мест с главным приложением — и `stack` — подъём окна без переноса; по умолчанию MUST действовать `swap`, а иное значение MUST приводить к отказу с указанием workspace, полученного значения и допустимых. Поле `mode` записи приложения в таблице `apps` workspace MUST принимать те же значения и задавать режим клавиши этого приложения в этом workspace; иное значение MUST приводить к отказу с указанием workspace, приложения, полученного значения и допустимых. Без поля `mode` режим приложения в workspace MUST быть режимом workspace, в том числе у приложения, место которого задано `rect` (записью файла или записью дополнительного приложения сессии). Режим workspace и режим приложения MUST задавать только поведение клавиши: раскладка workspace в памяти, её снятие с экрана и память о геометрии окон в обоих режимах одинаковы (спецификация ws-daemon, «Расстановка окон»). Запись-таблица без `cell` и `rect` или с обоими полями сразу MUST отклоняться с указанием workspace и приложения. Порядок записей в таблице `apps` workspace MUST сохраняться таким, как в файле: по нему конец цикла клавиши выбирает следующее приложение workspace, а приложения, добавленные сессией, MUST идти после описанных в файле. У приложения MUST быть задано хотя бы одно из полей `cmd` и `class`: без `cmd` приложение не открывает новых окон и только собирает подходящие по `class`, без `class` окно узнаётся лишь по запуску. Поле `family` MUST называть другое приложение того же файла, у которого самого нет `family`: уровней ровно два — семейство и его варианты. Имя приложения MUST NOT содержать двоеточие и знак `#`: этими знаками демон отделяет части тега экземпляра. Прямоугольники ячеек, `rect` приложения и `rect` в таблице `apps` workspace — это положение и размер окна на экране как есть: демон MUST передавать их композитору без прибавления или вычитания отступов. Координаты прямоугольников MUST отсчитываться от левого верхнего угла экрана: целое число — пиксели, строка с процентом — доля ширины или высоты монитора; смешивать формы в одном прямоугольнике MUST быть можно. Координаты MUST допускать отрицательные значения, а размеры — значения больше экрана: окно может выходить за его края частично с любой стороны, демон MUST передавать такие значения композитору без обрезания и без сдвига внутрь экрана. Необязательный ключ `gap` в корне файла задаёт зазор в пикселях только для команд `half`, `place` и `maximize`, которые строят геометрию от рабочей области; по умолчанию 0. Неизвестные ключи MUST приводить к предупреждению в журнале, но не к отказу.

- **WHEN** файл содержит один шаблон `halves` с ячейками `left` и `right`, одно приложение `terminal` с `cmd = "wezterm-gui"` и один workspace `work` с `template = "halves"`, `main = "terminal"` и `apps = { terminal = "right" }`
- **THEN** `workspaced check` завершается успешно и выводит один workspace, одно приложение и один шаблон

#### Scenario: Заголовок диалога у приложения
- **WHEN** у приложения `chrome` заданы `class = "(?i)^google-chrome$"` и `dialog_title = "^(Диспетчер задач|Task Manager)$"`
- **THEN** `workspaced check` завершается успешно, окно Chrome с заголовком «Диспетчер задач» остаётся свободным, а обычное окно Chrome принимается в workspace; конфиг с `dialog_title` без `class` или с ошибкой в выражении отклоняется с указанием приложения и поля

#### Scenario: Список исключённых классов
- **WHEN** в корне файла задано `ignore_classes = ["termfilechooser", "pinentry.*"]`
- **THEN** `workspaced check` завершается успешно, окна классов `termfilechooser` и `pinentry-gtk` не принимаются ни в один workspace, а окно класса `termfilechooser-2` под выражение не подходит: класс сопоставляется целиком; конфиг с ошибкой в выражении отклоняется с указанием `ignore_classes`

#### Scenario: Режим workspace
- **WHEN** у workspace `surf` задано `mode = "stack"`, а у `work` поля `mode` нет
- **THEN** `workspaced check` завершается успешно, `surf` работает подъёмом окон, `work` — обменом мест; конфиг с `mode = "stak"` отклоняется с указанием workspace, значения `stak` и допустимых `swap` и `stack`

#### Scenario: Порядок приложений в разделе workspace

- **THEN** демон держит их в этом порядке, и конец цикла клавиши переходит от `chrome` к `yandex-browser`, а не к `chrome-ai` по алфавиту

#### Scenario: Цепочки сохранения сессии и записи в конфиг

- **THEN** `workspaced check` завершается успешно; конфиг с `title` без `class`, с некорректным регулярным выражением или с `startup.workspace`, которого нет среди workspace, отклоняется с указанием поля

#### Scenario: Семейство и его вариант

#### Scenario: Запись привязки с двумя действиями

- **THEN** `workspaced check` завершается с ошибкой, называющей цепочку записи и оба поля

#### Scenario: Переопределение клавиши и режима в workspace
- **WHEN** у приложения `chrome-ai` задано `chain = "SUPER+SHIFT+V"`, в разделе `surf` записано `chrome-ai = { cell = "right", chain = "SUPER+V" }`, а в разделе `work` — `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 }, mode = "swap" }`
- **THEN** `workspaced check` завершается успешно; ключ `chrome-ai` в `surf` — Super+V, место — ячейка `right`; `calc` в `work` выбирается обменом мест, хотя ячейки у него нет

#### Scenario: Запись приложения без места
- **WHEN** в разделе `surf` записано `chrome-ai = { chain = "SUPER+V" }` либо `chrome-ai = { cell = "right", rect = { x = 0, y = 0, w = 10, h = 10 } }`
- **THEN** `workspaced check` завершается с ошибкой, называющей `surf` и `chrome-ai`

- **WHEN** в разделе `work` записано `chromium = { cell = "left", mode = "stak" }`
- **THEN** `workspaced check` завершается с ошибкой, называющей `work`, `chromium`, значение `stak` и допустимые `swap` и `stack`

#### Scenario: Приложение без ячейки берёт режим workspace
- **WHEN** в разделе `work` (без поля `mode`) записано `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 } }`
- **THEN** `workspaced check` завершается успешно, и клавиша `calc` в `work` меняет калькулятор местами с главным приложением, как у приложений с ячейкой; запись `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 }, mode = "stack" }` оставляет главное приложение на месте и только поднимает окно калькулятора

### Requirement: Слежение за конфигом
Демон MUST замечать изменение файла конфига без перезапуска, перечитывать его и, если файл корректен, применять: новые и изменённые workspace и приложения доступны следующей цепочкой, а привязки обновляются вызовом `hyprctl reload`. Тот же вызов демон MUST делать один раз при старте, после удачной загрузки конфига: файл могли поправить, пока демон не работал, а бинарник — обновить до версии с новыми действиями, и привязки композитора тогда отстали бы от конфига. Если композитор в этот момент недоступен, демон MUST записать предупреждение и продолжить работу, а повторять вызов по сроку MUST NOT. Перечитывание MUST запускаться по событиям файловой системы, означающим завершённую запись файла: закрытие файла, открытого на запись, и появление файла под своим именем после записи во временный файл с переименованием. События, приходящие посреди записи, демон MUST NOT учитывать, а задержку вместо них применять MUST NOT: одно сохранение файла MUST давать ровно одно перечитывание. При перечитывании демон MUST сравнить раздел каждого workspace в прежнем и новом файле и у тех workspace, чей раздел изменился или исчез, снять раскладку в памяти (спецификация ws-daemon, «Расстановка окон») — назначение мест, главное приложение и изменённые прямоугольники — вместе с запомненными прямоугольниками окон: раскладка MUST быть собрана заново из нового файла, и правка файла MUST возвращать расстановку без перезапуска демона. Если такой workspace активен на каком-либо столе, его окна на этом столе MUST сразу встать на места из новой раскладки, а фокус и порядок окон по глубине MUST NOT меняться; окна неактивного workspace встают на места из файла при его поднятии. Раскладка workspace, раздел которого не менялся, MUST сохраняться, чтобы правка одного workspace не сбрасывала обмен мест и сдвинутые окна в другом. После каждого перечитывания демон MUST сверить теги открытых окон и записи ожидания с составом приложений: окна приложений, которых в конфиге не стало, MUST становиться посторонними, а ожидания их окон MUST сниматься (требование «Посторонние окна» спецификации ws-daemon). При ошибке демон MUST оставить прежний конфиг и записать ошибку в журнал.

#### Scenario: Новый workspace добавлен вручную
- **WHEN** пользователь дописал в конфиг workspace `notes` с `chain = "SUPER+W n"` и сохранил файл
- **THEN** демон перечитывает конфиг по событию завершения записи, в журнале одна строка о перечитывании, `workspaced status --json` содержит `notes`, а Super+W, n поднимает его

#### Scenario: Запись во временный файл с переименованием
- **WHEN** конфиг применён командой `chezmoi apply`, которая пишет временный файл и переименовывает его на место конфига
- **THEN** демон перечитывает конфиг один раз, неполный файл не читается, `hyprctl reload` вызывается один раз

#### Scenario: Перезапуск демона с новым конфигом при живом композиторе
- **WHEN** в конфиг добавлена запись `[[binds]]` с действием, которого прежний бинарник не знал, и демон перезапущен с новым бинарником
- **THEN** демон при старте вызывает `hyprctl reload config-only`, и число привязок в `hyprctl binds` совпадает с выводом `workspaced keys --list` с поправкой на служебные привязки подкарт, а новое сочетание работает нажатием без ручной перезагрузки конфига композитора

#### Scenario: Откат правки возвращает расстановку
- **WHEN** `work` активен на столе 1, в разделе `work` ячейка `chromium` заменена прямоугольником и файл сохранён, затем правка отменена командой `chezmoi apply`
- **THEN** после первого сохранения окна Chromium на столе 1 стоят в записанном прямоугольнике, после отката — снова в ячейке `left`, без поднятия `work`; фокус не меняется, а раскладка соседнего workspace `surf`, где окно Chrome сдвинуто мышью, не сбрасывается

#### Scenario: Запись workspace не сдвигает окна
- **WHEN** в `work` окно `neovide` сдвинуто мышью и вызвана цепочка `save_workspace`
- **THEN** после перечитывания записанного файла окно `neovide` остаётся в сдвинутом прямоугольнике, который теперь записан у `neovide` в разделе `work`, и `workspaced status --json` не показывает у `work` изменённых мест

#### Scenario: Перечитывание освобождает окно исчезнувшего приложения
- **WHEN** приложение `alacritty` удалено из конфига, а его окно на столе несёт тег `app:alacritty#1`
- **THEN** после перечитывания конфига тег с окна снят и окно считается посторонним; подробности — в требовании «Посторонние окна» спецификации ws-daemon

### Requirement: Запись по команде сохранения
По цепочке `save_workspace` или команде `workspaced save-workspace` демон MUST снять раскладку активного workspace текущего стола с экрана (спецификация ws-daemon, «Расстановка окон») и записать в его раздел: места приложений (`apps`) по раскладке в памяти, `main` — главное приложение, дополнительные приложения сессии этого workspace и свободные окна, открытые на текущем столе. Место приложения MUST записываться именем ячейки шаблона workspace, если прямоугольник места с ней совпадает — сначала проверяется исходная ячейка места, затем ячейки шаблона по порядку, — а иначе `rect`. Раскладку в памяти демон MUST NOT записывать в файл никакой другой командой. Окна workspace MUST определяться по тегам состава (спецификация ws-daemon, «Состав workspace»), а не по описанию приложений: окно, убранное из workspace командой отделения, MUST NOT давать места своему приложению, а общее окно, входящее и в другие workspace, MUST записываться наравне с остальными — приложение под своим именем, с местом из раскладки этого workspace: общее окно, ушедшее за пользователем на другой стол, MUST давать место, снятое, когда оно стояло на столе этого workspace, а не нынешнее положение. Записи того же приложения в разделах других workspace команда MUST NOT менять: после записи приложение описано в нескольких разделах, и окно остаётся общим и после перезапуска демона. Для свободного окна и для дополнительного приложения сессии демон MUST сначала найти среди всех приложений конфига то, которому окно подходит по выражениям `class` и, если оно задано, `title`: поиск MUST идти сначала по приложениям-вариантам, затем по семействам, внутри каждой группы по именам, и найденное приложение MUST быть записано под своим именем с `rect`; новое приложение MUST заводиться только тогда, когда подходящего не нашлось, — с `cmd`, `args`, `cwd` из процесса окна (по правилу требования «Файлы сессий» спецификации ws-sessions, по которому окно из песочницы flatpak записывается командой `flatpak run`) и `rect`. Окно, которое в workspace не принимается (класс из `ignore_classes`, заголовок под `dialog_title` его приложения), демон MUST NOT записывать: в конфиге ему не место, как и в составе workspace. Дополнительные приложения сессии записанного workspace MUST после записи быть сняты: они перешли в конфиг. Если у приложения несколько окон, в `rect` MUST записываться место первого экземпляра, а остальные его окна MUST NOT попадать в файл отдельными записями. Записанное окно MUST получить тег экземпляра этого приложения и тег состава этого workspace и перестать быть свободным, а раскладка workspace MUST быть собрана заново из записанного конфига без перезапуска демона (требование «Слежение за конфигом»): изменённые прямоугольники мест становятся местами из описания. Свободные окна на других столах и окна на `special:hidden` MUST NOT записываться. Таблицу `apps` раздела команда MUST править на месте, а не собирать заново: у записи приложения MUST меняться только место (имя ячейки или `rect`), поля `chain` и `mode` записи, порядок записей и комментарии внутри таблицы MUST сохраняться; запись без переопределений — строка или таблица `{ rect = … }` без других полей — MUST записываться строкой, если новое место записывается ячейкой, и таблицей `{ rect = … }` иначе; запись-таблица с полями `chain`, `mode` MUST сохранять свою форму и менять только поле места (`cell` или `rect`) на прежней позиции. Записи, которых в файле не было (дополнительные приложения сессии, свободные окна стола), MUST добавляться в конец таблицы в порядке раздела эффективного конфига. Остальные разделы и workspace, комментарии и порядок ключей MUST сохраняться. Запись MUST быть атомарной; перед записью файл MUST быть перечитан, и если он изменился с момента последнего чтения, команда MUST быть отклонена с сообщением, а конфиг перечитан. После удачной записи команда MUST NOT перечитывать конфиг сама: перечитывание приходит событием завершённой записи файла, одно на одно сохранение. Без команды сохранения демон MUST NOT изменять файл.

#### Scenario: Сохранение после обмена ячеек
- **WHEN** в workspace `dev-front` терминал переведён в главную ячейку цепочкой приложения и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` `main = "terminal-front"`, назначения `apps` соответствуют экрану, комментарии в файле на месте, остальные workspace не изменились

#### Scenario: Сохранение приложения с двумя окнами
- **WHEN** в workspace `work` у `chromium` два окна: первый экземпляр сдвинут пользователем, второй стоит в ячейке `left`, и вызвана команда сохранения
- **THEN** у `chromium` записан `rect` первого экземпляра, второй записи о `chromium` в файле нет, и следующее поднятие `work` ставит оба окна в этот прямоугольник

#### Scenario: Сохранение постороннего окна
- **WHEN** на столе с активным `dev-front` из лаунчера открыт калькулятор, не описанный в конфиге, он принят дополнительным приложением сессии, перемещён пользователем, и вызвана команда сохранения workspace
- **THEN** в конфиге у `dev-front` появляется приложение с `cmd` калькулятора и `rect` его текущего положения, окно несёт тег этого приложения, а следующий `raise` `dev-front` ставит калькулятор на это место

#### Scenario: Дополнительные приложения сессии переходят в конфиг
- **WHEN** в `work` приняты калькулятор и окно `chrome-ai`, затем вызвана цепочка `save_workspace`
- **THEN** в конфиге у `work` записаны оба приложения, в `[apps]` появилось описание калькулятора, дополнительных приложений сессии у `work` больше нет, и следующая запись снимка сессии их не содержит

#### Scenario: Диалог в конфиг не попадает
- **WHEN** на столе с активным `surf` открыт диалог выбора файла класса `termfilechooser`, перечисленного в `ignore_classes`, и вызвана команда сохранения workspace
- **THEN** диалог в конфиг не записан, приложения по его классу в `[apps]` не появилось, окно осталось свободным

#### Scenario: Окно подходит приложению другого workspace
- **WHEN** на столе с активным `work` открыто свободное окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai` из workspace `surf`, и вызвана команда сохранения
- **THEN** в таблице `apps` у `work` появляется запись `chrome-ai` с `rect` окна, нового приложения по классу окна в `[apps]` не появляется, окно несёт тег `app:chrome-ai#1`

#### Scenario: Одно перечитывание на одну запись
- **WHEN** вызвана цепочка `save_workspace` и файл конфига записан
- **THEN** в журнале демона одна строка о перечитывании конфига, `hyprctl reload config-only` вызывается один раз

#### Scenario: Свободное окно на другом столе не записывается
- **WHEN** на столе 1 активен `dev-front`, на столе 3 без активного workspace открыт свободный терминал, и на столе 1 вызвана команда сохранения
- **THEN** терминал в конфиг не попадает и остаётся свободным

#### Scenario: Работа без сохранения
- **WHEN** пользователь два часа поднимает workspace, меняет ячейки и двигает окна, не вызывая команду сохранения
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст

#### Scenario: Общее окно записывается в раздел workspace
- **WHEN** окно `chrome-ai` из `surf` перетащено в `work`, сдвинуто пользователем, и на столе 1 вызвана цепочка `save_workspace`
- **THEN** в разделе `work` появляется запись `chrome-ai` с `rect` окна, запись `chrome-ai = "right"` в разделе `surf` не меняется, окно по-прежнему входит в оба workspace, а после перезагрузки поднятие второго из них забирает окно первого, а не запускает второй Chrome AI

#### Scenario: Отделённое окно не записывается
- **WHEN** у `chromium` в `work` два окна, первое убрано из `work` командой отделения и осталось в `dev-front`, второе стоит в ячейке `left`, и вызвана цепочка `save_workspace`
- **THEN** у `chromium` в разделе `work` остаётся ячейка `left`: место считается по второму окну, входящему в `work`

#### Scenario: Переопределения переживают запись
- **WHEN** в разделе `surf` записано `chrome-ai = { cell = "right", chain = "SUPER+V" }`, окно `chrome-ai` сдвинуто пользователем, и на столе `surf` вызвана цепочка `save_workspace`
- **THEN** запись `chrome-ai` в разделе `surf` содержит `rect` нового положения окна и прежнее `chain = "SUPER+V"`, поля `cell` в ней нет, остальные записи раздела не изменились

#### Scenario: Порядок записей сохраняется
- **WHEN** в разделе `surf` приложения записаны в порядке `chrome`, `yandex-browser`, `chrome-ai`, в `surf` принято окно калькулятора, и вызвана цепочка `save_workspace`
- **THEN** в разделе `surf` записи идут в порядке `chrome`, `yandex-browser`, `chrome-ai`, калькулятор, а комментарии внутри таблицы `apps` на месте

#### Scenario: Раскладка после обмена мест
- **WHEN** в `work` окно `chrome-ai` (запись сессии) сдвинуто в 400,300 1400×1000, Super+V поменял его местами с herdr, и вызвана цепочка `save_workspace`
- **THEN** в разделе `work` записаны `main = "chrome-ai"`, `chrome-ai = "center"` и `herdr = { rect = { x = 400, y = 300, w = 1400, h = 1000 } }`, записи `chromium` и `neovide` не изменились, комментарии на месте

#### Scenario: Прямоугольник, совпадающий с другой ячейкой
- **WHEN** в `work` окно `neovide` сдвинуто мышью точно в прямоугольник ячейки `left` шаблона `thirds`, а окно Chromium — в другое место, и вызвана цепочка `save_workspace`
- **THEN** у `neovide` записано `neovide = "left"`, у `chromium` — `rect` его нынешнего прямоугольника

#### Scenario: Раскладка без команды не пишется
- **WHEN** пользователь сдвигает окна `work`, меняет их местами клавишами и сохраняет сессию, не вызывая цепочку `save_workspace`
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст, а раскладка живёт в памяти демона и в снимке сессии
