## Why

Проверка шага 5 серии изменений модели окон
([`docs/window-model.md`](../../../docs/window-model.md)) 23.09.2026 на
workspace `work` (режим обмена ячеек `swap`) показала расхождение с тем, как
пользователь представляет раскладку. Окно Chrome AI, перетащенное в `work`
клавишей Shift+Super+V, стоит в центре экрана. Пользователь передвигает его
и меняет размер, нажимает Super+V и ожидает, что Chrome AI встанет на главное
место, а herdr с главного места займёт прямоугольник, который он только что
задал Chrome AI. Сейчас этого не происходит по трём причинам:

- **Ручная подгонка в режиме `swap` демоном не учитывается.** Места
  приложений берутся из конфига; требование «Расстановка окон» (ws-daemon)
  прямо говорит, что ручная подгонка живёт только до следующей расстановки,
  а поднятие workspace снова ставит окна в ячейки.
- **Приложение без ячейки в режиме `swap` не меняется с главным.** По решению
  D7 изменения `workspace-overrides` запись с `rect` (в том числе запись
  сессии, которую получает перетащенное окно) выбирается в режиме `stack`:
  клавиша только поднимает окно наверх.
- **Клавиша приложения, окно которого активно, заканчивает цикл.** Окно,
  которое пользователь только что перетаскивал мышью, активно, и Super+V
  возвращает фокус herdr, ничего не переставляя.

Пользователь сформулировал требование так: изменение положения и размера
окна становится его основным положением на этом workspace — раскладкой
workspace в памяти, полноценной, но не записанной в конфиг, пока не нажата
клавиша записи workspace (Ctrl+Super+S Ctrl+Super+W). Закрытие окна убирает
заданное ему место из этой раскладки.

## What Changes

- **Раскладка workspace в памяти.** У каждого приложения workspace есть
  место: исходное (ячейка или `rect` из описания) и, если окно сдвигали,
  изменённый прямоугольник. Раскладка одна на workspace, в обоих режимах;
  по ней ставятся новые окна, окна, приходящие на стол, запускаемые
  приложения, по ней идёт обмен мест.
- **Раскладка снимается с экрана в момент действия.** Hyprland 0.56.2
  не сообщает о перемещении и изменении размера окна ни событием сокета,
  ни событием Lua, поэтому демон читает прямоугольники окон у композитора
  тогда, когда собирается по раскладке действовать: клавиша приложения,
  поднятие и вытеснение workspace, перенос на стол, уход общего окна
  за пользователем, команды сохранения. Опроса и таймеров нет.
- **Обмен мест вместо обмена ячеек.** В режиме `swap` вызванное приложение
  и главное обмениваются местами целиком — прямоугольниками, какими они
  стоят сейчас; главное приложение демон хранит явно. Решение D7
  `workspace-overrides` отменяется: приложение без ячейки тоже меняется
  с главным, отказаться можно полем `mode = "stack"` у записи.
- **Нажатие клавиши неглавного приложения в режиме `swap` ставит его
  на главное место**, даже если его окно активно (например, после
  перетаскивания мышью).
- **Поднятие не двигает окна, которые уже стоят на столе**, в обоих
  режимах; окно, приходящее на стол, встаёт туда, где его оставили в этом
  workspace, а без этого — на место своего приложения в раскладке.
  Режим workspace задаёт только поведение клавиши.
- **Возврат к исходному.** Когда в workspace не остаётся окон приложения
  (закрытие, отделение), его изменённое место снимается. Ctrl+Super+Пробел
  снимает изменённые места всех приложений workspace, сохраняя обмен мест.
- **Запись в конфиг только по команде.** Ctrl+Super+S Ctrl+Super+W пишет
  раскладку в раздел workspace: место, совпадающее с ячейкой шаблона, —
  именем ячейки, иначе `rect`; `main` — главное приложение.
  Перечитывание изменённого раздела собирает раскладку заново и сразу
  применяет её на столе, где workspace активен.
- **Снимок сессии хранит раскладку.** Ctrl+Super+S дважды пишет главное
  приложение и изменённые места каждого workspace, а у окон —
  прямоугольники по всем их workspace, не только режима `stack`. Прямоугольник
  записи дополнительного приложения сессии командой сохранения сессии больше
  не переписывается: сдвинутое окно даёт изменённое место в раскладке.

## Что не входит

- События о перемещении окна: их нет в Hyprland 0.56.2; плагин композитора
  и опрос отвергнуты (`design.md`, решение D2).
- Снятие записи дополнительного приложения сессии при закрытии его
  последнего окна: закрытие снимает только изменённое место, запись
  по-прежнему снимает команда отделения окна.
- Панель Quickshell и конфиг сессии не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-daemon`: «Расстановка окон» (раскладка в памяти, снятие с экрана,
  главное приложение, память окна в обоих режимах, возврат к исходному),
  «Цепочка приложения» (обмен мест, отмена исключения для приложения без
  ячейки, нажатие клавиши неглавного приложения), «Расстановка по команде»
  (сброс изменённых мест в обоих режимах), «Следование общего окна
  за столом» (место окна одинаково в обоих режимах).
- `ws-config`: «Файл конфига и его разделы» (режим задаёт только
  клавишу, исключение для приложения без ячейки снято), «Слежение
  за конфигом» (раскладка изменённого раздела применяется сразу),
  «Запись по команде сохранения» (пишется раскладка в памяти).
- `ws-sessions`: «Файлы сессий» (раскладка workspace, прямоугольники окна
  по всем workspace), «Загрузка сессии» и «Восстановление при старте»
  (место окна одинаково в обоих режимах), «Дополнительные приложения
  сессии» (команда сохранения снимает раскладку, прямоугольник записи
  не переписывается).

## Порядок архивации

Требования «Цепочка приложения» (ws-daemon), «Файл конфига и его разделы»
и «Запись по команде сохранения» (ws-config) взяты из дельт изменения
`workspace-overrides`; «Файлы сессий», «Загрузка сессии» и «Восстановление
при старте» (ws-sessions) — из дельты `session-instances`; остальные —
из `openspec/specs/`. Поэтому изменение архивируется после
`workspace-overrides` и `session-instances`. Изменения `keys-help`
и `panel-shared-windows` этих требований не трогают.

## Impact

- Демон `~/work/pets/workspaced`: `state.rs` (раскладка: изменённые места,
  главное приложение, формат workspace в снимке), `daemon.rs` (снятие
  раскладки, обмен мест, шаг цикла в режиме `swap`, поднятие, следование,
  расстановка, возврат к исходному, применение раскладки после
  перечитывания), `config.rs` (режим приложения), `save.rs` (запись
  workspace и снимка), `session.rs` (снимок и восстановление раскладки).
- Снимок `~/.local/state/workspaced/sessions/default.toml` получает
  необязательные поля; прежний снимок читается.
- Конфиг `dot_config/workspaced/config.toml` и панель не меняются.
- Документация: `AGENTS.md` (режимы, расстановка, сохранение),
  `docs/window-model.md` (разделы 2.1, 2.3, 2.4, 2.5, 3, 5), `README.md`
  демона.
