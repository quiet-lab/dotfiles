# Design: Токен панели ввода

## Решение

Контракт панели ввода с форком herdr — токен `input_pane` источника
`claude-input` на панели Claude Code, значение — `pane_id` панели Neovim
с буфером ввода. По нему форк находит панель ввода, чтобы передать ей фокус
при выборе workspace в Spaces и агента в Agents, а также следить
за состоянием blocked (follow-blocked).

## Почему токен на панели Claude Code

Снимок клиента несёт токены только панелей с агентом; у панели Neovim агента
нет, и её токены до клиента не доходят. Панель Claude Code агента имеет,
поэтому токен ставится на неё и указывает на панель ввода.

## Почему токен, а не переменная среды

`CLAUDE_INPUT_PANE` видна только процессу внутри панели; сервер herdr
переменных среды панелей не читает. Токен панели — состояние сервера,
доступное форку напрямую и видимое в `herdr pane get` (`tokens`).

## Границы

- Токен ставится после `pane split`; при `resume` с живой панелью буфера
  `open` ставит тот же токен заново (команда идемпотентна), новую панель
  не создаёт.
- `close` токен не снимает: панель буфера закрывается, токен остаётся
  до конца сессии панели Claude Code.
- Токены хранятся по имени без привязки к источнику; токены других
  источников (например, `symbol`, `color` источника `duty`) имеют другие
  имена и не затрагиваются.
- Ошибка `report-metadata` (herdr без `--token`, код 2) не прерывает хук.
