## Why

Буфер диалога `claude://dialog` держался открытым, пока экран панели Claude Code оставался диалогом. Пользователь 7 ноября 2026 решил: после ответа по `:w` окно сразу возвращается к `claude://input`, постоянно открыт только буфер основного поля ввода.

## What Changes

- По `:w` в буфере диалога (после Enter, в множественном выборе — после стрелок до «Submit») окно панели сразу показывает `claude://input` с прежним содержимым.
- Подпись отвеченного диалога запоминается; пока экран с ней совпадает, буфер диалога не открывается снова.
- Другой экран (следующий вопрос карточки, новый вопрос, запрос разрешения) открывает пустой буфер диалога заново.

## Capabilities

### Modified Capabilities
- `claude-input`: требования о буфере диалога, возврате ввода и сохранении диалога.

## Impact

`dot_config/nvim/local/claude-input/lua/claude_input/init.lua`, `tests/switch_spec.lua`, `docs/claude-input.md`.
