# Proposal: Демон workspace для сессии Hyprland

## Why

В сессии Hyprland все окна плавающие, и собирать рабочее окружение под задачу приходится руками: запускать редактор, терминал и браузер с нужным каталогом и профилем, расставлять их по экрану и повторять это после каждой перезагрузки. Изменение hyprland-config оставило это «до Lua-раскладки зон». Обсуждение 13–15 сентября 2026 показало, что нужна не раскладка, а уровень выше: именованные наборы приложений с окружением и геометрией, которые вызываются цепочкой клавиш на любом столе, и сессии, которые восстанавливают их после перезагрузки.

## What Changes

- Новый демон `workspaced` на Rust (отдельный проект `~/work/pets/workspaced`, ссылка `~/.local/bin/workspaced`, по образцу `eww-daemon`): единственный владелец модели «приложение, workspace, стол, сессия». Он слушает события Hyprland, запускает приложения с их окружением, расставляет окна по ячейкам шаблона, паркует вытесненные окна и отдаёт состояние панели по своему сокету.
- Рукописный конфиг `~/.config/workspaced/config.toml` под chezmoi: шаблоны геометрии с прямоугольниками ячеек в координатах экрана, приложения с командой, аргументами, каталогом, переменными окружения и цепочкой клавиш, workspace с набором приложений по ячейкам, главным по умолчанию и иконкой, привязки с произвольными цепочками клавиш. Демон пишет в этот файл только по команде «сохранить workspace».
- Сессии в `~/.local/state/workspaced/sessions/`: сессия `default` пишется демоном при каждом изменении, именованные сессии сохраняются командой; загрузка сессии сверяет открытое с нужным, после перезагрузки поднимается workspace, активный на момент выхода, остальные лениво.
- Цепочки клавиш генерирует демон из конфига в виде Lua-кода, `hyprland.lua` подгружает их при перезагрузке конфига: цепочка workspace поднимает его на текущем или указанном столе, цепочка приложения меняет его местами с главным окном workspace или находит workspace с этим приложением, цепочка сохранения записывает текущее состояние workspace в конфиг, цепочка сессий открывает окно выбора сессии.
- Панель Quickshell: плитка стола показывает, помимо иконок окон активного workspace, иконки остальных workspace, поднятых на этом столе, а по команде демона открывает окно выбора сессии с картой «стол → workspace».
- **BREAKING** для модели столов: окна workspace мигрируют между столами вслед за вызовом, а вытесненные окна уходят на специальный стол `special:pool`, который панель не показывает. Ручной перенос окна на другой стол не запрещается, но следующий вызов workspace собирает свои окна обратно.
- Юнит `workspaced.service` в автозапуске сессии рядом с `quickshell-panel.service`; Lua-раскладка зон, запланированная в hyprland-config, не создаётся.

## Capabilities

### New Capabilities
- `ws-config`: формат конфига демона (шаблоны, приложения, workspace, привязки), правила подстановки окружения, генерация цепочек клавиш и проверка их конфликтов, запись в конфиг по команде сохранения.
- `ws-daemon`: поведение демона в работе: поднятие workspace на столе, цепочка приложения, расстановка окон по ячейкам, парковка, учёт посторонних окон, протокол состояния для панели, жизненный цикл и перезапуск без потери состояния.
- `ws-sessions`: сессии: автосохранение `default`, именованные снимки, загрузка со сверкой, восстановление после перезагрузки, окна вне workspace.

### Modified Capabilities
- `qs-workspaces`: плитка стола дополнительно показывает иконки workspace, поднятых на этом столе, и позволяет поднять workspace кликом; окна на `special:pool` не отображаются (уже разрешено требованием «Отображение скрытых окон», подтверждается сценарием). Capability вводится изменением quickshell-panel, которое должно быть заархивировано до этого; дельта здесь оформлена как добавление требований.
- `qs-sessions` (новая, в составе панели): окно выбора сессии по команде демона с картой «стол → workspace» и пометкой, что поднимется сразу, а что лениво.
- `hyprland-binds`: добавляются требования к цепочкам клавиш демона (подкарты, загрузка привязок из демона, Escape); таблица привязок Openbox не меняется.
- `hyprland-config`: требование «Поведение окон в переходный период» переформулируется: окна остаются плавающими постоянно, расположение задаёт демон, Lua-раскладка зон не планируется; добавляется специальный стол `special:pool`.
- `hyprland-autostart`: в состав автозапуска добавляется юнит `workspaced.service` (текст требования берётся из дельты quickshell-panel).

## Impact

- Новый проект `~/work/pets/workspaced` (Rust: tokio или std-потоки, serde, toml_edit, notify). В dotfiles попадают конфиг, юнит и правки `hyprland.lua`.
- `dot_config/hypr/hyprland.lua`: загрузка привязок из `workspaced keys --lua`, правило стола `special:pool`, комментарий о Lua-раскладке снимается.
- `dot_config/quickshell/panel/`: плитка стола (`tiles/Workspaces.qml`) получает иконки workspace, новое всплывающее окно выбора сессии, подключение к сокету демона через `Socket` из `Quickshell.Io`.
- `dot_config/systemd/user/workspaced.service`.
- Зависимости от порядка изменений: quickshell-panel должно быть заархивировано первым, так как дельты `qs-workspaces` и `hyprland-autostart` строятся на его спецификациях.
- Спайк до реализации: принимает ли `hl.exec_cmd` в Hyprland 0.56.2 правило `tag`, работают ли `window.tag`, `window.move` и `window.resize` с точными координатами через сокет с Lua-конфигом. Запасной путь для идентификации окон: pid процесса, запущенного демоном, и командная строка с каталогом из `/proc`.
