# Design: Демон workspace для сессии Hyprland

## Context

Мотивация — в proposal.md («Why»). Что уже есть и что ограничивает подход:

- Hyprland 0.56.2 с Lua-конфигом `dot_config/hypr/hyprland.lua`. Диспетчеры через сокет `.socket.sock` принимают только выражения Lua (`dispatch hl.dsp.focus({ workspace = 3 })`), несколько шагов по порядку — одним выражением-функцией (находка проекта quickshell-panel, D4). События приходят из `.socket2.sock` (`openwindow`, `closewindow`, `movewindowv2`, `workspacev2`, `activewindowv2`, `windowtitlev2`). Факты об окнах — `j/clients` по тому же сокету: адрес, класс, заголовок, стол, pid, теги, положение, размер. В заглушках API есть `hl.exec_cmd(cmd, rules)`, поле `tags` окна, диспетчеры `window.tag`, `window.move`, `window.resize`, `window.center`, `bring_to_top`, подкарты `hl.define_submap`.
- Восемь столов «1»…«8» на DP-2, все окна плавающие (hyprland-config, «Поведение окон в переходный период»), скрытие окна — перенос на `special:hidden` без перехода (Super+Z), панель показывает такие окна приглушёнными.
- Панель Quickshell (изменение quickshell-panel): плитка стола 274×36 с иконками окон, всплывающие окна `PopupWindow` справа от колонки, команды композитору через `Hyprland.dispatch`, файлы и потоки через `Quickshell.Io`. Панель не просит клавиатуру; поле фильтра лаунчера включает режим по требованию.
- Прецедент демона в проекте: `eww-daemon` (Rust, `~/work/pets/eww-daemon`, ссылка в `~/.local/bin`), но его код завязан на X11 и переносится только подход.
- Ограничения проекта: дотфайлы под chezmoi, рукописные файлы с комментариями, `chezmoi status` должен оставаться пустым в покое.

Терминология в этом изменении: **стол** — рабочий стол Hyprland 1…8 (в обсуждении «десктоп»); **workspace** — именованный набор приложений с геометрией из конфига демона; **приложение** — запись конфига с командой, окружением и цепочкой; **окно** — живое окно Hyprland, у которого может быть приложение; **ячейка** — прямоугольник шаблона; **главная ячейка** — та, где стоит главное окно workspace.

## Goals / Non-Goals

**Goals:**
- Один владелец модели (демон); Hyprland — источник фактов об окнах и исполнитель; панель — отражение и пульт; `hyprland.lua` — только привязки.
- Рукописный конфиг меняется только по явной команде пользователя; всё, что меняется в работе, живёт в сессиях, которые пишет демон.
- Демон переживает перезапуск и `hyprctl reload` без потери состояния: окна помечены тегами в композиторе, списки восстанавливаются из `default`.
- Панель работает и без демона (плитки столов как раньше), демон работает и без панели (цепочки клавиш).

**Non-Goals:**
- Мозаичная раскладка и автоматическое перераспределение ячеек при закрытии окна: окна плавающие, пустая ячейка остаётся пустой, перекрытия допустимы.
- Группы и вкладки Hyprland, несколько мониторов, сессия Openbox (демон запускается только в Hyprland).
- Интерактивный редактор конфига в панели: конфиг правится руками, панель только показывает и вызывает.
- Восстановление содержимого окон (вкладки браузера, буферы редактора): демон восстанавливает только запуск, каталог, окружение и геометрию.

## Decisions

**D1. Демон `workspaced` на Rust — отдельный проект, в dotfiles только конфиг, юнит и привязки.**
Проект `~/work/pets/workspaced`, сборка `cargo build --release`, ссылка `~/.local/bin/workspaced` на бинарник, как у `eww-daemon`. Один бинарник с подкомандами: `workspaced daemon` — сервер; клиентские подкоманды `raise <workspace> [--desktop N]`, `app <app> [--desktop N] [--workspace W]`, `next`, `save-workspace`, `session save <имя>`, `session load <имя>`, `session list --json`, `keys --lua`, `status --json`, `check` — шлют запрос в сокет демона и печатают ответ. Зависимости: `serde`, `toml_edit` (запись с сохранением комментариев), `notify` (слежение за конфигом), `nix` или `libc` (setsid для запуска приложений), сокеты Unix из std; асинхронная среда не нужна, достаточно потока на сокет событий, потока на сокет клиентов и общего состояния под мьютексом. Альтернатива «вся логика в Lua-конфиге, панель читает JSON» отвергнута: панели нужна модель (списки workspace, иконки, сессии), Lua теряет состояние при `hyprctl reload`, а окно выбора сессии требует двусторонней связи. Альтернатива «логика в панели Quickshell» отвергнута: без панели цепочки клавиш мертвы.

**D2. Идентификация окон: демон запускает приложение сам и помечает окно тегом.**
Демон запускает команду приложения сам (`setsid`, каталог `cwd`, окружение из трёх слоёв), запоминает pid и ждёт `openwindow`; окно сопоставляется с приложением по pid из `j/clients` (pid окна равен pid запущенного процесса либо его потомка по `/proc/<pid>/stat`), после чего демон ставит окну тег `app:<имя>` диспетчером `window.tag`. Тег живёт в композиторе, поэтому после перезапуска демона или `hyprctl reload` окна опознаются по тегам из `j/clients` без повторного запуска. Запуск через `hl.exec_cmd` с правилом `tag` — запасной путь, если сопоставление по pid не сработает для конкретной программы (проверяется спайком в задаче 1.2); он не даёт задать окружение, поэтому основным быть не может. Окно, запущенное не демоном (терминал руками в нужном каталоге), приложением не считается: оно постороннее, см. D6.

**D3. Конфиг `~/.config/workspaced/config.toml`: только данные, без вычисляемых конструкций.**
Формат зафиксирован в спецификации ws-config. Ключевые выборы: координаты ячеек — от левого верхнего угла экрана в пикселях или процентах от размера монитора (панель 330 px учитывается в числах, по решению пользователя), отрицательные координаты и размеры больше экрана допустимы и передаются композитору как есть (проверено 2026-09-15: Hyprland ставит плавающее окно в −400,−150 размером 5000×2600); окружение приложения складывается из `[env]` корня, `env` workspace и `env` приложения, нижний слой перекрывает верхний, `$VAR` и `~` подставляются в `args`, `cwd` и значения `env`; workspace задаёт приложения таблицей «имя → ячейка» либо «имя → `{ rect = … }`» для окна вне ячеек; цепочка — строка сочетаний через пробел (`"SUPER+W 3 f"`), у workspace и приложения короткая форма `chain`, для сочетаний со столом — массив `[[binds]]`. Типов и ролей нет: два Firefox с разными профилями — два приложения, которым можно дать одну цепочку. TOML выбран за читаемость и `toml_edit`, который переписывает файл с сохранением комментариев и порядка; JSON отвергнут из-за комментариев, Lua — из-за невозможности записи обратно.

**D4. Демон пишет в конфиг только по команде «сохранить workspace».**
Команда записывает в раздел активного workspace текущее назначение приложений по ячейкам, ручную подгонку геометрии (`rect` у приложения, если его окно не совпадает с ячейкой) и посторонние окна, добавленные к workspace в сессии (как новые приложения с `cmd`, `args`, `cwd` из `/proc` и `rect`). Разделы `templates`, `binds`, `keys`, `env` и остальные workspace не трогаются, файл переписывается атомарно (временный файл и переименование), перед записью перечитывается. Автоматическая запись отвергнута по решению пользователя: рукописный файл под chezmoi не должен меняться без явного действия, иначе `chezmoi status` никогда не пуст.

**D5. Одна операция `raise(W, N)`, из неё выводятся все цепочки.**
Алгоритм: для каждого приложения W найти окно по тегу где угодно (другой стол, `special:pool`, `special:hidden`) и перенести на стол N без перехода; окна, не найденные, запустить (D2) на стол N; окна на N, принадлежащие другим workspace, — на `special:pool`; посторонние окна, привязанные к W в сессии, — вернуть на N; расставить окна по ячейкам из состояния сессии (по умолчанию из конфига); фокус на главное окно; W становится активным на N, добавляется в список N, если его там не было; если W был активным на другом столе M, он остаётся в списке M, но перестаёт быть там активным (его окна перенесены на N). Несколько диспетчеров идут одним выражением-функцией, чтобы порядок сохранился. Цепочка workspace — `raise(W, текущий)`; `[[binds]]` со столом — переход на стол и `raise`; «следующий workspace» — `raise(следующий в списке стола, текущий)`. Миграция и пересечение workspace (общее приложение у двух workspace) получаются из этого же алгоритма.

**D6. Цепочка приложения: обмен с главной ячейкой или поиск workspace.**
Порядок: (1) приложение есть в активном workspace текущего стола — если оно в главной ячейке, только фокус; иначе окна приложения и главной ячейки меняются ячейками (закрытое окно сначала запускается), фокус на приложение; (2) иначе среди workspace в списке текущего стола первый по порядку списка, содержащий приложение, поднимается здесь, дальше (1); (3) иначе среди workspace других столов по возрастанию номера стола, с переходом на стол; (4) приложение не входит ни в один workspace — запускается плавающим в центре экрана поверх остальных на текущем столе, привязывается к активному workspace стола в состоянии сессии (не в конфиге), ячейки не меняются; повторная цепочка для него — только фокус и поднятие наверх. Два приложения с одной цепочкой в одном workspace — ошибка конфига (`workspaced check`, демон сообщает и не загружает файл). Обмен двух ячеек выбран вместо «главное по стабильному порядку»: бывшее главное встаёт в ячейку поднятого, остальные не шевелятся, вопрос о «домашнем месте» не возникает.

**D7. Геометрия: демон расставляет плавающие окна диспетчерами, пересчёта по событиям нет.**
Положение и размер задаются `window.move` и `window.resize` с точными экранными координатами по прямоугольнику ячейки за вычетом зазора `gap` (и `rect` для окон вне ячеек). Расстановка выполняется при `raise`, при обмене ячеек, при появлении окна запущенного приложения и при загрузке сессии. Ручные перемещения демон не отменяет и не записывает, пока не вызвана команда сохранения. Закрытие окна ячейку не освобождает для других: следующий запуск приложения встанет туда же. Собственная Lua-раскладка `hl.layout.register` отвергнута: главное окно и состав живут в демоне, гонять их в Lua через `hyprctl eval` сложнее, чем расставить плавающие окна, а исключение из правила «всё плавающее» не понадобится.

**D8. Парковка: окна workspace на `special:pool`, посторонние окна остаются на столе.**
Окно с тегом приложения, чей workspace не активен ни на одном столе, лежит на `special:pool`; панель этот стол не показывает (qs-workspaces разрешает не показывать специальные столы, кроме `special:hidden`), а иконка workspace в плитке стола остаётся доступом к нему. Посторонние окна (без тега), открытые на столе, привязываются в сессии к активному workspace этого стола в момент появления и паркуются вместе с ним; если workspace на столе нет, окно свободно и `raise` его не трогает. Скрытие пользователем (`special:hidden`, Super+Z) не меняется: демон не переносит окна с `special:hidden` при `raise`, кроме случая, когда цепочка приложения адресует именно это окно. Смешанный вариант выбран, чтобы плитка стола показывала только окна активного workspace, а случайные окна не пропадали из панели.

**D9. Сессии: `default` пишется при каждом изменении, именованные — по команде, загрузка — сверкой.**
Каталог `~/.local/state/workspaced/sessions/`, файл на сессию (формат в спецификации ws-sessions). `default.toml` переписывается с задержкой 500 мс после последнего изменения (raise, обмен, открытие и закрытие окна, перемещение, смена активного стола). Именованная сессия — копия текущего состояния под именем. Загрузка: для каждого окна снимка найти живое окно с тем же приложением (для посторонних — та же команда и каталог), переиспользовать и расставить; лишние окна закрыть штатно (`window.close`, приложение само спросит про несохранённое); недостающие запустить. Перед загрузкой текущее состояние записывается в `default`, чтобы был путь назад. Восстановление при старте демона: читается `default`; полностью поднимается только workspace, активный на столе, который был активен при выходе; посторонние окна снимка с `rect` восстанавливаются сразу на своих местах; активные workspace других столов поднимаются при первом переходе на стол (событие `workspacev2`), припаркованные — при первом вызове. Если файла `default` нет — пустое состояние.

**D10. Восстановление посторонних окон: команда и каталог из `/proc`.**
При снимке демон читает `/proc/<pid>/cmdline` и `/proc/<pid>/cwd` окна; при загрузке запускает команду в этом каталоге и ставит окно по `rect`. Для программ в песочнице (flatpak) каталог может оказаться внутри песочницы — тогда окно восстанавливается командой без каталога. Окно без pid (Xwayland без `_NET_WM_PID`) в снимок не попадает.

**D11. Цепочки клавиш: демон генерирует Lua, `hyprland.lua` его выполняет.**
`workspaced keys --lua` печатает код с `hl.define_submap` и `hl.bind` по конфигу: первое сочетание цепочки открывает подкарту, каждое следующее — вложенную, последнее выполняет `hl.dsp.exec_cmd("workspaced …")` и сбрасывает подкарту; в каждой подкарте `Escape` сбрасывает без действия. Цепочки `[keys]` (`save_workspace`, `sessions`, `next_workspace`) обрабатываются так же. `hyprland.lua` подгружает результат при перезагрузке конфига: `local code = io.popen("workspaced keys --lua"):read("a"); load(code, "workspaced", "t", { hl = hl })()`, с проверкой ошибки и записью в журнал, чтобы сломанный конфиг демона не ломал перезагрузку Hyprland. Конфликт «одна цепочка — начало другой» демон отвергает при чтении с указанием обеих строк. При изменении файла конфига демон вызывает `hyprctl reload`, чтобы привязки обновились. Альтернатива «демон сам держит привязки через свой grab» невозможна в Wayland; альтернатива «привязки дублируются руками в `hyprland.lua`» отвергнута: две правды.

**D12. Протокол с панелью: сокет Unix, строки JSON.**
Сокет `$XDG_RUNTIME_DIR/workspaced/sock`. Запросы клиентов — одна строка JSON (`{"cmd":"raise","workspace":"dev-front","desktop":3}`), ответ — одна строка. Команда `subscribe` переводит соединение в поток: демон шлёт полное состояние при подключении и после каждого изменения (`{"event":"state", …}` со списками workspace по столам, активным, иконками и составом) и события (`{"event":"show-sessions","sessions":[…]}` с содержимым сессий для окна выбора). Панель подключается через `Socket` из `Quickshell.Io`, переподключается с задержкой при обрыве и без демона показывает плитки как раньше. Альтернатива — файл состояния плюс `FileView`: не даёт события «показать окно сессий» и требует опроса каталога сессий.

**D13. Панель: иконки workspace в плитке и окно выбора сессии.**
В плитке стола после иконок окон (или вместо них, если окон нет) идут иконки workspace из списка стола: активный первым и с подсветкой, остальные приглушённые; иконка — `Quickshell.iconPath` по полю `icon` конфига с заглушкой. Клик по иконке шлёт демону `raise`, правый клик открывает меню «Поднять», «Убрать со стола», наведение показывает состав в подсказке. Имя workspace текстом в плитке не показывается: оно есть только в подсказке при наведении на иконку (решение пользователя 2026-09-15). Лимит 10 иконок и метка «+N» считаются по сумме окон и workspace. Окно выбора сессии — `PopupWindow` справа от колонки, список сессий с датой; при перемещении по списку (стрелки, наведение) справа карта «стол → workspace» с пометкой «сразу» у workspace активного стола и «лениво» у остальных; Enter или клик загружает, Escape закрывает; клавиатура — режим по требованию по образцу поля фильтра (D3 quickshell-panel), отпускается при закрытии.

**D14. Юнит и жизненный цикл.**
`dot_config/systemd/user/workspaced.service`: `ExecStart=%h/.local/bin/workspaced daemon`, `Restart=on-failure`, `RestartSec=1`, `PartOf=hyprland-session.target`, `After=hyprland-session.target`, `WantedBy=hyprland-session.target`; `quickshell-panel.service` получает `After=workspaced.service` без `Requires`. При старте демон читает конфиг, `j/clients` (теги дают приложения, стол даёт положение), затем `default`, и сверяет: окна, которые уже открыты, не запускаются повторно. Перезапуск демона посреди работы, таким образом, ничего не теряет. Перезагрузка Hyprland (`hyprctl reload`) демона не касается: теги и столы живут в композиторе.

**D15. Изменения в `hyprland.lua`.**
Загрузка привязок из демона (D11); правило стола `special:pool` не нужно, специальные столы создаются по первому переносу; комментарий «до Lua-раскладки зон» у правила плавающих окон заменяется на «расположение задаёт workspaced»; `Super+Shift+N` и меню «На стол N» панели не меняются: перенос окна workspace руками допустим, следующий `raise` соберёт окна обратно (D5). Функция половин `half()` остаётся.

**D16. Проверка и отладка.**
Спайк до реализации (задача 1.2): через `hyprctl eval` и сокет проверить `window.tag` с последующим чтением `tags` в `j/clients`, `window.move`/`window.resize` с точными координатами для плавающего окна по адресу, `hl.exec_cmd` с правилом `tag`, и что `dispatch` через сокет принимает выражение-функцию. Во время разработки демон запускается из терминала `workspaced daemon` с журналом в stdout, события смотрятся `socat` на `.socket2.sock`, состояние — `workspaced status --json`. Панель во время разработки запускается `qs -c panel`.

## Risks / Trade-offs

- [pid окна не совпадает с pid запущенного процесса: программа переисполняет себя или запускается через обёртку-скрипт] → сопоставление по цепочке родителей в `/proc`, окно ждётся до 30 с (neovide с LazyVim стартует 20–26 с); запасной путь — `hl.exec_cmd` с правилом `tag` (D2); список проблемных программ фиксируется в tasks.
- [Приложение с одним экземпляром на все окна (Firefox без `--no-remote`, Telegram) откроет окно в уже работающем процессе, и pid не совпадёт] → в конфиге примеров и в документации указано `--no-remote` и отдельные профили; окно, появившееся у чужого процесса, остаётся посторонним, о чём демон пишет в журнал.
- [Загрузка сессии закрывает окно с несохранёнными данными] → закрытие штатное (`window.close`), приложение показывает свой диалог; перед загрузкой состояние пишется в `default`.
- [Диспетчеры уходят асинхронно, и расстановка обгоняет появление окна] → расстановка окна запущенного приложения выполняется по `openwindow` после сопоставления, а не сразу после запуска; переносы и расстановка уже открытых окон идут одним выражением.
- [Два процесса пишут `config.toml` (демон по команде и пользователь в редакторе)] → демон перечитывает файл перед записью и пишет атомарно; при расхождении с тем, что он читал, команда сохранения отклоняется с сообщением и повторяется после перечтения.
- [`chezmoi status` показывает расхождение после команды сохранения] → это ожидаемо: пользователь забирает изменения `chezmoi re-add`, как с `lazy-lock.json`.
- [Окно панели «выбор сессии» удерживает клавиатуру] → тот же механизм отпускания, что у поля фильтра (D3 quickshell-panel), отпускание при закрытии и по `activewindowv2`.
- [Демон упал между изменением и записью `default`] → задержка записи 500 мс мала, при старте состояние сверяется с живыми окнами по тегам, потеря — не более последнего действия.
- [Цепочки клавиш занимают сочетания `SUPER+W`, `SUPER+A`, `SUPER+S`, `SUPER+TAB`] → `Super+T` и `Super+D` зарезервированы hyprland-binds как не переносимые и не используются; `SUPER+W`, `SUPER+A`, `SUPER+S` сейчас свободны, `SUPER+TAB` свободно (Alt+Tab занят); выбор конкретных сочетаний — в конфиге пользователя, спецификация их не навязывает.

## Migration Plan

1. Спайк API (задача 1.2), затем каркас демона с чтением конфига и `check`.
2. Демон, конфиг и юнит вводятся при работающей панели: без демона панель ведёт себя как раньше, поэтому промежуточные состояния безопасны.
3. `hyprland.lua` получает загрузку привязок с защитой от ошибки: пока демона нет в `PATH`, перезагрузка конфига проходит с записью в журнал.
4. Откат: `systemctl --user disable --now workspaced.service`, убрать блок загрузки привязок из `hyprland.lua`, окна на `special:pool` вернуть `hyprctl eval` переносом на стол; конфиг и сессии можно оставить.
