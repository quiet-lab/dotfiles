## Context

- Прежнее изменение `herdr-prestart` (архив) ставило herdr пакетом AUR
  и обновляло его системным юнитом при загрузке; `herdr update`
  отвергался, потому что бинарник лежал в `/usr/bin`, а замена в обход
  pacman ломает учёт пакета.
- Форк `duty-herdr` выпускается в GitHub Releases `quiet-lab/duty-herdr`
  (манифест `releases/latest/download/latest.json`); бинарник станции —
  `~/.local/bin/herdr`, `herdr --version` печатает
  `herdr 0.9.5 (duty-v0.9.5 …)`. `herdr update` форка берёт манифест
  из Releases форка и проверяет SHA-256.
- Сценарий `herdr-prestart` запускает юнит `herdr-prestart.service`
  в `hyprland-session.target`, то есть после входа; туннели к этому
  времени подняты (спецификация `hyprland-autostart`, «Туннели при
  загрузке системы» и «Вход после туннелей»).
- `PATH` сессии формирует `dot_config/hypr/hyprland.lua`: `~/.local/bin`
  ставится раньше `/usr/bin`, поэтому и без пакета запуск `herdr` по
  `PATH` (`[apps.herdr]` демона workspaced) находит форк; после удаления
  `herdr-bin` в `/usr/bin` второго herdr нет.
- Таймеры и опрос запрещены (`docs/decisions/0007-no-timers.md`).

## Goals / Non-Goals

**Goals:**

- herdr станции — форк из `~/.local/bin`, обновляется без root и без pacman.
- Значки состояния, цвета заголовков spaces и `focused_tab` настроены
  в конфиге herdr.

**Non-Goals:**

- Пакет `duty-herdr-bin` форка: бинарник в `~/.local/bin` ставится и
  обновляется самим herdr.
- Изменение кода форка.

## Decisions

### D1. Условие пересмотра прежнего решения выполнено

Прежнее решение (пакет AUR, пока нет форка) оговаривало: появился форк
со своей установкой в `~/.local/bin` — пакет удаляется, юнит и
`system/herdr-update/` удаляются, обновление переходит в пользовательский
юнит подготовки. Форк выпущен и установлен; все три действия выполняются
этим изменением. Доверие к PKGBUILD AUR уходит вместе с пакетом: бинарник
форка проверяется по SHA-256 из манифеста собственного репозитория.

### D2. Обновление шагом предстарта, не системным юнитом

Шаг `"$herdr" update` стоит в `herdr-prestart` перед установкой
интеграции: хук состояния агента ставится под уже обновлённую версию.
Обновление без root заменяет `~/.local/bin/herdr`; запущенный сервер
работает со старым файлом, новая версия действует со следующего запуска
сервера (так же, как у прежнего пакета). Шаг не ставит `failed=1`:
отсутствие сети или Releases — не ошибка подготовки, herdr стартует
установленной версией; причина идёт в журнал юнита.

### D3. Срок шага — 10 с

Замер: загрузка бинарника форка (32 159 048 байт) с GitHub Releases на
станции — 3,06 с (`curl -o /dev/null -w '%{time_total}'`, один прогон).
Срок вдвое больше замера с округлением в большую сторону — 10 с; при
зависании соединения шаг срезается по сроку (`timeout`). Вместе со сроком
`claude update` (90 с) шаг укладывается в `TimeoutStartSec=120` юнита.
Единичный прогон на станции — единственный замер; на медленной сети шаг
пропускает обновление и повторяется при следующем старте сессии.

### D4. Привязка к amn0 не переносится

Запросы AUR привязывались к `amn0` (`curl --interface amn0`), потому что
соединение, помеченное в туннель, обрывалось на рукопожатии TLS
(`docs/open-questions/amn0-tcp-mss.md`). У `herdr update` выбора
интерфейса нет, а GitHub в набор `zones` не входит и идёт мимо туннеля
через проводное соединение. Привязка не нужна; открытый вопрос
остаётся для сайтов AUR.

### D5. Конфиг herdr

`[ui.status_icons]` — значки шириной в 2 ячейки без U+FE0F (требование
форка); `[ui.sidebar.spaces]` — правила цвета токена `workspace` по
образцу README форка; строки агентов `state_icon/machine/tab`,
`focused_tab`, `agent`. Конфиг проверяется командой
`herdr config check`.

## Risks / Trade-offs

- Шаг обновления при медленной сети пропускается молча для запуска
  (только сообщение в журнале); новая версия появится при следующей сессии.
- Обновление форка не проходит по подписи: проверка — SHA-256 из
  манифеста в том же репозитории.
- Выпуск форка с несовместимым конфигом останавливает herdr на
  разборе; `herdr config check` выполняется перед применением.
