# Design: Все привязки клавиш в конфиге демона workspaced

## Context

Мотивация — в proposal.md («Why»). Что есть сейчас и что ограничивает подход:

- `dot_config/hypr/hyprland.lua`: раздел «Привязки» с вызовами `hl.bind(сочетание, действие, флаги)`, где действие — диспетчер `hl.dsp.*` или функция Lua; три привязки с кодом: половины рабочей области (расчёт по `hl.get_active_monitor()` и полю `reserved`), Alt+Tab (два диспетчера подряд), переключение курсора (`hl.config`). Блок в конце раздела выполняет код от `workspaced keys --lua` через `load` в окружении с `hl` и при ошибке показывает уведомление.
- Демон workspaced (`~/work/pets/workspaced`, спецификации ws-config, ws-daemon после синхронизации 2026-09-15): конфиг разбирается serde, цепочки собираются из `chain` приложений и workspace, `[keys]` и `[[binds]]` с `action`; проверка конфликтов по префиксам; генератор строит дерево подкарт и печатает `hl.bind`, `hl.define_submap`. Демон следит за файлом конфига и после успешного разбора выполняет `hyprctl reload config-only`; при ошибке оставляет прежний конфиг, и Hyprland сохраняет прежние привязки в памяти.
- Диспетчеры Hyprland из демона идут через сокет выражениями Lua, несколько шагов — одной функцией (`dispatch_all`); `j/monitors` отдаёт размер монитора и зарезервированные зоны.
- Сессия Openbox остаётся запасной, её привязки живут в `rc.xml` и в это изменение не входят.

## Goals / Non-Goals

**Goals:**
- Один файл привязок для сессии Hyprland: `config.toml` демона; `hyprland.lua` не содержит `hl.bind`.
- Действия, которые умеет композитор сам (диспетчеры, запуск команд), выполняются им без обращения к демону: задержка нажатия не растёт, повторяющиеся привязки и привязки мыши работают как раньше.
- Сломанный конфиг не оставляет сессию без клавиш.
- Одна команда показывает все привязки и находит конфликты, включая зарезервированные сочетания.

**Non-Goals:**
- Замена механизма привязок Hyprland (swhkd и другие демоны горячих клавиш) — отвергнута в proposal.
- Привязки Openbox и общий файл для двух сессий: действия привязок специфичны для Hyprland.
- Редактирование привязок из панели: файл правится руками.
- Условные привязки по классу окна или по активному workspace, кроме уже существующего выбора приложения по активному workspace.

## Decisions

**D1. Запись `[[binds]]` получает четыре вида действия, ровно одно на запись.**
`action` — существующие действия демона (`desktop`, `workspace`, `app`, именованные `"sessions"`, `"save-workspace"`, `"next-workspace"`) и новое `{ half = "left" }`; `exec` — строка команды, в Lua превращается в `hl.dsp.exec_cmd(cmd)`; `dispatch` — строка или массив строк, каждая — выражение диспетчера без префикса `hl.dsp.` (в Lua `hl.dsp.window.close()`), массив разворачивается в функцию с `hl.dispatch` по порядку, чтобы шаги не обгоняли друг друга; `lua` — тело функции, оборачивается в `function() … end`. Две формы вместо одной унифицированной таблицы `action = { kind = …, … }` выбраны за краткость записи: большинство строк файла — `exec` и `dispatch`, и они должны читаться как таблица привязок Openbox. Действия демона остаются под `action`, чтобы существующие записи не менялись. `lua` оставлен как единственный выход для кода, который не выразить диспетчером (переключение курсора через `hl.config` и `hl.notification`); в файле три такие записи: переключение курсора и обе стороны Alt+Tab (обход окон стола по `stable_id` через `hl.get_windows()`, потому что `cycle_next` идёт по порядку слоёв, который `bring_to_top` меняет, и назад давал переключение между двумя окнами), и они не дают повода делать в конфиге второй язык. Альтернатива «всё через `exec workspaced …`» отвергнута: запуск процесса на каждое нажатие стрелки и на повтор громкости заметен, а привязки мыши через процесс невозможны.

**D2. Флаги привязки и диапазоны.**
`locked`, `repeating`, `mouse`, `release` — булевы поля записи, передаются третьим аргументом `hl.bind` без интерпретации демоном; `mouse` допустим только у одиночного сочетания, потому что удержание кнопки внутри подкарты не имеет смысла и не проверялось. `range = [от, до]` разворачивает запись в серию с подстановкой `$n` в `chain`, `exec` и `dispatch` до разбора цепочки и проверки конфликтов, чтобы Super+1…8 и Super+Shift+1…8 занимали две записи, а не шестнадцать. Знак `$` выбран потому, что в выражениях Lua он невозможен, а подстановка окружения `$ИМЯ` к полям привязок не применяется: команда `exec` уходит композитору как есть, и `~` в ней раскрывает оболочка. Флаги `repeating` и `release` вместе с функцией Lua (массив `dispatch`) проверены спайком 2026-09-16: Hyprland 0.56.2 повторяет вызов функции (первый повтор через 600 мс, затем каждые 44 мс) и вызывает её по отпусканию, ограничений не нужно. Находка 2026-09-16: в заглушках Lua-API (`/usr/share/hypr/stubs/hl.meta.lua`, класс `HL.BindOptions`) нет поля `mouse`, удержание кнопки мыши задаётся полем `drag` (аналог `bindm`), а пример `{ mouse = true }` из `/usr/share/hypr/hyprland.lua` устарел; в конфиге демона флаг остаётся `mouse`, генератор печатает оба ключа `drag = true, mouse = true`, потому что примеры в сети и старые конфиги используют `mouse`, а лишний ключ композитор не считает ошибкой.

**D3. Половины рабочей области переезжают в демон командой `half`.**
Демон уже расставляет окна по прямоугольникам с зазором `gap` и читает `j/monitors`, где есть `reserved` в виде массива из четырёх чисел (left, top, right, bottom), в отличие от недокументированной формы поля в Lua-API, ради которой в `hyprland.lua` разбирались три варианта. Команда `half <сторона>` сужает рабочую область на `gap` с каждой стороны, делит её пополам, вычитает `gap` с каждой стороны половины и отправляет `window.float({ action = "on" })`, `window.resize`, `window.move` одной последовательностью. Правило пользователя: расстояние от края экрана и панели до окна, между окнами и между плитками панели — одно число. В панели это `Theme.margin` и `Theme.gap` по 10 px; у демона `gap = 5` при ячейках, отодвинутых на 5 px от границ рабочей области, даёт те же 10 px; половины повторяют этот приём, поэтому числа сценария «Окно в половину рабочей области» (10,10 и 1905×2140) не меняются. Альтернатива — оставить расчёт в `lua` — отвергнута: это тридцать строк кода в строке TOML и дублирование геометрии, которой владеет демон.

**D4. Копия последнего удачного кода привязок и запасной путь загрузки.**
`workspaced keys --lua` после успешной генерации пишет тот же код в `~/.local/state/workspaced/keys.lua` (атомарно, через временный файл). Блок загрузки в `hyprland.lua` сначала выполняет команду; при пустом выводе или ошибке разбора читает копию, выполняет её и показывает уведомление с причиной; если копии нет, показывает уведомление «привязки не загружены». Без этого ошибка в конфиге на момент старта сессии (демон ещё не проверил файл) или ручной `hyprctl reload` при сломанном файле оставили бы сессию без Super+Return и Super+M. Каталог `~/.local/state/workspaced/` уже используется для сессий. Альтернатива «аварийный минимум привязок прямо в `hyprland.lua`» отвергнута: это второй файл привязок, пусть и из двух строк, а копия покрывает тот же случай полнее.

**D5. Список `reserved` в `[keys]` и проверка одиночных сочетаний.**
Зарезервированные сочетания (карта XKB: `SUPER+space`, `ALT+E`, `ALT+R`; свободные по решению hyprland-binds: `SUPER+T`, `SUPER+D`, `ALT+space`, `ALT+SUPER+space`) перечисляются в конфиге с комментарием. Проверка сравнивает каждое звено каждой цепочки с этим списком после нормализации (модификаторы в верхнем регистре, порядок модификаторов канонический, клавиша как есть) и отклоняет совпадение. Проверка конфликтов по префиксам уже покрывает одиночные сочетания, потому что они — цепочки из одного звена; отдельное правило нужно только для `mouse`. Список живёт в конфиге, а не в коде демона, потому что это решение пользователя о его раскладке, а не свойство демона.

**D6. `keys --list` печатает привязки в порядке файла.**
Для просмотра генерируется таблица «цепочка — действие — источник» из того же набора привязок, что и код Lua; порядок — как в файле (сначала `[keys]`, затем приложения, workspace, `[[binds]]`), чтобы строка вывода находилась в файле поиском по цепочке. Отдельный формат `--json` не нужен: панель привязки не показывает.

**D7. Перенос привязок в конфиг группами с комментариями.**
Записи `[[binds]]` в `config.toml` идут в том же порядке и с теми же комментариями групп, что раздел «Привязки» в `hyprland.lua`: программы, окно, фокус, половины, столы, мышь, блокировка, скриншоты, dunst, мультимедиа, служебные. В `hyprland.lua` остаются переменные `HOME` и `scripts` только если они нужны автозапуску; комментарий о непереносимых сочетаниях переезжает к списку `reserved`. Пути скриптов в `exec` пишутся с `~`, оболочка Hyprland (`exec_cmd` запускает через `/bin/sh`) раскрывает его.

## Risks / Trade-offs

- [Функция Lua в `hl.bind` с флагом `repeating` может не повторяться] → спайк в первой задаче; при отрицательном результате массив `dispatch` с `repeating` отклоняется проверкой, а серия громкости остаётся одиночным `exec`.
- [Ошибка в `lua` записи ломает загрузку всего кода привязок] → генератор оборачивает каждую функцию `lua` в `pcall` с уведомлением; синтаксис проверяется при генерации через `luac -p`, если он доступен, иначе только при загрузке с откатом на копию (D4).
- [Демон недоступен на старте сессии, копии нет: сессия без клавиш] → копия появляется при первом же успешном `keys --lua`, то есть при первом старте после установки; уведомление на экране называет причину, а выход из сессии возможен через lightdm или `hyprctl dispatch exit` из tty.
- [Отступ панели (10 px в `Theme.qml`) и удвоенный `gap` демона (5 px в `config.toml`) заданы в двух файлах и могут разойтись] → комментарий у `gap` в конфиге называет правило и значение панели; задача 4.3 сверяет оба числа.
- [Команда `half` требует работающего демона, в отличие от прежнего расчёта в Lua] → без демона Super+Shift+стрелки не действуют, как и цепочки workspace; демон под systemd перезапускается за 5 с.

## Migration Plan

1. Расширить демон (разбор, проверка, генератор, `half`, `keys --list`, копия), пересобрать, проверить `cargo test` и `workspaced check` на текущем конфиге без новых записей — поведение не меняется.
2. Перенести привязки в `config.toml`, пока `hyprland.lua` ещё содержит свои: `workspaced check` найдёт дубли между двумя источниками только после удаления, поэтому сначала сравнить `keys --list` с таблицей hyprland-binds.
3. Удалить раздел «Привязки» из `hyprland.lua`, добавить запасной путь, `chezmoi apply`, `hyprctl reload`, сверить `hyprctl binds` с ожидаемым числом привязок.
4. Откат: `git checkout` двух файлов и `hyprctl reload`; демон прежней версии игнорирует неизвестные ключи с предупреждением, поэтому старый бинарник с новым конфигом привязки не сгенерирует, но и не упадёт.
