## MODIFIED Requirements

### Requirement: Фокус кликом и рамка активного окна
Фокус окна MUST переходить только по клику в области окна: наведение курсора фокус не переводит, в том числе при переходе между плавающими окнами. Курсор MUST NOT переноситься к окну при смене фокуса диспетчером (активация из плитки стола, Alt+Tab). Рамка окна MUST быть шириной 1 px, как рамка плиток панели; рамка активного окна MUST быть цвета рамки плиток панели (yellow Tokyo Night `#E0AF68`), рамка неактивного окна — тёмно-зелёной `#2D6A4F`. Слои с клавиатурой по требованию (поле фильтра панели) MUST NOT удерживать клавиатуру при клике по окну (`misc.layers_hog_keyboard_focus` выключен). Запрос активации от приложения (xdg-activation: клик по уведомлению Telegram в панели Quickshell, открытие ссылки из другой программы) MUST переводить фокус на окно приложения и переходить на его стол (`misc.focus_on_activate` включён); левый клик по уведомлению панели MUST выполнять действие уведомления по умолчанию и закрывать его.

#### Scenario: Наведение не меняет фокус
- **WHEN** в фокусе терминал, а курсор проходит над окном браузера без клика
- **THEN** фокус клавиатуры остаётся у терминала, браузер не поднимается над ним

#### Scenario: Активация из панели без переноса курсора
- **WHEN** пользователь кликает по иконке окна в плитке стола
- **THEN** окно получает фокус и поднимается наверх, а курсор остаётся на панели

#### Scenario: Клик по уведомлению
- **WHEN** окно Telegram на столе 3, пользователь на столе 1 кликает левой кнопкой по уведомлению Telegram
- **THEN** уведомление закрывается, композитор переходит на стол 3, окно Telegram получает фокус и поднимается наверх

#### Scenario: Цвет рамки
- **WHEN** окно в фокусе
- **THEN** его рамка жёлтая `#E0AF68` шириной 1 px, как рамки плиток панели; `hyprctl getoption general:border_size` показывает 1, а рамки окон без фокуса тёмно-зелёные `#2D6A4F`

### Requirement: Привлечение внимания без действия пользователя

Программа сессии MUST NOT поднимать своё окно, забирать фокус клавиатуры
и переключать стол, пока пользователь ничего не сделал: привлечение внимания
к окну (вызов `QWindow::alert`, который QtWayland превращает в запрос
xdg-activation) MUST оставаться без последствий для фокуса и стола. Для
Telegram Desktop это обеспечивает его собственная настройка «Draw attention
to the window» в разделе «Уведомления и звуки», которая MUST быть
выключена. Настройка `misc.focus_on_activate` MUST оставаться общей
и включённой, а правило окна `focus_on_activate` и правило `suppress_event`
для окна Telegram MUST NOT задаваться: композитор проверяет токен активации
только на существование и не отличает запрос по входящему сообщению
от запроса по клику по уведомлению, поэтому правило окна отняло бы и переход
к окну по клику. Настройка Telegram лежит вне источника chezmoi
и MUST быть описана в `docs/host-state.md`.

#### Scenario: Сообщение приходит, пока пользователь на другом столе

- **WHEN** окно Telegram на столе 2, пользователь работает на столе 1
  и в чате приходит сообщение
- **THEN** панель показывает уведомление, активным остаётся стол 1, фокус
  остаётся у окна на столе 1, а в событиях композитора нет ни `urgent`,
  ни `activewindow` с классом `org.telegram.desktop`, ни перехода
  на стол 2

#### Scenario: Переход по клику по уведомлению сохраняется

- **WHEN** пользователь на столе 1 кликает левой кнопкой по уведомлению
  Telegram
- **THEN** композитор переходит на стол окна Telegram, окно получает фокус
  и поднимается наверх, а в окне открыт топик того сообщения, о котором
  было уведомление

#### Scenario: Ссылка из другой программы активирует браузер

- **WHEN** пользователь открывает ссылку из программы на другом столе
- **THEN** окно браузера получает фокус, композитор переходит на его стол
