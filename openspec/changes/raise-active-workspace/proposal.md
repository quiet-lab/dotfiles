# Proposal: Поднятие workspace, уже активного на другом столе, переходит на тот стол

## Why

По цепочке workspace демон поднимал его на текущем столе, даже если workspace уже был активен на другом: окна переезжали за пользователем, а прежний стол пустел. Пользователь ожидает обратного: цепочка ведёт к workspace туда, где он уже поднят, и переносит его только тогда, когда он нигде не активен.

## What Changes

- Цепочка workspace, команда `raise` без `--desktop`, цепочка приложения и `next` MUST сначала проверить, активен ли workspace на каком-либо столе. Если активен на другом столе, демон MUST перейти на тот стол и отдать фокус главному окну, не перенося окна. Если нигде не активен, workspace поднимается на текущем столе, как раньше.
- Явный стол (`--desktop N`, запись `[[binds]]` со столом, восстановление сессии) по-прежнему переносит workspace: это осознанная миграция.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `ws-daemon`: требование «Поднятие workspace на столе» — выбор стола без явного указания.

## Impact

- Проект `~/work/pets/workspaced`: `daemon.rs` (`raise`: стол по умолчанию — тот, где workspace активен; путь цепочки приложения по списку текущего стола).
- Спецификация ws-daemon; AGENTS.md.
