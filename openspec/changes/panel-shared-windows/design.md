# Design: Общие окна в плитках панели

## Context

Мотивация — в `proposal.md`, замысел целиком и место шага в серии —
в [`docs/window-model.md`](../../../docs/window-model.md): раздел 2.5
(принадлежность окон, следование за столом), раздел 2.6 (панель), раздел 3
(таблица qs-workspaces), раздел 4 (предложение о клике по значку общего
окна, принятое 22.09.2026), раздел 5, шаг 6. Решения прежних изменений
действуют и здесь: [`shared-windows`](../shared-windows/design.md) — состав
тегами `ws:<имя>` (D1), правило размещения из четырёх шагов (D4), следование
по событию смены стола (D5), состав для панели по тегам (D11), на столе
активен ровно один workspace (D13);
[`ws-tile-order`](../archive/2026-09-23-ws-tile-order/) — порядок
workspace в плитке и скрытие окон неактивных workspace;
[`ws-tile-tabs`](../archive/2026-09-23-ws-tile-tabs/) — плитка активного стола
двойной высоты с табами.

Что было до шага.

Демон (коммит `e772598`, шаги 4 и 5 выполнены, не заархивированы),
`state_json` в `src/daemon.rs`: для каждого стола 1…8 — список workspace
по порядку и активный; у workspace — `name`, `icon`, `active`, `apps`
(имена записей раздела конфига) и `windows` — адреса окон по тегам состава
(`ws_windows`), в порядке `hyprctl clients -j`, где бы окно ни стояло:
на столе, на другом столе, на `special:pool` или на `special:hidden`.
Общее окно стоит в `windows` каждого своего workspace. Состояние рассылается
после команд и по событиям композитора (`openwindow`, `closewindow`,
`movewindow`, смена стола — после следования). Поля «где стоит окно»
в состоянии нет, но оно и не нужно: панель знает положение каждого окна
от композитора. `workspaced status --json` дополнительно отдаёт у окна поле
`workspaces`, но в поток подписки оно не входит.

Панель, `tiles/Workspaces.qml`:

- `rebuild` раскладывает окна `Hyprland.toplevels` по столам (`byWs`): окно
  на обычном столе — в его стол, окно на `special:hidden` — в стол
  происхождения (`origins`), окна на прочих специальных столах
  (`special:pool`) отбрасываются.
- `itemsFor(wins, wsList, withWs)` строит ряд плитки только из окон
  `byWs[стол]`: сначала значки workspace (у неактивного стола), затем окна
  этого стола, входящие в `windows` активного workspace, затем прочие окна
  стола, кроме входящих в `windows` неактивных workspace этого стола.
  Поэтому общее окно, стоящее на столе 2, в плитке стола 1 не видно,
  хотя в состав активного там `work` оно входит.
- `activate` фокусирует окно диспетчером `hl.dsp.focus({ window })`;
  композитор переходит на стол, где окно стоит. Окно в фокусе по повторному
  клику скрывается.
- Wsd.qml хранит `desktops` и `currentDesktop` из состояния демона
  и переподключается по событиям файловой системы, без таймеров.
- IPC у плиток столов нет; есть только у уведомлений (`notifications`).

## Goals / Non-Goals

**Goals:**

- Ряд окон плитки совпадает с составом активного workspace стола по данным
  демона.
- Общее окно видно в плитках обоих столов, и клик по нему в плитке стола,
  где его сейчас нет, приводит пользователя к окну на этом столе.
- Окна вне состава workspace (диалоги из `ignore_classes`, окна стола без
  активного workspace) остаются видны, как раньше.
- Ряд плитки и клик проверяются командами, без мыши.

**Non-Goals:**

- Изменения демона и его состояния для панели.
- Сохранение состава в снимке сессии (шаг 7).
- Изменение раскладки плиток и табов.

## Decisions

**D1. Источник ряда окон — список `windows` активного workspace стола.**
Ряд окон плитки стола `N` строится из адресов `windows` workspace, активного
на `N` в состоянии демона, в порядке окон композитора
(`Hyprland.toplevels`). Где окно стоит, для состава значения не имеет:
значок показывается и тогда, когда окно на другом столе, на `special:hidden`
или (на время следования) на `special:pool`. Окна неактивных workspace
не показываются нигде, в том числе в плитке стола, где они числятся
(решение пользователя 23.09.2026, изменение `ws-tile-order`). Сведения
об окне — класс, заголовок, значок, признак скрытости — панель берёт
у композитора по адресу; адрес, которого у композитора нет (окно только что
закрыто, а состояние демона ещё не пришло), пропускается.

Рассмотренные варианты:

- *Показывать окна каждого workspace, числящегося на столе.* Отвергнут:
  противоречит решению пользователя от 23.09.2026 — значки окон только
  у активного workspace; к тому же плитка неактивного стола и так делит
  10 мест между значками workspace и окон.
- *Оставить ряд по расположению окон и добавлять к нему общие окна
  с других столов.* Отвергнут: это два источника правды вместо одного,
  а окно, отставшее при следовании, на мгновение выпадало бы из плитки
  стола, на котором пользователь уже находится.
- *Брать состав из поля `workspaces` у окна.* Отвергнут: поле есть только
  в ответе `workspaced status --json`, а в поток подписки не входит;
  списки `windows` у workspace несут те же сведения.

Состав workspace, которого нет ни в одном списке столов (убран командой
`remove`), в состояние не попадает; такие окна по правилу размещения стоят
на `special:pool` и не видны, как раньше.

**D2. Свободные окна показываются по расположению, после окон workspace.**
Документ (раздел 3, строка «Иконки workspace в плитке стола») говорил, что
ряд «свободных окон стола» исчезает вместе с понятием свободного окна. Это
не так: после шага 3 свободными остаются окна стола без активного
workspace, окна классов из `ignore_classes` (порталы выбора файла, запрос
пароля), диалоги по `dialog_title` и окна без командной строки (требование
ws-daemon «Посторонние окна»). Если их не показывать, портал выбора файла
или окно на столе без workspace пропадёт из панели совсем. Поэтому окно,
чей адрес не входит в `windows` ни одного workspace ни одного стола,
считается свободным и показывается, как раньше: в плитке стола, где стоит,
а скрытое — в плитке стола происхождения; в ряду оно идёт после окон
активного workspace. Окно, входящее только в неактивные workspace, свободным
не считается и не показывается, как сейчас.

Отвергнуто: убрать ряд свободных окон по букве документа — пропадают
диалоги и окна столов без workspace, которые демон намеренно оставляет
свободными. Расхождение с документом исправлено в документе
(задача 5.3).

**D3. Значок окна, стоящего на другом столе, — тот же, без приглушения.**
Общее окно в плитке стола, где его сейчас нет, показывается тем же значком
и с той же непрозрачностью, что и окно, стоящее на столе. По правилу
размещения (D4 шага 4) при переходе на этот стол окно придёт туда само,
то есть для пользователя оно на этом столе есть. Приглушённый значок
в панели уже означает «окно скрыто» (`special:hidden`): такое окно
по переходу на стол не появится, пока его не вернут кликом. Скрытое общее
окно приглушено во всех плитках, где показано. Где окно стоит сейчас,
сообщает подсказка при наведении (D6).

Рассмотренные варианты:

- *Приглушать, как скрытое окно.* Отвергнут: смешивает два разных
  состояния — «окно придёт само» и «окно убрано пользователем»; повторный
  клик по приглушённому значку возвращает скрытое окно, а у общего окна
  клик значит другое (D4).
- *Отдельная метка на значке (точка, рамка).* Отвергнут на этом шаге:
  в значок 20×20 при ряде 24 px метку заметного размера не вписать без
  правки раскладки, а сведения о положении окна даёт подсказка. Если
  понадобится, метку можно добавить, не трогая остального.

В плитке стола, на котором сейчас композитор, окна активного workspace
по правилу размещения стоят на этом столе, поэтому «окно на другом
столе» встречается только в плитках других столов и на время следования.

**D4. Клик по значку окна, которого на столе плитки нет, — переход на стол
и фокус после прихода окна.** Принятое предложение
(`docs/window-model.md`, раздел 4): клик «переводит на тот стол, поднимает
тот workspace и даёт окну фокус». Workspace поднимать не нужно: значки окон
показываются только у активного workspace стола (D1), он уже поднят.
Порядок действий:

1. панель запоминает ожидание фокуса: адрес окна и стол плитки;
2. переводит композитор на стол плитки диспетчером
   `hl.dsp.focus({ workspace = N })`;
3. демон по событию смены стола переносит окно на этот стол и ставит его
   в состояние, запомненное для активного там workspace (следование,
   решение D5 шага 4);
4. по событию композитора `movewindowv2` панель видит, что окно стоит
   на столе ожидания, и выполняет обычную активацию — фокус и подъём
   наверх — одним запросом (`chain`), после чего ожидание снимается.

Ожидание снимается и без фокуса: когда окно закрыто, когда композитор
перешёл на другой стол, чем стол ожидания, при новом клике по значку
и при потере связи с демоном (без демона окно не придёт). Если окно уже
стоит на столе плитки к моменту события о смене стола, фокус передаётся
сразу. Таймеров нет: ожидание кончается только событием.

Значок считается «на другом столе», если окно не скрыто и стоит не на столе
плитки (на другом столе или на `special:pool`). Для такого значка проверка
повторного клика (окно в фокусе — скрыть) не выполняется: окно в фокусе
на столе пользователя, показанное в плитке другого стола, по клику должно
уйти туда вместе с пользователем, а не скрыться. Скрытое окно по клику,
как и раньше, переносится на стол плитки и получает фокус; для общего
окна это совпадает с правилом размещения, потому что активный на столе
плитки workspace его содержит.

Рассмотренные варианты:

- *Фокус окна сразу вместе с переходом на стол одним запросом.* Отвергнут:
  `hl.dsp.focus({ window })` переводит композитор на стол, где окно стоит
  в этот момент, — то есть обратно на прежний стол, пока демон не перенёс
  окно; событие смены стола демон обрабатывает после запроса панели.
- *Новая команда демона «перейти к окну на столе N»* (переключение стола
  через демон, перенос окна, фокус одной последовательностью). Отвергнут
  на этом шаге: следование по событию смены стола уже переносит окно
  (решение D5 шага 4 откладывает переключение столов через демон до
  заметного запаздывания), а вторая точка входа дублировала бы правило
  размещения. Если запаздывание окажется заметным, команда вводится тогда
  вместе с переключением столов по клавишам.
- *Панель сама переносит окно на стол плитки и затем переходит туда.*
  Отвергнут: окно уже стояло бы на столе к событию смены стола, демон
  не счёл бы его пришедшим и не поставил бы в прямоугольник или ячейку,
  запомненные для этого workspace; панель взяла бы на себя правило
  размещения.

Пункты контекстного меню остаются прежними: «Показать» действует как левый
клик, «На стол N» переносит окно, где бы оно ни стояло, и перечисляет все
столы, кроме того, где окно стоит (для скрытого — кроме стола плитки).

**D5. Скрытое окно из состава workspace показывается по составу.**
Требование «Отображение скрытых окон» показывает скрытое окно в плитке
стола происхождения. Для окна активного workspace это обычно тот же стол,
но у общего окна столов два, а окно workspace, ставшего неактивным после
скрытия окна, по D1 не показывается вовсе. Поэтому правило разделяется:
скрытое окно из состава активного workspace показывается приглушённым
в плитках столов, где активен его workspace; правило стола происхождения
действует для свободных окон (D2). Клик по приглушённому значку возвращает
окно на стол своей плитки. Документ относил «Отображение скрытых окон»
к неизменным требованиям; уточнение не меняет сценариев требования,
а добавляет случай общего окна.

Отвергнуто: показывать скрытое окно только в плитке стола происхождения —
общее окно, скрытое на столе 2, пропадало бы из плитки стола 1, в чей
workspace оно входит, то есть вернулась бы та самая ошибка, которую шаг
исправляет.

**D6. Подсказка у значка окна называет его workspace и стол, где оно
стоит.** К строкам подсказки (название, заголовок, класс, стол, признак
скрытости) добавляется строка со списком workspace, в которые окно входит
по состоянию демона (например, «workspace: surf, work»), а строка стола
называет стол, где окно стоит, с пометкой, если это не стол плитки
(«Стол 2, придёт при переходе»). Список workspace собирается по спискам
`windows` всех workspace всех столов. Свободное окно строки workspace
не получает.

**D7. Сворачивание неактивных workspace в плитке неактивного стола.**
Документ (раздел 3, строка «Ограничение числа иконок») требует на шаге 6
сворачивать неактивные workspace до одного значка при нехватке места
в плитках неактивных столов: общие окна добавляют значки в плитки столов,
где их раньше не было. Правило: если в плитке неактивного стола значков
workspace и окон вместе больше 10, а неактивных workspace два и больше,
значки неактивных workspace заменяются одной кнопкой 24×24 с числом
свёрнутых workspace («+2») жёлтым цветом, как метка переполнения табов.
Порядок ряда при сворачивании: значок активного workspace, кнопка
свёрнутых, окна. Левый и правый клик по кнопке открывают меню с пунктом
«Поднять <имя>» для каждого свёрнутого workspace; наведение показывает
подсказку со списком их имён. Кнопка считается одним значком ряда; если
значков и после сворачивания больше 10, показываются первые 10 и прежняя
метка «+N» серым. У одного неактивного workspace сворачивание места
не освобождает и не выполняется. Плитка активного стола не меняется: там
workspace стоят табами со своей меткой «+N».

Позиция значка активного workspace при сворачивании может отличаться от
его позиции в списке: требование «позиции workspace не меняются при
переключении» действует для ряда без сворачивания, а свёрнутый ряд
по построению показывает один workspace. Это принято: сворачивание
наступает только при переполнении плитки.

Рассмотренные варианты:

- *Не сворачивать, обходиться меткой «+N».* Отвергнут: при переполнении
  метка отрезает окна в конце ряда, а значки неактивных workspace, которые
  нужны реже, занимают начало ряда.
- *Сворачивать и активный workspace.* Отвергнут: значок активного
  workspace — единственный признак того, какой workspace на столе поднят.

**D8. Модель ряда — одна функция по адресам, пересчёт по событиям.**
`rebuild` помимо `byWs` строит `byAddr` — запись окна по нормализованному
адресу (без `0x`, в нижнем регистре), с полем `at` (стол, где окно стоит;
пусто для специальных столов, кроме скрытого) — и список всех окон
в порядке композитора. По состоянию демона (`Wsd.desktops`) строятся
`members` — адрес окна → список его workspace. `itemsFor(tile, wsList,
withWs)` собирает ряд: значки workspace (со сворачиванием по D7), окна
активного workspace в порядке композитора с полями `ws` (стол плитки),
`at`, `away`, `workspaces`, затем свободные окна `byWs[tile]`. Ряд
пересчитывается привязкой свойств при изменении `byWs`, `byAddr`
и `Wsd.desktops`: и события композитора, и новое состояние демона
перерисовывают плитки сразу, без опроса. Ожидание фокуса (D4) проверяется
в `rebuild`, который вызывается на `movewindowv2`, `workspacev2`
и `closewindow`.

**D9. IPC для проверки рядов.** Панель заводит обработчик IPC с целью
`workspaces`: `row(desktop)` возвращает ряд плитки строкой JSON (вид
элемента, имя workspace или адрес окна, признаки `active`, `hidden`, `away`,
число свёрнутых и значение метки «+N»), `activate(desktop, address)`
выполняет левый клик по значку окна в этой плитке. Так агент проверяет
состав рядов и переход к общему окну командами
`qs -c panel ipc call workspaces …`, а пользователю остаётся проверка
вида и кликов мышью. Отвергнуто: проверять только журналом и снимками
экрана — состав ряда из журнала не восстановить, а снимки экрана пользователь
просил не делать.

**D10. Демон не меняется.** Шаг 6 документа относил к себе ws-daemon
«Состояние для панели», а раздел 3 документа говорил, что шаг 6 меняет
требования панели, а не демона. Проверка кода подтверждает второе:
состав по тегам в состоянии уже есть (решение D11 шага 4), положение окна
панель знает от композитора, а рассылка состояния идёт по тем же событиям,
по которым меняется состав. Требование ws-daemon не меняется, дельты
ws-daemon нет.

Отвергнуто: добавить в состояние у workspace стол, где стоит каждое окно,
или поле `workspaces` у окна — это дублирует сведения композитора, и они
могли бы расходиться с ним на время между событием и рассылкой.

**D11. Переподключение и события — без изменений.** Без демона
(`Wsd.desktops` пуст) все окна свободны, и плитки показывают окна
по расположению, как требует спецификация. Разрыв соединения очищает
состояние и снимает ожидание фокуса (D4); переподключение по событиям
файловой системы остаётся прежним (Wsd.qml не меняется). Таймеров
и опроса шаг не добавляет
([`docs/decisions/0007-no-timers.md`](../../../docs/decisions/0007-no-timers.md)).

**D12. Уточнения при реализации (23.09.2026).** Поведение дельты
не меняют, дополняют решения D4, D8 и D9 подробностями.

- Поле `at` записи окна: номер стола, где окно стоит; для скрытого окна —
  `special:hidden`, для прочих специальных столов (`special:pool`) — пустая
  строка. Признак `away` — «не скрыто и `at` не совпадает со столом плитки»,
  поэтому окно на `special:pool` в плитке своего стола тоже считается
  стоящим не на столе и по клику ждёт прихода.
- Ожидание фокуса (D4) выполняется, когда окно стоит на столе ожидания;
  какой стол сейчас у композитора, отдельно не проверяется: переход
  на другой стол ожидание уже снял. Номер стола в `workspacev2` берётся
  из данных события («id,имя»), а не из `Hyprland.focusedWorkspace`, который
  к моменту обработки события может быть ещё прежним. Сразу после перехода
  `activate` проверяет ожидание ещё раз: окно могло прийти раньше.
- IPC (D9): `row` возвращает массив JSON; элемент `ws` — `name`, `active`;
  `fold` — `count` и `names`; `win` — `address` (с префиксом `0x`), `class`,
  `hidden`, `away`, `at`, `workspaces`; метка «+N» — последний элемент
  `{ kind: "more", count }`. `activate` ищет окно во всём ряду плитки,
  а не только среди первых десяти показанных иконок: команда нужна для
  проверок, и окно за меткой «+N» тоже можно выбрать.
- Список workspace окна в подсказке (D6) упорядочен по имени.

## Risks / Trade-offs

- [Окно по клику приходит на стол с запаздыванием на время обработки
  события демоном, и фокус передаётся позже перехода] → ожидание
  кончается событием о переносе; если запаздывание заметно, вводится
  переключение столов через демон (D5 шага 4).
- [Демон решил не переносить окно (например, оно стало скрытым между
  кликом и переходом), и ожидание фокуса остаётся] → ожидание снимается
  первым же переходом на другой стол или новым кликом; окно, пришедшее
  на этот стол позже по другой причине, получит фокус, пока пользователь
  на столе, — это совпадает с намерением клика.
- [Между событием композитора об открытии окна и состоянием демона с новым
  составом окно на мгновение показывается свободным, в конце ряда] →
  рассылка приходит не позже чем через 50 мс (ws-daemon, «Состояние для
  панели»), значок переходит на своё место в ряду.
- [Свёрнутый ряд меняет позицию значка активного workspace] → принято
  (D7), сворачивание наступает только при переполнении.
