## Why

Окно, открытое в workspace по ходу работы, заводит там запись
дополнительного приложения сессии, и эта запись переживает закрытие окна:
по спецификации ws-sessions («Дополнительные приложения сессии») её снимает
только команда отделения. Запись без окон при поднятии workspace получает
в общее пользование окна других workspace. 28.09.2026 так запись давно
закрытого окна wezterm в `surf` при поднятии `surf` забрала по семейству
общее окно herdr из `work`. Пользователь 29.09.2026 решил, что окно,
открытое по ходу работы, входит в workspace только пока открыто, а записей
без окон, забирающих чужие окна, быть не должно.

## What Changes

- Запись дополнительного приложения сессии снимается, когда в её workspace
  закрыто последнее окно приложения, а не только по команде отделения. Если
  окон приложения не осталось нигде, запись с командой запуска снимается во
  всех workspace, как при отделении.
- Без окон живёт только запись из снимка сессии, окно которой ещё не
  появилось: она ждёт своего окна, закрытие других окон её не снимает,
  а снимок переносит её как есть. С появлением окна запись подчиняется
  общему правилу.
- Общие окна остаются общими независимо от того, как запущены: запись
  сессии, как и приложение конфига, получает при поднятии общее окно своего
  приложения, а окна варианта по семейству (herdr для записи `wezterm`) —
  нет. Окно, общее при сохранении сессии, возвращается одним окном во все
  свои workspace.
- Восстановление сессии сначала поднимает workspace по конфигу, затем
  запускает окна из снимка, которых в конфиге нет. Такое окно входит
  в workspace как окно, открытое по ходу работы.
- Запись workspace в конфиг (Ctrl+Super+W) пишет только записи сессии,
  у которых в workspace есть окна; запись без окон остаётся в сессии.
- Сохранение сессии (Ctrl+Super+S дважды) по-прежнему не меняет конфиг
  и запоминает окна, которых в конфигурации workspace нет, с командной
  строкой, каталогом и прямоугольником; после этого изменения в снимок
  попадают только записи с окнами и записи, ещё ждущие окна.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ws-sessions`: «Восстановление при старте» (порядок: сначала конфиг, затем
  окна сессии; ожидающая запись не забирает окон варианта, общее окно возвращается одним окном), «Дополнительные
  приложения сессии» (запись живёт, пока открыто окно; ожидание записи из
  снимка).
- `ws-daemon`: «Захват открытых окон приложения» (запись сессии получает
  общее окно своего приложения, но не окна вариантов по семейству).
- `ws-config`: «Запись по команде сохранения» (записи сессии без окон
  в конфиг не пишутся).

## Порядок архивации

Требования «Восстановление при старте» и «Дополнительные приложения
сессии» (ws-sessions) и «Запись по команде сохранения» (ws-config) взяты
из дельт изменения `live-layout`, «Захват открытых окон приложения»
(ws-daemon) — из дельты `work-area-center`. Дельты написаны против
редакции, которая действует после архивации всех активных изменений:
`session-instances`, `live-layout`, `work-area-center`,
`askpass-only-quickshell`, `sticky-chains`, `chains-sticky`. Поэтому это
изменение архивируется последним — после `chains-sticky`.

## Impact

- Демон `~/work/pets/workspaced`: `state.rs` (ожидание записей из снимка),
  `daemon.rs` (снятие записи при закрытии окна, сверка ожиданий после
  каждого сообщения, запрет окон вариантов для записей сессии, порядок
  запуска при поднятии), `session.rs` (записи снимка ждут окон),
  `save.rs` (запись workspace без записей, у которых нет окон).
- Формат снимка `default.toml` и конфиг `dot_config/workspaced/config.toml`
  не меняются.
- Документация: `AGENTS.md` (раздел «Сессия Hyprland»),
  `docs/window-model.md` (разделы 2.5, 2.7).
