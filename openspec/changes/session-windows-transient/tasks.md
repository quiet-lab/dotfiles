## 3. Проверка вживую

- [ ] 3.1 Перезапуск службы новым бинарником (основная сессия): `systemctl --user restart workspaced.service`. Проверка: `systemctl --user is-active workspaced` — active; `workspaced status --json` показывает прежние окна и составы; в журнале нет ошибок чтения снимка.
- [ ] 3.2 Закрытие окна снимает запись (агент): на столе с активным workspace открыть окно приложения, которого нет в конфиге (например, `galculator` или `alacritty`), убедиться по журналу, что оно принято дополнительным приложением сессии, закрыть его диспетчером `hyprctl eval 'hl.dispatch(hl.dsp.window.close({ window = "address:<адрес>" }))'`. Проверка: в журнале строка «запись сессии … снята», `workspaced save-session` пишет `default.toml` без этой записи.
- [ ] 3.3 Запись без окон не забирает окно варианта (агент): в `surf` открыть обычное окно wezterm, закрыть его, поднять `surf`. Проверка: окно herdr не получает тега `ws:surf` (`hyprctl clients -j`), записи `wezterm` у `surf` нет.
- [ ] 3.4 Порядок восстановления после перезагрузки (пользователь: нужна перезагрузка): открыть в `surf` окно вне конфига (Telegram или калькулятор), нажать Ctrl+Super+S дважды, перезагрузиться. Проверка: при переходе на стол 2 сначала появляются окна браузеров `surf`, затем окно сессии в своём прямоугольнике; herdr и Chrome AI из `work` в `surf` не переходят. Агент после перезагрузки сверяет журнал (порядок строк запуска) и `hyprctl clients -j`.
- [ ] 3.5 Запись workspace (агент, с копией конфига): при ожидающей записи из снимка вызвать `workspaced save-workspace`. Проверка: запись без окна в `config.toml` не попала, `workspaced status --json` её сохраняет; конфиг возвращается из копии.
