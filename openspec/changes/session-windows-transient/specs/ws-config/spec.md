## MODIFIED Requirements

### Requirement: Запись по команде сохранения
По цепочке `save_workspace` или команде `workspaced save-workspace` демон MUST снять раскладку активного workspace текущего стола с экрана (спецификация ws-daemon, «Расстановка окон») и записать в его раздел: места приложений (`apps`) по раскладке в памяти, `main` — главное приложение, дополнительные приложения сессии этого workspace и свободные окна, открытые на текущем столе. Место приложения MUST записываться именем ячейки шаблона workspace, если прямоугольник места с ней совпадает — сначала проверяется исходная ячейка места, затем ячейки шаблона по порядку, — а иначе `rect`. Раскладку в памяти демон MUST NOT записывать в файл никакой другой командой. Окна workspace MUST определяться по тегам состава (спецификация ws-daemon, «Состав workspace»), а не по описанию приложений: окно, убранное из workspace командой отделения, MUST NOT давать места своему приложению, а общее окно, входящее и в другие workspace, MUST записываться наравне с остальными — приложение под своим именем, с местом из раскладки этого workspace: общее окно, ушедшее за пользователем на другой стол, MUST давать место, снятое, когда оно стояло на столе этого workspace, а не нынешнее положение. Записи того же приложения в разделах других workspace команда MUST NOT менять: после записи приложение описано в нескольких разделах, и окно остаётся общим и после перезапуска демона. Для свободного окна и для дополнительного приложения сессии демон MUST сначала найти среди всех приложений конфига то, которому окно подходит по выражениям `class` и, если оно задано, `title`: поиск MUST идти сначала по приложениям-вариантам, затем по семействам, внутри каждой группы по именам, и найденное приложение MUST быть записано под своим именем с `rect`; новое приложение MUST заводиться только тогда, когда подходящего не нашлось, — с `cmd`, `args`, `cwd` из процесса окна (по правилу требования «Файлы сессий» спецификации ws-sessions, по которому окно из песочницы flatpak записывается командой `flatpak run`) и `rect`. Окно, которое в workspace не принимается (класс из `ignore_classes`, заголовок под `dialog_title` его приложения), демон MUST NOT записывать: в конфиге ему не место, как и в составе workspace. Дополнительные приложения сессии и записи о месте MUST записываться, только если в workspace есть их окна: запись сессии без окон — запись из снимка, окно которой ещё не появилось (спецификация ws-sessions, «Дополнительные приложения сессии»), — MUST NOT попадать в файл ни в `[apps]`, ни в таблицу `apps` раздела, ни полем `main` и MUST оставаться в сессии. Записанные дополнительные приложения сессии MUST после записи быть сняты: они перешли в конфиг. Если у приложения несколько окон, в `rect` MUST записываться место первого экземпляра, а остальные его окна MUST NOT попадать в файл отдельными записями. Записанное окно MUST получить тег экземпляра этого приложения и тег состава этого workspace и перестать быть свободным, а раскладка workspace MUST быть собрана заново из записанного конфига без перезапуска демона (требование «Слежение за конфигом»): изменённые прямоугольники мест становятся местами из описания. Свободные окна на других столах и окна на `special:hidden` MUST NOT записываться. Таблицу `apps` раздела команда MUST править на месте, а не собирать заново: у записи приложения MUST меняться только место (имя ячейки или `rect`), поля `chain` и `mode` записи, порядок записей и комментарии внутри таблицы MUST сохраняться; запись без переопределений — строка или таблица `{ rect = … }` без других полей — MUST записываться строкой, если новое место записывается ячейкой, и таблицей `{ rect = … }` иначе; запись-таблица с полями `chain`, `mode` MUST сохранять свою форму и менять только поле места (`cell` или `rect`) на прежней позиции. Записи, которых в файле не было (дополнительные приложения сессии, свободные окна стола), MUST добавляться в конец таблицы в порядке раздела эффективного конфига. Остальные разделы и workspace, комментарии и порядок ключей MUST сохраняться. Запись MUST быть атомарной; перед записью файл MUST быть перечитан, и если он изменился с момента последнего чтения, команда MUST быть отклонена с сообщением, а конфиг перечитан. После удачной записи команда MUST NOT перечитывать конфиг сама: перечитывание приходит событием завершённой записи файла, одно на одно сохранение. Без команды сохранения демон MUST NOT изменять файл.

#### Scenario: Сохранение после обмена ячеек
- **WHEN** в workspace `dev-front` терминал переведён в главную ячейку цепочкой приложения и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` `main = "terminal-front"`, назначения `apps` соответствуют экрану, комментарии в файле на месте, остальные workspace не изменились

#### Scenario: Сохранение приложения с двумя окнами
- **WHEN** в workspace `work` у `chromium` два окна: первый экземпляр сдвинут пользователем, второй стоит в ячейке `left`, и вызвана команда сохранения
- **THEN** у `chromium` записан `rect` первого экземпляра, второй записи о `chromium` в файле нет, и следующее поднятие `work` ставит оба окна в этот прямоугольник

#### Scenario: Сохранение постороннего окна
- **WHEN** на столе с активным `dev-front` из лаунчера открыт калькулятор, не описанный в конфиге, он принят дополнительным приложением сессии, перемещён пользователем, и вызвана команда сохранения workspace
- **THEN** в конфиге у `dev-front` появляется приложение с `cmd` калькулятора и `rect` его текущего положения, окно несёт тег этого приложения, а следующий `raise` `dev-front` ставит калькулятор на это место

#### Scenario: Дополнительные приложения сессии переходят в конфиг
- **WHEN** в `work` приняты калькулятор и окно `chrome-ai`, затем вызвана цепочка `save_workspace`
- **THEN** в конфиге у `work` записаны оба приложения, в `[apps]` появилось описание калькулятора, дополнительных приложений сессии у `work` больше нет, и следующая запись снимка сессии их не содержит

#### Scenario: Диалог в конфиг не попадает
- **WHEN** на столе с активным `surf` открыт диалог выбора файла класса `termfilechooser`, перечисленного в `ignore_classes`, и вызвана команда сохранения workspace
- **THEN** диалог в конфиг не записан, приложения по его классу в `[apps]` не появилось, окно осталось свободным

#### Scenario: Окно подходит приложению другого workspace
- **WHEN** на столе с активным `work` открыто свободное окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai` из workspace `surf`, и вызвана команда сохранения
- **THEN** в таблице `apps` у `work` появляется запись `chrome-ai` с `rect` окна, нового приложения по классу окна в `[apps]` не появляется, окно несёт тег `app:chrome-ai#1`

#### Scenario: Одно перечитывание на одну запись
- **WHEN** вызвана цепочка `save_workspace` и файл конфига записан
- **THEN** в журнале демона одна строка о перечитывании конфига, `hyprctl reload config-only` вызывается один раз

#### Scenario: Свободное окно на другом столе не записывается
- **WHEN** на столе 1 активен `dev-front`, на столе 3 без активного workspace открыт свободный терминал, и на столе 1 вызвана команда сохранения
- **THEN** терминал в конфиг не попадает и остаётся свободным

#### Scenario: Работа без сохранения
- **WHEN** пользователь два часа поднимает workspace, меняет ячейки и двигает окна, не вызывая команду сохранения
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст

#### Scenario: Общее окно записывается в раздел workspace
- **WHEN** окно `chrome-ai` из `surf` перетащено в `work`, сдвинуто пользователем, и на столе 1 вызвана цепочка `save_workspace`
- **THEN** в разделе `work` появляется запись `chrome-ai` с `rect` окна, запись `chrome-ai = "right"` в разделе `surf` не меняется, окно по-прежнему входит в оба workspace, а после перезагрузки поднятие второго из них забирает окно первого, а не запускает второй Chrome AI

#### Scenario: Отделённое окно не записывается
- **WHEN** у `chromium` в `work` два окна, первое убрано из `work` командой отделения и осталось в `dev-front`, второе стоит в ячейке `left`, и вызвана цепочка `save_workspace`
- **THEN** у `chromium` в разделе `work` остаётся ячейка `left`: место считается по второму окну, входящему в `work`

#### Scenario: Переопределения переживают запись
- **WHEN** в разделе `surf` записано `chrome-ai = { cell = "right", chain = "SUPER+V" }`, окно `chrome-ai` сдвинуто пользователем, и на столе `surf` вызвана цепочка `save_workspace`
- **THEN** запись `chrome-ai` в разделе `surf` содержит `rect` нового положения окна и прежнее `chain = "SUPER+V"`, поля `cell` в ней нет, остальные записи раздела не изменились

#### Scenario: Порядок записей сохраняется
- **WHEN** в разделе `surf` приложения записаны в порядке `chrome`, `yandex-browser`, `chrome-ai`, в `surf` принято окно калькулятора, и вызвана цепочка `save_workspace`
- **THEN** в разделе `surf` записи идут в порядке `chrome`, `yandex-browser`, `chrome-ai`, калькулятор, а комментарии внутри таблицы `apps` на месте

#### Scenario: Раскладка после обмена мест
- **WHEN** в `work` окно `chrome-ai` (запись сессии) сдвинуто в 400,300 1400×1000, Super+V поменял его местами с herdr, и вызвана цепочка `save_workspace`
- **THEN** в разделе `work` записаны `main = "chrome-ai"`, `chrome-ai = "center"` и `herdr = { rect = { x = 400, y = 300, w = 1400, h = 1000 } }`, записи `chromium` и `neovide` не изменились, комментарии на месте

#### Scenario: Прямоугольник, совпадающий с другой ячейкой
- **WHEN** в `work` окно `neovide` сдвинуто мышью точно в прямоугольник ячейки `left` шаблона `thirds`, а окно Chromium — в другое место, и вызвана цепочка `save_workspace`
- **THEN** у `neovide` записано `neovide = "left"`, у `chromium` — `rect` его нынешнего прямоугольника

#### Scenario: Раскладка без команды не пишется
- **WHEN** пользователь сдвигает окна `work`, меняет их местами клавишами и сохраняет сессию, не вызывая цепочку `save_workspace`
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст, а раскладка живёт в памяти демона и в снимке сессии

#### Scenario: Запись без окна в конфиг не попадает
- **WHEN** после перезагрузки у `surf` в сессии есть запись Telegram из снимка, окно Telegram ещё не появилось, в `surf` открыт и принят калькулятор, и вызвана цепочка `save_workspace`
- **THEN** в разделе `surf` появляется калькулятор, записи Telegram в файле нет ни в `[apps]`, ни в разделе `surf`, а в сессии запись Telegram остаётся и ждёт окна
