# qs-network Specification

## Purpose

Сетевая плитка панели Quickshell и её меню действий: строки состояния ETH, WIFI и VPN с адресами и именами соединений, обновление по событиям NetworkManager без опросов, вызов редактора соединений и всплывающее меню с действиями nmcli.

## Requirements

### Requirement: Строки состояния сети
Плитка MUST показывать три строки: ETH, WIFI и VPN. Каждая строка MUST состоять из глифа и текста. Для подключённого проводного или беспроводного устройства глиф MUST быть подсвечен как активный, а текст MUST содержать имя строки и IPv4-адрес устройства; для устройства без соединения глиф MUST быть приглушён, а текст — «ETH отключено» или «WIFI отключено». Среди беспроводных устройств MUST NOT учитываться устройства с именами вида `p2p*`. Строка VPN MUST показывать имя первого активного соединения типа vpn («VPN <имя>»), а при отсутствии активного VPN — «VPN отключено». Глифы строк MUST быть: 󰈀 для ETH, 󰤨 и 󰤮 для подключённого и отключённого WIFI, 󰦝 для VPN.

#### Scenario: Проводное соединение и VPN активны
- **WHEN** проводное устройство подключено с адресом 192.168.1.10, активно VPN-соединение `axata`, радиомодуль wifi выключен
- **THEN** плитка показывает «ETH 192.168.1.10» и «VPN axata» с активными глифами, а строку WIFI — с глифом 󰤮 и текстом «WIFI отключено»

#### Scenario: Wifi без соединения
- **WHEN** радиомодуль wifi включён, но соединения нет
- **THEN** строка показывает 󰤮 в приглушённом виде и текст «WIFI отключено»

### Requirement: Состояние из NetworkManager по событиям
Плитка MUST перестраивать строки только в ответ на события NetworkManager: панель держит открытым поток событий (`nmcli monitor`) и после каждого события перечитывает состояние устройств, адреса и активные VPN-соединения одним вызовом скрипта панели на основе `nmcli`. Панель MUST NOT опрашивать состояние сети по таймеру и MUST NOT держать страховочный опрос на случай пропущенных событий: единственный источник изменений — события NetworkManager. Модуль Quickshell для NetworkManager версии 0.3.1 не сообщает адреса IPv4 и VPN-соединения, поэтому чтение состояния через `nmcli` допускается, но только как реакция на событие.

#### Scenario: Смена сети
- **WHEN** пользователь подключается к другому wifi
- **THEN** строка WIFI показывает новый IPv4-адрес сразу после того, как NetworkManager сообщил о смене состояния, без ожидания интервала опроса

#### Scenario: Отсутствие опросов
- **WHEN** состояние сети не меняется в течение минуты
- **THEN** панель за это время не запускает ни одного процесса `nmcli`, кроме постоянно открытого потока событий, и не обращается к NetworkManager по таймеру

### Requirement: Клик по плитке и кнопка меню
Клик по телу плитки MUST запускать `nm-connection-editor`; подсказка при наведении MUST сообщать «ЛКМ — редактор соединений». В заголовке плитки MUST быть кнопка «⋮» с подсказкой «Действия сети», которая открывает меню сети; повторный клик по кнопке при открытом меню MUST закрывать его.

#### Scenario: Редактор соединений
- **WHEN** пользователь кликает по строкам состояния
- **THEN** запускается nm-connection-editor, меню сети при этом не открывается

#### Scenario: Открытие меню кнопкой
- **WHEN** пользователь кликает «⋮»
- **THEN** рядом с плиткой появляется меню сети

### Requirement: Меню сети
Меню сети MUST быть всплывающим окном панели, расположенным справа от колонки на уровне плитки сети, поверх остальных окон. Содержимое меню MUST строиться по текущему состоянию NetworkManager при каждом открытии. Меню MUST закрываться, когда указатель покидает его область, и после выполнения любого действия из меню.

#### Scenario: Уход указателя
- **WHEN** меню открыто и указатель уходит за его границы
- **THEN** меню закрывается без выполнения действий

#### Scenario: Содержимое соответствует состоянию
- **WHEN** пользователь выключил wifi из меню и открывает меню снова
- **THEN** меню содержит пункт «Включить Wi-Fi» и не содержит пунктов «Поиск сетей Wi-Fi» и «Выключить Wi-Fi»

### Requirement: Пункты меню
Меню MUST содержать пункты, зависящие от состояния сети:
- при включённом радиомодуле wifi — «Поиск сетей Wi-Fi» (`nmcli device wifi rescan`) и «Выключить Wi-Fi» (`nmcli radio wifi off`); при выключенном — только «Включить Wi-Fi» (`nmcli radio wifi on`);
- для каждого соединения NetworkManager типа vpn: активного — «Отключить <имя>» (`nmcli con down id <имя>`), неактивного — «Подключить <имя>» (`nmcli con up id <имя>`);
- для подключённого проводного устройства — «Отключить <устройство>» (`nmcli device disconnect <устройство>`).

Каждое действие MUST выполняться через nmcli, после чего меню MUST закрываться; результат действия MUST отражаться в строках плитки через события NetworkManager, а не через отдельное обновление из меню.

#### Scenario: Переключение wifi из меню
- **WHEN** пользователь кликает «Выключить Wi-Fi»
- **THEN** выполняется `nmcli radio wifi off`, меню закрывается, строка WIFI переходит в состояние «WIFI отключено»

#### Scenario: Поиск сетей
- **WHEN** пользователь кликает «Поиск сетей Wi-Fi»
- **THEN** выполняется `nmcli device wifi rescan`, меню закрывается

#### Scenario: Подключение VPN из меню
- **WHEN** активно `axata`, а пользователь кликает «Подключить kozloff-de»
- **THEN** выполняется `nmcli con up id kozloff-de`, меню закрывается, а после установления соединения строка VPN показывает имя активного соединения

### Requirement: VPN только по действию пользователя
Панель MUST NOT поднимать и MUST NOT разрывать VPN-соединения сама по себе: ни при старте панели, ни при обновлении состояния, ни при открытии меню. Соединение `axata` поднимает сессия согласно требованию «VPN при старте сессии» спецификации hyprland-autostart; соединение `kozloff-de` MUST подниматься только по клику пользователя на пункт «Подключить kozloff-de». Панель MUST NOT менять настройки автоподключения соединений NetworkManager.

#### Scenario: Состояние после старта сессии
- **WHEN** сессия запущена, панель стартовала и сессия подняла `axata`
- **THEN** строка VPN показывает «VPN axata», а меню предлагает «Отключить axata» и «Подключить kozloff-de»; `kozloff-de` остаётся неактивным, пока пользователь не выберет его в меню

#### Scenario: Перезапуск панели
- **WHEN** панель перезапущена при активном `axata`
- **THEN** `nmcli -t -f NAME con show --active` по-прежнему содержит `axata`, соединение не разрывалось и не переподключалось
