# eww-launcher Specification

## Purpose

Лаунчер приложений внутри дашборда: поиск по названию и сетка полноцветных иконок из .desktop-записей. Реализации — `widgets/launcher/scripts/apps-list` (генерация сетки), `widgets/launcher/scripts/apps-update` (обработка ввода), плитка launcher-tile.

## Requirements

### Requirement: Источник списка приложений
Сетку лаунчера MUST поставлять демон `eww-daemon launcher` (Rust, проект `~/work/pets/eww-daemon`; deflisten `launcher-grid`). При старте демон MUST прочитать все записи `.desktop` из стандартных каталогов: `$XDG_DATA_HOME/applications` (по умолчанию `~/.local/share/applications`), `applications` в каждом каталоге `$XDG_DATA_DIRS` (по умолчанию `/usr/local/share:/usr/share`; так учитываются экспорты flatpak) и `/var/lib/snapd/desktop/applications`, а дальше следить за существующими из них через inotify и пересобирать сетку только при создании, изменении, удалении или переименовании файлов. Опросы по таймеру ЗАПРЕЩЕНЫ: прежний `defpoll` каждые 60 с заставлял eww перестраивать сетку из 90 иконок в главном потоке GTK и замораживал дашборд на секунду.

Правила разбора записей: пропуск `NoDisplay=true`, `Hidden=true` и записей не типа Application; имя `Name[ru_RU]` → `Name[ru]` → `Name` (фолбэк — id); дедупликация по id, более ранний каталог приоритетнее; сортировка по имени без учёта регистра. Запись MUST отбрасываться, если её нельзя запустить: `TryExec` (если задан), иначе первое слово `Exec` (без кавычек, с пропуском префикса `env VAR=…`) не является существующим файлом по абсолютному пути и не находится в `PATH`. Из записей, чьи имена различаются только номером версии (токен вида `3.12` или `v2.1`; одиночное число, как в «Supreme Commander 2», версией не считается), MUST оставаться старшая версия.

#### Scenario: Незапускаемая запись и дубликат по версии
- **WHEN** в каталоге есть запись с `Exec=/opt/nope/bin/nope` (файла нет) и две записи «Приложение 1.2» и «Приложение 1.10»
- **THEN** первая в сетке не показывается, из двух версий остаётся «Приложение 1.10»

#### Scenario: Новое приложение появляется без опроса
- **WHEN** в `~/.local/share/applications` появляется или удаляется файл `.desktop`
- **THEN** сетка обновляется в течение секунды, без периодических опросов

### Requirement: Разделы и частые приложения
Без фильтра сетка MUST начинаться с ряда до семи самых частых приложений (по статистике запусков, только с ненулевым счётчиком, без заголовка), затем идти разделами, как в jgmenu: приложение попадает в первый подходящий раздел по полю `Categories` в порядке Стандартные (Utility), Разработка (Development), Образование (Education), Игры (Game), Графика (Graphics), Мультимедиа (AudioVideo, Audio, Video), Интернет (Network), Офис (Office), Наука (Science), Настройки (Settings), Система (System), остальное — Прочее. Перед иконками раздела MUST стоять его заголовок (класс `apps-cat`, цвет рамки `$yellow`, 1.3em, полужирный). Шапка плитки: подпись «APP:» с оформлением номера стола (цвет рамки, 1.3em, начертание 900) и поле фильтра с фоном цвета рамки и чёрным текстом. Ряды по 7 иконок 32×32 в ячейках 38px; видимая область 124px (три ряда), остальное — вертикальной прокруткой. При наведении на иконку демон (`eww-daemon hover launcher <id>`) MUST открывать у курсора окно `hoverinfo` с подробностями записи: название, GenericName, Comment, раздел, команда запуска, id; окно держится в пределах колонки плиток, следует за курсором и закрывается при уходе курсора (`hover-hide`). Штатные tooltip у кнопок не используются.

#### Scenario: Заголовки разделов
- **WHEN** поле фильтра пусто
- **THEN** сетка показывает ряд частых приложений, затем заголовки разделов с их иконками

### Requirement: Статистика запусков
Запуск MUST выполняться через демон (`eww-daemon launch <id>` в `onclick` кнопки): демон запускает приложение (`gtk-launch "<id>"`; для `Terminal=true` — `wezterm --config-file ~/.config/wezterm/apps.lua start --class <id> -- <Exec без %-кодов>`) отдельной сессией, увеличивает счётчик и сохраняет его в `~/.local/share/eww-daemon/usage.json`. Статистика MUST сохраняться между перезапусками и учитываться в ряду частых приложений и в порядке результатов фильтра.

#### Scenario: Частые приложения
- **WHEN** приложение запущено через лаунчер несколько раз
- **THEN** оно появляется в первом ряду сетки, а счётчик записан в `usage.json`

### Requirement: Фильтр
Поле ввода MUST передавать текст демону через сокет (`eww-daemon launcher-query '{}'`, сокет `$XDG_RUNTIME_DIR/eww-daemon/launcher.sock`); демон MUST ответить новой сеткой из памяти, без чтения файлов. При непустом фильтре заголовков разделов и ряда частых нет: плоский список приложений, название которых содержит запрос без учёта регистра (в том числе для кириллицы), упорядоченный по частоте запусков, затем по имени.

#### Scenario: Фильтр «бра»
- **WHEN** пользователь вводит «бра»
- **THEN** остаётся плоский список без заголовков, в нём есть «Яндекс Браузер» и другие записи с этой подстрокой; очистка поля возвращает разделы

### Requirement: Кэш иконок
Иконки записей (`Icon=`: имя в теме или абсолютный путь, при промахе `application-x-executable`) MUST подбираться по индексу тем, который демон строит одним обходом каталогов при первом обращении, и кэшироваться на диске в `~/.cache/eww-daemon/icons.json`; холодный старт с построением индекса MUST занимать не более секунды.

#### Scenario: Холодный старт
- **WHEN** кэш иконок отсутствует
- **THEN** сетка выводится в течение секунды (замер: 200 мс), а последующие старты используют кэш
