# hyprland-config Specification

## Purpose

Состав и размещение рабочего конфига Hyprland под управлением chezmoi: монитор, карта XKB, эффекты, рабочие столы и поведение окон, которые сессия обязана обеспечивать.

## Requirements

### Requirement: Конфиг под управлением chezmoi
Конфиг Hyprland MUST храниться в источнике chezmoi в каталоге `dot_config/hypr/` и попадать в `~/.config/hypr/` командой `chezmoi apply`. Главный файл MUST быть `hyprland.lua` на Lua-API Hyprland; файла `hyprland.conf` в `~/.config/hypr/` MUST NOT быть, чтобы Hyprland не выбрал устаревший формат. Конфиги сопутствующих программ сессии (hyprpaper, hypridle, hyprlock) MUST лежать в том же каталоге `dot_config/hypr/`. Пути внутри конфига MUST записываться без префиксов chezmoi (`executable_`, `dot_`).

#### Scenario: Конфиг применён
- **WHEN** выполнена команда `chezmoi apply`
- **THEN** `~/.config/hypr/hyprland.lua` совпадает с источником, `chezmoi status` не показывает расхождений, а `Hyprland --version` и `luac -p ~/.config/hypr/hyprland.lua` завершаются без ошибок

#### Scenario: Конфиг перезагружен в работающей сессии
- **WHEN** после правки конфига выполнена `hyprctl reload`
- **THEN** Hyprland применяет новый конфиг без перезапуска сессии и без сообщений об ошибках в `hyprctl configerrors`

### Requirement: Монитор
Сессия MUST выводить изображение на монитор DP-2 в режиме 3840×2160 с родной частотой обновления и масштабом 1. Для любого другого подключённого монитора конфиг MUST задавать режим по умолчанию (`preferred`, положение `auto`), чтобы Hyprland стартовал и при смене оборудования.

#### Scenario: Монитор в родном режиме
- **WHEN** сессия запущена
- **THEN** `hyprctl monitors` показывает DP-2 в режиме 3840x2160 с частотой не ниже 119 Гц и масштабом 1

### Requirement: Параметры драйвера NVIDIA для KMS
Система MUST содержать файл `/etc/modprobe.d/nvidia-vrr.conf` со строкой `options nvidia_modeset conceal_vrr_caps=1`, включённый в initramfs. Без него nvidia-drm при каждом modeset переводит монитор в режим Adaptive-Sync, и при 3840×2160@120 изображение темнее, а шрифты хуже, чем при 60 Гц. Файл лежит вне источника chezmoi и MUST быть описан в design.md изменения, которое его вводит.

#### Scenario: VRR скрыт от композитора
- **WHEN** система загружена с этим файлом
- **THEN** `modetest -M nvidia-drm -c` показывает у всех коннекторов `vrr_capable` со значением 0, `hyprctl monitors` показывает `vrr: false`, а изображение при 120 Гц не отличается от изображения при 60 Гц

### Requirement: Карта XKB и зарезервированные сочетания
Конфиг MUST загружать карту клавиатуры файлом `~/.config/X11/xkb_custom` через `input.kb_file`. Сочетания Win+Пробел, Alt+E и Alt+R MUST оставаться за картой XKB: ни одна привязка конфигурации MUST NOT занимать их, иначе композитор перехватит их раньше XKB.

#### Scenario: Раскладки переключаются картой
- **WHEN** в терминале сессии нажаты Alt+R, затем Alt+E, затем Win+Пробел
- **THEN** ввод переключается на русскую раскладку, затем на английскую, затем по кругу, а `hyprctl devices` показывает активную раскладку

### Requirement: Рабочие столы
Сессия MUST предоставлять восемь рабочих столов с именами «1»…«8», все на мониторе DP-2. Стол с номером N MUST существовать до первого перехода на него, чтобы переключение и перенос окон работали с любого стола.

#### Scenario: Переход на пустой стол
- **WHEN** пользователь переходит на стол 7, на котором нет окон
- **THEN** `hyprctl activeworkspace` показывает стол с именем «7» на DP-2

### Requirement: Фокус кликом и рамка активного окна
Фокус окна MUST переходить только по клику в области окна: наведение курсора фокус не переводит, в том числе при переходе между плавающими окнами. Курсор MUST NOT переноситься к окну при смене фокуса диспетчером (активация из плитки стола, Alt+Tab). Рамка окна MUST быть шириной 1 px, как рамка плиток панели; рамка активного окна MUST быть цвета рамки плиток панели (yellow Tokyo Night `#E0AF68`), рамка неактивного окна — тёмно-зелёной `#2D6A4F`. Слои с клавиатурой по требованию (поле фильтра панели) MUST NOT удерживать клавиатуру при клике по окну (`misc.layers_hog_keyboard_focus` выключен). Запрос активации от приложения (xdg-activation: клик по уведомлению Telegram в dunst, открытие ссылки из другой программы) MUST переводить фокус на окно приложения и переходить на его стол (`misc.focus_on_activate` включён); левый клик по уведомлению dunst MUST выполнять действие уведомления по умолчанию и закрывать его.

#### Scenario: Наведение не меняет фокус
- **WHEN** в фокусе терминал, а курсор проходит над окном браузера без клика
- **THEN** фокус клавиатуры остаётся у терминала, браузер не поднимается над ним

#### Scenario: Активация из панели без переноса курсора
- **WHEN** пользователь кликает по иконке окна в плитке стола
- **THEN** окно получает фокус и поднимается наверх, а курсор остаётся на панели

#### Scenario: Клик по уведомлению
- **WHEN** окно Telegram на столе 3, пользователь на столе 1 кликает левой кнопкой по уведомлению Telegram
- **THEN** уведомление закрывается, композитор переходит на стол 3, окно Telegram получает фокус и поднимается наверх

#### Scenario: Цвет рамки
- **WHEN** окно в фокусе
- **THEN** его рамка жёлтая `#E0AF68` шириной 1 px, как рамки плиток панели; `hyprctl getoption general:border_size` показывает 1, а рамки окон без фокуса тёмно-зелёные `#2D6A4F`

### Requirement: Эффекты окон, слоёв и курсор
Конфиг MUST включать размытие, скругление углов, тени и анимации окон и слоёв. Прозрачность и размытие: окно в фокусе с непрозрачностью 0.9, без фокуса 0.7, полноэкранное и модальные диалоги непрозрачные; браузеры и видеопроигрыватели непрозрачные и без размытия независимо от фокуса, игры в фокусе непрозрачные; размытие фона только у терминалов и neovide в фокусе; скругление 8 px, мягкая тень. Для слоя панели Quickshell (пространство имён `panel`) конфиг MUST задавать правило слоя с размытием и порогом прозрачности, при котором полностью прозрачные промежутки между плитками не размываются и не затемняются, а плитки получают размытый фон. Курсор MUST быть аппаратным (`cursor:no_hardware_cursors = false`); конфиг MUST сохранять возможность переключить курсор на программный одной настройкой.

#### Scenario: Прозрачность окон
- **WHEN** в фокусе терминал, а рядом окно браузера без фокуса
- **THEN** терминал полупрозрачный с размытым фоном, браузер непрозрачный и без размытия; при переводе фокуса на браузер его вид не меняется, а терминал становится прозрачнее

#### Scenario: Размытие панели
- **WHEN** панель Quickshell открыта поверх обоев и окон
- **THEN** плитки панели полупрозрачные с размытым фоном, а промежутки между ними показывают обои и окна без размытия и затемнения

#### Scenario: Эффекты не дают рывков
- **WHEN** в сессии открыты четыре окна и панель Quickshell, а пользователь перемещает плавающее окно и переключает рабочие столы
- **THEN** анимации идут без заметных рывков, загрузка GPU по `nvidia-smi` не достигает насыщения

### Requirement: Поведение окон
Новые окна MUST открываться плавающими с сохранением возможности перевести окно в мозаичный режим привязкой; расположение окон workspace по ячейкам задаёт демон workspaced (спецификация ws-daemon), собственная раскладка зон в конфиге Hyprland MUST NOT создаваться. Помимо `special:hidden` для окон, скрытых пользователем, сессия MUST допускать специальный стол `special:pool` для окон, припаркованных демоном; переключение на него привязкой MUST NOT предусматриваться. Приложения Xwayland MUST поддерживаться: Xwayland включён, окна GTK-программ, запущенных с `GDK_BACKEND=x11`, и приложений AppImage отображаются без чёрных областей. Браузеры (Chromium, Google Chrome и Яндекс.Браузер из контейнера ubuntu-box) MUST работать нативно под Wayland (`--ozone-platform=wayland` в файле флагов Chromium и в ярлыках distrobox): под Xwayland печать через wtype даёт цифры вместо текста. Неполадки воспроизведения видео под Wayland MUST решаться без возврата браузера на X11.

#### Scenario: Новое окно плавающее
- **WHEN** из сессии запущен терминал
- **THEN** `hyprctl activewindow` показывает `floating: 1`

#### Scenario: Окно Xwayland
- **WHEN** из сессии запущена GTK-программа с `GDK_BACKEND=x11`
- **THEN** `hyprctl clients` показывает для неё `xwayland: 1`, окно отрисовано полностью

#### Scenario: Диктовка в браузер
- **WHEN** в поле ввода Google Chrome, Chromium или Яндекс.Браузера пользователь диктует фразу через voxtype
- **THEN** `hyprctl clients` показывает для окна `xwayland: 0`, в поле появляется распознанный текст, а не цифры

#### Scenario: Припаркованное окно
- **WHEN** демон перенёс окно на `special:pool`
- **THEN** `hyprctl clients -j` показывает у окна стол `special:pool`, окно не видно ни на одном столе, `hyprctl binds` не содержит привязки для показа `special:pool`
