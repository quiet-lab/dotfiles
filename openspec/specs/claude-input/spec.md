# claude-input Specification

## Purpose
Буфер ввода Claude Code в neovim: панель под панелью Claude Code в herdr, содержимое буфера повторяется в строке ввода Claude Code, сохранение отправляет запрос.

## Requirements

### Requirement: Панель буфера ввода открывается вместе с сессией Claude Code
Хук Claude Code `SessionStart` с событиями `startup` и `resume` MUST вызывать сценарий `~/.claude/hooks/herdr-claude-input.sh open`. Внутри herdr сценарий MUST делить панель Claude Code вниз без передачи фокуса так, чтобы область вывода новой панели была ровно 13 строк (`viewport_rows` в ответе `herdr pane get`), и запускать в ней процессом панели neovim с командой `ClaudeInput`. События `compact` и `clear` панель MUST NOT открывать.

#### Scenario: Запуск Claude Code в herdr
- **WHEN** в панели herdr запускается `claude`
- **THEN** под панелью Claude Code появляется панель с neovim, у неё `viewport_rows` равно 13, фокус остаётся у Claude Code, а neovim открыт в буфере `claude://input` в режиме вставки

### Requirement: Одна панель буфера на панель Claude Code
Идентификатор панели Claude Code панель буфера MUST получать переменной окружения `CLAUDE_INPUT_PANE`. Соответствие «панель Claude Code → панель буфера» MUST храниться файлом в `${XDG_STATE_HOME:-~/.local/state}/claude-input/`. Если файл указывает на живую панель, `open` MUST NOT создавать новую.

#### Scenario: Повторный старт для той же панели
- **WHEN** панель буфера для панели Claude Code уже открыта и сессия возобновляется (`SessionStart` с событием `resume`)
- **THEN** вторая панель не создаётся

### Requirement: Сценарий хука не действует вне своей области
Сценарий MUST ничего не делать и завершаться с кодом 0 вне herdr (`HERDR_ENV` не равна 1 или не задана `HERDR_PANE_ID`), у субагентов (поле `agent_id` во входе хука), при высоте панели Claude Code меньше 20 строк и при любой ошибке.

#### Scenario: Исполнитель duty
- **WHEN** Claude Code запущен в панели workspace с заданной `DUTY_TASK`
- **THEN** панель буфера создаётся так же, как в корневом workspace

#### Scenario: Вне herdr
- **WHEN** Claude Code запущен в терминале без herdr
- **THEN** сценарий ничего не выводит и завершается с кодом 0

### Requirement: Панель буфера закрывается с завершением сессии
Хук `SessionEnd` MUST вызывать `herdr-claude-input.sh close`, который закрывает панель буфера, записанную для панели Claude Code, и удаляет файл соответствия. Выход из neovim (`:q`) MUST закрывать панель буфера.

#### Scenario: Выход из Claude Code
- **WHEN** пользователь выходит из Claude Code, под которым открыта панель буфера
- **THEN** панель буфера закрывается, файла соответствия для панели Claude Code не остаётся

#### Scenario: Завершение исполнителя duty
- **WHEN** сессия Claude Code в дочернем workspace с заданной `DUTY_TASK` завершается
- **THEN** панель буфера закрыта, файла соответствия для панели исполнителя нет

### Requirement: Буфер ввода повторяется в строке ввода Claude Code
Команда neovim `ClaudeInput` MUST открывать единственный буфер `claude://input` (`buftype=acwrite`, без файла подкачки, `filetype=markdown`) и переводить neovim в режим вставки. Каждое изменение буфера (`TextChanged`, `TextChangedI`, `TextChangedP`) MUST заменять строку ввода Claude Code в панели `CLAUDE_INPUT_PANE` полным содержимым буфера; перевод строки MUST NOT отправлять запрос.

#### Scenario: Набор текста
- **WHEN** в буфере набран текст из двух строк «первая» и «вторая»
- **THEN** строка ввода Claude Code содержит ровно эти две строки, запрос не отправлен

#### Scenario: Правка текста
- **WHEN** в буфере, содержимое которого уже передано, удаляется слово
- **THEN** строка ввода Claude Code содержит новое содержимое буфера целиком, прежнее содержимое не остаётся

### Requirement: Замена строки ввода одним запросом к сокету herdr
Замена MUST идти одним запросом `pane.send_text` к сокету herdr (`HERDR_SOCKET_PATH`) из neovim без запуска процесса и без таймеров: последовательность очистки (`i`, `ctrl+u`, Esc в кодировке `CSI 27 u`, `g g d G i`, Backspace) и текст. Текст до 700 знаков без управляющих символов, кроме перевода строки, MUST идти сырыми байтами, иначе — в рамке bracketed paste. В полёте MUST быть не больше одной отправки; изменение во время отправки MUST приводить к отправке последнего состояния после ответа.

#### Scenario: Быстрый набор
- **WHEN** пользователь набирает несколько знаков быстрее, чем приходит ответ сервера herdr
- **THEN** одновременно идёт не больше одной отправки, а после последнего ответа строка ввода совпадает с буфером

#### Scenario: Длинный текст
- **WHEN** в буфере больше 700 знаков
- **THEN** текст передаётся в рамке bracketed paste, строка ввода показывает его вставкой, а прежнее содержимое не остаётся

### Requirement: Отправка ждёт выхода Claude Code из диалога
Пока панель Claude Code в статусе `blocked`, отправка MUST откладываться и MUST выполняться по событию смены статуса из подписки herdr `pane.agent_status_changed`.

#### Scenario: Диалог Claude Code
- **WHEN** панель Claude Code в статусе `blocked` (открыт вопрос с вариантами), а буфер меняется
- **THEN** в панель Claude Code ничего не отправляется, а после смены статуса строка ввода получает последнее содержимое буфера

### Requirement: Сохранение буфера отправляет запрос
`:w` (`BufWriteCmd`) MUST заменять строку ввода Claude Code содержимым буфера запросом `pane.send_text` и следующим запросом `pane.send_keys` передавать клавишу Enter, затем очищать буфер и снимать признак изменения; сырой байт `\r` строка ввода Claude Code отправкой запроса не считает. Пустой буфер `:w` MUST NOT отправлять. При статусе `blocked` `:w` MUST NOT отправлять и MUST NOT очищать буфер, а neovim MUST сообщать, что Claude Code ждёт ответа в диалоге.

#### Scenario: Отправка местной команды
- **WHEN** в буфере набрано `/help` и выполнено `:w`
- **THEN** Claude Code открывает справку, буфер пуст и не помечен изменённым

#### Scenario: Отправка запроса модели
- **WHEN** в буфере набран текст и выполнено `:w`
- **THEN** Claude Code отправляет запрос модели, буфер пуст

### Requirement: Буфер диалога открывается на время диалога
Пока панель Claude Code в статусе `blocked` и её экран — диалог с пунктами выбора, окно панели буфера MUST показывать буфер `claude://dialog` (`buftype=acwrite`, без файла подкачки, пустой при открытии, режим вставки) вместо `claude://input`. Открытый буфер диалога MUST оставаться, пока экран остаётся диалогом, при любом статусе. Переходы MUST происходить по событиям подписки herdr `pane.agent_status_changed` и по правкам буфера диалога, без таймеров.

#### Scenario: Вопрос с вариантами
- **WHEN** в буфере ввода набран текст «черновик», а Claude Code открывает AskUserQuestion
- **THEN** окно панели буфера показывает пустой `claude://dialog` в режиме вставки

#### Scenario: Местный диалог
- **WHEN** открыт выбор модели `/model` (статус `idle`)
- **THEN** буфер диалога не открывается

### Requirement: Буфер ввода возвращается после диалога
Когда экран панели Claude Code перестаёт быть диалогом, окно панели буфера MUST возвращаться к `claude://input` с прежним содержимым.

#### Scenario: Диалог закрыт
- **WHEN** ответ на диалог отправлен и Claude Code вышел из `blocked`
- **THEN** окно панели буфера показывает `claude://input` с текстом «черновик»

### Requirement: Распознавание диалога по экрану панели
Экран панели Claude Code MUST читаться через сокет herdr (`pane.read`). Экран MUST считаться диалогом, только если последняя непустая строка содержит «Enter to select», «Enter to confirm» или «Esc to cancel» и на нём есть пункты выбора: нумерованные строки, номера которых снизу вверх идут подряд до 1, или, при подсказке Enter в подвале, строки с тем же отступом, что строка выделения `❯`. Выделенный пункт MUST определяться по знаку `❯`, а не запоминаться плагином.

#### Scenario: MCP elicitation
- **WHEN** на экране запрос MCP elicitation с Accept и Decline без подсказки Enter
- **THEN** буфер диалога не открывается

### Requirement: Цифра переводит выделение
Содержимое буфера диалога из одного числа N MUST переводить выделение диалога на пункт N стрелками от выделенного пункта и очищать буфер; в одиночном выборе и запросе разрешения клавиша цифры MUST NOT отправляться, так как Claude Code по ней сразу подтверждает пункт. Если пункта N нет, MUST NOT отправляться ничего, буфер MUST очищаться.

#### Scenario: Выбор пункта
- **WHEN** выделен пункт 1 вопроса AskUserQuestion и в буфере набрано `3`
- **THEN** выделен пункт 3, ответ не отправлен, буфер пуст

#### Scenario: Пункта нет
- **WHEN** в вопросе четыре пункта и в буфере набрано `8`
- **THEN** выделение не меняется, буфер пуст

### Requirement: Цифра при выделенном пункте свободного ввода
Если выделен пункт свободного ввода, число MUST считаться выбором пункта, только когда буфер перед ним был пуст. Если в поле есть текст, переданный плагином, он MUST сниматься тем же запросом до стрелок.

#### Scenario: Передумал после текста
- **WHEN** выделен пункт свободного ввода, в буфере набран текст, затем буфер очищен и набрано `2`
- **THEN** поле свободного ввода пусто, выделен пункт 2, буфер пуст

### Requirement: Цифра в множественном выборе переключает отметку
В вопросе с множественным выбором число N, указывающее на пункт, отличный от свободного ввода, MUST переключать отметку пункта N; число, указывающее на пункт свободного ввода, MUST только переводить на него выделение.

#### Scenario: Отметка пункта
- **WHEN** в вопросе с множественным выбором пункт 2 не отмечен и в буфере набрано `2`
- **THEN** пункт 2 отмечен, буфер пуст

### Requirement: Текст в пункте свободного ввода
Когда выделен пункт свободного ввода, содержимое буфера диалога, кроме случая выбора числом, MUST целиком повторяться в поле этого пункта одним запросом с префиксом очистки, как в буфере ввода; очистка буфера MUST очищать поле. Когда выделен другой пункт, текст MUST NOT отправляться.

#### Scenario: Свой ответ
- **WHEN** выделен пункт «Type something» и в буфере набрано «свой ответ»
- **THEN** надпись пункта — «свой ответ», ответ не отправлен

### Requirement: Сохранение буфера диалога подтверждает выбор
`:w` в буфере диалога MUST подтверждать выбор клавишей Enter (`pane.send_keys`): в множественном выборе — после перехода стрелками на строку «Submit», иначе — сразу; затем буфер MUST очищаться. В карточке из нескольких вопросов `:w` MUST переходить к следующему вопросу, буфер диалога MUST оставаться открытым, а `:w` на вкладке обзора MUST отправлять ответы. `:q` MUST закрывать neovim и панель, как в буфере ввода.

#### Scenario: Карточка из двух вопросов
- **WHEN** в первом вопросе выделен пункт 2 и выполнено `:w`
- **THEN** выбран пункт 2, открыт второй вопрос, окно показывает пустой `claude://dialog`

### Requirement: Буфер диалога ничего не подтверждает сам
Каждая отправка из буфера диалога MUST идти после чтения экрана в той же цепочке, одновременно MUST идти не больше одной цепочки. Esc MUST отправляться только в префиксе очистки при выделенном пункте свободного ввода. Ответ на диалог (Enter) MUST отправляться только по `:w` пользователя.

#### Scenario: Запрос разрешения
- **WHEN** открыт запрос разрешения Bash и в буфере набрано `2`
- **THEN** выделен пункт «No», ответ не отправлен, пока пользователь не выполнит `:w`
