# claude-input Specification

## Purpose
Буфер ввода Claude Code в neovim: панель под панелью Claude Code в herdr, содержимое буфера повторяется в строке ввода Claude Code, сохранение отправляет запрос.

## Requirements

### Requirement: Панель буфера ввода открывается вместе с сессией Claude Code
Хук Claude Code `SessionStart` с событиями `startup` и `resume` MUST вызывать сценарий `~/.claude/hooks/herdr-claude-input.sh open`. Внутри herdr сценарий MUST делить панель Claude Code вниз так, чтобы область вывода новой панели была ровно 13 строк (`viewport_rows` в ответе `herdr pane get`), и запускать в ней процессом панели neovim с командой `ClaudeInput`. После открытия фокус MUST быть у панели ввода, а клиент пользователя, смотрящий другой workspace, MUST NOT переключаться на workspace сессии. Фокус MUST отдаваться командой `herdr pane activate` после запуска neovim; если этой команды нет, сценарий MUST выводить сообщение об ошибке в stderr, MUST завершаться с кодом 1 и MUST NOT открывать панель. После открытия панели буфера панель Claude Code MUST нести токен `input_pane` источника `claude-input` со значением `pane_id` панели буфера (`herdr pane get <панель Claude>`, поле `tokens`); при возобновлении с живой панелью буфера токен MUST быть выставлен заново; ошибка установки токена (herdr без `--token`) MUST NOT прерывать хук. События `compact` и `clear` панель MUST NOT открывать.

#### Scenario: Запуск Claude Code в herdr
- **WHEN** в панели herdr запускается `claude` в workspace, который смотрит клиент
- **THEN** под панелью Claude Code появляется панель с neovim, у неё `viewport_rows` равно 13, фокус у панели ввода, а neovim открыт в буфере `claude://input` в режиме вставки, а `herdr pane get` панели Claude Code показывает токен `input_pane` со значением `pane_id` панели ввода

#### Scenario: Запуск Claude Code в невидимом workspace при наличии pane activate
- **WHEN** `claude` запускается в workspace, который клиент не смотрит, и команда `herdr pane activate` есть
- **THEN** фокус внутри этого workspace у панели с neovim, активный workspace клиента не изменился

#### Scenario: Запуск Claude Code в невидимом workspace без pane activate
- **WHEN** `claude` запускается в любом workspace herdr, у которого нет команды `herdr pane activate`
- **THEN** хук пишет сообщение об ошибке в stderr, панель с neovim не открывается, код выхода 1 (ненулевой код нужен, чтобы Claude Code показал stderr SessionStart; сессия продолжается)

#### Scenario: Возобновление сессии с живой панелью буфера
- **WHEN** сессия возобновляется (`resume`) в панели Claude Code, у которой панель буфера жива в том же workspace
- **THEN** новая панель не создаётся, а `herdr pane get` панели Claude Code показывает токен `input_pane` со значением `pane_id` живой панели буфера

#### Scenario: herdr без `--token`
- **WHEN** `herdr pane report-metadata` отвергает `--token`
- **THEN** хук продолжает работу, панель с neovim открыта, ошибки не выводится

### Requirement: Одна панель буфера на панель Claude Code
Идентификатор панели Claude Code панель буфера MUST получать переменной окружения `CLAUDE_INPUT_PANE`. Соответствие «панель Claude Code → панель буфера» MUST храниться файлом в `${XDG_STATE_HOME:-~/.local/state}/claude-input/`. Если файл указывает на живую панель, `open` MUST NOT создавать новую.

#### Scenario: Повторный старт для той же панели
- **WHEN** панель буфера для панели Claude Code уже открыта и сессия возобновляется (`SessionStart` с событием `resume`)
- **THEN** вторая панель не создаётся

### Requirement: Сценарий хука не действует вне своей области
Сценарий MUST ничего не делать и завершаться с кодом 0 вне herdr (`HERDR_ENV` не равна 1 или не задана `HERDR_PANE_ID`), у субагентов (поле `agent_id` во входе хука), при высоте панели Claude Code меньше 20 строк и при любой ошибке.

#### Scenario: Исполнитель duty
- **WHEN** Claude Code запущен в панели workspace с заданной `DUTY_TASK`
- **THEN** панель буфера создаётся так же, как в корневом workspace

#### Scenario: Вне herdr
- **WHEN** Claude Code запущен в терминале без herdr
- **THEN** сценарий ничего не выводит и завершается с кодом 0

### Requirement: Панель буфера закрывается с завершением сессии
Хук `SessionEnd` MUST вызывать `herdr-claude-input.sh close`, который закрывает панель буфера, записанную для панели Claude Code, и удаляет файл соответствия. Выход из neovim (`:q`) MUST закрывать панель буфера.

#### Scenario: Выход из Claude Code
- **WHEN** пользователь выходит из Claude Code, под которым открыта панель буфера
- **THEN** панель буфера закрывается, файла соответствия для панели Claude Code не остаётся

#### Scenario: Завершение исполнителя duty
- **WHEN** сессия Claude Code в дочернем workspace с заданной `DUTY_TASK` завершается
- **THEN** панель буфера закрыта, файла соответствия для панели исполнителя нет

### Requirement: Буфер ввода повторяется в строке ввода Claude Code
Команда neovim `ClaudeInput` MUST открывать единственный буфер `claude://input` (`buftype=acwrite`, без файла подкачки, `filetype=markdown`) и переводить neovim в режим вставки. Каждое изменение буфера (`TextChanged`, `TextChangedI`, `TextChangedP`) MUST заменять строку ввода Claude Code в панели `CLAUDE_INPUT_PANE` полным содержимым буфера; перевод строки MUST NOT отправлять запрос.

#### Scenario: Набор текста
- **WHEN** в буфере набран текст из двух строк «первая» и «вторая»
- **THEN** строка ввода Claude Code содержит ровно эти две строки, запрос не отправлен

#### Scenario: Правка текста
- **WHEN** в буфере, содержимое которого уже передано, удаляется слово
- **THEN** строка ввода Claude Code содержит новое содержимое буфера целиком, прежнее содержимое не остаётся

### Requirement: Замена строки ввода одним запросом к сокету herdr
Замена MUST идти одним запросом `pane.send_text` к сокету herdr (`HERDR_SOCKET_PATH`) из neovim без запуска процесса и без таймеров: последовательность очистки (`i`, `ctrl+u`, Esc в кодировке `CSI 27 u`, `g g d G i`, Backspace) и текст. Текст до 700 знаков без управляющих символов, кроме перевода строки, MUST идти сырыми байтами, иначе — в рамке bracketed paste. В полёте MUST быть не больше одной отправки; изменение во время отправки MUST приводить к отправке последнего состояния после ответа.

#### Scenario: Быстрый набор
- **WHEN** пользователь набирает несколько знаков быстрее, чем приходит ответ сервера herdr
- **THEN** одновременно идёт не больше одной отправки, а после последнего ответа строка ввода совпадает с буфером

#### Scenario: Длинный текст
- **WHEN** в буфере больше 700 знаков
- **THEN** текст передаётся в рамке bracketed paste, строка ввода показывает его вставкой, а прежнее содержимое не остаётся

### Requirement: Отправка ждёт выхода Claude Code из диалога
Пока панель Claude Code в статусе `blocked`, отправка MUST откладываться и MUST выполняться по событию смены статуса из подписки herdr `pane.agent_status_changed`.

#### Scenario: Диалог Claude Code
- **WHEN** панель Claude Code в статусе `blocked` (открыт вопрос с вариантами), а буфер меняется
- **THEN** в панель Claude Code ничего не отправляется, а после смены статуса строка ввода получает последнее содержимое буфера

### Requirement: Сохранение буфера отправляет запрос
`:w` (`BufWriteCmd`) MUST заменять строку ввода Claude Code содержимым буфера запросом `pane.send_text` и следующим запросом `pane.send_keys` передавать клавишу Enter, затем очищать буфер и снимать признак изменения; сырой байт `\r` строка ввода Claude Code отправкой запроса не считает. `<S-CR>` и `<S-Space>` в буфере ввода (режимы вставки и обычный) MUST действовать как `:w`. Пустой буфер `:w` MUST NOT отправлять. При статусе `blocked` `:w` MUST NOT отправлять и MUST NOT очищать буфер, а neovim MUST сообщать, что Claude Code ждёт ответа в диалоге.

#### Scenario: Отправка местной команды
- **WHEN** в буфере набрано `/help` и выполнено `:w`
- **THEN** Claude Code открывает справку, буфер пуст и не помечен изменённым

#### Scenario: Отправка запроса модели
- **WHEN** в буфере набран текст и выполнено `:w`
- **THEN** Claude Code отправляет запрос модели, буфер пуст

#### Scenario: Shift+Enter в буфере ввода
- **WHEN** в буфере ввода набран текст и в режиме вставки нажато Shift+Enter
- **THEN** Claude Code отправляет запрос модели, буфер пуст

### Requirement: Буфер диалога открывается на время диалога
Пока панель Claude Code в статусе `blocked` и её экран — диалог с пунктами выбора, окно панели буфера MUST показывать буфер `claude://dialog` (`buftype=acwrite`, без файла подкачки, пустой при открытии, режим вставки) вместо `claude://input`. Буфер диалога MUST создаваться при открытии диалога, MUST NOT входить в список буферов и MUST удаляться, когда окно возвращается к вводу. Открытый буфер диалога MUST оставаться, пока экран остаётся диалогом, при любом статусе. После ответа или отмены буфер диалога MUST NOT открываться снова, пока экран совпадает с диалогом, на который ответ отправлен. Переходы MUST происходить по событиям подписок herdr (`pane.agent_status_changed`, `pane.output_matched`) и по правкам буфера диалога, без таймеров.

#### Scenario: Вопрос с вариантами
- **WHEN** в буфере ввода набран текст «черновик», а Claude Code открывает AskUserQuestion
- **THEN** окно панели буфера показывает пустой `claude://dialog` в режиме вставки

#### Scenario: Местный диалог
- **WHEN** открыт выбор модели `/model` (статус `idle`)
- **THEN** буфер диалога не открывается

#### Scenario: Экран отвеченного диалога
- **WHEN** по `:w` ответ отправлен, а экран панели ещё совпадает с отвеченным диалогом
- **THEN** буфер диалога не открывается

#### Scenario: Буфера диалога нет вне диалога
- **WHEN** диалог завершён
- **THEN** буфера `claude://dialog` нет ни в окне, ни в списке буферов

### Requirement: Буфер ввода возвращается после диалога
По `:w` на последнем экране диалога (одиночный вопрос, запрос разрешения, вкладка обзора карточки) окно панели буфера MUST сразу возвращаться к `claude://input` с прежним содержимым, не дожидаясь смены экрана панели Claude Code. Когда экран панели перестаёт быть диалогом без `:w` (статус вышел из `blocked` или на экране появился подвал строки ввода Claude Code), окно MUST возвращаться к вводу так же.

#### Scenario: Диалог закрыт
- **WHEN** по `:w` ответ на одиночный вопрос отправлен
- **THEN** окно панели буфера сразу показывает `claude://input` с текстом «черновик»

#### Scenario: Карточка в статусе idle закрыта в панели
- **WHEN** открыт буфер диалога карточки, статус панели `idle`, а на экране появляется строка ввода Claude Code
- **THEN** окно показывает `claude://input`, буфер диалога удалён

### Requirement: Распознавание диалога по экрану панели
Экран панели Claude Code MUST читаться через сокет herdr (`pane.read`). Замыкающие пустые строки и строки линии рамки (начинаются с «───», могут нести подпись, например имя сессии) MUST пропускаться. Экран MUST считаться диалогом, только если последняя оставшаяся строка содержит «Enter to select», «Enter to confirm» или «Esc to cancel» и на нём есть пункты выбора: нумерованные строки, номера которых снизу вверх идут подряд до 1, или, при подсказке Enter в подвале, строки с тем же отступом, что строка выделения `❯`; вкладка обзора карточки распознаётся по пункту «Submit answers» без подвала; в множественном выборе кнопка подтверждения под пунктами — ненумерованная строка «Submit» или «Next» (так называется кнопка вопроса, за которым в карточке идёт ещё вопрос) — MUST входить в позиции выделения между пунктами. Выделенный пункт MUST определяться по знаку `❯`, а не запоминаться плагином. Строка вкладок карточки (`←` … `→` со знаками `☒` и `☐`) MUST давать число отвеченных и всех вопросов. Экран карточки (строка вкладок или вкладка обзора) MUST считаться диалогом при любом статусе панели, кроме `working`; подпись диалога MUST включать число отвеченных вопросов карточки.

#### Scenario: MCP elicitation
- **WHEN** на экране запрос MCP elicitation с Accept и Decline без подсказки Enter
- **THEN** буфер диалога не открывается

#### Scenario: Линия рамки с именем сессии
- **WHEN** под подвалом «Enter to select» диалога стоит линия «──── claude-input-keys ─»
- **THEN** экран распознан как диалог

### Requirement: Цифра переводит выделение
Содержимое буфера диалога из одного числа N MUST переводить выделение диалога на пункт N стрелками от выделенного пункта и очищать буфер; в одиночном выборе и запросе разрешения клавиша цифры MUST NOT отправляться, так как Claude Code по ней сразу подтверждает пункт. Если пункта N нет, MUST NOT отправляться ничего, буфер MUST очищаться.

#### Scenario: Выбор пункта
- **WHEN** выделен пункт 1 вопроса AskUserQuestion и в буфере набрано `3`
- **THEN** выделен пункт 3, ответ не отправлен, буфер пуст

#### Scenario: Пункта нет
- **WHEN** в вопросе четыре пункта и в буфере набрано `8`
- **THEN** выделение не меняется, буфер пуст

### Requirement: Цифра при выделенном пункте свободного ввода
Если выделен пункт свободного ввода, число MUST считаться выбором пункта, только когда буфер перед ним был пуст. Если в поле есть текст, переданный плагином, он MUST сниматься тем же запросом до стрелок.

#### Scenario: Передумал после текста
- **WHEN** выделен пункт свободного ввода, в буфере набран текст, затем буфер очищен и набрано `2`
- **THEN** поле свободного ввода пусто, выделен пункт 2, буфер пуст

### Requirement: Цифра в множественном выборе переключает отметку
В вопросе с множественным выбором число N, указывающее на пункт, отличный от свободного ввода, MUST переключать отметку пункта N; число, указывающее на пункт свободного ввода, MUST только переводить на него выделение.

#### Scenario: Отметка пункта
- **WHEN** в вопросе с множественным выбором пункт 2 не отмечен и в буфере набрано `2`
- **THEN** пункт 2 отмечен, буфер пуст

### Requirement: Текст в пункте свободного ввода
Когда выделен пункт свободного ввода, содержимое буфера диалога, кроме случая выбора числом, MUST целиком повторяться в поле этого пункта одним запросом с префиксом очистки, как в буфере ввода; очистка буфера MUST очищать поле. Когда выделен другой пункт, текст MUST NOT отправляться.

#### Scenario: Свой ответ
- **WHEN** выделен пункт «Type something» и в буфере набрано «свой ответ»
- **THEN** надпись пункта — «свой ответ», ответ не отправлен

### Requirement: Сохранение буфера диалога подтверждает выбор
`:w` в буфере диалога MUST подтверждать выбор клавишей Enter (`pane.send_keys`): в множественном выборе — после перехода стрелками на кнопку подтверждения («Submit» или «Next», по тому, что показано на экране), иначе — сразу; затем буфер диалога MUST очищаться. В карточке из нескольких вопросов `:w` MUST переходить к следующему вопросу, а буфер диалога MUST оставаться открытым и пустым до вкладки обзора: переход к следующему вопросу или обзору MUST определяться событием `pane.output_matched` по строке вкладок с большим числом отвеченных вопросов, в том числе после ответа прямо в панели Claude Code. `:w` на вкладке обзора MUST отправлять ответы и возвращать окно к вводу. `<S-CR>` и `<S-Space>` в буфере диалога (режимы вставки и обычный) MUST действовать как `:w`. `:q` MUST закрывать neovim и панель, как в буфере ввода.

#### Scenario: Карточка из двух вопросов
- **WHEN** в первом вопросе выделен пункт 2 и выполнено `:w`
- **THEN** выбран пункт 2, окно продолжает показывать пустой `claude://dialog`, и по экрану второго вопроса в нём отвечается второй вопрос

#### Scenario: Shift+Enter в диалоге
- **WHEN** в одиночном вопросе выделен пункт 2 и в режиме вставки нажато Shift+Enter
- **THEN** выбран пункт 2, окно показывает `claude://input`

#### Scenario: Отмена на вкладке обзора
- **WHEN** на вкладке обзора в буфере набрано `2` и нажато Shift+Enter
- **THEN** выделение переходит на «Cancel», затем отправляется Enter, окно показывает `claude://input`

#### Scenario: Множественный выбор не на последнем вопросе
- **WHEN** на экране множественного выбора первого из двух вопросов под пунктами стоит кнопка «Next» и выполнено `:w`
- **THEN** выделение переходит стрелками на «Next», отправляется Enter, буфер остаётся открытым и пустым до следующего вопроса

### Requirement: Буфер диалога ничего не подтверждает сам
Каждая отправка из буфера диалога MUST идти после чтения экрана в той же цепочке, одновременно MUST идти не больше одной цепочки. Esc MUST отправляться только в префиксе очистки при выделенном пункте свободного ввода и по Ctrl+C пользователя. Ответ на диалог (Enter) MUST отправляться только по `:w`, `<S-CR>` или `<S-Space>` пользователя.

#### Scenario: Запрос разрешения
- **WHEN** открыт запрос разрешения Bash и в буфере набрано `2`
- **THEN** выделен пункт «No», ответ не отправлен, пока пользователь не выполнит `:w`

### Requirement: Окно буфера ввода переносит строки визуально
Окно, показывающее буфер `claude://input` или `claude://dialog`, MUST переносить длинные строки по словам визуально (`wrap`, `linebreak`, `breakindent`), настройка MUST ставиться на окно при каждом показе буфера, а не глобально, и MUST NOT затрагивать окна других буферов. Содержимое буфера и текст, отправляемый в строку ввода Claude Code, MUST NOT содержать вставленных символов переноса.

#### Scenario: Длинная строка в буфере ввода
- **WHEN** в `claude://input` набрана строка длиннее ширины окна
- **THEN** окно показывает её перенесённой по словам, в буфере она остаётся одной строкой, в строку ввода Claude Code текст уходит без переносов

#### Scenario: Длинная строка в буфере диалога
- **WHEN** в `claude://dialog` набрана строка длиннее ширины окна
- **THEN** окно показывает её перенесённой по словам, в буфере она остаётся одной строкой

#### Scenario: Соседний буфер
- **WHEN** в том же Neovim открыто окно другого буфера
- **THEN** его опции переноса не меняются

### Requirement: Панель буфера переоткрывается командой
Сценарий `~/.claude/hooks/herdr-claude-input.sh reopen` MUST закрывать панель буфера командой `herdr pane close`, удалять файл соответствия и открывать панель заново тем же путём, что `open`; процессы по образцу MUST NOT завершаться. Идентификатор старой панели MUST браться из файла соответствия, а при его отсутствии — из токена `input_pane` панели Claude Code. Вызов MAY идти из панели Claude Code, из панели буфера или из любой другой панели workspace: панель Claude Code MUST находиться по токену `input_pane` (токен самой панели; панель агента, чей токен равен вызывающей панели; единственная панель агента Claude Code workspace), файл соответствия и токен MUST относиться к найденной панели; не найдена — сообщение в stderr и код 1. Горячая клавиша Ctrl+Alt+R клиента herdr (таблица `[keys]` конфигурации herdr, действие «команда по клавише») MUST вызывать этот же сценарий. Пользовательский навык `/input-reopen` MUST выполнять только этот сценарий.

#### Scenario: Зависший nvim
- **WHEN** nvim в панели буфера не реагирует на клавиши и пользователь вызывает `/input-reopen`
- **THEN** старая панель закрыта, под панелью Claude Code открыта новая с `nvim +ClaudeInput`, файл соответствия и токен `input_pane` указывают на новую панель

#### Scenario: Нет файла соответствия
- **WHEN** файла соответствия нет, а токен `input_pane` указывает на живую панель
- **THEN** панель из токена закрыта, новая открыта, файл соответствия создан заново

#### Scenario: Нет панели ввода
- **WHEN** панель буфера закрыта и файла соответствия нет
- **THEN** сценарий открывает панель ввода, как `open`

#### Scenario: Невозможно открыть панель
- **WHEN** панель Claude Code ниже 20 строк или herdr не создал панель
- **THEN** сценарий пишет причину в stderr и завершается с кодом 1; при успехе печатает идентификатор новой панели

#### Scenario: Вызов из панели буфера
- **WHEN** фокус в панели nvim и нажата Ctrl+Alt+R
- **THEN** панель Claude Code найдена по токену, старая панель буфера закрыта, новая открыта под панелью Claude Code на 13 строк

#### Scenario: Панель Claude не найдена
- **WHEN** в workspace нет панели агента Claude Code
- **THEN** сценарий пишет причину в stderr и завершается с кодом 1

### Requirement: Подсказка в буфере диалога
Подсказка диалога MUST показываться отдельным окном, на которое окно панели делится по вертикали: слева окно буфера диалога, справа окно подсказки (не плавающее, `split = "right"`). Ширина окна подсказки относится к ширине окна диалога как 1 к 4 (пятая часть ширины панели, округление вниз), но не меньше 20 столбцов; в узкой панели подсказке отдаются 20 столбцов, остальное — диалогу. Заголовок — в `winbar` окна подсказки («Вопрос k из n» для вопроса карточки, «Обзор ответов» для вкладки обзора, иначе «Диалог»). Строки — «клавиша → описание» колонками: номера пунктов текущего экрана с текстом пункта (выделенный помечен `❯` и подсвечен `CursorLine`), `S-CR` и `S-Space` — подтвердить, `C-c` — отменить диалог. Подсветка — группы which-key (`WhichKey`, `WhichKeySeparator`, `WhichKeyDesc`, `WhichKeyTitle`, `WhichKeyNormal`) с запасными (`Special`, `Comment`, `Normal`, `Title`, `NormalFloat`), если группы нет; библиотека which-key MUST NOT вызываться. Текст буфера не меняется, виртуальных строк в нём нет. Окно MUST NOT брать фокус и ввод, не переносить длинные строки (обрезка), MUST обновляться по каждому новому экрану диалога и при изменении размеров, закрываться вместе с буфером диалога и при его отмене; после закрытия окно ввода занимает всю ширину панели.

#### Scenario: Вкладка обзора
- **WHEN** открыта вкладка обзора карточки
- **THEN** справа от окна диалога видно окно разделения с заголовком «Обзор ответов» и строками «1 → ❯ Submit answers», «2 → Cancel», «S-CR → подтвердить», «S-Space → подтвердить», «C-c → отменить диалог», текст буфера пуст, в нём нет виртуальных строк, фокус остаётся в буфере диалога

#### Scenario: Ширина подсказки
- **WHEN** ширина панели 160 или 80 столбцов
- **THEN** окно подсказки занимает 32 или 20 столбцов, окно диалога — остальное

#### Scenario: Конец диалога
- **WHEN** диалог закрыт или отменён Ctrl+C
- **THEN** окна подсказки нет, окно ввода занимает всю ширину панели

### Requirement: Отмена диалога клавишей Ctrl+C
Ctrl+C в буфере диалога (режимы вставки и обычный) MUST отправлять в панель Claude Code клавишу Esc (`pane.send_keys`), во время идущей отправки — после неё, и сразу возвращать окно к `claude://input`, удаляя буфер диалога; прежний кадр отменённого диалога MUST NOT открывать буфер диалога снова.

#### Scenario: Отмена карточки
- **WHEN** открыт второй вопрос карточки и нажато Ctrl+C
- **THEN** Claude Code получает Esc, окно показывает `claude://input`, буфера диалога нет

### Requirement: История ввода в буфере ввода
В буфере `claude://input` клавиша `<Up>` на первой строке и `<Down>` на последней в режимах вставки и обычном MUST листать историю запросов Claude Code, а в середине многострочного текста стрелки MUST двигать курсор; `k`, `j` и буфер диалога MUST NOT меняться. История — записи `display` файла `~/.claude/history.jsonl`, у которых `project` равен `cwd` панели Claude Code (ответ `pane.get`); подряд одинаковые записи MUST считаться одной.

#### Scenario: Последняя запись
- **WHEN** в пустом буфере нажато `<Up>` на первой строке
- **THEN** буфер содержит последнюю запись проекта, строка ввода Claude Code получает тот же текст

#### Scenario: Предыдущая запись
- **WHEN** нажато `<Up>` второй раз
- **THEN** буфер содержит предпоследнюю запись

### Requirement: Листание истории ввода
`<Up>` MUST брать более старую запись и на самой старой ничего не делать; `<Down>` MUST брать более новую, а за самой новой возвращать черновик — текст буфера перед началом листания. Содержимое буфера MUST заменяться целиком, курсор — в конец, текст MUST попадать в строку ввода Claude Code обычной отправкой буфера. Файл MUST читаться по требованию при первом `<Up>` после сброса, без наблюдателей и таймеров; без файла или `cwd` стрелки MUST NOT менять буфер и MUST NOT выводить ошибок.

#### Scenario: Возврат черновика
- **WHEN** после листания `<Down>` нажато за самой новой записью
- **THEN** буфер содержит черновик, бывший до листания

#### Scenario: Середина многострочного текста
- **WHEN** курсор не на первой строке многострочного текста и нажато `<Up>`
- **THEN** курсор поднялся на строку выше, история не листается

#### Scenario: Записи другого проекта
- **WHEN** в файле есть записи с другим `project`
- **THEN** листание их не показывает

#### Scenario: Подряд одинаковые записи
- **WHEN** в файле две подряд одинаковые записи проекта
- **THEN** листание даёт одну запись

### Requirement: Сброс позиции истории ввода
Правка буфера пользователем (не самим листанием), `:w`, `<S-CR>`, `<S-Space>` и возврат из буфера диалога MUST сбрасывать позицию: следующее `<Up>` MUST начинать с самой новой записи и заново запоминать черновик.

#### Scenario: Правка после листания
- **WHEN** после листания пользователь изменил текст буфера и нажал `<Up>` на первой строке
- **THEN** листание начинается с самой новой записи, черновиком становится изменённый текст
