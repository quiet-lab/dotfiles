# eww-appicon Specification

## Purpose

Общий резолвер иконок для всех виджетов EWW (лаунчер приложений, модуль рабочих столов). Принимает список имён-кандидатов по убыванию приоритета и возвращает путь к файлу полноцветной иконки на stdout. Реализация — `scripts/appicon`, POSIX sh.

## Requirements

### Requirement: Порядок разрешения кандидатов
Резолвер MUST обрабатывать кандидатов строго в порядке аргументов командной строки; первый успешный кандидат завершает работу. Кандидат-абсолютный путь принимается как есть, если файл существует.

Для каждого имени-кандидата источники проверяются в порядке:
1. Кэш `/tmp/eww-icons` по ключу из полного набора кандидатов.
2. Desktop-файлы: точное `<имя>.desktop`, затем `<префикс>-<имя>.desktop` (distrobox-экспорты), затем совпадение первого слова `Exec=` с именем; каталоги `~/.local/share/applications` приоритетнее `/usr/share/applications`.
3. Каталоги иконок: `~/.local/share/icons` → `/usr/share/icons` → `/usr/share/pixmaps`.

#### Scenario: Кандидат через desktop-файл
- **WHEN** вызов `appicon firefox` при существующем `firefox.desktop` c `Icon=firefox`
- **THEN** путь найден через Icon= записи и выведен на stdout

### Requirement: Поиск внутри каталогов иконок
Поиск MUST быть рекурсивным (`find -L`, симлинки Papirus обязательны к учёту). Внутри корня сначала проверяется подкаталог активной GTK-темы иконок (из `~/.config/gtk-3.0/settings.ini` или переменной `APPICON_THEME`), затем корень целиком. Предпочтение: SVG, затем PNG наибольшего размера файла.

#### Scenario: Тема приоритетна
- **WHEN** иконка существует и в каталоге темы, и в общем корне
- **THEN** возвращается путь из каталога активной темы

### Requirement: Фолбэк generic-иконки
При полном неуспехе по всем кандидатам резолвер MUST вернуть первую найденную generic-иконку из списка `application-x-executable`, `applications-other`, `unknown`, `image-missing`, чтобы image-виджет не оставался пустым.

#### Scenario: Неизвестное приложение
- **WHEN** ни один кандидат не разрешился
- **THEN** stdout содержит путь к application-x-executable (или следующей найденной generic)

### Requirement: Кэширование результатов
Результат — включая отрицательный (пустой файл) — MUST кэшироваться в `/tmp/eww-icons`. Повторный вызов с тем же набором кандидатов MUST читаться из кэша без поиска. Сброс кэша — `rm -rf /tmp/eww-icons`.

#### Scenario: Промах тоже кэшируется
- **WHEN** второй подряд вызов с кандидатами, не разрешающимися в системе
- **THEN** поиск по desktop-файлам и каталогам не повторяется

### Requirement: Контракт вывода
На stdout MUST выводиться ровно один путь. При полном неуспехе (нет даже generic) — пустой вывод, код возврата 1, результат кэшируется как пустой.

#### Scenario: Успешное разрешение
- **WHEN** резолвер нашёл иконку первого кандидата
- **THEN** stdout содержит единственную строку-путь, код возврата 0
