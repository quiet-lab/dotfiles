# eww-shell Specification

## Purpose

Каркас EWW-дашборда: окна плиток у левого края экрана, выстроенные в вертикальную колонку, и статичные плитки (громкость, избранное, питание). Базовые стили — Tokyo Night. Специфицируется поведение под Openbox/X11, монитор 0.

## Requirements

### Requirement: Окна плиток
Каждая плитка дашборда MUST быть отдельным окном eww на мониторе 0 с привязкой `left top` и фиксированной геометрией (x = 10px, ширина 320px, если не указано иное):

| Окно | y | Особенности |
|------|---|-------------|
| `tile-pwr-lock`, `tile-pwr-logout`, `tile-pwr-restart`, `tile-pwr-reboot`, `tile-pwr-off` | 10px | x = 10/76/142/208/274px, квадраты 56×56 в один ряд |
| `tile-clock` | 76px | |
| `tile-weather` | 325px | |
| `tile-cpu`, `tile-ram`, `tile-gpu` | 680px | x = 10/120/230px, ширина 100px |
| `tile-volume` | 792px | |
| `tile-network` | 840px | |
| `tile-disks` | 957px | |
| `tile-favorites` | 1202px | |
| `tile-ws1` … `tile-ws8` | 1462px + 46px·(n−1) | по окну на рабочий стол, ширина 274px, высота 36px |
| `tile-tray` | 1462px | x = 294px, ширина 36px, высота 312px (вертикальный, справа от столов) |
| `tile-lang` | 1784px | x = 294px, ширина 36px, высота 36px (на уровне `tile-ws8`) |
| `tile-launcher` | 1830px | высота 320px (квадрат) |

Колонка MUST занимать экран по вертикали целиком (10…2150px) в трёх группах: вверху — ряд плиток питания, часы с календарём и погода (10…540px); внизу — квадратный лаунчер 320×320px у нижнего края (1830…2150px), а прямо над ним, через зазор 10px, блок рабочих столов с треем и раскладкой (1462…1820px); остальные плитки (шкалы, громкость, сеть, диски, избранное, всего 643px) MUST стоять по центру свободного промежутка между верхней и нижней группами (отступы 140px сверху и 139px снизу). Координаты рассчитаны из высот плиток при зазоре 10px и жёстко привязаны к экрану 3840×2160; при изменении высоты плитки координаты MUST быть пересчитаны (нижняя группа привязана к нижнему краю, средняя центрируется заново). Раздельные окна обусловлены композитором: picom размывает фон по форме окна целиком, и только так промежутки между плитками остаются без размытия.

Каждое окно плитки MUST резервировать страту `left` шириной 330px: это не даёт открытым окнам перекрывать колонку, а Openbox не выталкивает окно с собственной стратой из зоны страты (окно без неё он сдвигает в рабочую область на 10% ширины).

Все окна плиток MUST использовать тип `utility` со `stacking fg`. Использование типа `dock` ЗАПРЕЩЕНО: Openbox лишает dock-окна фокуса клавиатуры, и поле фильтра лаунчера перестаёт получать ввод.

#### Scenario: Открытые окна не залезают под колонку
- **WHEN** пользователь разворачивает любое окно на мониторе 0
- **THEN** оно располагается правее полосы 330px от левого края

#### Scenario: Поле поиска принимает клавиатуру
- **WHEN** пользователь кликает в поле фильтра лаунчера
- **THEN** окно получает фокус ввода и символы попадают в поле

### Requirement: Состав колонки
Окна плиток MUST образовывать колонку в порядке сверху вниз: ряд из пяти плиток питания [pwr-lock, pwr-logout, pwr-restart, pwr-reboot, pwr-off], clock-tile, weather-tile, ряд [cpu-tile, ram-tile, gpu-tile], volume-tile, network-tile, disks-tile, favorites-tile, блок [плитки столов workspace-tile (по одной на стол) слева, справа от них столбик tray-tile над lang-tile], launcher-tile с межплиточным зазором 10px. Тот же зазор 10px MUST выдерживаться при размещении окон горячими клавишами Openbox (`MoveResizeTo` в rc.xml): от краёв рабочей области и между окнами.

Полный ряд имеет ширину 320px; ряд из трёх шкал — 100px + 10px + 100px + 10px + 100px.

#### Scenario: Порядок фиксирован
- **WHEN** дашборд открывается
- **THEN** плитки следуют в порядке, указанном выше, без пропусков

### Requirement: Запуск при старте сессии
Демон eww и все окна плиток (`eww open-many`) MUST запускаться автоматически при старте сессии Openbox без ручных действий пользователя.

Автозапуск MUST быть безопасным:
- если исполняемый файл `eww` отсутствует в `$PATH`, автозапуск MUST пропустить запуск демона и окон, не прерывая остальной старт сессии;
- повторное выполнение автозапуска (например, после `openbox --restart`) MUST NOT порождать второй экземпляр демона или дубликаты окон плиток.

#### Scenario: Вход в сессию
- **WHEN** пользователь логинится в Openbox-сессию
- **THEN** демон eww активен и колонка дашборда видима

#### Scenario: Перезапуск Openbox не дублирует дашборд
- **WHEN** выполняется `openbox --restart`, а демон eww уже работает
- **THEN** демон не запускается повторно, каждое окно плитки существует в единственном экземпляре

#### Scenario: Отсутствует исполняемый файл eww
- **WHEN** при старте сессии `eww` отсутствует в `$PATH`
- **THEN** автозапуск не запускает демон и окна и не сообщает об ошибке, остальные компоненты автостарта продолжают работу

### Requirement: Опросы только для используемых переменных
Конфигурация MUST учитывать ограничение eww: poll запускается лишь когда его переменная используется в открытом окне. Переменная `network-sync` (страховка опроса сети) MUST иметь скрытую ссылку внутри network-tile (`label :visible false`), иначе её poll не выполняется.

#### Scenario: Страховочный poll живёт
- **WHEN** открыто окно `tile-network`
- **THEN** poll `network-sync` исполняется каждые 10 секунд

### Requirement: Плитка громкости
volume-tile MUST показывать кнопку динамика и горизонтальный scale, привязанный к переменной `current-volume` (poll 1s → `widgets/volume/scripts/volume`, всегда валидное число). Диапазон scale: 0–101 (допускается громкость свыше 100%).

Кнопка по клику MUST вызывать общий `scripts/popup audio` (pavucontrol) с тултипом «Микшер». Перемещение ползунка MUST выполнять `pactl set-sink-volume @DEFAULT_SINK@ {}%`.

#### Scenario: Регулировка громкости
- **WHEN** пользователь тянет ползунок громкости
- **THEN** громкость default sink меняется соответственно позиции

### Requirement: Плитка избранного
favorites-tile MUST содержать три кнопки, каждая открывает yazi в wezterm (`wezterm start --class yazi --cwd <каталог> -- yazi`) с рабочим каталогом: `~`, `~/Загрузки`, `~/.config`. Класс окна `yazi` нужен плиткам столов для показа иконки yazi.

#### Scenario: Переход в загрузки
- **WHEN** пользователь кликает «󰉋 ~/Загрузки»
- **THEN** открывается терминал wezterm с yazi в ~/Загрузки

### Requirement: Плитка питания
Питание MUST быть представлено пятью одинаковыми квадратными плитками 56×56px в один ряд в самом верху колонки (y = 10px, зазор 10px, ряд занимает всю ширину 320px), каждая — отдельное окно с одной кнопкой и подсказкой; иконки — глифы Nerd Font цвета рамки, подпись лежит в overlay поверх поля 54×54 (крупный шрифт не растягивает окно), размер и отступы подобраны каждому глифу отдельно так, что большая сторона глифа 44px, наименьший зазор до рамки 5px и зазоры слева/справа и сверху/снизу равны: Lock Screen (`loginctl lock-session`), Logout (`openbox --exit`), Openbox Restart (`openbox --restart`), Reboot (`systemctl reboot`), Shutdown (`systemctl poweroff`).

#### Scenario: Выключение машины
- **WHEN** пользователь кликает кнопку питания
- **THEN** система выполняет `systemctl poweroff`

### Requirement: Базовый стиль плиток
Каждая плитка MUST иметь чёрный полупрозрачный фон `$tile-bg` (rgba(0, 0, 0, 0.8)), рамку `$tile-border` (1px, $yellow), радиус 12px и внутренний отступ 9px, так что внешний отступ содержимого от края плитки равен 10px, а размеры плиток не зависят от рамки. Фон под каждым окном плитки MUST размываться композитором (правило picom `class_g ?= 'eww'` с `blur-background = true` и `corner-radius = 12`); промежутки между плитками не размываются, так как не принадлежат ни одному окну. Палитра — Tokyo Night: фон #1A1B26, текст #A9B1D6, акценты green/cyan/magenta/blue/yellow/red. Шрифт IosevkaTermSlab NF с фолбэком MesloLGMDZ Nerd Font, базовый размер 14px.

Заголовки плиток («СЕТЬ», «ДИСКИ», «ИЗБРАННОЕ», «ПРИЛОЖЕНИЯ») MUST быть приглушённого серого цвета (#565F89), полужирные.

#### Scenario: Единый вид плиток
- **WHEN** дашборд отрисован
- **THEN** все плитки имеют одинаковый фон, жёлтую рамку, радиус и отступы, заголовки читаются серым

### Requirement: Модульная структура конфигурации
Конфигурация MUST быть разложена по виджетам: каждый компонент занимает собственную папку `widgets/<имя>/` с его yuck-файлом (`defwidget` и относящиеся к нему `defpoll`/`deflisten`/`defvar`), scss-файлом стилей и — при наличии — собственными скриптами. Главный `eww.yuck` MUST подключать модули через `(include ...)`, главный `eww.scss` — через `@import`; в главных файлах остаются только глобальные переменные и базовые стили и объявления окон плиток `tile-*`. Окна отдельных компонентов (например, `netmenu`) объявляются в папке своего виджета.

Скрипты, используемые единственным виджетом, MUST располагаться в папке этого виджета; общие для нескольких виджетов (`scripts/appicon`, `scripts/popup`) — в корневом каталоге `scripts/`. Запускаемые eww команды MUST записываться путями относительно корня конфигурации: рабочий каталог команд равен каталогу конфигурации.

#### Scenario: Папка виджета самодостаточна
- **WHEN** разработчик правит скрипт или стили плитки погоды
- **THEN** все изменённые файлы лежат внутри `widgets/weather/`, общие файлы не затрагиваются

#### Scenario: Сборка из модулей
- **WHEN** выполняется `eww reload`
- **THEN** подключаются include-файлы всех папок `widgets/`, колонка отрисовывается целиком без пропущенных плиток

#### Scenario: Общий скрипт не задублирован
- **WHEN** два виджета используют один вспомогательный сценарий (резолвер иконок, popup)
- **THEN** в репозитории существует ровно одна его копия — в корневом `scripts/`
