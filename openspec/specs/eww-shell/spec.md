# eww-shell Specification

## Purpose

Каркас EWW-дашборда: окно у левого края экрана, вертикальная колонка плиток и статичные плитки (громкость, избранное, питание). Базовые стили — Tokyo Night. Специфицируется поведение под Openbox/X11, монитор 0.

## Requirements

### Requirement: Окно дашборда
Система MUST отображать единственное окно `dashboard` с геометрией: x = 5px, y = 0px, ширина 320px, привязка `left center`, монитор 0.

Окно MUST резервировать страту `left` шириной 330px, чтобы открытые окна не перекрывали колонку.

Окно MUST использовать тип `utility` со `stacking fg`. Использование типа `dock` ЗАПРЕЩЕНО: Openbox лишает dock-окна фокуса клавиатуры, и поле фильтра лаунчера перестаёт получать ввод.

#### Scenario: Открытые окна не залезают под колонку
- **WHEN** пользователь разворачивает любое окно на мониторе 0
- **THEN** оно располагается правее полосы 330px от левого края

#### Scenario: Поле поиска принимает клавиатуру
- **WHEN** пользователь кликает в поле фильтра лаунчера
- **THEN** окно получает фокус ввода и символы попадают в поле

### Requirement: Состав колонки
Колонка `dash` MUST содержать плитки в порядке сверху вниз: clock-tile, weather-tile, ряд [cpu-tile, ram-tile, gpu-tile], volume-tile, network-tile, disks-tile, favorites-tile, workspaces, launcher-tile, power-tile с межплиточным зазором 5px.

Полный ряд имеет ширину 320px; ряд из трёх шкал — 103px + 5px + 103px + 5px + 103px.

#### Scenario: Порядок фиксирован
- **WHEN** дашборд открывается
- **THEN** плитки следуют в порядке, указанном выше, без пропусков

### Requirement: Запуск при старте сессии
Демон eww и окно `dashboard` MUST запускаться автоматически при старте сессии Openbox без ручных действий пользователя.

Автозапуск MUST быть безопасным:
- если исполняемый файл `eww` отсутствует в `$PATH`, автозапуск MUST пропустить запуск демона и окна, не прерывая остальной старт сессии;
- повторное выполнение автозапуска (например, после `openbox --restart`) MUST NOT порождать второй экземпляр демона или дубликат окна `dashboard`.

#### Scenario: Вход в сессию
- **WHEN** пользователь логинится в Openbox-сессию
- **THEN** демон eww активен и колонка дашборда видима

#### Scenario: Перезапуск Openbox не дублирует дашборд
- **WHEN** выполняется `openbox --restart`, а демон eww уже работает
- **THEN** демон не запускается повторно, окно `dashboard` существует в единственном экземпляре

#### Scenario: Отсутствует исполняемый файл eww
- **WHEN** при старте сессии `eww` отсутствует в `$PATH`
- **THEN** автозапуск не запускает демон и окно и не сообщает об ошибке, остальные компоненты автостарта продолжают работу

### Requirement: Опросы только для используемых переменных
Конфигурация MUST учитывать ограничение eww: poll запускается лишь когда его переменная используется в открытом окне. Переменная `network-sync` (страховка опроса сети) MUST иметь скрытую ссылку внутри network-tile (`label :visible false`), иначе её poll не выполняется.

#### Scenario: Страховочный poll живёт
- **WHEN** открыто окно dashboard
- **THEN** poll `network-sync` исполняется каждые 10 секунд

### Requirement: Плитка громкости
volume-tile MUST показывать кнопку динамика и горизонтальный scale, привязанный к переменной `current-volume` (poll 1s → `widgets/volume/scripts/volume`, всегда валидное число). Диапазон scale: 0–101 (допускается громкость свыше 100%).

Кнопка по клику MUST вызывать общий `scripts/popup audio` (pavucontrol) с тултипом «Микшер». Перемещение ползунка MUST выполнять `pactl set-sink-volume @DEFAULT_SINK@ {}%`.

#### Scenario: Регулировка громкости
- **WHEN** пользователь тянет ползунок громкости
- **THEN** громкость default sink меняется соответственно позиции

### Requirement: Плитка избранного
favorites-tile MUST содержать три кнопки, каждая открывает yazi в wezterm с рабочим каталогом: `~`, `~/Загрузки`, `~/.config`.

#### Scenario: Переход в загрузки
- **WHEN** пользователь кликает «󰉋 ~/Загрузки»
- **THEN** открывается терминал wezterm с yazi в ~/Загрузки

### Requirement: Плитка питания
power-tile MUST содержать четыре кнопки с тултипами: Lock Screen (`loginctl lock-session`), Logout (`openbox --exit`), Openbox Restart (`openbox --restart`), Shutdown (`systemctl poweroff`).

#### Scenario: Выключение машины
- **WHEN** пользователь кликает кнопку питания
- **THEN** система выполняет `systemctl poweroff`

### Requirement: Базовый стиль плиток
Каждая плитка MUST иметь фон `$black` (#24283B), радиус 12px, внутренний отступ 10px. Палитра — Tokyo Night: фон #1A1B26, текст #A9B1D6, акценты green/cyan/magenta/blue/yellow/red. Шрифт IosevkaTermSlab NF с фолбэком MesloLGMDZ Nerd Font, базовый размер 14px.

Заголовки плиток («СЕТЬ», «ДИСКИ», «ИЗБРАННОЕ», «ПРИЛОЖЕНИЯ») MUST быть приглушённого серого цвета (#565F89), полужирные.

#### Scenario: Единый вид плиток
- **WHEN** дашборд отрисован
- **THEN** все плитки имеют одинаковый фон, радиус и отступы, заголовки читаются серым

### Requirement: Модульная структура конфигурации
Конфигурация MUST быть разложена по виджетам: каждый компонент занимает собственную папку `widgets/<имя>/` с его yuck-файлом (`defwidget` и относящиеся к нему `defpoll`/`deflisten`/`defvar`), scss-файлом стилей и — при наличии — собственными скриптами. Главный `eww.yuck` MUST подключать модули через `(include ...)`, главный `eww.scss` — через `@import`; в главных файлах остаются только глобальные переменные и базовые стили, композиция колонки `dash` и окно `dashboard`. Окна отдельных компонентов (например, `netmenu`) объявляются в папке своего виджета.

Скрипты, используемые единственным виджетом, MUST располагаться в папке этого виджета; общие для нескольких виджетов (`scripts/appicon`, `scripts/popup`) — в корневом каталоге `scripts/`. Запускаемые eww команды MUST записываться путями относительно корня конфигурации: рабочий каталог команд равен каталогу конфигурации.

#### Scenario: Папка виджета самодостаточна
- **WHEN** разработчик правит скрипт или стили плитки погоды
- **THEN** все изменённые файлы лежат внутри `widgets/weather/`, общие файлы не затрагиваются

#### Scenario: Сборка из модулей
- **WHEN** выполняется `eww reload`
- **THEN** подключаются include-файлы всех папок `widgets/`, колонка отрисовывается целиком без пропущенных плиток

#### Scenario: Общий скрипт не задублирован
- **WHEN** два виджета используют один вспомогательный сценарий (резолвер иконок, popup)
- **THEN** в репозитории существует ровно одна его копия — в корневом `scripts/`
