# qs-monitors Specification

## Purpose

Метрики системы в панели Quickshell сессии Hyprland: круговые шкалы загрузки CPU, RAM и GPU с температурной подсветкой и плитка дисков с полосами заполнения. Метрики поставляют скрипты панели, каждый из которых за один вызов выдаёт одну строку JSON с числом и классом. Аппаратные допущения: CPU AMD (k10temp), GPU NVIDIA (nvidia-smi).

## Requirements

### Requirement: Скрипты метрик панели
Метрики шкал и дисков MUST вычисляться скриптами из каталога `dot_config/quickshell/panel/scripts/` (в `$HOME` — `~/.config/quickshell/panel/scripts/`, пути без префикса `executable_`). Скрипт каждой метрики MUST за один вызов выводить ровно одну строку JSON с числовым значением и температурным классом (`{"value":<число>,"class":"<класс>"}`); панель MUST NOT вызывать для одной метрики отдельные скрипты за значением и за классом. Скрипты MUST быть переносимыми оболочечными сценариями (`sh -n` без ошибок).

#### Scenario: Вызов скрипта метрики
- **WHEN** скрипт загрузки CPU запущен из терминала
- **THEN** в выводе одна строка JSON с полями `value` (целое число 0–100) и `class` (одно из `t-low`, `t-mid`, `t-high`, `t-crit`), которая разбирается без ошибок

#### Scenario: Ошибка в выводе скрипта
- **WHEN** скрипт завершился с ошибкой или вывел строку, не являющуюся JSON
- **THEN** панель сохраняет предыдущее значение шкалы, не завершается и не выводит окно с ошибкой; следующий опрос выполняется по расписанию

### Requirement: Загрузка CPU
Загрузка CPU MUST вычисляться как доля занятого процессорного времени по разности двух чтений `/proc/stat` с промежутком в 1 секунду, в процентах 0–100. Панель MUST обновлять значение каждые 3 секунды.

#### Scenario: Простой системы
- **WHEN** все ядра простаивают между двумя чтениями
- **THEN** шкала CPU показывает значение, близкое к 0, с классом `t-low`

#### Scenario: Полная загрузка
- **WHEN** все ядра заняты между двумя чтениями
- **THEN** шкала CPU показывает значение, близкое к 100, с классом `t-crit`

### Requirement: Использование RAM
Использование RAM MUST вычисляться из `/proc/meminfo` по формуле `(MemTotal − MemAvailable) / MemTotal × 100` с обновлением каждые 3 секунды. Рядом с именем шкалы MUST отображаться общий объём памяти в ГиБ (`MemTotal / 1048576`, целое число с суффиксом «G»), обновляемый раз в час.

#### Scenario: Память исчерпана
- **WHEN** MemAvailable равно 0
- **THEN** шкала RAM показывает «100%» с классом `t-crit`

#### Scenario: Общий объём
- **WHEN** MemTotal равно 65 GiB в килобайтах
- **THEN** в заголовке шкалы RAM виден текст «65G»

### Requirement: Загрузка и температура GPU, температура CPU
Загрузка GPU MUST браться из `nvidia-smi --query-gpu=utilization.gpu` с обновлением каждые 3 секунды, температура GPU — из `nvidia-smi --query-gpu=temperature.gpu` каждые 5 секунд. Температура CPU MUST браться из `sensors -u k10temp-pci-00c3` (датчик Tctl) каждые 5 секунд. Если утилита недоступна или завершилась с ошибкой, скрипт MUST вывести значение 0 с классом `t-low`, а панель MUST продолжать работу.

#### Scenario: Отсутствие nvidia-smi
- **WHEN** утилита `nvidia-smi` недоступна или завершается с ошибкой
- **THEN** шкала GPU показывает «0%», подпись температуры — «0°», панель продолжает работать, остальные шкалы обновляются

#### Scenario: Датчик k10temp прочитан
- **WHEN** `sensors -u k10temp-pci-00c3` сообщает Tctl 61,5 °C
- **THEN** в заголовке шкалы CPU виден текст «61°»

### Requirement: Температурные классы
Значения загрузки CPU, RAM, GPU и температур MUST переводиться в классы по порогам: меньше 50 — `t-low`, меньше 75 — `t-mid`, меньше 90 — `t-high`, иначе `t-crit`. Класс MUST задавать цвет дуги шкалы и цвет подписи температуры: `t-low` #39FF14, `t-mid` #EAFF00, `t-high` #FF9500, `t-crit` #FF073A. Имена шкал MUST иметь постоянные цвета: CPU — #FF073A, RAM — #2E9FFF (общий объём — цветом основного текста #A9B1D6), GPU — #39FF14.

#### Scenario: Перегрев
- **WHEN** Tctl достигла 92 °C
- **THEN** подпись температуры CPU окрашена в #FF073A (`t-crit`)

#### Scenario: Граница порога
- **WHEN** загрузка RAM равна ровно 75
- **THEN** дуга шкалы RAM окрашена в #FF9500 (`t-high`)

### Requirement: Круговые шкалы
Панель MUST показывать три плитки шкал (CPU, RAM, GPU) размером 100×100 px в порядке CPU, RAM, GPU на месте, заданном спецификацией qs-shell. Каждая плитка MUST содержать заголовок с именем шкалы и температурой (для RAM — общим объёмом) и круговую шкалу размером 70×70 px с толщиной дуги 10 px по центру плитки. В центре круга MUST быть подпись `<значение>%` полужирным шрифтом 16 px цветом основного текста; заголовок — полужирным 15 px. Дуга MUST заполняться пропорционально значению 0–100 по часовой стрелке, фон дуги — rgba(169,177,214,0.15); цвет заполненной части дуги задаётся температурным классом значения.

#### Scenario: Центральная подпись
- **WHEN** загрузка CPU равна 42
- **THEN** в центре круга виден текст «42%», дуга заполнена на 42 % и окрашена в #39FF14

#### Scenario: Плитки в колонке
- **WHEN** панель открыта
- **THEN** под плиткой погоды видны три плитки шкал CPU, RAM, GPU с заголовками «CPU 61°», «RAM 65G», «GPU 45°»

### Requirement: Плитка дисков
Плитка дисков MUST показывать заголовок «ДИСКИ» и по одной строке на каждое блочное устройство из `lsblk -J -o NAME,FSTYPE,LABEL,MOUNTPOINT`, у которого задан тип файловой системы, за исключением устройств `loop*`, `zram*`, `ram*` и записей с типом `swap`. Список MUST обновляться каждые 30 секунд; скрипт MUST выводить одну строку JSON — массив записей с именем, признаком монтирования, процентом заполнения, свободным местом и типом файловой системы. Имя строки — LABEL устройства, а при его отсутствии имя устройства без префикса `/dev`.

Для смонтированного устройства строка MUST содержать имя (ширина не меньше 70 px), горизонтальную полосу заполнения высотой 10 px со скруглением 5 px (доля заполнения — колонка use% из `df -Ph`, не больше 100; заполненная часть #7AA2F7 на фоне #1A1B26) и свободное место из колонки avail серым (#565F89, ширина не меньше 55 px). Для несмонтированного устройства строка MUST содержать имя слева и тип файловой системы справа серым шрифтом 12 px без полосы. Если `df` не вернул данных по устройству, полоса MUST быть пустой, а вместо свободного места показан знак «?».

#### Scenario: Смонтированный раздел
- **WHEN** `lsblk` вернул раздел с меткой «data», смонтированный в `/mnt/data`, а `df -Ph` показывает 63 % занятости и 120G свободных
- **THEN** строка показывает «data», полосу, заполненную на 63 %, и текст «120G»

#### Scenario: Несмонтированный раздел ntfs
- **WHEN** `lsblk` вернул раздел с fstype=ntfs без точки монтирования
- **THEN** строка показывает имя устройства слева и текст «ntfs» справа, без полосы

#### Scenario: Скрытые служебные устройства
- **WHEN** в системе есть устройства loop, zram и раздел подкачки
- **THEN** они не отображаются в списке

#### Scenario: df недоступен
- **WHEN** устройство смонтировано, но `df -Ph` для него завершился с ошибкой
- **THEN** строка показывает имя, пустую полосу и знак «?» вместо свободного места
