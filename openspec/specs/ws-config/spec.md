# ws-config Specification

## Purpose

Рукописный конфиг демона workspaced: шаблоны геометрии, приложения с окружением и цепочками клавиш, workspace с набором приложений по ячейкам, привязки; правила подстановки, проверки и записи обратно по команде сохранения.

## Requirements

### Requirement: Файл конфига и его разделы
Демон MUST читать конфиг из `~/.config/workspaced/config.toml` (файл под chezmoi). Файл MUST состоять из разделов: `[env]` — общие переменные окружения; `[keys]` — цепочки служебных действий `save_session`, `save_workspace`, `sessions`, `next_workspace` и список `reserved` зарезервированных сочетаний; `[templates.<имя>]` — шаблон геометрии с полем `main` (имя главной ячейки) и таблицей `cells`, где каждая ячейка — прямоугольник `{ x, y, w, h }`; `[apps.<имя>]` — приложение с полями `cmd` (команда запуска), `args` (массив), `cwd`, `env` (таблица), `chain`, `class` и `title` (регулярные выражения для захвата открытого окна по классу и заголовку; `title` без `class` не допускается), `dialog_title` (регулярное выражение по заголовку собственного диалога приложения; без `class` не допускается), `family` (имя приложения-семейства, если это приложение — его вариант) и `rect` (прямоугольник `{ x, y, w, h }` — положение и размер окна по умолчанию, когда workspace об этом приложении ничего не говорит); `[startup]` — `workspace` (имя существующего workspace, который поднимается при старте демона) и `desktop` (стол 1…8, по умолчанию 1); `[workspaces.<имя>]` — workspace с полями `template` (обязательно), `main` (имя приложения в главной ячейке по умолчанию), `icon`, `chain`, `env`, `mode` и таблицей `apps`, где значение — имя ячейки шаблона либо таблица `{ rect = { x, y, w, h } }` для окна вне ячеек; `[[binds]]` — записи с полем `chain`, ровно одним из полей действия `action`, `exec`, `dispatch`, `lua` и необязательными `range`, `locked`, `repeating`, `mouse`, `release`. В корне файла MUST быть допустим необязательный список `ignore_classes` — регулярные выражения, которые сопоставляются с классом окна целиком; окно с подходящим классом демон MUST NOT принимать в workspace ни при каких условиях (спецификация ws-daemon, «Посторонние окна» и «Захват открытых окон приложения»). По умолчанию список пуст. Оба поля, `dialog_title` и `ignore_classes`, нужны потому, что признака диалога композитор не сообщает; выражения с ошибкой MUST приводить к отказу с указанием приложения или списка. Поле `mode` MUST задавать поведение клавиши приложения в этом workspace (спецификация ws-daemon, «Цепочка приложения» и «Расстановка окон») и принимать значения `swap` — обмен ячеек — и `stack` — подъём окна без переноса; по умолчанию MUST действовать `swap`, а иное значение MUST приводить к отказу с указанием workspace, полученного значения и допустимых. Порядок записей в таблице `apps` workspace MUST сохраняться таким, как в файле: по нему конец цикла клавиши выбирает следующее приложение workspace, а приложения, добавленные сессией, MUST идти после описанных в файле. У приложения MUST быть задано хотя бы одно из полей `cmd` и `class`: без `cmd` приложение не открывает новых окон и только собирает подходящие по `class`, без `class` окно узнаётся лишь по запуску. Поле `family` MUST называть другое приложение того же файла, у которого самого нет `family`: уровней ровно два — семейство и его варианты. Имя приложения MUST NOT содержать двоеточие и знак `#`: этими знаками демон отделяет части тега экземпляра. Прямоугольники ячеек, `rect` приложения и `rect` в таблице `apps` workspace — это положение и размер окна на экране как есть: демон MUST передавать их композитору без прибавления или вычитания отступов. Координаты прямоугольников MUST отсчитываться от левого верхнего угла экрана: целое число — пиксели, строка с процентом — доля ширины или высоты монитора; смешивать формы в одном прямоугольнике MUST быть можно. Координаты MUST допускать отрицательные значения, а размеры — значения больше экрана: окно может выходить за его края частично с любой стороны, демон MUST передавать такие значения композитору без обрезания и без сдвига внутрь экрана. Необязательный ключ `gap` в корне файла задаёт зазор в пикселях только для команд `half`, `place` и `maximize`, которые строят геометрию от рабочей области; по умолчанию 0. Неизвестные ключи MUST приводить к предупреждению в журнале, но не к отказу.

### Requirement: Окружение и подстановка
Окружение приложения MUST складываться из трёх слоёв в порядке возрастания приоритета: `[env]` корня файла, `env` workspace, из которого приложение запускается, `env` самого приложения; значение нижнего слоя перекрывает верхний, поверх окружения демона. В значениях `args`, `cwd` и `env` MUST подставляться `~` в начале строки (домашний каталог) и `$ИМЯ` (переменная сложенного окружения, при отсутствии — окружения демона, при отсутствии и там — пустая строка). Подстановка MUST выполняться в момент запуска, а не при чтении конфига, чтобы одно приложение получало разное окружение в разных workspace.

#### Scenario: Переменная workspace в аргументах приложения
- **WHEN** у workspace задано `env = { ROOT = "~/work/front-end" }`, а у приложения `args = ["--cwd", "$ROOT"]`
- **THEN** процесс запускается с аргументом `--cwd /home/mne/work/front-end` и переменной `ROOT=/home/mne/work/front-end` в окружении

#### Scenario: Приложение перекрывает переменную workspace
- **WHEN** в `[env]` корня `NODE_ENV = "production"`, у workspace `NODE_ENV = "development"`, а у приложения `NODE_ENV = "test"`
- **THEN** процесс получает `NODE_ENV=test`

### Requirement: Цепочки клавиш и привязки
Цепочка MUST записываться строкой сочетаний через пробел, где сочетание — модификаторы и клавиша в синтаксисе Hyprland через `+` (`"SUPER+W 3 f"`); одиночное сочетание (`"SUPER+Return"`, `"XF86AudioMute"`, `"SUPER+mouse:272"`) — цепочка из одного звена. Короткая форма `chain` у workspace означает действие «поднять на текущем столе», у приложения — «вести цикл по его экземплярам в режиме его workspace» по правилам ws-daemon. Запись `[[binds]]` MUST принимать ровно одно действие: `action` — таблица с любым сочетанием ключей `desktop` (1…8), `workspace` и `app`, таблица `{ half = "left" | "right" | "up" | "down" }`, таблица `{ place = "top-left" | "top-center" | "top-right" | "bottom-left" | "bottom-center" | "bottom-right" | "center" | "full" }` таблица `{ move = <стол 1…8> }` (перенести активный workspace текущего стола на этот стол) либо строка `"sessions"`, `"save-session"`, `"save-workspace"`, `"next-workspace"`, `"maximize"`, `"arrange"`, `"detach"` (убрать активное окно из активного workspace текущего стола, спецификация ws-daemon, «Отделение окна»); `exec` — командная строка, запускаемая композитором; `dispatch` — выражение диспетчера Hyprland без префикса `hl.dsp.` (`"window.close()"`) либо массив таких выражений, выполняемых по порядку одним вызовом; `lua` — тело функции на Lua, выполняемое композитором при нажатии. Флаги `locked` (действует при заблокированном экране), `repeating` (повторяется при удержании), `mouse` (привязка к кнопке мыши с удержанием), `release` (срабатывает при отпускании) MUST передаваться композитору; `mouse` MUST быть допустим только у цепочки из одного звена. Поле `range = [от, до]` MUST разворачивать запись в серию: для каждого целого из диапазона подстрока `$n` в `chain`, `exec`, `dispatch` и в значении действия `move` заменяется числом. Значение `move` MUST читаться числом или строкой и MUST проверяться после разворачивания серии: до него на месте номера стоит `$n`. Стол вне диапазона 1…8 MUST приводить к отказу с указанием цепочки и полученного значения. Цепочки MUST быть произвольными; демон MUST NOT навязывать смысл сегментам. Одна цепочка MUST NOT совпадать с другой или быть её началом, в том числе одиночное сочетание с первым звеном цепочки; две цепочки с общим первым звеном и разными последующими MUST быть допустимы; два приложения с одной цепочкой внутри одного workspace MUST считаться ошибкой; одна цепочка у приложений из разных workspace MUST быть допустима. Сочетание из списка `reserved` раздела `[keys]` MUST NOT встречаться ни в одной цепочке. Демон MUST проверять эти условия при чтении и при ошибке называть обе конфликтующие записи либо запись и зарезервированное сочетание.

- **THEN** `workspaced check` завершается с ошибкой о том, что флаг `mouse` допустим только у одиночного сочетания

### Requirement: Генерация привязок для Hyprland
Команда `workspaced keys --lua` MUST печатать код Lua для конфига Hyprland, который объявляет все привязки конфига: одиночные сочетания — прямыми привязками с их флагами, цепочки — подкартами для каждого префикса, где последнее сочетание выполняет действие и закрывает подкарту, а `Escape` в любой подкарте закрывает её без действия. Действия демона MUST вызывать соответствующую подкоманду; `exec`, `dispatch` и `lua` MUST выполняться композитором без участия демона. Код MUST зависеть только от конфига и быть одинаковым при повторных вызовах с тем же файлом. При успешной генерации команда MUST записать копию кода в `~/.local/state/workspaced/keys.lua`. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr, не печатать частичный код и не трогать копию. Команда `workspaced keys --list` MUST печатать таблицу всех привязок: цепочка, действие и источник (раздел конфига), в порядке следования в файле.

#### Scenario: Цепочка из трёх сочетаний
- **WHEN** в конфиге есть `[[binds]]` с `chain = "SUPER+W 3 f"` и `action = { desktop = 3, workspace = "dev-front" }`
- **THEN** после `hyprctl reload` нажатие Super+W, затем 3, затем f поднимает `dev-front` на столе 3, а нажатие Super+W, затем Escape ничего не делает

#### Scenario: Перезагрузка при ошибке конфига
- **WHEN** конфиг содержит ошибку и выполнена `hyprctl reload`
- **THEN** `workspaced keys --lua` завершается с ошибкой, `keys.lua` не изменяется, конфиг Hyprland загружает привязки из копии, а в журнале Hyprland есть сообщение об ошибке от `workspaced keys`

#### Scenario: Копия после успешной генерации
- **WHEN** конфиг корректен и выполнена `workspaced keys --lua`
- **THEN** содержимое `~/.local/state/workspaced/keys.lua` совпадает с напечатанным кодом

#### Scenario: Список привязок
- **WHEN** выполнена `workspaced keys --list`
- **THEN** в выводе есть строка с `SUPER+Return`, действием `exec wezterm-gui` и источником `binds`, и строка с `SUPER+W d`, действием `raise dots` и источником `workspaces.dots`

### Requirement: Слежение за конфигом
Демон MUST замечать изменение файла конфига без перезапуска, перечитывать его и, если файл корректен, применять: новые и изменённые workspace и приложения доступны следующей цепочкой, а привязки обновляются вызовом `hyprctl reload`. Тот же вызов демон MUST делать один раз при старте, после удачной загрузки конфига: файл могли поправить, пока демон не работал, а бинарник — обновить до версии с новыми действиями, и привязки композитора тогда отстали бы от конфига. Если композитор в этот момент недоступен, демон MUST записать предупреждение и продолжить работу, а повторять вызов по сроку MUST NOT. Перечитывание MUST запускаться по событиям файловой системы, означающим завершённую запись файла: закрытие файла, открытого на запись, и появление файла под своим именем после записи во временный файл с переименованием. События, приходящие посреди записи, демон MUST NOT учитывать, а задержку вместо них применять MUST NOT: одно сохранение файла MUST давать ровно одно перечитывание. При перечитывании демон MUST сравнить раздел каждого workspace в прежнем и новом файле и снять текущие назначения ячеек у тех workspace, чей раздел изменился или исчез: их назначения MUST быть собраны заново из нового файла при следующем обращении, и правка файла MUST возвращать расстановку без перезапуска демона. Назначения workspace, раздел которых не менялся, MUST сохраняться, чтобы правка одного workspace не сбрасывала обмен ячеек в другом. После каждого перечитывания демон MUST сверить теги открытых окон и записи ожидания с составом приложений: окна приложений, которых в конфиге не стало, MUST становиться посторонними, а ожидания их окон MUST сниматься (требование «Посторонние окна» спецификации ws-daemon). При ошибке демон MUST оставить прежний конфиг и записать ошибку в журнал.

#### Scenario: Новый workspace добавлен вручную
- **WHEN** пользователь дописал в конфиг workspace `notes` с `chain = "SUPER+W n"` и сохранил файл
- **THEN** демон перечитывает конфиг по событию завершения записи, в журнале одна строка о перечитывании, `workspaced status --json` содержит `notes`, а Super+W, n поднимает его

#### Scenario: Запись во временный файл с переименованием
- **WHEN** конфиг применён командой `chezmoi apply`, которая пишет временный файл и переименовывает его на место конфига
- **THEN** демон перечитывает конфиг один раз, неполный файл не читается, `hyprctl reload` вызывается один раз

#### Scenario: Перезапуск демона с новым конфигом при живом композиторе
- **WHEN** в конфиг добавлена запись `[[binds]]` с действием, которого прежний бинарник не знал, и демон перезапущен с новым бинарником
- **THEN** демон при старте вызывает `hyprctl reload config-only`, и число привязок в `hyprctl binds` совпадает с выводом `workspaced keys --list` с поправкой на служебные привязки подкарт, а новое сочетание работает нажатием без ручной перезагрузки конфига композитора

#### Scenario: Откат правки возвращает расстановку
- **WHEN** в разделе `work` ячейка `chromium` заменена прямоугольником, `work` поднят, затем правка отменена и файл сохранён
- **THEN** назначения `work` снова берутся из файла, и следующее поднятие `work` ставит Chromium в ячейку `left`; назначения соседнего workspace `surf` не сбрасываются

#### Scenario: Перечитывание освобождает окно исчезнувшего приложения
- **WHEN** приложение `alacritty` удалено из конфига, а его окно на столе несёт тег `app:alacritty#1`
- **THEN** после перечитывания конфига тег с окна снят и окно считается посторонним; подробности — в требовании «Посторонние окна» спецификации ws-daemon

### Requirement: Запись по команде сохранения
По цепочке `save_workspace` или команде `workspaced save-workspace` демон MUST записать в раздел активного workspace текущего стола: назначение приложений по ячейкам (`apps`), `main` по текущей главной ячейке, `rect` у приложений, окна которых не совпадают со своей ячейкой, дополнительные приложения сессии этого workspace и свободные окна, открытые на текущем столе. Для свободного окна и для дополнительного приложения сессии демон MUST сначала найти среди всех приложений конфига то, которому окно подходит по выражениям `class` и, если оно задано, `title`: поиск MUST идти сначала по приложениям-вариантам, затем по семействам, внутри каждой группы по именам, и найденное приложение MUST быть записано под своим именем с `rect`; новое приложение MUST заводиться только тогда, когда подходящего не нашлось, — с `cmd`, `args`, `cwd` из процесса окна (по правилу требования «Файлы сессий» спецификации ws-sessions, по которому окно из песочницы flatpak записывается командой `flatpak run`) и `rect`. Окно, которое в workspace не принимается (класс из `ignore_classes`, заголовок под `dialog_title` его приложения), демон MUST NOT записывать: в конфиге ему не место, как и в составе workspace. Дополнительные приложения сессии записанного workspace MUST после записи быть сняты: они перешли в конфиг. Если у приложения несколько окон, в `rect` MUST записываться место первого экземпляра, а остальные его окна MUST NOT попадать в файл отдельными записями. Записанное окно MUST получить тег экземпляра этого приложения и перестать быть свободным, а назначения ячеек workspace MUST быть пересобраны из записанного конфига без перезапуска демона. Свободные окна на других столах и окна на `special:hidden` MUST NOT записываться. Остальные разделы и workspace, комментарии и порядок ключей MUST сохраняться. Запись MUST быть атомарной; перед записью файл MUST быть перечитан, и если он изменился с момента последнего чтения, команда MUST быть отклонена с сообщением, а конфиг перечитан. После удачной записи команда MUST NOT перечитывать конфиг сама: перечитывание приходит событием завершённой записи файла, одно на одно сохранение. Без команды сохранения демон MUST NOT изменять файл.

#### Scenario: Сохранение после обмена ячеек
- **WHEN** в workspace `dev-front` терминал переведён в главную ячейку цепочкой приложения и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` `main = "terminal-front"`, назначения `apps` соответствуют экрану, комментарии в файле на месте, остальные workspace не изменились

#### Scenario: Сохранение приложения с двумя окнами
- **WHEN** в workspace `work` у `chromium` два окна: первый экземпляр сдвинут пользователем, второй стоит в ячейке `left`, и вызвана команда сохранения
- **THEN** у `chromium` записан `rect` первого экземпляра, второй записи о `chromium` в файле нет, и следующее поднятие `work` ставит оба окна в этот прямоугольник

#### Scenario: Сохранение постороннего окна
- **WHEN** на столе с активным `dev-front` из лаунчера открыт калькулятор, не описанный в конфиге, он принят дополнительным приложением сессии, перемещён пользователем, и вызвана команда сохранения workspace
- **THEN** в конфиге у `dev-front` появляется приложение с `cmd` калькулятора и `rect` его текущего положения, окно несёт тег этого приложения, а следующий `raise` `dev-front` ставит калькулятор на это место

#### Scenario: Дополнительные приложения сессии переходят в конфиг
- **WHEN** в `work` приняты калькулятор и окно `chrome-ai`, затем вызвана цепочка `save_workspace`
- **THEN** в конфиге у `work` записаны оба приложения, в `[apps]` появилось описание калькулятора, дополнительных приложений сессии у `work` больше нет, и следующая запись снимка сессии их не содержит

#### Scenario: Диалог в конфиг не попадает
- **WHEN** на столе с активным `surf` открыт диалог выбора файла класса `termfilechooser`, перечисленного в `ignore_classes`, и вызвана команда сохранения workspace
- **THEN** диалог в конфиг не записан, приложения по его классу в `[apps]` не появилось, окно осталось свободным

#### Scenario: Окно подходит приложению другого workspace
- **WHEN** на столе с активным `work` открыто свободное окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai` из workspace `surf`, и вызвана команда сохранения
- **THEN** в таблице `apps` у `work` появляется запись `chrome-ai` с `rect` окна, нового приложения по классу окна в `[apps]` не появляется, окно несёт тег `app:chrome-ai#1`

#### Scenario: Одно перечитывание на одну запись
- **WHEN** вызвана цепочка `save_workspace` и файл конфига записан
- **THEN** в журнале демона одна строка о перечитывании конфига, `hyprctl reload config-only` вызывается один раз

#### Scenario: Свободное окно на другом столе не записывается
- **WHEN** на столе 1 активен `dev-front`, на столе 3 без активного workspace открыт свободный терминал, и на столе 1 вызвана команда сохранения
- **THEN** терминал в конфиг не попадает и остаётся свободным

#### Scenario: Работа без сохранения
- **WHEN** пользователь два часа поднимает workspace, меняет ячейки и двигает окна, не вызывая команду сохранения
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст
