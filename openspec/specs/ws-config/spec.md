# ws-config Specification

## Purpose

Рукописный конфиг демона workspaced: шаблоны геометрии, приложения с окружением и цепочками клавиш, workspace с набором приложений по ячейкам, привязки; правила подстановки, проверки и записи обратно по команде сохранения.

## Requirements

### Requirement: Файл конфига и его разделы
Демон MUST читать конфиг из `~/.config/workspaced/config.toml` (файл под chezmoi). Файл MUST состоять из разделов: `[env]` — общие переменные окружения; `[keys]` — цепочки служебных действий `save_workspace`, `sessions`, `next_workspace` и список `reserved` зарезервированных сочетаний; `[templates.<имя>]` — шаблон геометрии с полем `main` (имя главной ячейки) и таблицей `cells`, где каждая ячейка — прямоугольник `{ x, y, w, h }`; `[apps.<имя>]` — приложение с полями `cmd` (обязательно), `args` (массив), `cwd`, `env` (таблица), `chain`; `[workspaces.<имя>]` — workspace с полями `template` (обязательно), `main` (имя приложения в главной ячейке по умолчанию), `icon`, `chain`, `env` и таблицей `apps`, где значение — имя ячейки шаблона либо таблица `{ rect = { x, y, w, h } }` для окна вне ячеек; `[[binds]]` — записи с полем `chain`, ровно одним из полей действия `action`, `exec`, `dispatch`, `lua` и необязательными `range`, `locked`, `repeating`, `mouse`, `release`. Координаты прямоугольников MUST отсчитываться от левого верхнего угла экрана: целое число — пиксели, строка с процентом — доля ширины или высоты монитора; смешивать формы в одном прямоугольнике MUST быть можно. Координаты MUST допускать отрицательные значения, а размеры — значения больше экрана: окно может выходить за его края частично с любой стороны, демон MUST передавать такие значения композитору без обрезания и без сдвига внутрь экрана. Необязательный ключ `gap` в корне файла задаёт зазор в пикселях, на который каждое окно отступает внутрь своей ячейки; по умолчанию 0. Неизвестные ключи MUST приводить к предупреждению в журнале, но не к отказу.

#### Scenario: Минимальный конфиг
- **WHEN** файл содержит один шаблон `halves` с ячейками `left` и `right`, одно приложение `terminal` с `cmd = "wezterm-gui"` и один workspace `work` с `template = "halves"`, `main = "terminal"` и `apps = { terminal = "right" }`
- **THEN** `workspaced check` завершается успешно и выводит один workspace, одно приложение и один шаблон

#### Scenario: Проценты и пиксели в одной ячейке
- **WHEN** ячейка задана как `{ x = 330, y = 0, w = "50%", h = "100%" }` на мониторе 3840×2160
- **THEN** демон считает прямоугольник 330,0 размером 1920×2160

#### Scenario: Окно шире экрана со сдвигом за левый край
- **WHEN** ячейка задана как `{ x = -400, y = -150, w = 5000, h = 2600 }` и в неё поставлено окно при `gap = 0`
- **THEN** `hyprctl clients -j` показывает у окна положение −400,−150 и размер 5000×2600

#### Scenario: Ссылка на несуществующую ячейку
- **WHEN** workspace ссылается на ячейку `top`, которой нет в его шаблоне
- **THEN** `workspaced check` завершается с ошибкой, называющей workspace, приложение и ячейку; демон продолжает работать с прежним конфигом

#### Scenario: Запись привязки с двумя действиями
- **WHEN** запись `[[binds]]` содержит и `exec`, и `dispatch`
- **THEN** `workspaced check` завершается с ошибкой, называющей цепочку записи и оба поля

### Requirement: Окружение и подстановка
Окружение приложения MUST складываться из трёх слоёв в порядке возрастания приоритета: `[env]` корня файла, `env` workspace, из которого приложение запускается, `env` самого приложения; значение нижнего слоя перекрывает верхний, поверх окружения демона. В значениях `args`, `cwd` и `env` MUST подставляться `~` в начале строки (домашний каталог) и `$ИМЯ` (переменная сложенного окружения, при отсутствии — окружения демона, при отсутствии и там — пустая строка). Подстановка MUST выполняться в момент запуска, а не при чтении конфига, чтобы одно приложение получало разное окружение в разных workspace.

#### Scenario: Переменная workspace в аргументах приложения
- **WHEN** у workspace задано `env = { ROOT = "~/work/front-end" }`, а у приложения `args = ["--cwd", "$ROOT"]`
- **THEN** процесс запускается с аргументом `--cwd /home/mne/work/front-end` и переменной `ROOT=/home/mne/work/front-end` в окружении

#### Scenario: Приложение перекрывает переменную workspace
- **WHEN** в `[env]` корня `NODE_ENV = "production"`, у workspace `NODE_ENV = "development"`, а у приложения `NODE_ENV = "test"`
- **THEN** процесс получает `NODE_ENV=test`

### Requirement: Цепочки клавиш и привязки
Цепочка MUST записываться строкой сочетаний через пробел, где сочетание — модификаторы и клавиша в синтаксисе Hyprland через `+` (`"SUPER+W 3 f"`); одиночное сочетание (`"SUPER+Return"`, `"XF86AudioMute"`, `"SUPER+mouse:272"`) — цепочка из одного звена. Короткая форма `chain` у workspace означает действие «поднять на текущем столе», у приложения — «сделать главным» по правилам ws-daemon. Запись `[[binds]]` MUST принимать ровно одно действие: `action` — таблица с любым сочетанием ключей `desktop` (1…8), `workspace` и `app`, таблица `{ half = "left" | "right" | "up" | "down" }` либо строка `"sessions"`, `"save-workspace"`, `"next-workspace"`; `exec` — командная строка, запускаемая композитором; `dispatch` — выражение диспетчера Hyprland без префикса `hl.dsp.` (`"window.close()"`) либо массив таких выражений, выполняемых по порядку одним вызовом; `lua` — тело функции на Lua, выполняемое композитором при нажатии. Флаги `locked` (действует при заблокированном экране), `repeating` (повторяется при удержании), `mouse` (привязка к кнопке мыши с удержанием), `release` (срабатывает при отпускании) MUST передаваться композитору; `mouse` MUST быть допустим только у цепочки из одного звена. Поле `range = [от, до]` MUST разворачивать запись в серию: для каждого целого из диапазона подстрока `$n` в `chain`, `exec` и `dispatch` заменяется числом. Цепочки MUST быть произвольными; демон MUST NOT навязывать смысл сегментам. Одна цепочка MUST NOT совпадать с другой или быть её началом, в том числе одиночное сочетание с первым звеном цепочки; два приложения с одной цепочкой внутри одного workspace MUST считаться ошибкой; одна цепочка у приложений из разных workspace MUST быть допустима. Сочетание из списка `reserved` раздела `[keys]` MUST NOT встречаться ни в одной цепочке. Демон MUST проверять эти условия при чтении и при ошибке называть обе конфликтующие записи либо запись и зарезервированное сочетание.

#### Scenario: Одна цепочка у двух приложений в разных workspace
- **WHEN** `firefox-front` и `firefox-chat` имеют `chain = "SUPER+A b"`, первое входит в `dev-front`, второе в `chat`
- **THEN** `workspaced check` завершается успешно

#### Scenario: Одна цепочка у двух приложений одного workspace
- **WHEN** `firefox-front` и `firefox-back` имеют `chain = "SUPER+A b"` и оба входят в `dev-front`
- **THEN** `workspaced check` завершается с ошибкой, называющей `dev-front` и оба приложения

#### Scenario: Цепочка является началом другой
- **WHEN** у workspace `chain = "SUPER+W f"`, а в `[[binds]]` есть `chain = "SUPER+W f 3"`
- **THEN** `workspaced check` завершается с ошибкой, называющей обе цепочки

#### Scenario: Одиночное сочетание совпадает с началом цепочки
- **WHEN** в `[[binds]]` есть `chain = "SUPER+W"` с `exec = "wezterm-gui"`, а у workspace `chain = "SUPER+W d"`
- **THEN** `workspaced check` завершается с ошибкой, называющей обе записи

#### Scenario: Запуск команды с флагами
- **WHEN** в `[[binds]]` есть `chain = "XF86AudioRaiseVolume"`, `exec = "~/.scripts/change-volume.sh +"`, `locked = true`, `repeating = true`
- **THEN** после `hyprctl reload` удержание клавиши повышает громкость несколько раз подряд, в том числе при экране, закрытом hyprlock

#### Scenario: Серия по диапазону
- **WHEN** в `[[binds]]` есть `chain = "SUPER+$n"`, `range = [1, 8]`, `dispatch = "focus({ workspace = $n })"`
- **THEN** `hyprctl binds` содержит восемь привязок Super+1…Super+8, и Super+3 переводит на стол «3»

#### Scenario: Несколько диспетчеров по порядку
- **WHEN** в `[[binds]]` есть `chain = "ALT+Tab"` и `dispatch = ["window.cycle_next({ next = true })", "window.bring_to_top()"]`
- **THEN** нажатие Alt+Tab переводит фокус на следующее окно стола, и оно оказывается поверх остальных

#### Scenario: Зарезервированное сочетание
- **WHEN** в `[keys]` задано `reserved = ["SUPER+space", "ALT+E"]`, а в `[[binds]]` есть `chain = "ALT+E"`
- **THEN** `workspaced check` завершается с ошибкой, называющей запись и зарезервированное сочетание

#### Scenario: Мышь в цепочке
- **WHEN** в `[[binds]]` есть `chain = "SUPER+W mouse:272"` с `mouse = true`
- **THEN** `workspaced check` завершается с ошибкой о том, что флаг `mouse` допустим только у одиночного сочетания

### Requirement: Генерация привязок для Hyprland
Команда `workspaced keys --lua` MUST печатать код Lua для конфига Hyprland, который объявляет все привязки конфига: одиночные сочетания — прямыми привязками с их флагами, цепочки — подкартами для каждого префикса, где последнее сочетание выполняет действие и закрывает подкарту, а `Escape` в любой подкарте закрывает её без действия. Действия демона MUST вызывать соответствующую подкоманду; `exec`, `dispatch` и `lua` MUST выполняться композитором без участия демона. Код MUST зависеть только от конфига и быть одинаковым при повторных вызовах с тем же файлом. При успешной генерации команда MUST записать копию кода в `~/.local/state/workspaced/keys.lua`. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr, не печатать частичный код и не трогать копию. Команда `workspaced keys --list` MUST печатать таблицу всех привязок: цепочка, действие и источник (раздел конфига), в порядке следования в файле.

#### Scenario: Цепочка из трёх сочетаний
- **WHEN** в конфиге есть `[[binds]]` с `chain = "SUPER+W 3 f"` и `action = { desktop = 3, workspace = "dev-front" }`
- **THEN** после `hyprctl reload` нажатие Super+W, затем 3, затем f поднимает `dev-front` на столе 3, а нажатие Super+W, затем Escape ничего не делает

#### Scenario: Перезагрузка при ошибке конфига
- **WHEN** конфиг содержит ошибку и выполнена `hyprctl reload`
- **THEN** `workspaced keys --lua` завершается с ошибкой, `keys.lua` не изменяется, конфиг Hyprland загружает привязки из копии, а в журнале Hyprland есть сообщение об ошибке от `workspaced keys`

#### Scenario: Копия после успешной генерации
- **WHEN** конфиг корректен и выполнена `workspaced keys --lua`
- **THEN** содержимое `~/.local/state/workspaced/keys.lua` совпадает с напечатанным кодом

#### Scenario: Список привязок
- **WHEN** выполнена `workspaced keys --list`
- **THEN** в выводе есть строка с `SUPER+Return`, действием `exec wezterm-gui` и источником `binds`, и строка с `SUPER+W d`, действием `raise dots` и источником `workspaces.dots`

### Requirement: Слежение за конфигом
Демон MUST замечать изменение файла конфига без перезапуска, перечитывать его и, если файл корректен, применять: новые и изменённые workspace и приложения доступны следующей цепочкой, а привязки обновляются вызовом `hyprctl reload`. При ошибке демон MUST оставить прежний конфиг и записать ошибку в журнал.

#### Scenario: Новый workspace добавлен вручную
- **WHEN** пользователь дописал в конфиг workspace `notes` с `chain = "SUPER+W n"` и сохранил файл
- **THEN** не позднее чем через 2 секунды `workspaced status --json` содержит `notes`, а Super+W, n поднимает его

### Requirement: Запись по команде сохранения
По цепочке `save_workspace` или команде `workspaced save-workspace` демон MUST записать в раздел активного workspace текущего стола: назначение приложений по ячейкам (`apps`), `main` по текущей главной ячейке, `rect` у приложений, окна которых не совпадают со своей ячейкой, и посторонние окна, привязанные к workspace в сессии, — как новые приложения с `cmd`, `args`, `cwd` из процесса окна и `rect`. Остальные разделы и workspace, комментарии и порядок ключей MUST сохраняться. Запись MUST быть атомарной; перед записью файл MUST быть перечитан, и если он изменился с момента последнего чтения, команда MUST быть отклонена с сообщением, а конфиг перечитан. Без команды сохранения демон MUST NOT изменять файл.

#### Scenario: Сохранение после обмена ячеек
- **WHEN** в workspace `dev-front` терминал переведён в главную ячейку цепочкой приложения и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` `main = "terminal-front"`, назначения `apps` соответствуют экрану, комментарии в файле на месте, остальные workspace не изменились

#### Scenario: Сохранение постороннего окна
- **WHEN** на workspace `dev-front` цепочкой запущен калькулятор, не входящий ни в один workspace, перемещён пользователем и вызвана команда сохранения
- **THEN** в конфиге у `dev-front` появляется приложение с `cmd` калькулятора и `rect` его текущего положения, а следующий `raise` `dev-front` ставит калькулятор на это место

#### Scenario: Работа без сохранения
- **WHEN** пользователь два часа поднимает workspace, меняет ячейки и двигает окна, не вызывая команду сохранения
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст
