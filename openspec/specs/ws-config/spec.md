# ws-config Specification

## Purpose

Рукописный конфиг демона workspaced: шаблоны геометрии, приложения с окружением и цепочками клавиш, workspace с набором приложений по ячейкам, привязки; правила подстановки, проверки и записи обратно по команде сохранения.

## Requirements

### Requirement: Файл конфига и его разделы
Демон MUST читать конфиг из `~/.config/workspaced/config.toml` (файл под chezmoi). Файл MUST состоять из разделов: `[env]` — общие переменные окружения; `[keys]` — цепочки служебных действий `save_session`, `save_workspace`, `sessions`, `next_workspace` и список `reserved` зарезервированных сочетаний; `[templates.<имя>]` — шаблон геометрии с полем `main` (имя главной ячейки) и таблицей `cells`, где каждая ячейка — прямоугольник `{ x, y, w, h }`; `[apps.<имя>]` — приложение с полями `cmd` (команда запуска), `args` (массив), `cwd`, `env` (таблица), `chain`, `class` и `title` (регулярные выражения для захвата открытого окна по классу и заголовку; `title` без `class` не допускается), `dialog_title` (регулярное выражение по заголовку собственного диалога приложения; без `class` не допускается), `family` (имя приложения-семейства, если это приложение — его вариант) и `rect` (прямоугольник `{ x, y, w, h }` — положение и размер окна по умолчанию, когда workspace об этом приложении ничего не говорит); `[startup]` — `workspace` (имя существующего workspace, который поднимается при старте демона) и `desktop` (стол 1…8, по умолчанию 1); `[workspaces.<имя>]` — workspace с полями `template` (обязательно), `main` (имя приложения в главной ячейке по умолчанию), `icon`, `chain`, `env`, `mode` и таблицей `apps`, где значение — запись приложения в этом workspace: имя ячейки шаблона строкой, таблица `{ rect = { x, y, w, h } }` для окна вне ячеек либо таблица с полем места `cell` (имя ячейки шаблона) или `rect` (прямоугольник) — ровно одним из двух — и необязательными полями `chain` (клавиша приложения в этом workspace, требование «Цепочки клавиш и привязки») и `mode` (режим клавиши этого приложения в этом workspace); `[[binds]]` — записи с полем `chain`, ровно одним из полей действия `action`, `exec`, `dispatch`, `lua` и необязательными `range`, `locked`, `repeating`, `mouse`, `release`. В корне файла MUST быть допустим необязательный список `ignore_classes` — регулярные выражения, которые сопоставляются с классом окна целиком; окно с подходящим классом демон MUST NOT принимать в workspace ни при каких условиях (спецификация ws-daemon, «Посторонние окна» и «Захват открытых окон приложения»). По умолчанию список пуст. Оба поля, `dialog_title` и `ignore_classes`, нужны потому, что признака диалога композитор не сообщает; выражения с ошибкой MUST приводить к отказу с указанием приложения или списка. Поле `mode` MUST задавать поведение клавиши приложения в этом workspace (спецификация ws-daemon, «Цепочка приложения» и «Расстановка окон») и принимать значения `swap` — обмен ячеек — и `stack` — подъём окна без переноса; по умолчанию MUST действовать `swap`, а иное значение MUST приводить к отказу с указанием workspace, полученного значения и допустимых. Поле `mode` записи приложения в таблице `apps` workspace MUST принимать те же значения и задавать режим клавиши этого приложения в этом workspace; иное значение MUST приводить к отказу с указанием workspace, приложения, полученного значения и допустимых. Без поля `mode` режим приложения в workspace — режим workspace, за одним исключением: приложение без ячейки (место задано `rect`, в том числе записью дополнительного приложения сессии) в workspace режима `swap` MUST выбираться в режиме `stack`. Режим приложения MUST задавать только поведение его клавиши; поводы для расстановки и память о геометрии окон MUST определяться режимом workspace (спецификация ws-daemon, «Расстановка окон»). Запись-таблица без `cell` и `rect` или с обоими полями сразу MUST отклоняться с указанием workspace и приложения. Порядок записей в таблице `apps` workspace MUST сохраняться таким, как в файле: по нему конец цикла клавиши выбирает следующее приложение workspace, а приложения, добавленные сессией, MUST идти после описанных в файле. У приложения MUST быть задано хотя бы одно из полей `cmd` и `class`: без `cmd` приложение не открывает новых окон и только собирает подходящие по `class`, без `class` окно узнаётся лишь по запуску. Поле `family` MUST называть другое приложение того же файла, у которого самого нет `family`: уровней ровно два — семейство и его варианты. Имя приложения MUST NOT содержать двоеточие и знак `#`: этими знаками демон отделяет части тега экземпляра. Прямоугольники ячеек, `rect` приложения и `rect` в таблице `apps` workspace — это положение и размер окна на экране как есть: демон MUST передавать их композитору без прибавления или вычитания отступов. Координаты прямоугольников MUST отсчитываться от левого верхнего угла экрана: целое число — пиксели, строка с процентом — доля ширины или высоты монитора; смешивать формы в одном прямоугольнике MUST быть можно. Координаты MUST допускать отрицательные значения, а размеры — значения больше экрана: окно может выходить за его края частично с любой стороны, демон MUST передавать такие значения композитору без обрезания и без сдвига внутрь экрана. Необязательный ключ `gap` в корне файла задаёт зазор в пикселях только для команд `half`, `place` и `maximize`, которые строят геометрию от рабочей области; по умолчанию 0. Неизвестные ключи MUST приводить к предупреждению в журнале, но не к отказу.

#### Scenario: Минимальный конфиг
- **WHEN** файл содержит один шаблон `halves` с ячейками `left` и `right`, одно приложение `terminal` с `cmd = "wezterm-gui"` и один workspace `work` с `template = "halves"`, `main = "terminal"` и `apps = { terminal = "right" }`
- **THEN** `workspaced check` завершается успешно и выводит один workspace, одно приложение и один шаблон

#### Scenario: Заголовок диалога у приложения
- **WHEN** у приложения `chrome` заданы `class = "(?i)^google-chrome$"` и `dialog_title = "^(Диспетчер задач|Task Manager)$"`
- **THEN** `workspaced check` завершается успешно, окно Chrome с заголовком «Диспетчер задач» остаётся свободным, а обычное окно Chrome принимается в workspace; конфиг с `dialog_title` без `class` или с ошибкой в выражении отклоняется с указанием приложения и поля

#### Scenario: Список исключённых классов
- **WHEN** в корне файла задано `ignore_classes = ["termfilechooser", "pinentry.*"]`
- **THEN** `workspaced check` завершается успешно, окна классов `termfilechooser` и `pinentry-gtk` не принимаются ни в один workspace, а окно класса `termfilechooser-2` под выражение не подходит: класс сопоставляется целиком; конфиг с ошибкой в выражении отклоняется с указанием `ignore_classes`

#### Scenario: Режим workspace
- **WHEN** у workspace `surf` задано `mode = "stack"`, а у `work` поля `mode` нет
- **THEN** `workspaced check` завершается успешно, `surf` работает подъёмом окон, `work` — обменом ячеек; конфиг с `mode = "stak"` отклоняется с указанием workspace, значения `stak` и допустимых `swap` и `stack`

#### Scenario: Порядок приложений в разделе workspace
- **WHEN** в разделе `surf` приложения записаны в порядке `chrome`, `yandex-browser`, `chrome-ai`
- **THEN** демон держит их в этом порядке, и конец цикла клавиши переходит от `chrome` к `yandex-browser`, а не к `chrome-ai` по алфавиту

#### Scenario: Цепочки сохранения сессии и записи в конфиг
- **WHEN** в `[keys]` заданы `save_session = "CTRL+SUPER+s CTRL+SUPER+s"` и `save_workspace = "CTRL+SUPER+s CTRL+SUPER+w"`
- **THEN** `workspaced check` завершается успешно, а `workspaced keys --list` показывает для первой цепочки команду `save-session`, для второй — `save-workspace`

#### Scenario: Класс, заголовок и стартовый workspace
- **WHEN** у приложения `herdr` заданы `class = "^wezterm-herdr$"` и `title = "^herdr · "`, а в `[startup]` — `workspace = "work"`
- **THEN** `workspaced check` завершается успешно; конфиг с `title` без `class`, с некорректным регулярным выражением или с `startup.workspace`, которого нет среди workspace, отклоняется с указанием поля

#### Scenario: Семейство и его вариант
- **WHEN** в файле есть `[apps.wezterm]` с `cmd = "wezterm-gui"` и `class = "^org\\.wezfurlong\\.wezterm$"`, а `[apps.herdr]` содержит `family = "wezterm"`, свою команду запуска и `class = "^wezterm-herdr$"`
- **THEN** `workspaced check` завершается успешно и показывает `herdr` как вариант семейства `wezterm`; конфиг, где `family` называет приложение, которого нет, где вариант указан вариантом другого варианта или где приложение названо своим же семейством, отклоняется с указанием приложения и поля

#### Scenario: Приложение без команды запуска
- **WHEN** у приложения `wezterm` задан только `class`, без `cmd`
- **THEN** `workspaced check` завершается успешно: приложение собирает окна, но само их не открывает; конфиг с приложением без `cmd` и без `class` отклоняется с указанием приложения

#### Scenario: Положение окна по умолчанию у приложения
- **WHEN** у приложения `neovide` задано `rect = { x = 1125, y = 10, w = 1920, h = 2140 }`, и ни один workspace его не описывает
- **THEN** `workspaced check` завершается успешно, а окно `neovide`, открытое по его цепочке, встаёт в этот прямоугольник

#### Scenario: Проценты и пиксели в одной ячейке
- **WHEN** ячейка задана как `{ x = 330, y = 0, w = "50%", h = "100%" }` на мониторе 3840×2160
- **THEN** демон считает прямоугольник 330,0 размером 1920×2160

#### Scenario: Окно шире экрана со сдвигом за левый край
- **WHEN** ячейка задана как `{ x = -400, y = -150, w = 5000, h = 2600 }` и в неё поставлено окно при `gap = 5`
- **THEN** `hyprctl clients -j` показывает у окна положение −400,−150 и размер 5000×2600

#### Scenario: Ссылка на несуществующую ячейку
- **WHEN** workspace ссылается на ячейку `top`, которой нет в его шаблоне
- **THEN** `workspaced check` завершается с ошибкой, называющей workspace, приложение и ячейку; демон продолжает работать с прежним конфигом

#### Scenario: Запись привязки с двумя действиями
- **WHEN** запись `[[binds]]` содержит и `exec`, и `dispatch`
- **THEN** `workspaced check` завершается с ошибкой, называющей цепочку записи и оба поля

#### Scenario: Переопределение клавиши и режима в workspace
- **WHEN** у приложения `chrome-ai` задано `chain = "SUPER+SHIFT+V"`, в разделе `surf` записано `chrome-ai = { cell = "right", chain = "SUPER+V" }`, а в разделе `work` — `calc = { rect = { x = 2600, y = 1500, w = 600, h = 400 }, mode = "swap" }`
- **THEN** `workspaced check` завершается успешно; ключ `chrome-ai` в `surf` — Super+V, место — ячейка `right`; `calc` в `work` выбирается обменом ячеек, хотя ячейки у него нет

#### Scenario: Запись приложения без места
- **WHEN** в разделе `surf` записано `chrome-ai = { chain = "SUPER+V" }` либо `chrome-ai = { cell = "right", rect = { x = 0, y = 0, w = 10, h = 10 } }`
- **THEN** `workspaced check` завершается с ошибкой, называющей `surf` и `chrome-ai`

#### Scenario: Недопустимый режим приложения в workspace
- **WHEN** в разделе `work` записано `chromium = { cell = "left", mode = "stak" }`
- **THEN** `workspaced check` завершается с ошибкой, называющей `work`, `chromium`, значение `stak` и допустимые `swap` и `stack`

### Requirement: Окружение и подстановка
Окружение приложения MUST складываться из трёх слоёв в порядке возрастания приоритета: `[env]` корня файла, `env` workspace, из которого приложение запускается, `env` самого приложения; значение нижнего слоя перекрывает верхний, поверх окружения демона. В значениях `args`, `cwd` и `env` MUST подставляться `~` в начале строки (домашний каталог) и `$ИМЯ` (переменная сложенного окружения, при отсутствии — окружения демона, при отсутствии и там — пустая строка). Подстановка MUST выполняться в момент запуска, а не при чтении конфига, чтобы одно приложение получало разное окружение в разных workspace.

#### Scenario: Переменная workspace в аргументах приложения
- **WHEN** у workspace задано `env = { ROOT = "~/work/front-end" }`, а у приложения `args = ["--cwd", "$ROOT"]`
- **THEN** процесс запускается с аргументом `--cwd /home/mne/work/front-end` и переменной `ROOT=/home/mne/work/front-end` в окружении

#### Scenario: Приложение перекрывает переменную workspace
- **WHEN** в `[env]` корня `NODE_ENV = "production"`, у workspace `NODE_ENV = "development"`, а у приложения `NODE_ENV = "test"`
- **THEN** процесс получает `NODE_ENV=test`

### Requirement: Цепочки клавиш и привязки
Цепочка MUST записываться строкой сочетаний через пробел, где сочетание — модификаторы и клавиша в синтаксисе Hyprland через `+` (`"SUPER+W 3 f"`); одиночное сочетание (`"SUPER+Return"`, `"XF86AudioMute"`, `"SUPER+mouse:272"`) — цепочка из одного звена. Короткая форма `chain` у workspace означает действие «поднять на текущем столе», у приложения и у записи приложения в таблице `apps` workspace — клавишу приложения: цикл по его экземплярам по правилам спецификации ws-daemon, «Цепочка приложения». Ключ приложения в workspace — `chain` его записи в этом workspace, а если его нет, собственный `chain` приложения; workspace откликается на цепочку, если в нём есть запись приложения с таким ключом. Переопределение освобождает собственную клавишу приложения в этом workspace: её может занять ключом другое приложение того же workspace. Переопределение, совпадающее с собственной клавишей приложения, ничего не меняет. Все приложения, отзывающиеся на одну цепочку собственной клавишей или ключом в каком-либо workspace, MUST давать одну привязку, вызывающую команду `workspaced key '<цепочка>'`; какое приложение и в каком workspace она вызывает, MUST решать демон при нажатии по активному workspace текущего стола. В `workspaced keys --list` у такой привязки MUST стоять действие `key <цепочка>`, а в колонке источника — все отозвавшиеся записи (`apps.<имя>` для собственной клавиши, `workspaces.<workspace>.apps.<имя>` для ключа в workspace). Запись `[[binds]]` MUST принимать ровно одно действие: `action` — таблица с любым сочетанием ключей `desktop` (1…8), `workspace` и `app` и необязательным логическим ключом `pull` (перетащить окна приложения в активный workspace текущего стола, спецификация ws-daemon, «Цепочка приложения»; ключ допустим только вместе с `app` и без `workspace`, иначе запись MUST отклоняться с указанием цепочки; действие с `pull = true` MUST вызывать команду `workspaced app <имя> --pull`; действие `{ app = "<имя>" }` без `workspace` MUST вызывать команду `workspaced app <имя>`, которая действует как собственная клавиша приложения), таблица `{ half = "left" | "right" | "up" | "down" }`, таблица `{ place = "top-left" | "top-center" | "top-right" | "bottom-left" | "bottom-center" | "bottom-right" | "center" | "full" }`, таблица `{ move = <стол 1…8> }` (перенести активный workspace текущего стола на этот стол) либо строка `"sessions"`, `"save-session"`, `"save-workspace"`, `"next-workspace"`, `"maximize"`, `"arrange"`, `"detach"` (убрать активное окно из активного workspace текущего стола, спецификация ws-daemon, «Отделение окна»); `exec` — командная строка, запускаемая композитором; `dispatch` — выражение диспетчера Hyprland без префикса `hl.dsp.` (`"window.close()"`) либо массив таких выражений, выполняемых по порядку одним вызовом; `lua` — тело функции на Lua, выполняемое композитором при нажатии. Необязательные строки `desc` (описание) и `group` (группа) записи `[[binds]]` MUST использоваться только перечнем для подсказки (требование «Перечень клавиш для подсказки») и MUST NOT влиять на привязку. Раздел `[keys]` MUST принимать необязательную таблицу `reserved_desc`: сочетание из списка `reserved` → его описание. Флаги `locked` (действует при заблокированном экране), `repeating` (повторяется при удержании), `mouse` (привязка к кнопке мыши с удержанием), `release` (срабатывает при отпускании) MUST передаваться композитору; `mouse` MUST быть допустим только у цепочки из одного звена. Поле `range = [от, до]` MUST разворачивать запись в серию: для каждого целого из диапазона подстрока `$n` в `chain`, `exec`, `dispatch` и в значении действия `move` и в `desc` заменяется числом. Значение `move` MUST читаться числом или строкой и MUST проверяться после разворачивания серии: до него на месте номера стоит `$n`. Стол вне диапазона 1…8 MUST приводить к отказу с указанием цепочки и полученного значения. Цепочки MUST быть произвольными; демон MUST NOT навязывать смысл сегментам. Одна цепочка MUST NOT совпадать с другой или быть её началом, в том числе одиночное сочетание с первым звеном цепочки; две цепочки с общим первым звеном и разными последующими MUST быть допустимы; две записи приложений одного workspace с одинаковым ключом MUST считаться ошибкой, в том числе когда ключ одной из них задан переопределением, а другой — собственной клавишей; одна цепочка у приложений из разных workspace MUST быть допустима. Цепочка переопределения MUST проходить те же проверки совпадения, начала цепочки и зарезервированных сочетаний, что и остальные цепочки. Сочетание из списка `reserved` раздела `[keys]` MUST NOT встречаться ни в одной цепочке. Демон MUST проверять эти условия при чтении и при ошибке называть обе конфликтующие записи либо запись и зарезервированное сочетание; ошибка двух записей одного workspace MUST называть workspace, оба приложения и цепочку.

#### Scenario: Цепочка приложения ведёт цикл
- **WHEN** у приложения `chromium` задано `chain = "SUPER+C"`, оно входит в workspace `work` режима обмена ячеек, и у него два окна
- **THEN** Super+C по очереди выбирает экземпляры `chromium` в главной ячейке, а за последним возвращает расстановку и фокус прежнему главному окну

#### Scenario: Отделение окна в записи привязки

### Requirement: Генерация привязок для Hyprland
Команда `workspaced keys --lua` MUST печатать код Lua для конфига Hyprland, который объявляет все привязки конфига: одиночные сочетания — прямыми привязками с их флагами, цепочки — подкартами для каждого префикса, где последнее сочетание выполняет действие и закрывает подкарту, а `Escape` в любой подкарте закрывает её без действия. Действия демона MUST вызывать соответствующую подкоманду; `exec`, `dispatch` и `lua` MUST выполняться композитором без участия демона. Код MUST зависеть только от конфига и быть одинаковым при повторных вызовах с тем же файлом. При успешной генерации команда MUST записать копию кода в `~/.local/state/workspaced/keys.lua`. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr, не печатать частичный код и не трогать копию. Команда `workspaced keys --list` MUST печатать таблицу всех привязок: цепочка, действие и источник (раздел конфига), в порядке следования в файле.

### Requirement: Слежение за конфигом
Демон MUST замечать изменение файла конфига без перезапуска, перечитывать его и, если файл корректен, применять: новые и изменённые workspace и приложения доступны следующей цепочкой, а привязки обновляются вызовом `hyprctl reload`. Тот же вызов демон MUST делать один раз при старте, после удачной загрузки конфига: файл могли поправить, пока демон не работал, а бинарник — обновить до версии с новыми действиями, и привязки композитора тогда отстали бы от конфига. Если композитор в этот момент недоступен, демон MUST записать предупреждение и продолжить работу, а повторять вызов по сроку MUST NOT. Перечитывание MUST запускаться по событиям файловой системы, означающим завершённую запись файла: закрытие файла, открытого на запись, и появление файла под своим именем после записи во временный файл с переименованием. События, приходящие посреди записи, демон MUST NOT учитывать, а задержку вместо них применять MUST NOT: одно сохранение файла MUST давать ровно одно перечитывание. При перечитывании демон MUST сравнить раздел каждого workspace в прежнем и новом файле и снять текущие назначения ячеек у тех workspace, чей раздел изменился или исчез: их назначения MUST быть собраны заново из нового файла при следующем обращении, и правка файла MUST возвращать расстановку без перезапуска демона. Назначения workspace, раздел которых не менялся, MUST сохраняться, чтобы правка одного workspace не сбрасывала обмен ячеек в другом. После каждого перечитывания демон MUST сверить теги открытых окон и записи ожидания с составом приложений: окна приложений, которых в конфиге не стало, MUST становиться посторонними, а ожидания их окон MUST сниматься (требование «Посторонние окна» спецификации ws-daemon). При ошибке демон MUST оставить прежний конфиг и записать ошибку в журнал.

### Requirement: Запись по команде сохранения
По цепочке `save_workspace` или команде `workspaced save-workspace` демон MUST записать в раздел активного workspace текущего стола: назначение приложений по ячейкам (`apps`), `main` по текущей главной ячейке, `rect` у приложений, окна которых не совпадают со своей ячейкой, дополнительные приложения сессии этого workspace и свободные окна, открытые на текущем столе. Окна workspace MUST определяться по тегам состава (спецификация ws-daemon, «Состав workspace»), а не по описанию приложений: окно, убранное из workspace командой отделения, MUST NOT давать места своему приложению, а общее окно, входящее и в другие workspace, MUST записываться наравне с остальными — приложение под своим именем, с местом, которое окно занимает в этом workspace. Записи того же приложения в разделах других workspace команда MUST NOT менять: после записи приложение описано в нескольких разделах, и окно остаётся общим и после перезапуска демона. Для свободного окна и для дополнительного приложения сессии демон MUST сначала найти среди всех приложений конфига то, которому окно подходит по выражениям `class` и, если оно задано, `title`: поиск MUST идти сначала по приложениям-вариантам, затем по семействам, внутри каждой группы по именам, и найденное приложение MUST быть записано под своим именем с `rect`; новое приложение MUST заводиться только тогда, когда подходящего не нашлось, — с `cmd`, `args`, `cwd` из процесса окна (по правилу требования «Файлы сессий» спецификации ws-sessions, по которому окно из песочницы flatpak записывается командой `flatpak run`) и `rect`. Окно, которое в workspace не принимается (класс из `ignore_classes`, заголовок под `dialog_title` его приложения), демон MUST NOT записывать: в конфиге ему не место, как и в составе workspace. Дополнительные приложения сессии записанного workspace MUST после записи быть сняты: они перешли в конфиг. Если у приложения несколько окон, в `rect` MUST записываться место первого экземпляра, а остальные его окна MUST NOT попадать в файл отдельными записями. Записанное окно MUST получить тег экземпляра этого приложения и тег состава этого workspace и перестать быть свободным, а назначения ячеек workspace MUST быть пересобраны из записанного конфига без перезапуска демона. Свободные окна на других столах и окна на `special:hidden` MUST NOT записываться. Таблицу `apps` раздела команда MUST править на месте, а не собирать заново: у записи приложения MUST меняться только место (имя ячейки или `rect`), поля `chain` и `mode` записи, порядок записей и комментарии внутри таблицы MUST сохраняться; запись без переопределений — строка или таблица `{ rect = … }` без других полей — MUST записываться строкой, если новое место — ячейка, и таблицей `{ rect = … }`, если окно стоит не в ней; запись-таблица с полями `chain`, `mode` MUST сохранять свою форму и менять только поле места (`cell` или `rect`) на прежней позиции. Записи, которых в файле не было (дополнительные приложения сессии, свободные окна стола), MUST добавляться в конец таблицы в порядке раздела эффективного конфига. Остальные разделы и workspace, комментарии и порядок ключей MUST сохраняться. Запись MUST быть атомарной; перед записью файл MUST быть перечитан, и если он изменился с момента последнего чтения, команда MUST быть отклонена с сообщением, а конфиг перечитан. После удачной записи команда MUST NOT перечитывать конфиг сама: перечитывание приходит событием завершённой записи файла, одно на одно сохранение. Без команды сохранения демон MUST NOT изменять файл.

- **THEN** в журнале демона одна строка о перечитывании конфига, `hyprctl reload config-only` вызывается один раз

#### Scenario: Свободное окно на другом столе не записывается
- **WHEN** на столе 1 активен `dev-front`, на столе 3 без активного workspace открыт свободный терминал, и на столе 1 вызвана команда сохранения
- **THEN** терминал в конфиг не попадает и остаётся свободным

#### Scenario: Работа без сохранения
- **WHEN** пользователь два часа поднимает workspace, меняет ячейки и двигает окна, не вызывая команду сохранения
- **THEN** `config.toml` не изменяется, `chezmoi status` пуст

#### Scenario: Общее окно записывается в раздел workspace
- **WHEN** окно `chrome-ai` из `surf` перетащено в `work`, сдвинуто пользователем, и на столе 1 вызвана цепочка `save_workspace`
- **THEN** в разделе `work` появляется запись `chrome-ai` с `rect` окна, запись `chrome-ai = "right"` в разделе `surf` не меняется, окно по-прежнему входит в оба workspace, а после перезагрузки поднятие второго из них забирает окно первого, а не запускает второй Chrome AI

#### Scenario: Отделённое окно не записывается
- **WHEN** у `chromium` в `work` два окна, первое убрано из `work` командой отделения и осталось в `dev-front`, второе стоит в ячейке `left`, и вызвана цепочка `save_workspace`
- **THEN** у `chromium` в разделе `work` остаётся ячейка `left`: место считается по второму окну, входящему в `work`

#### Scenario: Переопределения переживают запись
- **WHEN** в разделе `surf` записано `chrome-ai = { cell = "right", chain = "SUPER+V" }`, окно `chrome-ai` сдвинуто пользователем, и на столе `surf` вызвана цепочка `save_workspace`
- **THEN** запись `chrome-ai` в разделе `surf` содержит `rect` нового положения окна и прежнее `chain = "SUPER+V"`, поля `cell` в ней нет, остальные записи раздела не изменились

#### Scenario: Порядок записей сохраняется
- **WHEN** в разделе `surf` приложения записаны в порядке `chrome`, `yandex-browser`, `chrome-ai`, в `surf` принято окно калькулятора, и вызвана цепочка `save_workspace`
- **THEN** в разделе `surf` записи идут в порядке `chrome`, `yandex-browser`, `chrome-ai`, калькулятор, а комментарии внутри таблицы `apps` на месте

### Requirement: Перечень клавиш для подсказки
Команда `workspaced keys --json` MUST печатать перечень всех привязок конфига в JSON вида `{ "groups": [ { "name": <группа>, "keys": [ { "chain", "label", "desc", "action", "source" } ] } ] }`. `chain` и `action` MUST совпадать с цепочкой и действием в выводе `keys --list`, `source` — раздел конфига (`keys.next_workspace`, `apps.herdr`, `workspaces.surf.apps.chrome`, `workspaces.work`, `binds[N]`, `keys.reserved`). `label` MUST быть подписью для человека: модификаторы в порядке Ctrl, Alt, Shift, Super, звенья через пробел, `slash` — «/», `space` — «Пробел», `Return` — «Enter», стрелки — символами, кнопки мыши — «ЛКМ» и «ПКМ», без префикса `XF86`; буква с модификаторами заглавная. Команда MUST читать конфиг сама и MUST NOT требовать работающего демона. При ошибке конфига команда MUST завершаться ненулевым кодом с описанием ошибки в stderr и MUST NOT печатать частичный перечень.

Группы MUST идти в порядке: Workspace, Столы, Приложения, Окна, Уведомления, Звук и яркость, Снимки экрана, Раскладка, Сессия и прочее; группа из поля `group`, которой нет в этом списке, MUST идти после них в порядке первого появления; пустая группа MUST NOT выводиться. Строки внутри группы MUST идти в порядке `keys --list`, зарезервированные сочетания — последними в группе «Раскладка». Запись `[[binds]]` с `range` MUST выводиться одной строкой, где `$n` в цепочке, описании и действии заменено подписью «от…до» («Super+1…8»). Каждое сочетание списка `reserved` MUST выводиться в группе «Раскладка» с описанием из `reserved_desc`, а без него — «Зарезервировано».

Без поля `group` группа MUST выводиться из источника и действия: цепочки workspace и служебные цепочки `[keys]`, действия `next-workspace`, `save-session`, `save-workspace`, `sessions`, `arrange` и `{ workspace = … }` — Workspace; `{ move = … }` и `dispatch` с переходом или переносом окна на стол (`workspace = ` без `special:`) — Столы; клавиши приложений и `{ app = … }` — Приложения; `half`, `place`, `maximize`, `detach` и прочие `dispatch` — Окна; `exec` с `ipc call notifications` — Уведомления; `exec` громкости, яркости и `playerctl`, цепочки `XF86Audio*` и `XF86MonBrightness*` — Звук и яркость; `exec` со `screenshot` — Снимки экрана; `dispatch` с `exit()`, прочие `exec` и `lua` — Сессия и прочее. Без поля `desc` описание MUST выводиться из действия: у действий демона — фразой по-русски («Окно в левую половину»), у клавиш приложений — по источнику («Приложение herdr», «chrome в workspace surf»), у цепочек workspace — «Поднять workspace <имя>», у `exec`, `dispatch` и `lua` — действием, как в `keys --list`.

#### Scenario: Группы и подписи
- **WHEN** выполнена `workspaced keys --json` с конфигом сессии
- **THEN** первая группа — «Workspace» со строкой `label` «Super+Tab w» и описанием «Поднять workspace work», в группе «Приложения» есть строка «Super+B — chrome в workspace surf», в группе «Окна» — «Alt+Super+← — Окно в левую половину»

#### Scenario: Серия одной строкой
- **WHEN** в `[[binds]]` есть `chain = "CTRL+SUPER+$n"`, `range = [1, 8]`, `action = { move = "$n" }` без `desc`
- **THEN** в группе «Столы» ровно одна строка этой записи: «Ctrl+Super+1…8 — Перенести workspace на стол 1…8 и перейти туда»

#### Scenario: Зарезервированные сочетания
- **WHEN** в `[keys]` заданы `reserved = ["SUPER+space", "ALT+SUPER+space"]` и `reserved_desc = { "SUPER+space" = "Следующая раскладка" }`
- **THEN** в группе «Раскладка» есть строки «Super+Пробел — Следующая раскладка» и «Alt+Super+Пробел — Зарезервировано»

#### Scenario: Ошибка конфига
- **WHEN** привязка занимает зарезервированное сочетание и выполнена `workspaced keys --json`
- **THEN** команда завершается ненулевым кодом, в stderr названы запись и сочетание, stdout пуст
