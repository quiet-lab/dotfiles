# qs-launcher Specification

## Purpose

Плитка лаунчера панели Quickshell в сессии Hyprland: поле фильтра и сетка полноцветных иконок приложений из записей `.desktop`, разделы и ряд частых приложений, статистика запусков в собственном файле панели.

## Requirements

### Requirement: Источник списка приложений
Список приложений MUST строиться из записей `.desktop` в стандартных каталогах: `$XDG_DATA_HOME/applications` (по умолчанию `~/.local/share/applications`), `applications` в каждом каталоге `$XDG_DATA_DIRS` (по умолчанию `/usr/local/share:/usr/share`, так учитываются экспорты flatpak) и `/var/lib/snapd/desktop/applications`. Записи с `NoDisplay=true`, `Hidden=true` и записи не типа Application MUST NOT попадать в сетку. Название MUST браться из `Name[ru_RU]`, затем `Name[ru]`, затем `Name`. Записи с одинаковым идентификатором MUST сводиться к одной, при этом запись из более раннего каталога в этом порядке приоритетнее. Панель MUST отслеживать изменения в этих каталогах и обновлять сетку при создании, изменении, удалении или переименовании файлов; опросы каталогов по таймеру MUST NOT применяться.

#### Scenario: Скрытые записи не показываются
- **WHEN** в каталоге приложений есть запись с `NoDisplay=true` и запись с `Hidden=true`
- **THEN** ни одна из них не отображается в сетке

#### Scenario: Русское название
- **WHEN** запись содержит поля `Name=Files` и `Name[ru]=Файлы`
- **THEN** в подсказке и при фильтрации используется название «Файлы»

#### Scenario: Новое приложение появляется без опроса
- **WHEN** в `~/.local/share/applications` появляется или удаляется файл `.desktop`
- **THEN** сетка отражает изменение в течение секунды без периодического перечитывания каталогов

### Requirement: Разделы и частые приложения
При пустом поле фильтра сетка MUST начинаться с ряда до семи самых частых приложений по статистике запусков (только с ненулевым счётчиком, без заголовка), а затем идти разделами: приложение попадает в первый подходящий раздел по полю `Categories` в порядке Стандартные (Utility), Разработка (Development), Образование (Education), Игры (Game), Графика (Graphics), Мультимедиа (AudioVideo, Audio, Video), Интернет (Network), Офис (Office), Наука (Science), Настройки (Settings), Система (System); остальные — в раздел Прочее. Перед иконками каждого раздела MUST стоять его заголовок жёлтым цветом палитры Tokyo Night, размером 18 px, полужирным начертанием. Внутри раздела приложения MUST быть упорядочены по названию без учёта регистра. Пустые разделы MUST NOT отображаться. Шапка плитки MUST содержать подпись «APP:» в оформлении номера стола (цвет рамки, 18 px, начертание 900) и поле фильтра с фоном цвета рамки и чёрным текстом.

#### Scenario: Заголовки разделов
- **WHEN** поле фильтра пусто
- **THEN** сетка показывает ряд частых приложений, затем заголовки разделов с их иконками, а разделы без приложений отсутствуют

#### Scenario: Нет статистики
- **WHEN** файл статистики отсутствует или все счётчики нулевые
- **THEN** ряда частых приложений нет, сетка начинается с первого непустого раздела

### Requirement: Фильтр
При непустом поле фильтра сетка MUST превращаться в плоский список без заголовков разделов и ряда частых: в нём остаются приложения, название которых содержит введённый текст без учёта регистра, в том числе для кириллицы, упорядоченные по убыванию счётчика запусков, затем по названию. Сетка MUST обновляться сразу при каждом изменении текста, без нажатия Enter и без заметной задержки. Очистка поля MUST возвращать разделы и ряд частых.

#### Scenario: Фильтр «бра»
- **WHEN** пользователь вводит «бра»
- **THEN** остаётся плоский список без заголовков, в нём есть «Яндекс Браузер» и другие записи с этой подстрокой; очистка поля возвращает разделы

#### Scenario: Регистр не учитывается
- **WHEN** пользователь вводит «FIRE»
- **THEN** в списке есть «Firefox»

### Requirement: Фокус поля фильтра
Панель на layer-shell MUST NOT удерживать фокус клавиатуры постоянно, чтобы ввод продолжал поступать в окна приложений. Поле фильтра MUST принимать ввод с клавиатуры после клика по нему и MUST отдавать фокус клавиатуры обратно окнам после нажатия Escape или после запуска приложения из сетки. Нажатие Escape MUST также очищать поле.

#### Scenario: Ввод после клика
- **WHEN** пользователь щёлкает по полю фильтра и набирает текст
- **THEN** текст появляется в поле, сетка фильтруется, а окно приложения, бывшее в фокусе, ввод не получает

#### Scenario: Возврат фокуса по Escape
- **WHEN** в поле фильтра введён текст и нажата Escape
- **THEN** поле очищается, сетка показывает разделы, а последующий ввод с клавиатуры попадает в окно приложения, а не в панель

#### Scenario: Возврат фокуса после запуска
- **WHEN** пользователь отфильтровал список и щёлкнул по иконке приложения
- **THEN** приложение запускается, а ввод с клавиатуры больше не попадает в поле фильтра

### Requirement: Сетка иконок
Сетка MUST состоять из рядов по семь иконок 32×32 px в ячейках 38 px. Плитка MUST быть квадратной, 320×320 px; сетка MUST занимать всё пространство под шапкой, а содержимое, не помещающееся по высоте, MUST быть доступно вертикальной прокруткой колесом мыши; горизонтальной прокрутки MUST NOT быть.

#### Scenario: Прокрутка длинной сетки
- **WHEN** приложений больше, чем помещается в плитку
- **THEN** плитка сохраняет размер 320×320 px, а остальные ряды доступны прокруткой колесом внутри плитки

### Requirement: Запуск приложения
Клик по иконке MUST запускать приложение по его записи `.desktop` отдельно от панели, так что перезапуск или завершение панели не завершает приложение. Для записей с `Terminal=true` приложение MUST запускаться в wezterm с конфигом `~/.config/wezterm/apps.lua` и классом окна, равным идентификатору записи, командой из поля `Exec` без %-кодов. Каждый запуск MUST увеличивать счётчик приложения в статистике.

#### Scenario: Запуск по клику
- **WHEN** пользователь щёлкает по иконке приложения
- **THEN** приложение открывается, а его счётчик в статистике увеличивается на единицу

#### Scenario: Консольное приложение
- **WHEN** пользователь щёлкает по иконке записи с `Terminal=true`
- **THEN** открывается окно wezterm с классом, равным идентификатору записи, и в нём выполняется команда из `Exec`

#### Scenario: Приложение переживает перезапуск панели
- **WHEN** приложение запущено из лаунчера, после чего панель перезапущена
- **THEN** окно приложения остаётся открытым

### Requirement: Подсказка при наведении
При наведении курсора на иконку MUST появляться подсказка с названием приложения; при уходе курсора подсказка MUST скрываться. Подсказка MUST целиком помещаться на экране.

#### Scenario: Название в подсказке
- **WHEN** курсор задерживается на иконке
- **THEN** появляется подсказка с названием приложения, которая исчезает после ухода курсора

### Requirement: Иконки приложений
Каждая иконка MUST быть полноцветной и браться по полю `Icon` записи: имя из активной темы значков или абсолютный путь к файлу. Если иконка не найдена, MUST отображаться generic-иконка `application-x-executable` из темы; ячейка сетки MUST NOT оставаться пустой.

#### Scenario: Иконка из темы
- **WHEN** запись содержит `Icon=firefox`, и в активной теме значков есть такая иконка
- **THEN** в ячейке показана иконка Firefox из темы

#### Scenario: Неизвестная иконка
- **WHEN** запись содержит имя иконки, которого нет ни в теме, ни по абсолютному пути
- **THEN** в ячейке показана generic-иконка `application-x-executable`

### Requirement: Собственная статистика запусков
Панель MUST вести счётчик запусков для каждого приложения, запущенного из лаунчера, и хранить его в `~/.local/share/quickshell-panel/usage.json`; каталог MUST создаваться при первой записи. Статистика MUST сохраняться между перезапусками панели и сессии и учитываться в ряду частых приложений и в порядке результатов фильтра. Другие файлы статистики панель MUST NOT читать.

#### Scenario: Частые приложения
- **WHEN** приложение запущено через лаунчер несколько раз, после чего панель перезапущена
- **THEN** приложение остаётся в первом ряду сетки, а его счётчик записан в `~/.local/share/quickshell-panel/usage.json`
