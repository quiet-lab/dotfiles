# eww-network Specification

## Purpose

Сетевая плитка дашборда и контекстное меню сети: состояние eth/wifi/vpn с адресами, реактивное обновление по событиям NetworkManager и страховочный опрос. Реализации — `scripts/network`, `scripts/network-listen`, `scripts/network-sync`, `scripts/netmenu-items`, ветки `net*` в `scripts/popup`.

## Requirements

### Requirement: Строки состояния сети
Плитка MUST показывать три строки (класс net-row): ETH, WIFI, VPN. Подключённое устройство — глиф с классом `net-on` и текст с IPv4-адресом (`nmcli -t -f IP4.ADDRESS dev show`); иначе класс `net-off` и текст «отключено». Для WIFI устройства с именем вида `p2p*` исключаются; для VPN берётся первое активное соединение типа vpn (имя вместо IP).

#### Scenario: Wifi без соединения
- **WHEN** радиомодуль wifi включён, но соединения нет
- **THEN** строка показывает 󰤮 с классом net-off и текст «WIFI отключено»

### Requirement: Реактивное обновление
Переменная `network` MUST обновляться демоном `widgets/network/scripts/network-listen` (deflisten): стартовый замер, затем пересборка на каждое событие `nmcli monitor`. После события MUST выполняться два замера с паузой 2 секунды между ними — защита от гонок nmcli, сообщающего о событии до фактического изменения состояния. Многострочный вывод склеивается в одну строку.

#### Scenario: Смена сети
- **WHEN** пользователь подключается к другому wifi
- **THEN** строки плитки перестраиваются дважды (сразу и через 2с), финальный вариант отражает новое состояние

### Requirement: Страховочный опрос
Poll `network-sync` (10s) MUST выполнять `eww update network=<текущее состояние>` в обход monitor — на случай пропущенных событий. Poll живёт только благодаря скрытой ссылке на переменную внутри network-tile; удалять её запрещено.

#### Scenario: Пропущенное событие monitor
- **WHEN** nmcli monitor не сообщил о смене состояния
- **THEN** плитка всё равно актуализируется не позже чем через 10 секунд

### Requirement: Клик по плитке
Клик по телу плитки MUST открывать `nm-connection-editor &` (тултип «ЛКМ — редактор соединений»). Кнопка «⋮» MUST открывать окно netmenu.

#### Scenario: Редактор соединений
- **WHEN** пользователь кликает по строкам состояния
- **THEN** запускается nm-connection-editor

### Requirement: Окно netmenu
Окно `netmenu` MUST располагаться в точке x=330px, y=200px шириной 240px (anchor left top, монитор 0, stacking fg). Содержимое — литерал `netmenu-content`: poll раз в 60 секунд плюс принудительное обновление при каждом открытии меню (`scripts/popup netmenu`).

#### Scenario: Открытие меню
- **WHEN** пользователь кликает «⋮»
- **THEN** содержимое перегенерируется и меню переключается в открытое состояние

### Requirement: Пункты меню
`widgets/network/scripts/netmenu-items` MUST формировать пункты по текущему состоянию:
- wifi включён → «Поиск сетей Wi-Fi» и «Выключить Wi-Fi»; выключен → только «Включить Wi-Fi»;
- для каждого vpn-соединения: активного — «Отключить <имя>», неактивного — «Подключить <имя>»;
- подключённый ethernet → «Отключить <устройство>».

Каждое действие выполняется веткой общего скрипта `scripts/popup` (`wifi-rescan`, `wifi-toggle`, `vpn-up`/`vpn-down id`, `eth-down device`) и завершается закрытием меню (`net-close`).

#### Scenario: Переключение wifi из меню
- **WHEN** пользователь кликает «Выключить Wi-Fi»
- **THEN** выполняется `nmcli radio wifi off`, меню закрывается

#### Scenario: Рескан сетей
- **WHEN** пользователь кликает «Поиск сетей Wi-Fi»
- **THEN** выполняется `nmcli device wifi rescan`, меню закрывается
