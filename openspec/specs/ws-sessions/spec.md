# ws-sessions Specification

## Purpose

Сессии демона workspaced: автосохранение текущего состояния, именованные снимки, загрузка со сверкой открытых окон, восстановление после перезагрузки и окна вне workspace.

## Requirements

### Requirement: Файлы сессий
Сессии MUST храниться в `~/.local/state/workspaced/sessions/<имя>.toml`, по файлу на сессию. Файл MUST содержать: время снимка, номер активного стола, для каждого стола список workspace по порядку и активный, для каждого workspace назначение приложений по ячейкам и таблицу дополнительных приложений сессии, и список окон: для окна приложения — имя приложения, стол или `pool`, прямоугольник; для постороннего окна — стол, командную строку, каталог и прямоугольник. Запись дополнительного приложения сессии MUST хранить его имя ключом таблицы, прямоугольник и, если запись описывает не приложение конфига, класс окна, командную строку и каталог процесса. Таблица дополнительных приложений MUST быть необязательной: снимок прежнего формата MUST читаться без ошибки. Поле `workspace` у постороннего окна в снимках прежних версий MUST читаться без ошибки и MUST NOT учитываться и записываться. Сессия `default` MUST записываться в обработчике события композитора или команды, изменивших состояние (поднятие, обмен, открытие, закрытие и перемещение окна, смена активного стола), — по одной записи на событие и до ответа на команду, так что к возврату команды файл уже обновлён. Отложенной записи и записи по таймеру MUST NOT быть. Именованная сессия MUST записываться только по команде `session save <имя>` или из окна выбора и MUST быть копией текущего состояния на момент команды.

Командная строка и каталог, которые демон записывает для окна — в снимке сессии, в записи дополнительного приложения сессии и в разделе workspace по команде сохранения, — MUST быть пригодны для запуска с хоста. У процесса в песочнице flatpak путь к исполняемому файлу и рабочий каталог существуют только внутри песочницы, поэтому командной строкой такого окна MUST записываться `flatpak run <идентификатор приложения>` и исходные аргументы процесса после пути к исполняемому файлу, а каталог MUST NOT записываться. Идентификатор приложения MUST браться из `/proc/<pid>/cgroup` по юниту вида `app-flatpak-<идентификатор>-<номер>.scope`, причём экранирование `\xNN` в имени юнита MUST раскодироваться. Если юнита такого вида нет, MUST записываться командная строка процесса как есть.

#### Scenario: Автосохранение
- **WHEN** выполнена команда `workspaced raise dev-front --desktop 1`
- **THEN** к моменту, когда команда вернула управление, `default.toml` уже содержит стол 1 с активным `dev-front` и его окна с прямоугольниками

#### Scenario: Именованный снимок
- **WHEN** выполнена `workspaced session save review`
- **THEN** появляется `review.toml` с тем же содержимым, что у `default.toml` на этот момент; дальнейшая работа его не меняет

#### Scenario: Дополнительное приложение в снимке
- **WHEN** в `work` принят посторонний калькулятор по цепочке `save_session`
- **THEN** к возврату команды в `default.toml` у `work` есть запись дополнительного приложения с классом окна, командной строкой, каталогом и прямоугольником, а само окно записано как окно этого приложения

#### Scenario: Окно программы из flatpak
- **WHEN** в `work` по цепочке `save_session` принято окно Postman, запущенного из flatpak с аргументами `--force-device-scale-factor=1.5` и `--no-sandbox`
- **THEN** командной строкой записано `flatpak run com.getpostman.Postman --force-device-scale-factor=1.5 --no-sandbox`, каталога у записи нет, и этой командой окно поднимается с хоста; путь `/app/extra/Postman/postman` в снимок не попадает

#### Scenario: Снимок прежней версии с привязками
- **WHEN** в `default.toml` у постороннего окна записано `workspace = "work"`, а таблицы дополнительных приложений в файле нет
- **THEN** демон читает снимок, ставит окно на его место на столе, но к `work` не привязывает; после следующей записи снимка поля `workspace` у окна нет

### Requirement: Загрузка сессии
По `session load <имя>` или выбору в окне сессий демон MUST сначала записать текущее состояние в `default`, затем привести систему к снимку: окно, для которого в системе есть открытое окно того же приложения (для постороннего — с той же командной строкой и каталогом), MUST быть переиспользовано и поставлено на место из снимка; окно, которого в снимке нет, MUST быть закрыто штатно, как по запросу закрытия от композитора; окно из снимка, которого нет в системе, MUST быть запущено. Дополнительные приложения сессии MUST браться из загружаемого снимка и заменять прежние целиком: приложения загруженного снимка входят в свои workspace, а дополнительные приложения прежнего состояния MUST быть сняты. Списки workspace по столам и активные MUST стать как в снимке, приведённом к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»); активный стол — как в снимке.

#### Scenario: Загрузка со сверкой
- **WHEN** открыты окна `editor-front`, `terminal-front` и Telegram, и загружена сессия, в которой есть `editor-front`, `firefox-front`, а Telegram нет
- **THEN** окна `editor-front` и `terminal-front` не перезапускаются (`terminal-front` паркуется, если его workspace в снимке не активен), Telegram получает запрос закрытия, `firefox-front` запускается, все окна на местах из снимка

#### Scenario: Дополнительные приложения из снимка
- **WHEN** в текущем состоянии у `work` есть дополнительное приложение `galculator`, а в загружаемой сессии у `work` записано дополнительное приложение `keepassxc`
- **THEN** после загрузки `work` содержит `keepassxc` и не содержит `galculator`, окно `keepassxc` запущено и стоит на месте из снимка

#### Scenario: Несохранённый документ
- **WHEN** загружаемая сессия не содержит окна редактора с несохранённым файлом
- **THEN** редактор получает штатный запрос закрытия и показывает свой диалог, демон не завершает процесс принудительно

### Requirement: Восстановление при старте
При старте демон MUST загрузить `default`: списки workspace по столам, активные и дополнительные приложения сессии восстанавливаются целиком; полностью поднимается (с запуском приложений) только workspace, активный на столе, который был активен на момент снимка; посторонние окна снимка MUST быть запущены сразу на своих местах; активный workspace другого стола MUST подниматься при первом переходе на этот стол; workspace, не активные ни на одном столе, MUST подниматься при первом вызове. Дополнительное приложение сессии MUST восстанавливаться так же, как приложение конфига: при поднятии его workspace демон MUST захватить подходящее открытое окно, а при его отсутствии запустить приложение по записанным командной строке и каталогу. Списки столов из снимка демон MUST привести к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»): столом workspace MUST стать тот, где он в снимке активен, а если он не активен ни на одном столе — первый по номеру стол, в списке которого он встретился; из остальных списков он MUST быть убран, и стол, лишившийся своего активного workspace, MUST остаться без активного. Порядок оставшихся workspace в списке стола MUST сохраняться. Если `default` отсутствует или не читается, демон MUST стартовать с пустым состоянием и записать причину в журнал. После восстановления демон MUST поднять workspace из раздела `[startup]` конфига на его столе, если раздел задан: приложения без окон запускаются, открытые подходящие окна захватываются; если этот workspace уже поднят сессией, повторное поднятие только расставляет окна.

#### Scenario: После перезагрузки
- **WHEN** при выходе был активен стол 1 с `dev-front`, на столе 2 активен `chat`, и сессия запущена заново
- **THEN** через 10 секунд после старта открыты окна `dev-front` на столе 1 и нет окон `chat`; плитка «2» показывает иконку `chat`; при первом переходе на стол 2 `chat` поднимается

#### Scenario: Дополнительное приложение после перезапуска демона
- **WHEN** в `work` принят посторонний калькулятор, и демон перезапущен при открытом окне калькулятора
- **THEN** после старта окно остаётся окном того же дополнительного приложения по своему тегу, второй калькулятор не запускается, и поднятие `work` на другом столе переносит окно туда

#### Scenario: Стартовый workspace из конфига
- **WHEN** в `[startup]` задан `workspace = "work"`, а сессия `default` не содержит активного workspace на столе 1 (например, после удаления прежних workspace из конфига)
- **THEN** через 10 секунд после старта демона `work` поднят на столе 1, его приложения открыты или захвачены, плитка «1» показывает его иконку как активную

#### Scenario: Голая сессия
- **WHEN** загружена именованная сессия, снятая без посторонних окон
- **THEN** посторонние окна, открытые до загрузки, закрыты штатно, восстановлены только workspace снимка

#### Scenario: Посторонние окна в снимке
- **WHEN** в снимке есть калькулятор вне workspace с прямоугольником 1600,900 600×400 на столе 1
- **THEN** после загрузки калькулятор запущен и стоит на столе 1 в прямоугольнике 1600,900 600×400

#### Scenario: Снимок с повторами в списках столов
- **WHEN** в `default.toml` `surf` записан в списках столов 1, 2, 6 и 7 и активен на столе 2, а `work` — в списках столов 1, 2 и 3 и активен на столе 1
- **THEN** после старта `surf` числится только на столе 2, `work` — только на столе 1, списки столов 3, 6 и 7 пусты, и `workspaced status --json` показывает каждый workspace ровно на одном столе

### Requirement: Список сессий для выбора
Команда `session list --json` и событие `show-sessions` MUST отдавать для каждой сессии имя, время снимка и карту «стол → список workspace с активным», достаточную для показа, что поднимется сразу и что лениво, без чтения файлов панелью. Сессия `default` MUST присутствовать в списке под своим именем.

#### Scenario: Список с содержимым
- **WHEN** в каталоге есть `default.toml` и `review.toml`
- **THEN** `workspaced session list --json` печатает обе с временем и картой столов

### Requirement: Дополнительные приложения сессии
По цепочке `save_session` или команде `workspaced save-session` демон MUST включить посторонние окна текущего стола в активный workspace этого стола как дополнительные приложения сессии и MUST NOT изменять файл конфига. Постороннее окно — окно без тега `app:`, находящееся на текущем столе. Для каждого такого окна демон MUST сначала искать среди всех приложений конфига то, которому окно подходит по выражениям `class` и, если оно задано, `title`; поиск MUST идти сначала по приложениям-вариантам, затем по семействам, внутри каждой группы по именам. Если подходящее приложение найдено, окно MUST получить тег экземпляра этого приложения, а дополнительным приложением сессии MUST стать само приложение с прямоугольником окна — и только тогда, когда в этом workspace его ещё нет. Если подходящего приложения нет, демон MUST завести дополнительное приложение сессии с именем, построенным из класса окна и не совпадающим ни с одним именем приложения конфига или другого дополнительного приложения, и записать у него класс окна, командную строку и каталог процесса окна (по правилу требования «Файлы сессий») и его прямоугольник; окно MUST получить тег экземпляра этого приложения. Окно, у которого командной строки процесса получить не удалось, MUST остаться свободным с записью в журнал. Приложения, уже входящие в workspace, MUST NOT менять ни место, ни главную ячейку: команда MUST только добавлять записи о вновь принятых окнах. Если посторонних окон на столе нет, команда MUST ничего не менять и записать строку в журнал.

Дополнительное приложение сессии демон MUST во всём остальном вести как приложение workspace: его окна MUST переноситься вместе с workspace на другой стол, MUST парковаться при вытеснении workspace и возвращаться с ним, MUST вставать на свой прямоугольник при поднятии workspace и MUST входить в состав окон workspace для панели. Если в конфиге появляется приложение с именем дополнительного приложения сессии, MUST действовать запись конфига, а дополнительное приложение MUST быть снято с записью предупреждения в журнал. Запись, которая называет приложение конфига и задаёт ему только место, MUST быть снята, когда приложения с таким именем в конфиге не стало; запись workspace, которого в конфиге не стало, MUST быть снята так же. Перечитывание конфига MUST сохранять дополнительные приложения сессии, кроме снятых по этим правилам.

#### Scenario: Окно из лаунчера становится частью workspace
- **WHEN** на столе 1 активен `work`, из лаунчера открыт калькулятор, не описанный в конфиге, и нажата цепочка `save_session`
- **THEN** `config.toml` не изменился, `chezmoi status` пуст, окно калькулятора несёт тег `app:<имя>#1`, плитка стола 1 показывает его значок, а поднятие `work` на столе 3 переносит калькулятор туда вместе с окнами `work` и ставит на записанное место

#### Scenario: Окно подходит приложению конфига
- **WHEN** на столе 2 активен `surf`, в котором описаны `chrome` и `yandex-browser`, открыто постороннее окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai`, и нажата цепочка `save_session`
- **THEN** окно получает тег `app:chrome-ai#1`, дополнительным приложением `surf` становится `chrome-ai` с прямоугольником окна, нового приложения с именем по классу окна не появляется, `config.toml` не изменился

#### Scenario: Места описанных приложений не трогаются
- **WHEN** в `work` пользователь сдвинул окно Chromium из ячейки `left`, открыл посторонний терминал и нажал цепочку `save_session`
- **THEN** у `chromium` в назначениях workspace остаётся ячейка `left`, главная ячейка прежняя, и следующее поднятие `work` возвращает Chromium в `left`; терминал встаёт на место, записанное при сохранении

#### Scenario: Посторонних окон нет
- **WHEN** на столе все окна принадлежат приложениям активного workspace и нажата цепочка `save_session`
- **THEN** ничего не меняется, в журнале демона строка о том, что посторонних окон на столе нет

#### Scenario: Приложение появилось в конфиге
- **WHEN** дополнительное приложение сессии `galculator` живёт в `work`, и пользователь дописал в конфиг `[apps.galculator]`
- **THEN** после перечитывания конфига действует описание из файла, дополнительное приложение снято, в журнале демона предупреждение об этом
