# ws-sessions Specification

## Purpose

Сессии демона workspaced: автосохранение текущего состояния, именованные снимки, загрузка со сверкой открытых окон, восстановление после перезагрузки и окна вне workspace.

## Requirements

### Requirement: Файлы сессий
Сессии MUST храниться в `~/.local/state/workspaced/sessions/<имя>.toml`, по файлу на сессию. Файл MUST содержать: время снимка, номер активного стола, для каждого стола список workspace по порядку и активный, для каждого workspace назначение приложений по ячейкам и таблицу дополнительных приложений сессии, и список окон: для окна приложения — имя приложения, стол или `pool`, прямоугольник; для свободного окна — стол, командную строку, каталог и прямоугольник. Запись дополнительного приложения сессии MUST хранить его имя ключом таблицы, прямоугольник и, если запись описывает не приложение конфига, класс окна, командную строку и каталог процесса. Таблица дополнительных приложений MUST быть необязательной: снимок прежнего формата MUST читаться без ошибки. Поле `workspace` у свободного окна в снимках прежних версий MUST читаться без ошибки и MUST NOT учитываться и записываться.

Снимок `default` MUST записываться только по команде сохранения сессии — цепочке `save_session` или `workspaced save-session` (требование «Дополнительные приложения сессии»). События композитора и остальные команды демона файл MUST NOT изменять: снимок — это сохранённое состояние, к которому возвращаются, а не след последнего действия. Отложенной записи и записи по таймеру MUST NOT быть. Перед загрузкой именованной сессии демон MUST записать `default` (требование «Загрузка сессии»): это единственный случай, когда файл обновляется не по команде сохранения, и он тоже вызван явной командой пользователя. Именованная сессия MUST записываться только по команде `session save <имя>` или из окна выбора и MUST быть копией текущего состояния на момент команды.

Состояние, изменившееся после последнего снимка — принятые окна, переносы workspace между столами, обмен ячеек, списки столов и записи ожидания запуска, — MUST жить только в памяти демона: перезапуск демона и перезагрузка системы MUST возвращать систему к последнему записанному снимку.

Командная строка и каталог, которые демон записывает для окна — в снимке сессии, в записи дополнительного приложения сессии и в разделе workspace по команде сохранения, — MUST быть пригодны для запуска с хоста. У процесса в песочнице flatpak путь к исполняемому файлу и рабочий каталог существуют только внутри песочницы, поэтому командной строкой такого окна MUST записываться `flatpak run <идентификатор приложения>` и исходные аргументы процесса после пути к исполняемому файлу, а каталог MUST NOT записываться. Идентификатор приложения MUST браться из `/proc/<pid>/cgroup` по юниту вида `app-flatpak-<идентификатор>-<номер>.scope`, причём экранирование `\xNN` в имени юнита MUST раскодироваться. Если юнита такого вида нет, MUST записываться командная строка процесса, приведённая к виду, пригодному для запуска: строка, которую процесс переписал одной строкой с пробелами вместо отдельных аргументов (так делают Chromium и основанные на нём браузеры), MUST делиться по пробелам, если файла с таким именем нет; относительный путь к исполняемому файлу (`./steamwebhelper`) MUST заменяться абсолютным от рабочего каталога процесса; имя без каталога MUST оставаться как есть, если находится в `PATH`; если исполняемый файл так не найден, вместо него MUST браться путь из `/proc/<pid>/exe`. Если не найден и он, у окна нет командной строки: в снимок оно MUST NOT попадать, дополнительным приложением MUST NOT становиться, а демон MUST записать предупреждение в журнал. Команду свободного окна из снимка прежней версии демон MUST приводить к тому же виду перед запуском и сверкой с открытыми окнами; команду, исполняемый файл которой не найден, демон MUST NOT запускать и MUST записать предупреждение в журнал.

#### Scenario: Автосохранение
- **WHEN** выполнена команда `workspaced raise dev-front --desktop 1`, затем открыто новое окно
- **THEN** `default.toml` не изменился: снимок сам по себе не пишется, и время изменения файла прежнее

#### Scenario: Снимок пишет команда сохранения
- **WHEN** после этого нажата цепочка `save_session`
- **THEN** к моменту, когда команда вернула управление, `default.toml` содержит стол 1 с активным `dev-front` и все его окна с прямоугольниками

#### Scenario: Изменения после последнего снимка не переживают перезапуск
- **WHEN** после команды сохранения пользователь перенёс `work` на стол 3, принял там новое окно и перезапустил демон
- **THEN** демон восстанавливает состояние на момент сохранения: `work` снова на прежнем столе, принятого окна в его составе нет

#### Scenario: Именованный снимок
- **WHEN** выполнена `workspaced session save review`
- **THEN** появляется `review.toml` с состоянием на этот момент; дальнейшая работа его не меняет

#### Scenario: Дополнительное приложение в снимке
- **WHEN** в `work` принят калькулятор, не описанный в конфиге, и нажата цепочка `save_session`
- **THEN** к возврату команды в `default.toml` у `work` есть запись дополнительного приложения с классом окна, командной строкой, каталогом и прямоугольником, а само окно записано как окно этого приложения

#### Scenario: Окно программы из flatpak
- **WHEN** в `work` принято окно Postman, запущенного из flatpak с аргументами `--force-device-scale-factor=1.5` и `--no-sandbox`, и нажата цепочка `save_session`
- **THEN** командной строкой записано `flatpak run com.getpostman.Postman --force-device-scale-factor=1.5 --no-sandbox`, каталога у записи нет, и этой командой окно поднимается с хоста; путь `/app/extra/Postman/postman` в снимок не попадает

#### Scenario: Командная строка Chromium
- **WHEN** свободное окно Chromium, процесс которого показывает в `/proc/<pid>/cmdline` одну строку `/usr/lib/chromium/chromium --ozone-platform=wayland`, попадает в снимок
- **THEN** командой записаны два элемента, `/usr/lib/chromium/chromium` и `--ozone-platform=wayland`, и этой командой окно поднимается

#### Scenario: Относительная команда
- **WHEN** свободное окно Steam принадлежит процессу с командой `./steamwebhelper …` и рабочим каталогом `~/.local/share/Steam/ubuntu12_64`, и нажата цепочка `save_session`
- **THEN** командой в снимке записан абсолютный путь `/home/mne/.local/share/Steam/ubuntu12_64/steamwebhelper` с прежними аргументами; снимок прежней версии с `./steamwebhelper` при восстановлении запускается тем же абсолютным путём

#### Scenario: Снимок прежней версии с привязками
- **WHEN** в `default.toml` у свободного окна записано `workspace = "work"`, а таблицы дополнительных приложений в файле нет
- **THEN** демон читает снимок, ставит окно на его место на столе, но к `work` не привязывает; после следующей записи снимка поля `workspace` у окна нет

### Requirement: Загрузка сессии
По `session load <имя>` или выбору в окне сессий демон MUST сначала записать текущее состояние в `default`, затем привести систему к снимку: окно, для которого в системе есть открытое окно того же приложения (для постороннего — с той же командной строкой и каталогом), MUST быть переиспользовано и поставлено на место из снимка; окно, которого в снимке нет, MUST быть закрыто штатно, как по запросу закрытия от композитора; окно из снимка, которого нет в системе, MUST быть запущено. Дополнительные приложения сессии MUST браться из загружаемого снимка и заменять прежние целиком: приложения загруженного снимка входят в свои workspace, а дополнительные приложения прежнего состояния MUST быть сняты. Списки workspace по столам и активные MUST стать как в снимке, приведённом к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»); активный стол — как в снимке.

#### Scenario: Загрузка со сверкой
- **WHEN** открыты окна `editor-front`, `terminal-front` и Telegram, и загружена сессия, в которой есть `editor-front`, `firefox-front`, а Telegram нет
- **THEN** окна `editor-front` и `terminal-front` не перезапускаются (`terminal-front` паркуется, если его workspace в снимке не активен), Telegram получает запрос закрытия, `firefox-front` запускается, все окна на местах из снимка

#### Scenario: Дополнительные приложения из снимка
- **WHEN** в текущем состоянии у `work` есть дополнительное приложение `galculator`, а в загружаемой сессии у `work` записано дополнительное приложение `keepassxc`
- **THEN** после загрузки `work` содержит `keepassxc` и не содержит `galculator`, окно `keepassxc` запущено и стоит на месте из снимка

#### Scenario: Несохранённый документ
- **WHEN** загружаемая сессия не содержит окна редактора с несохранённым файлом
- **THEN** редактор получает штатный запрос закрытия и показывает свой диалог, демон не завершает процесс принудительно

### Requirement: Восстановление при старте
При старте демон MUST загрузить `default`: списки workspace по столам, активные и дополнительные приложения сессии восстанавливаются целиком; полностью поднимается (с запуском приложений) только workspace, активный на столе, который был активен на момент снимка; посторонние окна снимка MUST быть запущены сразу на своих местах; активный workspace другого стола MUST подниматься при первом переходе на этот стол; workspace, не активные ни на одном столе, MUST подниматься при первом вызове. Дополнительное приложение сессии MUST восстанавливаться так же, как приложение конфига: при поднятии его workspace демон MUST захватить подходящее открытое окно, а при его отсутствии запустить приложение по записанным командной строке и каталогу. Списки столов из снимка демон MUST привести к правилу «workspace числится ровно на одном столе» (спецификация ws-daemon, «Поднятие workspace на столе»): столом workspace MUST стать тот, где он в снимке активен, а если он не активен ни на одном столе — первый по номеру стол, в списке которого он встретился; из остальных списков он MUST быть убран, и стол, лишившийся своего активного workspace, MUST остаться без активного. Порядок оставшихся workspace в списке стола MUST сохраняться. Если `default` отсутствует или не читается, демон MUST стартовать с пустым состоянием и записать причину в журнал. После восстановления демон MUST поднять workspace из раздела `[startup]` конфига на его столе, если раздел задан: приложения без окон запускаются, открытые подходящие окна захватываются; если этот workspace уже поднят сессией, повторное поднятие только расставляет окна.

#### Scenario: После перезагрузки
- **WHEN** при выходе был активен стол 1 с `dev-front`, на столе 2 активен `chat`, и сессия запущена заново
- **THEN** через 10 секунд после старта открыты окна `dev-front` на столе 1 и нет окон `chat`; плитка «2» показывает иконку `chat`; при первом переходе на стол 2 `chat` поднимается

#### Scenario: Дополнительное приложение после перезапуска демона
- **WHEN** в `work` принят посторонний калькулятор, и демон перезапущен при открытом окне калькулятора
- **THEN** после старта окно остаётся окном того же дополнительного приложения по своему тегу, второй калькулятор не запускается, и поднятие `work` на другом столе переносит окно туда

#### Scenario: Стартовый workspace из конфига
- **WHEN** в `[startup]` задан `workspace = "work"`, а сессия `default` не содержит активного workspace на столе 1 (например, после удаления прежних workspace из конфига)
- **THEN** через 10 секунд после старта демона `work` поднят на столе 1, его приложения открыты или захвачены, плитка «1» показывает его иконку как активную

#### Scenario: Голая сессия
- **WHEN** загружена именованная сессия, снятая без посторонних окон
- **THEN** посторонние окна, открытые до загрузки, закрыты штатно, восстановлены только workspace снимка

#### Scenario: Посторонние окна в снимке
- **WHEN** в снимке есть калькулятор вне workspace с прямоугольником 1600,900 600×400 на столе 1
- **THEN** после загрузки калькулятор запущен и стоит на столе 1 в прямоугольнике 1600,900 600×400

#### Scenario: Снимок с повторами в списках столов
- **WHEN** в `default.toml` `surf` записан в списках столов 1, 2, 6 и 7 и активен на столе 2, а `work` — в списках столов 1, 2 и 3 и активен на столе 1
- **THEN** после старта `surf` числится только на столе 2, `work` — только на столе 1, списки столов 3, 6 и 7 пусты, и `workspaced status --json` показывает каждый workspace ровно на одном столе

### Requirement: Список сессий для выбора
Команда `session list --json` и событие `show-sessions` MUST отдавать для каждой сессии имя, время снимка и карту «стол → список workspace с активным», достаточную для показа, что поднимется сразу и что лениво, без чтения файлов панелью. Сессия `default` MUST присутствовать в списке под своим именем.

#### Scenario: Список с содержимым
- **WHEN** в каталоге есть `default.toml` и `review.toml`
- **THEN** `workspaced session list --json` печатает обе с временем и картой столов

### Requirement: Дополнительные приложения сессии
Окно, принятое в workspace по событию (спецификация ws-daemon, «Посторонние окна») или по команде сохранения сессии, а также окно, перетащенное в workspace цепочкой приложения с признаком перетаскивания (спецификация ws-daemon, «Цепочка приложения»), MUST становиться дополнительным приложением сессии этого workspace, если приложения с таким местом в workspace ещё нет. Запись MUST жить только в сессии: файл конфига демон MUST NOT изменять. Если окно подходит приложению конфига, дополнительным приложением MUST становиться само это приложение с прямоугольником окна — и только тогда, когда в этом workspace его ещё нет. Если подходящего приложения нет, демон MUST завести дополнительное приложение сессии с именем, построенным из класса окна и не совпадающим ни с одним именем приложения конфига или другого дополнительного приложения, и записать у него класс окна, командную строку и каталог процесса окна (по правилу требования «Файлы сессий») и его прямоугольник. Если приложение окна известно только записи сессии другого workspace, в этом workspace MUST заводиться полная запись под тем же именем — с классом, командной строкой, каталогом и прямоугольником: запись только о месте без приложения в файле конфига не выживает. Окно MUST получить тег экземпляра этого приложения и тег состава этого workspace (спецификация ws-daemon, «Состав workspace»). Имя дополнительного приложения MUST быть единственным в сессии: одно имя MUST называть одну программу, и окно другой программы MUST NOT приписываться чужой записи, даже если класс окна тот же (спецификация ws-daemon, «Посторонние окна»). Окно без класса и окно, для процесса которого не найден исполняемый файл, дополнительным приложением MUST NOT становиться: первое не отличить от служебного окна приложения, второе нечем запустить заново.

По цепочке `save_session` или команде `workspaced save-session` демон MUST записать снимок сессии целиком. Команда MUST пройти по всем столам, на которых активен workspace, и принять в него окна без тега по тем же правилам, что действуют при появлении окна; местом принятого окна MUST становиться прямоугольник, который окно занимает сейчас, — окно, уже поставленное пользователем куда нужно, команда MUST NOT двигать. Затем команда MUST обновить прямоугольники дополнительных приложений сессии по нынешнему положению их окон (у приложения с несколькими окнами — по первому экземпляру, входящему в этот workspace) и записать снимок. Окно, которое стоит не на столе этого workspace (общее окно ушло за пользователем к другому своему workspace), MUST давать прямоугольник, запомненный для этого workspace в режиме `stack`, а без такого прямоугольника запись MUST NOT меняться: нынешнее положение окна описывает место в другом workspace. Приложения, описанные в конфиге, MUST сохранять своё место и главную ячейку: их ведёт файл. Команда MUST записать в журнал строку с числом workspace, числом их окон и числом принятых окон. Файл конфига команда MUST NOT изменять.

Дополнительное приложение сессии демон MUST во всём остальном вести как приложение workspace: его окна MUST переноситься вместе с workspace на другой стол, MUST парковаться при вытеснении workspace и возвращаться с ним, MUST вставать на свой прямоугольник при поднятии workspace и MUST входить в состав окон workspace для панели. Если в конфиге появляется приложение с именем дополнительного приложения сессии, MUST действовать запись конфига, а дополнительное приложение MUST быть снято с записью предупреждения в журнал. Запись, которая называет приложение конфига и задаёт ему только место, MUST быть снята, когда приложения с таким именем в конфиге не стало; запись workspace, которого в конфиге не стало, MUST быть снята так же. Запись MUST сниматься и тогда, когда из этого workspace по команде отделения окна (спецификация ws-daemon, «Отделение окна») уходит последнее окно приложения; если окно при этом закрывается и других окон у приложения нет нигде, запись с командной строкой MUST сниматься во всех workspace, где она есть, а если окна приложения остаются в других workspace, их записи MUST оставаться. Перечитывание конфига MUST сохранять дополнительные приложения сессии, кроме снятых по этим правилам.

#### Scenario: Окно из лаунчера становится частью workspace
- **WHEN** на столе 1 активен `work` и из лаунчера открыт калькулятор, не описанный в конфиге
- **THEN** `config.toml` не изменился, `chezmoi status` пуст, окно калькулятора несёт тег `app:<имя>#1`, плитка стола 1 показывает его значок, а поднятие `work` на столе 3 переносит калькулятор туда вместе с окнами `work`

#### Scenario: Окно подходит приложению конфига
- **WHEN** на столе 2 активен `surf`, в котором описаны `chrome` и `yandex-browser`, и открыто окно класса `google-chrome-ai`, подходящее описанному в конфиге приложению `chrome-ai`
- **THEN** окно получает тег `app:chrome-ai#1`, дополнительным приложением `surf` становится `chrome-ai` с прямоугольником окна, нового приложения с именем по классу окна не появляется, `config.toml` не изменился

#### Scenario: Команда сохранения проходит по всем столам
- **WHEN** на столе 1 активен `work`, на столе 2 активен `surf`, на столе 2 открыто окно, появившееся до поднятия `surf` и потому оставшееся свободным, и нажата цепочка `save_session`
- **THEN** окно входит в `surf` дополнительным приложением с нынешним прямоугольником, снимок записан, в журнале строка с числом workspace, их окон и принятых окон

#### Scenario: Места дополнительных приложений обновляются
- **WHEN** принятое окно калькулятора передвинуто пользователем и нажата цепочка `save_session`
- **THEN** у дополнительного приложения записан новый прямоугольник, и следующее поднятие `work` ставит калькулятор туда, а не на прежнее место

#### Scenario: Посторонних окон нет
- **WHEN** на столах все окна уже входят в свои workspace и нажата цепочка `save_session`
- **THEN** снимок всё равно записан, в журнале демона строка с числом workspace, их окон и нулём принятых окон

#### Scenario: Места описанных приложений не трогаются
- **WHEN** в `work` пользователь сдвинул окно Chromium из ячейки `left` и нажал цепочку `save_session`
- **THEN** у `chromium` в назначениях workspace остаётся ячейка `left`, главная ячейка прежняя, и следующее поднятие `work` возвращает Chromium в `left`

#### Scenario: Приложение появилось в конфиге
- **WHEN** дополнительное приложение сессии `galculator` живёт в `work`, и пользователь дописал в конфиг `[apps.galculator]`
- **THEN** после перечитывания конфига действует описание из файла, дополнительное приложение снято, в журнале демона предупреждение об этом

#### Scenario: Окна без класса не становятся приложением
- **WHEN** на столе 1 активен `work`, на столе 2 — `surf`, в Chromium и в Яндекс.Браузере открыты диспетчеры задач, окна которых пришли с пустым классом, и нажата цепочка `save_session`
- **THEN** оба окна остаются свободными, ни в `work`, ни в `surf` нет дополнительного приложения `app`, в снимке они записаны свободными окнами со своими командами, и поднятие `surf` запускать нечего

#### Scenario: Перетаскивание заводит запись о месте
- **WHEN** окно `chrome-ai` из `surf` перетащено в `work` командой `workspaced app chrome-ai --pull`
- **THEN** у `work` появляется дополнительное приложение сессии `chrome-ai` — запись только о месте с прямоугольником окна, `config.toml` не изменился, а после `save_session` запись есть в `default.toml`

#### Scenario: Место общего окна при сохранении сессии
- **WHEN** окно `chrome-ai` входит в `work` (стол 1, запись о месте) и `surf` (стол 2), пользователь на столе 2, окно стоит там, и нажата цепочка `save_session`
- **THEN** запись `chrome-ai` у `work` сохраняет прежний прямоугольник, а не получает положение окна на столе 2

#### Scenario: Отделение общего окна снимает запись только в своём workspace
- **WHEN** дополнительное приложение сессии `alacritty` принято в `work`, его единственное окно перетащено в `dev-front` (там заведена полная запись под тем же именем), и в `work` нажато Shift+Super+Delete
- **THEN** запись `alacritty` у `work` снята, у `dev-front` осталась, окно не закрыто и входит в `dev-front`

### Requirement: Раскладка снимка по устаревшему шаблону
Команда сохранения сессии MUST записывать у раскладки workspace геометрию ячеек его шаблона из файла конфига: имя каждой ячейки и её прямоугольник на мониторе в момент снимка (таблица `grid`). Таблица MUST быть необязательной: снимок без неё MUST читаться без ошибки.

При загрузке сессии и при восстановлении при старте раскладка workspace из снимка MUST считаться устаревшей, если она называет ячейку, которой в нынешнем шаблоне workspace нет, или если ячейка из таблицы `grid` снимка исчезла из шаблона либо стоит теперь в другом прямоугольнике. Ячейка, добавленная в шаблон после снимка, раскладку устаревшей MUST NOT делать. Снимок без таблицы `grid` MUST сверяться только по именам ячеек. Устаревшую раскладку демон MUST отбросить целиком — назначения мест, главное приложение и изменённые места — и собрать раскладку из конфига, записав причину в журнал. Вместе с ней MUST отбрасываться прямоугольники окон снимка для этого workspace: окно, восстановленное по записи снимка или уже открытое, MUST вставать на место своего приложения в раскладке, собранной из конфига, а не в прямоугольник из снимка. Прямоугольники окон для других workspace, состав окон и записи дополнительных приложений сессии MUST оставаться в силе. Если раскладка не устарела, прямоугольники окон из снимка MUST действовать как есть, даже если окно стоит вне ячейки и вне изменённого места своего приложения.

#### Scenario: Снимок до смены шаблона
- **WHEN** снимок записан, когда у `work` был шаблон `thirds`: у `work` назначения `chromium` — `left`, `chrome` — `right`, `herdr` и `neovide` — `center`, у окон прямоугольники для `work` по этим ячейкам, у общего окна `chrome` — ещё и для `surf`; в конфиге у `work` шаблон `thirds-split` с `chromium` в `left_top`, `chrome` в `left_bottom`, `herdr` в `center`, `neovide` в `right`, и система перезагружена
- **THEN** в журнале строка о том, что раскладка `work` собирается заново из конфига; окна `work` встают в ячейки `thirds-split` по конфигу, а при переходе на стол `surf` окно `chrome` встаёт в свой прямоугольник для `surf` из снимка

#### Scenario: Ячейка с тем же именем и другой геометрией
- **WHEN** снимок записан, когда ячейка `center` шаблона `work` была 1125,10 1920×2140, после этого в конфиге она стала 1130,10 1910×2140, и система перезагружена
- **THEN** раскладка `work` из снимка отбрасывается, и окно `herdr` встаёт в 1130,10 1910×2140

#### Scenario: Сдвинутый экземпляр при годной раскладке
- **WHEN** шаблон `work` после снимка не менялся, а второе окно Chromium в снимке стоит в 400,300 1400×1000 — вне ячеек и вне изменённого места `chromium`, — и система перезагружена
- **THEN** раскладка `work` из снимка действует, а второе окно Chromium встаёт в 400,300 1400×1000

### Requirement: Раскладка снимка по прежнему разделу workspace
Команда сохранения сессии MUST записывать у раскладки workspace домашние места записей его раздела из файла конфига — ячейку шаблона или прямоугольник на мониторе в момент снимка (таблица `homes`) — и главное приложение раздела (поле `homes_main`: поле `main` раздела, без него — приложение главной ячейки шаблона). Записи дополнительных приложений сессии в таблицу MUST NOT попадать. Таблица и поле MUST быть необязательными: снимок без них MUST читаться без ошибки.

При загрузке сессии и при восстановлении при старте раскладка workspace из снимка MUST считаться устаревшей, если в разделе появилась запись, которой нет в таблице `homes`, если запись из таблицы из раздела исчезла, если домашнее место записи стало другим или если главное приложение раздела сменилось. Снимок без таблицы `homes` MUST считаться устаревшим, если в его назначениях мест нет записи раздела; пустые назначения мест устаревшими MUST NOT считаться. Устаревшая раскладка MUST отбрасываться так же, как раскладка по устаревшему шаблону (требование «Раскладка снимка по устаревшему шаблону»), с причиной в журнале. Если раздел после снимка не менялся, обмены мест и раскладка по домам из снимка MUST действовать.

#### Scenario: Запись добавлена в раздел после снимка
- **WHEN** снимок записан, когда в разделе `surf` были `chrome` в `left`, `chrome-ai` в `right` и `yandex-browser` в `center`; после этого в раздел добавлен `chrome-ai2` в `right`, а `chrome-ai` переставлен в `left`, и демон перезапущен
- **THEN** в журнале строка о том, что раскладка `surf` собирается заново из конфига; после поднятия `surf` окно `chrome-ai` стоит в `left`, окно `chrome-ai2` — в `right`

#### Scenario: Обмен мест при неизменном разделе
- **WHEN** в workspace режима `swap` клавиша приложения поменяла местами `neovide` и главное приложение, сессия сохранена, раздел не менялся, и система перезагружена
- **THEN** раскладка из снимка действует: `neovide` стоит на главном месте

### Requirement: Столы снимка за числом столов
При загрузке снимка сессии — при старте демона и по команде `session load` — демон MUST отбросить записи снимка, относящиеся к столу с номером больше N (число столов из ключа `desktops`, спецификация ws-config, «Число столов»): список workspace такого стола, окно приложения без workspace и постороннее окно, записанные с таким столом. О каждой отброшенной записи демон MUST писать предупреждение в журнал с номером стола и тем, что отброшено; пустой список стола, который снимки прежних версий писали для всех восьми столов, MAY отбрасываться без предупреждения. Окна, уже открытые на экране, отброшенная запись MUST NOT трогать: демон их не закрывает и не переносит. Запись окна, входящего в workspace, MUST оставаться: стол снимка для такого окна при восстановлении не учитывается, и окно встаёт по правилу размещения своего workspace. Активный стол снимка с номером больше N MUST заменяться столом 1. Сам файл снимка при загрузке MUST NOT переписываться: он меняется только командами сохранения.

#### Scenario: Снимок восьми столов при четырёх столах
- **WHEN** в снимке `default` есть пустые списки столов 5…7 и окно Firefox на столе 4, а в конфиге `desktops = 4`, и демон перезапущен
- **THEN** списки столов 5…7 отброшены, окно Firefox восстанавливается на столе 4, `workspaced status --json` показывает столы 1…4

#### Scenario: Окно на столе за числом столов
- **WHEN** в снимке записано постороннее окно на столе 6, на столе 5 — список с workspace `dev`, а в конфиге `desktops = 4`
- **THEN** окно стола 6 не запускается, список стола 5 не восстанавливается, в журнале по предупреждению о каждой записи; окна, открытые на экране, остаются, где стоят
