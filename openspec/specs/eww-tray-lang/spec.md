# eww-tray-lang Specification

## Purpose

Вертикальная полоса из двух плиток справа от плиток рабочих столов: системный трей (`widgets/tray`) и переключатель раскладки клавиатуры (`widgets/lang`). Оба — отдельные окна eww (`tile-tray`, `tile-lang`), см. eww-shell.

## Requirements

### Requirement: Раскладка полосы
Полоса MUST иметь ширину плитки раскладки (36px) и стоять справа от плиток столов (x = 294…330px), занимая по высоте весь блок столов (1462…1820px): сверху трей высотой 312px с иконками в столбик, затем зазор 10px, снизу квадратный переключатель раскладки 36×36px на уровне последней плитки стола. Порядок фиксирован: сначала трей, затем переключатель.

#### Scenario: Полоса заполняет блок столов
- **WHEN** дашборд открыт
- **THEN** окно `tile-tray` занимает y = 1462…1773px, окно `tile-lang` — y = 1784…1819px, оба шириной 36px при x = 294px

### Requirement: Системный трей
tray-tile MUST содержать виджет eww `systray` (вертикальный, иконки 20px, зазор 6px, новые иконки добавляются в начало). Высота плитки 312px MUST сохраняться и при пустом трее.

Виджет работает по протоколу StatusNotifierItem (D-Bus): eww регистрирует `org.kde.StatusNotifierWatcher`. Приложения, использующие только XEmbed (`_NET_SYSTEM_TRAY_S0`, например nm-applet), MUST попадать в трей через мост `xembedsniproxy` (пакет AUR `xembed-sni-proxy-standalone-git`): автозапуск Openbox запускает его после открытия окон eww, поскольку мосту нужен уже зарегистрированный StatusNotifierWatcher. Других владельцев селекции XEmbed (трей tint2) в сессии быть не должно, иначе мост не получит иконки.

Клики по иконкам MUST передаваться приложениям с координатами относительно экрана. В eww 0.6.0 (до коммита 48f5aa8 включительно) виджет `systray` на X11 прибавляет к экранным координатам ещё и положение окна, из-за чего мост получает точку за пределами экрана, меню не открываются, а вызов `ContextMenu` зацикливается между eww и мостом. Кроме того, eww отправляет вызов по нажатию кнопки, пока физическая кнопка ещё удержана; мост воспроизводит клик через XTest и не может нажать уже нажатую кнопку, поэтому при обычном (не мгновенном) клике приложение ничего не получает. Для элементов с собственным меню DBusMenu (handy, Telegram) обработка по нажатию обязательна: GTK ожидает нажатие для показа меню, а XTest там не участвует. Колесо мыши над иконкой MUST передаваться методом `Scroll` (положительная дельта — вверх, как в KDE), чтобы pasystray менял громкость, как в трее XEmbed.

Меню DBusMenu (Telegram, handy) рисует сам eww, и они MUST быть оформлены в духе плиток: фон `$tile-bg` с размытием picom, рамка `$tile-border` со скруглением 8px (углы окна срезает picom тем же радиусом), текст и разделители цвета рамки, шрифт подписей пунктов фиксированный, 18px (размер задаётся узлу `label`: глобальное правило `* { font-size: 14px }` не даёт подписям наследовать размер от `menu`); текст пунктов MUST начинаться на одной вертикали с разделителями (боковые отступы пунктов и разделителей равны, индикатор флажка у неотмеченных пунктов нулевого размера, отмеченный пункт получает жёлтый маркер; место под флажки в сборке eww не резервируется). Место открытия меню задаётся атрибутами виджета `systray` из локальной сборки eww: `:menu-anchor "workarea"` держит меню внутри рабочей области с зазором `:menu-gap` пикселей от её края, `:menu-anchor "pointer"` открывает меню прямо в точке клика поверх плиток. В конфигурации MUST стоять `:menu-anchor "workarea" :menu-gap 10`: меню открывается с зазором 10px от правого края колонки плиток. Подсказки (`tooltip`) MUST иметь фон, рамку и отступы.

Используемая сборка eww MUST содержать все исправления (экранные координаты на X11; клик по отпусканию для элементов без DBusMenu и по нажатию для элементов с ним; передача прокрутки; RGBA-визуал окна DBusMenu, без которого полупрозрачный фон превращается в чёрный; атрибуты `menu-anchor` и `menu-gap` для размещения меню; атрибут `hide` — список Id или Title элементов StatusNotifierItem, которые не показываются в трее, но остаются зарегистрированными): ветка `fix-systray-x11-click-coords` в `~/builds/eww` (файлы `crates/eww/src/widgets/systray.rs`, `crates/notifier_host/src/item.rs`). В upstream eww этих исправлений нет; у других пользователей проблема не проявляется, потому что их панель стоит в точке (0, 0), а трей состоит из родных StatusNotifier-приложений без моста.

#### Scenario: Меню иконки трея
- **WHEN** пользователь кликает правой кнопкой по иконке nm-applet в tray-tile, удерживая кнопку обычное для клика время
- **THEN** контекстное меню nm-applet открывается рядом с иконкой, на шине проходит ровно один вызов `ContextMenu`

#### Scenario: Приложение XEmbed через мост
- **WHEN** запущены eww, затем xembedsniproxy, затем nm-applet
- **THEN** иконка nm-applet отображается в tray-tile

#### Scenario: Приложение со StatusNotifierItem
- **WHEN** запускается приложение, регистрирующее StatusNotifierItem (например, Telegram)
- **THEN** его иконка появляется в tray-tile

### Requirement: Громкость в трее
Внизу tray-tile MUST стоять собственная кнопка громкости (глиф Nerd Font 28px цвета рамки, видимая часть около 20px — как иконки трея; ширина окна остаётся 36px), а иконка pasystray MUST быть скрыта атрибутом `:hide {["PulseAudio system tray"]}` виджета `systray`; сам pasystray при этом запущен (список `dot_config/openbox/tray`), поскольку его меню используется. Левый клик по кнопке MUST открывать Volume Control (`pavucontrol`); правый клик MUST открывать штатное меню pasystray: демон (`eww-daemon tray-menu "PulseAudio system tray"`) находит элемент по Id среди `RegisteredStatusNotifierItems` и вызывает его метод `ContextMenu` в точке курсора. Наведение на кнопку MUST выдвигать над ней панель громкости (кнопка остаётся открытой, зазор 6px), закрывающую все иконки трея: ширина плитки, высота — весь трей над кнопкой (270px), анимация выезда снизу вверх (`revealer`, переход `slideup`, 150 мс); в панели вертикальный ползунок цвета рамки (`scale`, 0…101, привязан к `current-volume` — poll 1s скрипта `widgets/tray/scripts/volume`, всегда число; отдельной плитки громкости в колонке нет, громкость живёт только в трее) и число процентов. Громкость MUST меняться и колесом мыши над ползунком, и кликом по полосе (`pactl set-sink-volume @DEFAULT_SINK@ N%`). Панель MUST скрываться, как только курсор покидает плитку трея (`onhoverlost` внешнего eventbox, переменная `tray-vol`).

#### Scenario: Панель громкости по наведению
- **WHEN** курсор входит в кнопку громкости внизу трея
- **THEN** над кнопкой снизу вверх выезжает панель с вертикальным ползунком, закрывая иконки трея, но не кнопку; клик по полосе на уровне 60% ставит громкость 60%, колесо вверх её увеличивает; когда курсор выходит за пределы плитки трея, панель исчезает

#### Scenario: Клики по кнопке громкости
- **WHEN** пользователь кликает по кнопке громкости левой кнопкой
- **THEN** открывается окно pavucontrol
- **WHEN** пользователь кликает по ней правой кнопкой
- **THEN** у курсора открывается штатное меню pasystray (Default Sink, Volume Control…, Quit), а иконки pasystray в самом трее нет

### Requirement: Переключатель раскладки
lang-tile MUST показывать текущую раскладку заглавными буквами (US, RU) из потока `xkb-switch -W` (deflisten `kb-layout`, скрипт `widgets/lang/scripts/layout` сначала выводит текущую раскладку `xkb-switch -p`). Клик по плитке MUST переключать раскладку на следующую (`xkb-switch -n`). Скрипт MUST выводить каждое значение без буферизации, чтобы плитка обновлялась сразу.

#### Scenario: Смена раскладки горячей клавишей
- **WHEN** пользователь переключает раскладку сочетанием клавиш Openbox
- **THEN** подпись плитки меняется на новую раскладку без клика по ней

#### Scenario: Смена раскладки кликом
- **WHEN** пользователь кликает по lang-tile
- **THEN** активной становится следующая раскладка, подпись обновляется
