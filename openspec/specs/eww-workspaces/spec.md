# eww-workspaces Specification

## Purpose

Модуль рабочих столов Openbox: одинаковые плитки, по одной на стол, с иконками окон слева и номером стола справа; каждая плитка — отдельное окно eww. Реализация — демон `eww-daemon workspaces` (Rust, проект `~/work/pets/eww-daemon`, символическая ссылка `~/.local/bin/eww-daemon`; deflisten `workspace`) и разметка в `workspaces.yuck`. Прежний shell-скрипт `widgets/workspaces/scripts/workspace` с резолвером `scripts/appicon` оставлен как запасной вариант.

## Requirements

### Requirement: Реактивное обновление
Демон MUST вывести начальное состояние и обновлять его по событиям X без опроса: `PropertyNotify` корневого окна (`_NET_CURRENT_DESKTOP`, `_NET_CLIENT_LIST`, `_NET_CLIENT_LIST_STACKING`, `_NET_ACTIVE_WINDOW`, `_NET_NUMBER_OF_DESKTOPS`) и каждого клиентского окна (`_NET_WM_DESKTOP`, `_NET_WM_STATE`, `_NET_WM_NAME`, `WM_NAME`). Состояние окон MUST храниться в памяти: при смене стола список окон не перечитывается. Задержка от события до вывода MUST быть не более 50 мс (замер: 9–32 мс против 0,4–1,6 с у shell-скрипта). Число столов — `_NET_NUMBER_OF_DESKTOPS`, фолбэк 8; текущий стол — `_NET_CURRENT_DESKTOP`, фолбэк 0.

Состояние MUST передаваться в eww одной JSON-строкой на обновление: список столов с номером, признаком активности, списком окон (идентификатор, путь к иконке либо глиф, признак свёрнутости, название программы) и числом не показанных окон. Разметка плитки MUST описываться в yuck-файле виджета, а не генерироваться демоном. Если новое состояние совпадает с предыдущим выведенным, демон MUST NOT выводить его повторно; события одной пачки MUST сворачиваться в один вывод.

#### Scenario: Переключение стола
- **WHEN** пользователь переходит на другой рабочий стол
- **THEN** рамка и светлый номер переходят к плитке нового активного стола, раскладка остальных плиток не меняется

#### Scenario: Сворачивание окна вызывает перерисовку
- **WHEN** пользователь сворачивает активное окно
- **THEN** плитки перерисовываются без ожидания смены стола или списка окон

### Requirement: Окно на каждый стол
Каждый рабочий стол MUST отображаться отдельным окном eww `tile-ws<n>` (n = 1…8), объявленным в `eww.yuck`; окно рисует виджет `workspace-tile` с параметром `i` (индекс стола, 0-based), который выбирает свой стол из общего состояния `workspace.desktops` фильтром jq по полю `idx`. Число окон MUST совпадать с числом столов в `rc.xml` Openbox (`<desktops><number>`). Если стола с таким индексом нет, окно MUST остаться пустым без ошибок.

Раздельные окна обусловлены композитором: picom размывает фон по форме окна целиком, и только так промежутки между плитками столов остаются без размытия.

#### Scenario: Столы в отдельных окнах
- **WHEN** дашборд открыт
- **THEN** существует восемь окон `tile-ws1`…`tile-ws8`, каждое показывает плитку своего стола

### Requirement: Единая раскладка плитки стола
Каждый рабочий стол MUST отображаться плиткой одинаковой формы независимо от того, активен ли он и есть ли на нём окна: слева ряд иконок приложений 20×20 (полноцветная иконка либо глиф-фолбэк), справа номер стола в собственном блоке (класс `ws-num`) во всю высоту содержимого плитки (34px), вплотную к рамке и без зазора: правые углы блока скруглены под внутренний радиус рамки, ширина блока 30px (24px + отступы по 3px), цифра максимальной жирности (900) увеличенного размера (1.3em). Плитка MUST иметь фиксированные размеры: ширина 274px (справа от неё полоса 36px с треем и переключателем раскладки), высота 36px (рамка 1px, ряд иконок 24px с отступами по 5px сверху и снизу). Пустой стол MUST занимать плитку того же размера только с номером.

Клик по свободному месту плитки MUST переключать на этот стол (`xdotool set_desktop`). Каждая иконка MUST быть кнопкой: левый клик показывает окно (`eww-daemon window <id> activate`: демон посылает EWMH-сообщения `_NET_CURRENT_DESKTOP` со столом окна и `_NET_ACTIVE_WINDOW`, Openbox переключает стол, поднимает окно и даёт ему фокус); правый клик открывает контекстное меню окна (`eww-daemon window-menu <id> <стол>`: окно eww `winmenu` у курсора с пунктами «Показать», «Свернуть», «Закрыть» и «На стол N» для всех столов, кроме стола окна; действия выполняются через EWMH: `_NET_ACTIVE_WINDOW`, `WM_CHANGE_STATE`, `_NET_CLOSE_WINDOW`, `_NET_WM_DESKTOP`; меню закрывается после действия и когда курсор его покидает); при наведении на иконку демон (`eww-daemon hover window <id>`) MUST открывать у курсора окно `hoverinfo` с подробностями: название программы, заголовок окна, класс, стол, признак свёрнутости, PID и команда; окно держится в пределах колонки плиток и следует за курсором, а при уходе курсора закрывается (`hover-hide`). Штатные tooltip у иконок не используются.

#### Scenario: Плитки не меняют высоту при переключении стола
- **WHEN** пользователь переходит с пустого стола на стол с шестью окнами
- **THEN** высота каждой плитки остаётся прежней

#### Scenario: Переход к окну другого стола
- **WHEN** пользователь кликает по иконке окна на неактивном столе
- **THEN** активируется этот стол и фокус получает именно это окно

#### Scenario: Контекстное меню окна
- **WHEN** пользователь кликает правой кнопкой по иконке окна на столе 3
- **THEN** у курсора открывается меню с пунктами «Показать», «Свернуть», «Закрыть», «На стол 1, 2, 4…8» (без «На стол 3»); выбор «На стол 5» переносит окно на пятый стол, и меню закрывается

#### Scenario: Переключение стола кликом по плитке
- **WHEN** пользователь кликает по плитке вне иконок
- **THEN** активным становится соответствующий стол

### Requirement: Отличия активного стола
Плитка активного стола (класс `ws-fo`) MUST выделяться блоком номера, залитым цветом рамки (`$yellow`), с чёрной цифрой; рамка активной плитки того же цвета и толщины, что у остальных плиток. У остальных столов блок номера имеет полупрозрачный фон `$ws-num-bg` (rgba(6, 6, 6, 0.6)) и цифру цвета рамки (`$yellow`). Фон плитки `$tile-bg` MUST заливать только область ряда иконок, а не всю плитку, чтобы под блоком номера не складывались две полупрозрачные заливки. Заливки содержимого MUST NOT перекрывать рамку плитки: содержимое отступает от края на толщину рамки (1px), и рамка видна так же, как у остальных плиток. Иных отличий в раскладке активная плитка MUST NOT иметь: список окон с подписями на ней не разворачивается.

При наведении курсора на плитку неактивного стола MUST подсвечиваться только блок номера: его фон становится `$background`, как у кнопки переключателя раскладки; рамка, цифра и ряд иконок не меняются.

#### Scenario: Подсветка при наведении
- **WHEN** курсор находится над плиткой неактивного стола
- **THEN** фон блока номера становится `$background`, остальное оформление плитки не меняется; после ухода курсора возвращается обычное оформление

#### Scenario: Активный стол не реагирует на наведение
- **WHEN** курсор находится над плиткой активного стола
- **THEN** её оформление не меняется

#### Scenario: Активный стол читается по номеру
- **WHEN** дашборд отрисован
- **THEN** ровно одна плитка имеет жёлтый блок с чёрной цифрой, у остальных блок полупрозрачный с жёлтой цифрой; рамки у всех плиток жёлтые

### Requirement: Отображение свёрнутых окон
Иконка свёрнутого окна MUST отображаться приглушённой (класс `ws-min`, полупрозрачность). Свёрнутость MUST определяться по наличию атома `_NET_WM_STATE_HIDDEN` в списке `_NET_WM_STATE` окна.

#### Scenario: Свёрнутое окно приглушено
- **WHEN** пользователь сворачивает окно на активном столе
- **THEN** после перерисовки его иконка в плитке становится полупрозрачной, остальные иконки не меняются

### Requirement: Ограничение числа иконок
Плитка MUST показывать не более 10 иконок. Если окон на столе больше, отображаются первые 10 в порядке `_NET_CLIENT_LIST` и метка «+N», где N — количество не показанных окон. При 10 и менее окнах метка MUST отсутствовать.

#### Scenario: Тринадцать окон на столе
- **WHEN** на столе открыто 13 окон
- **THEN** плитка показывает 10 иконок и метку «+3», ширина плитки остаётся 274px

### Requirement: Исключения окон
Из списка MUST исключаться sticky-окна (десктоп 4294967295) — панели, трей, окна самого eww. Окна без читаемого десктопа пропускаются.

#### Scenario: Трей не попадает в списки
- **WHEN** запущен trayer/sticky-виджет
- **THEN** ни одна плитка его не показывает

### Requirement: Соответствие WM_CLASS
Таблицы соответствия MUST покрывать известные классы (firefox/Navigator, Chromium/Google-chrome, Yandex-browser*, Wezterm/org.wezfurlong.wezterm, терминалы, Neovide/nvim, TelegramDesktop, pavucontrol, nm-connection-editor, Thunar, PCManFM, Code/code-oss): имя иконки-кандидата и название программы для всплывающей подсказки. Неизвестный класс → кандидаты из нижнего регистра класса и его последнего компонента; название — последний компонент после точки.

Иконки разрешаются общим резолвером appicon; при неудаче используется Nerd Font глиф-фолбэк.

Программы, работающие внутри терминала, собственного окна не имеют. Заголовок окна wezterm имеет вид `<программа> · <заголовок панели>` (обработчик `format-window-title` в конфиге wezterm, имя программы на переднем плане wezterm берёт из pty). Демон MUST брать имя программы из этого префикса и подбирать иконку по нему (yazi, nvim, htop и т. д.); если иконка программы не найдена или на переднем плане оболочка (bash, zsh, fish, sh), MUST использоваться иконка терминала. Смена заголовка приходит событием `PropertyNotify` окна, поэтому иконка обновляется сразу и без опросов. Флаг `wezterm start --class <имя>` при запуске из дашборда допустим, но демону не нужен.

#### Scenario: Yazi из избранного
- **WHEN** пользователь открывает yazi кнопкой избранного (`wezterm start --class yazi`)
- **THEN** плитка стола показывает иконку yazi и подсказку «Yazi»

#### Scenario: Yazi из обычной оболочки
- **WHEN** пользователь запускает yazi в уже открытом wezterm
- **THEN** плитка показывает иконку yazi сразу по смене заголовка окна, а после выхода из yazi — снова иконку терминала

#### Scenario: Браузер
- **WHEN** WM_CLASS окна = «Navigator»
- **THEN** иконка окна — firefox, подсказка при наведении — «Firefox»

### Requirement: Экранирование вывода
Строковые значения в JSON (название программы, путь к иконке, глиф) MUST экранироваться: `\` → `\\`, `"` → `\"`, управляющие символы удаляются. Внутренний разделитель полей скрипта MUST быть управляющим символом, который удаляется из значений при экранировании, чтобы он не мог встретиться в данных.

#### Scenario: Кавычки в заголовке окна
- **WHEN** название программы или путь к иконке содержит символ `"`
- **THEN** выведенный JSON остаётся корректным и eww отрисовывает плитку
