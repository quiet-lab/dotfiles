# Заметки к коду демона workspaced

Сведения, нужные при правке кода демона (`~/work/pets/workspaced`,
репозиторий `git@github.com:quiet-lab/workspaced.git`). Документ временный:
его место — README самого проекта, задача переноса стоит в `todo.md`.
После переноса этот файл удаляется, а строка о нём убирается
из [`README.md`](README.md).

## Модули `src/`

- `config.rs` — разбор `~/.config/workspaced/config.toml`: проценты и пиксели,
  три слоя окружения с подстановкой `~` и `$ИМЯ`, проверки, записи `[[binds]]`.
- `keys.rs` — сочетания и цепочки: конфликты, список `reserved`, генерация Lua
  с подкартами `ws:<цепочка>`, таблица для `keys --list`, копия кода
  в `~/.local/state/workspaced/keys.lua`.
- `hypr.rs` — сокеты Hyprland: диспетчеры выражениями Lua, несколько шагов одной
  последовательностью `(function() … return … end)()`, мониторы с рабочей
  областью, активное окно.
- `state.rs` — столы, назначения ячеек, посторонние окна, формат сессии.
- `daemon.rs` — поднятие workspace, цепочка приложения с обменом ячеек, `half`,
  `place`, `maximize`, запуск с `setsid` и сопоставление окна по pid,
  `/proc/<pid>/exe` и классу, тег `app:<имя>`, парковка на `special:pool`,
  сервер сокета `$XDG_RUNTIME_DIR/workspaced/sock` строками JSON с подпиской.
- `session.rs` — `default.toml` с задержкой 500 мс, именованные сессии, загрузка
  со сверкой, ленивое восстановление.
- `save.rs` — запись workspace в конфиг с сохранением комментариев (`toml_edit`).
- `client.rs` — команды командной строки к работающему демону.

## Что стоит знать до правки

- `j/monitors` отдаёт `reserved` массивом `[left, top, right, bottom]`; при
  работающей панели это `[330, 0, 0, 0]`. В Lua-API форма того же поля
  не документирована, демон читает сокет и полагается на массив.
- Поля окна в Lua-API (`/usr/share/hypr/stubs/hl.meta.lua`, класс `HL.Window`):
  `stable_id` (порядок создания, по нему идёт обход окон стола),
  `focus_history_id`, `mapped`, `address`, `class`, `title`, `tags`, `at`, `size`,
  `floating`, `hidden`, `pid`, `workspace`. Окно пользователя выбирается по тегу
  `app:<имя>`, а не по классу.
- serde: `deny_unknown_fields` действует только на структуру, на вариант
  перечисления его повесить нельзя. Неизвестные ключи отлавливаются
  на структурах разделов конфига (`config.rs`), варианты действия проверяет код.
- Новый вид действия: сначала применить конфиг (`chezmoi apply`), затем
  перезапустить юнит. В обратном порядке новый демон получает старый конфиг,
  отвергает его и завершается с ошибкой.
- При собственном старте демон привязки Hyprland не перезагружает, нужен
  `hyprctl reload config-only`; после удачного перечитывания файла демон
  выполняет его сам.
- SIGTERM демон не обрабатывает (в `main.rs` сбрасывается только SIGPIPE):
  при остановке могут пропасть изменения последних 500 мс. Риск принят
  в design изменения `workspace-daemon`.
- Запуск приложений: `wezterm-gui start` без `--always-new-process` открывает
  окно в уже работающем wezterm; `/usr/bin/firefox` — сценарий оболочки, поэтому
  исполняемый файл дочернего процесса читается из `/proc`, пока он жив; Telegram
  одноэкземплярный, окно принимается через 2 с после выхода процесса;
  `kill -SEGV` процесс на Rust переживает.
- Тесты: `cargo test`.
