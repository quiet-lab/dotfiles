# 0009. Туннель AmneziaWG — awg-quick с выбором маршрута по адресу назначения

Дата: 2026-11-02. Статус: принято, выполнено.

## Решение

В условиях, когда станции нужны одновременно OpenVPN `axata` (сеть
10.0.0.0/8), выход во внешний мир через сервер Amnezia Premium и прямой
выход к адресам России и Белоруссии, а приложение AmneziaVPN включает kill switch,
блокирующий UDP OpenVPN, и забирает весь трафик маршрутами 0.0.0.0/1
и 128.0.0.0/1, учитывая, что протокол AmneziaWG 2.0 поддерживают только
собственные инструменты Amnezia, выбран туннель `awg-quick@amn0`
(`amneziawg-tools` и пользовательский `amneziawg-go` из AUR) без своих
маршрутов (`Table = off`), а трафик в туннель отбирает таблица nftables
`inet amn`: всё, кроме частных сетей, `bypass.txt` и набора подсетей России
и Белоруссии из ipdeny.com, получает метку 0x1 (таблица маршрутизации 100),
чтобы три потока трафика работали вместе без
приложения, ценой ручного переноса конфига из хранилища приложения
(`amn-export-config`), неточности списков стран (российский сервис
на адресах вне зон идёт через туннель, пока адрес не внесён в `bypass.txt`)
и видимости имён зон `ru`, `by`, `su`, `рф` провайдеру: их разрешает домашний
маршрутизатор, остальные имена идут через туннель.

Устройство и порядок работы — [`../amnezia-split-tunnel.md`](../amnezia-split-tunnel.md).

## Рассмотренные варианты

- Приложение AmneziaVPN с раздельным туннелированием по сайтам — kill switch
  и маршруты приложения ломают OpenVPN `axata`, правила хранятся в приложении,
  а не в репозитории.
- Соединение WireGuard в NetworkManager — параметров обфускации AmneziaWG
  (Jc, S1–S4, H1–H4, I1) не поддерживает, сервер такой клиент не примет.
- Модуль ядра `amneziawg-dkms` — пересборка при каждом обновлении ядра
  CachyOS; пропускной способности пользовательской реализации хватает.

## Пересмотр

Если NetworkManager получит поддержку AmneziaWG или приложение AmneziaVPN —
раздельное туннелирование без kill switch, управляемое файлами.
