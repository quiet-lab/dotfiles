# 0004. Все привязки клавиш — в конфиге демона workspaced

Дата: 2026-09-16. Статус: принято, выполнено.

## Контекст

После появления демона workspaced привязки сессии оказались разделены между
двумя файлами: около шестидесяти вызовов `hl.bind` в `hyprland.lua`
(программы, окно, фокус, половины экрана, столы, мышь, мультимедиа, dunst,
скриншоты) и цепочки клавиш в `config.toml` демона, которые демон превращал
в Lua. Пользователь потребовал держать все привязки и цепочки в одном
файле: видеть их целиком, править в одном месте и проверять конфликты
одной командой.

## Решение

Единственный источник привязок сессии — `~/.config/workspaced/config.toml`,
раздел `[[binds]]` (сейчас 47 записей). Запись несёт ровно одно действие:
`action` (действие демона), `exec` (команда), `dispatch` (одно выражение
диспетчера или список) или `lua` (тело функции); флаги `locked`,
`repeating`, `mouse`, `release`; `range = [от, до]` с подстановкой `$n`
для серий вроде Super+1…8. Сочетания из списка `reserved` в `[keys]`
занимать нельзя, проверка конфига их отклоняет.

Собственных `hl.bind` в `hyprland.lua` нет: блок загрузки выполняет код,
который печатает `workspaced keys --lua`, а при ошибке берёт копию
`~/.local/state/workspaced/keys.lua` и показывает уведомление, чтобы
сессия не осталась без клавиш. Проверка — `workspaced check`, просмотр —
`workspaced keys --list`; после удачного перечитывания файла демон сам
вызывает `hyprctl reload config-only`.

Требования — спецификации `hyprland-binds` и `ws-config`; частные решения
о видах действия, флагах и диапазонах —
`../../openspec/changes/archive/2026-09-16-keys-in-daemon/design.md`.

## Рассмотренные варианты

**Отдельный демон горячих клавиш swhkd.** Отвергнут по четырём причинам,
записанным в proposal изменения: не умеет привязки с мышью; выполняет
каждое действие отдельным процессом; работает от root и потому обходит
блокировку экрана; сопоставляет сочетания по кодам клавиш без учёта карты
XKB.

**Оставить привязки в `hyprland.lua`, а в конфиге демона — только
цепочки.** Отвергнуто требованием пользователя: два файла на одну таблицу
привязок.

**Все действия через `exec workspaced …`** вместо диспетчеров и кода Lua.
Отвергнуто (design D1): запуск процесса на каждое нажатие стрелки
и на каждый повтор громкости заметен, а привязки мыши через процесс
невозможны.

**Расчёт половин рабочей области в поле `lua`** вместо команды демона
`half`. Отвергнуто (design D3): это тридцать строк кода в строке TOML
и дублирование геометрии, которой владеет демон.

## Условия пересмотра

- Hyprland перестал принимать привязки, заданные кодом Lua при загрузке
  конфига, или лишил конфиг возможности выполнять внешнюю команду при
  загрузке: тогда генерация привязок демоном теряет способ попасть
  в композитор.
- Понадобились условные привязки — по классу активного окна или
  по активному workspace, кроме уже существующего выбора приложения.
  В нынешнюю схему они не заложены (Non-Goals изменения), и способ их
  выразить придётся выбирать заново.
