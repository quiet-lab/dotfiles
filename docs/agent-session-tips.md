# Приёмы работы агента в живой сессии

Оболочка агента живёт в wezterm внутри работающей сессии Hyprland, поэтому
часть проверок агент делает сам, а часть — только пользователь. Здесь
собраны приёмы, которые иначе приходится открывать заново.

Правила, действующие в каждой сессии, лежат в `AGENTS.md`: раздел «Сессия
Hyprland» (диспетчеры через `hyprctl eval`, ограничения `wtype`,
расширение Surfingkeys, чтение событий из `.socket2.sock`) и раздел
«Команды с правами root» (обёртка `sudo-askpass`, `pacman --noconfirm`).
Здесь они не повторяются.

Факты проверены 2026-09-21 на Hyprland 0.56.2, если не сказано иное.

## Подпись экземпляра Hyprland

После перезахода в сессию у оболочки агента остаётся
`HYPRLAND_INSTANCE_SIGNATURE` прежнего экземпляра, и `hyprctl`
не подключается. Подпись живого экземпляра — имя самого свежего каталога
в `$XDG_RUNTIME_DIR/hypr`; её надо выставить перед командами:

```bash
export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t $XDG_RUNTIME_DIR/hypr | head -1)
```

Каталог подписи содержит `hyprland.log`, `hyprland.lock`, сокет команд
`.socket.sock` и сокет событий `.socket2.sock`.

## Что можно спросить у композитора

- Значения настроек: `hyprctl getoption decoration:shadow:range` печатает
  тип, значение и признак `set`.
- Режим монитора меняется выражением Lua:
  `hyprctl eval 'hl.monitor({ output = "DP-2", mode = "3840x2160@60", position = "0x0", scale = 1 })'`.
- `hyprctl monitors -j` отдаёт `reserved` массивом `[left, top, right,
  bottom]`; при работающей панели это `[330, 0, 0, 0]`.
- Поля правил окон видны на живых правилах в `hyprland.lua`: размер —
  `size = { 1920, 1080 }`, центрирование — `center = true`. В заглушках
  Lua-API (`/usr/share/hypr/stubs/hl.meta.lua`) класс `HL.WindowRuleSpec`
  описывает только `enabled`, `match` и `name`, остальные поля там
  не перечислены — сверять их приходится по примерам и по рабочему конфигу.
- Параметр пружины анимации в 0.56.2 называется `dampening` (в примере
  конфига из ветки main — уже `damping`); в заглушках нет ни того, ни
  другого.

## Вывод из Lua и журнал

`print` из конфига попадает в `$XDG_RUNTIME_DIR/hypr/<подпись>/hyprland.log`
с меткой `[Lua]`. Файл содержит байты, которые ripgrep считает двоичными,
поэтому искать в нём нужно с ключом `-a`:

```bash
rg -a -o '\[Lua\][^\n]{0,80}' $XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/hyprland.log | tail
```

`hyprctl rollinglog` показывает те же строки, но буфер очень короткий
(в опыте 27–58 строк) и при включённом отладочном журнале
(`debug.disable_logs = false` в конфиге, журнал libinput) строка
вытесняется за секунды. Поэтому читать надо файл, а не `rollinglog`.

`hyprctl eval` возвращаемое значение не печатает: `hyprctl eval 'return
2+2'` отвечает `ok`. Значение печатает `hyprctl repl 'return 2+2'` — отвечает
`4`. Результат из Lua, который нужен целиком, проще записать в файл.

Строку, начинающуюся с `--`, `hyprctl eval` принимает за флаг и печатает
подсказку по использованию вместо выполнения. Такое выражение передаётся
через сокет команд напрямую либо переписывается без ведущего `--`.

## Перезагрузка конфига: что она делает и чего не делает

- `hyprctl reload` не перезапускает автозапуск: обработчик
  `hyprland.start` срабатывает один раз при старте композитора.
- `hl.env` действует только на процессы, запущенные после перезагрузки
  конфига; уже работающие переменную не получат.
- Привязки, добавленные на время через `hyprctl eval`, живут до следующей
  перезагрузки конфига. Демон workspaced вызывает
  `hyprctl reload config-only` после каждого удачного перечитывания своего
  файла, поэтому временная привязка исчезает при любой правке
  `dot_config/workspaced/config.toml`. Пробную привязку надёжнее заводить
  записью `[[binds]]` в живом конфиге демона и убирать после проверки.

## Окна и ввод

Проверки нажатиями делает пользователь: `wtype` подаёт символы виртуальной
клавиатурой и привязки композитора не запускает. Агент наблюдает результат
по событиям из `.socket2.sock` и по `hyprctl clients -j`.

Сочетание с модификатором `wtype` не доносит и до самого окна: `wtype -M ctrl n
-m ctrl` окно Chromium не получает, второе окно браузера так не открыть.
Сочетание подаёт в окно диспетчер композитора:

```bash
hyprctl eval 'hl.dispatch(hl.dsp.send_shortcut({ mods = "CTRL", key = "code:57", window = "address:0x…" }))'
```

Имя клавиши диспетчер не принимает: с `key = "n"` он отвечает «key not found»,
нужен код клавиши XKB (`code:57` — это `n`). Фокус окну по адресу даёт
`hl.dispatch(hl.dsp.focus({ window = "address:0x…" }))`. (Установлено 21.09.2026
на пробе о профилях Chrome.)

Из той же пробы: второе окно браузера на Chromium нужно просить ключом
`--new-window`, иначе открывается вкладка и события `openwindow` композитор
не присылает. Окно DevTools и окно расширения с окном композитора не связать:
под Wayland браузер отдаёт в них пустые `bounds`.

Окно wezterm с работающей внутри программой по `hl.dsp.window.close`
не закрывается: wezterm спрашивает подтверждение. Такое окно закрывается
по pid процесса.

## chezmoi и юниты

- `chezmoi apply <файл>` для файла, которого ещё нет в `$HOME`, завершается
  ошибкой на `stat`; применять нужно каталог. (Установлено 2026-09-15,
  заново не проверялось.)
- После пересборки демона workspaced с новым видом действия порядок такой:
  сначала применить конфиг (`chezmoi apply`), затем перезапустить юнит.
  В обратном порядке новый демон получает старый конфиг, отвергает его
  и завершается с ошибкой.
- Про `chezmoi apply --force` для файла, изменившегося в `$HOME`, написано
  в `AGENTS.md`.

## Пакеты и темы

Перед удалением осиротевших пакетов (`pacman -Qdtq`) список сверяется
с темами значков и курсоров из конфигов. Один раз это уже стоило работы
панели: вместе с сиротами ушёл `breeze-icons`, а тема `breeze-dark` задана
в четырёх местах — `dot_config/gtk-3.0/settings.ini`, `dot_gtkrc-2.0`,
`dot_config/dunst/dunstrc` и строка `//@ pragma IconTheme breeze-dark`
в `dot_config/quickshell/panel/shell.qml`. Курсор задан темой
`~/.icons/default`, которая наследует `capitaine-cursors`.

Сейчас оба пакета помечены как явно установленные (`breeze-icons` возвращён
с `--asexplicit` после того случая), и от них не зависит ни один другой
пакет, поэтому в списке сирот они не появляются. Но правило остаётся:
пакет, на который ссылается только конфиг, пакетным связям не виден.

## Вход в GitHub

Автоматический вход `gh` невозможен: либо браузер, либо токен, созданный
на сайте. Токен передаётся файлом: `gh auth login --with-token < файл`.
Сейчас вход выполнен по токену в аккаунт `quiet-lab`, протокол для операций
git в настройках `gh` — https, но удалённые репозитории заданы по SSH.

## Хранилища секретов в системе нет

Поставщика `org.freedesktop.secrets` в системе нет (kwallet удалён вместе
с осиротевшими пакетами KDE): `gdbus introspect --session --dest
org.freedesktop.secrets …` отвечает «The name is not activatable».
Следствия:

- git хранит пароли в `~/.config/git-credentials`, `gh` — в
  `~/.config/gh/hosts.yml`, оба файла в открытом виде и вне chezmoi.
- Браузеры на Chromium без хранилища секретов переходят на basic store
  и сообщают об этом при старте; это ожидаемо, а не сбой настройки.
