# Подсказка горячих клавиш по контексту в панели herdr (keys-help)

Плагин herdr `quiet-lab.keys-help` по клавише Ctrl+Alt+Shift+/ делит
текущую панель и показывает внизу таблицу клавиш того, что сейчас на
переднем плане верхней панели: оболочки bash с ble.sh в её текущем режиме
или запущенной программы в её текущем режиме. Клавиши композитора
показывает другая панель (спецификация qs-keys-help). Поведение —
спецификация `openspec/specs/herdr-keys-help/spec.md`, выбор размещения —
[`decisions/0010-keys-help-herdr-plugin.md`](decisions/0010-keys-help-herdr-plugin.md).

## Устройство

Источник — `dot_config/herdr/plugins/keys-help/`, в системе —
`~/.config/herdr/plugins/keys-help/`:

| Путь | Назначение |
|---|---|
| `herdr-plugin.toml` | манифест herdr: действие `toggle`, панель `viewer`, сборка |
| `src/`, `Cargo.toml`, `Cargo.lock` | ядро, извлекатели и просмотрщик — один бинарник `keys-help` |
| `manifests/*.toml` | манифесты программ |
| `manifests/data/` | данные манифестов, которых нет в живой системе |
| `tests/` | тесты ядра на Rust, тест модуля ble.sh (`test_ble_provider.py`), тест модуля Neovim (`nvim_provider.sh`) |
| `tests/fixtures/` | снимки `ble-bind -P` (`ble/`), страниц `man` (`man/`), `keymap.toml` yazi (`yazi/`), конфига television (`tv/`), пробный манифест (`manifests/`) |

Вне плагина:

| Путь источника | Назначение |
|---|---|
| `dot_config/blesh/keys-help.bash` | поставщик контекста ble.sh |
| `dot_config/nvim/lua/keys_help.lua` | поставщик контекста Neovim |
| `dot_config/yazi/init.lua` | поставщик контекста yazi |
| `dot_config/herdr/config.toml` | клавиша `ctrl+alt+shift+slash`, раздел `[ui]` |
| `dot_config/wezterm/wezterm.lua` | `enable_kitty_keyboard = true` |
| `dot_config/herdr/keys-help/symlink_view.toml.tmpl`, `herdr-keys-help/view.toml` | конфигурация представления |
| `.claude/settings.json`, `.claude/hooks/keys-help-unknown.sh` | хук разбора неизвестных программ |
| `run_onchange_after_build-herdr-keys-help.sh.tmpl` | сборка плагина |
| `run_after_link-herdr-keys-help.sh` | регистрация плагина в herdr |
| `run_onchange_after_ya-pkg-install.sh.tmpl` | установка плагинов и тем yazi из `package.toml` (`ya pkg install`) |

Конфигурации yazi (`init.lua`, `yazi.toml`, `theme.toml`, `package.toml`,
тема `flavors/modus-vivendi.yazi`), atuin и television лежат под chezmoi;
плагины и темы пакетов yazi в источник не входят.

Подкоманды бинарника: `toggle`, `viewer`, `table <контекст> [--pane <id>]
[--json]` (печать таблицы для проверок и тестов), `unknown list`. Сборку
при `chezmoi apply` выполняет сценарий `run_onchange_after_build-herdr-keys-help.sh.tmpl`
(`cargo build --release --locked`; в тексте сценария хеши `Cargo.toml`,
`Cargo.lock`, `herdr-plugin.toml` и `src/`, поэтому он выполняется заново только
при их изменении); каталог `target/` chezmoi не ведёт. Регистрирует плагин
сценарий `run_after_link-herdr-keys-help.sh` при каждом `chezmoi apply`: если
плагина нет в `~/.config/herdr/plugins.json`, он вызывает `herdr plugin link`.
Регистрации нужен запущенный сервер herdr; без него сценарий пишет сообщение
и завершается успешно, а плагин регистрирует следующий `apply` или вручную
`herdr plugin link ~/.config/herdr/plugins/keys-help`.

Журнал плагина — `$HERDR_PLUGIN_STATE_DIR/keys-help.log` (без переменной —
`$XDG_STATE_HOME/herdr-keys-help/keys-help.log`): ошибки манифестов и
неизвестные поля манифестов, возможные опечатки. Для проверок переменные
`KEYS_HELP_MANIFESTS` (каталоги манифестов через `:`) и `KEYS_HELP_VIEW`
(путь конфигурации представления) заменяют обычные пути.

Ядро знает только виды источников и формат записи. Имена программ, пути
их конфигов, регулярные выражения и описания лежат в манифестах. Таймеров
и опроса нет: просмотрщик — один поток с `poll` по дескрипторам (подписка
herdr, inotify, signalfd, pidfd, ввод терминала).

## Открытие и закрытие

Действие `toggle` ищет в tab панель с токеном `keys_help`. Панель есть —
закрывает её (`plugin pane close`), независимо от фокуса. Панели нет —
открывает просмотрщик под панелью, с которой нажата клавиша
(`placement = "split"`, направление вниз, без фокуса), и передаёт цель
окружением `KEYS_HELP_TARGET`.

Панелью просмотрщика владеет токен `keys_help` (`pane.report_metadata`,
без срока): `toggle` ставит его сразу после открытия, чтобы повторное
нажатие закрыло панель ещё до старта просмотрщика, просмотрщик ставит
его при старте.

Размер: нижняя панель занимает треть высоты (доля верхнего потомка 0.667,
`layout.set_split_ratio`, если панель — второй потомок split), но не меньше
5 строк содержимого. При нехватке просмотрщик увеличивает свою панель
(`pane.resize`) на каждый `SIGWINCH` и `layout.updated` своего tab, если
высоты split хватает на 5 строк, рамку и 3 строки верхней панели. Уменьшение
пользователем выше минимума не отменяется.

Клавиша в herdr — `[[keys.command]]` с `key = "ctrl+alt+shift+slash"`,
`type = "plugin_action"`, `command = "quiet-lab.keys-help.toggle"`.
Чтобы терминал передавал модификаторы на пунктуации, в wezterm включён
протокол клавиатуры kitty (`enable_kitty_keyboard = true`). Рамки herdr —
только разделители: `pane_outer_borders = false`, `pane_gaps = false`.

## Канал «верхняя панель → просмотрщик»

Каталог `$XDG_RUNTIME_DIR/herdr-keys-help/panes/<HERDR_PANE_ID>/`. Каждый
поставщик пишет в него свою запись — файл `<программа>-<pid>.json`, один
JSON-объект целиком одной записью:

```json
{"v":1,"program":"ble","mode":"vi_nmap","pid":12345,
 "state":"active","command":null,"table":"…/ble/12345/vi_nmap.bind",
 "server":null,"env":{}}
```

| Поле | Смысл |
|---|---|
| `program` | имя программы; по нему манифест объявляет себя поставщику (`[detect] provider`) |
| `mode` | режим, `null` — без режима |
| `pid` | процесс поставщика: оболочка, yazi, у Neovim — процесс переднего плана панели (при запуске с `--embed` клиент TUI, родитель процесса Lua) |
| `state` | `active` — программа на переднем плане в режиме `mode`; `exec` — оболочка запустила команду `command`; `widget` — оболочка выполняет виджет или команду привязки `command` |
| `table`, `server`, `env` | необязательные подстановки для источников таблиц: `{record.table}`, `{record.server}`, `{env.ИМЯ}` |

Поставщик удаляет запись при выходе (ble.sh — `EXIT`, Neovim —
`VimLeavePre`); yazi выхода не видит, поэтому запись yazi, как и запись
упавшего процесса, снимает просмотрщик по событию pidfd. Просмотрщик читает записи по `IN_CLOSE_WRITE`
и `IN_MOVED_TO`, неразобранный JSON пропускает до следующего события.
Активна последняя изменённая запись живого процесса (порядок — по `mtime`
при старте, затем по порядку событий inotify), поэтому стек bash → yazi →
nvim разрешается без счётчиков; запись в состоянии `active` процесса
переднего плана важнее более свежих записей прочих процессов (nvim после
Ctrl-Z и `fg`). Таблицы с командными источниками, подставляющими поля
записи, строятся заново при каждой перезаписи записи (смена режима Neovim
подхватывает привязки LSP); кеш таблиц снимает таблицы завершившихся
процессов и не превышает 64 записей.

Переменные окружения для подстановок оболочка берёт из файла
`$XDG_RUNTIME_DIR/herdr-keys-help/env-vars`, который пишет просмотрщик
из полей `env` всех манифестов.

Поставщики, все по событиям:

- ble.sh — `dot_config/blesh/keys-help.bash`, подключается строкой из
  `dot_blerc`: хуки смены keymap (`ble/decode/keymap/push`, `pop`,
  `ble/keymap:vi/update-mode-indicator`), `PREEXEC`, `PRECMD`, `ATTACH`,
  обёртки виджетов `-x` и `-c`, `EXIT`; запись идёт встроенным `printf`,
  без внешних процессов на смену режима; дамп `ble-bind -m <keymap> -P`
  пишется в `$XDG_RUNTIME_DIR/herdr-keys-help/ble/<pid>/<keymap>.bind` при
  первой записи keymap, `keys-help-refresh` сбрасывает дампы после ручного
  `ble-bind`; вне herdr модуль ничего не делает;
- Neovim — `dot_config/nvim/lua/keys_help.lua` (подключён в
  `lua/config/autocmds.lua`): `VimEnter`, `ModeChanged`, `VimLeavePre`;
  режим записывается только при смене; таблицу отдаёт функция `dump`
  (`nvim_get_keymap` и `nvim_buf_get_keymap` с `desc`; происхождение — по
  файлу определения: `user`, `lazyvim`, имя плагина или `nvim`; группа —
  происхождение), её вызывает манифест через `nvim --server <адрес>
  --remote-expr`;
- yazi — поставщик в `dot_config/yazi/init.lua` (`provider = "yazi"`): при
  запуске создаёт каталог панели (единственный внешний процесс — `mkdir -p`)
  и пишет запись со слоем `mgr`; слой (`mgr`, `tasks`, `spot`, `pick`,
  `input`, `confirm`, `cmp`, `help`) определяет обёртка `Root:redraw` по
  `cx.layer`, запись пишется только при смене слоя; без поставщика запуск
  виден по записи оболочки и процессу переднего плана, контекст —
  `yazi.manager`;
- herdr — подписка `events.subscribe` (`pane.focused`, `pane.updated`,
  `pane.output_matched`) как страховка для программ, которые о себе не
  сообщают и запущены не из оболочки.

## Цель просмотрщика

Первая цель — панель из `KEYS_HELP_TARGET`, без неё — панель в фокусе tab,
кроме самого просмотрщика. Просмотрщик следует за панелью в фокусе своего
workspace. `pane.focused` на панель без токена `keys_help` меняет цель;
фокус на самом просмотрщике и в чужих workspace цель не меняет. herdr
сообщает `pane.focused` только для workspace, открытого в клиенте: смена
фокуса в фоновом workspace (`herdr pane activate`) событий не порождает, и
цель меняется, когда workspace открывают в клиенте. `pane.moved` переносит
цель и каталог записей (`rename` на новый `pane_id`) и оставляет на месте
прежнего каталога символическую ссылку на новый: поставщики панели
сохраняют прежний `HERDR_PANE_ID` и пишут по старому пути. `pane.closed`
цели переводит цель на панель в фокусе tab. По `pane.closed` любой панели
просмотрщик удаляет каталог записей закрытой панели вместе со ссылками
прежних id, при старте — каталоги панелей, которых нет в `pane.list`.
`events_lost` — новая подписка и пересчёт. Подписки `pane.output_matched`
строятся из манифестов и пересоздаются при смене цели.

## Контексты

Контекст — строка `<программа>.<режим>`: `ble.vi_imap`, `ble.vi_nmap`,
`ble.isearch`, `yazi.manager`, `yazi.input`, `nvim.normal`, `atuin.search`,
`fzf`, `htop.generic`. Порядок разрешения для цели:

1. Запись `state = active` — манифест с `provider = <program>`, режим из записи.
2. Запись `exec` или `widget`, либо записи нет — кандидаты манифестов по
   `shell_commands`, `process`, `title`, `screen`; при нескольких —
   наибольший `priority`; режим — по экрану, по конфигурации программы
   или `default`.
3. Манифеста нет — универсальный извлекатель, контекст `<команда>.generic`.
4. Извлекатель ничего не нашёл — запись в файл неизвестных программ,
   в панели строка «клавиши <команда> не найдены».

Команда — имя исполняемого файла (`basename` argv0 процесса переднего
плана или первого слова `command` без присваиваний, `sudo` и `env`).
Оболочка без записи ble.sh идёт по шагу 3 как `bash.generic`. Приоритет
между источниками для одной программы: манифест программы, универсальный
извлекатель, запись в файл неизвестных.

## Формат манифеста

Манифест — TOML-файл в `manifests/`; имя программы в ядре не записано.
Неизвестные поля манифеста разбору не мешают и попадают в журнал плагина.

```toml
program = "ble"               # имя, первая часть контекста
priority = 100                # выбор среди кандидатов; generic — 0
origins = ["readline", "ble", "user"]

[detect]
provider = "ble"              # записи этого program
process = []                  # имена процессов переднего плана (glob)
shell_commands = []           # command записей exec/widget (glob)
title = ""                    # регулярное выражение по заголовку
screen = []                   # [{ source = "visible", lines = 30, regex = "…" }]

[modes]
default = "vi_imap"
names = { mgr = "manager" }   # родное имя режима → имя в контексте
# from_config = { file = "…", key = "…", map = { … } }
# [[modes.screen]] mode = "input", regex = "…"

[[source]]                    # источники таблицы, по порядку
modes = ["*"]
kind = "regex"                # regex | toml | json | static
file = "{record.table}"       # или command = [...] / env = "NAME"
regex = '''…(?P<key>…)(?P<action>…)'''
on_conflict = "override"      # override | keep

[key]                         # нормализация записи клавиши
map = { "ctrl-" = "C-", "alt-" = "M-" }

[view]                        # умолчания представления программы
origin_order = ["atuin", "tv", "fzf", "user"]

[[applies]]                   # применимость команд к позиции курсора
modes = ["vi_imap", "emacs"]
action = "^(backward-char|beginning-of-line)$"
when = "col > 0"

[[describe]]                  # описание по действию
action = "^history-isearch-backward$"
desc = "поиск по истории назад"
[[group]]
action = "^history"
group = "history"
[[origin]]
type = "^[xc]$"
origin = "user"
```

Поля источника:

- общие: `modes`, `on_conflict`, `skip` (поле → регулярное выражение, по
  исходному значению и по нормализованной клавише), `group` и `origin` —
  значения по умолчанию для записей источника; вход — `command`, `file`
  (или `path`), `env` или `text`;
- `regex`: `regex` (именованные захваты `key`, `action`, `desc`, `group`,
  `origin`, `type` и другие — для условий правил), `unquote`, `split` —
  регулярное выражение-разделитель захвата `key` (каждая часть — отдельная
  запись: `ctrl-k up` в `man fzf` при `split = ' +'`), `sections` — заголовки
  разделов; `sections` без `regex` разбирает строки «клавиша — описание»
  ядро;
- `toml`: `tables` (пути с подстановками), `layout` — `arrays` (массивы
  таблиц `arrays`, по умолчанию при непустом `arrays`), `key_value`
  (`клавиша = действие`, по умолчанию) или `value_key` (`действие = клавиша`
  или список), `key_field`, `action_field`, `desc_field`, `group_field`,
  `origin_field`, `replace_if` (массив, заменяющий накопленные записи);
  внутри источника первое вхождение клавиши побеждает;
- `json`: массив объектов по `pointer` (по умолчанию корень), те же
  `*_field`, `raw_fields` — поля, из которых собирается `raw`;
- `static`: `entries = [{ key, action, desc, desc_full, group, origin, raw }]`
  или `file` с массивом `entries`.

Раздел `[view]` — умолчания представления программы: те же поля, что у
уровня `view.toml` (раздел «Конфигурация представления»), и `origin_order`.
Раздел `[[applies]]` (`modes`, `action` — регулярное выражение по имени
действия, `when`) описан в разделе «Строка ввода оболочки».

Верхний уровень: `first_nonempty` — источники по порядку, первый непустой
результат побеждает; `env` — дополнительные имена переменных для файла
`env-vars`. Правила `[[describe]]` (`desc`, `desc_full`), `[[group]]`
(`group`) и `[[origin]]` (`origin`) принимают условия по полям записи и
захватам источника и необязательный список `modes`.

Подстановки в `file`, `command`, `env`, `path`, `text`: `{mode}` (родное имя
режима), `{mode_name}` (имя в контексте), `{record.<поле>}`, `{env.<ИМЯ>}`
(из записи, затем из окружения процесса программы, затем из окружения
просмотрщика), `{command}`, `{pid}`; тильда в начале пути; подстановка без
значения пропускает источник. Источник
`command` запускается без оболочки, с `stdin` из `/dev/null`, без
терминала, с окружением `TERM=dumb MANPAGER=cat PAGER=cat MANWIDTH=200`;
его ожидание — по pidfd, сроков нет, смена контекста или выход просмотрщика
завершает процесс по pid. Таблица кешируется в памяти по ключу «манифест,
режим, значения подстановок, `mtime` прочитанных файлов».

Клавиша нормализуется к записи ble.sh: модификаторы `C-`, `M-`, `S-`, `s-`
(Super) в порядке `C-M-S-s-`, именованные клавиши (`ESC`, `RET`, `TAB`, `SP`, `up`,
`f1`), последовательности через пробел. По нормализованной записи работают
`hide`, `pin` и `[entry]`.

Запись таблицы:

| Поле | Смысл |
|---|---|
| `key` | нормализованная клавиша |
| `desc` | короткое описание: что делает, в нескольких словах, без имён виджетов и функций |
| `desc_full` | полный текст описания из источника |
| `group`, `origin` | группа и происхождение |
| `action` | имя виджета, функции или действия |
| `source` | `manifest:<файл>`, `generic`, `user` |
| `raw` | исходный фрагмент: строка `ble-bind -P`, `rhs` и `файл:строка` для Neovim, фрагмент `man` или `--help` для `generic` |

Короткое описание берётся из `[[describe]]`; авторы манифестов
переформулируют длинные тексты источников и имена виджетов по-русски.
Нет короткого описания — ядро сокращает полный текст правилом ниже;
нет и полного — показывается действие.

Манифесты первой очереди:

| Манифест | Режимы | Таблица |
|---|---|---|
| `ble.toml` | keymap ble.sh (`vi_imap`, `vi_nmap`, `vi_xmap`, `vi_smap`, `vi_omap`, `vi_cmap`, `isearch`, `nsearch`, `menu_complete`, `auto_complete`, `emacs`) | дамп `ble-bind -m <keymap> -P` из записи поставщика |
| `fzf.toml` | нет (`fzf`) | `man fzf` и `--bind` из `FZF_DEFAULT_OPTS` процесса |
| `atuin.toml` | `search`, `insert`, `normal` — по `keymap_mode` конфига atuin | статическая таблица умолчаний и `[keymap.<режим>]` конфига |
| `tv.toml` | нет (`tv`) | `[keybindings]` конфига television |
| `yazi.toml` | `manager`, `tasks`, `spot`, `pick`, `input`, `confirm`, `cmp`, `help` | `manifests/data/yazi-keymap-26.9.1.toml`, затем `~/.config/yazi/keymap.toml` |
| `nvim.toml` | `normal`, `insert`, `visual`, `select`, `cmdline`, `replace`, `terminal`, `operator` | `dump` из процесса Neovim, затем базовые клавиши vim (`manifests/data/vim-basic.toml`) |
| `generic.toml` | `generic` | универсальный извлекатель |

Таблица fzf, atuin и tv внутри открытой программы статична и строится один
раз при входе в контекст.

## Добавление программы

Добавление программы — один манифест в `manifests/` без правок ядра:

1. Задать `program`, `priority` и `[detect]`: по какому поставщику, процессу,
   команде оболочки, заголовку или экрану программа распознаётся.
2. Задать `[modes]`, если у программы есть режимы.
3. Задать `[[source]]`: живая конфигурация программы (`toml`, `json`,
   `command`) или `static`; данные, которых нет в системе, — в
   `manifests/data/`.
4. Задать `[[describe]]`, `[[group]]`, `[[origin]]`: короткие русские
   описания и группы.
5. Проверить: `keys-help table <контекст> --pane <id>` на панели с
   запущенной программой; добавить снимок источника в `tests/fixtures/`
   и тест.

Программа, которая сообщает о режиме сама, получает поставщика (модуль в
её конфигурации под chezmoi, запись в канал по формату выше). Конфигурации
программ, с которыми работает плагин, берутся под chezmoi.

## Универсальный извлекатель

`manifests/generic.toml` — обычный манифест с `program = "*"`,
`priority = 0`, `[detect] fallback = true`; контекст — `<команда>.generic`,
происхождение всех записей — `generic`. Источники по порядку, первый
непустой результат побеждает:

1. `man`: разделы о клавишах (KEY BINDINGS, KEYS, KEYBOARD SHORTCUTS,
   COMMANDS, INTERACTIVE, SHORTCUTS, NAVIGATION); запись — строка с
   отступом, где термин похож на клавишу, а описание отделено двумя
   пробелами или стоит ниже с большим отступом; группа — ближайший
   подзаголовок.
2. `--help` с тем же разбором; программа запускается без терминала,
   поэтому полноэкранная завершается ошибкой, не заняв экран.
3. Известные файлы конфигурации клавиш: `~/.config/<команда>/config.toml`
   (таблицы `keybindings`, `keys`, `keymap`) и
   `~/.config/<команда>/keybindings.conf` (строки `bind <клавиша> <действие>`
   и `<клавиша> = <действие>`).

Результат кешируется в `$XDG_CACHE_HOME/herdr-keys-help/generic/<команда>.json`
с ключом «путь исполняемого файла, его `mtime` и размер, `mtime` страницы
man»: при тех же входах извлечение не повторяется.

### Правило сокращения описаний

Применяется к записям `generic` и к любой записи без короткого описания;
полный текст остаётся в `desc_full`. Константы — в ядре.

1. Пробельные символы схлопываются, разметка man снимается.
2. Берётся первое предложение: текст до первого `. `, `; `, `: ` или конца строки.
3. Отбрасываются скобочные пояснения и начальные служебные слова (артикли,
   `this`, `will`, `used to`, `allows (you) to`, `lets you`, «позволяет»,
   «используется для», «служит для»).
4. Регистр букв исходника сохраняется, точка в конце снимается.
5. Предел — 32 символа: длиннее режется по границе слова с `…`.

## Файл неизвестных программ и порядок разбора

Файл `$XDG_STATE_HOME/herdr-keys-help/unknown-programs.toml`:

```toml
[program.htop]
count = 3
last = "2026-11-08"
```

Просмотрщик пишет в него команду, для которой нет ни манифеста, ни таблицы
универсального извлекателя, — один раз на появление процесса (новый pid
команды на переднем плане цели); повторов нет. Запись идёт через временный файл и `rename` под `flock`: файл один
на пользователя, а писать могут просмотрщики нескольких tab. Команда, у
которой появились манифест или таблица, удаляется из файла при следующем
появлении. Файл видит только то, что запускалось при открытом просмотрщике.

Разбор идёт по событию: хук `SessionStart` проекта
(`.claude/settings.json` → `.claude/hooks/keys-help-unknown.sh`) печатает
список из файла по убыванию счётчика и молчит, если файла нет или он пуст.
Главная сессия по списку ставит задачу на манифесты. Для каждой программы
из списка:

1. Завести манифест по разделу «Добавление программы».
2. При необходимости пополнить `view.toml` (раздел ниже).
3. Удалить строку программы из файла неизвестных.

## Конфигурация представления

Файл `~/.config/herdr/keys-help/view.toml` — символическая ссылка на
`herdr-keys-help/view.toml` источника chezmoi (`symlink_view.toml.tmpl`);
каталог `herdr-keys-help/` исключён в `.chezmoiignore`. Правки из
просмотрщика попадают в репозиторий без `re-add`. Запись идёт через
`toml_edit` (комментарии и порядок сохраняются) во временный файл в
каталоге настоящего файла и `rename` поверх настоящего пути.

```toml
[defaults]
order = ["history", "completion", "edit", "motion"]
only_modifiers = false

[context."ble.vi_nmap"]
hide = ["h", "j", "k", "l", "w", "b", "e", "0", "$"]
pin = ["C-r", "M-r", "M-h"]
hide_groups = ["motion"]

[entry."ble.vi_nmap"."C-r"]
desc = "поиск по истории"
group = "history"
```

| Поле | Тип | Наследование |
|---|---|---|
| `order` | список групп | заменяется более частным уровнем |
| `hide` | список клавиш | объединяется |
| `hide_groups` | список групп | объединяется |
| `pin` | список клавиш | заменяется |
| `only_modifiers` | bool | заменяется |
| `show_origin` | bool или список происхождений | заменяется |
| `[entry."<контекст>"."<клавиша>"]` `desc`, `group` | | частное поверх общего |

Уровни: `[defaults]` → `[view]` манифеста программы →
`[context."<программа>.*"]` и `[context."<программа>"]`
→ `[context."<программа>.<режим>"]`; среди шаблонов более частный (больше
символов до `*`) применяется позже. Шаблон `x.*` подходит и к `x`, и к
`x.<режим>`; `*.generic` — ко всем контекстам универсального извлекателя.
Ключи `[entry]` принимают те же шаблоны.

Порядок показа: записи из `hide` и групп из `hide_groups` не показываются;
затем блоки по порядку: `pin` (в заданном порядке); раздел «по позиции
курсора»; раздел «дополнение» (оба — раздел «Строка ввода оболочки»);
по разделу на каждое происхождение из `origin_order` манифеста (заголовок —
имя происхождения, записи по клавише); остальные записи по группам: группы
по `order`, остальные — по алфавиту, внутри группы — по клавише.
Происхождения, не перечисленные в `origin_order`, попадают в группы.
`origin_order` задаёт только манифест: переопределить его из `view.toml`
нельзя. Так в оболочке сначала идут клавиши atuin, television и fzf, затем
клавиши ble.sh и readline (`origin_order` в `ble.toml`). `only_modifiers = true`
оставляет записи, первая клавиша которых содержит `C-` или `M-`.
`show_origin = true` подписывает происхождение у каждой записи, список —
только у записей перечисленных происхождений, `false` — без подписей;
на состав записей поле не влияет. `[entry]` переопределяет `desc` и `group`
найденной записи или добавляет запись с происхождением `user`.

Изменение файла перечитывается по событию inotify; ошибка разбора
показывается строкой в панели, действует прежняя конфигурация.

## Ранжирование поиска

Совпадение образца `p` (без учёта регистра, кроме ступени 1) оценивается по
лучшей ступени; записи без совпадения в список не попадают, сортировка — по
очкам по убыванию, при равенстве — в порядке таблицы без поиска. Ступени и
веса — в ядре (`src/search.rs`) и от программ не зависят.

| Ступень | Условие | Очки |
|---|---|---|
| 1 | клавиша равна `p` с учётом регистра | 1000 |
| 2 | клавиша равна `p` без учёта регистра | 900 |
| 3 | клавиша начинается с `p` | 800 |
| 4 | слово короткого описания начинается с `p` | 700 − 10 × номер слова |
| 5 | `p` — подстрока клавиши или короткого описания | 500 − позиция / 4 |
| 6 | `p` — подстрока полного описания или действия | 300 |
| 7 | символы `p` идут по порядку в клавише или коротком описании | 200 − число пропущенных символов, не ниже 1 |

Подсвечиваются совпавшие символы ступени.

## Строка ввода оболочки

Пока панель открыта и в оболочке набирается команда, просмотрщик поднимает
наверх команды редактирования, применимые при текущей позиции курсора, и
предлагает кандидатов дополнения для текущего слова. Работает для ble.sh.

**Отметка и файлы.** Просмотрщик при выборе цели создаёт в каталоге цели
собственную файл-отметку `viewer.<pid просмотрщика>`, при смене цели и выходе
удаляет только её; файлы `*.line`, `*.words`, `*.cands` остаются и удаляются
уборкой каталога закрытой панели. Модуль ble.sh без отметок ничего не пишет
(проверка встроенным glob), а изменение строки без наблюдения обнуляет файл;
пустой файл просмотрщик считает отсутствующим, поэтому при возврате фокуса
без ввода разделы видны сразу и устаревшие данные не показываются.
Файлы пишутся целиком встроенным `printf`, читаются по `IN_CLOSE_WRITE` и
`IN_MOVED_TO`; их изменение пересчитывает только два верхних раздела, а не
контекст и таблицу. При выходе оболочка удаляет свои файлы.

| Файл | Содержимое | Когда пишется |
|---|---|---|
| `ble-<pid>.line` | первая строка — позиция курсора в символах (с нуля), далее текст строки как есть | после `ble/textarea#render`, только при изменении |
| `ble-<pid>.words` | по строке на слово, поля через табуляцию: вид (`sabbrev`, `alias`, `function`), имя, значение | в `PRECMD`; аббревиатуры перечитываются при смене `_ble_complete_sabbrev_version` |
| `ble-<pid>.cands` | первая строка — `COMPV`, далее по строке на кандидата ble.sh | после `ble/complete/candidates/generate` (обёртка ставится по `blehook complete_load`) |

Модуль проверяет наличие функций ble.sh и при отсутствии печатает
предупреждение в stderr вместо записи.

**Переменные позиции** (ядро, `src/cursor.rs`): `point`, `len`, `row`,
`rows`, `rows_below` (строк ниже текущей), `col` (символов от начала
текущей строки до курсора), `line_len`, `word_len` (непробельные символы
слева от курсора), `word_index` (номер слова текущей команды, 0 — позиция
команды), `blank` (1, если строка пуста или из пробелов). Слова слева и
справа от курсора в `when` недоступны, только их длина `word_len`.

**`[[applies]]`.** Правило манифеста: `modes` (необязательный список режимов),
`action` (регулярное выражение по действию), `when` — сравнения
`<переменная> <оп> <число или переменная>` (`<`, `<=`, `>`, `>=`, `==`, `!=`),
соединённые `&&`; неизвестная переменная — ошибка манифеста. Запись,
подходящая правилу, при истинном `when` применима, при ложном — остаётся
на месте и показывается приглушённой. Раздел «по позиции курсора» — не
больше 8 ячеек, по одной на правило с истинным `when` в порядке правил:
самая короткая клавиша правила, при равенстве — первая по таблице, так что
`home` и `C-a` с одним действием занимают одну ячейку (`C-a`). Остальные
применимые записи остаются в своих группах без приглушения. Раздел есть,
пока строка известна и не пуста. Частоту команд задаёт порядок правил:
в `ble.toml` правило на одну команду режимов `vi_imap`, `emacs` и
`auto_complete` — в начало и в конец строки, символ влево и вправо, слово
влево и вправо, удалить символ слева и справа, вырезать слово назад и
вперёд, вырезать до начала и до конца строки, затем прочие команды и
переходы по строкам многострочного ввода.

**Раздел «дополнение».** При непустом слове слева от курсора — до 20 ячеек
«кандидат → вид» в порядке источников: аббревиатуры ble.sh, ключ которых
начинается со слова (значение — раскрытие); кандидаты ble.sh из `.cands`,
если их `COMPV` равен слову; при `word_index = 0` — псевдонимы, функции и
команды из каталогов `PATH` процесса оболочки (список обновляется по
событиям inotify каталогов по имени файла, без пересканирования); при `word_index > 0` — параметры первого слова команды
(`-x`, `--long` с описанием), которые извлекаются разбором `man`, а при
пустом результате `--help` по правилам универсального извлекателя с тем же
кешем на диске; `--help` запускается только у исполняемых файлов ELF
(сценарии с `#!` — нет: сценарий без разбора `--help` выполнил бы своё
действие) и без переменных графической сессии, композитора и шины (`$XDG_CACHE_HOME/herdr-keys-help/options/<команда>.json`).
Описание кандидата — сокращение по правилу выше, подробности `K` показывают
вид, полное значение и источник.

## Вид и навигация

Шапка — контекст и цель (`ble.vi_nmap · w1:p1`), строка поиска при активном
поиске. Ниже — таблица ячеек «клавиша → действие» в порядке показа сверху
вниз по колонкам; заголовок группы — отдельная строка колонки, закреплённые
записи (`pin`) идут первым блоком «закреплено». Ширина ячейки — не менее
33 символов, число колонок `n = min(5, max(1, ⌊W / 33⌋))` по ширине панели
`W` (ширины 40, 80, 120, 140 и 180 дают 1, 2, 3, 4 и 5 колонок). На ячейке
шириной 33 описание длиннее 24 символов (при клавише до 7 символов)
обрезается с `…`. Клавиша выравнивается по самой
длинной клавише колонки, не поместившееся описание режется с `…`. Высота
колонки не больше числа строк таблицы на экране: остальные записи уходят
в следующие колонки, и колонки сдвигаются по горизонтали вслед за выбором.

Панель создаётся без фокуса; клавиши действуют после перехода фокуса
в неё (`prefix+j` herdr или мышь).

| Клавиша | Действие |
|---|---|
| `j`/`k` (стрелки вниз/вверх) | ячейка ниже/выше в колонке, на краю — соседняя колонка |
| `h`/`l` (стрелки влево/вправо) | ячейка той же строки левее/правее |
| `g`/`G` | первая/последняя запись |
| `/` | поиск: образец вводится в шапке, Enter применяет (Esc в строке ввода отменяет ввод); таблица заменяется списком совпадений по релевантности, совпавшие символы подсвечиваются, выбор — на самом релевантном |
| `n`/`N` | следующее/предыдущее совпадение в порядке релевантности по кругу |
| Esc | сброс поиска: прежний вид таблицы и прежний выбор; в окне подробностей — закрыть его |
| `K` | подробности выбранной записи |
| `d` | скрыть запись: дописать клавишу в `hide` текущего контекста (кандидата дополнения — нельзя, сообщение) |
| `D` | скрыть группу: дописать группу в `hide_groups` текущего контекста; только из раздела группы, в остальных разделах — сообщение «группу скрыть нельзя» |
| `u` | отменить последнее скрытие этой сессии просмотрщика |
| `q` | вернуть фокус верхней панели; панель остаётся открытой |

Подробности — окно поверх таблицы: клавиша, описание, полное описание,
действие, группа, происхождение, источник, контекст и `raw`; длинный текст прокручивается `j`/`k`, `q` и Esc
закрывают окно. Фокус на просмотрщике цель не меняет, поэтому скрытие,
поиск и подробности относятся к контексту панели, с которой пришёл
пользователь. При смене контекста выбор встаёт на первую запись, поиск
сбрасывается.
