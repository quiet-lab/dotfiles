# Neovim в русской раскладке

Поведение задаёт спецификация `ru-layout` (`openspec/specs/ru-layout/`),
причины выбора — `design.md` изменения `ru-layout` в `openspec/changes/archive/`.
Здесь — устройство, правила, которые нужно знать при работе, перечень того,
что остаётся ручным переключением, и проверка после обновления плагинов.

## Назначение

Neovim работает при системной русской раскладке без переключения: встроенные
команды, привязки плагинов, flash, командная строка, диалоги и терминальные
программы с латинскими клавишами получают те же действия, что и в английской
раскладке. Система не переключается ни в `:`, ни в терминале: перевод идёт
внутри Neovim по физическим клавишам. Модуль `claude-input` не затрагивается:
`:w` в буфере ввода и цифры диалога работают как прежде
([`claude-input.md`](claude-input.md)).

## Устройство

Каталог модуля — `dot_config/nvim/local/ru-layout` (в `$HOME`:
`~/.config/nvim/local/ru-layout`), модули — `lua/ru-layout/`, тесты — `tests/`.

| Файл | Что делает | По какому событию |
|---|---|---|
| `table.lua` | Сгенерированная таблица ЙЦУКЕН ↔ QWERTY и строка `langmap` | Загрузка модуля |
| `gen-table.lua` | Генератор таблицы из карты XKB | Ручной запуск |
| `tr.lua` | Перевод строк и левых частей привязок по таблице | Вызов из других модулей |
| `layout.lua` | Код активной раскладки (`us`/`ru`) из Hyprland, устройство `dh747-w-corne` | Событие `activelayout` сокета Hyprland, подключение по inotify; каталог с «мёртвыми» сокетами после отказа не пробуется, пока нет событий файловой системы |
| `keymap.lua` | Подмена API привязок, кириллический дубль каждой латинской привязки | Установка привязки; `FileType` и `BufWinEnter` для Vim-script плагинов (`BufWinEnter` — только для типов файлов из `M.filetypes`, не для всех буферов) |
| `punct.lua` | Знаки раскладки в n/x/o (`.` → `/`, `,` → `?` и далее), прежние действия на парах | `setup()` и `User LazyLoad` |
| `macro.lua` | Обёртка `@`: имя регистра по физической клавише | Нажатие `@` |
| `rchar.lua` | Обёртка `r` по правилу раздела «Замена символа» | Нажатие `r` |
| `cmdline.lua` | Перевод строки `:` по `<CR>` и `<Tab>`, переключатель `<M-l>` в `/` и `?` | Нажатие `<CR>`, `<Tab>`, `<M-l>` в командной строке |
| `dialogs.lua` | Ответы `confirm()` и `:s///c` по паре | Клавиша в запросе (`vim.on_key`) |
| `flash.lua` | Кириллические метки, поиск по обеим раскладкам, защита от смены внутренностей flash | Вызов команд flash; `User LazyLoad` для flash |
| `chords.lua` | Сочетания с Ctrl и Alt в кириллической форме: перевод встроенных команд, чтение продолжений, явные последовательности | `setup()` после `keymap.sweep()` |
| `index.lua` | Сгенерированный перечень встроенных сочетаний с Ctrl по режимам | Загрузка `chords.lua` |
| `gen-index.lua` | Генератор перечня из `$VIMRUNTIME/doc/index.txt` | Ручной запуск |
| `getchar.lua`, `plugins.lua` | Постоянный перевод сочетаний с модификатором в `getchar`/`getcharstr`; перевод букв на время вызова плагина; перечень обёрнутых плагинов | `setup()`; `User LazyLoad` |
| `terminal.lua` | Привязки режима `t` по паре в терминалах программ из списка | `TermOpen`, `TermRequest` |
| `init.lua` | `setup(opts)`: порядок установки модулей | Запуск Neovim |

Порядок загрузки:

1. `lua/config/lazy.lua` до `require("lazy").setup` добавляет каталог модуля
   в `runtimepath` и вызывает `keymap.install()`: подмена должна стоять
   до того, как lazy.nvim и LazyVim начнут ставить привязки.
2. `lua/plugins/ru-layout.lua` описывает локальный плагин (`lazy = false`,
   `priority = 1000`), его `config` вызывает `require("ru-layout").setup()`.
3. `setup()` задаёт `langmap` из таблицы (чужой непустой `langmap` не затирается),
   подключает раскладку, проходит по уже существующим привязкам (`keymap.sweep()`),
   ставит перевод сочетаний в `getchar` и `chords` (при запуске Neovim — сразу
   после VimEnter, чтобы сотни `:map` не входили во время запуска), затем `punct`, `macro`, `rchar`, `cmdline`, `dialogs`, `terminal`, `plugins`;
   `flash` ставится после загрузки flash.nvim. Ошибка одного модуля выводится
   сообщением уровня ERROR и остальные не останавливает. Параметры: `opts.layout`
   (`device`), `opts.terminal` (`programs`).

`require("ru-layout")` сам ничего не делает: побочные действия — только в
`setup()` и `install()`. Таймеров и опроса нет: раскладка приходит событием
сокета, переподключение — по inotify.

## Источник раскладки

Код активной раскладки берётся из Hyprland: подписка на `.socket2.sock`,
строки `activelayout>>устройство,раскладка`, события других устройств
(виртуальные клавиатуры `wtype`) пропускаются. Читается он синхронно из
памяти (`layout.get()`), `nil` считается английской раскладкой. От раскладки
зависят только метки flash и знаки `. , " ; : ? /`: без Hyprland (ssh, TTY,
другой композитор) метки остаются латинскими, знаки не переводятся, всё
остальное работает: перевод по физическим клавишам от раскладки не зависит.
При появлении экземпляра Hyprland модуль подключается сам. После отказа
подключения к каталогу с «мёртвыми» сокетами (Hyprland упал, файлы остались)
каталог не пробуется снова, пока файл сокета тот же и в каталоге нет событий
файловой системы: модуль ждёт другой экземпляр по inotify. Если карта
`dot_config/X11/xkb_custom` менялась, таблица пересоздаётся (раздел
«Регенерация таблицы»).

## Привязки

- К каждой привязке с латинской левой частью ставится вторая, с левой частью
  по раскладке (`<leader>ff` → `<leader>аа`, `<M-d>` → `<M-в>`), с теми же
  правой частью, функцией и опциями. Режимы `n`, `x`, `o` — всегда;
  `i`, `c`, `t`, `s` — только при модификаторе (`<M-…>`, `<C-…>`, `<A-…>`,
  `<D-…>`); `l` — никогда. Буквенные и знаковые привязки в `i`, `c`, `t`, `s`
  (mini.pairs, точки разрыва отмены, `jk`) не переводятся: иначе русский текст
  исказился бы (`iх ъ ж э б ю Э .` вставляется как набрано).
- `<Plug>…` и `<SNR>…` не переводятся. Кириллическая привязка пользователя
  дублем не перекрывается.
- Сочетание с модификатором дублируется в двух формах: полной (`<C-w>x` →
  `<C-ц>ч`, так передаёт Neovide) и физической (`<C-w>ч`, так передаёт wezterm).
  Кириллическая привязка с модификатором (`<M-в>`) получает обратный дубль
  на латинском сочетании (`<M-d>`), если оно свободно. Подробности — раздел
  «Независимость от хоста».
- Знаки по раскладке в n/x/o: клавиша, печатающая в RU `.`, действует как `/`
  (поиск), `,` — как `?`, `"` — как `@`, `;` — как `$`, `:` — как `^`, `?` — как
  `&`, `/` — как `|`. В английской раскладке клавиши действуют как прежде.
  Прежние действия знаков уходят на пары: `ю` — повтор `.`, `б` — `,` flash,
  `Э` — регистр `"`, `ж` — `;` flash, `Ж` — командная строка.

## Замена символа и макросы

- Правило `r`: в русской раскладке `r` с кириллической буквой над латинской
  буквой ставит символ той же клавиши в английской раскладке (`rа` над `abc`
  даёт `fbc`), над кириллицей, цифрой, знаком или пустой строкой — букву как
  набрана (`rф` над `xbc` даёт `abc`: так русский текст правится русскими
  буквами). В английской раскладке и для прочих аргументов (`<Esc>`, `<CR>`,
  `<C-v>…`, цифры, знаки) `r` работает как встроенный. Счётчик и повтор
  (`.`, `ю`) сохраняются. В visual решение принимается по всему выделению:
  перевод, если в нём есть латинская буква и нет кириллицы (`v$rа` над `abc1`
  даёт `ffff`, над `abcд` — `аааа`). Дубль `к` ставит модуль keymap (явной
  привязки нет); `gr` не затрагивается.
- Обёртка `@` читает имя регистра по физической клавише (`@ф` — `@a`,
  `@Ж` — `@:`, `@"` в RU — `@@`). Работает и в `:normal @a`, `:normal 2@a`,
  `:g/x/normal @a`: макрос, записанный при RU, воспроизводится. `@@`, `@:`
  и вложенные `@a` в записываемом макросе — как у встроенного `@`.

## Командная строка и поиск

Системная раскладка не переключается: `Ж` даёт `:` через `langmap`, а строка
переводится по `<CR>` и перед `<Tab>`. Правило перевода строки `:`:

1. Строка из одних русских букв (с `!` на конце) переводится целиком по
   физическим клавишам.
2. Иначе переводится голова команды: диапазон (`ю` → `.`, `б` → `,`, `ж` → `;`,
   `э<` → `'<`; шаблоны `/…/` остаются как набраны), командное слово
   (`Б`, `Ю` — команды `<`, `>`), модификаторы (`silent`, `vertical`, `tab` и
   др.) — с повторным применением правила к остатку. Слово с латинской буквой
   — строка не трогается целиком.
3. Аргументы — по виду команды: `:s` — шаблон и замена как набраны, флаги
   по клавишам; `:g`, `:v` — шаблон как набран, команда по правилу;
   `:set` — имя опции, значение только если его предлагает дополнение;
   `:help`, `:colorscheme`, `:Lazy` и другие команды с дополнением —
   лексема переводится, только если дополнение предлагает слово с таким
   началом; `map` и `unmap` для n/x/o — левая часть; всё остальное
   (`:let`, `:echo`, `:call`, `:lua`, `:normal`, `:grep`, пути) — текст,
   как набрано.

| Набрано после `Ж` | Выполняется |
|---|---|
| `ц`, `цй`, `йф!`, `в` | `:w`, `:wq`, `:qa!`, `:d` |
| `ыуе тгьиук`, `ыуе еы=4`, `ыуе ае=дгф` | `:set number`, `:set ts=4`, `:set ft=lua` |
| `ыуе ешедуыекштп=Привет` | `:set titlestring=Привет` (значение — текст) |
| `у файл.txt` | `:e файл.txt` |
| `%ы/старое/новое/п`, `ы.старое.новое.пс` | `:%s/старое/новое/g`, `:s.старое.новое.gc` |
| `п/x/тщкьфд @a`, `п!/x/в` | `:g/x/normal @a`, `:g!/x/d` |
| `'<,'>ы/a/b/`, `э<,э>в`, `ю,;в` | `:'<,'>s/a/b/`, `:'<,'>d`, `:.,;d` |
| `усрщ "привет"`, `дуе g:z='привет'` | `:echo "привет"`, `:let g:z='привет'` |
| `рудз ьфз`, `ышдуте! ц` | `:help map`, `:silent! w` |
| `Ялц гзвфеу` (команда с дополнением) | `:Zkw update` (переводится, если дополнение предлагает) |
| `ЮЮ`, `ыпс` | `:>>`, `:sgc` |
| `let g:z='привет'`, `s/а/б/п`, `sу`, `!ls фыв` | как набрано (латинское слово) |

Русское слово, набранное в `:` по ошибке, выполняется как команда тех же
клавиш в английской раскладке (`привет мир` → `:ghbdtn мир`, ошибка E492 как
прежде). В истории остаётся переведённая строка.

`<Tab>`: перед дополнением текст до курсора переводится по тому же правилу,
затем вызывается прежняя привязка `<Tab>` (blink.cmp, при её отсутствии —
встроенное дополнение). Пути и прочие текстовые аргументы не переводятся.
Привязка модуля переустанавливается после blink.cmp и на каждом `CmdlineEnter`.

`<M-l>` (и `<M-д>`) в `/` и `?` — переключатель: набранный текст переписывается
в шаблон по обеим раскладкам (`ыуд` → `\V\[ыs]\[уe]\[дl]`), повторное нажатие
возвращает исходный текст. Так латинский шаблон ищется после ввода
кириллицей и наоборот. В `:` клавиша не действует. `<M-д>` — дубль модуля
keymap.

## Диалоги

В запросе `confirm("?", "&Yes\n&No\n&Cancel")` и в ответах `:s///c` (режим
ожидания одной буквы) кириллическая клавиша заменяется клавишей той же
физической клавиши: `н`, `т`, `С` — `y`, `n`, `C` в `confirm()`; `н`, `т`, `ф`,
`й`, `д` — `y`, `n`, `a`, `q`, `l` в `:s///c`. `<Esc>`, `<CR>`, латиница
и цифры `inputlist()` работают как прежде.
Кнопки `confirm()` с русскими буквами встроенный запрос не принимает вовсе.

## flash

- `ы`, `Ы`, `к`, `К` — те же команды, что `s`, `S`, `r`, `R`; `а е А Е ж б`
  — `f t F T ; ,`.
- Метки по активной раскладке: в RU — кириллические (набор меток режима
  переводится), в US — латинские. Явные `opts` вызывающего главнее.
- Поиск идёт по обеим раскладкам: символ с парой превращается в класс
  `\[ыs]`, так `пр` находит и «проект», и `gh…`. Пропуск меток учитывает
  пары и регистр кириллицы. Backspace в строке поиска удаляет символ,
  а не байт.
- Команды flash оборачиваются на `flash.commands.*`, поэтому поведение
  получают и латинские клавиши LazyVim, и дубли `ы Ы к К`.
- `/` с `modes.search` flash работает с кириллическими метками.
- Защита: перед обёрткой `setup()` проверяет, что внутренности flash
  (`Char.mode`, `Labeler.skip`, `Pattern.extend`, `plugins.search.start`) на
  месте. Иначе обёртка не ставится, и один раз выводится предупреждение
  «ru-layout: внутренности flash изменились, откатите flash по lazy-lock.json».

## Плагины, читающие клавиши

`getchar.with_tr` подменяет `getchar` и `getcharstr` только на время вызова
плагина: кириллица переводится по паре, латиница, цифры и специальные клавиши
не меняются. Глобальной подмены нет (она сломала бы русский поиск flash).
Обёрнуты which-key (буква после префикса), mini.ai, mini.surround, mini.files
(закладки), snacks (выбор окна), bufferline (выбор буфера), neogit, neotest,
nvim-dap-ui, diffview. Без обёртки по причине: flash (ведёт `flash.lua`),
vim-fugitive, lazy.nvim, LazyVim (только прерывание или «нажмите любую
клавишу»). Кириллические дубли привязок в окне which-key скрыты: окно
показывает латинские привязки, русские работают.

## Независимость от хоста

Хосты Neovim передают одно и то же нажатие по-разному. wezterm (и herdr в нём)
кодирует сочетание по физической клавише: Ctrl+`в` — `<C-d>`, Alt+`в` — `<M-d>`,
Shift+`в` — `<S-В>`. Neovide передаёт символ: `<C-в>`, `<M-в>`, `В`. Модуль
не определяет хост и не переключает раскладку: обе формы обрабатываются
одинаково по устройству.

- `<S-В>` и `В` Neovim и так считает одной клавишей; без модификатора кириллица
  в обоих хостах одинакова, её ведут `langmap` и остальные модули.
- Встроенные сочетания с Ctrl. `chords.lua` ставит для каждой буквы
  `<C-кир>` → `<C-лат>` (`<C-в>` → `<C-d>`, `<C-S-В>` → `<C-S-d>`) в режимах
  `n`, `x`, `s`, `o`, `i`, `c`, `t`; в `c` вместо `<Esc>` (`<C-х>`) — `<C-c>`:
  `<Esc>` из привязки в командной строке выполнил бы команду. Сочетания с Alt
  переводятся только в `t`: в остальных режимах свободное `<M-в>` Neovim сам
  выполняет как `<Esc>в`, а `<M-d>` из привязки так не раскрывается.
- Продолжения. Вторую клавишу после `<C-r>`, `<C-x>`, `<C-g>`, `<C-v>`/`<C-q>`
  и `<C-\>` (в `n` и `x` — и после `<C-w>`) Neovim читает мимо привязок. На эти
  префиксы ставятся привязки-читатели: они читают продолжение `getcharstr()`,
  переводят кириллицу по перечню `index.lua` и отдают Neovim латинскую
  последовательность. Регистр после `<C-r>` в insert идёт как есть (его переводит
  `langmap`), в `:` — переводится; после `<C-м>` кириллица без модификатора
  вставляется как символ, `<C-в>` — как `^D`. Многоклавишные записи, начинающиеся
  не с Ctrl (`g<C-a>` в visual, `z<C-…>`), ставятся явными последовательностями.
- Приоритет. Перевод встроенных сочетаний ставится последним и с `<unique>`:
  привязку пользователя или плагина (`<C-d>`, `<C-в>`) он не перекрывает.
  Дубль латинской привязки (`<C-d>` → `<C-в>`) заменяет перевод, а после снятия
  привязки перевод возвращается. Порядок установки (до `lazy.setup`, после него,
  в `FileType`) на итог не влияет. Обратный дубль кириллической привязки
  (`<C-в>` → `<C-d>`) занимает латинское сочетание, если на нём нет привязки,
  поэтому в раскладке US оно выполняет ту же привязку, а не встроенную команду:
  хост, передающий физическую клавишу, иначе её не вызовет.
- `getchar` и `getcharstr` всегда возвращают сочетание с модификатором
  в латинской форме (`<C-в>` → `<C-d>`): плагин, читающий клавишу, получает
  одно и то же в обоих хостах. Буквы без модификатора переводятся только
  на время вызова обёрнутого плагина (раздел «Плагины, читающие клавиши»).

Перечень встроенных сочетаний создаётся из `index.txt`; `chords_spec.lua`
сверяет его с генератором и для каждой записи режимов `n`, `x`, `o`, `i`, `c`
сравнивает состояние (буфер, курсор, окна, режим, командная строка) после ввода
в латинской, физической и полной форме. Остатки — в таблице «Остатки без перевода».

## Терминал

В терминальном буфере программы из списка (по умолчанию `lazygit`) на время
работы получают привязки режима `t` по паре для всех букв и `Ё`/`ё`, поэтому
русские клавиши доходят до программы как клавиши той же латинской буквы.
`<Esc>`, `<C-\><C-n>`, `<C-…>`, ASCII-знаки раскладки не затрагиваются. Список
задаёт `opts.terminal.programs` в `lua/plugins/ru-layout.lua` (заданный список
заменяет прежний целиком: `{ "lazygit", "lazydocker", "k9s", "btop" }`).

Программа определяется по имени буфера терминала (`Snacks.lazygit`, запуск
командой) и по заголовку терминала (OSC 0/2) для запуска из shell. Shell
(`bash`, `zsh`, `fish`) и всё вне списка привязок не получают: русский текст
в shell набирается как есть. `$ lazygit` из shell переводится только при
заголовке с именем команды (fish выставляет его сам, в bash и zsh нужен
`PROMPT_COMMAND` или `preexec` с OSC 0), иначе остаётся ручное переключение.

Русский текст внутри программы из списка (сообщение коммита в lazygit, поиск
по кириллице) набирается после `<M-l>` в режиме `t`: клавиша снимает привязки
перевода в этом буфере, повторное нажатие ставит их обратно. Alt+`д` в русской
раскладке приходит как `<M-l>`; `<M-д>` — дубль модуля keymap. Состояние хранит переменная буфера
`ru_layout_terminal_off`; новый терминал и возврат заголовка к программе
вне списка начинают с включённого перевода.

## Требование → как покрыто → что остаётся вручную

Требования проекта «Neovim в русской раскладке».

| № | Требование | Как покрыто | Что осталось вручную и почему |
|---|---|---|---|
| 1 | Команды и клавиши в n/x/o при RU | `langmap` — встроенные команды; `keymap.lua` — привязки; знаки по раскладке; `@` и `r` | Буква в `confirm()` с русскими кнопками: встроенный запрос не принимает; `-- More --` |
| 2 | Горячие клавиши в insert, `:` и поиске, включая назначенные вручную, в любом хосте | Встроенные сочетания с Ctrl по перечню `index.txt` — `chords.lua` в обеих формах; продолжения — привязки-читатели; дубли привязок в полной и физической форме, обратный дубль кириллических; перевод сочетаний в `getchar`; `<M-l>` в `/` и в терминале | Смешанная форма внутри одного сочетания и прочие остатки — таблица «Остатки без перевода» |
| 3 | flash при RU | `flash.lua`: `ы`, поиск по обеим раскладкам, кириллические метки, `f`/`t`, `Ы`, `к` | Макрос с метками flash, записанный в одной раскладке и воспроизведённый в другой |
| 4 | Универсальность для плагинов | Подмена API привязок; проход по `FileType`; обёртки потребителей `getchar`; сторожевой тест | Плагин, сохранивший `getchar` в локальную переменную при загрузке: обёрткой не перехватывается, сторожевой тест его не видит |
| 5 | Разбор по режимам | Таблица ниже | — |
| 6 | Минимум ручных переключений | Таблица остатков ниже | Остатки таблицы ниже |
| 7 | `claude-input` не ломается | Тесты `claude-input` зелёные; буквенные привязки в `i`, `c` не переводятся; `:w` — перевод `<CR>` | — |

Режимы:

| Режим | Что делает модуль |
|---|---|
| normal, visual, operator-pending | `langmap`, дубли привязок, знаки, `r`, `@`, flash |
| select | Дубли только с модификатором: печатаемые буквы остаются текстом |
| insert, replace | Дубли только с модификатором; текст не искажается |
| `:` | Перевод по `<CR>` и `<Tab>`, `Ж` без переключения системы |
| `/`, `?` | Знаки `.` и `,`; `<M-l>` переключает шаблон на обе раскладки |
| terminal | Привязки режима `t` по паре для программ из списка; `<M-l>` включает и выключает перевод в буфере |
| диалоги | `confirm()`, `:s///c` по паре, цифры `inputlist()` |
| окна-подсказки | which-key, mini.*, выбор окна и буфера через `getchar` |

Остатки проекта:

| Место | Состояние | Чем закрыто | Что остаётся и почему |
|---|---|---|---|
| Латинский текст в insert | Не переводится | — | Язык текста выбирает пользователь: клавиша одна, смысл разный; одинаково при любом решении |
| Русский текст в `:` после переключения системы | Переводится | Система не переключается: `:s/старое/новое/` не тронут, команда переводится | — |
| Латинский шаблон в `/` при RU | Переводится | `<M-l>` переписывает шаблон по обеим раскладкам; flash ищет по обеим | Набрать латинский шаблон при RU без `<M-l>` нельзя: шаблон — текст |
| `r` латинской буквой при RU | Переводится по правилу | Обёртка `r`: кириллица над латиницей — парная латинская клавиша | Латинская буква над кириллицей, цифрой или знаком: ставится как набрана, латиницу туда не получить |
| Ответ в `confirm()` и `:s///c` при RU | Переводится | `dialogs.lua` | Русские кнопки `confirm()`; `-- More --` |
| Shell в терминальном буфере | Не переводится | Программы из списка переводятся; `<M-l>` отключает перевод для русского текста | Shell вне списка получает текст как есть: русский текст в нём нужен; `$ lazygit` из shell — только при заголовке OSC |
| Макрос из RU через `:normal @a` | Переводится | Обёртка `@` | `:normal! @a`, `:exe "normal! @a"` |

Остатки без перевода:

| Остаток | Почему не закрывается |
|---|---|
| `:normal! @a` (с `!`) | Встроенный `@` без обёртки; перевод содержимого регистра при записи исказил бы русский текст вставки |
| Приглашение `-- More --` | Клавиши читаются мимо `vim.on_key`; в конфигурации с noice приглашения нет |
| Цепочки `\|` в `:` | Переводится первая команда (и команда `:g`); после `\|` строка как набрана |
| ASCII-знаки раскладки ru в `:` (`.` `,` `/` `;` `:` `"` `?`) | Один символ набирается разными клавишами в двух раскладках, по строке не отличить; кириллица на их местах переводится |
| Разделитель `:s` кириллицей (`:ыюаюбю`) | Та же буква в тексте шаблона осмысленна |
| Значения опций `:set` вне дополнения | Значение — текст, переводится только предложенное дополнением |
| Метки flash при макросе в другой раскладке | Набор меток берётся по раскладке в момент воспроизведения; метки зависят и от текста буфера |
| Метки flash в режиме char при `jump_labels = true` | Остаются латинскими (по умолчанию выключено) |
| `label.uppercase` для кириллицы | flash использует `string.upper`, заглавных кириллических меток нет — меток меньше |
| Плагин с кэшированным `getchar` | Функция сохранена до обёртки; сторожевой тест такой плагин не видит |
| Прежнее действие знака с `<SID>` в правой части | Контекст сценария теряется; среди привязок LazyVim таких на этих знаках нет |
| `'langremap'` включена на время макроса | Кириллица в правой части привязок, сработавших внутри макроса, переводится `langmap` |
| Смешанная форма в продолжении: латинский префикс и кириллическое сочетание (`<C-v><C-в>` в insert, `<C-r><C-к>`) | Neovim читает вторую клавишу мимо привязок: `<C-v><C-в>` вставляет текст `<C-в>`, `<C-r><C-к>ф` — `ф`. Одна форма внутри сочетания получается только при смене раскладки посреди него |
| Аргумент диграфа `<C-k>` | Две клавиши после `<C-k>` — текст, кириллица в нём осмысленна |
| Сообщение `-- ^X mode --` | Пока читатель ждёт вторую клавишу, Neovim режима не показывает |
| `<C-В>`, `<C-S-в>`, `<C-M-в>` | Кодирование Ctrl+Shift и Ctrl+Alt в Neovide не установлено; переводятся `<C-кир>` и `<C-S-КИР>` |
| `<C-c>` после `<C-w>` | Нажатое `<C-c>` Neovim принимает как прерывание до привязок, кириллическое `<C-с>` — как отмену читателем |

## Проверка после обновления плагинов

```sh
# после :Lazy update
cd ~/.config/nvim/local/ru-layout && bash tests/run-all.sh
```

Тесты идут на оснастке `tests/harness` (испытуемый Neovim без пользовательской
конфигурации, двойник Hyprland `fake-hypr.py` в своём `XDG_RUNTIME_DIR`);
конфигурация, живой Hyprland и плагины пользователя не затрагиваются. Каждый
файл `tests/*_spec.lua` запускается отдельно: `nvim --headless --clean -u NONE -l
tests/<имя>_spec.lua`; итог — `ALL OK` и код 0. Прогон останавливается
на первом падении.

- Падение `guard_spec` — в плагине появился новый потребитель `getchar` или
  изменилось число точек чтения. Открыть указанный файл плагина; если функция
  читает клавишу-команду (метку, букву меню), добавить обёртку в `plugins.lua`
  и случай в `plugins_spec.lua`; если клавиша не нужна в латинице («нажмите
  любую клавишу») — внести плагин в `M.ignored` с причиной; обновить числа
  `points` и прогнать `getchar_spec`, `plugins_spec`, `guard_spec`.
- Падение `plugins_spec`, если починить сразу нельзя — откат плагина по
  `lazy-lock.json`: `:Lazy restore <плагин>`.
- Падение `flash_spec` или предупреждение «внутренности flash изменились» при
  запуске — откат flash по `lazy-lock.json`: `:Lazy restore flash.nvim`.
- Падение `cmdline_spec` в разделе blink — `<Tab>` модуля не стоит поверх
  blink.cmp или меню не предлагает команды: разбор в `cmdline.lua`, функция
  переустановки привязки.

Каталог модуля в `$HOME` ставится `chezmoi apply`; `lazy-lock.json` после
обновления забирается `chezmoi re-add ~/.config/nvim/lazy-lock.json`.

## Живые проверки

Нажатия подаёт ydotool (устройство uinput проходит через карту XKB, как
физическая клавиатура); `wtype` привязки композитора не запускает.

- Событие `activelayout` Hyprland при Super+Пробел: строка
  `activelayout>>dh747-w-corne,…`.
- Кодирование сочетаний хостом: wezterm — `<M-d>`, `<C-D>`, `<S-В>`; Neovide —
  `<M-в>`, `<C-в>`, `В`.
- Одинаковый результат в обоих хостах: Ctrl+`ц` в insert удаляет слово, Ctrl+`к`
  `ф` вставляет регистр `a`, Ctrl+`ц` `ы` делит окно, Ctrl+`ф` в терминальном
  буфере даёт `^A`.

Сценарии — `live-checks/check2.py <wezterm|neovide>` в каталоге результатов
задачи ru-layout (кодирование) и `live-check` в каталоге результатов задачи
host-keys (результат в обоих хостах). Сценарий запускает хост с отдельным
Neovim, подаёт нажатия и сверяет итог.

## Регенерация таблицы

Таблица `table.lua` создаётся из карты XKB, той же, что `kb_file` в
`hyprland.lua`. При любом изменении `dot_config/X11/xkb_custom`:

```sh
cd dot_config/nvim/local/ru-layout/lua/ru-layout
nvim -l gen-table.lua ~/.config/X11/xkb_custom table.lua dot_config/X11/xkb_custom
```

Генератор сам форматирует выходной файл stylua по `stylua.toml` плагина (stylua
из `PATH` или `~/.local/share/nvim/mason/bin/stylua`); без stylua форматирование
выполняется вручную: `stylua lua/ru-layout/table.lua` в каталоге плагина.
`stylua --check lua tests` в источнике проверяет и этот файл.

Затем прогнать `tests/run-all.sh`: `table_spec` сверяет пары физических клавиш.
`table.lua` руками не правится.

## Регенерация перечня встроенных сочетаний

`index.lua` создаётся из `$VIMRUNTIME/doc/index.txt` (и меток `insert.txt`,
`cmdline.txt`) установленного Neovim. После обновления Neovim:

```sh
cd dot_config/nvim/local/ru-layout/lua/ru-layout
nvim -l gen-index.lua index.lua
```

Генератор форматирует файл stylua, как `gen-table.lua`. `chords_spec.lua`
сверяет `index.lua` с генератором и падает, если перечень устарел; затем
сравнивает обе формы каждой записи. Запись, которую нельзя проверить в одном
Neovim (`<C-z>`, закрытие окна), внесена в `SKIP` теста с причиной.
`index.lua` руками не правится.
