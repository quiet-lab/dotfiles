# Документация репозитория dotfiles

Здесь лежат долговременные сведения о системе и о работе с ней: то, что
не выводится из конфигов, но нужно помнить. Каталог исключён
в `.chezmoiignore`, поэтому `chezmoi apply` его в `$HOME` не переносит —
это документация репозитория, а не dotfile.

## Чем это отличается от соседей

- **`openspec/`** — требования к поведению: спецификации capability
  (`openspec/specs/`) и активные изменения. Там описано, как должны
  вести себя панель Quickshell, демон workspaced и сессия Hyprland,
  и по чему это проверяется.
- **`docs/decisions/`** — принятые решения, которые поведением не являются:
  выбор инструмента, размещение компонента, отвергнутые варианты и причины
  отказа, условия пересмотра. Спецификация отвечает на вопрос «как система
  себя ведёт», запись решения — «почему выбрано именно так».
- **`docs/open-questions/`** — вопросы, ответа на которые сейчас получить
  нельзя: каждый отдельным файлом, с обязательным условием пересмотра.
  Когда вопрос решается, его содержание переезжает в запись решения,
  а файл удаляется.
- **`todo.md`** в корне — снимок текущей работы и перечень отложенных дел.
  Долговременных сведений там нет, только ссылки сюда.
- **`AGENTS.md`** (он же `CLAUDE.md` по ссылке) — правила, нужные в каждой
  сессии: соглашения chezmoi, команды, запреты. Подробности лежат здесь,
  в `AGENTS.md` остаётся ссылка.

История сделанного нигде не ведётся: её хранят история git и архив
`openspec/changes/archive/`.

## Как вести документы

- Документ описывает нынешнее состояние, а не историю изменений.
  Устаревший текст исправляется или удаляется тем же изменением, которое
  сделало его неверным.
- Одно сведение — в одном документе; в остальных на него ставится ссылка
  относительным путём.
- Имена файлов — латиницей, слова через дефис.
- Факт о системе перед записью проверяется по живому состоянию — командой,
  файлом, журналом, — а не переносится из старого текста.
