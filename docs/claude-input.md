# Буфер ввода Claude Code в neovim

Поведение задаёт спецификация `claude-input` (`openspec/specs/claude-input/`),
выбор последовательностей и замеры — `design.md` изменения
`claude-input-buffer` в `openspec/changes/archive/`.
Здесь — устройство и проверка после обновления Claude Code.

## Устройство

- Хук `~/.claude/hooks/herdr-claude-input.sh` (источник
  `dot_claude/hooks/executable_herdr-claude-input.sh`) вызывается из
  `~/.claude/settings.json`: `open` по `SessionStart` (`startup`, `resume`),
  `close` по `SessionEnd`. `open` делит панель Claude Code в herdr вниз,
  выводит новую панель на 13 строк и запускает в ней `exec nvim +ClaudeInput`
  с переменной `CLAUDE_INPUT_PANE` — идентификатором панели Claude Code.
  Фокус после открытия — у панели ввода, клиент на другой workspace не
  переключается: панель делится с `--no-focus`, затем `herdr pane activate`.
  Без команды `pane activate` хук пишет ошибку в stderr и панель не открывает.
  Хук действует и у исполнителей duty в дочерних workspace (задана
  `DUTY_TASK`); не действует вне herdr и у субагентов.
- Панель Claude Code несёт токен `input_pane` источника `claude-input`
  со значением `pane_id` панели буфера (`herdr pane report-metadata --token`;
  виден в `tokens` ответа `herdr pane get`). Токен стоит на панели Claude Code,
  потому что снимок клиента несёт токены только панелей с агентом. Форк herdr
  по токену находит панель ввода: фокус на неё при выборе workspace в Spaces
  и агента в Agents, слежение за blocked. Токен ставит `open` после создания
  панели буфера и заново при `resume` с живой панелью буфера.
- Окна буферов `claude://input` и `claude://dialog` переносят строки
  визуально по словам (`wrap`, `linebreak`, `breakindent` на окно при каждом
  показе буфера, при уходе буфера значения возвращаются); текст буфера
  и строка ввода Claude Code переносов не получают.
- Команда `/input-reopen` (навык `dot_claude/skills/input-reopen`) вызывает
  `herdr-claude-input.sh reopen`, когда nvim завис: хук закрывает панель буфера
  (идентификатор — из файла соответствия, при его отсутствии — из токена
  `input_pane`; закрытие панели herdr завершает зависший nvim) и открывает
  панель заново путём `open`. Нет старой панели — просто открывает.
  Вызов допустим из любой панели workspace: панель Claude Code ищется по токену
  `input_pane` (у самой панели; панель агента с токеном, равным вызывающей
  панели; единственная панель агента Claude Code workspace), предки процесса
  не проверяются. Горячая клавиша Ctrl+Alt+R клиента herdr (таблица
  `[keys]` в `dot_config/herdr/config.toml`) вызывает тот же хук.
- Соответствие панелей лежит в `~/.local/state/claude-input/<панель>`
  (двоеточие в имени заменено подчёркиванием). Файл, оставшийся после
  обрыва, не мешает: `open` проверяет, жива ли записанная панель.
- Плагин neovim — локальный каталог `~/.config/nvim/local/claude-input`
  (модуль `claude_input`), спецификация lazy.nvim —
  `lua/plugins/claude-input.lua`. Он пишет в сокет herdr
  (`HERDR_SOCKET_PATH`) напрямую через `vim.uv`, по соединению на запрос.

## Буфер диалога

- Плагин держит подписку `pane.agent_status_changed` на панель Claude Code.
  По событию, по правке буфера диалога и по `:w` он читает экран панели
  (`pane.read`, источник `detection`) и разбирает его модулем
  `claude_input/dialog.lua`.
- Статус `blocked` и экран с пунктами выбора — окно панели переходит
  на `claude://dialog`; пока экран остаётся диалогом, буфер диалога
  держится при любом статусе (в поле «Type something» детектор herdr
  показывает `done`). Экран без диалога — окно возвращается
  к `claude://input`. После `:w` на последнем экране диалога окно
  возвращается к вводу сразу, не дожидаясь смены экрана. Буфер диалога
  создаётся на время диалога, не входит в список буферов (в строке
  буферов его нет) и удаляется при возврате окна к вводу.
- Карточка из нескольких вопросов отвечается в одном буфере диалога:
  `:w` на вопросе оставляет буфер открытым, переход к следующему вопросу
  или обзору плагин узнаёт подпиской `pane.output_matched` на строку
  вкладок с большим числом `☒` (статус при смене вопроса остаётся
  `blocked`, событий статуса нет). После правки поля свободного ввода
  детектор herdr держит `idle` до конца карточки, поэтому экран карточки
  считается диалогом при любом статусе, а закрытие диалога ловит подписка
  `pane.output_matched` на подвал строки ввода Claude Code.
- Подсказка диалога — окно разделения справа от окна диалога (слева
  ввод, справа подсказка); ширина подсказки — пятая часть ширины панели
  (1:4 к диалогу), не меньше 20 столбцов. Заголовок «Вопрос k из n»,
  «Обзор ответов» или «Диалог» — в `winbar` окна. Строки «клавиша →
  описание» — номера пунктов с текстом (выделенный помечен `❯`),
  `S-CR`/`S-Space` — подтвердить, `C-c` — отменить диалог; длинные строки
  обрезаются. Группы подсветки — which-key, при их отсутствии запасные;
  сам which-key не вызывается. Окно не берёт фокус, обновляется по каждому
  экрану и изменению размеров и закрывается вместе с буфером диалога;
  текст буфера остаётся пустым.
- Shift+Enter и Shift+Пробел (вставка и обычный режим) подтверждают
  выбор в буфере диалога и отправляют запрос в буфере ввода, как `:w`.
  Ctrl+C в буфере диалога отправляет Esc и отменяет диалог. Режим после
  возврата в окно ввода соответствует режиму нажатия: из вставки —
  вставка, после `:w` — обычный режим.
- Цифра — стрелки до пункта с этим номером (клавиша цифры в одиночном
  выборе и запросе разрешения сразу подтверждает пункт, поэтому
  не отправляется); в множественном выборе — клавиша цифры, она
  переключает отметку. Текст при выделенном пункте свободного ввода
  уходит в поле с префиксом очистки буфера ввода. `:w` — Enter клавишей
  (`pane.send_keys`), в множественном выборе — после стрелок до кнопки
  подтверждения под пунктами: «Submit» (последний вопрос) или «Next»
  (за вопросом идёт ещё вопрос).
- После стрелок и Enter плагин запоминает подпись диалога и не принимает
  решений по экрану, который с ней совпадает: Claude Code ещё не обработал
  клавиши, и префикс с Esc закрыл бы диалог.
- После `:w` подпись отвеченного диалога запоминается отдельно: пока экран
  с ней совпадает, буфер диалога не открывается снова. Другой экран
  (следующий вопрос карточки, новый вопрос, запрос разрешения) открывает
  его заново, пустым; экран без диалога память сбрасывает.
- Тесты — `tests/` плагина (в `$HOME` не ставятся):
  `nvim --headless --clean -u NONE -l tests/dialog_spec.lua` — разбор
  снятых экранов из `tests/fixtures/`, `tests/switch_spec.lua` —
  переключение и отправки на поддельном сервере herdr в том же процессе.

## Проверка после обновления Claude Code

Замена строки ввода опирается на режим vim Claude Code, на распознавание
вставки по длине куска (~800 знаков) и на понимание Esc в кодировке
`CSI 27 u`. После обновления Claude Code строку ввода стоит сверить
с буфером: набрать многострочный текст, поправить его в середине и
посмотреть строку ввода командой `herdr pane read <панель Claude> --source
visible`. Точный снимок строки ввода даёт Ctrl+G в Claude Code, запущенном
с `VISUAL`, указывающим на сценарий, который копирует свой аргумент в файл
и сразу выходит: Claude Code передаёт редактору файл с текущим запросом.
Без такой подмены Ctrl+G открывает редактор пользователя (`VISUAL=neovide`)
отдельным окном. Enter в пробах — только с местной командой `/help`:
обычный текст и `!команда` уходят модели.

Буфер диалога опирается на вид экранов диалогов: подвал с «Enter to
select», «Enter to confirm» или «Esc to cancel» (под ним бывает линия
рамки с именем сессии «──── имя ─»), строка вкладок карточки
(`←  ☒ …  ☐ …  ✔ Submit  →`), подвал строки ввода (`-- INSERT --` с
пометкой режима разрешений, `⏵⏵`, `⏸`), знак выделения `❯`,
номера пунктов, надписи «Type something», «Chat about this», «Submit», «Next»
и «Submit answers». После обновления снять экраны вопроса AskUserQuestion
(одиночный выбор, множественный выбор последним вопросом и не последним, вкладка обзора), запроса разрешения
и доверия каталогу командой `herdr pane read <панель Claude> --source
detection`, положить их в `tests/fixtures/` и прогнать
`tests/dialog_spec.lua`. Запрос разрешения при правилах `allow`
пользователя вызывается файлом с правилами `ask`, переданным
`claude --settings`; доверие каталогу — запуском в новом пустом каталоге.
