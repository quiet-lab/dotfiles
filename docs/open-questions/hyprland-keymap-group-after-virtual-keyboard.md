# Когда Hyprland начнёт сам присылать окну группу раскладки после виртуальной клавиатуры

## Вопрос

Когда в Hyprland смена клавиатуры сиденья (`SeatManager::setKeyboard`,
`destroyKeyboard`) после того, как виртуальная клавиатура `wtype` пропадает,
начнёт сама присылать окну событие `modifiers` с номером группы, и обход
в VoxType станет не нужен.

## Что мешает решить сейчас

Ответ зависит от апстрима Hyprland: когда и в каком виде авторы исправят
поведение `destroyKeyboard`, из проекта не решить. Разбор багов уже вёлся
в обсуждениях, на которые нет ни привязки к версии, ни срока.

## Условие пересмотра

Вопрос пересматривается при обновлении Hyprland, после которого проверка
через `wev` из `docs/media-and-portals.md` (подраздел «Раскладка окна после
диктовки») показывает событие `modifiers` с группой сразу после выхода
`wtype`, без обхода.

Если в новой версии проверка проходит, обход в VoxType (ключ
`post_output_command`, скрипт `voxtype-restore-layout`) убирается отдельным
изменением OpenSpec, а этот файл удаляется.

## Контекст

Причина разобрана 23.09.2026 по исходникам Hyprland 0.56.2
(`src/managers/input/InputManager.cpp`, `src/protocols/core/Seat.cpp`)
и по событиям `wev`, изменение `voxtype-restore-layout`:
`wtype` создаёт виртуальную клавиатуру с картой из одной раскладки, окно
заводит для неё состояние xkb с группой 0; когда `wtype` выходит,
`destroyKeyboard` делает клавиатурой сиденья последнее устройство списка
и присылает окну полную карту us+ru, но не присылает `modifiers` с номером
группы, поэтому окно остаётся на группе 0, хотя главная клавиатура и плитка
раскладки показывают RU.

Похожие обсуждения апстрима:

- <https://github.com/hyprwm/Hyprland/discussions/13295>
- <https://github.com/hyprwm/Hyprland/discussions/10159>
- <https://github.com/atx/wtype/issues/44>

Ни одно не даёт срока исправления и не гарантирует, что решён именно
этот случай (смена клавиатуры сиденья после исчезновения виртуальной
клавиатуры), а не смежный.

## Что действует до решения

Обход остаётся в VoxType: скрипт `voxtype-restore-layout` вызывается через
`post_output_command` после каждого вывода текста (требование «Раскладка
окна после диктовки» спецификации `voxtype-dictation`). Убирать обход
раньше подтверждённого исправления нельзя — раскладка снова будет плыть.

## Возможные исходы

- Hyprland присылает группу сам — обход убирается, требование
  спецификации `voxtype-dictation` про перехват `post_output_command`
  снимается или сужается.
- Апстрим считает это ожидаемым поведением и не планирует менять —
  вопрос закрывается решением «обход остаётся постоянно», контекст
  переезжает в `docs/decisions/`.
