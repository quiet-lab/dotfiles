name: handoff
description: Передача незавершённой работы следующей сессии. Вызывается в конце сессии в любом проекте — пересматривает сделанное, переписывает раздел «Текущая работа» в todo.md как снимок состояния и разбирает открытые вопросы.
---

Раздел «Текущая работа» корневого `todo.md` проекта — точка входа
в новую сессию: хук `~/.claude/hooks/session-handoff.sh` печатает его
при старте вместе с перечнем `docs/open-questions/`. Это снимок того,
чем заняты сейчас, а не журнал.

Язык и требования к тексту задаёт `CLAUDE.md` проекта, где он молчит —
`~/.claude/CLAUDE.md`. Собственные правила передачи работы в `CLAUDE.md`
проекта главнее этого текста.

## Первый вызов в проекте

Нет `todo.md` или раздела «Текущая работа» — завести: раздел в самом
верху, остальное не трогать. Каталог `docs/open-questions/` заводится
с первым вопросом, которому там место; его `README.md` берётся из
`open-questions-readme.md` рядом с навыком и правится под проект
(упоминаются только соседи, которые в проекте есть). Пустой каталог
впрок не создаётся. Проект не под git — шаги с коммитами пропускаются.

## Порядок работы

1. **Дождаться фоновых агентов.** Если ждать нельзя — описать поручение
   и его состояние в подразделе «Где остановились».

2. **Остановить процессы, запущенные сессией** на этой машине: службы
   из исходников, наблюдатели, фоновые оболочки, циклы ожидания,
   контейнеры. Снимок говорит, как поднять нужное заново. Процессы
   на удалённых машинах без вопроса не трогать: перечислить пользователю
   и спросить.

   Фоновые оболочки Claude Code узнаются только по командной строке,
   начинающейся с `source …/shell-snapshots/snapshot-bash-…`:
   `pgrep -af 'shell-snapshots/snapshot-bash'` без текущей команды.
   Завершать по PID, прочитав командную строку каждого; искать
   по дочерним `sleep` или `pkill -f` нельзя — под шаблон попадают чужие
   процессы. После остановки тот же `pgrep` показывает только текущую
   команду.

3. **Пересмотреть сессию** и сверить с состоянием репозитория
   и сабмодулей, если они есть; в снимок попадает только подтверждённое:

   ```
   git status --short
   git log --oneline -20
   git submodule foreach --quiet 'echo "$sm_path:"; git status --short --branch'
   ```

4. **Незакоммиченные правки** сессии сохранить коммитом
   `WIP: <о чём правка>` либо описать в «Где остановились»: файлы,
   состояние, что делать дальше. Правки не этой сессии (соседняя сессия,
   пользователь) не коммитить и не откатывать — только назвать.

5. **Переписать раздел «Текущая работа»** целиком, сделанное убрать.
   Первая строка — дата снимка. Подразделы по порядку:

   - **Цель** — задача целиком в двух-трёх предложениях: чего добиваемся
     и что не меняется.
   - **Открытые вопросы к пользователю** — без чего работа встанет.
   - **Где остановились** — что работает, что проверено, в каких ветвях
     работа, чисты ли деревья; до восьми пунктов.
   - **Следующие шаги** — по порядку, каждый можно начать без расспросов:
     что, где, чем проверить; до восьми.
   - **Как проверить** — команды.
   - **Что пробовали и отвергли** — с причиной, до пяти строк.

   Нет сведений — «Нет.»; заглушек не оставлять.

6. **Разобрать открытые вопросы.** Вопрос, зависящий только
   от пользователя и мешающий ближайшей работе, остаётся в снимке.
   Вопрос, упирающийся во внешние обстоятельства или срок, — файлом
   в `docs/open-questions/` по шаблону `README.md` каталога, с условием
   пересмотра; шаг, зависящий от него, получает ссылку. Просмотреть
   файлы каталога: наступило условие пересмотра — вопрос в работу;
   решён — туда, где проект хранит решения, файл удалить; отпал — файл
   удалить.

7. **Долгоживущее — не в снимок.** Решение — туда, где проект хранит
   решения, описание устройства — в документацию; в снимке ссылка.

8. **Изменение OpenSpec**, если проект им пользуется, — ссылкой на его
   `tasks.md` с открытыми номерами задач, без второго перечня.

9. **Остальной `todo.md` не трогать**, кроме записи, вопрос которой
   переехал в `docs/open-questions/`: она заменяется ссылкой на файл.

10. **Закоммитить и отправить.** `todo.md` вместе с заведёнными
    и удалёнными файлами `docs/open-questions/` — коммитом о том, что
    снимок обновлён; затем `git push origin HEAD` — текущая ветвь,
    а не основная и не заранее названная; так же в сабмодулях с новыми
    коммитами. Отправка — если она разрешена заранее (правилом
    в `CLAUDE.md` или в памяти); иначе один раз спросить, перечислив,
    что уйдёт. Коммиты `WIP: …` назвать в отчёте.

11. **Отметить, что снимок обновлён:**

    ```
    bash ~/.claude/hooks/session-handoff.sh done
    ```

    Команда снимает отметки о сессиях, завершившихся без `/handoff`.
    В проекте с собственной копией хука вызывается она, путь от корня
    проекта.

## Проверка

```
bash ~/.claude/hooks/session-handoff.sh start
```

Раздел и перечень вопросов печатаются, сводка заканчивается строкой
«Конец сводки.», выжимка за ней называет цель, вопросы и первый шаг.
В настоящей сессии хук отвечает JSON через `jq`; без `jq` пользователь
получает предложение его установить.
