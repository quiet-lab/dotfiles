name: handoff
description: Передача незавершённой работы следующей сессии. Вызывается в конце сессии и после каждой задачи в любом проекте — пересматривает сделанное, переписывает раздел «Текущая работа» в местном todo.local.md как снимок состояния и разбирает открытые вопросы.
---

Раздел «Текущая работа» файла `todo.local.md` в корне репозитория —
точка входа в новую сессию: хук `session-handoff.sh` печатает его при
старте вместе с перечнем `docs/open-questions/`. Это снимок того, чем
заняты сейчас, а не журнал. Файл местный: он исключён через `.gitignore`
(строка `*.local.md`), у каждой машины свой, в git не попадает.

Хук и навык лежат в двух местах: в `~/.claude/` и в `.claude/` проекта,
который держит порядок передачи работы у себя. Проектная копия — источник
правил; копии обязаны совпадать байт в байт, поэтому в тексте навыка
нет ничего проектного. Хук вызывается из `.claude/hooks/` проекта,
если там есть копия, иначе из `~/.claude/hooks/`.

Язык и требования к тексту задаёт `CLAUDE.md` проекта, где он молчит —
`~/.claude/CLAUDE.md`. Собственные правила передачи работы в `CLAUDE.md`
проекта главнее этого текста.

## Первый вызов на машине

Нет `todo.local.md` — создать в корне репозитория по шаблону:

```markdown
# Очередь задач этой машины

## Текущая работа

Снимок на <дата>.

### Цель

Нет.

### Открытые вопросы к пользователю

Нет.

### Где остановились

Нет.

### Следующие шаги

Нет.

### Как проверить

Нет.

### Что пробовали и отвергли

Нет.
```

Нет в `.gitignore` строки `*.local.md` — добавить её коммитом, иначе
местный файл попадёт в git; где правка `.gitignore` проекту не нужна,
строка пишется в `.git/info/exclude`. Файл есть, а раздела «Текущая работа» нет —
завести раздел в самом верху, остальное не трогать. Каталог
`docs/open-questions/` заводится с первым вопросом, которому там место;
его `README.md` берётся из `open-questions-readme.md` рядом с навыком
и правится под проект (упоминаются только соседи, которые в проекте
есть). Пустой каталог впрок не создаётся. Проект не под git — шаги
с коммитами пропускаются.

## Порядок работы

1. **Дождаться фоновых агентов.** Если ждать нельзя — описать поручение
   и его состояние в подразделе «Где остановились».

2. **Остановить процессы, запущенные сессией** на этой машине: службы
   из исходников, наблюдатели, фоновые оболочки, циклы ожидания,
   контейнеры. Снимок говорит, как поднять нужное заново. Процессы
   на удалённых машинах (стенды, общие контуры) без вопроса не трогать:
   перечислить пользователю и спросить.

   Фоновые оболочки Claude Code узнаются только по командной строке,
   начинающейся с `source …/shell-snapshots/snapshot-bash-…`:
   `pgrep -af 'shell-snapshots/snapshot-bash'` без текущей команды.
   Завершать по PID, прочитав командную строку каждого; искать
   по дочерним `sleep` или `pkill -f` нельзя — под шаблон попадают чужие
   процессы. После остановки тот же `pgrep` показывает только текущую
   команду.

3. **Пересмотреть сессию** и сверить с состоянием репозитория
   и сабмодулей, если они есть; в снимок попадает только подтверждённое:

   ```
   git status --short
   git log --oneline -20
   git submodule foreach --quiet 'echo "$sm_path:"; git status --short --branch'
   ```

4. **Незакоммиченные правки** сессии сохранить коммитом
   `WIP: <о чём правка>` либо описать в «Где остановились»: файлы,
   состояние, что делать дальше. Правки не этой сессии (соседняя сессия,
   пользователь) не коммитить и не откатывать — только назвать.

5. **Переписать раздел «Текущая работа»** целиком, сделанное убрать.
   Первая строка — дата снимка. Подразделы по порядку:

   - **Цель** — задача целиком в двух-трёх предложениях: чего добиваемся
     и что не меняется.
   - **Открытые вопросы к пользователю** — без чего работа встанет.
   - **Где остановились** — что работает, что проверено, в каких ветвях
     работа, чисты ли деревья; до восьми пунктов.
   - **Следующие шаги** — по порядку, каждый можно начать без расспросов:
     что, где, чем проверить; до восьми.
   - **Как проверить** — команды.
   - **Что пробовали и отвергли** — с причиной, до пяти строк.

   Нет сведений — «Нет.»; заглушек не оставлять.

6. **Разобрать открытые вопросы.** Вопрос, зависящий только
   от пользователя и мешающий ближайшей работе, остаётся в снимке.
   Вопрос, упирающийся во внешние обстоятельства или срок, — файлом
   в `docs/open-questions/` по шаблону `README.md` каталога, с условием
   пересмотра; шаг, зависящий от него, получает ссылку. Просмотреть
   файлы каталога: наступило условие пересмотра — вопрос в работу;
   решён — туда, где проект хранит решения (записи решений,
   спецификации), файл удалить; отпал — файл удалить.

7. **Долгоживущее — не в снимок.** Решение — туда, где проект хранит
   решения, проверяемое поведение — в спецификации, описание устройства —
   в документацию; в снимке ссылка.

8. **Изменение OpenSpec**, если проект им пользуется, — ссылкой на его
   `tasks.md` с открытыми номерами задач, без второго перечня.

9. **Остальной `todo.local.md` не трогать**, кроме записи, вопрос
   которой переехал в `docs/open-questions/`: она заменяется ссылкой
   на файл.

10. **Закоммитить вопросы.** Заведённые и удалённые файлы
    `docs/open-questions/` — коммитом по-русски. Сам снимок
    не коммитится и не отправляется: `todo.local.md` в git нет.
    Коммиты сделанной работы навык не трогает, их отправка — по правилам
    проекта. Коммиты `WIP: …` назвать в отчёте.

11. **Отметить, что снимок обновлён:**

    ```
    bash .claude/hooks/session-handoff.sh done
    ```

    В проекте без своей копии хука — `bash ~/.claude/hooks/session-handoff.sh done`.
    Команда снимает отметки о сессиях, завершившихся без `/handoff`.

## Проверка

```
bash .claude/hooks/session-handoff.sh start
```

В проекте без своей копии — `~/.claude/hooks/session-handoff.sh`;
в проекте со сверкой родительских ветвей перед этим запускается
и она (`.claude/hooks/session-sync-check.sh`). Раздел и перечень
вопросов печатаются, сводка заканчивается строкой «Конец сводки.»,
выжимка за ней называет цель, вопросы и первый шаг. Нет
`todo.local.md` — вместо раздела строка «Местного снимка todo.local.md
нет». В настоящей сессии хук отвечает JSON через `jq`; без `jq`
пользователь получает предложение его установить.
